# Стандарт учебных материалов DevAcademy

Обязательные правила для уроков, упражнений, тестов, проверок и маршрутов. Формат файлов -
[content-authoring/README.md](content-authoring/README.md); уровни подготовки - [learning-levels.md](learning-levels.md);
исследование источников и лицензии - [curriculum-research.md](curriculum-research.md); аудит текущего контента -
[curriculum-audit.md](curriculum-audit.md).

Главное правило: **не считать, что человек знает то, чему его ещё не научили, и не заставлять повторять то, что он уже
доказанно знает.**

## 1. Слои трека

Каждый язык строится из независимых слоёв; общий материал не дублируется, а связывается `requires` и `prerequisites`.

| Слой | Уровень курса | Для кого | Пример (Go) |
|---|---|---|---|
| С нуля | 0 | никогда не программировал | `go-first-steps` |
| Для программистов | 1 | знает другой язык | `go-for-programmers`: плотные уроки, зачитывающие базовые (`assessmentFor`) |
| Язык и идиомы | 1-2 | прошёл один из двух слоёв выше | `go-fundamentals` |
| Профессиональный | 4-5 | работает с языком | `go-professional` |
| Проверка знаний | - | все, кто хочет пропустить известное | `go-skill-check` (уроки-проверки) + `content/routes/go.yaml` |

Фреймворки (`react`, `fastapi`, `spring-boot`, `aspnetcore`) не повторяют язык: они `requires` курс языка и начинают
с того, что добавляет фреймворк.

## 2. Урок для начинающего: педагогическая последовательность

Урок вводит **одно основное понятие** (иногда два тесно связанных). Десять этапов - это порядок мысли, а не десять
экранов; они ложатся на существующие разделы `theory.md`, квиз и упражнение:

| Этап | Где | Требование |
|---|---|---|
| 1. Зачем | начало `simple` | 1-3 предложения о практическом смысле: какую задачу это решает |
| 2. Простыми словами | `simple` | одно понятие; каждый новый термин определяется при первом появлении |
| 3. Минимальный пример | `examples` | короткая запускаемая программа ` ```go run ` с блоком ` ```output ` (проверяется запуском) |
| 4. Построчный разбор | `examples` сразу после примера | что делает строка, зачем, что будет при запуске |
| 5. Первый опыт | `examples`, «Попробуйте» | изменить одну деталь примера и предсказать результат |
| 6. Небольшая практика | упражнение, уровень A/B | заготовка почти готова; нужно изменить или дописать по образцу |
| 7. Самостоятельная задача | упражнение уровня C или `challenge` | без пошаговой инструкции, только изученное |
| 8. Разбор ошибок | `mistakes` | типичная ошибка → текст сообщения компилятора/вывод → почему → как исправить → как узнать самому |
| 9. Проверка понимания | `quiz` | 3-5 вопросов только по материалу этого и предыдущих уроков |
| 10. Итог | `summary` | что теперь умеете, где пригодится, что дальше |

Разделы:

* `simple`, `precise`, `examples`, `mistakes`, `summary` - обязательны (валидатор).
* `programmer` - кратко для тех, кто знает другой язык: чем конструкция отличается от Python/Java/JS/C#, 5-15 строк.
  Для уровня 1+ урок открывается на нём. Обязателен в уроках уровня 0, у которых есть путь для программистов.
* `deep-dive` - устройство изнутри (компилятор, рантайм, память). Не нужен для упражнения, скрывается при глубине Quick.
* `facts` - по желанию.

Порядок разделов в файле для начинающего: `simple`, `examples`, `precise`, `mistakes`, `summary`, `programmer`,
`deep-dive`.

## 3. Метаданные урока

* `goal` - одна измеримая цель («Написать программу, которая ...»).
* `objectives` - что человек сможет сделать; каждое проверяется упражнением или квизом.
* `masteryCriteria` - наблюдаемые утверждения, совпадающие с тем, что проверяют тесты.
* `prerequisites` - в курсе уровня 0 каждый урок, кроме первого, ссылается на предыдущий (валидатор предупреждает).
* `difficulty` - в курсе уровня 0 только `intro` / `easy` (валидатор предупреждает).
* `concepts` - понятия, которые урок **вводит** (`introduces`) и на которые **опирается** (`uses`). Валидатор
  требует, чтобы каждое используемое понятие вводилось этим уроком или уроком из его зависимостей (prerequisites
  транзитивно и уроки курсов из `requires`). Так ловится «использование до объяснения». Идентификаторы: `<язык>.<понятие>`
  (`go.for-loop`, `python.list`). Понятие указывается в `uses`, если его нужно знать для решения упражнения или понимания
  примера; упоминание мимоходом с пометкой «подробно позже» понятием не считается.
* `formerIds` - только при переименовании урока **с эквивалентным содержанием** (то же умение, те же проверки). Прогресс
  переносится миграцией. Если содержание другое - новый id без `formerIds`: старая запись остаётся историей и ничего не
  зачитывает.

## 4. Упражнения

### Уровни для начинающих

| Уровень | Что делает ученик | Заготовка |
|---|---|---|
| A | повторяет и меняет пример | рабочая программа, в которой нужно заменить значение / строку / условие |
| B | упражнение по образцу | каркас с комментарием-подсказкой на месте пропуска |
| C | небольшая задача самостоятельно | только `package main` / сигнатура функции |
| D | мини-проект из нескольких изученных понятий | пустой каркас, условие с примерами ввода-вывода |

Правила:

1. Задача проверяет только объяснённое ранее (контролируется `concepts.uses`). Исключение - явно помеченные
   исследовательские и профессиональные задачи.
2. Для новичка - бытовой контекст (покупки, оценки, температура, текст), не олимпиадные задачи.
3. Тесты: минимум один открытый и один скрытый; скрытые проверяют края (ноль, отрицательные, пустой ввод, кириллица).
   Подсказка (`hint`) каждого теста говорит, что проверяется, а не как решить.
4. 1-4 подсказки упражнения: направление → место → конкретная конструкция → частичный разбор.
5. Эталонное решение использует только изученное и проходит все тесты; заготовка не проходит (`--run-solutions`).
6. В условии - пример ввода и вывода; формат вывода однозначен.
7. Функции проверяются тестами (`evaluation: command` с `go test`, `harness` для Python), чтобы ошибка указывала на
   конкретный случай; программы целиком - `io`.

### Профессиональные задачи

Реалистичный инженерный контекст и объективная проверка: исправить гонку, найти утечку ресурса, сократить аллокации
(проверка `testing.AllocsPerRun`), корректная отмена через `context` (проверка отсутствия «зависших» горутин), набор
тест-кейсов, который отличает корректную реализацию от ошибочных (мутанты в скрытых тестах), безопасный рефакторинг
под существующие тесты. Каждая такая задача объясняет компромиссы решения. Если часть цели автоматически не
проверяется (например, читаемость API), урок прямо пишет, что проверяется, а что нет.

## 5. Квизы

* 3-5 вопросов; порог 0.7 по умолчанию.
* Только изученное; для начинающих - предсказание вывода коротких программ, поиск ошибки, выбор подходящей конструкции.
* Каждое объяснение говорит, почему верный ответ верен и в чём ошибка частого неверного.
* Без вопросов на запоминание дат и имён авторов.

## 6. Проверки знаний (диагностика)

* Урок-проверка - отдельный урок курса проверок трека с `assessmentFor` на покрываемые уроки.
* Состав: короткое упражнение с реальным запуском (обязательно для компетенций, связанных с написанием кода) и квиз на
  чтение кода / предсказание вывода. Квиз без упражнения - слабое доказательство (валидатор предупреждает).
* Сложность проверки соответствует компетенции: проверка «условия и циклы» не требует интерфейсов.
* Маршрут трека перечисляет компетенции в порядке от простых к сложным с `after`.
* Проверки не дают ярлыков уровня; результат - список компетенций с состоянием (см. learning-levels.md §5).

## 7. Тексты

* Русский язык; код, идентификаторы, флаги и названия API - на английском.
* Спокойный профессиональный тон. Не использовать «это очень просто», «как вы уже знаете», «очевидно», «магия»
  вместо объяснения.
* Объяснять не только как написать, но и почему это работает.
* Технические факты - по официальной документации; версии и даты - только проверенные (`facts` с https-источником).
* Все тексты, примеры, задания, решения и тесты - оригинальные. Чужие курсы - ориентир методики, не источник текста
  (см. curriculum-research.md, лицензии).

## 8. Прогресс и совместимость

* Прогресс хранится по id урока. Переименование - только через `formerIds` и только при эквивалентном содержании.
* Миграция (`ProgressMigrationService`) копирует запись на новый id, если у него ещё нет записи; старую запись не
  удаляет; повторный запуск ничего не меняет.
* Удалённые или заменённые неэквивалентным материалом уроки не зачитываются новым материалом.

## 9. Автоматические проверки

`make validate-content` (= `devacademy validate-content --content content --run-solutions`):

| Проверка | Тип |
|---|---|
| YAML, обязательные поля, неизвестные ключи | ошибка |
| prerequisites / related / next / ссылки `lesson:` существуют, нет циклов уроков и курсов | ошибка |
| `concepts.uses` вводятся в зависимостях | ошибка |
| `formerIds` не совпадают с существующими id и не повторяются | ошибка |
| маршруты: точки входа и уроки-проверки существуют и принадлежат треку, у проверки есть `assessmentFor`, `after` без циклов | ошибка |
| эталон проходит все тесты, заготовка - нет, примеры теории дают объявленный вывод | ошибка (`--run-solutions`) |
| курс уровня 0: урок без prerequisites, сложность выше easy | предупреждение (эвристика) |
| prerequisite из курса более высокого уровня | предупреждение (эвристика) |
| проверка без упражнения | предупреждение |

Семантика (понятны ли объяснения, соответствует ли квиз теме, адекватна ли сложность) автоматически не доказывается -
она фиксируется в отчёте аудита с пометкой «экспертная оценка, не исследование с участниками».
Если для языка нет рантайма, его решения помечаются как SKIPPED / NOT VERIFIED, а не как проверенные.
