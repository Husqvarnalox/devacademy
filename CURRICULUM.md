# Учебный план DevAcademy

Документ описывает модель учебного плана и честно разделяет «есть сейчас» и «запланировано». Технические термины и
идентификаторы не переводятся. Формат файлов контента: [docs/content-authoring/README.md](docs/content-authoring/README.md);
архитектура: [ARCHITECTURE.md](ARCHITECTURE.md); статус работ: [ROADMAP.md](ROADMAP.md).

## 2. Уровни 0-6: ориентир, а не квалификация

Уровень (`level` в `course.yaml`) показывает, насколько курс далёк от нуля. Он не означает диплом, грейд или готовность к
работе, и приложение не выдаёт «процент мастерства».

| Уровень | Ориентир |
|---|---|
| 0 | Первый запуск: как выполняется программа, среда, ввод-вывод |
| 1 | Основы языка или инструмента; простые программы |
| 2 | Рабочие навыки: структуры данных, модули, тесты, чтение чужого кода |
| 3 | Уверенная практика: проектирование небольших систем, отладка, профилирование на базовом уровне |
| 4 | Углублённые темы: конкурентность, производительность, архитектура |
| 5 | Специализация: тонкости рантайма, безопасность, масштабирование |
| 6 | Внутреннее устройство и исследовательские темы |

## 3. Структура: треки, курсы, уроки

* **Трек** (`catalog.yaml`) - направление: язык, фреймворк, алгоритмы, ML. Статус `available` только если есть хотя бы один
  настоящий курс.
* **Курс** - упорядоченный набор уроков со своей версией учебного плана (`version`, semver) и зависимостями `requires`.
* **Урок** - единица прогресса. Прогресс хранится по id урока, поэтому смена языка или параллельное прохождение
  нескольких курсов ничего не теряют.
* **Путь обучения** (`content/paths/*.yaml`) - цель (`targets`: курсы); нужные курсы и уроки выводятся из графа зависимостей
  (`course.requires` + `lesson.prerequisites`). Это граф, а не жёсткий список.

### Общие модули учатся один раз

Алгоритмы, SQL, сети, статистика, линейная алгебра, архитектура ПО преподаются в отдельных курсах. Языковые специализации
не повторяют теорию, а добавляют упражнения на своём языке через **варианты упражнения** (`variants:` - один набор тестов,
несколько языков). Усвоенные темы переиспользуются во всех путях; пропустить тему можно после проверки уровня
(**assessment credit**: урок-проверка с `assessmentFor` засчитывает перечисленные уроки, когда выполнено его правило
завершения - упражнение и квиз). Проверки трека собраны в маршрут (`content/routes/<track>.yaml`) с компетенциями; страница
«Проверка знаний» показывает их состояние (подтверждено / есть пробел / не проверено) и предлагает уроки для пробелов.

## 4. Формат урока

Каждый урок (реализовано, проверяется `validate-content`):

1. `theory.md` с обязательными разделами: `simple` (простыми словами), `precise` (точно), `examples`, `mistakes`, `summary`;
   по желанию `facts`, `deep-dive`. Запускаемые примеры с объявленным выводом проверяются запуском.
2. Метаданные: цель, сложность (`intro`…`expert`), время, `prerequisites`, `objectives`, `masteryCriteria`, ссылки `related`/`next`.
3. Факты (`historical`, `internals`, `misconception`, `performance`, `security`, `real-world`); для `historical` и
   `internals` обязателен https-источник.
4. Квиз (single / multiple / short / numeric) с объяснениями и порогом прохождения.
5. Упражнение: заготовка, эталонное решение, 1-4 подсказки, минимум один публичный и один скрытый тест. Проверка по stdout
   (`io`) или тест-харнесс (`harness`). Для алгоритмических задач - `complexity` и `editorial`, показываются после решения.
6. Необязательное «испытание» (`challenge`) повышенной сложности.

Сквозное правило: факты о версиях и API - только проверенные; иначе формулировка «сверьтесь с актуальной документацией».

## 5. Правила оценивания

* Упражнение считается решённым, только когда проходят **все** публичные и скрытые тесты. Успешный код выхода или успешная
  сборка сами по себе ничего не значат.
* Урок завершён, когда решено упражнение (если есть) **и** лучший результат квиза не ниже порога (если есть квиз). Урок
  без упражнения и квиза завершается кнопкой «Прочитано».
* Скрытые тесты не показываются: только «скрытый тест N не пройден» и подсказка автора.
* ИИ-тьютор не засчитывает решения, не запускает команды и не пишет файлы; без ИИ работают подсказки из контента.
* Повторение: интервалы 1, 3, 7, 16, 35 дней; при ≥3 неудачных попытках первое повторение через день.
* Для ML-упражнений (запланировано): воспроизводимые датасеты, фиксированные seed, допуски для чисел, проверка shape/dtype,
  GPU не обязателен; скрипт, который «просто завершился», не считается успехом.
* Проверки через реальные инструменты (tsc, Vitest, Jest, pytest) - Command evaluator; сейчас он работает для `node --test` и `go test`, остальные инструменты запланированы.

## 6. Метаданные версий фреймворков

Для курсов по фреймворкам и библиотекам в `course.yaml` блок `framework`: `id`, `version`, `docs` (https), `compatibility`,
`deprecated`, `migrationNotes`. Версия учебного плана (`version` курса) независима от версии фреймворка. Новая мажорная версия
фреймворка не обновляет примеры автоматически: готовится новая версия курса, эталонные решения прогоняются на новой версии.

## 7. Режим сравнения (запланировано)

Уроки-сравнения (React / Vue / Angular, Express / Fastify / NestJS, Django / FastAPI / Flask, Pandas / Polars,
PyTorch / TensorFlow / JAX и др.) оформляются по фиксированным критериям: назначение, архитектура, модель компонентов и
состояния, производительность, экосистема, кривая обучения, развёртывание, ограничения, типичное применение. Без оценок
«X лучше всех». Дизайн: ARCHITECTURE.md §13.
