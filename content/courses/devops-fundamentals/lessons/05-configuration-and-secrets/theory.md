## Конфигурация вне кода

Одна и та же сборка программы запускается на ноутбуке, в тестовом стенде и в продакшене. Адрес базы данных, ключи внешних сервисов, уровень логирования, число рабочих процессов различаются между этими местами. Если зашить их в код, для каждого окружения придётся собирать отдельный артефакт, а секреты окажутся в репозитории. Поэтому принцип **двенадцатифакторного приложения** требует: **конфигурация хранится вне кода**, обычно в переменных окружения. Проверка простая: можно ли открыть исходники публично, не раскрыв ни одного секрета?

Обычно настройки приходят из нескольких источников, и важно знать, **какой побеждает**. Типичный порядок от слабого к сильному:

1. **значения по умолчанию** в коде (разумные, безопасные);
2. **файл конфигурации** (общие для окружения настройки);
3. **переменные окружения** (то, что задаёт платформа или оркестратор);
4. **аргументы командной строки** (разовое явное переопределение).

**Секрет** (пароль, токен, приватный ключ) - особая конфигурация: его нельзя печатать в логи, класть в образ и в репозиторий. Конфигурацию печатают при запуске для диагностики, и именно здесь секреты чаще всего утекают.

## Приоритет, типы, ошибки

**Приоритет.** Итоговое значение ключа - значение из самого сильного источника, где ключ задан. Хорошая загрузка запоминает и **источник** значения: при отладке полезнее всего ответ «откуда взялось 9090?».

**Типы.** Все внешние источники дают строки. Загрузчик обязан привести их к типам и проверить:

* целое: `int(...)`, но строки вроде `eighty` дают ошибку, а не падение в рабочем запросе;
* логическое: распознавайте `true/false/1/0/yes/no/on/off` явно. Нельзя писать `bool(строка)`: `bool("false")` равно `True`;
* строка, URL, секрет - хранятся как есть, но печатаются по-разному.

**Fail fast.** Ошибку конфигурации нужно обнаружить **при запуске**, собрать **все** ошибки сразу (не по одной за запуск) и завершиться без работы:

* неизвестные ключи в файле, окружении или флагах - почти всегда опечатки; их нужно отвергать, а не игнорировать;
* обязательный ключ без значения - ошибка;
* значение неподходящего типа - ошибка.

**Секреты в выводе.** Секретный ключ при печати заменяют на `***`. Но секрет бывает **внутри составного значения**: строка подключения `postgres://user:пароль@host/db` содержит пароль в части *userinfo* (до последнего `@` в authority). Её нужно маскировать так: `postgres://user:***@host/db`. Сообщения об ошибках не должны повторять секретные значения: для типа `secret` и `url` ошибку формулируют без значения.

**Ограничения переменных окружения.** Они наследуются дочерними процессами, видны администратору (`/proc`, отладочные дампы), могут попасть в отчёты о сбоях. Для чувствительных данных предпочтительнее хранилище секретов или смонтированные файлы с ограниченным доступом; переменные окружения - компромисс. Про то, как образы получают такие значения только во время запуска, см. [урок про контейнеры](lesson:devops.fundamentals.containers-and-layers), а общие принципы работы с секретами - в [курсе по безопасности](lesson:security.fundamentals.secrets-and-dependencies).

## Слияние источников с запоминанием происхождения

```python run
DEFAULTS = {"port": 8080, "debug": False, "log_level": "info"}
FILE = {"port": 9000, "log_level": "debug"}
ENV = {"port": "9090"}
FLAGS = {}

merged = {k: (v, "default") for k, v in DEFAULTS.items()}
for name, layer in (("file", FILE), ("env", ENV), ("flags", FLAGS)):
    for key, value in layer.items():
        merged[key] = (value, name)
for key in sorted(merged):
    print(f"{key}={merged[key][0]!r} from {merged[key][1]}")
```
```output
debug=False from default
log_level='debug' from file
port='9090' from env
```

Словарь, который перезаписывается слоями от слабого к сильному, - самая простая реализация приоритета; хранится и пара «значение, источник».

## Строка "false" и явное приведение

```python run
raw = "false"
print("bool(raw):", bool(raw))


def parse_bool(text):
    t = text.strip().lower()
    if t in {"true", "1", "yes", "on"}:
        return True
    if t in {"false", "0", "no", "off"}:
        return False
    raise ValueError(f"invalid bool: {text!r}")


for s in ["false", "ON", "0", "maybe"]:
    try:
        print(f"{s!r:8} ->", parse_bool(s))
    except ValueError as e:
        print(f"{s!r:8} ->", e)
```
```output
bool(raw): True
'false'  -> False
'ON'     -> True
'0'      -> False
'maybe'  -> invalid bool: 'maybe'
```

Явный разбор делает поведение предсказуемым, а неопознанное значение - ошибкой на старте.

## Маскирование пароля в URL

```python run
def redact_url(value):
    if "://" not in value:
        return value
    scheme, rest = value.split("://", 1)
    end = min([len(rest)] + [i for i in (rest.find(c) for c in "/?#") if i != -1])
    authority, tail = rest[:end], rest[end:]
    userinfo, at, hostport = authority.rpartition("@")
    if at and ":" in userinfo:
        authority = userinfo.split(":", 1)[0] + ":***@" + hostport
    return f"{scheme}://{authority}{tail}"


for url in ["postgres://app:s3cret@db:5432/app?sslmode=require", "redis://:tokenonly@cache:6379/0",
            "postgres://reader@replica/app", "sqlite:///local.db"]:
    print(redact_url(url))
```
```output
postgres://app:***@db:5432/app?sslmode=require
redis://:***@cache:6379/0
postgres://reader@replica/app
sqlite:///local.db
```

Обратите внимание: `rpartition("@")` отделяет userinfo по **последнему** `@`, а пароль берётся после **первого** `:`. Так корректно обрабатываются пароли, содержащие `:` или `@` (в корректных URL `@` в пароле кодируется как `%40`, но защитный код не должен рассчитывать на идеальный ввод).

## Типичные ошибки

* **Секреты в репозитории или образе.** Даже удалённый позже коммит остаётся в истории; слой образа - тоже. Ротируйте скомпрометированный секрет.
* **`bool(os.environ["DEBUG"])`.** Любая непустая строка, включая `"false"`, истинна.
* **Молчаливое игнорирование неизвестных ключей.** Опечатка `prot=8080` оставит порт по умолчанию, и никто не заметит.
* **Печать всей конфигурации в логи при запуске.** Нужно редактирование: секреты и пароли в URL.
* **Проверка типов «потом».** Ошибка `eighty` вместо числа обнаружится на первом запросе в продакшене, а не при запуске.
* **Неочевидный приоритет.** Если никто не знает, что побеждает - файл или окружение, диагностика превращается в угадывание; фиксируйте порядок и печатайте источник.
* **Разные имена для одного и того же ключа в источниках.** Окружение `APP_DB_URL`, ключ `db_url`, флаг `--db-url`: определите одно правило преобразования.
* **Считать окружение хранилищем секретов.** Переменные окружения видны процессу и часто оказываются в дампах; для высокой чувствительности используйте хранилище секретов.
* **Бессрочные долгоживущие ключи.** Предпочитайте короткоживущие учётные данные и ротацию.

## Итоги

* Конфигурация, различающаяся между развёртываниями, хранится вне кода; секрет - конфигурация, которую нельзя раскрывать.
* Приоритет источников: умолчания < файл < окружение < флаги; полезно запоминать источник значения.
* Типы приводятся и проверяются при запуске; все ошибки собираются сразу; неизвестные ключи отвергаются.
* Булевы значения разбираются явно, а не через `bool(строка)`.
* Секреты маскируются в выводе, включая пароль в строке подключения; значения секретов не попадают в сообщения об ошибках.
