## Объекты в C++ копируются, а время жизни управляется областью видимости

В Python и Java переменная обычно хранит ссылку на объект. В C++ переменная **и есть** объект: `std::vector<int> a = b;` создаёт **вторую независимую копию** всех элементов. Это называется **семантикой значений** (value semantics).

Из этого следует три практических вывода:

1. **Передача по значению копирует.** `void f(std::vector<int> v)` работает с копией; изменения вызывающий код не увидит (зато копирование может быть дорогим).
2. **Ссылка `&` - это другое имя того же объекта.** `void f(std::vector<int>& v)` изменяет объект вызывающего кода. `const std::vector<int>&` читает без копирования и без права менять.
3. **Время жизни объекта - его блок `{ }`.** При выходе из блока вызывается **деструктор**. Если класс освобождает ресурс (память, файл, блокировку) в деструкторе, то освобождение происходит автоматически и в правильный момент. Этот приём называется **RAII**.

```cpp
void shift(std::vector<int>& v) {  // ссылка: меняем оригинал
    for (int& x : v) x -= 1;
}
```

## Копирование, ссылки, RAII

**Копирование и перемещение.** Копия вызывает конструктор копирования; для `std::vector` и `std::string` он выделяет новую память и копирует элементы. Перемещение (`std::move`) передаёт содержимое без копирования: исходный объект остаётся в допустимом, но неопределённом по содержимому состоянии. Возврат локального объекта из функции (`return v;`) компилятор обычно оптимизирует: копирование не происходит (в C++17 для временных объектов это гарантировано).

**Ссылки.** Ссылка при создании обязана быть привязана к объекту и потом не перепривязывается. Её нельзя сделать «пустой» (в отличие от указателя). `const T&` может привязаться и к временному значению; его время жизни продлевается до конца ссылки.

**Висячие ссылки.** Ссылка на объект, который уже уничтожен, - неопределённое поведение. Классический пример: функция возвращает ссылку на свою локальную переменную. Компилятор часто выдаёт предупреждение (`-Wall`), но не всегда. Правило: не возвращайте ссылки на локальные объекты и не храните ссылки на элементы вектора, если вектор может перераспределить память.

**Порядок деструкции.** Локальные объекты уничтожаются при выходе из блока **в порядке, обратном созданию**. Элементы класса уничтожаются в порядке, обратном объявлению. Деструктор вызывается и при выходе из блока через `return` или исключение (размотка стека).

**RAII.** Идея: ресурс захватывается в конструкторе и освобождается в деструкторе. Примеры из стандартной библиотеки: `std::vector` (память), `std::string`, `std::unique_ptr` (единственный владелец динамического объекта), `std::lock_guard` (блокировка), `std::ofstream` (файл). Благодаря RAII не нужен ни ручной `delete`, ни `finally`. В этом курсе упражнения обходятся без `new` и `delete`: для коллекций используйте `std::vector`, для владения - `std::unique_ptr` / `std::make_unique`.

**Правило нуля.** Если все поля класса сами управляют ресурсами (vector, string, unique_ptr), писать деструктор, конструктор копирования и оператор присваивания вручную не нужно: сгенерированные работают правильно.

**const-корректность.** `const` в сигнатуре - обещание не менять объект. Компилятор проверяет это и ловит случайные изменения. Параметры, которые только читаются, принимают как `const T&`.

**Что выбрать для параметра.** Маленькие типы (`int`, `double`) - по значению. Большие, которые только читаются, - `const T&`. Которые нужно изменить - `T&`. Которые функция забирает себе - по значению с `std::move`.

## Примеры

**Пример 1. Копия против ссылки.**

```cpp run
#include <iostream>
#include <vector>

void byValue(std::vector<int> v) { v[0] = 99; }
void byRef(std::vector<int>& v) { v[0] = 99; }

int main() {
    std::vector<int> a{1, 2, 3};
    byValue(a);
    std::cout << a[0] << "\n";
    byRef(a);
    std::cout << a[0] << "\n";
    std::vector<int> b = a;
    b[1] = -1;
    std::cout << a[1] << " " << b[1] << "\n";
}
```
```output
1
99
2 -1
```

**Пример 2. Порядок конструкторов и деструкторов.**

```cpp run
#include <iostream>
#include <string>

struct Noisy {
    std::string name;
    explicit Noisy(std::string n) : name(std::move(n)) { std::cout << "create " << name << "\n"; }
    ~Noisy() { std::cout << "destroy " << name << "\n"; }
};

int main() {
    Noisy a("a");
    {
        Noisy b("b");
        Noisy c("c");
    }
    std::cout << "end of main\n";
}
```
```output
create a
create b
create c
destroy c
destroy b
end of main
destroy a
```

**Пример 3. Деструктор срабатывает при исключении.**

```cpp run
#include <iostream>
#include <stdexcept>

struct Guard {
    ~Guard() { std::cout << "cleanup\n"; }
};

void work() {
    Guard g;
    throw std::runtime_error("fail");
}

int main() {
    try {
        work();
    } catch (const std::exception& e) {
        std::cout << "caught " << e.what() << "\n";
    }
}
```
```output
cleanup
caught fail
```

Деструктор `g` выполнился при размотке стека, до `catch`.

**Пример 4. Считаем копии.**

```cpp run
#include <iostream>

struct Tracked {
    Tracked() = default;
    Tracked(const Tracked&) { std::cout << "copy\n"; }
};

void take(Tracked) {}
void view(const Tracked&) {}

int main() {
    Tracked t;
    take(t);
    view(t);
    Tracked u = t;
    (void)u;
}
```
```output
copy
copy
```

**Пример 5. `unique_ptr` как владелец.**

```cpp run
#include <iostream>
#include <memory>

struct Res {
    ~Res() { std::cout << "released\n"; }
};

int main() {
    {
        auto p = std::make_unique<Res>();
        std::cout << "using\n";
    }
    std::cout << "after scope\n";
}
```
```output
using
released
after scope
```

## Типичные ошибки

* **Параметр по значению, когда нужно менять.** Функция меняет копию, вызывающий код не видит эффекта.
* **Параметр по значению для больших объектов.** Лишнее копирование. Используйте `const T&`.
* **Возврат ссылки на локальную переменную.** После выхода из функции объект уничтожен: неопределённое поведение.
* **Ссылка на элемент вектора, а затем `push_back`.** Вектор может перераспределить память, и ссылка повиснет.
* **Ручной `new` без `delete`.** Утечка. Лучше `std::vector`, `std::string`, `std::make_unique`.
* **Предполагать порядок деструкции «как написано».** Он обратный порядку создания.
* **Использовать объект после `std::move`.** Содержимое не определено; допустимы только присваивание и уничтожение.
* **Забыть `explicit` у одно-аргументного конструктора.** Возможны неожиданные неявные преобразования.

<!-- section: summary -->
## Итоги

* Переменная - это сам объект; присваивание и передача по значению копируют.
* `T&` - второе имя объекта, `const T&` - только чтение без копии.
* Деструктор вызывается при выходе из блока, в обратном порядке создания, в том числе при исключении.
* RAII связывает владение ресурсом со временем жизни объекта: используйте `vector`, `string`, `unique_ptr`.
