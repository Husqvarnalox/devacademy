## Собрать всё в одну программу

Все уроки до этого посвящены отдельным инструментам: ввод, условия, циклы, функции, списки, словари, обработка ошибок, классы. Настоящая программа использует их вместе, и главная трудность - не знание отдельных конструкций, а их **разделение на части**: кто читает ввод, кто проверяет одну строку, кто хранит результат, кто печатает итоги.

В этом уроке вы пишете небольшую законченную программу «учёт покупок». Ввод у неё неидеальный, как в жизни: часть строк записана неверно. Программа должна такие строки **посчитать и пропустить**, а не упасть.

## Одна новая идея: разбор одной строки выносят в функцию, которая возвращает значение или `null`

Для каждой строки нужно ответить: «это корректная запись или нет?». Удобно сделать функцию, которая принимает строку и возвращает результат разбора, либо `null`, если строка некорректна. Тип такого результата записывают с вопросительным знаком: `Purchase?` означает «`Purchase` или `null`». Вы встречали `Int?` в уроке о nullable-значениях, здесь то же правило для своего типа.

Остальная программа тогда проста: прочитать строки до конца ввода, для каждой вызвать функцию, при `null` увеличить счётчик пропущенных, иначе сохранить результат.

## Пример 1. Разбор строк в функции

```kotlin run
data class Purchase(val product: String, val price: Int)

fun parseLine(line: String): Purchase? {
    val parts = line.split(";")
    if (parts.size != 2) {
        return null
    }
    val product = parts[0].trim()
    val price = parts[1].trim().toIntOrNull()
    if (product == "" || price == null || price < 0) {
        return null
    }
    return Purchase(product, price)
}

fun main() {
    val lines = listOf("хлеб;45", "молоко;80", "сыр", "чай;abc", " ;10", "яблоки; 120 ", "соль;-5")
    val accepted = mutableListOf<Purchase>()
    var skipped = 0
    for (line in lines) {
        val purchase = parseLine(line)
        if (purchase == null) {
            skipped += 1
        } else {
            accepted.add(purchase)
        }
    }
    println("Принято: ${accepted.size}, пропущено: $skipped")
    println(accepted)
}
```
```output
Принято: 3, пропущено: 4
[Purchase(product=хлеб, price=45), Purchase(product=молоко, price=80), Purchase(product=яблоки, price=120)]
```

Разбор:

* `parseLine` проверяет по порядку: два поля через `;`, непустое название, число в цене, цена не отрицательная. При любом нарушении возвращает `null`, иначе объект `Purchase`.
* Условие `product == "" || price == null || price < 0` читается слева направо и использует то, что оператор `||` не вычисляет правую часть, если левая уже `true`. Если `price == null`, до сравнения `price < 0` дело не доходит. Благодаря этой проверке компилятор знает, что в правой части `price` уже не `null`, и разрешает сравнение (эта возможность называется умным приведением типа; подробно - в курсе «Kotlin: первые шаги»).
* Строка `«яблоки; 120 »` принята: пробелы убрал `trim()`. Строки «сыр» (нет второго поля), «чай;abc» (цена не число), « ;10» (пустое название) и «соль;-5» (отрицательная цена) пропущены.
* `main` ничего не знает о разборе: она только вызывает функцию и считает.

## Пример 2. Чтение до конца ввода

Программа читает ввод, поэтому показана без запуска. Она читает строки вида `день;температура` до конца ввода, считает верные и неверные строки и суммирует температуры:

```kotlin
fun main() {
    var good = 0
    var bad = 0
    var sum = 0
    while (true) {
        val line = readlnOrNull() ?: break
        val parts = line.split(";")
        val value = if (parts.size == 2) parts[1].trim().toIntOrNull() else null
        if (value == null) {
            bad += 1
        } else {
            good += 1
            sum += value
        }
    }
    println("Верных строк: $good, неверных: $bad")
    println("Сумма: $sum")
}
```

Для ввода

```text
пн;20
вт;abc
ср
чт; 25
```

она напечатает `Верных строк: 2, неверных: 2` и `Сумма: 45`.

Разбор:

* `readlnOrNull() ?: break` завершает цикл на конце ввода и избавляет от ошибки чтения после конца (урок о nullable-значениях).
* `if (...) ... else null` здесь - выражение: значение `value` либо число, либо `null`. Обе ситуации «неверное число» и «неверное число полей» сводятся к `null`.

## Как делить задачу

1. Определите **данные**: что хранит одна запись (класс `Purchase`).
2. Определите **проверку одной строки** как функцию: вход - строка, выход - запись или `null`.
3. Напишите **цикл чтения**, который вызывает функцию и накапливает результаты (список, счётчик, словарь).
4. Напишите **вывод итогов** отдельно от чтения.
5. Проверьте программу на трёх видах ввода: обычный, с неверными строками, пустой.

**Попробуйте.** В примере 1 добавьте в `listOf` строку `"хлеб;45;3"` и убедитесь, что она попала в пропущенные (в ней три поля). Затем измените условие так, чтобы нулевая цена тоже считалась ошибкой.

## Точные правила

* Тип `Purchase?` допускает значение `null`. Результат нужно проверить (`== null`) до использования свойств, иначе компилятор не пропустит обращение.
* Функция с возвращаемым типом `Purchase` (без `?`) не может вернуть `null`. Чтобы разрешить это, меняют тип на `Purchase?`.
* Сравнение `price < 0` допустимо только для обычного `Int`. Для `Int?` сначала нужна проверка на `null` или значение по умолчанию.
* `toIntOrNull()` не принимает пробелы по краям (`" 120"` даёт `null`), поэтому `trim()` вызывают до него.
* `readlnOrNull()` возвращает `null` на конце ввода; результат нельзя использовать как `String`, пока не обработан `null`.
* Подсчёт пропущенных строк - часть задачи, а не обработка ошибок «на всякий случай»: тихо проглатывать плохие строки без счётчика нельзя, пользователь не узнает о потере данных.
* Порядок вывода и точные формулировки строк входят в условие: их проверяют тесты.

## Типичные ошибки

**1. `null` в функции с типом без `?`.**

```kotlin
data class Purchase(val product: String, val price: Int)

fun parseLine(line: String): Purchase {
    val parts = line.split(";")
    if (parts.size != 2) {
        return null
    }
    return Purchase(parts[0], parts[1].toInt())
}

fun main() {
    println(parseLine("хлеб;45"))
}
```

```text
Main.kt:6:16: error: null cannot be a value of a non-null type 'Purchase'.
        return null
               ^^^^
```

Тип результата `Purchase` не допускает `null`. Объявите `Purchase?`.

**2. Сравнение значения, которое может быть `null`.**

```kotlin
fun main() {
    val price = "45".toIntOrNull()
    if (price < 0) {
        println("отрицательная")
    }
}
```

```text
Main.kt:3:15: error: operator call is prohibited on a nullable receiver of type 'Int?'. Use '?.'-qualified call instead.
    if (price < 0) {
              ^
```

Сначала проверьте `price == null`, и только потом сравнивайте. В условии с `||` проверку на `null` ставят первой.

**3. Строка из `readlnOrNull()` используется без проверки.**

```kotlin
fun main() {
    while (true) {
        val line = readlnOrNull()
        println(line.trim())
    }
}
```

```text
Main.kt:4:21: error: only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type 'String?'.
        println(line.trim())
                    ^
```

Тип `line` - `String?`. Добавьте `?: break` к чтению: `val line = readlnOrNull() ?: break`.

**4. Забытый `trim()` перед `toIntOrNull()`.**

```kotlin
fun main() {
    val parts = " 120 ".split(";")
    println(parts[0].toIntOrNull())
    println(parts[0].trim().toIntOrNull())
}
```

```text
null
120
```

Ошибки компиляции здесь нет, и это опаснее: корректная строка молча попадёт в пропущенные. Результат такой ошибки виден только по итоговому счётчику, поэтому всегда сверяйте программу на примере со строкой, где вокруг числа есть пробелы.

**5. Чтение без проверки конца ввода.**

```kotlin
fun main() {
    val line = readln()
    println(line)
}
```

Запуск с пустым вводом:

```text
Exception in thread "main" kotlin.io.ReadAfterEOFException: EOF has already been reached
	at kotlin.io.ConsoleKt.readln(Console.kt:152)
	at MainKt.main(Main.kt:2)
	at MainKt.main(Main.kt)
```

`readln()` на конце ввода бросает исключение. Для чтения «до конца» используйте `readlnOrNull() ?: break`.

## Итоги

* Большую задачу делят на данные (класс), проверку одной записи (функция, возвращающая значение или `null`), цикл чтения и вывод итогов.
* Тип `Тип?` выражает «значение или ничего»; перед использованием результат проверяют на `null`.
* Неверные строки считают и пропускают, а не обрываются на них.
* Читают «до конца» через `readlnOrNull() ?: break`; перед `toIntOrNull()` вызывают `trim()`.
* Проверяйте программу на обычном вводе, на вводе с плохими строками и на пустом вводе.

## Для тех, кто уже программирует

* Возврат «значение или `null`» вместо исключения или кода ошибки - основной способ в Kotlin сообщать «не получилось разобрать». Это аналог `Optional` в Java и `(value, ok)` в Go, но на уровне типа и без обёртки.
* Паттерн «разобрать строку в функции, вернуть `T?`» заменяет `try/except` в Python и `parseInt` с проверкой `NaN` в JavaScript.
* `data class` для записи - аналог `record` в Java и `dataclass` в Python; печать и `==` бесплатно.
* Цикл `while (true)` с `readlnOrNull() ?: break` - идиома Kotlin для чтения до конца ввода, аналог `for scanner.Scan()` в Go.
* Умное приведение типов (`smart cast`: после проверки `price == null ||` компилятор считает `price` обычным `Int`) работает как в TypeScript при сужении типа; подробности - в «Kotlin: первые шаги».
* Структурировать такую программу дальше можно разбиением по файлам и пакетам, чтением из файлов и тестами; всё это в `kotlin-fundamentals`.
