## Зачем уметь читать ошибки

Ошибки в программе бывают у всех, у новичков и у опытных разработчиков. Разница в том, как быстро человек находит причину. Компилятор не просто говорит «не получилось»: он указывает **место** и **вид** ошибки. Если уметь читать такое сообщение, исправление занимает минуту, а не час.

**Ошибка компиляции** - проблема, которую компилятор обнаруживает до запуска программы. Пока она не исправлена, программа не запустится вообще. Это удобно: ошибка не успевает причинить вреда, а вы видите её сразу.

## Одна новая идея: сообщение состоит из адреса и объяснения

Типичное сообщение выглядит так:

```text
Main.kt:3:5: error: unresolved reference 'Println'.
    Println("Сумма: 450 руб.")
    ^^^^^^^
```

В нём три части:

1. **Адрес** `Main.kt:3:5` - файл, номер строки и номер столбца: ошибка найдена в третьей строке, начиная с пятого символа. Нумерация идёт с единицы.
2. **Объяснение** `error: unresolved reference 'Println'.` - слово `error` говорит, что это ошибка, а после двоеточия написано, что именно не так. Здесь: «не нахожу имя `Println`».
3. **Указатель** - сама строка кода и значки `^^^^^^^` под тем фрагментом, который не понравился компилятору.

Читать сообщение нужно в таком порядке: адрес (куда смотреть), указатель (на что именно), объяснение (что не так).

<!-- section: examples -->
## Пример 1. Читаем и исправляем одну ошибку

Программа с ошибкой:

```kotlin
fun main() {
    println("Счёт оплачен")
    Println("Спасибо!")
}
```

Сообщение:

```text
Main.kt:3:5: error: unresolved reference 'Println'.
    Println("Спасибо!")
    ^^^^^^^
```

Адрес - строка 3, столбец 5, то есть начало слова `Println`. Указатель подчёркивает слово целиком. Объяснение: имя неизвестно. В Kotlin регистр важен, значит, нужно `println`. Исправленная программа:

```kotlin run
fun main() {
    println("Счёт оплачен")
    println("Спасибо!")
}
```
```output
Счёт оплачен
Спасибо!
```

## Пример 2. Ошибка указана строкой ниже, чем причина

В этой программе забыта закрывающая скобка во второй строке, а не в третьей:

```kotlin
fun main() {
    println("Заказ принят"
    println("Сумма: 450 руб.")
}
```

```text
Main.kt:3:5: error: unresolved reference 'println' on receiver of type 'String'.
    println("Сумма: 450 руб.")
    ^^^^^^^
Main.kt:3:31: error: syntax error: Expecting ')'.
    println("Сумма: 450 руб.")
                              ^
```

Компилятор не понимает, где кончается вторая команда, и продолжает читать третью строку как её часть. Поэтому он жалуется на строку 3, а настоящая причина стоит строкой выше. Правило: если в указанной строке всё верно, посмотрите на предыдущую.

```kotlin run
fun main() {
    println("Заказ принят")
    println("Сумма: 450 руб.")
}
```
```output
Заказ принят
Сумма: 450 руб.
```

## Пример 3. Несколько независимых ошибок

```kotlin
fun main() {
    println("Один")
    println(Два)
    printl("Три")
}
```

```text
Main.kt:3:13: error: unresolved reference 'Два'.
    println(Два)
            ^^^
Main.kt:4:5: error: unresolved reference 'printl'.
    printl("Три")
    ^^^^^^
```

Здесь две разные ошибки: в третьей строке пропущены кавычки (слово без кавычек Kotlin считает именем), в четвёртой - опечатка в `println`. Компилятор показал обе сразу, и исправлять их можно по очереди сверху вниз.

**Попробуйте.** Введите в редакторе программу из примера 3 и исправьте только первую ошибку. Запустите снова: должно остаться одно сообщение. Затем исправьте вторую.

## Точные правила

* Сообщение имеет вид `файл:строка:столбец: error: объяснение`. Под ним печатаются строка кода и значки `^`, которые указывают на проблемный фрагмент.
* **Синтаксическая ошибка** (`syntax error: Expecting ...`) означает, что нарушена форма записи: не хватает скобки, кавычки или другого знака. Слово после `Expecting` называет то, что компилятор ожидал увидеть.
* **Неизвестное имя** (`unresolved reference '...'`) означает, что имя нигде не объявлено: оно написано с опечаткой, не тем регистром или это текст, забытый в кавычках.
* Одна причина может породить несколько сообщений. Неверно закрытая кавычка или скобка чаще всего вызывает цепочку; в ней важно первое сообщение.
* Место, на которое указывает компилятор, - это место, где он **перестал понимать** текст. Реальная причина может быть раньше: в той же или предыдущей строке.
* Кроме `error` бывают `warning` - предупреждения. Они не запрещают запуск: программа соберётся и выполнится, но компилятор советует обратить внимание на подозрительное место.
* Пока есть хотя бы одна `error`, программа не запускается и ничего не печатает, даже команды, стоящие до ошибки.
* Ошибки бывают и после запуска (например, при чтении некорректного ввода). Они называются ошибками времени выполнения; примеры - в уроке о преобразовании типов.

## Типичные ошибки

**1. Исправлять все ошибки сразу, не запуская программу.** Часть сообщений исчезает после одной правки, а часть появляется только тогда, когда компилятор «доходит» дальше. Исправили одно - запустите снова.

**2. Искать причину только в указанной строке.** Если в ней всё верно, смотрите выше (пример 2).

**3. Решить, что пропажа сообщений значит успех.** После исправления кавычки в программе из упражнения может остаться другая ошибка. Например, так выглядит сообщение, когда нет закрывающей фигурной скобки:

```text
Main.kt:4:35: error: syntax error: Expecting '}'.
    println("Спасибо за покупку!")
                                  ^
```

Указатель стоит в конце последней строки: компилятор дочитал файл до конца и не нашёл парную `}`.

**4. Сообщений больше, чем ошибок.** Незакрытая кавычка даёт два сообщения сразу:

```text
Main.kt:4:34: error: syntax error: Expecting '"'.
    println("Спасибо за покупку!)
                                 ^
Main.kt:4:34: error: syntax error: Expecting ')'.
    println("Спасибо за покупку!)
                                 ^
```

Первое говорит, что нужна закрывающая кавычка. Второе возникло потому, что скобка `)` оказалась внутри текста. Исправьте кавычку - обе пропадут.

**5. Не читать объяснение, а только искать красное.** Слова `unresolved reference` и `Expecting` почти всегда прямо называют проблему. Прочитайте, что именно ожидалось или не найдено.

## Итоги

* Сообщение компилятора состоит из адреса `файл:строка:столбец`, объяснения и указателя `^^^`.
* `syntax error: Expecting ...` - нарушена форма записи; `unresolved reference` - неизвестное имя.
* Причина может находиться строкой выше указанной; одна ошибка может давать несколько сообщений.
* Исправляйте по одной ошибке и запускайте программу заново.

В следующем уроке ([Вывод текста](lesson:kotlin.from-zero.output)) вы научитесь управлять тем, что и как печатает программа.

<!-- section: programmer -->
## Для тех, кто уже программирует

* Формат сообщений `файл:строка:столбец: error: текст` с копией строки и подчёркиванием `^^^` знаком по `javac`, `rustc` и `tsc`.
* Ошибки типов (`initializer type mismatch`, `unresolved reference`) выдаются на этапе компиляции: Kotlin статически типизирован. Типичный источник путаницы - синтаксические ошибки, дающие каскад сообщений на следующих строках.
* Предупреждения (`warning`) не останавливают сборку. Флаг `-Werror` превращает их в ошибки, но в приложении он не используется.
* Исключения во время выполнения выглядят иначе: `Exception in thread "main" ...` и стек вызовов с номерами строк `Main.kt:N`. Их разбор - в уроке о преобразовании типов.
