## Зачем нужны сравнения

Программы постоянно задают вопросы: хватает ли денег на покупку, не пуст ли ответ, взрослый ли посетитель, совпал ли пароль. Ответ на такой вопрос всегда один из двух: **да** или **нет**. В Kotlin эти два ответа - значения `true` и `false` типа `Boolean`, с которым вы познакомились в уроке об основных типах.

Чтобы получить такой ответ, значения **сравнивают**. Несколько ответов можно объединить в один: «взрослый **и** есть билет», «выходной **или** праздник». Это называется **логикой**.

## Одна новая идея: сравнение - это выражение, значение которого true или false

| Запись | Смысл |
|---|---|
| `a == b` | равно |
| `a != b` | не равно |
| `a < b` | меньше |
| `a > b` | больше |
| `a <= b` | меньше или равно |
| `a >= b` | больше или равно |

Результат сравнения можно напечатать или сохранить в переменную, как любое другое значение. Простые вопросы объединяют тремя логическими операторами:

| Запись | Читается | Истинно, когда |
|---|---|---|
| `a && b` | «и» | истинны **оба** |
| `a \|\| b` | «или» | истинно **хотя бы одно** |
| `!a` | «не» | `a` ложно |

Важно не путать `=` и `==`. Один знак `=` **присваивает** значение переменной, два знака `==` **сравнивают** два значения.

<!-- section: examples -->
## Пример 1. Сравнение чисел

```kotlin run
fun main() {
    val age = 17
    println(age >= 18)
    println(age < 18)
    println(age == 17)
    println(age != 17)
    println(2 + 3 == 5)
    println(5 < 5.5)
    println(0.1 + 0.2 == 0.3)
}
```
```output
false
true
true
false
true
true
false
```

Разбор по строкам:

* `age >= 18` - 17 не больше и не равно 18, ответ `false`. Следующая строка задаёт противоположный вопрос.
* `age == 17` истинно, а `age != 17` - его отрицание.
* В `2 + 3 == 5` сначала считается арифметика (приоритет выше), потом сравнение.
* `5 < 5.5` работает, хотя типы разные: операторы порядка допускают смешанные числа.
* В последней строке `false`, потому что `0.1 + 0.2` хранится приближённо и равно `0.30000000000000004`. Сравнивать дробные числа на точное равенство не стоит.

## Пример 2. И, или, не

```kotlin run
fun main() {
    val age = 25
    val hasTicket = true
    println(age >= 18 && hasTicket)
    println(age < 18 || hasTicket)
    println(!hasTicket)
    println(age > 20 && age < 30)
    val isHoliday = true
    val isSick = false
    val hasDeadline = false
    println(isHoliday || isSick && hasDeadline)
    println((isHoliday || isSick) && hasDeadline)
}
```
```output
true
true
false
true
true
false
```

Разбор:

* `age >= 18 && hasTicket` - оба условия истинны, результат `true`.
* `age < 18 || hasTicket` - левая часть ложна, правая истинна. Для `||` достаточно одной.
* `age > 20 && age < 30` - так записывают «возраст между 20 и 30». Цепочку `20 < age < 30` писать нельзя (см. ошибку 1).
* Пятая и шестая строки отличаются только скобками. У `&&` приоритет выше, чем у `||`, поэтому `isHoliday || isSick && hasDeadline` читается как `isHoliday || (isSick && hasDeadline)`: `true || false` = `true`. Со скобками первым вычисляется `isHoliday || isSick` = `true`, затем `true && false` = `false`. Одни и те же значения дают разный ответ.

## Пример 3. Сравнение строк и ленивое вычисление

```kotlin run
fun main() {
    val a = "кот"
    val b = "ко" + "т"
    println(a == b)
    println(a == "Кот")
    println(a.lowercase() == "КОТ".lowercase())
    println("apple" < "banana")
    val divisor = 0
    println(divisor != 0 && 10 / divisor > 2)
    println(divisor == 0 || 10 / divisor > 2)
}
```
```output
true
false
true
true
false
true
```

Разбор:

* `a == b` истинно: `==` сравнивает **содержимое** строк, а не то, как они были получены.
* `a == "Кот"` ложно: регистр букв важен. Чтобы сравнить без учёта регистра, приводят обе строки к одному виду через `lowercase()` (третья строка).
* `"apple" < "banana"` сравнивает строки по алфавиту символ за символом.
* В последних двух строках правая часть содержит деление на ноль. Но программа не падает: если результат уже понятен по левой части, правая **не вычисляется**. В `divisor != 0 && ...` левая часть ложна, и `&&` сразу даёт `false`. В `divisor == 0 || ...` левая часть истинна, и `||` сразу даёт `true`.

**Попробуйте.** В примере 3 поменяйте местами части в `divisor != 0 && 10 / divisor > 2` и посмотрите, что произойдёт. Затем в примере 2 измените `hasDeadline` на `true` и предскажите оба последних вывода до запуска.

## Точные правила

* Сравнения `== != < > <= >=` дают значение типа `Boolean`. Его можно вывести, сохранить в `val` и использовать в других выражениях.
* `==` и `!=` требуют операндов совместимых типов. `1 == 1.0` (`Int` и `Double`) и `"5" == 5` (`String` и `Int`) не компилируются. Операторы `< > <= >=` допускают смешанные числа: `1 < 1.5` верно.
* `==` для строк сравнивает содержимое, с учётом регистра и пробелов. Это отличает Kotlin от Java, где `==` у строк сравнивает ссылки.
* Строки сравниваются операторами порядка посимвольно, по кодам символов. `"apple" < "banana"` истинно; заглавные буквы идут раньше строчных (`"Z" < "a"`).
* `&&` («и») и `||` («или») применяются к `Boolean`. `!` («не») переворачивает значение.
* **Приоритет** от высокого к низкому: `!`, затем арифметика, затем сравнения `< > <= >=`, затем `== !=`, затем `&&`, затем `||`. Скобки меняют порядок. Если приоритет неочевиден, ставьте скобки: они не мешают и помогают читателю.
* Ленивое вычисление: в `a && b` выражение `b` вычисляется, только если `a` истинно; в `a || b` - только если `a` ложно. Поэтому проверку, защищающую от ошибки, ставят слева: `d != 0 && x / d > 1`.
* Цепочки вида `1 < x < 5` не поддерживаются: `1 < x` даёт `Boolean`, и сравнивать его с `5` нельзя. Пишите `x > 1 && x < 5`.
* Присваивание `x = 5` - не выражение: его нельзя использовать внутри условия или печатать. Для сравнения нужен `==`.
* Дробные числа на точное равенство лучше не сравнивать: из-за приближённого хранения `0.1 + 0.2 == 0.3` ложно.

## Типичные ошибки

**1. Цепочка сравнений как в математике.**

```kotlin
fun main() {
    val x = 3
    println(1 < x < 5)
}
```

```text
Main.kt:3:21: error: argument type mismatch: actual type is 'Int', but 'Boolean' was expected.
    println(1 < x < 5)
                    ^
```

Компилятор сначала считает `1 < x`, получает `Boolean`, а затем пытается сравнить его с числом `5`. Напишите две проверки: `x > 1 && x < 5`.

**2. Присваивание вместо сравнения.**

```kotlin
fun main() {
    val x = 3
    val same = (x = 5)
    println(same)
}
```

```text
Main.kt:3:17: error: 'val' cannot be reassigned.
    val same = (x = 5)
                ^
Main.kt:3:17: error: only expressions are allowed in this context.
    val same = (x = 5)
                ^^^^^
```

`x = 5` - присваивание, а не вопрос. Вторая ошибка называет суть: присваивание не выражение, значения у него нет. Для вопроса напишите `x == 5`.

**3. Сравнение значений разных типов.**

```kotlin
fun main() {
    println(1 == 1.0)
}
```

```text
Main.kt:2:13: error: operator '==' cannot be applied to 'Int' and 'Double'.
    println(1 == 1.0)
            ^^^^^^^^
```

`Int` и `Double` - разные типы, и `==` для них не определён. Приведите одно значение к типу другого: `1.toDouble() == 1.0`. Так же не сравниваются текст и число:

```kotlin
fun main() {
    println("5" == 5)
}
```

```text
Main.kt:2:13: error: operator '==' cannot be applied to 'String' and 'Int'.
    println("5" == 5)
            ^^^^^^^^
```

Если число пришло как текст из `readln()`, сначала вызовите `toInt()`.

**4. Число вместо `Boolean`.**

```kotlin
fun main() {
    val ok: Boolean = 1
    println(ok)
}
```

```text
Main.kt:2:21: error: initializer type mismatch: expected 'Boolean', actual 'Int'.
    val ok: Boolean = 1
                    ^
```

В Kotlin `1` и `0` не означают «да» и «нет». Логическое значение пишут словами `true` и `false` или получают сравнением.

**5. Отрицание числа.**

```kotlin
fun main() {
    val x = 3
    println(!x)
}
```

```text
Main.kt:3:13: error: unresolved reference 'not' for operator '!' on receiver of type 'Int'.
    println(!x)
            ^
```

Оператор `!` переворачивает только `Boolean`. Чтобы проверить, что число не равно нулю, напишите `x != 0`.

**6. Защита поставлена справа.**

```kotlin
fun main() {
    val a = 0
    println(10 / a > 2 && a != 0)
}
```

```text
Exception in thread "main" java.lang.ArithmeticException: / by zero
	at MainKt.main(Main.kt:3)
```

Здесь деление на ноль выполняется раньше проверки, потому что левая часть вычисляется первой. Поменяйте части: `a != 0 && 10 / a > 2`. (Показан главный фрагмент сообщения; в полном есть ещё строка со стеком.)

## Итоги

* Сравнения `==`, `!=`, `<`, `>`, `<=`, `>=` дают `Boolean`: `true` или `false`.
* `&&` («и»), `||` («или») и `!` («не») объединяют ответы. У `&&` приоритет выше, чем у `||`; неочевидный порядок задают скобками.
* `==` сравнивает содержимое строк с учётом регистра. `=` присваивает, `==` сравнивает.
* `&&` и `||` вычисляют правую часть только при необходимости; проверку, защищающую от ошибки, ставят слева.

Получив ответ «да» или «нет», программа сможет выбрать, какое действие выполнить. Это делает оператор `if`, которому посвящён следующий урок: [Условия: if и else](lesson:kotlin.from-zero.if-else).

<!-- section: programmer -->
## Для тех, кто уже программирует

* `==` в Kotlin - структурное равенство (вызывает `equals`), в отличие от Java, где `==` у ссылок сравнивает идентичность. Идентичность в Kotlin проверяют отдельным оператором `===`.
* Сравнение `Int` с `Double` через `==` не компилируется, как и `Int` с `Long`; это строже, чем в Java/C# (там происходит неявное расширение) и строже, чем в JavaScript (`==` с приведением типов, `===` без).
* Нет «истинных» и «ложных» значений: `if (1)` или `if (list)` невозможно, условие обязано быть `Boolean`. В Python и JavaScript это допустимо.
* `&&` и `||` ленивы, как в C-подобных языках. Версии без ленивости - инфиксные функции `and`, `or`, `xor` для `Boolean` (и побитовые для целых).
* Нет тернарного оператора `?:` в смысле C: роль условного выражения играет `if` как выражение (см. следующие уроки), а `?:` в Kotlin - оператор для `null` (урок 18).
* Строки сравниваются через `compareTo`, посимвольно по значениям UTF-16, без учёта локали. Для сравнения без регистра есть `equals(other, ignoreCase = true)`.
* Цепочка `a < b < c` не поддерживается. Проверка принадлежности диапазону `x in 1..5` появится в уроке о диапазонах.
