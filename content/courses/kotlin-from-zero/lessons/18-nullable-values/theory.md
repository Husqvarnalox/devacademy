## Когда значения может не быть

В жизни нередко бывает, что ответа нет: пользователь ввёл вместо числа слово «абв», строка в списке пустая, ввод закончился. До сих пор мы это не учитывали. Если текст `"абв"` превратить в число командой `toInt()`, программа упадёт с ошибкой, а если ввод закончился, упадёт `readln()`.

Хотелось бы иметь честный способ сказать: «число получилось» или «числа нет». В Kotlin для этого существуют **типы, допускающие отсутствие значения**. Они помечаются вопросительным знаком: `Int?` читается «`Int` или ничего». Значение «ничего» записывается словом `null`.

## Одна новая идея: тип с `?` может хранить значение или `null`

* `Int` - число, которое **есть всегда**. Положить в такую переменную `null` нельзя.
* `Int?` - число **или** `null`. Перед использованием нужно убедиться, что значение есть.

Самый частый источник таких значений - безопасное преобразование:

* `"42".toIntOrNull()` даёт `42`, а `"абв".toIntOrNull()` даёт `null` вместо падения программы;
* `readlnOrNull()` читает строку, как `readln()`, но на конце ввода возвращает `null`.

Чтобы работать с таким значением, есть два инструмента: проверка `x == null` («значения нет») и оператор `?:` («если слева `null`, взять значение справа»). Его называют *элвис-оператором*: если повернуть голову, `?:` похож на причёску Элвиса.

## Пример 1. `toIntOrNull` и `?:`

```kotlin run
fun main() {
    val a = "42".toIntOrNull()
    val b = "abc".toIntOrNull()
    println(a)
    println(b)
    val x: Int? = null
    println(x)
    println(x == null)
    println(b ?: -1)
    val total = (a ?: 0) + (b ?: 0)
    println("Итого: $total")
    println("4.5".toIntOrNull())
    println("".toIntOrNull())
    println(" 7".toIntOrNull())
}
```
```output
42
null
null
true
-1
Итого: 42
null
null
null
```

Разбор:

* `a` содержит число 42, `b` - `null`: текст `abc` не является числом.
* Переменную типа `Int?` создают, указав тип явно: `val x: Int? = null`. `println(x)` печатает слово `null`.
* `x == null` проверяет, пусто ли значение. Выражение `b ?: -1` читается «`b`, а если `b` пусто, то `-1`». Так задают значение по умолчанию.
* В `(a ?: 0) + (b ?: 0)` скобки обязательны: каждое необязательное число заменяется нулём, если его нет, и только потом выполняется сложение.
* `toIntOrNull()` строго требует целое число: `4.5`, пустая строка и текст с пробелом (`" 7"`) тоже дают `null`. Пробелы можно убрать заранее через `trim()` (его покажет урок о строках).

## Пример 2. `readlnOrNull` и проверка на `null`

В примере ввод пуст (программа запускается без данных), поэтому `readlnOrNull()` возвращает `null`.

```kotlin run
fun main() {
    val line = readlnOrNull()
    println(line)
    val name = readlnOrNull() ?: "гость"
    println("Привет, $name")
    val text: String? = "кот"
    if (text == null) {
        println("текста нет")
    } else {
        println("Длина: ${text.length}")
    }
}
```
```output
null
Привет, гость
Длина: 3
```

Разбор:

* Ввода нет, поэтому первый вызов даёт `null`. Обычный `readln()` в этом месте упал бы с `ReadAfterEOFException`.
* `readlnOrNull() ?: "гость"` подставляет значение по умолчанию.
* Проверка `text == null` позволяет безопасно обратиться к значению в другой ветке: после проверки Kotlin знает, что в блоке `else` строка существует, и разрешает вызвать `text.length`. Подробно этот механизм разберёт курс «Kotlin: первые шаги».

## Пример 3. Чтение до конца ввода

Теперь можно читать ввод любой длины. Цикл `while (true)` продолжается, пока строки есть; когда `readlnOrNull()` возвращает `null`, конструкция `?: break` выходит из цикла. Эта программа читает ввод, поэтому показана без запуска.

```kotlin
fun main() {
    var sum = 0
    var bad = 0
    while (true) {
        val line = readlnOrNull() ?: break
        val number = line.toIntOrNull()
        if (number == null) {
            bad += 1
        } else {
            sum += number
        }
    }
    println("Сумма: $sum, некорректных: $bad")
}
```

Для ввода

```text
10
abc
5
7.5
```

программа напечатает `Сумма: 15, некорректных: 2`.

Разбор:

* `val line = readlnOrNull() ?: break` читается так: «прочитай строку; если её нет, выйди из цикла». Справа от `?:` может стоять и команда `break`, и значение.
* Строки `abc` и `7.5` не являются целыми числами, поэтому для них `toIntOrNull()` даёт `null`. Они не учитываются в сумме, а счётчик `bad` увеличивается.
* Программа корректно работает на любом количестве строк, в том числе на пустом вводе: тогда напечатается `Сумма: 0, некорректных: 0`.

**Попробуйте.** В примере 1 замените `"abc"` на `"17"` и посмотрите, как изменятся ответы. Затем в примере 3 добавьте счётчик корректных чисел `good` и напечатайте его.

## Точные правила

* `Тип?` - тип, допускающий `null`. `Int`, `String`, `Boolean` без вопросительного знака `null` не принимают.
* `null` - единственное значение, означающее «значения нет». Его нельзя ни сложить, ни сравнить по порядку с числом.
* `toIntOrNull()` возвращает `Int?`: число или `null`, если строку нельзя полностью разобрать как целое десятичное число (допустим знак `-` или `+`). Аналоги: `toDoubleOrNull()`, `toLongOrNull()`.
* `readlnOrNull()` возвращает `String?`: строка или `null` на конце ввода. Пустая строка (пользователь нажал Enter) - это не `null`, а строка длины 0.
* `x == null` и `x != null` - проверки наличия значения. Они работают с любым необязательным типом.
* `a ?: b` даёт `a`, если оно не `null`, иначе `b`. Результат имеет тип без вопросительного знака, если `b` его не допускает: `val n: Int = text.toIntOrNull() ?: 0` допустимо. Справа могут стоять `break`, `continue` и `return`.
* К значению типа `Int?` нельзя применять арифметику, а у `String?` нельзя обращаться к `length`, пока нет проверки или значения по умолчанию. Это и есть защита: ошибка обнаруживается при компиляции, а не при работе программы.
* Прочие инструменты (безопасный вызов `?.`, утверждение `!!`) разбираются в курсе «Kotlin: первые шаги» и в fundamentals.

## Типичные ошибки

**1. `null` в обычной переменной.**

```kotlin
fun main() {
    val x: Int = null
    println(x)
}
```

```text
Main.kt:2:18: error: null cannot be a value of a non-null type 'Int'.
    val x: Int = null
                 ^^^^
```

Тип `Int` обещает, что число есть всегда. Если значение может отсутствовать, объявите `Int?`.

**2. Арифметика с необязательным числом.**

```kotlin
fun main() {
    val a = "5".toIntOrNull()
    println(a + 1)
}
```

```text
Main.kt:3:15: error: operator call is prohibited on a nullable receiver of type 'Int?'. Use '?.'-qualified call instead.
    println(a + 1)
              ^
```

`a` может быть `null`, а `null + 1` смысла не имеет. Подставьте значение по умолчанию: `(a ?: 0) + 1`, либо сначала проверьте `a != null`.

**3. Необязательное значение в обычную переменную.**

```kotlin
fun main() {
    val n: Int = "5".toIntOrNull()
    println(n)
}
```

```text
Main.kt:2:16: error: initializer type mismatch: expected 'Int', actual 'Int?'.
    val n: Int = "5".toIntOrNull()
               ^
```

`toIntOrNull()` может вернуть `null`, а переменная `Int` его не примет. Напишите `val n: Int = "5".toIntOrNull() ?: 0`.

**4. Обращение к необязательной строке.**

```kotlin
fun main() {
    val s = readlnOrNull()
    println(s.length)
}
```

```text
Main.kt:3:14: error: only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type 'String?'.
    println(s.length)
             ^
```

Если ввод закончился, `s` равно `null`, и обращаться к длине нельзя. Проверьте `s == null` или подставьте значение: `(s ?: "").length`.

**5. Присвоение `String?` обычной строке.**

```kotlin
fun main() {
    val line: String = readlnOrNull()
    println(line)
}
```

```text
Main.kt:2:22: error: initializer type mismatch: expected 'String', actual 'String?'.
    val line: String = readlnOrNull()
                     ^
```

Исправление: `readlnOrNull() ?: ""` либо `readlnOrNull() ?: break` внутри цикла. Компилятор не даёт «забыть» про отсутствующее значение.

## Итоги

* `Int?`, `String?` - типы, допускающие `null` («значения нет»). Обычные типы `null` не принимают.
* `toIntOrNull()` вместо падения возвращает `null`; `readlnOrNull()` возвращает `null` на конце ввода.
* `x == null` проверяет отсутствие значения, `a ?: b` подставляет значение по умолчанию.
* `val line = readlnOrNull() ?: break` в цикле `while (true)` читает ввод до конца.
* Компилятор не позволяет работать с необязательным значением, не обработав `null`: ошибок вроде «NullPointerException» из-за забытой проверки у вас не будет.

Теперь можно хранить много значений сразу: [Списки](lesson:kotlin.from-zero.lists).

## Для тех, кто уже программирует

* В Kotlin `null` входит в систему типов: `String` и `String?` - разные типы. Компилятор отслеживает проверки, поэтому `NullPointerException` в чистом Kotlin практически невозможен (остаются `!!` и взаимодействие с Java).
* `?:` - «элвис-оператор», аналог `??` из C#/JavaScript и `||` из JavaScript (но только для `null`, а не для «ложных» значений). Справа допустимы `return`, `break`, `continue` и `throw`.
* `toIntOrNull()` похож на `int.TryParse` в C# или `Integer.parseInt` с обработкой исключения в Java, но возвращает значение, а не использует выходной параметр. Он не принимает пробелы и дробные числа.
* `readlnOrNull()` соответствует `readLine()` из старых версий Kotlin и `BufferedReader.readLine()` из Java: тоже `null` на конце ввода.
* После проверки `if (x == null) ... else ...` Kotlin автоматически приводит `x` к необязательному типу без `?` в ветке `else` (*smart cast*). Подробности, оператор `?.` и `!!` - в «Kotlin: первые шаги».
* Тип `Int?` на JVM хранится как объект `Integer`, а `Int` - как примитив `int`, если компилятор может это сделать. На работу с кодом это не влияет, но в больших коллекциях бывает заметно.
