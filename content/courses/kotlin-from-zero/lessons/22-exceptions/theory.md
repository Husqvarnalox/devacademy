## Когда программа не может продолжить

Вы уже видели, что программа иногда аварийно завершается: `"abc".toInt()` или обращение к элементу списка за границей. Это не «поломка компьютера», а **исключение** - сигнал, который программа или библиотека подаёт, когда не может выполнить действие. Если ничего не делать, исключение останавливает программу и печатает сообщение.

Но в реальных задачах плохой ввод - обычное событие: пользователь ввёл слово вместо числа. Ожидать, что такого никогда не произойдёт, нельзя. Нужен способ сказать программе: «попробуй выполнить это, а если случится вот такая ошибка, сделай вот что».

## Одна новая идея: `try` пробует, `catch` перехватывает исключение определённого вида

Запись:

```kotlin
try {
    // код, который может завершиться исключением
} catch (e: ВидИсключения) {
    // что делать, если исключение случилось
}
```

Если в блоке `try` всё прошло хорошо, блок `catch` пропускается. Если случилось исключение подходящего вида, остаток блока `try` не выполняется, управление передаётся в `catch`, и после него программа **продолжается**. Переменная `e` содержит описание исключения, например `e.message` - его текст.

Своё исключение выбрасывают командой `throw`: `throw IllegalArgumentException("текст")`. Так функция сообщает, что ей передали неверное значение.

<!-- section: examples -->
## Пример 1. Перехват ошибки разбора

```kotlin run
fun main() {
    try {
        val n = "abc".toInt()
        println("Число: $n")
    } catch (e: NumberFormatException) {
        println("Не число")
    }
    println("Программа продолжается")
}
```
```output
Не число
Программа продолжается
```

Разбор:

* `"abc".toInt()` бросает `NumberFormatException`. Строка `println("Число: $n")` внутри `try` уже не выполняется.
* Управление переходит в `catch`, который подходит по виду исключения. После блока программа идёт дальше, и последняя строка печатается.

## Пример 2. `throw` и текст исключения

```kotlin run
fun checkAge(age: Int): Int {
    if (age < 0 || age > 120) {
        throw IllegalArgumentException("возраст вне диапазона 0..120: $age")
    }
    return age
}

fun main() {
    try {
        println(checkAge(30))
        println(checkAge(200))
        println("сюда не дойдём")
    } catch (e: IllegalArgumentException) {
        println("Ошибка: ${e.message}")
    }
    try {
        "12x".toInt()
    } catch (e: NumberFormatException) {
        println("Ошибка: ${e.message}")
    }
}
```
```output
30
Ошибка: возраст вне диапазона 0..120: 200
Ошибка: For input string: "12x"
```

Разбор:

* Функция `checkAge` сама проверяет значение и выбрасывает `IllegalArgumentException` («недопустимый аргумент») с понятным текстом.
* Первый вызов проходит, второй бросает исключение. Строка «сюда не дойдём» не печатается: после `throw` выполнение блока `try` прекращается.
* `e.message` - текст исключения. У `toInt()` он содержит строку, которую не удалось разобрать.

## Пример 3. Несколько `catch` и `try` как выражение

```kotlin run
fun divide(a: Int, b: Int): Int = a / b

fun main() {
    val inputs = listOf("10", "0", "x")
    for (text in inputs) {
        try {
            val d = text.toInt()
            println("100 / $d = ${divide(100, d)}")
        } catch (e: NumberFormatException) {
            println("$text - не число")
        } catch (e: ArithmeticException) {
            println("На ноль делить нельзя")
        }
    }
    val safe = try {
        "7".toInt()
    } catch (e: NumberFormatException) {
        -1
    }
    println(safe)
}
```
```output
100 / 10 = 10
На ноль делить нельзя
x - не число
7
```

Разбор:

* У одного `try` может быть несколько `catch` для разных видов исключений. Целочисленное деление на 0 бросает `ArithmeticException`, а плохой текст - `NumberFormatException`.
* Исключение не прекращает цикл: после перехвата выполняется следующая итерация.
* `try` можно использовать как выражение: значением становится последнее выражение блока, который отработал. Здесь при успешном разборе `safe` равно 7, а при ошибке было бы -1.

**Чтение с проверкой.** Программа, которая спрашивает возраст и не падает на плохом вводе, показана без запуска:

```kotlin
fun main() {
    val text = readln()
    try {
        val age = text.toInt()
        println("Возраст: $age")
    } catch (e: NumberFormatException) {
        println("Нужно ввести число")
    }
}
```

Для ввода `42` она напечатает `Возраст: 42`, а для ввода `сорок` - `Нужно ввести число`.

**Попробуйте.** В примере 1 замените `"abc"` на `"42"` и посмотрите, какие строки напечатаются. Затем в примере 2 вызовите `checkAge(-1)` и сравните сообщение.

## Точные правила

* Исключение - объект, который описывает ошибку. Если его не перехватить, программа завершается и печатает вид исключения, сообщение и стек вызовов.
* В `try` можно писать любой код. При первом исключении остаток блока пропускается.
* После `catch (e: Вид)` указывают тип исключения; блок срабатывает только для этого вида (и его частных случаев).
* Если вид не совпал, исключение продолжает подниматься и может остановить программу. Блок `catch` с неподходящим видом ничего не перехватывает.
* `NumberFormatException` является частным случаем `IllegalArgumentException`, поэтому при двух `catch` более частный вид пишут выше общего: подходящим считается первый подходящий блок.
* Часто встречаются `NumberFormatException` (плохой текст для `toInt()`), `ArithmeticException` (деление на 0), `IndexOutOfBoundsException` (индекс вне списка), `IllegalArgumentException` (недопустимый аргумент).
* `throw` выбрасывает исключение. Конструкторы принимают текст: `IllegalArgumentException("текст")`; доступ к нему через `e.message`. Тип `e.message` - nullable (`String?`), но при печати в шаблоне это не мешает.
* `try` может быть выражением, как `if`: значение берётся из последнего выражения выполненного блока.
* Исключения - для действительно исключительных ситуаций. Если проверка простая (`toIntOrNull()` из прошлого урока), её предпочтительнее исключения.

## Типичные ошибки

**1. Не перехваченное исключение.**

```kotlin
fun checkAge(age: Int): Int {
    if (age < 0) {
        throw IllegalArgumentException("возраст отрицательный: $age")
    }
    return age
}

fun main() {
    println(checkAge(10))
    println(checkAge(-5))
    println("конец")
}
```

```text
10
Exception in thread "main" java.lang.IllegalArgumentException: возраст отрицательный: -5
	at MainKt.checkAge(Main.kt:3)
	at MainKt.main(Main.kt:10)
	at MainKt.main(Main.kt)
```

Строка «конец» не напечатана: программа завершилась на исключении. Стек читают снизу вверх: `main` вызвала `checkAge` в строке 10, а `throw` стоит в строке 3.

**2. `try` без `catch`.**

```kotlin
fun main() {
    try {
        println("a".toInt())
    }
}
```

```text
Main.kt:4:6: error: syntax error: Expecting 'catch' or 'finally'.
    }
     ^
```

Блок `try` обязан иметь `catch` (или `finally`, о котором здесь не говорится).

**3. Неподходящий вид исключения.**

```kotlin
fun main() {
    try {
        println(10 / 0)
    } catch (e: NumberFormatException) {
        println("не число")
    }
}
```

```text
Exception in thread "main" java.lang.ArithmeticException: / by zero
	at MainKt.main(Main.kt:3)
	at MainKt.main(Main.kt)
```

Деление на 0 бросает `ArithmeticException`, а перехватывается только `NumberFormatException`, поэтому блок `catch` не сработал.

**4. `throw` не исключения.**

```kotlin
fun main() {
    throw "ошибка"
}
```

```text
Main.kt:2:11: error: type mismatch: inferred type is 'String', but 'Throwable' was expected.
    throw "ошибка"
          ^^^^^^^^
```

Выбрасывать можно только исключение: `throw IllegalArgumentException("ошибка")`. Текст - это аргумент конструктора.

**5. Пропущен вид исключения.**

```kotlin
fun main() {
    try {
        println("a".toInt())
    } catch {
        println("ошибка")
    }
}
```

```text
Main.kt:4:12: error: syntax error: Expecting exception variable declaration.
    } catch {
           ^
```

После `catch` нужны скобки с переменной и видом: `catch (e: NumberFormatException)`.

## Итоги

* Исключение - сигнал об ошибке, который останавливает программу, если его не перехватить.
* `try { ... } catch (e: Вид) { ... }` выполняет код и при исключении нужного вида переходит в `catch`; после блока программа продолжается.
* `throw IllegalArgumentException("текст")` сообщает о недопустимом значении; `e.message` даёт текст.
* Несколько `catch` перехватывают разные виды; блок выбирается по виду исключения.
* Для простых проверок предпочтительнее `toIntOrNull()` и обычные условия, а исключения оставляют для действительно неожиданных ситуаций.

Исключения закрывают тему ошибок ввода. Остался вопрос, как собирать связанные данные и действия над ними в одно целое: [Первый класс](lesson:kotlin.from-zero.first-class).

## Для тех, кто уже программирует

* Исключения в Kotlin **непроверяемые**: нет `throws` и нет обязательного `catch`, в отличие от Java. Компилятор не заставит перехватывать.
* `try`/`catch`/`finally` как в Java; отличие в том, что `try` - выражение, как и `if`. `NumberFormatException` и `ArithmeticException` те же классы JVM.
* Привычный способ избегать исключений в Kotlin - функции `...OrNull` (`toIntOrNull`), обычные проверки и `require(условие) { "сообщение" }`, который бросает `IllegalArgumentException`. Исключение как поток управления считается плохой практикой.
* Деление целых на 0 бросает `ArithmeticException`, а деление `Double` на 0 даёт `Infinity` или `NaN`, как в JS и Java.
* `e.message` может быть `null`, потому что тип `String?`; в шаблонах это не ломается.
* Стек вызовов по формату совпадает с Java; имена `MainKt` и `Main.kt` - следствие того, как компилируется `main`.
* Корутины, `Result`, `runCatching` и собственные классы исключений разбираются в `kotlin-fundamentals`.
