## Когда цикл нужно остановить раньше или пропустить шаг

Обычный цикл идёт до конца: пока условие истинно или пока не перебран весь диапазон. Но реальные задачи часто устроены иначе. Найдя нужный товар в списке, незачем смотреть остальные. Встретив неверную оценку, её нужно пропустить, а остальные учесть. Для таких случаев в цикле есть две команды.

## Одна новая идея: две команды управляют ходом цикла

* `break` («прервать») немедленно заканчивает **весь цикл**. Программа продолжает работу со строки после цикла.
* `continue` («продолжить») заканчивает **текущую итерацию**: остаток тела пропускается, и цикл переходит к следующему шагу (для `while` - к проверке условия, для `for` - к следующему значению).

Обе команды обычно стоят внутри `if`: «если нашли - прервать», «если шаг не нужен - пропустить».

Циклы можно вкладывать друг в друга. Такая конструкция называется **вложенными циклами**: внешний цикл на каждой своей итерации запускает внутренний цикл целиком. Так печатают таблицы по строкам и столбцам.

## Пример 1. `break` и `continue`

```kotlin run
fun main() {
    for (i in 50..100) {
        if (i % 7 == 0) {
            println("Первое кратное 7: $i")
            break
        }
    }
    for (i in 1..10) {
        if (i % 2 == 0) continue
        print("$i ")
    }
    println()
    var attempts = 0
    while (true) {
        attempts += 1
        if (attempts * attempts > 50) break
    }
    println("Попыток: $attempts")
}
```
```output
Первое кратное 7: 56
1 3 5 7 9 
Попыток: 8
```

Разбор:

* В первом цикле перебираются числа с 50. Как только найдено кратное 7 (это 56), печатается сообщение и `break` прекращает перебор, хотя диапазон доходит до 100.
* Во втором цикле на чётных числах срабатывает `continue`: оставшаяся часть тела (`print`) пропускается. Печатаются только нечётные.
* `while (true)` - условие, которое никогда не ложно. Такой цикл заканчивается только по `break`. Здесь он останавливается, когда квадрат числа попыток превысит 50 (8 * 8 = 64).

## Пример 2. Вложенные циклы

```kotlin run
fun main() {
    for (row in 1..3) {
        for (col in 1..4) {
            print("$row$col ")
        }
        println()
    }
    for (i in 1..4) {
        for (j in 1..i) print("*")
        println()
    }
}
```
```output
11 12 13 14 
21 22 23 24 
31 32 33 34 
*
**
***
****
```

Разбор:

* Для каждой строки `row` внутренний цикл печатает четыре «ячейки»; после него `println()` переходит на следующую строку. Тело внутреннего цикла выполняется 3 * 4 = 12 раз.
* Во втором примере граница внутреннего цикла зависит от внешнего (`1..i`): в строке номер `i` печатается `i` звёздочек.

## Пример 3. `break` во вложенных циклах

```kotlin run
fun main() {
    for (i in 1..3) {
        for (j in 1..3) {
            if (j == 2) break
            println("i=$i j=$j")
        }
    }
    var found = false
    for (a in 1..9) {
        for (b in 1..9) {
            if (a * b == 42) {
                println("$a x $b = 42")
                found = true
                break
            }
        }
        if (found) break
    }
}
```
```output
i=1 j=1
i=2 j=1
i=3 j=1
6 x 7 = 42
```

Разбор:

* `break` прерывает только **ближайший** цикл, то есть внутренний. Внешний продолжает работать: поэтому строки выводятся для всех трёх значений `i`, но каждый раз только с `j=1`.
* Чтобы выйти из обоих циклов, используют переменную-флаг: `found` меняется внутри, и после внутреннего цикла проверка `if (found) break` останавливает внешний.

**Попробуйте.** В примере 1 замените `continue` на `break` и предскажите вывод второго цикла. В примере 2 измените количество столбцов и убедитесь, что тело внутреннего цикла выполняется `строки * столбцы` раз.

## Точные правила

* `break` и `continue` допустимы только внутри цикла (`while`, `for`). За его пределами компилятор сообщает об ошибке.
* `break` относится к ближайшему внешнему по отношению к команде циклу. После него выполнение идёт со следующей за этим циклом команды.
* `continue` пропускает остаток тела. В `for` следующая итерация берёт следующее значение, в `while` управление возвращается к проверке условия.
* В цикле `while` перед `continue` нужно успеть изменить переменную, от которой зависит условие, иначе получится бесконечный цикл.
* `while (true)` с `break` внутри - обычный приём, когда момент остановки известен только в середине тела.
* Число выполнений тела вложенного цикла равно произведению: внутренний цикл выполняется заново на каждой итерации внешнего.
* Имена переменных во вложенных циклах должны различаться (`row` и `col`, `i` и `j`).
* Перед глубокой вложенностью стоит остановиться: вложенность в три и более уровня читается плохо, и логику чаще выносят в функцию (урок 17).

## Типичные ошибки

**1. `break` вне цикла.**

```kotlin
fun main() {
    val x = 5
    if (x > 3) {
        break
    }
    println(x)
}
```

```text
Main.kt:4:9: error: 'break' and 'continue' are only allowed inside loops.
        break
        ^^^^^
```

Команда `if` не является циклом. Чтобы просто завершить программу или пропустить часть кода, используйте условие, а не `break`.

**2. `continue` до изменения счётчика.**

```kotlin
fun main() {
    var i = 0
    while (i < 5) {
        if (i == 2) continue
        i += 1
        println(i)
    }
}
```

Программа печатает

```text
1
2
```

и зависает. При `i == 2` срабатывает `continue`, управление возвращается к проверке условия, но `i` по-прежнему равно 2 - строка `i += 1` обходится стороной, и так повторяется бесконечно. Увеличение счётчика нужно поставить **до** `continue` либо использовать `for`, в котором значение меняется само.

**3. `break` останавливает не тот цикл.** Ошибки компиляции нет, но результат неожиданный: во вложенных циклах `break` прерывает только внутренний, как показано в примере 3. Если нужно выйти сразу из обоих, добавьте флаг или вынесите поиск в функцию.

**4. Условие в `while (true)` без `break`.** Цикл без выхода не завершится никогда. Прежде чем писать `while (true)`, найдите в теле команду `break`, которая обязательно сработает.

<!-- section: summary -->
## Итоги

* `break` прерывает цикл целиком, `continue` пропускает остаток текущей итерации.
* Обе команды допустимы только внутри цикла и обычно стоят под `if`.
* Во вложенных циклах `break` и `continue` действуют на ближайший внутренний цикл. Для выхода из обоих помогает флаг.
* В `while` перед `continue` нужно обновить счётчик, иначе цикл становится бесконечным.

Циклы, `if` и `when` уже позволяют писать длинные программы. Чтобы они не превращались в один огромный `main`, повторяющиеся действия оформляют отдельными именованными блоками: [Функции](lesson:kotlin.from-zero.functions).

<!-- section: programmer -->
## Для тех, кто уже программирует

* `break` и `continue` работают как в Java, C и JavaScript. Как и там, они действуют на ближайший цикл.
* В Kotlin есть метки для выхода из внешнего цикла: `outer@ for (...) { ... break@outer }`. Это замена `goto`, которого в языке нет.
* Цикла с `else`, как в Python (`for ... else`), нет; аналог получают флагом или поиском в функции с досрочным `return`.
* `while (true) { ... break ... }` - стандартная замена `do { } while` и `loop {}` в тех случаях, когда условие выхода проверяется в середине тела.
* Внутри `when` команда `break` относится к окружающему циклу (если он есть), а не к самому `when`. Проваливаться и прерывать `when` не нужно.
* В лямбдах `forEach { }` команды `break` и `continue` неприменимы (в новых версиях Kotlin допустимы в inline-лямбдах как нелокальные); для досрочного выхода предпочитают обычный `for`.

## Метки: выход из внешнего цикла

Это необязательный раздел. Метка - имя, которое вы даёте циклу, записывая его перед ключевым словом и знаком `@`. Тогда `break@имя` прерывает именно этот цикл, даже если команда находится во вложенном.

```kotlin run
fun main() {
    outer@ for (a in 1..9) {
        for (b in 1..9) {
            if (a * b == 42) {
                println("$a x $b = 42")
                break@outer
            }
        }
    }
}
```
```output
6 x 7 = 42
```

Результат тот же, что в примере 3, но без переменной-флага. Метки удобны, когда вложенность нельзя убрать. Если же вы часто пользуетесь ими, это признак, что поиск лучше вынести в отдельную функцию.
