## Что проверяет эта проверка

Объявления типов и `declare(strict_types=1)`, `TypeError`, различие `==` и `===`, приведение `(int)` и `(bool)`, `filter_var`, `get_debug_type` и `var_export`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Массивы как упорядоченные словари и declare(strict_types=1)](lesson:php.first-steps.arrays-and-strict-types), [Типы, strict_types и приведение типов](lesson:php.fundamentals.types-and-juggling).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```php run
<?php
declare(strict_types=1);

function double(int $n): int
{
    return $n * 2;
}

echo double(21), "\n";
try {
    echo double("21"), "\n";
} catch (TypeError $e) {
    echo "TypeError\n";
}
var_dump("5" + 3, "5" . 3, 0 == "a", "10" == "1e1", "10" === "1e1");
var_dump((int) "12abc", (bool) "0", filter_var("abc", FILTER_VALIDATE_INT));
```
```output
42
TypeError
int(8)
string(2) "53"
bool(false)
bool(true)
bool(false)
int(12)
bool(false)
bool(false)
```

С `declare(strict_types=1)` вызов функции с строкой вместо `int` приводит к `TypeError`, но арифметика и сравнение от этого режима не зависят: `"5" + 3` остаётся `8`. Нестрогое `==` приводит операнды к общему типу (`"10" == "1e1"` истинно, потому что обе строки числовые), а `===` сравнивает тип и значение. Приведение `(int)` не проверяет ввод, а `filter_var` возвращает `false` для текста, который не является числом.

<!-- section: precise -->
## Что нужно уметь

* объяснять, чьи вызовы проверяет `declare(strict_types=1)` (вызовы из файла, где он объявлен) и что он не влияет на арифметику и сравнение;
* читать объявления `int`, `?string`, `int|float`, `mixed` и предсказывать `TypeError` для конкретного аргумента;
* называть результат `==` для `0 == "a"`, `"1" == "01"`, `"10" == "1e1"`, `null == false` и знать, почему в курсе используется `===`;
* приводить значения: `(int)`, `(bool)`, `(string)`, понимать, что `"0"` ложно, а `"0.0"` истинно;
* разбирать пользовательский ввод через `filter_var` с `FILTER_VALIDATE_INT` и `FILTER_VALIDATE_FLOAT`;
* определять тип значения через `get_debug_type` и печатать значения через `var_export`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Ожидание, что `strict_types` запретит `"5" + 3`: режим касается только вызовов функций и значений `return`.
* `(int) "abc"` даёт `0` без предупреждения: приведение не проверяет, что в строке число.
* Сравнение `if ($x == "")` истинно и для `0`, и для `null`, и для `false`; используйте `===`.
* Убеждённость, что `"abc" == 0` истинно: в PHP 8 это ложь, но от нестрогого сравнения всё равно лучше отказаться.
* `(bool) "0.0"` истинно: ложной считается только строка `"0"` и пустая строка.
