## Что проверяет эта проверка

Классы с первичным конструктором и свойствами, `data class` (`equals`, `toString`, `copy`, деструктуризация), `sealed class`, `object`, исчерпывающий `when` без `else`, умное приведение в `is`-ветках, свойства вне конструктора и их влияние на `equals`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок: [Классы, data-классы, sealed и when](lesson:kotlin.fundamentals.classes-sealed-and-when).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```kotlin run
sealed class Shape
data class Rect(val w: Int, val h: Int) : Shape()
data class Square(val side: Int) : Shape()
object Empty : Shape() {
    override fun toString() = "Empty"
}

fun area(s: Shape): Int = when (s) {
    is Rect -> s.w * s.h
    is Square -> s.side * s.side
    Empty -> 0
}

fun main() {
    val shapes = listOf(Rect(2, 3), Square(4), Empty, Rect(2, 3))
    for (s in shapes) {
        println("$s -> ${area(s)}")
    }
    println(Rect(2, 3) == Rect(2, 3))
    println(Rect(2, 3).copy(h = 10))
    println(shapes.toSet().size)
}
```
```output
Rect(w=2, h=3) -> 6
Square(side=4) -> 16
Empty -> 0
Rect(w=2, h=3) -> 6
true
Rect(w=2, h=10)
3
```
`sealed class` ограничивает список наследников: компилятор знает все варианты, поэтому `when` без `else` исчерпывающий, а добавление нового варианта сразу даёт ошибку в каждом неполном `when`. В ветке `is Rect` значение `s` уже имеет тип `Rect` (smart cast). Data-классы сравниваются по свойствам конструктора, поэтому множество склеивает одинаковые прямоугольники.

## Что нужно уметь

* объявлять класс с первичным конструктором и свойствами `val` и `var`;
* объяснять, что `data class` генерирует `equals`, `hashCode`, `toString`, `copy` и `componentN`, и что учитываются только свойства первичного конструктора;
* писать `sealed class` и наследников и обрабатывать их `when` без `else`;
* использовать `object` для единственного экземпляра и сравнивать его без `is`;
* понимать, что `copy` поверхностный и что классы по умолчанию `final`;
* предсказывать результат `==` для обычного класса, data-класса и ссылок.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Сравнивать обычные классы через `==` и ждать равенства по содержимому: без `equals` сравниваются ссылки.
* Свойство в теле data-класса не участвует в `equals`, `hashCode` и `toString`.
* `when` над sealed-типом без одной из веток не компилируется, если используется как выражение.
* Добавлять `else` в `when` над sealed-типом: ошибка о новом варианте перестаёт срабатывать.
* Ждать, что `copy()` скопирует вложенный изменяемый список: он общий для оригинала и копии.
