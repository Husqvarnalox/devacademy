## Что проверяет эта проверка

Лямбды и функции высшего порядка, `filter`, `map`, `fold`, `groupBy`, `partition`, `sortedBy`, `first`, последовательности `sequenceOf` и `generateSequence`, ленивое и жадное вычисление, read-only и изменяемые интерфейсы коллекций.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок: [Коллекции, функции высшего порядка и последовательности](lesson:kotlin.fundamentals.collections-and-sequences).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```kotlin run
fun main() {
    val nums = listOf(5, 12, 7, 20, 3)
    println(nums.filter { it > 4 }.map { it * 2 })
    println(nums.fold(0) { acc, x -> acc + x })
    val (small, big) = nums.partition { it < 10 }
    println("$small $big")
    println(listOf("kiwi", "fig", "plum", "pear").groupBy { it.length })
    val firstBig = generateSequence(1) { it * 2 }.first { it > 50 }
    println(firstBig)
    val steps = mutableListOf<String>()
    val r = sequenceOf(1, 2, 3, 4).filter { steps.add("f$it"); it % 2 == 0 }.map { steps.add("m$it"); it * 10 }.first()
    println("$r $steps")
}
```
```output
[10, 24, 14, 40]
47
[5, 7, 3] [12, 20]
{4=[kiwi, plum, pear], 3=[fig]}
64
20 [f1, f2, m2]
```
`filter` и `map` на списке выполняются жадно: каждый шаг обрабатывает весь список и создаёт новый. `partition` делит список на два по условию, `groupBy` собирает словарь `ключ -> список`. `generateSequence` задаёт бесконечную ленивую последовательность, из которой `first` берёт значения, пока условие не выполнится. Цепочка над `Sequence` обрабатывает элементы по одному и останавливается, как только найден первый результат: `f3` и `f4` не вычисляются.

## Что нужно уметь

* записывать лямбды с `it` и с именованными параметрами и передавать их в `filter`, `map`, `fold`;
* выбирать между `map`, `filter`, `groupBy`, `partition` и `fold` для типичных преобразований;
* предсказывать порядок вызовов лямбд в цепочке на `List` (жадно) и на `Sequence` (лениво, поэлементно);
* создавать бесконечные последовательности через `generateSequence` и брать из них нужное через `first`, `take`;
* помнить, что `List` не гарантирует неизменяемость, а `MutableList` - изменяемый интерфейс того же списка;
* читать результаты `groupBy` и `toSortedMap()`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Ждать, что цепочка на списке остановится на первом нужном элементе: она обработает весь список на каждом шаге.
* Забыть `toList()` или `first()` у последовательности: без терминальной операции ничего не вычисляется.
* Путать `fold` и `reduce`: `fold` принимает начальное значение, `reduce` берёт первый элемент.
* Бесконечная последовательность без ограничения (`take` или `first`) зависает.
* Изменять внешнюю переменную из лямбды в `map` вместо того, чтобы возвращать значение.
