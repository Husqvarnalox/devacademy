## Что проверяет эта проверка

Потоки `thread` и `join`, атомарные счётчики, `suspend`-функции, `runBlocking`, `launch`, `async` и `await`, `coroutineScope`, `delay`, `withTimeoutOrNull`, отмена и структурированная конкурентность.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок: [Конкурентность: потоки, синхронизация и корутины](lesson:kotlin.fundamentals.concurrency-threads-and-coroutines).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```kotlin run
import kotlinx.coroutines.*

suspend fun slow(x: Int): Int {
    delay(50)
    return x * 10
}

fun main() = runBlocking {
    val results = coroutineScope {
        listOf(1, 2, 3).map { async { slow(it) } }.awaitAll()
    }
    println(results)
    launch {
        delay(20)
        println("B")
    }
    println("A")
    println(withTimeoutOrNull(30) { delay(100); "поздно" })
}
```
```output
[10, 20, 30]
A
B
null
```
`async` запускает корутину и возвращает `Deferred`, `awaitAll` ждёт все результаты и возвращает их в порядке запуска, независимо от того, какая закончилась первой. `launch` не блокирует вызывающий код: `A` печатается раньше `B`, потому что `delay` приостанавливает корутину, не блокируя поток. `withTimeoutOrNull` возвращает `null`, если блок не уложился во время.

## Что нужно уметь

* запускать потоки через `thread { ... }`, дожидаться их через `join()` и защищать общий счётчик атомиком или блокировкой;
* объяснять, что `suspend`-функцию можно вызывать только из корутины или другой `suspend`-функции;
* запускать корутины через `launch` и `async`, а результаты собирать через `await` и `awaitAll`;
* предсказывать порядок вывода корутин в `runBlocking` с `delay`;
* различать `delay` (приостанавливает корутину) и `Thread.sleep` (блокирует поток);
* объяснять, что дочерние корутины живут в области (`coroutineScope`) и отменяются вместе с ней при ошибке.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Читать результат потоков до `join()`: данные могут быть ещё не записаны.
* Изменять обычный `var` счётчик из нескольких потоков: гонка данных даёт разные результаты.
* Вызывать `await()` сразу после `async` в цикле: задачи выполняются последовательно, а не параллельно.
* Использовать `Thread.sleep` внутри корутины: поток блокируется.
* Ждать, что `launch` завершится до следующей строки: он только планирует выполнение.
