## От чисел к вероятностям

Линейная регрессия предсказывает любое число. Для классификации нам нужен ответ «объект принадлежит классу 1 с вероятностью p», где `p` лежит между 0 и 1. Логистическая регрессия делает это в два шага:

1. Считаем обычную линейную комбинацию `z = w·x + b` — число от минус до плюс бесконечности. Его называют **логитом**.
2. Пропускаем логит через **сигмоиду** `σ(z) = 1 / (1 + e^(-z))`, которая сжимает любое число в интервал `(0, 1)`: большие положительные `z` дают вероятность около 1, большие отрицательные — около 0, а `z = 0` — ровно 0.5.

Чтобы получить метку, выбираем **порог**: чаще всего «класс 1, если `p ≥ 0.5`». Обучение — это подбор весов `w`, при которых вероятности для настоящих единиц близки к 1, а для нулей — к 0. Мера такого несоответствия — **логистическая потеря** (она же кросс-энтропия), а минимизируем мы её тем же пакетным градиентным спуском, что и в [линейной регрессии](lesson:ml.numpy.linear-regression).

Ключевая практическая трудность — **численная устойчивость**: наивные формулы для сигмоиды и логарифма вероятности переполняются на больших по модулю логитах. Эта лекция учит записывать их правильно.

<!-- section: precise -->
## Модель, потеря, градиент

Пусть `Xb` — матрица `n × (d + 1)` со столбцом единиц, `y ∈ {0, 1}ⁿ`, `w` — веса. Логиты `z = Xb w`, вероятности `p = σ(z)`. Правдоподобие метки `y_i` равно `p_i^y_i (1 - p_i)^(1 - y_i)`. Минимизируем среднее отрицательное логарифмическое правдоподобие:

`L(w) = -(1/n) Σ [ y_i ln p_i + (1 - y_i) ln(1 - p_i) ]`.

Подставим `p = σ(z)`: `-ln σ(z) = ln(1 + e^(-z))`, `-ln(1 - σ(z)) = ln(1 + e^z)`. После упрощения получается форма, которую мы реализуем:

`L = (1/n) Σ [ ln(1 + e^(z_i)) - y_i z_i ]`.

Её вычисляют через `np.logaddexp(0, z) = ln(e^0 + e^z)`: эта функция внутри вычитает максимум и не переполняется. Градиент удивительно прост:

`∇L(w) = (1/n) Xbᵀ (σ(Xb w) - y)`.

Это та же форма «признаки на ошибку», что и в линейной регрессии, только ошибка — разность вероятности и метки. Функция `L` выпукла, поэтому спуск не застревает в локальных минимумах. Но если классы **линейно разделимы**, то нижняя грань потери равна нулю и не достигается: веса растут бесконечно, а вероятности стремятся к 0 и 1. Поэтому на практике добавляют **L2-регуляризацию** `½ λ ‖w[1:]‖²` (смещение не штрафуют).

## Устойчивая сигмоида

Формула `1 / (1 + np.exp(-z))` при `z = -1000` вычисляет `exp(1000)`, которое выходит за диапазон `float64` (максимум порядка `1.8e308`), и NumPy выдаёт `inf` с предупреждением `overflow`. Результат `1/inf = 0` формально верен, но предупреждение и риск `nan` в соседних выражениях остаются. Устойчивая запись разбивает случаи:

* `z ≥ 0`: `1 / (1 + e^(-z))` — экспонента от неположительного числа, не больше 1;
* `z < 0`: `e^z / (1 + e^z)` — тоже экспонента от отрицательного числа.

В обоих случаях аргумент `exp` неположителен, и переполнения нет. Аналогично логарифм вероятности нельзя считать как `np.log(sigmoid(z))`: при `z = -800` сигмоида округляется до 0, и логарифм даёт `-inf`. Поэтому потеря считается сразу по логитам через `logaddexp`.

## Примеры

**Пример 1. Наивная и устойчивая формулы на больших логитах.**

```python run
import numpy as np

z = np.array([-800.0, 0.0, 800.0])
y = np.array([1.0, 1.0, 0.0])          # первый и последний ответы - уверенные ошибки

with np.errstate(over="ignore", divide="ignore"):
    p = 1.0 / (1.0 + np.exp(-z))                 # exp(800) = inf
    naive = -np.mean(y * np.log(p) + (1 - y) * np.log(1 - p))
stable = np.mean(np.logaddexp(0.0, z) - y * z)

print("наивная потеря конечна:", bool(np.isfinite(naive)))
print("устойчивая потеря:", round(float(stable), 3))      # (800 + ln 2 + 800) / 3
```
```output
наивная потеря конечна: False
устойчивая потеря: 533.564
```

**Пример 2. Обучение на двух облаках точек.**

```python run
import numpy as np

def sigmoid(z):
    out = np.empty_like(z)
    pos = z >= 0
    out[pos] = 1.0 / (1.0 + np.exp(-z[pos]))
    e = np.exp(z[~pos])
    out[~pos] = e / (1.0 + e)
    return out

rng = np.random.default_rng(0)
n = 100
X = np.vstack([rng.normal(-1.5, 1.0, (n, 2)), rng.normal(1.5, 1.0, (n, 2))])
y = np.concatenate([np.zeros(n), np.ones(n)])
Xb = np.hstack([np.ones((2 * n, 1)), X])

def loss(w):
    z = Xb @ w
    return np.mean(np.logaddexp(0.0, z) - y * z)

w = np.zeros(3)
history = [loss(w)]
for _ in range(500):
    w -= 0.5 * Xb.T @ (sigmoid(Xb @ w) - y) / (2 * n)
    history.append(loss(w))

acc = np.mean((sigmoid(Xb @ w) >= 0.5) == y)
print("потеря на старте = ln 2:", bool(np.isclose(history[0], np.log(2))))
print("потеря убывает:", bool(np.all(np.diff(history) <= 1e-12)))
print("потеря меньше 0.1:", bool(history[-1] < 0.1))
print("точность не ниже 0.95:", bool(acc >= 0.95))
```
```output
потеря на старте = ln 2: True
потеря убывает: True
потеря меньше 0.1: True
точность не ниже 0.95: True
```

Начальная потеря равна `ln 2 ≈ 0.693`: модель с нулевыми весами всем объектам даёт вероятность 0.5.

**Пример 3. Проверка градиента конечными разностями.** Это стандартный способ поймать ошибку в формуле прежде, чем она испортит обучение.

```python run
import numpy as np

rng = np.random.default_rng(1)
Xb = np.hstack([np.ones((20, 1)), rng.normal(size=(20, 2))])
y = (rng.random(20) < 0.5).astype(float)
w = np.array([0.3, -0.5, 0.8])

def loss(w):
    z = Xb @ w
    return np.mean(np.logaddexp(0.0, z) - y * z)

p = 1.0 / (1.0 + np.exp(-(Xb @ w)))
g = Xb.T @ (p - y) / 20
num = np.empty(3)
for j in range(3):
    e = np.zeros(3)
    e[j] = 1e-6
    num[j] = (loss(w + e) - loss(w - e)) / 2e-6

print("градиент совпал с численным:", bool(np.allclose(g, num, rtol=0, atol=1e-6)))
```
```output
градиент совпал с численным: True
```

**Пример 4. Порог и разделимые данные.** При повышении порога положительных меток становится не больше. На разделимых данных веса растут без предела, пока их не остановит число эпох или регуляризация.

```python run
import numpy as np

p = np.array([0.05, 0.3, 0.55, 0.7, 0.95])
counts = [int((p >= t).sum()) for t in (0.1, 0.5, 0.9)]
print("число положительных при порогах 0.1, 0.5, 0.9:", counts)

x = np.array([[-2.0], [-1.0], [1.0], [2.0]])
y = np.array([0.0, 0.0, 1.0, 1.0])
Xb = np.hstack([np.ones((4, 1)), x])
w = np.zeros(2)
sizes = []
for epoch in range(1, 3001):
    p = 1.0 / (1.0 + np.exp(-(Xb @ w)))
    w -= 1.0 * Xb.T @ (p - y) / 4
    if epoch in (100, 1000, 3000):
        sizes.append(float(w[1]))
print("наклон растёт с числом эпох:", sizes[0] < sizes[1] < sizes[2])
```
```output
число положительных при порогах 0.1, 0.5, 0.9: [4, 3, 1]
наклон растёт с числом эпох: True
```

## Типичные ошибки

* **Наивная сигмоида.** `1 / (1 + np.exp(-z))` даёт предупреждения `overflow` на больших отрицательных `z`. Разбивайте случаи по знаку.
* **`np.log(sigmoid(z))`.** При `z = -800` получается `-inf`, и потеря превращается в `nan`. Считайте потерю по логитам через `np.logaddexp`.
* **Метки не 0/1.** Формула потери предполагает `y ∈ {0, 1}`. Метки `-1/+1` или `1/2` дают неверные градиенты, а ошибки молча проходят.
* **Забыли о смещении или штрафуете его.** Без столбца единиц граница вынуждена проходить через начало координат. В L2-регуляризации смещение не входит в штраф.
* **Слишком большой `lr` на неотмасштабированных признаках.** Потеря начинает расти или скакать. Стандартизуйте признаки, смотрите на историю потери.
* **Порог 0.5 как догма.** При несбалансированных классах или разной цене ошибок порог выбирают по задаче (и по валидационной выборке), а не по умолчанию.
* **Одна точность вместо потери.** Точность не растёт плавно; для отладки смотрите на потерю и норму градиента.

<!-- section: summary -->
## Итоги

* Модель: `p = σ(Xb w)`; потеря `mean(logaddexp(0, z) - y z)`; градиент `Xbᵀ (p - y) / n`.
* Устойчивость требует разветвлённой сигмоиды и `logaddexp`; проверяйте формулы на логитах порядка ±800.
* Градиент проверяют конечными разностями; потеря при `w = 0` равна `ln 2`.
* На разделимых данных веса растут бесконечно, поэтому нужна регуляризация или ограничение числа эпох.
* Порог превращает вероятность в метку, и его выбор зависит от задачи.

## Как это делается в библиотеке

Этап B курса — реализация в scikit-learn — **запланирован**: библиотека в окружении курса не установлена, поэтому исполняемого кода с ней здесь нет, а ниже только описание.

В scikit-learn логистическую регрессию реализует класс `LogisticRegression` из `sklearn.linear_model`. По документации, он по умолчанию применяет L2-регуляризацию (параметр `C` — обратная сила регуляризации, а не сама сила) и умеет выбирать между несколькими решателями, например `lbfgs` — квазиньютоновским методом, который использует приближённую кривизну и обычно сходится за десятки итераций, а не за сотни эпох простого спуска. Для больших выборок есть `SGDClassifier` со стохастическим спуском. Порог для метки по умолчанию 0.5, но вероятности доступны отдельно, и порог можно менять.

Сравнение с нашей реализацией:

* **Корректность.** Модель и потеря те же; с достаточно слабой регуляризацией и сходимостью веса близки к нашим. Отличия возникают из-за регуляризации по умолчанию и критериев остановки.
* **Численная устойчивость.** Библиотека обрабатывает большие логиты так же, как мы, через устойчивые формулы; обучение на разделимых данных остаётся ограниченным именно благодаря штрафу.
* **Сложность.** Наш пакетный спуск стоит `O(n d)` на эпоху и требует подбора `lr`; квазиньютоновские решатели делают меньше итераций ценой более дорогого шага и памяти на приближение кривизны.
* **Удобство.** Библиотека берёт на себя смещение, многоклассовый случай, разреженные данные и подбор параметров через перекрёстную проверку.
