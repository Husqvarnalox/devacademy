## Та же линейная регрессия, но для многих признаков и без циклов

В курсе [«Основы машинного обучения»](lesson:ml.foundations.linear-regression) мы обучали модель `y = w·x + b` с одним признаком в цикле по точкам. Теперь признаков может быть сколько угодно, а все вычисления мы запишем матрицами. Пусть `X` — матрица `n × d` (строка — объект, столбец — признак), `y` — вектор ответов длины `n`. Добавим к `X` столбец из единиц, чтобы смещение `b` стало ещё одним весом: получится матрица `Xb` формы `n × (d + 1)`, а предсказание — просто `Xb @ w`.

Найти лучшие веса можно тремя способами, и они различаются не результатом (на хороших данных он один и тот же), а **надёжностью**, **скоростью** и **удобством**:

1. **Нормальные уравнения**: решить `(XbᵀXb) w = Xbᵀ y`. Просто и быстро, но при плохих данных теряет точность.
2. **`np.linalg.lstsq`**: решает ту же задачу методами на основе разложений матрицы (внутри — SVD), устойчив и работает даже при вырожденных признаках.
3. **Пакетный градиентный спуск**: итеративно двигается против градиента. Нужен, когда прямое решение слишком дорого или невозможно (большие модели), и полезен как тренировка перед нейросетями.

<!-- section: precise -->
## Постановка и градиент

Модель `ŷ = Xb w`. Потери: `L(w) = (1/n) · ‖Xb w - y‖²`. Остаток `r = Xb w - y`. Градиент по весам:

`∇L(w) = (2/n) · Xbᵀ r`.

Это тот же вывод, что и для одного признака (`∂L/∂w = (2/n) Σ e_i x_i`), записанный для всех весов сразу: цикл по точкам и по признакам заменяется двумя матричными произведениями. Шаг спуска: `w ← w - lr · ∇L(w)`. Функция `L` выпукла и квадратична, её матрица Гессе равна `H = (2/n) XbᵀXb`. Спуск сходится при `lr < 2/λ_max(H)`; скорость определяется отношением наибольшего и наименьшего собственных чисел (числом обусловленности). Масштаб признаков поэтому влияет на сходимость так же, как в одномерном случае (см. стандартизацию в предыдущем курсе).

## Нормальные уравнения

Условие `∇L = 0` даёт `XbᵀXb w = Xbᵀ y`. Матрица `XbᵀXb` — симметричная, размера `(d+1) × (d+1)`; её решают через `np.linalg.solve` (не через обращение, см. [линейную алгебру](lesson:python.numpy.linear-algebra)). Время: `O(n d²)` на построение `XbᵀXb` и `O(d³)` на решение. Проблема в устойчивости: **число обусловленности** `cond(XbᵀXb) = cond(Xb)²`. Если `cond(Xb) ≈ 10^6`, то у нормальных уравнений оно около `10^12`, и из 16 цифр `float64` остаётся примерно четыре. Если столбцы линейно зависимы, `XbᵀXb` вырождена, и `solve` либо бросает `LinAlgError`, либо возвращает мусор.

## lstsq: QR и SVD

`np.linalg.lstsq(Xb, y, rcond=None)` минимизирует `‖Xb w - y‖²` напрямую, без возведения `Xb` в квадрат. Реализация в NumPy использует SVD (через LAPACK `gelsd`): `Xb = U Σ Vᵀ`, `w = V Σ⁺ Uᵀ y`, где малые сингулярные числа (ниже порога, определяемого `rcond`) отбрасываются. Поэтому ошибка зависит от `cond(Xb)`, а не от `cond(Xb)²`, а при вырожденных признаках `lstsq` возвращает решение с **минимальной нормой** среди всех решений. Похожим образом работает QR-разложение: `Xb = QR`, и решается `R w = Qᵀ y`. Время — тоже `O(n d²)`, но с большей константой.

Что выбрать: для небольших, хорошо обусловленных задач нормальные уравнения достаточны и быстры; во всех остальных случаях берите `lstsq`.

## Примеры

**Пример 1. Все три способа на одних данных.**

```python run
import numpy as np

rng = np.random.default_rng(0)
n = 200
X = rng.normal(size=(n, 3))
w_true = np.array([1.5, 2.0, -1.0, 0.5])      # первое число - смещение
y = w_true[0] + X @ w_true[1:] + 0.05 * rng.normal(size=n)

Xb = np.hstack([np.ones((n, 1)), X])
w_ne = np.linalg.solve(Xb.T @ Xb, Xb.T @ y)
w_ls = np.linalg.lstsq(Xb, y, rcond=None)[0]

w = np.zeros(4)
lr = 0.1
for _ in range(1000):
    w -= lr * (2.0 / n) * (Xb.T @ (Xb @ w - y))

print("формы:", Xb.shape, w_ne.shape, w_ls.shape)
print("нормальные уравнения = lstsq:", np.allclose(w_ne, w_ls, rtol=0, atol=1e-10))
print("спуск = lstsq:", np.allclose(w, w_ls, rtol=0, atol=1e-6))
print("веса около истинных:", np.allclose(w_ls, w_true, rtol=0, atol=0.05))
```
```output
формы: (200, 4) (4,) (4,)
нормальные уравнения = lstsq: True
спуск = lstsq: True
веса около истинных: True
```

**Пример 2. Обусловленность: нормальные уравнения теряют точность.** Признаки `x, x², ..., x⁸` на отрезке `[0, 1]` сильно скоррелированы.

```python run
import numpy as np

x = np.linspace(0.0, 1.0, 50)
X = np.vander(x, 9, increasing=True)          # 1, x, ..., x^8 - уже со столбцом единиц
w_true = np.ones(9)
y = X @ w_true                                # данные без шума

w_ls = np.linalg.lstsq(X, y, rcond=None)[0]
w_ne = np.linalg.solve(X.T @ X, X.T @ y)

print("порядок cond(X):", int(np.log10(np.linalg.cond(X))))
print("порядок cond(X^T X):", int(np.log10(np.linalg.cond(X.T @ X))))
err_ls = np.linalg.norm(w_ls - w_true)
err_ne = np.linalg.norm(w_ne - w_true)
print("ошибка lstsq мала:", err_ls < 1e-6)
print("нормальные уравнения хуже более чем в 1000 раз:", err_ne > 1000 * err_ls)
```
```output
порядок cond(X): 5
порядок cond(X^T X): 11
ошибка lstsq мала: True
нормальные уравнения хуже более чем в 1000 раз: True
```

Квадрат числа обусловленности — не абстракция: ровно столько цифр теряет метод нормальных уравнений.

**Пример 3. Вырожденные признаки.** Дублируем столбец: `XbᵀXb` становится вырожденной.

```python run
import numpy as np

rng = np.random.default_rng(1)
a = rng.normal(size=(50, 2))
X = np.hstack([np.ones((50, 1)), a, a[:, :1]])      # последний столбец повторяет первый признак
y = 1.0 + 2.0 * a[:, 0] - 3.0 * a[:, 1]

print("ранг X:", np.linalg.matrix_rank(X), "из", X.shape[1])
w = np.linalg.lstsq(X, y, rcond=None)[0]
print("lstsq воспроизводит y:", np.allclose(X @ w, y, rtol=0, atol=1e-10))
print("вес первого признака делится между двумя копиями:", np.allclose(w[1] + w[3], 2.0, rtol=0, atol=1e-10))
```
```output
ранг X: 3 из 4
lstsq воспроизводит y: True
вес первого признака делится между двумя копиями: True
```

## Типичные ошибки

* **Забыть про столбец единиц.** Без него прямая вынуждена проходить через начало координат. Проверяйте форму `Xb`: `(n, d + 1)`.
* **Обращать матрицу.** `np.linalg.inv(Xb.T @ Xb) @ Xb.T @ y` медленнее и менее точно, чем `solve`, а `lstsq` лучше обоих.
* **Градиент без деления на `n` или без множителя 2.** Эффективный `lr` меняется, а эталонное сравнение с `lstsq` ломается.
* **Спуск на неотмасштабированных признаках.** Признаки порядка 1000 требуют крошечного `lr`; стандартизуйте их по обучающей выборке.
* **Сравнивать веса вырожденной задачи с «истинными».** При дублирующих столбцах решение не единственно; сравнивайте предсказания `Xb @ w`.
* **Доверять `solve` вслепую.** Следите за `np.linalg.cond`; если число обусловленности велико, переходите на `lstsq`.

<!-- section: summary -->
## Итоги

* Векторная форма: `ŷ = Xb w`, `L = mean((Xb w - y)²)`, градиент `(2/n) Xbᵀ (Xb w - y)`.
* Нормальные уравнения возводят число обусловленности в квадрат; `lstsq` (SVD) устойчивее и справляется с вырожденными признаками.
* Градиентный спуск нужен, когда прямое решение дорого, и требует масштабирования признаков и подбора `lr`.
* Сложность: нормальные уравнения и `lstsq` — `O(n d²)` (плюс `O(d³)`); одна эпоха спуска — `O(n d)`.
* Всегда проверяйте результат: сходимость спуска к `lstsq`, остатки и число обусловленности.

## Как это делается в библиотеке

Этап B курса — реализация в scikit-learn — **запланирован**: библиотека в окружении курса не установлена, поэтому исполняемого кода с ней здесь нет, а ниже только описание.

В scikit-learn линейную регрессию по методу наименьших квадратов выполняет класс `LinearRegression` из `sklearn.linear_model`. По документации библиотеки, это обычный метод наименьших квадратов, обёрнутый в объект с интерфейсом `fit` и `predict`; решение строится через `scipy.linalg.lstsq`, то есть через разложение матрицы, а не через нормальные уравнения. Смещение библиотека обрабатывает сама (параметр `fit_intercept`), столбец единиц добавлять не нужно. Для регуляризованных вариантов есть `Ridge` и `Lasso`, а для больших данных, где прямое решение дорого, — `SGDRegressor` со стохастическим градиентным спуском.

Сравнение с нашей реализацией:

* **Корректность.** Результат совпадает с `lstsq` с точностью до ошибок округления; именно это мы проверяем в тестах: нормальные уравнения и спуск должны сойтись к `lstsq`.
* **Численная устойчивость.** Библиотека не использует нормальные уравнения по умолчанию, поэтому не теряет цифры из-за возведения числа обусловленности в квадрат; вырожденные признаки допустимы.
* **Сложность.** Прямое решение — порядка `O(n d²)` по времени и `O(n d)` по памяти; стохастический спуск делает за эпоху `O(n d)` и подходит, когда `n` или `d` очень велики.
* **Удобство.** Библиотека берёт на себя смещение, проверку входных данных, разреженные матрицы и интеграцию в конвейеры; мы же получаем понимание того, что происходит внутри.
