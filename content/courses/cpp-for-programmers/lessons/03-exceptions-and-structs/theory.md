## Зачем этот урок

Данные приходят неправильными: в поле «количество» кто-то написал `12abc`, число не помещается в `int`, список пуст. В C++ для таких случаев есть исключения, но у них свои правила: `std::stoi` молча разбирает только начало строки, исключение нужно перехватывать по ссылке, а необработанное исключение завершает программу. Вторая половина урока - `struct`: в C++ это обычный тип-значение, который копируется при присваивании, а поля без начального значения содержат мусор. Успешное прохождение (упражнение и квиз) засчитывает уроки 22-23 курса «C++ с нуля».

## Главная мысль

Исключения нужны для ошибок, которые вызывающий код может исправить, но не должен проверять после каждого вызова; ожидаемый плохой ввод удобнее возвращать как `std::optional`. Структуры ведут себя как числа: `b = a` создаёт независимую копию, а объект, переданный в функцию без `&`, - тоже копия.

## Пример 1. Исключения и строгий разбор

```cpp run
#include <iostream>
#include <optional>
#include <stdexcept>
#include <string>
#include <utility>

std::optional<int> parseWhole(const std::string& text) {
    try {
        std::size_t used = 0;
        int value = std::stoi(text, &used);
        if (used != text.size()) {
            return std::nullopt;
        }
        return value;
    } catch (const std::invalid_argument&) {
        return std::nullopt;
    } catch (const std::out_of_range&) {
        return std::nullopt;
    }
}

struct Guard {
    std::string name;
    explicit Guard(std::string n) : name(std::move(n)) {
        std::cout << "open " << name << "\n";
    }
    ~Guard() {
        std::cout << "close " << name << "\n";
    }
};

int checked(int percent) {
    Guard guard("checked");
    if (percent < 0 || percent > 100) {
        throw std::invalid_argument("percent");
    }
    return percent;
}

int main() {
    std::cout << std::stoi("12abc") << " " << std::stoi("  7") << " " << std::stoi("-5x") << "\n";

    for (const std::string text : {"42", "12abc", "abc", "99999999999", ""}) {
        try {
            int value = std::stoi(text);
            std::cout << "[" << text << "] -> " << value << "\n";
        } catch (const std::invalid_argument&) {
            std::cout << "[" << text << "] invalid_argument\n";
        } catch (const std::out_of_range&) {
            std::cout << "[" << text << "] out_of_range\n";
        }
    }

    for (const std::string text : {"42", "12abc", "abc", "99999999999"}) {
        std::optional<int> value = parseWhole(text);
        std::cout << text << ": " << (value ? std::to_string(*value) : "нет") << "\n";
    }

    try {
        std::cout << checked(50) << "\n";
        std::cout << checked(150) << "\n";
        std::cout << "сюда не дойдём\n";
    } catch (const std::exception&) {
        std::cout << "перехвачено\n";
    }
    try {
        throw std::out_of_range("x");
    } catch (const std::logic_error&) {
        std::cout << "out_of_range - это logic_error\n";
    }
    try {
        try {
            throw std::runtime_error("inner");
        } catch (const std::runtime_error&) {
            std::cout << "повторный бросок\n";
            throw;
        }
    } catch (...) {
        std::cout << "поймано внешним\n";
    }
}
```
```output
12 7 -5
[42] -> 42
[12abc] -> 12
[abc] invalid_argument
[99999999999] out_of_range
[] invalid_argument
42: 42
12abc: нет
abc: нет
99999999999: нет
open checked
close checked
50
open checked
close checked
перехвачено
out_of_range - это logic_error
повторный бросок
поймано внешним
```

Разбор. `std::stoi("12abc")` возвращает `12` и молча отбрасывает хвост; пробелы в начале пропускаются, поэтому `"  7"` даёт `7`. Чтобы узнать, всё ли разобрано, передают второй аргумент: `stoi(text, &used)` записывает число использованных символов, и строка допустима, только если `used == text.size()`. Исключение `std::invalid_argument` бросается, когда число вообще не найдено (`"abc"`, пустая строка), а `std::out_of_range` - когда оно не помещается в `int`. Обработчики `catch` проверяются сверху вниз, а тип исключения указывают как `const T&`: так объект не копируется и не «обрезается» до базового типа. При броске `checked(150)` выполнение сразу покидает функцию, и объект `Guard` уничтожается по пути (`close checked` напечатано до `перехвачено`): этот порядок - **раскрутка стека**, она вызывает деструкторы локальных объектов. Исключения образуют иерархию: `std::out_of_range` является `std::logic_error`, поэтому его ловит и обработчик базового типа. `throw;` без аргумента пробрасывает текущее исключение дальше. Функция `parseWhole` превращает исключения в `std::optional<int>`: «нет числа» там - обычный исход, а не ошибка.

**Попробуйте.** Поменяйте местами два обработчика в первом цикле и оставьте только `catch (const std::exception&)`. Что изменится в выводе?

## Пример 2. Структуры - значения

```cpp run
#include <iostream>
#include <string>
#include <vector>

struct Point {
    int x = 0;
    int y = 0;

    int manhattan() const {
        return (x < 0 ? -x : x) + (y < 0 ? -y : y);
    }
    bool operator==(const Point&) const = default;
};

struct Student {
    std::string name;
    int score = 0;
};

void raise(Student s) {
    s.score += 10;
}

void raiseRef(Student& s) {
    s.score += 10;
}

int main() {
    Point a{3, -4};
    Point b = a;
    b.x = 9;
    std::cout << a.x << " " << b.x << " " << a.manhattan() << "\n";
    std::cout << (a == b) << " " << (a == Point{3, -4}) << "\n";

    Point origin{};
    Point inferred{.x = 5};
    std::cout << origin.x << origin.y << " " << inferred.x << inferred.y << "\n";

    Student anna{"Anna", 80};
    raise(anna);
    std::cout << anna.score << "\n";
    raiseRef(anna);
    std::cout << anna.score << "\n";

    std::vector<Student> group = {{"Anna", 80}, {"Boris", 55}};
    for (Student s : group) {
        s.score = 100;
    }
    std::cout << group[0].score << " ";
    for (Student& s : group) {
        s.score += 1;
    }
    std::cout << group[0].score << " " << group[1].score << "\n";

    std::vector<Student> other = group;
    other[0].name = "Clara";
    std::cout << group[0].name << " " << other[0].name << "\n";
}
```
```output
3 9 7
0 1
00 50
80
90
80 81 56
Anna Clara
```

Разбор. `Point b = a` копирует структуру: изменение `b.x` не меняет `a` (в Java, Python и JavaScript обе переменные ссылались бы на один объект). Параметр `Student s` в `raise` - копия, поэтому балл Anna остался `80`, а `raiseRef` с параметром-ссылкой изменил оригинал. Цикл `for (Student s : group)` изменяет копии, и вектор не меняется; `for (Student& s : group)` меняет сами элементы, а для чтения без копирования пишут `const Student&`. Вектор структур копируется вместе с элементами (`other` не зависит от `group`). Поля с начальными значениями (`int x = 0;`) избавляют от мусора; `Point{}` обнуляет все поля. Функция-член с `const` обещает не менять объект и вызывается у `const`-объектов. Сравнение `==` для структуры по умолчанию не определено, но C++20 позволяет получить его строкой `bool operator==(const Point&) const = default;`. Инициализация по именам (`Point{.x = 5}`) появилась в C++20, порядок полей должен совпадать с объявлением.

## Точные правила

* `throw expr;` создаёт копию `expr` и начинает поиск обработчика вверх по стеку. Обработчики перебираются по порядку; сработает первый, тип которого подходит (тип совпадает или является базовым). Поэтому обработчик более общего типа ставят после частных.
* Ловят по `const T&`. Параметр `catch (std::exception e)` копирует объект и отрезает производную часть (**срезка**), а `catch (...)` ловит всё без доступа к значению. `throw;` пробрасывает то же исключение.
* Необработанное исключение вызывает `std::terminate`: программа завершается аварийно. Сообщение в таком случае зависит от стандартной библиотеки и не входит в стандарт.
* При раскрутке стека вызываются деструкторы всех полностью построенных локальных объектов. Исключение, вылетевшее из деструктора во время раскрутки, завершает программу, поэтому деструкторы не бросают.
* `std::stoi`, `std::stod` и подобные пропускают пробелы в начале, разбирают максимальный допустимый префикс и бросают `std::invalid_argument` (нет ни одной цифры) или `std::out_of_range` (значение не помещается в тип). Для строгого разбора используют второй параметр `std::size_t*`. Тексты `what()` стандартом не заданы.
* `v.at(i)` и `map.at(key)` бросают `std::out_of_range`, а `v[i]` - нет (UB).
* `std::optional<T>` (заголовок `<optional>`, C++17) хранит значение или ничего: `if (opt)`, `*opt`, `opt.value_or(0)`. Он подходит для ожидаемых отказов (плохой ввод), исключения - для нарушений договора.
* В `struct` все члены по умолчанию открыты, в `class` - закрыты; других отличий нет. Структуру копируют, присваивают и передают по значению, как `int`.
* Локальная переменная структуры без инициализаторов содержит мусор в полях встроенных типов: `Point p;` не обнуляет `x` и `y`. `Point p{};` обнуляет, а `int x = 0;` в объявлении поля задаёт значение по умолчанию.
* Агрегатная инициализация `Point{1, 2}` присваивает поля в порядке объявления; пропущенные получают значение по умолчанию (или нуль). Запрещает сужение: `Point{1.5, 2}` - ошибка.
* Функция-член, не меняющая объект, помечается `const` после списка параметров.

## Типичные ошибки

**1. Верить `stoi` на `12abc`.** Функция вернёт `12` и не сообщит о хвосте. Для строгого разбора сравнивайте `used` с `text.size()`, как в упражнении.

**2. Структура без инициализации.**

```cpp
struct Point {
    int x;
    int y;
};

Point p;
std::cout << p.x << "\n";
```

Компилятор не предупреждает, а программа печатает мусор (например, `1873046944`; у вас значение будет другим). Пишите `Point p{};` или задавайте `int x = 0;` в объявлении поля.

**3. Сравнение структур через `==`.**

```
main.cpp:13:11: error: invalid operands to binary expression ('Point' and 'Point')
```

Компилятор сам не сравнивает поля структуры: добавьте `bool operator==(const Point&) const = default;`.

**4. Обработчик базового типа раньше производного.**

```cpp
try {
    throw std::runtime_error("x");
} catch (const std::exception&) {
} catch (const std::runtime_error&) {   // недостижим
}
```

```
main.cpp:7:20: warning: exception of type 'const std::runtime_error &' will be caught by earlier handler [-Wexceptions]
```

Второй обработчик никогда не сработает. Ставьте частные типы выше общих.

**5. Ловить по значению.** `catch (std::exception e)` копирует исключение и отрезает производную часть. Всегда `const std::exception&`.

**6. Неперехваченное исключение.** Из `main` вылетело исключение, которого никто не поймал: вызывается `std::terminate`, процесс завершается аварийно. Перехватывайте исключения там, где умеете с ними справиться; ожидаемый плохой ввод обрабатывайте без исключения.

**7. Изменение копии в цикле.** `for (Student s : group) { s.score = 100; }` не меняет вектор. Для изменения нужна ссылка: `Student& s`.

**8. Исключения как управление потоком.** Исключения дороги по сравнению с обычной проверкой; не используйте их для обычных ветвлений внутри цикла по большому вводу.

## Главное для тех, кто уже программирует

* Исключения устроены как в Java и C#: `try`, `catch`, `throw`. Нет блока `finally`: ресурсы освобождают деструкторы (RAII), которые срабатывают при раскрутке стека. Нет проверяемых исключений.
* Бросить можно значение любого типа (`throw 1;`), но принято бросать объекты производных от `std::exception`. Ловят по `const&`, как в Java, но не по значению: срезка.
* Исключения в C++ почти бесплатны, пока не бросаются, но брошенное исключение заметно медленнее обычного возврата. В Go ошибки возвращают значением, в Rust - через `Result`; в C++ для этого есть `std::optional`, коды возврата и (с C++23) `std::expected`.
* Деление целых на ноль, выход за границы `v[i]` и разыменование нулевого указателя не бросают исключений, а дают UB. Исключение бросают `.at()`, `std::stoi` и `new` при нехватке памяти.
* `struct` и `class` в C++ - значения, как `struct` в Go и C#; `class` в Java, Python и JavaScript - ссылка. Копия при присваивании - поведение по умолчанию, для общего объекта используют ссылку или указатель.
* Поля встроенных типов в локальной структуре не обнуляются - в отличие от Go (нулевые значения) и Java (поля класса по умолчанию нулевые).
* Нет автоматических `equals`, `hashCode`, `toString`: сравнение включают `= default` (C++20), вывод пишут оператором `<<`.
* Деструктор вызывается в предсказуемый момент (выход из области видимости), а не сборщиком мусора. Это основа RAII, которой посвящён следующий курс.
