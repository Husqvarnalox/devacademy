## Почему «работает» и «успеет» - разные вещи

Программа может быть верной и всё равно бесполезной: на 10 элементах она отвечает мгновенно, а на 10^5 думает минуты. Чтобы заранее понимать, **как быстро растёт время работы вместе с размером входа**, придумали оценку сложности.

Идея простая. Мы не меряем секунды (они зависят от процессора, языка и нагрузки), а считаем **число элементарных шагов** как функцию от размера входа `n`:

* прочитать элемент массива, сравнить два числа, сложить - один шаг;
* цикл по `n` элементам - порядка `n` шагов;
* цикл в цикле - порядка `n · n` шагов;
* если на каждом шаге задача уменьшается вдвое - порядка `log n` шагов.

Затем отбрасываем константы и младшие слагаемые: `3n + 7` и `100n` оба «растут как `n`». Для больших `n` важна только форма роста. Записывается это так: **O(n)**.

Разницу между формами роста лучше один раз увидеть в числах. При `n = 10^5`:

| Сложность | Примерное число операций | Что это значит |
|---|---|---|
| O(log n) | 17 | мгновенно |
| O(n) | 10^5 | мгновенно |
| O(n log n) | 1.7·10^6 | мгновенно |
| O(n^2) | 10^10 | десятки секунд |
| O(2^n) | больше, чем атомов во Вселенной | никогда |

Поэтому в этом курсе у каждой задачи есть большие тесты: правильный, но медленный алгоритм не пройдёт. Это не придирка, а ровно то, что происходит в реальных системах.

## Формальные определения

Пусть `f(n)` и `g(n)` - неотрицательные функции натурального аргумента (число шагов).

* **O (верхняя граница).** `f(n) ∈ O(g(n))`, если существуют константы `c > 0` и `n0`, такие что `f(n) <= c · g(n)` для всех `n >= n0`.
  «Растёт не быстрее `g`».
* **Ω (нижняя граница).** `f(n) ∈ Ω(g(n))`, если `f(n) >= c · g(n)` для всех `n >= n0`. «Растёт не медленнее `g`».
* **Θ (точная оценка).** `f(n) ∈ Θ(g(n))`, если одновременно `f ∈ O(g)` и `f ∈ Ω(g)`. «Растёт так же, как `g`».

Пример. `f(n) = 3n + 7`. Возьмём `c = 4`, `n0 = 7`: при `n >= 7` верно `3n + 7 <= 4n`, значит `f ∈ O(n)`. Так как `3n + 7 >= 3n`, то `f ∈ Ω(n)`, и значит `f ∈ Θ(n)`. При этом `f ∈ O(n^2)` тоже верно, но это слабая оценка; `f ∉ O(1)`, потому что `f` неограниченно растёт.

Часто говорят «сложность O(n)», подразумевая Θ(n) - то есть пытаются дать *точную* оценку. Строго же O - только верхняя граница.

**Худший, лучший и средний случай.** Время зависит не только от `n`, но и от самих данных. Линейный поиск числа в массиве: в лучшем случае 1 шаг, в худшем `n`. Если не оговорено иное, называют **худший случай**: он гарантирует, что дальше медленнее не будет.

**Память.** Аналогично считают дополнительную память (без учёта входа): в лучшей отрезковой задаче ниже нужно O(1) переменных, а в решении с рекурсией глубины `n` - O(n) на стек.

**Как считать по коду.**

1. Последовательные блоки складываются: `O(n) + O(n^2) = O(n^2)` (остаётся наибольший).
2. Вложенные циклы перемножаются: цикл по `i` до `n` и по `j` до `n` - `O(n^2)`; если внутренний цикл идёт от `i + 1` до `n`, то шагов `n(n-1)/2`, всё равно `O(n^2)`.
3. Цикл, в котором переменная умножается или делится на константу, - `O(log n)`.
4. Вызов функции стоит столько, сколько стоит её тело (в Python: `x in список` - `O(n)`, `x in множество` - в среднем `O(1)`, `sorted` - `O(n log n)`).

**Как выбрать алгоритм по ограничениям.** При лимите в несколько секунд и `n` порядка `2·10^5` допустимы `O(n)`, `O(n log n)`; `O(n^2)` уместен при `n <= 3000 - 5000`; `O(2^n)` - при `n <= 20 - 25`. Это грубое правило, но оно спасает от напрасной реализации.

**Измерение.** Секундомер ненадёжен: на результат влияют фоновые процессы, кэш процессора и «прогрев» интерпретатора. Надёжнее:

* считать операции явным счётчиком (детерминированно, подходит для проверки оценки);
* ставить **эксперимент удвоения**: увеличить `n` вдвое и посмотреть на отношение числа операций (или времени). Отношение ≈ 2 говорит об `O(n)`, ≈ 2.2 - об `O(n log n)`, ≈ 4 - об `O(n^2)`, ≈ 8 - об `O(n^3)`;
* для настоящего времени в Python использовать `timeit` и брать минимум из нескольких повторов.

## Задача урока и её решение: лучшая полоса

Дан массив чисел `a[0..n-1]`. Найти наибольшую сумму непустого непрерывного отрезка.

**Перебор.** Для каждой пары границ `(i, j)` посчитать сумму: `O(n^2)` пар. Даже с накоплением суммы по `j` это `n(n+1)/2` шагов.

**Идея линейного решения.** Пусть `cur(i)` - наибольшая сумма отрезка, который **оканчивается ровно в позиции `i`**. Такой отрезок либо состоит из одного элемента `a[i]`, либо является продолжением лучшего отрезка, оканчивающегося в `i-1`:

`cur(i) = max(a[i], cur(i-1) + a[i])`.

Ответ - `max(cur(i))` по всем `i`.

**Псевдокод.**

```
best = cur = a[0]
для i от 1 до n-1:
    cur = max(a[i], cur + a[i])
    best = max(best, cur)
вывести best
```

**Корректность (инвариант).** Перед обработкой элемента `i`:

1. `cur` равно наибольшей сумме отрезка, оканчивающегося в `i-1`;
2. `best` равно наибольшей сумме среди всех отрезков внутри `a[0..i-1]`.

*База:* при `i = 1` оба значения равны `a[0]` - единственному отрезку. *Шаг:* любой отрезок, оканчивающийся в `i`, - это `a[i]` плюс (возможно пустой) отрезок, оканчивающийся в `i-1`. Чтобы сумма была наибольшей, добавляемую часть берут наибольшей, но только если она положительна - ровно это и делает `max(a[i], cur + a[i])`. Любой отрезок внутри `a[0..i]` либо оканчивается в `i` (учтён через `cur`), либо лежит в `a[0..i-1]` (учтён предыдущим `best`), поэтому `best = max(best, cur)` восстанавливает инвариант. После последнего шага `best` - ответ.

**Сложность.** Один проход: время `Θ(n)`, память `O(1)`.

## Примеры

**Пример 1. Считаем шаги вместо секунд.** Сравним линейный и бинарный поиск числа в отсортированном массиве. Бинарный поиск мы разберём в [следующем уроке](lesson:algorithms.foundations.binary-search); здесь важно только число шагов.

```python run
def linear_search(a, x):
    steps = 0
    for i, v in enumerate(a):
        steps += 1
        if v == x:
            return i, steps
    return -1, steps

def binary_search(a, x):
    lo, hi = 0, len(a)          # ищем в a[lo:hi]
    steps = 0
    while lo < hi:
        steps += 1
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo, steps

for n in (10, 1000, 1_000_000):
    a = list(range(n))
    x = n - 1                    # худший случай для линейного поиска
    print(n, linear_search(a, x)[1], binary_search(a, x)[1])
```
```output
10 10 3
1000 1000 10
1000000 1000000 20
```

Миллион элементов: 10^6 шагов против 20. Это и есть разница между `O(n)` и `O(log n)`.

**Пример 2. Эксперимент удвоения.** Три функции с разной формой роста. Отношение числа операций при `n = 2048` к числу при `n = 1024` выдаёт класс.

```python run
def ops_linear(n):
    ops = 0
    for _ in range(n):
        ops += 1
    return ops

def ops_nlogn(n):
    ops = 0
    for _ in range(n):
        j = 1
        while j < n:
            j *= 2
            ops += 1
    return ops

def ops_quadratic(n):
    ops = 0
    for i in range(n):
        for j in range(i + 1, n):
            ops += 1
    return ops

for f in (ops_linear, ops_nlogn, ops_quadratic):
    small, big = f(1024), f(2048)
    print(f"{f.__name__:14} n=1024: {small:8}  n=2048: {big:8}  отношение: {big / small:.2f}")
```
```output
ops_linear     n=1024:     1024  n=2048:     2048  отношение: 2.00
ops_nlogn      n=1024:    10240  n=2048:    22528  отношение: 2.20
ops_quadratic  n=1024:   523776  n=2048:  2096128  отношение: 4.00
```

**Пример 3. Сколько пар вместо одного прохода.** Для задачи урока перебор рассматривает `n(n+1)/2` отрезков, а алгоритм Кадане - `n` элементов.

```python run
def pairs_naive(n):
    return n * (n + 1) // 2      # столько отрезков [i, j] проверяет перебор

def steps_linear(n):
    return n                     # один проход

for n in (1_000, 100_000, 1_000_000):
    print(n, pairs_naive(n), steps_linear(n), pairs_naive(n) // steps_linear(n))
```
```output
1000 500500 1000 500
100000 5000050000 100000 50000
1000000 500000500000 1000000 500000
```

При `n = 10^5` разрыв - в 50 000 раз. Если один проход занимает 1 мс, перебор занял бы около минуты.

**Пример 4. Решение задачи.** Версия на Python (в упражнении вы выберете любой из шести языков).

```python run
def best_segment(a):
    best = cur = a[0]
    for x in a[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best

print(best_segment([2, -5, 3, 4, -1]))
print(best_segment([-4, -2, -9]))
```
```output
7
-2
```

**Практическое замечание: замер времени.** Для реального времени в Python используйте `timeit` (результат зависит от машины, поэтому здесь не запускается):

```python
import timeit
print(min(timeit.repeat("best_segment(a)", globals=globals(), number=1, repeat=5)))
```

## Типичные ошибки

* **Измерять секундомером на одном маленьком входе.** На `n = 100` и квадратичный алгоритм мгновенный. Оценивайте рост, а не одно число.
* **Путать O с «точным» временем.** `O(n)` - это верхняя граница; говорить «`O(n)` быстрее `O(n^2)`» верно только при больших `n` и при сравнении худших случаев.
* **Забывать про скрытую сложность вызовов.** `if x in list` внутри цикла по `n` элементов - уже `O(n^2)`; срез `a[i:]` в цикле копирует массив; конкатенация строк в цикле может быть квадратичной.
* **Оставлять только лучший случай.** Алгоритм «в среднем быстрый» может иметь ужасный худший случай; в тестах задачи худшие данные обязательно будут.
* **Инициализировать `best` нулём.** В задаче урока при всех отрицательных числах правильный ответ - отрицательный; нулевая инициализация возвращает 0. Берите первый элемент.
* **Переполнение.** Сумма миллионов чисел порядка 10^9 не помещается в 32 бита: в Java, C++, Rust используйте `long`, `long long`, `i64`. В Python и JavaScript (до 2^53) проблемы нет в этих границах.
* **Считать, что константы не важны никогда.** При `n` порядка 10 или при одинаковой асимптотике константа решает; при росте `n` решает класс.

## Итоги

* Сложность - это зависимость числа элементарных шагов (и памяти) от размера входа; константы и младшие слагаемые отбрасываются.
* `O` - верхняя граница, `Ω` - нижняя, `Θ` - точная. Если не оговорено иное, речь о худшем случае.
* Последовательные блоки складываются, вложенные циклы перемножаются, деление пополам даёт логарифм.
* Допустимый класс определяют ограничения: для `n ~ 2·10^5` нужны `O(n)` или `O(n log n)`.
* Рост проверяют счётчиком операций и экспериментом удвоения; секундомер на одном входе ничего не доказывает.
* Лучшая полоса решается за `Θ(n)` по времени и `O(1)` по памяти; корректность доказывается инвариантом про `cur` и `best`.
