# Разбор: лучшая полоса

## Наивное решение
Перебрать все пары `(i, j)` и для каждой посчитать сумму: `O(n^3)`. С накоплением суммы по `j` получается `O(n^2)`:

```
best = -inf
для i в 0..n-1:
    s = 0
    для j в i..n-1:
        s += a[j]
        best = max(best, s)
```

При `n = 10^5` это около `5·10^9` итераций - десятки секунд в Python и несколько секунд даже в C++. На большом тесте решение получит превышение времени.

## Ключевая идея
Разобьём все отрезки по правой границе. Для фиксированной правой границы `i` лучший отрезок либо начинается в `i`, либо продолжает лучший отрезок для `i-1`. Значит достаточно хранить одно число - `cur(i)`:

`cur(i) = max(a[i], cur(i-1) + a[i])`, ответ - `max cur(i)`.

## Почему верно
Инвариант: перед шагом `i` `cur` - наилучшая сумма среди отрезков, оканчивающихся в `i-1`, а `best` - наилучшая среди всех отрезков в `a[0..i-1]`. Начало (`i = 1`) очевидно. Шаг: отрезок, оканчивающийся в `i`, - это `a[i]` плюс отрезок, оканчивающийся в `i-1`, который можно и не брать; выбор лучшего варианта и есть `max`. Любой отрезок либо оканчивается в `i`, либо лежит левее, значит `best` обновляется верно.

## Сложность
Время `Θ(n)`, память `O(1)`. Ввод и вывод - тоже `O(n)`, поэтому быстрого ввода достаточно (в Java - `StreamTokenizer`, в C++ - `sync_with_stdio(false)`, в Rust - чтение всего ввода одной строкой).

## Подводные камни
* Инициализация нулём ломает случай «все отрицательные».
* Переполнение `int`: сумма до `2·10^14`.
* Пустые отрезки запрещены, поэтому «ответ не меньше 0» неверен.

## Что обобщается
Тот же приём - «лучшее решение, оканчивающееся здесь» - лежит в основе динамического программирования. Он же позволяет искать и сам отрезок: запоминайте, где `cur` последний раз «перезапускался».
