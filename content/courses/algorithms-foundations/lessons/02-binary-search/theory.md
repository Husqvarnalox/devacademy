## Угадай число

Загадано число от 1 до 1000. Вы спрашиваете: «больше 500?» - ответ «да» оставляет 500 вариантов, «нет» - тоже 500. Следующий вопрос снова делит остаток пополам. Через 10 вопросов останется один вариант, потому что `2^10 = 1024`. Так же работает **бинарный поиск**: каждая проверка выбрасывает половину возможных ответов.

Для массива из миллиона элементов достаточно 20 сравнений вместо миллиона (мы видели это в [уроке про сложность](lesson:algorithms.foundations.complexity)). Условие одно: **данные упорядочены** так, что ответ на вопрос «больше ли?» однозначно говорит, в какой половине искать.

Главное, что стоит вынести из урока: бинарный поиск - это не про массивы, а про **монотонное условие**. Представьте строку из символов `Н Н Н Н Д Д Д Д Д`, где «Н» - значение не подходит, «Д» - подходит. Нужно найти границу. Проверяя среднюю позицию, мы выбрасываем либо левую, либо правую часть. Массив, отсортированный по возрастанию, и вопрос «a[i] >= x?» дают как раз такую строку. Но вопрос «хватит ли досок на куски длины L?» устроен так же: для малых `L` - «Д», для больших - «Н». Тогда искать можно не индекс, а само значение ответа.

Бинарный поиск знаменит тем, что его легко написать с ошибкой на единицу. Спасает дисциплина: заранее сформулировать **инвариант** - утверждение, истинное в начале каждой итерации, - и выводить из него каждую строку кода.

## Инвариант и полуинтервал

Будем искать **первую** позицию `i`, где условие `P(i)` становится истинным, при условии, что `P` монотонно: `Н...НД...Д` (в массиве: `P(i) = a[i] >= x`). Если «Д» нет, ответом считаем `n`.

Храним границы `lo` и `hi` в виде полуинтервала `[lo, hi)`:

> **Инвариант:** все позиции левее `lo` - «Н»; все позиции от `hi` и правее - «Д». Значит, первая «Д» лежит в `[lo, hi]`.

```
lo = 0; hi = n
пока lo < hi:
    mid = (lo + hi) // 2           # lo <= mid < hi
    если P(mid) ложно: lo = mid + 1 # mid - «Н», значит, и всё левее
    иначе:            hi = mid      # mid - «Д», ответ не правее mid, но mid ещё может быть ответом
вернуть lo                          # lo == hi
```

**Почему это верно.**

* *Начало:* при `lo = 0`, `hi = n` условия инварианта выполнены тривиально (слева и справа от диапазона нет позиций).
* *Шаг:* `lo < hi`, значит `mid` лежит в `[lo, hi)`. Если `P(mid)` ложно, то по монотонности ложно всё в `[0, mid]`, и `lo = mid + 1` сохраняет инвариант. Если истинно, то истинно всё в `[mid, n)`, и `hi = mid` его сохраняет.
* *Завершение:* `hi - lo` строго уменьшается (в первом случае растёт `lo`, во втором `hi` становится меньше, потому что `mid < hi`). Значит цикл заканчивается. При `lo == hi` инвариант говорит: левее `lo` - «Н», с `lo` и правее - «Д». Это и есть ответ.
* *Число шагов:* длина `hi - lo` сокращается минимум вдвое, поэтому итераций не больше `⌈log2(n + 1)⌉`.

**Две границы - два вопроса.** `lower_bound(x)` - первый индекс, где `a[i] >= x`. `upper_bound(x)` - первый индекс, где `a[i] > x`. Количество элементов, равных `x`, - это `upper_bound(x) - lower_bound(x)`.

## Бинарный поиск по ответу

Пусть требуется найти **наибольшее** целое `v`, для которого `ok(v)` истинно, причём `ok` монотонно: `Д...ДН...Н` (чем больше `v`, тем труднее). Здесь удобно другое представление: храним пару `(lo, hi)`, где

> **Инвариант:** `ok(lo)` истинно (для границы допускается «условно истинное» значение, например `0`), `ok(hi)` ложно.

```
lo = условно_подходящее; hi = заведомо_неподходящее
пока hi - lo > 1:
    mid = lo + (hi - lo) // 2
    если ok(mid): lo = mid иначе: hi = mid
вернуть lo
```

Цикл останавливается, когда `lo` и `hi` соседи; тогда `lo` - последнее подходящее значение. Условие `hi - lo > 1` гарантирует `lo < mid < hi`, и граница обязательно сдвигается: бесконечного цикла нет.

**Сложность.** Диапазон ответа `C` делится пополам: `O(log C)` проверок. Если проверка стоит `O(f)`, всё решение - `O(f · log C)`. В задаче урока `f = n`, `C = 10^9`, итого около `30 n` операций.

**Три вещи, которые нужно проверить до написания кода:**

1. Монотонность `ok`: если `ok(v)`, то `ok(w)` для всех `w` «лучше» `v`. Без неё бинарный поиск даёт бессмысленный результат.
2. Границы: `lo` действительно подходит (или условно считается подходящим), `hi` действительно не подходит.
3. Типы: диапазон и промежуточные величины (число кусков, `mid * mid`) могут не поместиться в 32 бита.

**Переполнение `mid`.** Выражение `(lo + hi) / 2` при `lo + hi > 2^31 - 1` в языках с 32-битными целыми даёт отрицательное число. Пишите `lo + (hi - lo) / 2` - оно безопасно всегда. В Python целые произвольной длины и этой проблемы нет, но привычку стоит сохранить.

**Нецелый ответ.** Для вещественного ответа (например, корень или оптимальное время) делают фиксированное число итераций (60-100), а не сравнивают `hi - lo > 1`; сравнение вещественных чисел с «нулём» ненадёжно.

## Примеры

**Пример 1. lower_bound и upper_bound.** Сравниваем собственную реализацию с `bisect` из стандартной библиотеки.

```python run
import bisect

def lower_bound(a, x):
    """Первый индекс i, где a[i] >= x (или len(a), если такого нет)."""
    lo, hi = 0, len(a)           # инвариант: ответ в [lo, hi]
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1         # a[0..mid] < x, ответ правее
        else:
            hi = mid             # a[mid] >= x, ответ не правее mid
    return lo

def upper_bound(a, x):
    """Первый индекс i, где a[i] > x."""
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] <= x:
            lo = mid + 1
        else:
            hi = mid
    return lo

a = [1, 3, 3, 3, 7, 9, 9]
for x in (0, 3, 4, 9, 10):
    print(x, lower_bound(a, x), upper_bound(a, x), bisect.bisect_left(a, x), bisect.bisect_right(a, x))
print("сколько троек:", upper_bound(a, 3) - lower_bound(a, 3))
```
```output
0 0 0 0 0
3 1 4 1 4
4 4 4 4 4
9 5 7 5 7
10 7 7 7 7
сколько троек: 3
```

Обратите внимание на `x = 4`: такого числа нет, обе границы равны 4 - это позиция, куда `4` можно вставить, не нарушив порядок.

**Пример 2. Бинарный поиск по значению: целый корень.** Найти наибольшее `v`, для которого `v · v <= n`. Здесь нет массива вообще: условие `v·v <= n` монотонно по `v`.

```python run
def isqrt_floor(n):
    """Наибольшее v, для которого v*v <= n (n >= 0)."""
    lo, hi = 0, n + 1            # инвариант: lo подходит (lo*lo <= n), hi не подходит (hi*hi > n)
    while hi - lo > 1:
        mid = (lo + hi) // 2
        if mid * mid <= n:
            lo = mid
        else:
            hi = mid
    return lo

for n in (0, 1, 15, 16, 17, 10**12):
    print(n, isqrt_floor(n))
```
```output
0 0
1 1
15 3
16 4
17 4
1000000000000 1000000
```

**Пример 3. Задача урока: распил досок.** Проверка `pieces(a, L) >= k` монотонно убывает по `L`, поэтому ищем наибольшее подходящее `L`.

```python run
def pieces(a, length):
    return sum(x // length for x in a)

def longest_piece(a, k):
    lo, hi = 0, max(a) + 1       # lo подходит (0 - условно), hi не подходит
    while hi - lo > 1:
        mid = (lo + hi) // 2
        if pieces(a, mid) >= k:
            lo = mid
        else:
            hi = mid
    return lo

print(longest_piece([8, 5, 13], 6))
print(longest_piece([3, 4], 100))
print(longest_piece([10, 10, 10], 6))
```
```output
4
0
5
```

Третий пример показывает ответ «ровно k»: условие `>= k`, а не `> k`. Второй - ситуацию, когда `lo` так и остаётся условным нулём.

**Пример 4. Границы: почему hi = max(a) + 1.** `L = max(a) + 1` не даёт ни одного куска (`k >= 1`), значит гарантированно не подходит. Значение `L = 0` нельзя проверять функцией `pieces` - деление на ноль; именно поэтому нижняя граница «условная»: мы её не проверяем, а лишь возвращаем, если всё остальное не подошло.

## Типичные ошибки

* **Смешивать полуинтервал и отрезок.** Пара `hi = n` (за концом) требует `while lo < hi` и `hi = mid`; пара `hi = n - 1` (последний допустимый индекс) требует `while lo <= hi` и `hi = mid - 1`. Если взять половину от одного и половину от другого - получится бесконечный цикл или пропуск ответа. Выберите одну схему и держите инвариант.
* **`lo = mid` при `mid = (lo + hi) / 2` в замкнутом отрезке.** При `hi = lo + 1` `mid` равен `lo`, и цикл не сдвигается. Используйте схему с `hi - lo > 1` или верхнее среднее.
* **Искать в неотсортированных данных или по немонотонному условию.** Алгоритм не проверяет порядок и тихо вернёт случайный результат.
* **Переполнение.** `(lo + hi) / 2` в 32-битных `int` и произведения вроде `mid * mid`.
* **Перепутать `>=` и `>`.** Разница между `lower_bound` и `upper_bound`, а в задаче о досках - между «не менее k кусков» и «более k».
* **Недостаточно широкий диапазон.** `hi` обязан быть заведомо неподходящим; слишком маленький `hi` отсечёт настоящий ответ, слишком большой стоит лишь пары лишних итераций - предпочитайте второе.
* **Бинарный поиск там, где нужен хеш.** Если массив не отсортирован и нужно проверить одно значение, сортировка + бинарный поиск дороже простого прохода.

<!-- section: summary -->
## Итоги

* Бинарный поиск - это поиск границы в монотонной последовательности «Н...НД...Д»: проверка среднего элемента выбрасывает половину диапазона, итого `O(log n)` проверок.
* Правильность держится на инварианте. Для первого «Д»: слева от `lo` - «Н», справа от `hi` включительно - «Д». Для наибольшего подходящего значения: `lo` подходит, `hi` нет, цикл `while hi - lo > 1`.
* `lower_bound` и `upper_bound` вместе дают число вхождений; в Python это `bisect_left` и `bisect_right`.
* Бинарный поиск по ответу применим, если проверка «подходит ли `v`» монотонна; стоимость - `O(f · log C)`.
* Следите за типами (64 бита), переполнением `lo + hi` и за тем, что `lo` и `hi` действительно подходят и не подходят.
