## Накопительный итог

Выписка по счёту хранит ежедневные изменения и ещё колонку «остаток на конец дня». Чтобы узнать, сколько вы заработали с 10-го по 25-е число, не нужно складывать 16 чисел: достаточно вычесть остаток на конец 9-го из остатка на конец 25-го. Колонка остатков - это **префиксные суммы**. Один раз посчитав её за `O(n)`, мы получаем сумму любого отрезка за `O(1)`.

Теперь вопрос посложнее: сколько существует отрезков с суммой **ровно** `K`? Каждый отрезок задаётся парой остатков: «на конец дня `r`» и «на конец дня до начала отрезка». Их разность должна быть `K`. Мы идём по дням слева направо, а для остатка сегодня спрашиваем: «сколько раз раньше встречался остаток `сегодня - K`?» Для быстрого ответа на вопрос «сколько раз встречалось значение» нужна структура, которая отвечает за `O(1)`, - **хеш-таблица** (в Python это `dict`).

Эта пара приёмов заменяет `n^2` пар границ одним проходом и - в отличие от скользящего окна из [прошлого урока](lesson:algorithms.foundations.two-pointers) - работает и с отрицательными числами.

## Префиксные суммы

Для массива `a[0..n-1]` определим `P[0] = 0`, `P[i] = a[0] + ... + a[i-1]` (`n + 1` значение). Тогда

`P[i+1] = P[i] + a[i]`, а сумма отрезка `a[l..r]` (включительно) равна `P[r+1] - P[l]`.

Доказательство: `P[r+1] - P[l] = (a[0] + ... + a[r]) - (a[0] + ... + a[l-1]) = a[l] + ... + a[r]`.

Предобработка `Θ(n)` по времени и памяти, каждый запрос `Θ(1)`. Если запросов `q`, то всё стоит `O(n + q)` вместо `O(n·q)` при суммировании «в лоб». Двумерный вариант (`P[i][j]` - сумма прямоугольника) даёт сумму любого прямоугольника по четырём значениям.

## Отрезки с суммой ровно k

Нужно посчитать пары `0 <= l <= r < n` с `a[l] + ... + a[r] = k`, то есть пары индексов `0 <= i < j <= n` с `P[j] - P[i] = k` (здесь `i = l`, `j = r + 1`). Фиксируем `j`: подходящие `i` - это те индексы левее `j`, у которых `P[i] = P[j] - k`. Число таких `i` - сколько раз значение `P[j] - k` встречалось среди `P[0..j-1]`.

```
seen = { 0: 1 }          # P[0] = 0
cur = 0; ответ = 0
для x из a:
    cur += x              # cur = P[j]
    ответ += seen.get(cur - k, 0)
    seen[cur] = seen.get(cur, 0) + 1
```

**Инвариант.** Перед обработкой элемента с индексом `j-1` (то есть при подсчёте для `P[j]`) словарь `seen` содержит для каждого значения `v` ровно число индексов `i` из `[0, j-1]` с `P[i] = v`. Порядок операций важен: сначала запрос, потом вставка текущего значения. Тогда пара `(i, j)` всегда имеет `i < j` и учитывается ровно один раз - когда мы стоим в `j`. Запись `{0: 1}` соответствует `P[0] = 0` (пустой префикс): без неё не учитываются отрезки, начинающиеся с первого элемента.

**Сложность.** Один проход, `O(1)` в среднем на операцию со словарём: `O(n)` ожидаемо, память `O(n)`.

## Хеш-таблица

**Устройство.** Для ключа `x` вычисляется целое `h(x)`, индекс ячейки равен `h(x) mod m`. Если в ячейке уже лежит другой ключ (**коллизия**), используют цепочки (список в ячейке) или открытую адресацию (поиск соседней свободной). Когда таблица заполнена больше, чем на заданную долю, она увеличивается вдвое и все ключи вставляются заново; такое расширение стоит `O(n)`, но случается редко, поэтому вставка в среднем `O(1)` (амортизированно).

**Стоимость.** Ожидаемо `O(1)` на поиск и вставку при хорошей хеш-функции. В худшем случае (все ключи в одной ячейке) `O(n)`. Ключи **не упорядочены**.

**Когда хеш-таблица не подходит или нежелательна.**

* Нужен порядок (ближайшее большее значение, диапазонные запросы) - используйте отсортированный массив или дерево.
* Есть риск специально подобранных ключей (атака коллизиями) - рандомизируйте хеш или используйте упорядоченный словарь (`std::map`, `TreeMap`) с операциями `O(log n)`. Замена одной сортировкой массива префиксных сумм здесь не подходит: сортировка теряет порядок индексов, а нам важно `i < j`.
* Значения - небольшие целые числа в известном диапазоне: быстрее и надёжнее массив-счётчик.

**Почему нельзя скользящее окно.** При отрицательных числах сумма не монотонна: если окно `[l, r]` имеет сумму больше `k`, расширение вправо может вернуть сумму к `k`. Следовательно, «сжать слева» нельзя: мы можем потерять подходящий отрезок. Префиксные суммы не требуют монотонности - они лишь сравнивают значения на равенство.

## Примеры

**Пример 1. Префиксные суммы и запросы за O(1).**

```python run
from itertools import accumulate

a = [3, -1, 4, 1, -5, 9, 2]
prefix = [0] + list(accumulate(a))     # prefix[i] = a[0] + ... + a[i-1]
print(prefix)

def range_sum(l, r):
    """Сумма a[l..r] включительно за O(1)."""
    return prefix[r + 1] - prefix[l]

print(range_sum(0, 6), range_sum(2, 4), range_sum(3, 3))
assert range_sum(2, 4) == sum(a[2:5])
```
```output
[0, 3, 2, 6, 7, 2, 11, 13]
13 0 1
```

**Пример 2. Подсчёт отрезков с суммой k и проверка перебором.**

```python run
def count_k_brute(a, k):
    n = len(a)
    return sum(1 for l in range(n) for r in range(l, n) if sum(a[l:r + 1]) == k)

def count_k(a, k):
    seen = {0: 1}          # префиксная сумма -> сколько раз встречалась (пустой префикс = 0)
    cur = 0
    ans = 0
    for x in a:
        cur += x
        ans += seen.get(cur - k, 0)   # сколько левых границ дают сумму ровно k
        seen[cur] = seen.get(cur, 0) + 1
    return ans

for a, k in (([1, 2, 3], 3), ([1, -1, 1, -1], 0), ([0, 0, 0], 0), ([2, -2, 3, 0, 1, -4, 2], 1), ([5], 7)):
    print(a, k, count_k(a, k), count_k_brute(a, k))
```
```output
[1, 2, 3] 3 2 2
[1, -1, 1, -1] 0 4 4
[0, 0, 0] 0 6 6
[2, -2, 3, 0, 1, -4, 2] 1 4 4
[5] 7 0 0
```

В трёх нулях (`K = 0`) префиксные суммы `[0, 0, 0, 0]`: четыре одинаковых значения, пар `C(4, 2) = 6`.

**Пример 3. Почему окно ломается.** Для `[1, -1, 1]` и `k = 1` подходят отрезки `[1]`, `[1, -1, 1]` и последний `[1]`: три. Скользящее окно для каждого `r` рассматривает лишь одно окно и не умеет вернуть сумму обратно к `k` через отрицательный элемент, поэтому пропускает отрезок `[1, -1, 1]`.

```python run
def count_window(a, k):
    """Скользящее окно: верно только для положительных чисел."""
    left = cur = ans = 0
    for right, x in enumerate(a):
        cur += x
        while cur > k and left <= right:
            cur -= a[left]; left += 1
        if cur == k and left <= right:
            ans += 1
    return ans

def count_hash(a, k):
    seen, cur, ans = {0: 1}, 0, 0
    for x in a:
        cur += x
        ans += seen.get(cur - k, 0)
        seen[cur] = seen.get(cur, 0) + 1
    return ans

print(count_window([1, 2, 3], 3), count_hash([1, 2, 3], 3))
print(count_window([1, -1, 1], 1), count_hash([1, -1, 1], 1))
```
```output
2 2
2 3
```

На положительных числах оба способа совпадают, на `[1, -1, 1]` окно даёт 2 вместо верных 3.

**Пример 4. Порядок «сначала запрос, потом вставка».** Для `a = [0]`, `k = 0` правильный ответ 1 (отрезок `[0]`). Идём: `cur = 0`; спрашиваем `seen[0 - 0]` - там 1 (начальная запись `{0: 1}`) - и только затем кладём `seen[0] = 2`. Если вставить раньше запроса, получим 2: к ответу добавится «пара» `i = j`, то есть пустой отрезок. Поэтому порядок операций обязателен.

## Типичные ошибки

* **Забыть `{0: 1}`.** Теряются отрезки, начинающиеся с первого элемента.
* **Вставить текущее значение до запроса.** В пару попадает `i = j`, то есть пустой отрезок. При `k = 0` это сразу даёт завышенный ответ.
* **Скользящее окно при отрицательных числах.** Жертвует корректностью ради «красивого» решения.
* **Сломанный индекс префикса.** Сумма `a[l..r]` - это `P[r+1] - P[l]`, а не `P[r] - P[l]`. Если массив префиксов хранится без `P[0] = 0`, границы сдвигаются и легко совершить ошибку на единицу.
* **32-битные префиксные суммы.** Префиксные суммы достигают `2·10^14`; в Java, C++, Rust ключи и значения - `long`, `long long`, `i64`.
* **Считать множество вместо мультимножества.** Нужно не «встречалось ли значение», а «сколько раз»: в словаре хранится счётчик.
* **Игнорировать худший случай хеш-таблицы.** Для обычных тестов `unordered_map` и `HashMap` быстры; если задача допускает специально подобранные данные, используйте сортировку.

<!-- section: summary -->
## Итоги

* Префиксные суммы `P[0] = 0`, `P[i+1] = P[i] + a[i]`: сумма `a[l..r] = P[r+1] - P[l]`, предобработка `O(n)`, запрос `O(1)`.
* Отрезки с суммой `k` - это пары индексов `i < j` с `P[j] - P[i] = k`: для каждого `j` нужно число прежних вхождений `P[j] - k`.
* Хеш-таблица даёт это число за `O(1)` в среднем; в начале в ней лежит `{0: 1}`, а порядок операций - сначала запрос, потом вставка.
* Метод не требует монотонности и поэтому работает с отрицательными числами, в отличие от скользящего окна.
* Хеш-таблица: ожидаемо `O(1)`, в худшем случае `O(n)`, ключи не упорядочены; альтернатива - сортировка.
