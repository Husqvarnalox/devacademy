# Разбор: ровно K

## Наивное решение
Перебирать пары границ `(l, r)` и накапливать сумму: `O(n^2)`. При `n = 10^5` это `5·10^9` итераций, а раннего прерывания нет: числа бывают отрицательными, сумма не монотонна.

## Ключевая идея
Пусть `P[i]` - сумма первых `i` элементов (`P[0] = 0`). Сумма отрезка `a[l..r]` равна `P[r+1] - P[l]`. Условие «сумма равна `K`» превращается в `P[j] - P[i] = K` при `i < j`. Для каждого `j` нужно число `i < j` с `P[i] = P[j] - K`. Этот вопрос - «сколько раз значение встречалось среди уже пройденных» - решает хеш-таблица со счётчиками.

## Алгоритм
```
seen = {0: 1}
cur = 0; ans = 0
для x в a:
    cur += x
    ans += seen[cur - K]  (0, если ключа нет)
    seen[cur] += 1
```

## Почему верно
Инвариант: перед обработкой `j`-го префикса `seen[v]` равно числу `i < j` с `P[i] = v`. Начальное состояние `{0: 1}` соответствует единственному `i = 0`. На шаге `j` мы прибавляем число подходящих `i`, затем добавляем `P[j]`, сохраняя инвариант для `j + 1`. Каждая пара `(i, j)` с `i < j` подсчитывается ровно на шаге `j`.

## Сложность
Время `O(n)` ожидаемо, память `O(n)`. Альтернатива без хеширования - упорядоченный словарь (`TreeMap`, `std::map`): `O(n log n)`; он нужен, если нельзя полагаться на хеш-функцию.

## Подводные камни
* Ответ до `n(n+1)/2 ≈ 2·10^10`; префиксные суммы до `2·10^14`: 64-битные типы.
* Порядок: сначала запрос `seen[cur - K]`, потом вставка `seen[cur]`.
* Начальное `{0: 1}`.
* В JavaScript `Map` с числовыми ключами корректно работает для целых до `2^53`; обычный объект `{}` тоже, но Map быстрее и не приводит ключи к строкам.
