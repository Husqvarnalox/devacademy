## Окошко, которое ползёт по массиву

Представьте рамку, закрывающую несколько подряд идущих чисел. Мы двигаем **правый** край рамки вправо, чтобы добавить число, и **левый** край вправо, чтобы убрать старое. Рамка никогда не ходит назад. За один проход по массиву каждый край пройдёт не более `n` позиций - значит, всего `O(n)` шагов, хотя внутри цикла есть ещё один цикл.

Это и есть **два указателя**. Приём заменяет перебор всех пар границ `(l, r)`, то есть `n^2` вариантов, одним проходом. Почему так можно? Потому что часть пар перебирать не нужно: мы заранее знаем, что они не подойдут (или что подходят). Знание это даёт **монотонность**: если сумма положительных чисел слишком велика, то при расширении отрезка она станет ещё больше.

Два типичных случая:

1. **Два указателя с двух концов** упорядоченного массива, которые идут навстречу друг другу (поиск пары с суммой `T`).
2. **Скользящее окно**: оба указателя идут в одну сторону, окно растёт справа и сжимается слева, пока выполняется условие.

## Пара с заданной суммой в упорядоченном массиве

Массив `a` упорядочен по возрастанию, нужно найти `i < j` с `a[i] + a[j] = T`. Ставим `i = 0`, `j = n - 1`:

```
пока i < j:
    s = a[i] + a[j]
    если s == T: найдено
    если s < T:  i += 1     # a[i] слишком мал даже с наибольшим из оставшихся
    иначе:       j -= 1     # a[j] слишком велик даже с наименьшим из оставшихся
```

**Инвариант.** Если пара существует, обе её позиции лежат в `[i, j]`. *Шаг:* при `s < T` для любого `k` в `[i+1, j]` верно `a[i] + a[k] <= a[i] + a[j] < T`, поэтому `i` не входит ни в одну подходящую пару - его выбрасываем; симметрично при `s > T`. Диапазон сокращается на 1 за шаг, поэтому время `O(n)`, память `O(1)`.

## Скользящее окно переменной длины

Задача: числа `a_i > 0`, посчитать отрезки с суммой не более `S`. Для правой границы `r` обозначим `l(r)` самую левую позицию, при которой сумма `a[l..r]` не превышает `S`. Тогда подходящие отрезки с правым концом `r` - это начала `l(r), l(r)+1, ..., r`, их `r - l(r) + 1`.

**Ключевое наблюдение:** `l(r)` не убывает при росте `r`. Действительно, если отрезок `[l, r+1]` подходит, то и вложенный в него `[l, r]` подходит (числа положительные, сумма меньше). Значит `l(r+1) >= l(r)`, и левый указатель можно только двигать вправо.

```
l = 0; cur = 0; ответ = 0
для r от 0 до n-1:
    cur += a[r]
    пока cur > S:           # окно слишком тяжёлое
        cur -= a[l]; l += 1
    ответ += r - l + 1      # начала l..r
```

**Инвариант.** После внутреннего цикла `cur` равно сумме `a[l..r]`, и `l` - наименьшая позиция, для которой эта сумма `<= S` (при `l = r + 1` окно пусто, `cur = 0`). Доказательство: `l` уменьшать не приходится по монотонности выше; увеличиваем `l` ровно до тех пор, пока сумма превышает `S`, а убрав элемент мы получаем сумму строго меньше - оптимальное `l` не пропущено.

**Амортизированный анализ.** Одна итерация внешнего цикла может выполнить `while` много раз, но `l` только растёт и не превосходит `n`: за весь проход `while` выполнится не более `n` раз. Вместе с `n` итерациями внешнего цикла получаем не более `2n` элементарных шагов: `Θ(n)`. Память `O(1)`.

**Условие применимости.** Нужна монотонность: расширение окна не уменьшает «стоимость», сжатие не увеличивает. При положительных числах сумма монотонна. При **отрицательных** числах сумма окна может уменьшаться при расширении, и приём ломается; тогда используют префиксные суммы и хеш-таблицу ([следующий урок](lesson:algorithms.foundations.prefix-sums-hashing)).

## Окно фиксированной длины

Если длина окна задана числом `k`, то при сдвиге добавляем элемент справа и убираем слева: `cur += a[i] - a[i-k]`. Это `O(n)` вместо `O(nk)` при пересчёте суммы заново.

## Примеры

**Пример 1. Пара с суммой в упорядоченном массиве.**

```python run
def pair_with_sum(a, target):
    """a отсортирован по возрастанию. Возвращает индексы (i, j), i < j, a[i] + a[j] == target, или None."""
    i, j = 0, len(a) - 1
    while i < j:
        s = a[i] + a[j]
        if s == target:
            return i, j
        if s < target:
            i += 1          # a[i] слишком мал даже с самым большим из оставшихся - выбрасываем его
        else:
            j -= 1          # a[j] слишком велик даже с самым маленьким - выбрасываем его
    return None

a = [1, 3, 4, 6, 8, 11]
for target in (10, 14, 2, 20):
    print(target, pair_with_sum(a, target))
```
```output
10 (2, 3)
14 (1, 5)
2 None
20 None
```

**Пример 2. Скользящее окно и подсчёт ходов указателей.** Число шагов не превышает `2n`, хотя внутри есть ещё один цикл.

```python run
def count_segments(a, limit):
    total = 0
    left = 0
    cur = 0
    moves = 0                       # сколько раз сдвинулись указатели
    for right, x in enumerate(a):
        cur += x
        moves += 1
        while cur > limit:
            cur -= a[left]
            left += 1
            moves += 1
        total += right - left + 1
    return total, moves

print(count_segments([2, 1, 3, 1, 1], 4))
print(count_segments([5, 5, 5], 4))
n = 1000
print(count_segments([1] * n, 10 * n))
print(count_segments([3, 1, 4, 1, 5, 9, 2, 6] * 100, 10))
```
```output
(9, 8)
(0, 6)
(500500, 1000)
(1898, 1598)
```

В последнем примере `n = 800`, а ходов указателей `1598 < 2n = 1600`.

**Пример 3. Окно фиксированной длины.**

```python run
def best_window_sum(a, k):
    """Наибольшая сумма k подряд идущих элементов."""
    cur = sum(a[:k])
    best = cur
    for i in range(k, len(a)):
        cur += a[i] - a[i - k]      # окно сдвинулось: добавили новый, убрали старый - O(1)
        best = max(best, cur)
    return best

print(best_window_sum([4, -1, 2, 7, -3, 5, 1], 3))
print(best_window_sum([1, 2, 3], 3))
```
```output
9
6
```

Окно фиксированной длины работает и с отрицательными числами: условие «ровно `k` элементов» не зависит от знака.

**Разбор примера 2, первый запуск.** `a = [2, 1, 3, 1, 1]`, `limit = 4`. Для `r = 0`: окно `[2]`, подходит 1 отрезок. `r = 1`: `[2, 1]`, сумма 3, подходит 2. `r = 2`: добавили 3, сумма 6 > 4, убираем 2 → 4, окно `[1, 3]`; отрезки `[1, 3]` и `[3]` - 2. `r = 3`: сумма 5 > 4, убираем 1 → 4, окно `[3, 1]`: 2 отрезка. `r = 4`: сумма 5, убираем 3 → 2, окно `[1, 1]`: 2. Итого `1 + 2 + 2 + 2 + 2 = 9`.

## Типичные ошибки

* **Применять окно при отрицательных числах.** Сумма не монотонна; корректный ответ нужно искать иначе (префиксные суммы).
* **Считать только максимальное окно.** Чтобы посчитать *все* подходящие отрезки, добавляйте `r - l + 1` на каждом шаге, а не только 1.
* **Выход за границы.** Если `a[r] > S`, внутренний цикл сдвинет `l` до `r + 1`; в этот момент окно пусто и `cur = 0`. Условие `cur > limit` при пустом окне ложно, поэтому доступа к `a[n]` нет. Но если условие записать как `l <= r and ...` с ошибкой, легко прочитать лишний элемент.
* **Нестрогое/строгое условие.** «Не превышает» - это `cur <= S` допустимо, цикл сжатия идёт по `cur > S`.
* **Срезы вместо индексов.** `sum(a[l:r+1])` на каждом шаге возвращает квадратичную сложность.
* **Возвращать указатель назад.** Если ваш алгоритм требует уменьшать `l`, это не скользящее окно; пересмотрите идею.
* **Забыть про переполнение.** Сумма окна и ответ выходят за 32 бита.

<!-- section: summary -->
## Итоги

* Два указателя убирают перебор пар границ за счёт монотонности: часть вариантов можно отбросить заранее.
* Пара с суммой в упорядоченном массиве - указатели с двух концов навстречу, `O(n)`.
* Скользящее окно: правый указатель добавляет, левый сжимает окно, пока условие нарушено; для каждого `r` подходящие начала - `l..r`.
* Линейность доказывается амортизированно: каждый указатель делает не более `n` шагов.
* Приём требует монотонности (положительные числа); при отрицательных нужны префиксные суммы.
