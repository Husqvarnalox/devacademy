## Волна по лабиринту

Бросьте камень в воду: волна расходится кольцами, и каждое следующее кольцо дальше от центра ровно на шаг. Поиск в ширину (**BFS**, breadth-first search) делает то же самое в лабиринте: сначала посещает клетки на расстоянии 0 от старта, потом на расстоянии 1, потом 2, и так далее. Поэтому когда «волна» впервые доходит до финиша, пройденный ею путь - кратчайший.

Сетку удобно считать **графом**: клетки - вершины, а рёбра соединяют соседние (вверх, вниз, влево, вправо) проходимые клетки. Все рёбра одинаковой длины - в один шаг. Для таких графов BFS и есть правильный инструмент. Он использует **очередь** (первым пришёл - первым ушёл): клетки ближнего кольца стоят в очереди раньше клеток дальнего.

Последняя часть урока учит самому важному приёму: иногда клетки недостаточно, чтобы описать положение. Если можно один раз пробить стену, то «стоять в клетке (3, 4) с неиспользованным тараном» и «стоять в клетке (3, 4) с использованным» - разные положения. Тогда вершиной графа становится пара.

## BFS на сетке

Дано поле `n x m`. Из клетки `(r, c)` можно перейти в четыре соседние, если они внутри поля и не стена.

```
dist[старт] = 0; очередь = [старт]
пока очередь не пуста:
    v = извлечь из начала очереди
    для каждого соседа u клетки v:
        если u проходима и dist[u] не задано:
            dist[u] = dist[v] + 1
            добавить u в конец очереди
```

Ответ - `dist[финиш]`, если оно задано, иначе пути нет.

**Где отмечать «посещено».** При **добавлении** в очередь (здесь это запись `dist[u]`), а не при извлечении. Иначе одну клетку могут добавить несколько соседей, прежде чем её извлекут, и очередь раздуется.

**Инвариант.** В любой момент очередь, прочитанная слева направо, содержит клетки с расстояниями `d, d, ..., d, d+1, ..., d+1` - не убывающие и отличающиеся не более чем на 1, а `dist` каждой клетки в очереди равно длине кратчайшего пути до неё.

**Корректность (индукция по расстоянию).** Пусть все клетки на расстоянии `< d` уже найдены с верным `dist`. Клетка `u` на настоящем расстоянии `d` имеет соседа `v` на расстоянии `d - 1` (предпоследняя клетка кратчайшего пути). Когда `v` извлекается, `u` либо уже получила `dist`, либо получает его теперь, и значение равно `dist[v] + 1 = d`. Меньшим оно быть не может: меньшее значение означало бы существование более короткого пути. Из-за FIFO клетки слоя `d - 1` извлекаются до слоя `d`, так что инвариант сохраняется.

**Сложность.** Каждая клетка попадает в очередь не более одного раза и при извлечении просматривает четыре соседа: `O(V + E) = O(n·m)`, память `O(n·m)`.

**Очередь, а не стек.** Стек (или рекурсия) превращает алгоритм в поиск в глубину: он найдёт путь, но не обязательно кратчайший. В Python `list.pop(0)` стоит `O(n)` - используйте `collections.deque` или индекс головы.

**BFS не подходит**, если рёбра имеют разную длину (нужен алгоритм Дейкстры) или есть отрицательные веса.

## Расширение состояния

Задача этого урока: пройти от `S` до `E`, разрешив пробить **не более одной** стены (шаг в клетку `#` тратит таран). Вершина графа - пара `(клетка, использован_ли_таран)`: `2·n·m` состояний. Из `(v, 0)` в стену ведёт ребро в `(u, 1)`, в пустую клетку - в `(u, 0)`; из `(v, 1)` в стену идти нельзя. Все рёбра по-прежнему длины 1, поэтому BFS остаётся верным. Ответ - минимум из `dist[(E, 0)]` и `dist[(E, 1)]`. Время `O(n·m)`, память `O(n·m)`.

Заметьте, чем отличается это от «пробить каждую стену и запустить BFS»: стен может быть `Θ(n·m)`, и общее время - `Θ((n·m)^2)`. Расширение состояния делает за один обход то, на что наивный перебор тратит тысячи.

## Примеры

**Пример 1. Кратчайший путь в лабиринте.**

```python run
from collections import deque

def shortest_path(grid):
    """Кратчайший путь от 'S' до 'E' по клеткам '.', 4 направления. Возвращает число шагов или -1."""
    n, m = len(grid), len(grid[0])
    for r in range(n):
        for c in range(m):
            if grid[r][c] == "S":
                start = (r, c)
    dist = {start: 0}                      # dist одновременно служит отметкой «посещено»
    queue = deque([start])
    while queue:
        r, c = queue.popleft()
        if grid[r][c] == "E":
            return dist[(r, c)]
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < n and 0 <= nc < m and grid[nr][nc] != "#" and (nr, nc) not in dist:
                dist[(nr, nc)] = dist[(r, c)] + 1   # отмечаем при добавлении в очередь
                queue.append((nr, nc))
    return -1

maze = [
    "S.#....",
    ".##.##.",
    "....#E.",
]
print(shortest_path(maze))
print(shortest_path(["S#E"]))
print(shortest_path(["S..", "..E"]))
```
```output
13
-1
3
```

**Пример 2. Слои волны.** В пустой сетке 4 на 4 число клеток на расстоянии `d` от угла - это длина диагонали: `1, 2, 3, 4, 3, 2, 1`.

```python run
from collections import deque

def layers(n, m, start):
    """Для пустой сетки n x m выводим, сколько клеток на каждом расстоянии от start."""
    dist = {start: 0}
    queue = deque([start])
    while queue:
        r, c = queue.popleft()
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < n and 0 <= nc < m and (nr, nc) not in dist:
                dist[(nr, nc)] = dist[(r, c)] + 1
                queue.append((nr, nc))
    counts = {}
    for d in dist.values():
        counts[d] = counts.get(d, 0) + 1
    return counts

print(layers(4, 4, (0, 0)))
```
```output
{0: 1, 1: 2, 2: 3, 3: 4, 4: 3, 5: 2, 6: 1}
```

**Пример 3. Почему одной отметки на клетку мало.** Ниже две версии: с состоянием `(клетка, таран)` и с единственной отметкой на клетку. Верный путь - по верхней строке до клетки `(1, 2)`, а затем пробить стену `(2, 2)`. Но клетки `(1, 2)` одновременно достигает и путь, который уже пробил стену `(1, 1)`. Он попадает в очередь первым, закрывает клетку отметкой, и версия без пары теряет единственный путь.

```python run
def solve(grid, per_cell_visited):
    n, m = len(grid), len(grid[0])
    flat = "".join(grid)
    start, end = flat.index("S"), flat.index("E")
    dist = {(start, 0): 0}
    seen_cells = {start}
    queue = [(start, 0)]
    head = 0
    while head < len(queue):
        cell, used = queue[head]
        head += 1
        r, c = divmod(cell, m)
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if not (0 <= nr < n and 0 <= nc < m):
                continue
            ncell = nr * m + nc
            nused = used + (grid[nr][nc] == "#")
            if nused > 1:
                continue
            key = (ncell, nused)
            if per_cell_visited:
                if ncell in seen_cells:
                    continue
                seen_cells.add(ncell)
            elif key in dist:
                continue
            dist[key] = dist[(cell, used)] + 1
            queue.append(key)
    options = [d for (cell, used), d in dist.items() if cell == end]
    return min(options) if options else -1

grid = ["S..#", ".#.#", "#.#E"]
print("правильно:", solve(grid, False), " одна отметка на клетку:", solve(grid, True))
```
```output
правильно: 5  одна отметка на клетку: -1
```

Упрощённый вариант возвращает `-1`. Первым в клетку пришёл вариант с уже использованным тараном и закрыл её для варианта с неиспользованным, у которого возможностей больше.

## Типичные ошибки

* **Отмечать «посещено» при извлечении.** Клетка попадает в очередь многократно, время растёт, а на плотных сетках очередь может не поместиться в памяти.
* **Стек вместо очереди.** Это уже DFS, путь не кратчайший.
* **`list.pop(0)` в Python.** Каждое извлечение стоит `O(n)`, на сетке 500 на 500 это десятки секунд. Берите `deque` или индекс головы.
* **Забыть границы поля** или перепутать `n` и `m` (строки и столбцы) при линеаризации `r*m + c`.
* **Одна отметка на клетку в задаче с тараном.** Ответ может оказаться неверным (пример 3) или `-1` там, где путь есть.
* **Стартовая клетка совпадает с финишем.** Ответ 0; проверяйте раньше, чем теряете такой случай.
* **Рекурсивный DFS на большой сетке.** Глубина рекурсии до `n·m` ломает стек вызовов в Python, Java и других языках.
* **Перебор «пробить каждую стену».** Выглядит просто, но `Θ((n·m)^2)`: на больших сетках не укладывается во время.

## Итоги

* Сетка - граф: клетки - вершины, соседние проходимые клетки соединены рёбрами длины 1.
* BFS с очередью обходит вершины по неубывающему расстоянию, поэтому первое достижение цели даёт кратчайший путь (индукция по слоям).
* Время `O(n·m)`, память `O(n·m)`; отметку «посещено» ставят при добавлении в очередь.
* Если положения клетки недостаточно, расширяйте вершину: `(клетка, использован ли таран)`. Это превращает перебор вариантов в один обход.
* BFS подходит для невзвешенных графов; для разных длин рёбер нужны другие алгоритмы.
