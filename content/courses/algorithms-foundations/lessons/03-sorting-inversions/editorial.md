# Разбор: хаос в очереди

## Наивное решение
Две вложенных петли по парам `(i, j)`, `i < j`, и счётчик пар с `a[i] > a[j]`. Это `n(n-1)/2` сравнений: при `n = 10^5` около `5·10^9`. В Python такое решение работает минуты, и даже в C++ оно близко к лимиту. На больших тестах получится превышение времени.

## Идея
Разобьём массив пополам. Любая инверсия `(i, j)` лежит в одной из категорий: обе позиции слева, обе справа или `i` слева, а `j` справа. Первые две категории считают рекурсивные вызовы. Третью можно посчитать, если обе половины **упорядочены**, - а упорядочить их нам и так нужно для слияния.

## Алгоритм
```
count(a):
    если |a| <= 1: вернуть (a, 0)
    (L, x) = count(левая половина)
    (R, y) = count(правая половина)
    слить L и R:
        если L[i] <= R[j]: взять L[i]
        иначе: взять R[j]; z += |L| - i
    вернуть (результат, x + y + z)
```

## Почему верно
Пусть обе половины упорядочены. Допустим, мы берём `R[j]`, потому что `R[j] < L[i]`. Так как `L` упорядочена, все элементы `L[i..]` не меньше `L[i]`, а значит строго больше `R[j]`. Все они стоят левее `R[j]` в исходном массиве, поэтому образуют с ним ровно `|L| - i` инверсий. Элементы `L[0..i-1]` были взяты раньше, потому что оказывались `<=` текущего `R`-элемента, - с `R[j]` инверсий у них нет. Каждая «перекрёстная» пара (элемент слева, элемент справа) учитывается не более одного раза - в момент, когда берётся её правый элемент. Равные элементы не считаются, так как при равенстве берётся левый.

## Сложность
`T(n) = 2T(n/2) + Θ(n) = Θ(n log n)`. Память `O(n)` на буфер.

## Подводные камни
* Ответ до `n(n-1)/2 ≈ 2·10^10` - 64-битный счётчик (`long`, `long long`, `i64`). В JavaScript `Number` точен до `2^53`, хватает.
* Условие `<=`, а не `<`, - иначе равные пары попадут в ответ.
* Не создавайте новые массивы на каждом уровне, если важна константа: один буфер длины `n` - лучше (так сделано в решениях на Java, C++, Go, Rust).

## Другие решения
Дерево Фенвика (BIT) по сжатым значениям тоже даёт `O(n log n)`: идём слева направо и для каждого элемента считаем, сколько уже встреченных больше его. Это пригодится, когда сортировать нельзя, а нужны запросы «сколько элементов больше `x` среди префикса».
