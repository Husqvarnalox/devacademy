## Зачем этот урок

Если вы пишете на Java, C#, Python, JavaScript или Go, то переменные, условия и циклы Kotlin узнаете сразу. Отличия прячутся в мелочах: `Int` занимает ровно 32 бита и молча переполняется, `7 / 2` равно `3`, неявных преобразований между `Int`, `Long` и `Double` нет вообще, `if` и `when` возвращают значение, а `"%.2f".format(x)` на русской системе печатает запятую вместо точки. Урок собирает такие места вместе. Успешное прохождение (упражнение и квиз) засчитывает уроки 01-16 курса «Kotlin с нуля».

## Главная мысль

Kotlin статически типизирован и строг к типам: компилятор не превращает `Int` в `Long` или `Double` за вас, не даёт сравнить `5 == 5.0` и не позволяет присвоить дробное число целой переменной. Но **внутри** типа арифметика границ не проверяет. Три привычки решают большинство проблем: брать `Long`, когда сумма может выйти за два миллиарда; помнить, что деление целых отбрасывает дробную часть; и не забывать, что `if`, `when` и `try` - выражения, поэтому результат можно присвоить, а ветки обязаны быть полными.

## Пример 1. Целые числа: переполнение, деление, остаток

```kotlin run
fun main() {
    val big = Int.MAX_VALUE
    println(big + 1)
    println("${7 / 2} ${-7 / 2} ${-7 % 3} ${(-7).mod(3)}")
    println(big * 2)
    println(big.toLong() * 2)
    val a: Long = 1_000_000 * 3000
    val b: Long = 1_000_000L * 3000
    println("$a $b")
    println(3_000_000_000)
    println(Math.multiplyExact(100_000L, 100_000L))
    try {
        Math.addExact(big, 1)
    } catch (e: ArithmeticException) {
        println(e.message)
    }
    println(Int.MIN_VALUE == -Int.MIN_VALUE)
}
```
```output
-2147483648
3 -3 -1 2
-2
4294967294
-1294967296 3000000000
3000000000
10000000000
integer overflow
true
```

Разбор:

* Переполнение `Int` не бросает исключения: значение «заворачивается» от максимума к минимуму. `-Int.MIN_VALUE` остаётся равным `Int.MIN_VALUE`, потому что `+2147483648` в `Int` не помещается.
* Деление двух целых - целое с отбрасыванием дробной части **к нулю**: `7 / 2` равно `3`, а `-7 / 2` равно `-3`. Остаток `%` берёт знак делимого: `-7 % 3` равно `-1`. Неотрицательный остаток для положительного делителя даёт `mod` (а `floorDiv` делит с округлением вниз).
* `big * 2` вычисляется в `Int` и переполняется, поэтому преобразование нужно делать **до** умножения: `big.toLong() * 2`. Объявление `val a: Long = 1_000_000 * 3000` вас не спасает: оба множителя - `Int`, и произведение считается как `Int`; нужен хотя бы один `Long`-литерал (`1_000_000L`).
* Литерал, который не помещается в `Int` (`3_000_000_000`), Kotlin сам делает `Long`. Подчёркивания в числах нужны только для читаемости.
* `Math.addExact`, `subtractExact` и `multiplyExact` (это методы Java, доступные в Kotlin на JVM) бросают `ArithmeticException` при переполнении - удобно там, где молчаливая ошибка опаснее исключения.

## Пример 2. Никаких неявных преобразований: Long, Char, Double

```kotlin run
import kotlin.math.roundToInt

fun main() {
    val count = 5
    val total: Long = count.toLong() * 1_000_000_000
    println(total)
    val c = 'a'
    println(c + 1)
    println(c.code + 1)
    println('d' - 'a')
    println((c + 2).uppercaseChar())
    val d = 2.9
    println("${d.toInt()} ${(-2.9).toInt()} ${2.5.roundToInt()} ${(-2.5).roundToInt()}")
    println(0.1 + 0.2)
    val zero = 0.0
    println("${1.0 / zero} ${zero / zero}")
    println("${10 / 4 * 2.0} ${10 / 4.0 * 2}")
    println(200.toByte())
}
```
```output
5000000000
b
98
3
C
2 -2 3 -2
0.30000000000000004
Infinity NaN
4.0 5.0
-56
```

Разбор:

* `val total: Long = count` не скомпилируется даже без потери данных: `Int` в `Long` нужно переводить явно (`toLong()`). Так же и `Int` в `Double`. Зато скрытых сужений вроде `i += 2.7` для целой переменной не бывает - эта запись просто не компилируется.
* `Char` - не число. `'a' + 1` - это `Char` (`b`), `'d' - 'a'` - `Int` (`3`), код символа дают `code` и `Char(код)`. Привычное из Java и C `'a' + 1 == 98` в Kotlin неверно.
* `toInt()` у `Double` отбрасывает дробную часть к нулю (`(-2.9).toInt()` равно `-2`); `roundToInt()` (нужен `import kotlin.math.roundToInt`) округляет к ближайшему целому, а половину - в сторону плюс бесконечности (`(-2.5).roundToInt()` равно `-2`).
* Деление дробных чисел на ноль исключения не бросает: `Infinity` и `NaN`. Целое деление на ноль бросает `ArithmeticException`. Дроби неточны так же, как в любом языке с `Double`.
* Порядок вычислений важен: `10 / 4 * 2.0` сначала делит целые (получается `2`), `10 / 4.0 * 2` сразу работает с дробными.
* `200.toByte()` оставляет только младшие 8 бит и даёт `-56`: явные сужающие преобразования границ не проверяют.

## Пример 3. if и when - выражения, диапазоны, метки

```kotlin run
fun kind(day: String): String = when (day) {
    "sat", "sun" -> "выходной"
    "mon", "tue", "wed", "thu", "fri" -> "будний"
    else -> "неизвестно"
}

fun grade(score: Int): Char = when {
    score >= 90 -> 'A'
    score >= 75 -> 'B'
    score in 50..74 -> 'C'
    else -> 'F'
}

fun main() {
    println("${kind("sat")} ${kind("tue")} ${kind("xyz")}")
    println("${grade(95)}${grade(80)}${grade(60)}${grade(10)}")
    val a = 4
    val parity = if (a % 2 == 0) "чётное" else "нечётное"
    println(parity)
    println((1..3).joinToString(" "))
    println((1 until 4).joinToString(" "))
    println((6 downTo 1 step 2).joinToString(" "))
    println((5..1).toList())
    println(3 in 1..5)
    val pairs = mutableListOf<String>()
    outer@ for (x in 1..3) {
        for (y in 1..3) {
            if (y == 3) continue@outer
            if (x == 3) break@outer
            pairs.add("$x$y")
        }
    }
    println(pairs.joinToString(" "))
}
```
```output
выходной будний неизвестно
ABCF
чётное
1 2 3
1 2 3
6 4 2
[]
true
11 12 21 22
```

Разбор:

* `when` - выражение: у него есть значение, несколько значений в одной ветке через запятую, форма без аргумента (`when { условие -> ... }`) и проверка диапазона `in 50..74`. Проваливания между ветками нет, `break` не нужен. Если `when` используется как значение, то ветки должны покрывать все случаи (для `Int` и `String` - через `else`), иначе будет ошибка компиляции.
* `if` тоже выражение, поэтому тернарного оператора `условие ? a : b` в Kotlin нет: пишут `if (условие) a else b`.
* `1..3` включает оба конца, `1 until 4` - правый конец не включает, `6 downTo 1 step 2` идёт вниз с шагом. Диапазон `5..1` **пустой**, а не идёт назад: для убывания нужен `downTo`.
* Метки `outer@` и `continue@outer` / `break@outer` работают для вложенных циклов; `x in 1..5` проверяет принадлежность диапазону.

## Пример 4. Ввод и форматирование

Ввод читают по строкам: `readln()` возвращает строку без перевода строки, а на конце данных бросает `ReadAfterEOFException`; безопасный вариант `readlnOrNull()` возвращает `null`.

```kotlin
fun main() {
    val first = readln().toInt()
    val (x, y) = readln().split(" ")
    println(first + x.toInt() + y.toInt())
    while (true) {
        val line = readlnOrNull() ?: break
        println(line)
    }
}
```

Форматированный вывод и сравнение строк:

```kotlin run
import java.util.Locale

fun main() {
    val price = "2.50".toDouble()
    println(price)
    println("%.2f|%5d|%-5d|%05d".format(Locale.ROOT, price, 42, 42, 42))
    println("%,d".format(Locale.ROOT, 1234567))
    println("2,50".toDoubleOrNull())
    println("2,50".replace(',', '.').toDouble())
    val a = "hel"
    val b = a + "lo"
    println(b == "hello")
    println(b === "hello")
}
```
```output
2.5
2.50|   42|42   |00042
1,234,567
null
2.5
true
false
```

Разбор:

* `"2.50".toDouble()` и `println(2.5)` от локали **не зависят**: точка всегда. А вот `"%.2f".format(x)` без `Locale` берёт локаль системы: на русской или белорусской получится `2,50`, на английской - `2.50`. Программа, которую проверяют автоматически, должна печатать одинаково везде, поэтому всегда передавайте `Locale.ROOT` первым аргументом: `"%.2f".format(Locale.ROOT, x)`.
* Спецификаторы: `%d` - целое, `%s` - строка, `%.2f` - дробное с двумя знаками, `%5d` и `%-5d` - ширина с выравниванием справа и слева, `%05d` - дополнение нулями, `%,d` - с разделителями разрядов.
* `==` в Kotlin сравнивает **содержимое** (вызывает `equals`), поэтому `b == "hello"` истинно. `===` сравнивает ссылки: строка, собранная во время работы, - другой объект, и `===` ложно. Для строк и чисел `===` почти никогда не нужен.

**Попробуйте.** Замените `2.5.roundToInt()` на `3.5` и `-3.5`, `(5..1).toList()` на `(5 downTo 1).toList()` и `1_000_000 * 3000` на `1_000_000 * 300`; предскажите вывод до запуска.

<!-- section: precise -->
* Целые типы: `Byte` (8 бит), `Short` (16), `Int` (32), `Long` (64) - все со знаком. `Char` - 16-битный код UTF-16, но **не** число. Дробные: `Float` (32) и `Double` (64). `Boolean` не является числом. Это отдельные типы, а не примитивы с обёртками: `Int` на JVM превращается в `int` или, если нужен `Int?`, в `Integer`.
* Литералы: `10` - `Int`, `10L` - `Long`, `1.5` - `Double`, `1.5f` - `Float`, `'x'` - `Char`, `"x"` - `String`. Целый литерал, не помещающийся в `Int`, получает тип `Long`.
* Неявных преобразований между числовыми типами нет: `toInt()`, `toLong()`, `toDouble()` вызывают явно. Арифметика смешанных типов определена перегрузками (`Int + Long` даёт `Long`), а вот присваивание и `==` между разными типами не компилируются.
* Арифметика `Int` и `Long` переполняется молча по модулю `2^32` и `2^64`. Проверяющие версии - `Math.addExact`, `subtractExact`, `multiplyExact`, `toIntExact`.
* `/` для двух целых - деление с отбрасыванием к нулю, `%` - остаток со знаком делимого; `mod` возвращает остаток со знаком делителя. Деление целого на ноль - `ArithmeticException`.
* `val` - значение, которое нельзя переприсвоить; `var` - переменная. `val` ничего не говорит о неизменяемости объекта, на который ссылается (подробно - урок 2).
* `==` и `!=` - структурное сравнение (`equals`), `===` и `!==` - сравнение ссылок.
* `if`, `when`, `try` - выражения. Ветка `else` у `when` обязательна, если он используется как значение и компилятор не может доказать полноту (для `Int` и `String` - всегда).
* Диапазоны: `a..b` (оба конца включены), `a until b`, `a downTo b`, `step n`; `x in диапазон` и `x !in диапазон`. `repeat(n) { ... }` повторяет блок `n` раз.
* Шаблоны строк: `"$name"`, `"${a + b}"`. Многострочные строки пишут в `"""`.
* Ввод: `readln()` читает строку, `readlnOrNull()` возвращает `null` в конце. `toInt()` и `toDouble()` бросают `NumberFormatException`, `toIntOrNull()` и `toDoubleOrNull()` возвращают `null`; пробелы вокруг числа не допускаются.

<!-- section: mistakes -->
**1. Дробное значение в `Int`.** `val x: Int = 3.5` не компилируется:

```text
Main.kt:2:16: error: initializer type mismatch: expected 'Int', actual 'Double'.
```

Если потеря задумана, напишите `3.5.toInt()` или `3.5.roundToInt()`.

**2. `Int` в `Long` без преобразования.** Даже расширение нужно записывать:

```text
Main.kt:3:21: error: initializer type mismatch: expected 'Long', actual 'Int'.
```

**3. Сравнение разных числовых типов.** `5 == 5.0` и `1 == 1L` не компилируются:

```text
Main.kt:3:13: error: operator '==' cannot be applied to 'Int' and 'Double'.
```

**4. Присваивание `val`.** Имя, объявленное через `val`, нельзя переприсвоить:

```text
Main.kt:3:5: error: 'val' cannot be reassigned.
```

**5. Присваивание вместо сравнения.** В Kotlin присваивание - не выражение, поэтому `if (z = 5)` не скомпилируется (в отличие от C):

```text
Main.kt:3:9: error: only expressions are allowed in this context.
```

**6. `when` без `else`, когда он вычисляется как значение:**

```text
Main.kt:3:13: error: 'when' expression must be exhaustive. Add an 'else' branch.
```

**7. `Char` вместо числа.** `val c: Char = 97` не компилируется (`expected 'Char', actual 'Int'`): используйте `Char(97)` или `'a'`.

**8. Чтение после конца ввода.** `readln()` на пустом вводе:

```text
Exception in thread "main" kotlin.io.ReadAfterEOFException: EOF has already been reached
```

**9. Молчаливые ошибки, которые компилятор не видит.** Переполнение `Int` (`count * price` для больших значений, в том числе при объявлении `: Long`), деление целых там, где ждали дробное (`sum / n` при целых `sum` и `n`), запятая в `"%.2f".format(x)` на русской системе, диапазон `5..1`. Здесь помогают тесты на границах и привычки из этого урока.

## Главное для тех, кто уже программирует

* Статическая типизация с фиксированными размерами: `Int` 32 бита, `Long` 64. Переполнение молчит (в Python целые не ограничены, в C# есть `checked`, в Rust отладочная сборка паникует); проверяющие версии - `Math.addExact` и друзья.
* Никаких неявных преобразований чисел: `Int` в `Long` - через `toLong()`, `5 == 5.0` - ошибка компиляции (Java и C# расширяют `int` до `long` молча; Go так же строг, как Kotlin).
* `/` для целых отбрасывает дробную часть к нулю (как в Java, C, Go, C#; в Python `//` округляет вниз). `%` берёт знак делимого; `mod` - знак делителя.
* `Char` - не число (в Java, C и Go это число). `'a' + 1` - `'b'`, код - `.code`.
* `val` / `var` вместо `final` / `var`: `val` - ссылку нельзя переприсвоить, но объект за ней может быть изменяемым.
* `if`, `when`, `try` - выражения; `switch` с проваливанием заменён на `when`; тернарного оператора нет.
* `==` - структурное равенство (как `equals` в Java, как `==` в Python и C#); `===` - ссылочное (как `==` в Java).
* Деление на ноль: целые - `ArithmeticException`, дробные - `Infinity`/`NaN`. `roundToInt()` округляет половину вверх.
* Ввод: `readln()` / `readlnOrNull()`, без `Scanner`. Форматирование `format` зависит от локали - для предсказуемого вывода `Locale.ROOT`.
* Программа - функция `fun main()` на верхнем уровне файла; ни класса, ни `static`, ни `args` не нужно.

## Почему переполнение молчит

`Int` на JVM - обычное 32-битное число в дополнительном коде: сложение выполняет та же инструкция процессора, что и для любого числа, а лишний бит отбрасывается. Проверка границ на каждой операции замедлила бы все программы, поэтому проверяющие версии (`Math.addExact`) вынесены отдельно - такая же практика принята в C, Go и Java. Kotlin добавляет к этому только одно: числовые типы не приводятся друг к другу неявно, потому что именно такие приведения чаще всего прячут потерю данных или переполнение.
