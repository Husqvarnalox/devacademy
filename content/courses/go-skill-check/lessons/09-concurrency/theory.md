## Что проверяет эта проверка

Горутины и каналы: буферизованные и небуферизованные каналы, `close` и `range`, тупики, `sync.WaitGroup`, `sync.Mutex`, схема пула работников.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Горутины и каналы](lesson:go.fundamentals.goroutines-and-channels).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```go run
package main

import (
	"fmt"
	"sync"
)

func main() {
	squares := make([]int, 4)
	var wg sync.WaitGroup
	for i := range squares {
		wg.Add(1)
		go func() {
			defer wg.Done()
			squares[i] = i * i
		}()
	}
	wg.Wait()
	fmt.Println(squares)
}
```
```output
[0 1 4 9]
```

Каждая горутина пишет в свой элемент среза, поэтому гонки нет, а `wg.Wait()` гарантирует, что все записи закончены. (В Go 1.22 и новее у каждой итерации цикла своя переменная `i`.)

<!-- section: precise -->
Проверка предполагает умение:

* запускать горутины и дожидаться их через `sync.WaitGroup`;
* понимать блокировки небуферизованных каналов и причины тупиков;
* закрывать канал со стороны отправителя и читать его через `range`;
* защищать общие данные мьютексом;
* собирать пул работников.

<!-- section: mistakes -->
Как подготовиться и на чём чаще всего ошибаются.

* Отправка в закрытый канал вызывает панику.
* `range` по незакрытому каналу блокируется навсегда.
* Результаты горутин приходят в произвольном порядке: не полагайтесь на него.
* Общую переменную без синхронизации читать и писать из разных горутин нельзя.
