## Что проверяет эта проверка

Пакет `context`: `WithCancel`, `WithTimeout`, `ctx.Done()`, `ctx.Err()`, распространение отмены на дочерние контексты, правило `defer cancel()` и соглашение о первом параметре `ctx`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Паттерны конкурентности и context](lesson:go.fundamentals.concurrency-patterns-and-context), [Отмена, дедлайны и утечки горутин](lesson:go.pro.context-cancellation).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```go run
package main

import (
	"context"
	"fmt"
)

func main() {
	ctx, cancel := context.WithCancel(context.Background())
	fmt.Println(ctx.Err())
	cancel()
	fmt.Println(ctx.Err())
}
```
```output
<nil>
context canceled
```

Пока контекст жив, `Err()` возвращает `nil`; после отмены - `context.Canceled`.

<!-- section: precise -->
Проверка предполагает умение:

* создавать контексты с отменой и сроком;
* в `select` ждать `ctx.Done()` вместе с рабочим каналом;
* возвращать `ctx.Err()` и сравнивать его через `errors.Is`;
* помнить про `defer cancel()`;
* передавать `ctx` первым параметром.

<!-- section: mistakes -->
Как подготовиться и на чём чаще всего ошибаются.

* `time.Sleep` не реагирует на отмену: используйте таймер и `select`.
* Забытый `cancel` держит ресурсы до истечения срока.
* Контекст не хранят в структурах: его передают как параметр.
* Горутина, не проверяющая `ctx.Done()`, не остановится по отмене.
