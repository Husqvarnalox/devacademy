## Что проверяет эта проверка

Организацию модуля (`go.mod`, `package`), файлы и функции тестов (`_test.go`, `TestXxx`, `*testing.T`), табличные тесты и подтесты `t.Run`, различие `Errorf` и `Fatalf`, команду `go test ./...`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Пакеты, модули и тестирование](lesson:go.fundamentals.packages-modules-testing).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

## Пример того, что понадобится

```go run
package main

import "fmt"

func clamp(v, lo, hi int) int {
	if v < lo {
		return lo
	}
	if v > hi {
		return hi
	}
	return v
}

func main() {
	fmt.Println(clamp(15, 0, 10), clamp(-3, 0, 10), clamp(5, 0, 10))
}
```
```output
10 0 5
```

Для такой функции табличный тест перечисляет случаи `{вход, ожидание}` и проверяет их в цикле через `t.Run`, как это сделано в упражнении.

<!-- section: precise -->
Проверка предполагает умение:

* знать правила имён: `_test.go`, `TestXxx(t *testing.T)`;
* писать табличные тесты и подтесты;
* различать `t.Errorf` (продолжить) и `t.Fatalf` (остановить тест);
* запускать `go test ./...` и отдельные тесты через `-run`;
* понимать роль `go.mod`.

<!-- section: mistakes -->
Как подготовиться и на чём чаще всего ошибаются.

* Файл теста без суффикса `_test.go` не будет запущен.
* Имя функции теста обязано начинаться с `Test` и заглавной буквы.
* Табличные тесты сильнее набора разрозненных проверок: случай легко добавить, а имя подтеста указывает на сбой.
* Повторение: список уроков ниже.
