## Что проверяет эта проверка

Интерфейсы и неявную реализацию, наборы методов, пустой интерфейс `any`, type switch и утверждение типа с `ok`, различие `nil`-интерфейса и интерфейса с nil-значением.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Интерфейсы](lesson:go.fundamentals.interfaces).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```go run
package main

import "fmt"

type Speaker interface{ Speak() string }

type Dog struct{}

func (Dog) Speak() string { return "гав" }

func main() {
	var s Speaker = Dog{}
	if d, ok := s.(Dog); ok {
		fmt.Println(d.Speak(), ok)
	}
	var e error
	fmt.Println(e == nil)
}
```
```output
гав true
true
```

`Dog` реализует `Speaker` без объявлений. Утверждение типа с `ok` безопасно. Интерфейс без значения равен `nil`.

<!-- section: precise -->
Проверка предполагает умение:

* объявлять интерфейс и реализовывать его без явных объявлений;
* знать, что методы с получателем-указателем не входят в набор методов значения;
* применять type switch и утверждение с `ok`;
* отличать nil-интерфейс от интерфейса с nil-указателем;
* принимать интерфейсы, возвращать конкретные типы.

<!-- section: mistakes -->
Как подготовиться и на чём чаще всего ошибаются.

* Утверждение типа без `ok` паникует при несовпадении.
* Возврат типизированного nil-указателя как `error` даёт ненулевую ошибку.
* Не объявляйте интерфейс «на всякий случай»: он нужен потребителю.
* Повторение: список уроков ниже.
