## Зачем этот урок

В Python и Java ошибка - это исключение, которое «летит» вверх по стеку. В Go исключений нет: функция, которая может не справиться, возвращает ошибку вторым значением, а вызывающий код обязан её проверить. Это самая заметная особенность языка для тех, кто пришёл из других технологий. Прохождение урока (упражнение и квиз) засчитывает уроки 17-20 курса «Go с нуля».

## Главная мысль

Функции в Go возвращают несколько значений, а ошибка - обычное значение типа `error`. Тип `error` - это интерфейс с методом `Error() string`; `nil` означает «ошибки нет». Проверка `if err != nil` после каждого вызова - не шаблонный шум, а явное решение: вернуть ошибку выше, добавить контекст или обработать здесь. Вторая особенность - области видимости: `:=` внутри блока создаёт новые переменные, поэтому ошибку, объявленную снаружи, легко «потерять».

## Пример 1. Ошибки-значения, обёртывание и errors.Is

```go run
package main

import (
	"errors"
	"fmt"
	"strconv"
)

var ErrNegative = errors.New("negative value")

func parsePositive(s string) (int, error) {
	n, err := strconv.Atoi(s)
	if err != nil {
		return 0, fmt.Errorf("parsePositive %q: %w", s, err)
	}
	if n < 0 {
		return 0, ErrNegative
	}
	return n, nil
}

func main() {
	for _, in := range []string{"42", "-5", "x1"} {
		n, err := parsePositive(in)
		switch {
		case errors.Is(err, ErrNegative):
			fmt.Println("отрицательное:", in)
		case err != nil:
			fmt.Println("ошибка:", err)
		default:
			fmt.Println("число:", n)
		}
	}
}
```
```output
число: 42
отрицательное: -5
ошибка: parsePositive "x1": strconv.Atoi: parsing "x1": invalid syntax
```

`ErrNegative` - **сторожевая ошибка** (sentinel): пакетная переменная, с которой сравнивают через `errors.Is`. `fmt.Errorf` с глаголом `%w` оборачивает исходную ошибку, добавляя контекст, и при этом `errors.Is` и `errors.As` продолжают находить причину внутри цепочки. Сравнение `err == ErrNegative` для обёрнутой ошибки дало бы `false`.

## Пример 2. Затенение err

```go run
package main

import (
	"errors"
	"fmt"
)

func load() (int, error) { return 0, errors.New("нет данных") }

func run() error {
	var err error
	var n int
	if true {
		n, err := load() // := создаёт новые n и err в этом блоке
		fmt.Println("внутри:", n, err)
	}
	fmt.Println("снаружи:", n, err)
	return err
}

func main() {
	fmt.Println(run())
}
```
```output
внутри: 0 нет данных
снаружи: 0 <nil>
<nil>
```

Функция `run` вернула `nil`, хотя `load` сообщила об ошибке: внешняя `err` никогда не присваивалась. Компилятор молчит, потому что обе переменные где-то используются. Решение: объявить `n` и `err` снаружи и присваивать через `=`: `n, err = load()`.

## Пример 3. Именованные результаты, `_` и defer

```go run
package main

import (
	"errors"
	"fmt"
)

func divmod(a, b int) (q, r int, err error) {
	if b == 0 {
		err = errors.New("деление на ноль")
		return
	}
	return a / b, a % b, nil
}

func main() {
	q, r, err := divmod(17, 5)
	fmt.Println(q, r, err)
	_, _, err = divmod(1, 0)
	fmt.Println(err)

	defer fmt.Println("defer 1")
	defer fmt.Println("defer 2")
	fmt.Println("конец main")
}
```
```output
3 2 <nil>
деление на ноль
конец main
defer 2
defer 1
```

Именованные результаты `q, r, err` объявлены в сигнатуре и имеют нулевые значения; голый `return` возвращает их текущие значения. Пустой идентификатор `_` отбрасывает ненужный результат. `defer` откладывает вызов до выхода из функции; отложенные вызовы выполняются в обратном порядке.

**Попробуйте:** уберите `err =` в `divmod` и верните ошибку явно `return 0, 0, errors.New(...)`. Результат не изменится: именованные результаты - это стиль, а не необходимость.

<!-- section: precise -->
* Функция может возвращать несколько значений; присвоить результат двузначной функции одной переменной нельзя: `assignment mismatch: 1 variable but f returns 2 values`.
* По соглашению `error` - последний результат. `nil` - «ошибки нет»; при ошибке остальные результаты надо считать недействительными (если документация не говорит иного).
* `errors.New("текст")` создаёт ошибку. `fmt.Errorf("...: %w", err)` оборачивает; `errors.Is(err, target)` ищет значение в цепочке, `errors.As(err, &target)` ищет значение нужного типа.
* Параметры передаются по значению (копируются). Срезы, карты, каналы и указатели копируются как небольшие «ручки» на общие данные, поэтому функция может менять содержимое, но не может переназначить переменную вызывающего.
* Именованные результаты допустимы; голый `return` возвращает их текущие значения. Злоупотреблять им в длинных функциях не рекомендуется.
* `defer` откладывает вызов до выхода из функции; аргументы вычисляются в момент `defer`, вызовы выполняются в порядке LIFO.
* Область видимости определяется блоком `{}`. `:=` внутри блока создаёт **новые** переменные, даже если внешние с теми же именами существуют. В `a, err := f()` переменные, уже объявленные в **этом же** блоке, переиспользуются, остальные создаются.
* `panic` - для невосстановимых ошибок программиста (выход за границы среза, обращение к nil-карте), а не способ сообщить об ожидаемой ошибке вроде неверного ввода пользователя.

<!-- section: mistakes -->
**1. Игнорирование ошибки.**
`n, _ := strconv.Atoi(s)` молча даёт `0` для неверной строки, и программа продолжает работать с ложными данными. Компилятор это разрешает. Решение: проверять `err`; пустой идентификатор допустим, только если ошибка действительно невозможна или безразлична (и это понятно из контекста).

**2. Затенение `err` и результата через `:=`.**
См. пример 2. Признак: функция «молча» возвращает `nil`, а в логах видно, что ошибка была. Узнать самому: `go vet` с анализатором `shadow`, а при чтении кода - искать `:=` в блоках `if` и `for`, где слева стоит уже знакомое имя.

**3. Присваивание двузначной функции одной переменной.**
```go
x := strconv.Atoi("5")
```
Сообщение: `assignment mismatch: 1 variable but strconv.Atoi returns 2 values`. Исправление: `x, err := strconv.Atoi("5")`.

**4. Сравнение обёрнутой ошибки через `==`.**
`err == ErrNotFound` не сработает, если ошибку обернули через `%w`. Используйте `errors.Is(err, ErrNotFound)`.

**5. Использование результата до проверки ошибки.**
`n, err := f(); total += n; if err != nil {...}`: значение `n` при ошибке не определено по смыслу. Проверяйте `err` сразу после вызова и выходите из функции раньше (`return`), чтобы основной путь кода оставался без вложенности.

**6. Возврат «нулевой» ошибки с типом.**
Если функция объявляет `var e *MyError` и возвращает его как `error`, то при `e == nil` интерфейс всё равно не равен `nil` (в нём хранится тип). Возвращайте литерал `nil` явно.

<!-- section: summary -->
Теперь вы знаете главное отличие Go от языков с исключениями: ошибки возвращаются значениями, проверяются сразу, оборачиваются через `%w` и сравниваются через `errors.Is`. Вы видите, как `:=` в блоке затеняет переменные, и умеете пользоваться несколькими результатами, `_` и `defer`. Следующий шаг - срезы, карты и строки. Для подробностей: [Функции](lesson:go.first-steps.functions), [Несколько значений](lesson:go.first-steps.return-values), [Область видимости](lesson:go.first-steps.scope), [Ошибка как значение](lesson:go.first-steps.errors-first-look).

## Главное для тех, кто уже программирует

* Нет исключений: `try/catch` заменяет проверка `err != nil`. Нет `finally`: его роль играет `defer`. Нет перегрузки функций и значений параметров по умолчанию; для необязательных аргументов используют отдельные функции, структуры настроек или функциональные опции.
* Несколько результатов - часть языка (а не кортеж, как в Python). Результат можно именовать; `_` отбрасывает ненужный.
* `error` - интерфейс. Собственные типы ошибок реализуют `Error() string`. `errors.Is/As` ходят по цепочке `%w`, поэтому контекст добавляют «снизу вверх» и не теряют причину.
* Функции - значения первого класса: их можно присваивать, передавать и возвращать; замыкания захватывают переменные (не копии).
* Параметры всегда копируются. «Ссылочное» поведение дают указатели, срезы, карты и каналы.
* `defer` выполняется при выходе из функции, в обратном порядке; аргументы вычисляются сразу. Типичное применение: `defer f.Close()`.
* Область видимости - блок. Затенение через `:=` - самый частый источник скрытых ошибок.
* `panic` и `recover` существуют, но не используются как обычный способ обработки ошибок.
