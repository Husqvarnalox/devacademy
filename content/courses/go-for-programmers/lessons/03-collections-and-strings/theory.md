## Зачем этот урок

В других языках «список» и «словарь» ведут себя однотипно: переменная указывает на объект. В Go три коллекции устроены по-разному: **массив** - значение фиксированной длины, **срез** - небольшой описатель (указатель, длина, ёмкость) на общий массив, **карта** - ссылка на хеш-таблицу. Из-за этого `append` может как менять чужие данные, так и создавать копию, а строка - это байты, а не символы. Урок собирает эти ловушки. Прохождение (упражнение и квиз) засчитывает уроки 21-26 курса «Go с нуля».

## Главная мысль

Нужно различать **значение** и **описатель**. Присваивание массива копирует все элементы, присваивание среза копирует только описатель, а общий массив остаётся один. Нулевое значение среза (`nil`) пригодно к использованию (`len`, `range`, `append`), нулевое значение карты можно читать, но нельзя в неё писать. Порядок обхода карты в Go намеренно случаен.

## Пример 1. Массив, срез и append

```go run
package main

import "fmt"

func main() {
	a := []int{1, 2, 3, 4}
	b := a[:2]
	b = append(b, 99)
	fmt.Println(a, b, len(b), cap(b))

	c := make([]int, 0, 1)
	c = append(c, 1)
	d := append(c, 2) // ёмкость исчерпана: создан новый массив
	d[0] = 100
	fmt.Println(c, d)

	arr := [3]int{1, 2, 3}
	arr2 := arr // копия массива целиком
	arr2[0] = 9
	fmt.Println(arr, arr2)
}
```
```output
[1 2 99 4] [1 2 99] 3 4
[1] [100 2]
[1 2 3] [9 2 3]
```

Срез `b` построен на том же массиве, что и `a`, и его ёмкость равна `4`, поэтому `append` записал `99` поверх `a[2]`. Во втором случае ёмкости не хватило, `append` выделил новый массив, и `c` остался нетронутым. Ключевое правило: **результат `append` всегда присваивают**, а возможное совместное использование памяти учитывают.

## Пример 2. nil-срез, nil-карта и порядок обхода

```go run
package main

import (
	"fmt"
	"sort"
)

func main() {
	var s []int
	fmt.Println(s == nil, len(s), cap(s))
	s = append(s, 1)

	var m map[string]int
	fmt.Println(m == nil, m["x"], len(m))
	// m["x"] = 1 вызвало бы панику: assignment to entry in nil map

	m = map[string]int{"b": 2, "a": 1, "c": 3}
	v, ok := m["z"]
	fmt.Println(v, ok)

	keys := make([]string, 0, len(m))
	for k := range m {
		keys = append(keys, k)
	}
	sort.Strings(keys)
	for _, k := range keys {
		fmt.Println(k, m[k])
	}
}
```
```output
true 0 0
true 0 0
0 false
a 1
b 2
c 3
```

Чтение из `nil`-карты безопасно, запись вызывает панику. Форма `v, ok := m[key]` отличает отсутствие ключа от нулевого значения. Порядок `for range` по карте не гарантируется и меняется между запусками, поэтому для стабильного вывода ключи собирают в срез и сортируют.

## Пример 3. Байты и руны

```go run
package main

import (
	"fmt"
	"strings"
	"unicode/utf8"
)

func main() {
	s := "Привет, Go"
	fmt.Println(len(s), utf8.RuneCountInString(s))
	for i, r := range "aя" {
		fmt.Println(i, string(r), r)
	}
	fmt.Println(s[:6], strings.ToUpper(s))
}
```
```output
16 10
0 a 97
1 я 1103
При ПРИВЕТ, GO
```

`len` считает байты: каждая кириллическая буква в UTF-8 занимает 2 байта. `range` по строке декодирует руны и выдаёт **байтовый** индекс (`0`, затем `1`). Срез `s[:6]` берёт 6 байтов, то есть ровно три русские буквы; при нечётной границе получилась бы битая последовательность.

**Попробуйте:** замените `s[:6]` на `s[:5]` и посмотрите, что напечатает программа.

<!-- section: precise -->
* Массив `[n]T`: длина - часть типа, `[3]int` и `[4]int` - разные типы; присваивание и передача в функцию копируют все элементы; сравнение `==` допустимо.
* Срез `[]T`: описатель из указателя, длины и ёмкости. `s[i:j]` создаёт новый описатель на тот же массив; `s[i:j:k]` дополнительно ограничивает ёмкость. Срезы нельзя сравнивать через `==` (только с `nil`).
* `append(s, ...)` пишет в существующий массив, если `len < cap`, иначе выделяет новый (ёмкость растёт ступенчато); возвращаемый срез нужно присвоить.
* `make([]T, n, c)`, `copy(dst, src)` копирует `min(len)` элементов.
* `nil`-срез: `len == 0`, `cap == 0`, работают `range` и `append`. Пустой `[]int{}` не `nil`, но для `len` и `range` они равнозначны (при кодировании JSON отличаются).
* Карта `map[K]V`: ключ должен быть сравнимым (не срез и не карта); чтение отсутствующего ключа даёт нулевое значение; запись в `nil`-карту - паника; `delete` безопасен для отсутствующих ключей; порядок обхода случаен; карта не потокобезопасна.
* Строка - неизменяемая последовательность байтов. `len(s)` и `s[i]` работают с байтами, `[]rune(s)` даёт кодовые точки. `rune` - псевдоним `int32`, `byte` - `uint8`.
* `for i, r := range s` декодирует UTF-8 и возвращает байтовый индекс; недопустимый байт превращается в `U+FFFD`.
* `strings.Builder` собирает строку без лишних копий; `strings.Fields` делит по пробельным символам; `strings.ToLower` учитывает Unicode.

<!-- section: mistakes -->
**1. Неожиданное совместное использование массива.**
`b := a[:2]; b = append(b, 99)` изменяет `a[2]`. Признак: «чужой» срез вдруг изменил значения. Решение: ограничить ёмкость (`a[:2:2]`) или скопировать (`copy` в новый срез).

**2. Запись в nil-карту.**

```go
var m map[string]int
m["a"] = 1
```
Во время выполнения: `panic: assignment to entry in nil map`. Решение: `m := make(map[string]int)` или литерал. Для срезов такой проблемы нет: `append` к `nil`-срезу допустим.

**3. Потерянный результат append.**
`append(s, 1)` без присваивания не меняет `s`: длина описателя у вызывающего кода прежняя. Компилятор сообщает `append(s, 1) (value of type []int) is not used`.

**4. Зависимость от порядка обхода карты.**
Тест, который сравнивает вывод цикла `for range` по карте, иногда проходит, иногда нет. Решение: отсортируйте ключи.

**5. Путаница байтов и символов.**
`len("Привет")` равно `12`, а не `6`; `s[0]` для кириллицы - половинка символа. Для посимвольной работы используйте `[]rune(s)` или `range`. Обратите внимание, что разворот строки по байтам ломает UTF-8.

**6. Изменение карты или среза во время итерации.**
Удаление ключей из карты внутри `range` допустимо, добавление даёт непредсказуемый результат (новый ключ может или не может быть посещён). Срез при `range` вычисляется один раз: добавление элементов в процессе цикла не удлиняет цикл.

<!-- section: summary -->
Теперь вы понимаете, чем массив, срез и карта отличаются от списков и словарей привычных языков: что копируется, что делится, где допустим `nil`, почему порядок обхода карты случаен и почему строка - это байты. Эти знания защищают от самых частых ошибок в Go-коде. Следующий урок - потоковый ввод. ## Главное для тех, кто уже программирует

* Нет встроенного «списка»: основная последовательность - срез. Он не владеет данными: несколько срезов могут смотреть на один массив (как `memoryview`, а не как `list` в Python).
* Массив - значение, срез и карта - описатели. Передача среза в функцию копирует описатель, поэтому функция может менять элементы, но не длину у вызывающего.
* `append` возвращает новый описатель: в Python это `list.append` на месте, в Go нужно `s = append(s, x)`. Ёмкость растёт ступенчато; алгоритм роста не является контрактом.
* Карта - хеш-таблица с `nil`-значением по умолчанию; обход в случайном порядке (в отличие от упорядоченных `dict` Python и `LinkedHashMap`). Множество реализуют как `map[T]struct{}`.
* Нет генераторов списков и срезов с отрицательными индексами. Выход за границы - паника, не «тихое» усечение.
* Строки неизменяемы и состоят из байтов (как `bytes`, а не `str` Python 3). Символ - `rune` (`int32`). Нет перегрузки `+` для чисел и строк: `"a" + 1` не компилируется.
* Из `slices` и `maps` стандартной библиотеки (Go 1.21+) доступны `slices.Sort`, `slices.Contains`, `maps.Keys` и другие.
