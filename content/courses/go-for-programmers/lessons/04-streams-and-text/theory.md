## Зачем этот урок

Любая реальная программа читает данные: из стандартного ввода, файла или сети. В Go для этого есть небольшой набор приёмов вокруг пакета `bufio`: буферизованное чтение чисел через `fmt.Fscan` и построчное чтение через `bufio.Scanner`. У них есть ловушки, которых нет в `input()` из Python или `Scanner` из Java: ограничение длины строки, признак конца ввода через `io.EOF` и переполнение целых фиксированной ширины. Прохождение урока (упражнение и квиз) засчитывает уроки 27-28 курса «Go с нуля».

## Главная мысль

Чтение в Go - это интерфейс `io.Reader`, а `bufio` добавляет буфер и удобные разборщики. Функции, которые принимают `io.Reader`, одинаково работают со стандартным вводом, файлами и строками в тестах (`strings.NewReader`), поэтому их удобно проверять без настоящего ввода. Конец данных - это значение ошибки `io.EOF`, а не особое состояние.

<!-- section: examples -->
## Пример 1. Числа через Fscan до конца ввода

```go run
package main

import (
	"bufio"
	"fmt"
	"io"
	"strings"
)

func main() {
	in := bufio.NewReader(strings.NewReader("3 5000000000\n7"))
	var total int64
	for {
		var v int64
		_, err := fmt.Fscan(in, &v)
		if err == io.EOF {
			break
		}
		if err != nil {
			fmt.Println("ошибка:", err)
			return
		}
		total += v
	}
	fmt.Println(total)
}
```
```output
5000000010
```

`strings.NewReader` играет роль стандартного ввода. `bufio.NewReader` оборачивает источник буфером: чтение чисел `fmt.Fscan` из небуферизованного `os.Stdin` на больших данных работает заметно медленнее. Цикл заканчивается, когда `Fscan` возвращает `io.EOF`; любая другая ошибка - это некорректные данные. Сумма хранится в `int64`: значения больше `2147483647` не поместились бы в 32 бита (в Go тип `int` на 64-битных платформах тоже 64-битный, но `int64` фиксирует ширину явно).

## Пример 2. Построчное чтение

```go run
package main

import (
	"bufio"
	"fmt"
	"strings"
)

func main() {
	sc := bufio.NewScanner(strings.NewReader("alpha beta\n\nпривет мир  !\r\nlast"))
	n := 0
	for sc.Scan() {
		n++
		fmt.Printf("%d: %q %d\n", n, sc.Text(), len(strings.Fields(sc.Text())))
	}
	if err := sc.Err(); err != nil {
		fmt.Println("ошибка:", err)
	}
}
```
```output
1: "alpha beta" 2
2: "" 0
3: "привет мир  !" 3
4: "last" 1
```

`Scan` возвращает `true`, пока есть следующая строка; `Text` отдаёт её без перевода строки (и без `\r` в конце, поэтому файлы Windows читаются так же). Пустая строка - тоже строка. Последняя строка без перевода строки не теряется. `strings.Fields` делит по любому количеству пробельных символов. После цикла обязательно проверяют `sc.Err()`.

## Пример 3. Предел Scanner и разбор чисел

```go run
package main

import (
	"bufio"
	"fmt"
	"strconv"
	"strings"
)

func main() {
	long := strings.Repeat("x", 70000)

	sc := bufio.NewScanner(strings.NewReader(long + "\nok"))
	for sc.Scan() {
		fmt.Println(len(sc.Text()))
	}
	fmt.Println("ошибка:", sc.Err())

	sc = bufio.NewScanner(strings.NewReader(long + "\nok"))
	sc.Buffer(make([]byte, 0, 64*1024), 1<<20)
	for sc.Scan() {
		fmt.Println(len(sc.Text()))
	}
	fmt.Println("ошибка:", sc.Err())

	_, err := strconv.ParseInt("9223372036854775808", 10, 64)
	fmt.Println(err)
}
```
```output
ошибка: bufio.Scanner: token too long
70000
2
ошибка: <nil>
strconv.ParseInt: parsing "9223372036854775808": value out of range
```

По умолчанию `Scanner` принимает строки до 64 КБ; длиннее - `Scan` возвращает `false`, а `Err` содержит `bufio.ErrTooLong`. Предел меняют методом `Buffer`. Разбор больше максимума типа даёт ошибку диапазона, а не молчаливое переполнение.

**Попробуйте:** замените `long` на `strings.Repeat("x", 100)` и убедитесь, что первый цикл теперь печатает обе строки.

<!-- section: precise -->
* `io.Reader` - интерфейс с методом `Read`. Конец данных - ошибка `io.EOF` (не сбой, а нормальное завершение).
* `fmt.Scan`/`Fscan` читают значения, разделённые пробельными символами, включая переводы строк. Возвращают число прочитанных значений и ошибку; при неверном формате ошибка не `io.EOF`.
* `bufio.NewReader(os.Stdin)` ускоряет чтение; `bufio.NewWriter(os.Stdout)` ускоряет вывод, но требует `Flush()` перед выходом (обычно через `defer`).
* `bufio.Scanner` по умолчанию делит по строкам (`ScanLines`), срезает `\n` и `\r\n`. Переключение: `sc.Split(bufio.ScanWords)` (слова) или `ScanRunes`. Максимальный размер токена по умолчанию 64 КБ; изменение - `sc.Buffer(buf, max)`.
* `Scan()` возвращает `false` и при конце данных, и при ошибке; различают их через `sc.Err()` (для конца данных `nil`).
* `int` - размер платформы (64 бита на 64-битных), `int32`/`int64` - фиксированные. Арифметика молча переполняется; `strconv.ParseInt(s, 10, 64)` сообщает о выходе за диапазон. Преобразование в более узкий тип отбрасывает старшие биты.
* `strings.Fields` делит по группам пробельных символов, `strings.Split` - по точному разделителю (пустые элементы сохраняются).
* Чтение, как и запись, лучше оформлять функцией, принимающей `io.Reader` и `io.Writer`: так её проверяют без стандартных потоков.

<!-- section: mistakes -->
**1. Игнорирование `io.EOF`.**
Цикл `for { fmt.Fscan(in, &v); total += v }` никогда не заканчивается: после конца данных `Fscan` продолжает возвращать ошибку, а `v` остаётся нулём. Проверяйте `err` и выходите при `io.EOF`.

**2. Обрыв из-за длинной строки.**
Если во входе есть строка длиннее 64 КБ, `Scanner` просто прекращает работу, и программа молча получает меньше данных, чем есть. Признак: результат обрывается на «странной» строке. Решение: всегда проверять `sc.Err()` и при необходимости вызывать `sc.Buffer`.

**3. Забытая проверка `sc.Err()`.**
Цикл `for sc.Scan()` не сообщает причину остановки. Без `Err()` ошибка чтения выглядит как нормальный конец ввода.

**4. Разбор чисел в `int` без учёта размера.**
Суммы, произведения и идентификаторы быстро выходят за 32 бита. Если вы выбрали `int32`, молчаливое переполнение даст неверные результаты. Используйте `int64` для явной ширины или `big.Int` для произвольной.

**5. `bufio.Writer` без `Flush`.**
Вывод остаётся в буфере и пропадает при завершении программы. Добавьте `defer w.Flush()` сразу после создания.

**6. Смешение `Scan` и `Scanner` на одном вводе.**
Каждый буферизованный читатель забирает данные «про запас», поэтому второй читатель не увидит уже прочитанного. Используйте один читатель на весь ввод.

## Главное для тех, кто уже программирует

* Нет `input()` и встроенного разбора: ввод читают через `os.Stdin`, обёрнутый в `bufio`. `fmt.Scan` удобен для учебных задач, но медленный на больших данных - в олимпиадном стиле берут `bufio.Reader` с `Fscan`.
* `io.Reader`/`io.Writer` - главные интерфейсы ввода-вывода. Файл, сеть, строка в памяти и стандартный ввод - всё `io.Reader`; функции для тестов принимают именно его.
* Конец данных - ошибка-значение `io.EOF`, а не `None` или `-1`. Сравнивайте через `==` (или `errors.Is`).
* `Scanner` не читает строки произвольной длины (предел 64 КБ по умолчанию) - в Python и Java такого ограничения нет. Для больших строк увеличивайте буфер или берите `bufio.Reader.ReadString('\n')`.
* Целые типы с явной шириной (`int32`, `int64`, `uint8`) переполняются без исключений, в отличие от Python (произвольная точность) и частично Java (`Math.addExact`).
* Парсинг: `strconv.Atoi`, `ParseInt(s, base, bits)`, `ParseFloat`; ошибки содержат исходную строку и причину.
