## Зачем нужна проверка типов

Представьте кассу, в которую в поле «цена» вместо числа ввели слово «много». Любая дальнейшая арифметика с этой ценой даст бессмыслицу, и обнаружится это уже у покупателя. В TypeScript такая ошибка обнаруживается **до запуска**: проверка сверяет значения с типами и останавливает программу, пока вы не исправите несоответствие. Это главное, ради чего типы записывают.

## Одна новая идея: переменная принимает значения только своего типа

В уроке 4 вы записали после имени тип: `let total: number = 0;`. Теперь у этой записи есть последствия: в `total` можно класть только числа. Когда вы пишете `total = "много";`, проверка видит, что слева ждут `number`, а справа `string`, и сообщает об **ошибке типов**:

```text
main.ts(2,1): error TS2322: Type 'string' is not assignable to type 'number'.
```

Переводится: «значение типа `string` нельзя присвоить там, где ожидают `number`». В сообщении всегда два типа: что нашли и что ждали.

Второе, что делает TypeScript, - **вывод типа**. Если у переменной есть начальное значение, аннотацию можно не писать: тип определится по значению. `let city = "Омск";` означает то же, что `let city: string = "Омск";`. После этого переменная остаётся строкой навсегда.

## Пример 1. Ошибка типа

Программа:

```typescript
let age: number = "30";
console.log(age);
```

Сообщение проверки:

```text
main.ts(1,5): error TS2322: Type 'string' is not assignable to type 'number'.
```

Разбор: значение `"30"` в кавычках - текст, а `age` объявлена для чисел. То, что внутри кавычек цифры, неважно: проверяется вид значения. Место в сообщении - имя переменной (строка 1, столбец 5). Исправление: `let age: number = 30;`. Программа не запустилась вообще: на экране нет ни одной строки вывода.

## Пример 2. Вывод типа

```typescript run
let city = "Омск";
let people = 1100000;
let isBig = true;
console.log(city, people, isBig);
```
```output
Омск 1100000 true
```

Разбор: аннотаций нет, но типы выведены: `city` - `string`, `people` - `number`, `isBig` - `boolean`. Узнать выведенный тип можно в редакторе, наведя курсор на имя; а ещё этот тип сразу проявляется, если присвоить значение другого типа.

## Пример 3. Выведенный тип тоже защищает

```typescript
let city = "Омск";
city = 5;
```

```text
main.ts(2,1): error TS2322: Type 'number' is not assignable to type 'string'.
```

Разбор: аннотации у `city` нет, но по начальному значению проверка вывела `string`. Поэтому вторая строка отвергнута: число в текстовую переменную не положить.

## Пример 4. Как подглядеть выведенный тип

```typescript
const price = 450;
const probe: boolean = price;
```

```text
main.ts(2,7): error TS2322: Type 'number' is not assignable to type 'boolean'.
```

Разбор: мы намеренно присвоили число там, где ждут `boolean`. Сообщение выдало тип `price`: `number`. Этот приём пригодится, когда непонятно, какой тип вывела проверка; после проверки строку с `probe` удалите.

## Пример 5. Когда аннотация необходима

```typescript run
let total: number;
total = 450;
console.log(total);
```
```output
450
```

Разбор: при объявлении значения ещё нет, так что выводить тип не из чего, и тип записывают явно. С начальным значением аннотация чаще лишняя: `const price = 450;` понятно и без неё. Общее правило курса: если значение очевидно из записи, аннотацию опускаем; если типа не видно или значения нет, пишем.

**Попробуйте.** Запишите `let temperature = 20;`, затем `temperature = "тепло";` и прочитайте сообщение. Исправьте и проверьте `temperature = 22.5;`.

## Точные правила

* Проверка типов выполняется до запуска и целиком по всему файлу. Если нашлась хотя бы одна ошибка, программа не запускается.
* Присваивание и начальное значение должны подходить по типу переменной. Подходит только тот же тип: строка `"30"` не подходит числовой переменной.
* Сообщение `TS2322` называет два типа: найденный и ожидаемый.
* Если у объявления есть начальное значение и нет аннотации, тип **выводится** из значения: `number` для чисел, `string` для текста, `boolean` для `true`/`false`.
* Выведенный тип действует так же строго, как записанный: позже в переменную нельзя положить другой тип.
* Если начального значения нет, аннотация обязательна для осмысленной проверки.
* Типы существуют только на этапе проверки: во время работы программы аннотаций нет, и они ничего не замедляют и не проверяют.
* Проверка видит только то, что записано в программе. Данные, полученные при работе (ввод пользователя, файл), она не проверяет; об этом - в уроке про чтение ввода.

## Типичные ошибки

**1. Число в кавычках.**

```typescript
const quantity: number = "3";
```

```text
main.ts(1,7): error TS2322: Type 'string' is not assignable to type 'number'.
```

Уберите кавычки: `3`. Кавычки превращают значение в текст.

**2. Текст без кавычек или число там, где ждут текст.**

```typescript
const itemName: string = 120;
```

```text
main.ts(1,7): error TS2322: Type 'number' is not assignable to type 'string'.
```

Если название должно быть текстом, возьмите его в кавычки.

**3. Слово вместо true/false.**

```typescript
const paid: boolean = "да";
```

```text
main.ts(1,7): error TS2322: Type 'string' is not assignable to type 'boolean'.
```

Логическое значение - только `true` или `false` без кавычек.

**4. Менять тип, а не значение.** Увидев `TS2322`, соблазнительно заменить `: number` на `: string`, чтобы ошибка исчезла. Сначала выясните, что вы хотели хранить. Тип - это ваше намерение, а ошибка нередко указывает на неверное значение.

**5. Думать, что типы проверяются во время работы.** Аннотаций во время работы уже нет. Поэтому ошибка типа в запущенной программе невозможна, если проверка прошла: её нашли раньше. Но и защитить от данных, которые ещё не пришли, проверка не может.

## Итоги

* Проверка типов до запуска сверяет значения с типами переменных и сообщает `TS2322`: «найден тип A, ожидался тип B».
* Без аннотации тип выводится по начальному значению и защищает так же строго.
* Аннотацию пишут, когда значения при объявлении нет или тип не очевиден; в остальных случаях её можно опустить.

С этого урока тип постоянно работает на вас. Следующий шаг - действия над числами: [Арифметика](lesson:typescript.from-zero.arithmetic).

## Для тех, кто уже программирует

* TypeScript выводит типы в духе Kotlin, Rust и `var` в C#, но аннотации нужны и ожидаемы на границах: параметры функций и тип результата (урок 9).
* `let city = "Омск"` выводит `string`, а `const city = "Омск"` - литеральный тип `"Омск"`; для чисел то же. Для простых программ разницы нет, подробно - в `typescript-first-steps`.
* Типы **стираются**: проверка статическая, время выполнения их не знает. Поэтому данные из `JSON.parse` и ввода приходят без гарантий; это основная тема `typescript-first-steps`.
* Тип `any` отключает проверку; в курсе он не используется. Режим `strict` запрещает неявный `any`.
* Приведения типов в виде `as` в этом курсе не нужны: они не проверяют значение, а только меняют мнение компилятора.
