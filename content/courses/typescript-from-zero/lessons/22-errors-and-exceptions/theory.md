## Зачем нужны исключения

До сих пор ошибки находила проверка типов: она читает код до запуска. Но есть ошибки, которые видны только при работе: деление на ноль, возраст -5, пустое название, неверные данные от пользователя. Типы тут бессильны: `-5` - такое же число, как `5`. Функции нужен способ сказать: «Я не могу дать осмысленный результат на таких данных». Вернуть случайное значение вроде `0` или `-1` опасно: вызывающий код может не заметить подмены и продолжит работать с неверными данными.

## Одна новая идея: выбросить и перехватить

В TypeScript для этого есть **исключения**. Функция может **выбросить** ошибку командой `throw`: выполнение функции немедленно прекращается, и ошибка «всплывает» вверх по вызовам. Если никто её не перехватил, программа останавливается и печатает сообщение. Чтобы продолжить работу, ошибку перехватывают блоком `try ... catch`.

```text
try {
  // код, который может выбросить ошибку
} catch (error) {
  // что делать, если ошибка произошла
}
```

Сначала выполняется `try`. Если внутри ничего не выброшено, `catch` пропускается. Если выброшена ошибка, остаток `try` не выполняется, и управление переходит в `catch`, где ошибка доступна под именем `error`. Саму ошибку создаёт запись `new Error("текст")`, а текст потом читают через `error.message`.

<!-- section: examples -->
## Пример 1. Выбросить и перехватить

```typescript run
function divide(a: number, b: number): number {
  if (b === 0) {
    throw new Error("деление на ноль");
  }
  return a / b;
}

try {
  console.log(divide(10, 4));
  console.log(divide(1, 0));
  console.log("эта строка не выполнится");
} catch (error) {
  if (error instanceof Error) {
    console.log("ошибка:", error.message);
    console.log(error.name);
  }
}
console.log("программа продолжается");
```
```output
2.5
ошибка: деление на ноль
Error
программа продолжается
```

`divide(10, 4)` выполняется нормально. На втором вызове условие `b === 0` истинно, и `throw` прекращает функцию: `return` не выполняется, а строка «эта строка не выполнится» пропущена - управление ушло в `catch`. Там проверка `error instanceof Error` убеждается, что перехвачено именно `Error`, и только тогда разрешает читать `error.message` и `error.name`. После блока `try ... catch` программа идёт дальше обычным порядком.

Если убрать `try ... catch`, то после первого `console.log` программа остановится с таким сообщением:

```text
main.ts:3
    throw new Error("деление на ноль");
    ^

Error: деление на ноль
    at divide (main.ts:3:11)
```

и строки после неудачного вызова не будут напечатаны.

## Пример 2. Пропустить плохие значения

```typescript run
function toFahrenheit(celsius: number): number {
  if (celsius < -273.15) {
    throw new Error("ниже абсолютного нуля: " + celsius);
  }
  return celsius * 1.8 + 32;
}

const readings: number[] = [20, -300, 0, -40];
for (const c of readings) {
  try {
    const f: number = toFahrenheit(c);
    console.log(c + " C = " + f + " F");
  } catch (error) {
    if (error instanceof Error) {
      console.log("пропущено:", error.message);
    }
  }
}
console.log("готово");
```
```output
20 C = 68 F
пропущено: ниже абсолютного нуля: -300
0 C = 32 F
-40 C = -40 F
готово
```

`try ... catch` внутри цикла обрабатывает каждое значение отдельно. Ошибка на втором элементе не мешает обработать третий и четвёртый: цикл продолжается со следующего круга. Так обычно обрабатывают списки данных, среди которых бывают испорченные. Переменная `f` объявлена внутри `try`, поэтому видна только там.

## Пример 3. finally и значения, не являющиеся Error

```typescript run
function describe(n: number): string {
  try {
    if (n < 0) {
      throw new Error("отрицательное число");
    }
    return "число " + n;
  } catch (error) {
    if (error instanceof Error) {
      return "ошибка: " + error.message;
    }
    return "неизвестная ошибка";
  } finally {
    console.log("проверено " + n);
  }
}

console.log(describe(5));
console.log(describe(-1));

try {
  throw "просто текст";
} catch (error) {
  console.log(error instanceof Error);
  console.log(typeof error, error);
}
```
```output
проверено 5
число 5
проверено -1
ошибка: отрицательное число
false
string просто текст
```

Блок `finally` выполняется всегда: и после успешного `try`, и после `catch`, даже если внутри уже был `return`. Поэтому строка «проверено» напечатана раньше, чем `console.log` во внешнем коде выводит возвращённое значение. В `finally` обычно помещают действия, которые нужно сделать в любом случае. Вторая часть примера показывает, что выбросить можно не только `Error`, но и любое значение, например строку. Поэтому внутри `catch` нельзя заранее знать, что именно прилетело.

**Попробуйте.** Напишите функцию `squareRoot(x: number): number`, которая выбрасывает `Error("отрицательное число")` при `x < 0`, а иначе возвращает `Math.sqrt(x)`. Вызовите её для чисел `[16, -4, 2.25]` внутри `try ... catch` в цикле и напечатайте результат или сообщение об ошибке.

## Точные правила

* `throw выражение;` прекращает текущую функцию и передаёт значение выше по цепочке вызовов. Обычно выбрасывают `new Error("сообщение")`.
* Если ошибку никто не перехватил, программа завершается с сообщением и трассировкой вызовов, а код выхода не нулевой.
* `try { ... } catch (error) { ... }`: при исключении в `try` остаток блока пропускается, управление уходит в `catch`.
* В режиме `strict` переменная `catch` имеет тип `unknown`: прочитать `error.message` сразу нельзя (`TS18046`). Сначала сужение: `if (error instanceof Error) { ... }`.
* Тип в `catch` можно указать только `unknown` или `any`; `catch (e: Error)` - ошибка `TS1196`.
* `finally { ... }` выполняется всегда, независимо от того, было ли исключение и был ли `return`.
* Переменные, объявленные в `try`, видны только внутри этого блока (за его пределами - `TS2304`).
* Функция с возвращаемым типом `number`, у которой `catch` не возвращает значения, вызывает `TS2366`: после `try ... catch` нужен либо `return`, либо `throw`.
* `new Error("текст")` сам по себе ничего не делает: ошибка возникает только после `throw`.
* У `Error` есть `message` (текст) и `name` (обычно `"Error"`).
* Выбросить можно любое значение (`throw "текст"`), но принято выбрасывать `Error`, потому что у него есть `message` и трассировка.
* Исключения - для **неожиданного**: неверные данные, нарушенные условия. Ожидаемый исход (например, «не нашли», когда `find` вернул `undefined`) исключением не оформляют.
* Проверять входные данные удобно в начале функции: сначала отсеять плохие значения через `throw`, потом считать.
* Исключение внутри `catch` или `finally` тоже можно выбросить - но в этом курсе так не делается.

## Типичные ошибки

**1. Чтение `error.message` без проверки.**

```typescript
try {
  throw new Error("сбой");
} catch (e) {
  console.log(e.message);
}
```

```text
main.ts(4,15): error TS18046: 'e' is of type 'unknown'.
```

«`e` имеет тип `unknown`». Значение в `catch` может быть чем угодно, поэтому нужна проверка: `if (e instanceof Error) { console.log(e.message); }`.

**2. Попытка указать тип `Error` в `catch`.**

```typescript
try {
  throw new Error("сбой");
} catch (e: Error) {
  console.log(e.message);
}
```

```text
main.ts(3,13): error TS1196: Catch clause variable type annotation must be 'any' or 'unknown' if specified.
```

Язык не позволяет обещать тип: выбросить можно что угодно. Оставьте `e` без аннотации и сужайте через `instanceof`.

**3. Использование переменной из `try` снаружи.**

```typescript
try {
  const value: number = 5;
  console.log(value);
} catch (error) {
  console.log("ошибка");
}
console.log(value);
```

```text
main.ts(7,13): error TS2304: Cannot find name 'value'.
```

Блок `{ }` ограничивает видимость. Если значение нужно после `try`, объявите переменную до него через `let` и присвойте внутри.

**4. Функция не возвращает значение во всех ветках.**

```typescript
function parse(n: number): string {
  try {
    if (n < 0) {
      throw new Error("отрицательное");
    }
    return "ok";
  } catch (error) {
    console.log("ловим");
  }
}
```

```text
main.ts(1,28): error TS2366: Function lacks ending return statement and return type does not include 'undefined'.
```

Ветка `catch` ничего не возвращает, и путь через неё заканчивается без значения. Добавьте `return` в `catch` или после блока.

**5. `new Error(...)` без `throw`.** Строка `new Error("плохо");` создаёт объект и тут же теряет его: проверка не жалуется, программа продолжает работу как ни в чём не бывало. Ошибка выбрасывается только записью `throw new Error("плохо");`.

**6. Пустой `catch`.** `catch (error) { }` молча проглатывает любую ошибку, включая неожиданные, и найти причину потом очень трудно. Как минимум напечатайте сообщение или сделайте осмысленную подстановку.

**7. `try ... catch` вместо обычной проверки.** Если `if (b === 0)` решает вопрос на месте, исключение не нужно. Выбрасывайте ошибку, когда функция не может выполнить свою работу и вызывающий код должен решить, что делать.

## Итоги

* `throw new Error("текст")` останавливает функцию и передаёт ошибку вызывающему коду.
* `try ... catch` перехватывает ошибку; остаток `try` пропускается, а программа идёт дальше.
* В `catch` значение имеет тип `unknown`: перед чтением `message` нужно сузить проверкой `error instanceof Error`.
* `finally` выполняется всегда.
* Проверка входных данных в начале функции с `throw` делает ошибки заметными, а не молчаливыми.
* Цикл с `try ... catch` внутри позволяет пропускать испорченные элементы и продолжать работу.

## Для тех, кто уже программирует

* Исключения работают как в Java, C#, Python и JavaScript: `throw` раскручивает стек до ближайшего `catch`. Проверяемых исключений (`throws` в сигнатуре) нет: тип функции не говорит, что она может выбросить.
* `catch (e)` - всегда `unknown` под `strict` (раньше был `any`). Надёжный шаблон: `e instanceof Error ? e.message : String(e)`.
* Выбросить можно любое значение, включая строку или число, поэтому `instanceof Error` - необходимая проверка, а не педантизм. Так же поступает JavaScript.
* Сообщение о неперехваченной ошибке в Node.js содержит трассировку и завершает процесс с кодом 1. Продолжить после неё нельзя.
* Ошибки ввода-вывода и разбора чаще возвращают значение (`number | undefined`, `NaN`), чем бросают; бросает код, который нарушает контракт.
* `finally` выполняется и при `return` внутри `try`; `return` в самом `finally` перекроет возврат из `try`, поэтому так не пишут.
* Собственные классы ошибок (`class MyError extends Error`) и обработка по типам вводятся позже, в `typescript-first-steps` и `typescript-fundamentals`.
