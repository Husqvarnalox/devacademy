## Зачем нужны объекты

Товар в магазине - это не одно значение, а сразу несколько: название, цена, количество. Можно держать их в трёх массивах и надеяться, что индексы совпадут, но один сбитый индекс - и цена окажется у чужого товара. Надёжнее собрать данные об одной вещи **в одно значение**. Такое значение называется **объектом**.

## Одна новая идея: объект - набор именованных полей

Объект записывают в фигурных скобках: пары «имя: значение» через запятую.

```text
const bread = { name: "хлеб", price: 40 };
```

Каждая пара называется **свойством**: `name` и `price` - имена свойств, `"хлеб"` и `40` - их значения. Прочитать свойство можно через точку: `bread.price` даёт 40. Свойства можно менять присваиванием: `bread.price = 45`.

Чтобы записать, какие свойства должны быть у объектов определённого вида, вводят **интерфейс** (*interface*): описание «формы» объекта.

```text
interface Product {
  name: string;
  price: number;
}
```

Это правило, а не данные: у любого значения типа `Product` обязательно есть строка `name` и число `price`. Интерфейс существует только для проверки типов; во время работы программы его уже нет. С интерфейсом проверка находит опечатки в именах свойств и пропущенные поля.

<!-- section: examples -->
## Пример 1. Объект и его свойства

```typescript run
interface Product {
  name: string;
  price: number;
}

const bread: Product = { name: "хлеб", price: 40 };

console.log(bread);
console.log(bread.name, bread.price);

bread.price = 45;
console.log(bread.price);
console.log(`${bread.name} стоит ${bread.price} руб.`);
```
```output
{ name: 'хлеб', price: 40 }
хлеб 40
45
хлеб стоит 45 руб.
```

`console.log` печатает объект целиком вместе с именами свойств. Первые две строки вывода показывают прежнюю цену 40: она меняется только после них. Одно свойство читается через точку. Объект, как и массив, объявлен через `const` и тем не менее изменяется: `const` запрещает присвоить переменной **другой** объект, но не запрещает менять свойства того, на что она указывает. Присвоить свойству значение не того типа нельзя: `bread.price = "дорого"` - ошибка `TS2322`.

## Пример 2. Массив объектов

```typescript run
interface Product {
  name: string;
  price: number;
  quantity: number;
}

const cart: Product[] = [
  { name: "хлеб", price: 40, quantity: 2 },
  { name: "сыр", price: 300, quantity: 1 },
  { name: "молоко", price: 90, quantity: 3 },
];

let total: number = 0;
for (const item of cart) {
  total = total + item.price * item.quantity;
}
console.log(total);
console.log(cart.length, cart[1].name);
console.log(cart.map((item) => item.name));
```
```output
650
3 сыр
[ 'хлеб', 'сыр', 'молоко' ]
```

Тип `Product[]` - массив объектов нужной формы. Каждый элемент можно обойти уже знакомым `for...of`, а внутри цикла читать свойства. Итог: 40 * 2 + 300 * 1 + 90 * 3 = 650. Методы массивов работают с объектами так же, как с числами: `map((item) => item.name)` собирает массив названий.

## Пример 3. Функции создают и читают объекты

```typescript run
interface Product {
  name: string;
  price: number;
}

function makeProduct(name: string, price: number): Product {
  return { name: name, price: price };
}

function label(p: Product): string {
  return `${p.name}: ${p.price} руб.`;
}

const items: Product[] = [makeProduct("хлеб", 40), makeProduct("чай", 120)];
for (const item of items) {
  console.log(label(item));
}
```
```output
хлеб: 40 руб.
чай: 120 руб.
```

Интерфейс можно использовать как тип параметра и как тип результата. В `makeProduct` объект собирается в `return`; если имя свойства совпадает с именем переменной, можно писать короче: `{ name, price }`. Функция `label` принимает любой объект формы `Product`.

## Пример 4. Объект - не копия, а ссылка

```typescript run
interface Product {
  name: string;
  price: number;
}

const a: Product = { name: "хлеб", price: 40 };
const b: Product = { name: "хлеб", price: 40 };
const c: Product = a;

console.log(a === b);
console.log(a === c);

c.price = 1;
console.log(a.price);

const d: Product = { ...a, price: 99 };
console.log(d, a);
```
```output
false
true
1
{ name: 'хлеб', price: 99 } { name: 'хлеб', price: 1 }
```

Объекты сравниваются и передаются **по ссылке**. `a` и `b` содержат одинаковые данные, но это два разных объекта, поэтому `a === b` ложно. `c = a` не создаёт копию, а даёт второе имя тому же объекту: изменение через `c` видно в `a`. Чтобы получить копию, значения «выписывают» в новый объект: `{ ...a, price: 99 }` - все свойства `a` и новое значение `price`. Такая запись не меняет исходный объект.

**Попробуйте.** Опишите интерфейс `Student` со свойствами `name` (строка) и `grade` (число). Создайте массив из трёх студентов, посчитайте средний балл циклом `for...of` и напечатайте имя первого студента.

## Точные правила

* Литерал объекта: `{ имя: значение, имя: значение }`. Доступ к свойству: `obj.имя`; запись: `obj.имя = значение`.
* `interface Имя { свойство: тип; ... }` описывает форму. Имя интерфейса по традиции пишут с заглавной буквы. Свойства разделяют точкой с запятой (или запятой, или переводом строки).
* Объект, присваиваемый переменной типа интерфейса, должен содержать **все** описанные свойства (иначе `TS2741`), только их (лишние в литерале дают `TS2353`) и значения правильных типов (`TS2322`).
* Обращение к несуществующему свойству - ошибка `TS2339` или, при похожем имени, `TS2551` с подсказкой.
* Интерфейс стирается при выполнении: нельзя спросить «объект этого интерфейса?» во время работы.
* Интерфейс описывает **форму**, а не происхождение: любой объект с нужными свойствами подходит. Про это подробно - в курсе «TypeScript: первые шаги».
* Объекты сравниваются по ссылке: `{ a: 1 } === { a: 1 }` ложно. `const x = y` для объектов не копирует.
* `const` запрещает переприсвоить переменную (`TS2588`), но свойства объекта менять разрешает.
* Копия объекта: `{ ...obj }`; с изменением свойства: `{ ...obj, price: 99 }`.
* Массив объектов: `Product[]`; обход `for (const item of items)`, чтение `item.price`.
* Свойства объекта могут быть любого типа, включая массивы и другие объекты.
* Имена свойств в литерале не требуют кавычек, если это обычные слова (`name`, `price`).

## Типичные ошибки

**1. Пропущено обязательное свойство.**

```typescript
interface Product {
  name: string;
  price: number;
}
const p: Product = { name: "хлеб" };
```

```text
main.ts(5,7): error TS2741: Property 'price' is missing in type '{ name: string; }' but required in type 'Product'.
```

«Свойство `price` отсутствует в типе `{ name: string; }`, но требуется в типе `Product`». Каждый объект типа `Product` обязан иметь цену.

**2. Лишнее свойство.**

```typescript
interface Product {
  name: string;
  price: number;
}
const p: Product = { name: "хлеб", price: 40, color: "белый" };
```

```text
main.ts(5,47): error TS2353: Object literal may only specify known properties, and 'color' does not exist in type 'Product'.
```

В литерале объекта нельзя указать свойство, которого нет в интерфейсе: чаще всего это опечатка. Если оно нужно, добавьте его в интерфейс.

**3. Значение свойства не того типа.**

```typescript
interface Product {
  name: string;
  price: number;
}
const p: Product = { name: "хлеб", price: "40" };
```

```text
main.ts(5,36): error TS2322: Type 'string' is not assignable to type 'number'.
```

Цена записана в кавычках, то есть это строка, а ожидалось число.

**4. Опечатка в имени свойства при чтении.**

```typescript
interface Product {
  name: string;
  price: number;
}
const p: Product = { name: "хлеб", price: 40 };
console.log(p.prise);
```

```text
main.ts(6,15): error TS2551: Property 'prise' does not exist on type 'Product'. Did you mean 'price'?
```

Именно за такие ошибки типы и ценят: без них результат `undefined` обнаружился бы только во время работы.

**5. Переприсвоение `const`.**

```typescript
interface Product {
  name: string;
  price: number;
}
const p: Product = { name: "хлеб", price: 40 };
p = { name: "сыр", price: 1 };
```

```text
main.ts(6,1): error TS2588: Cannot assign to 'p' because it is a constant.
```

Менять свойства `p.price = 45` можно, а присвоить переменной другой объект - нет. Если переменная должна указывать на разные объекты, объявите её через `let`.

**6. Сравнение объектов через `===`.** `{ name: "хлеб", price: 40 } === { name: "хлеб", price: 40 }` даёт `false`, и никакой ошибки нет. Сравнивайте нужные свойства: `a.name === b.name && a.price === b.price`.

**7. «Копия», которая не копия.** `const copy = original;` и `copy.price = 1` изменяют и `original`. Для настоящей копии используйте `{ ...original }`.

<!-- section: summary -->
## Итоги

* Объект собирает именованные значения: `{ name: "хлеб", price: 40 }`; свойство читается через точку.
* `interface` описывает форму объекта: какие свойства и каких типов он должен иметь. Он нужен только проверке типов и стирается.
* Проверка находит пропущенные свойства (`TS2741`), лишние (`TS2353`), неверные типы (`TS2322`) и опечатки в именах (`TS2551`).
* Массив объектов (`Product[]`) обходится циклом, а его методы работают так же, как для чисел.
* Объекты передаются и сравниваются по ссылке; копию делают через `{ ...obj }`.
* `const` не мешает менять свойства объекта, но запрещает присвоить переменной другой объект.

Теперь можно решать настоящие задачи с данными: [Массивы объектов](lesson:typescript.from-zero.arrays-of-objects).

<!-- section: programmer -->
## Для тех, кто уже программирует

* Объект-литерал и `interface` - это не класс: нет конструкторов и методов-обязанностей; данные описываются формой. Ближайший аналог - record/struct, `dataclass` в Python или DTO.
* Типизация **структурная**: подходит любой объект с нужными свойствами, имя интерфейса при этом не важно. Лишние свойства разрешены везде, кроме прямого литерала (проверка лишних свойств). Это основная тема курса «TypeScript: первые шаги».
* Интерфейс не существует при выполнении (стирание типов): `x instanceof Product` для интерфейса невозможен. Данные из JSON или ввода получают тип только по вашему обещанию.
* Объекты сравниваются по ссылке, как в Java (`==`) и C# для классов; равенства по значению нет.
* `{ ...a, price: 99 }` - поверхностная копия: вложенные объекты и массивы остаются общими.
* Альтернатива интерфейсу - псевдоним типа `type Product = { ... }`; разница мелкая, оба варианта работают одинаково для этого курса.
