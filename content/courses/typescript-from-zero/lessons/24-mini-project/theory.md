## Зачем это нужно

Все предыдущие уроки учили отдельным инструментам: значениям, условиям, циклам, массивам, объектам, исключениям, чтению ввода. Настоящая программа использует их вместе, и самое трудное в ней - не какой-либо один приём, а порядок: что делать сначала, что потом, что поручить отдельной функции. Этот урок - небольшой законченный проект: программа читает записи о расходах, отбрасывает испорченные строки и печатает отчёт.

## Одна идея: конвейер из небольших этапов

Большая задача решается проще, если разбить её на этапы, у каждого из которых один вход и один выход:

1. **Прочитать** весь ввод и разбить на строки.
2. **Разобрать** одну строку в объект `Entry` (категория и сумма) либо сообщить, что строка неверна.
3. **Накопить** суммы по категориям в массиве объектов `Total`.
4. **Вывести** отчёт: категории по убыванию суммы, затем итоги.

Каждый этап можно написать и проверить отдельно, а потом соединить. Этап «разобрать» оформляется функцией, которая **выбрасывает ошибку** на неверной строке, а главный цикл перехватывает её и увеличивает счётчик. Так плохая строка не останавливает программу и не портит итоги.

## Пример 1. Этап «разобрать»

Формат строки: `категория;сумма`. Неверно, если частей не две, категория пуста или сумма не является положительным числом.

```typescript run
interface Entry {
  category: string;
  amount: number;
}

function parseEntry(line: string): Entry {
  const parts: string[] = line.split(";");
  if (parts.length !== 2) {
    throw new Error("нужны ровно две части");
  }
  const category: string = parts[0].trim();
  if (category === "") {
    throw new Error("пустая категория");
  }
  const amount: number = Number(parts[1].trim());
  if (Number.isNaN(amount) || amount <= 0) {
    throw new Error("сумма должна быть положительным числом");
  }
  return { category: category, amount: amount };
}

const samples: string[] = ["еда;250.5", " кино ; 300 ", "кино", ";100", "еда;abc", "еда;-5", "еда;1;2"];
for (const line of samples) {
  try {
    console.log(parseEntry(line));
  } catch (error) {
    if (error instanceof Error) {
      console.log("неверно: " + error.message);
    }
  }
}
```
```output
{ category: 'еда', amount: 250.5 }
{ category: 'кино', amount: 300 }
неверно: нужны ровно две части
неверно: пустая категория
неверно: сумма должна быть положительным числом
неверно: сумма должна быть положительным числом
неверно: нужны ровно две части
```

Функция сначала делит строку по `;` и проверяет число частей: у `"кино"` частей одна, у `"еда;1;2"` три. Затем очищает название от пробелов и проверяет, что оно не пустое. Наконец, превращает вторую часть в число; условие `Number.isNaN(amount) || amount <= 0` отсеивает и слова, и нуль, и отрицательные суммы. Если все проверки пройдены, функция возвращает готовый объект. Строка `" кино ; 300 "` допустима: пробелы вокруг частей убираются.

## Пример 2. Этап «накопить»

```typescript run
interface Total {
  category: string;
  sum: number;
}

function addToTotals(totals: Total[], category: string, amount: number): void {
  const found = totals.find((t) => t.category === category);
  if (found === undefined) {
    totals.push({ category: category, sum: amount });
  } else {
    found.sum = found.sum + amount;
  }
}

const totals: Total[] = [];
addToTotals(totals, "еда", 250);
addToTotals(totals, "кино", 300);
addToTotals(totals, "еда", 100);
console.log(totals);
```
```output
[ { category: 'еда', sum: 350 }, { category: 'кино', sum: 300 } ]
```

Для каждой записи ищем итог своей категории. Если `find` вернул `undefined`, категория встретилась впервые, и в массив добавляется новый объект. Иначе `found` - тот самый объект, что лежит в массиве (объекты передаются по ссылке), и достаточно увеличить его `sum`. Функция ничего не возвращает (тип `void`): она изменяет переданный массив.

## Пример 3. Этап «вывести»

```typescript run
interface Total {
  category: string;
  sum: number;
}

const totals: Total[] = [
  { category: "еда", sum: 350 },
  { category: "транспорт", sum: 60 },
  { category: "кино", sum: 350 },
];

const sorted: Total[] = [...totals].sort((a, b) => b.sum - a.sum);
for (const t of sorted) {
  console.log(t.category + ": " + t.sum.toFixed(2));
}
```
```output
еда: 350.00
кино: 350.00
транспорт: 60.00
```

Компаратор `b.sum - a.sum` упорядочивает по убыванию. «Еда» и «кино» равны по сумме, и их порядок остался исходным, потому что сортировка стабильная. Копия `[...totals]` оставляет исходный массив нетронутым. Суммы печатаются с двумя знаками методом `toFixed(2)`.

## Пример 4. Сборка целиком

Главная часть программы: чтение, цикл с `try ... catch`, отчёт. Это программа с вводом, поэтому приведены ввод и вывод (функции `parseEntry` и `addToTotals` берутся из примеров 1 и 2).

```typescript
const text: string = readFileSync(0, "utf8");
const lines: string[] = text.trim().split("\n");

const totals: Total[] = [];
let all: number = 0;
let valid: number = 0;
let bad: number = 0;

for (const rawLine of lines) {
  const line: string = rawLine.trim();
  if (line === "") {
    continue;
  }
  try {
    const entry: Entry = parseEntry(line);
    addToTotals(totals, entry.category, entry.amount);
    all = all + entry.amount;
    valid = valid + 1;
  } catch (error) {
    bad = bad + 1;
  }
}
```

Ввод:

```text
еда;250
кино
транспорт;60
еда;100.5
```

Вывод после печати отчёта:

```text
еда: 350.50
транспорт: 60.00
Итого: 410.50
Записей: 3
Неверных строк: 1
```

Порядок работы цикла: пустые строки отбрасываются сразу и ничего не меняют; строка `кино` не проходит разбор, `parseEntry` выбрасывает ошибку, `catch` увеличивает `bad`. Увеличения `all` и `valid` стоят **после** `parseEntry` и `addToTotals`, поэтому для неверной строки они не выполняются.

**Попробуйте.** Расширьте формат: пусть сумма может быть записана с десятичной запятой (`"12,5"`). Подумайте, где нужно заменить запятую на точку (`replaceAll`) и почему делать это нужно **до** вызова `Number`.

## Точные правила задачи

* Строка ввода имеет вид `категория;сумма`. Пробелы вокруг частей допустимы и игнорируются; пустые строки (и из одних пробелов) пропускаются без подсчёта.
* Строка неверна, если после `split(";")` частей не две, категория пуста или сумма (после `trim`) не превращается через `Number` в число больше нуля.
* Каждая неверная строка увеличивает счётчик неверных строк; программа не останавливается.
* Категория сравнивается как строка точно: `Еда` и `еда` - разные категории.
* Отчёт: сначала строки `категория: сумма` по убыванию суммы (при равных суммах - в порядке первого появления категории), затем `Итого`, `Записей`, `Неверных строк`.
* Все суммы выводятся с двумя знаками после запятой (`toFixed(2)`).
* Для пустого ввода или ввода без верных строк категорий нет, и печатаются только три итоговые строки: `Итого: 0.00`, `Записей: 0`, `Неверных строк: N`.
* Окончания строк Windows (`\r\n`) не должны влиять на результат: каждая строка очищается `trim()`.
* Этапы лучше оформлять отдельными функциями с понятными типами: `parseEntry(line): Entry`, `addToTotals(totals, ...): void`.
* Один и тот же объект из `find` можно изменять: он лежит в массиве, а не копируется.
* Копию для сортировки делайте через `[...totals]`.

## Типичные ошибки

**1. Увеличение счётчика до разбора.** Если `valid = valid + 1` стоит перед вызовом `parseEntry`, то для неверной строки счётчик успеет вырасти, и отчёт покажет лишнюю запись. Увеличивайте счётчики после того, как все этапы прошли без ошибки.

**2. Пустые строки считаются неверными.** Пустая строка в конце ввода - обычное дело. Если проверять её только через `parseEntry`, она попадёт в «неверные». Пропускайте пустые строки до разбора.

**3. Забыт `trim` у категории.** `"еда "` и `"еда"` станут разными категориями. Очищайте обе части.

**4. Сумма `0` и отрицательная сумма.** `Number("0")` - валидное число, но по условию сумма должна быть больше нуля. Проверка `Number.isNaN(amount)` одна не отсекает такие строки; нужно ещё `amount <= 0`.

**5. Строка с лишними частями.** `"еда;1;2"` даёт три части, а не две. Если взять `parts[0]` и `parts[1]` без проверки `parts.length`, программа примет её как «еда;1» и молча потеряет данные.

**6. Чтение элемента массива без проверки.** Тип `parts[1]` для проверки типов - `string`, даже если части нет. Поэтому длину нужно проверять явно, как в примере 1: иначе `parts[1].trim()` упадёт с `TypeError` во время работы.

```text
TypeError: Cannot read properties of undefined (reading 'trim')
```

**7. Результат `find` без проверки.**

```typescript
interface Total {
  category: string;
  sum: number;
}

function addToTotals(totals: Total[], category: string, amount: number): void {
  const found = totals.find((t) => t.category === category);
  found.sum = found.sum + amount;
}
```

```text
main.ts(8,3): error TS18048: 'found' is possibly 'undefined'.
main.ts(8,15): error TS18048: 'found' is possibly 'undefined'.
```

Категория может быть новой, и тогда `find` вернёт `undefined`. Нужна ветка `if (found === undefined)`.

**8. Сортировка исходного массива.** `totals.sort(...)` изменяет `totals` на месте. В этой программе это безвредно, но привычка сортировать копию избавляет от ошибок в более длинных программах.

**9. Сумма с `NaN` в итогах.** Если не проверить `Number.isNaN`, одна строка вида `еда;abc` превращает всю сумму категории и общий итог в `NaN`.

## Итоги

* Программу удобно строить как конвейер: прочитать, разобрать, накопить, вывести. У каждого этапа свой вход и выход.
* Разбор одной строки оформляется функцией, которая выбрасывает ошибку на неверных данных; цикл перехватывает её и считает неверные строки.
* Суммы по категориям хранятся в массиве объектов; `find` определяет, есть ли уже категория, и учитывает случай `undefined`.
* Отчёт точно следует формату: порядок, два знака после запятой, итоговые строки.
* Пустые строки и окончания Windows обрабатываются до разбора.

## Для тех, кто уже программирует

* Структура программы типична для разбора текстовых данных: чтение, валидация, агрегация, отчёт. Те же этапы встретятся в любом языке; в TypeScript их типы фиксируются интерфейсами `Entry` и `Total`.
* Агрегация идёт через массив и `find`, потому что `Map` и `Record` в курсе не вводились; на больших данных поиск по массиву квадратичен, и естественный следующий шаг - `Map<string, number>`.
* Исключения для «ожидаемо плохих» строк - вопрос вкуса. Альтернатива: функция `parseEntry` возвращает `Entry | undefined`, а вызывающий код проверяет результат. Здесь выбран `throw`, чтобы причина была в сообщении ошибки, как в уроке 22.
* `parts[1]` имеет тип `string`, хотя элемента может не быть (настройка `noUncheckedIndexedAccess` выключена), поэтому проверка `parts.length` обязательна.
* Float-арифметика: `0.1 + 0.2` печатается как `0.30` только благодаря `toFixed(2)`. Для денег в реальных системах хранят копейки целыми числами.
* Сортировка стабильна (Node.js 11+), поэтому равные суммы сохраняют порядок первого появления без дополнительных ключей.
* Данные из ввода, прошедшие `parseEntry`, имеют настоящие типы: это единственное место, где граница «снаружи - внутри» пересекается явно. Всё остальное - обычные функции над проверенными данными.
