## Зачем нужно «значения может не быть»

Поиск не всегда успешен: в списке покупок может не оказаться нужного товара, в пустом массиве нет первого элемента, у пользователя может быть не заполнено поле. В таких случаях функции нечего вернуть. Многие языки в этот момент молча возвращают «пустоту», и программа ломается позже и в другом месте, когда пытается использовать несуществующее значение. TypeScript устроен иначе: он **записывает в тип**, что значения может не быть, и требует это обработать до запуска.

## Одна новая идея: тип «число или ничего» и проверка перед использованием

Значение, означающее «ничего нет», называется **`undefined`** («не определено»). Он уже встречался: так выглядит несуществующий элемент массива. Чтобы разрешить его в типе, используют **объединение** (по-английски *union*): тип из нескольких вариантов, записанных через вертикальную черту.

```text
number | undefined
```

Читается «число **или** `undefined`». Переменную такого типа нельзя использовать как число, пока не проверено, что число там есть. Проверка называется **сужением типа** (*narrowing*): после `if (value === undefined) { ... }` внутри остальной части функции компилятор знает, что `value` уже точно число, и разрешает его использовать.

Для частого случая «если нет значения, взять запасное» есть короткий оператор **`??`** («если слева ничего нет, то справа»): `value ?? 0` даёт `value`, а если там `undefined` - число `0`.

## Пример 1. Объединение и сужение

```typescript run
function describe(value: number | undefined): string {
  if (value === undefined) {
    return "нет данных";
  }
  return `значение ${value.toFixed(1)}`;
}

console.log(describe(undefined));
console.log(describe(2.5));
```
```output
нет данных
значение 2.5
```

Параметр `value` может быть числом или `undefined`. Первая проверка отсекает `undefined` и выходит из функции. После неё компилятор знает: здесь `value` - число, поэтому вызов `value.toFixed(1)` разрешён. Без `if` вызов был бы ошибкой `TS18048`: число могло бы отсутствовать.

## Пример 2. Функция, которая может ничего не найти

```typescript run
function firstNegative(values: number[]): number | undefined {
  for (const v of values) {
    if (v < 0) {
      return v;
    }
  }
  return undefined;
}

const found = firstNegative([4, -2, 7, -9]);
const missing = firstNegative([4, 7]);

console.log(found, missing);

if (found !== undefined) {
  console.log("Нашли:", found + 1);
}
```
```output
-2 undefined
Нашли: -1
```

Тип результата `number | undefined` честно сообщает о двух исходах. Тот, кто вызывает функцию, обязан обработать оба: строка `found + 1` разрешена только внутри блока `if (found !== undefined)`. Без проверки проверка типов остановила бы программу ещё до запуска. Так стандартные `find` и `at` из прошлых уроков и устроены.

## Пример 3. `at`, `find` и запасное значение `??`

```typescript run
const list: number[] = [4, 5, 6];

console.log(list.at(0), list.at(-1), list.at(10));

const empty: number[] = [];

const last: number = list.at(-1) ?? 0;
const nothing: number = empty.at(-1) ?? 0;
console.log(last, nothing);

const firstBig: number = list.find((n) => n > 4) ?? -1;
console.log(firstBig);
```
```output
4 6 undefined
6 0
5
```

Метод **`at(i)`** читает элемент по индексу: как `list[i]`, но за границами он честно даёт `undefined` (и тип результата - `number | undefined`), а отрицательный индекс отсчитывается с конца: `at(-1)` - последний элемент. Оператор `??` превращает «число или ничего» в обычное число: `list.at(-1) ?? 0` - последний элемент, а если массив пуст, то 0. После `??` справа тип результата - просто `number`.

## Пример 4. `??` и ноль

```typescript run
const count: number | undefined = 0;
console.log(count ?? 10);
console.log(count || 10);
```
```output
0
10
```

`??` подставляет запасное значение **только** для «ничего» (`undefined`). Ноль - настоящее значение, и `count ?? 10` его сохраняет. Похожий оператор `||` («или») считает ложью и ноль, и пустую строку, и поэтому подставляет запасное значение там, где оно не нужно. Для необязательных значений используйте `??`.

## Пример 5. Объединение из двух типов

```typescript run
function show(value: number | string): string {
  if (typeof value === "string") {
    return "строка длиной " + value.length;
  }
  return "число " + value.toFixed(2);
}

console.log(show("привет"));
console.log(show(3));
```
```output
строка длиной 6
число 3.00
```

Объединение не обязано содержать `undefined`: `number | string` - значение любого из двух типов. Здесь сужение выполняет `typeof` (он уже встречался в уроке про типы значений): внутри `if` компилятор считает `value` строкой, а после него - числом.

**Попробуйте.** Напишите функцию `lastOrDefault(values: number[], fallback: number): number`, которая возвращает последний элемент или `fallback` для пустого массива. Затем вызовите её с массивом `[0]` и `fallback` равным 5: что вернётся и почему `??` здесь верный выбор, а `||` нет.

## Точные правила

* `T | U` - объединение: значение типа `T` или типа `U`. `number | undefined` - «число или ничего».
* С включённой проверкой `strict` значение `undefined` не входит в обычные типы: переменной типа `number` его не присвоить (`TS2322`).
* Использовать значение объединения можно только так, как подходит **каждому** варианту. Для `number | undefined` методы числа недоступны (`TS18048`), пока `undefined` не исключён.
* **Сужение** - уточнение типа проверкой: `x === undefined`, `x !== undefined`, `typeof x === "string"`. Внутри ветки, где проверка прошла, тип уже уточнён; после `if (...) { return ...; }` уточнение действует для остального кода функции.
* `a ?? b` возвращает `a`, если он не `undefined` (и не `null`), иначе `b`. Результат имеет тип без `undefined`, если `b` его не содержит.
* `a || b` подставляет `b` для любого «ложного» `a`: `0`, `""`, `NaN`, `false`, `undefined`. Для необязательных значений он опасен: `0 || 10` даёт 10.
* Условие `if (x)` для числа тоже считает ложным ноль: `if (found)` пропустит найденное `0`. Для проверки наличия пишите явно: `found !== undefined`.
* `values.find(...)` и `values.at(i)` возвращают `T | undefined`. Индекс `values[i]` тип `T` не расширяет, хотя за границами тоже даёт `undefined`: надёжнее `at`.
* `values.at(-1)` - последний элемент; `at(-2)` - предпоследний.
* Функция с типом результата `T | undefined` должна возвращать значение на каждом пути: явный `return undefined;` в конце делает намерение видимым.
* Параметр функции с типом `T | undefined` не может быть опущен при вызове в этом курсе; передавайте `undefined` явно.

## Типичные ошибки

**1. Использование значения, которого может не быть.**

```typescript
const prices: number[] = [30, 10, 20];
const found = prices.find((p) => p > 15);
console.log(found + 1);
```

```text
main.ts(3,13): error TS18048: 'found' is possibly 'undefined'.
```

«`found`, возможно, равно `undefined`». Проверка не позволяет прибавить единицу к значению, которого может не быть. Добавьте `if (found !== undefined)` или запасное значение через `??`.

**2. Метод у значения, которого может не быть.**

```typescript
const prices: number[] = [30, 10, 20];
const found = prices.find((p) => p > 15);
console.log(found.toFixed(2));
```

```text
main.ts(3,13): error TS18048: 'found' is possibly 'undefined'.
```

Та же причина, другая операция: пока `undefined` не исключён, ни арифметика, ни методы числа недоступны.

**3. `undefined` в переменную числового типа.**

```typescript
const price: number = undefined;
```

```text
main.ts(1,7): error TS2322: Type 'undefined' is not assignable to type 'number'.
```

Если переменная может быть пустой, тип должен это сказать: `number | undefined`.

**4. Результат вместо обработки.**

```typescript
function firstBig(values: number[]): number | undefined {
  return values.find((v) => v > 100);
}
const result: number = firstBig([1, 2]);
```

```text
main.ts(4,7): error TS2322: Type 'number | undefined' is not assignable to type 'number'.
  Type 'undefined' is not assignable to type 'number'.
```

Функция честно обещает «число или ничего», а переменная хочет только число. Обработайте результат: `const result: number = firstBig([1, 2]) ?? 0;`.

**5. Вернули `undefined`, где обещано число.**

```typescript
function twice(value: number | undefined): number {
  if (value !== undefined) {
    return value * 2;
  }
  return value;
}
```

```text
main.ts(5,3): error TS2322: Type 'undefined' is not assignable to type 'number'.
```

В последней строке `value` уже точно `undefined`, а функция обещает число. Нужно вернуть настоящее число, например `return 0;`.

**6. Метод одного из типов объединения.**

```typescript
function f(v: number | string): string {
  return v.toUpperCase();
}
```

```text
main.ts(2,12): error TS2339: Property 'toUpperCase' does not exist on type 'string | number'.
  Property 'toUpperCase' does not exist on type 'number'.
```

У числа нет метода `toUpperCase`, а `v` может быть числом. Сначала сузьте тип: `if (typeof v === "string") { ... }`.

**7. Ноль потерян из-за `||` или `if (x)`.** Если `count` равен `0`, выражение `count || 10` даст 10, а условие `if (count)` не выполнится. Ошибки не будет, но программа решит, что значения нет. Используйте `??` и явное `!== undefined`.

<!-- section: summary -->
## Итоги

* `number | undefined` - объединение: «число или ничего». Тип заранее сообщает, что значения может не быть.
* Использовать такое значение можно только после проверки; она называется сужением типа: `x !== undefined`, `typeof x === "string"`.
* `a ?? b` подставляет запасное значение `b`, если `a` - `undefined`; ноль и пустую строку оператор сохраняет.
* `find` и `at` возвращают `T | undefined`; `at(-1)` - последний элемент.
* Не используйте `||` и `if (x)` для проверки наличия числа: ноль они считают отсутствием значения.
* Функция, которая может ничего не найти, объявляет результат `T | undefined`, а вызывающий обязан обработать оба случая.

Теперь можно заняться текстом всерьёз: [Методы строк](lesson:typescript.from-zero.string-methods).

## Для тех, кто уже программирует

* `T | undefined` играет роль `Optional<T>` в Java и `T?` в C#/Kotlin, но это обычное объединение типов, а не обёртка: значение не оборачивается, объект `undefined` существует во время работы.
* В JavaScript есть ещё `null`. Строгий режим различает `null` и `undefined`; в курсе используется только `undefined`. Оператор `??` обрабатывает оба.
* Сужение - это анализ потока управления: компилятор знает, какие проверки уже пройдены. `if (x === undefined) return;` сужает тип `x` ниже по коду. Это аналог smart cast в Kotlin.
* `??` аналогичен `?:` в Kotlin и `??` в C#; `||` для значений, которые могут быть «ложными» (0, "", NaN), даёт ошибки, известные из JavaScript.
* Типы стираются: во время работы `number | undefined` ничего не проверяет. Данные извне (ввод, JSON) приходят без гарантий.
* `arr[i]` в `strict` имеет тип элемента (без `undefined`), хотя за границами вернёт `undefined`; `noUncheckedIndexedAccess` это исправляет, но не входит в `strict`. `at` честнее.
