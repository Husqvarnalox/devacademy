## Зачем готовые методы

В прошлом уроке вы написали `applyAll` и `countWhere`: цикл, пустой массив-результат, вызов переданной функции. Такие задачи («преобразовать каждый элемент», «оставить подходящие», «найти первый подходящий») встречаются постоянно, поэтому у каждого массива уже есть готовые **методы**, устроенные точно так же: в них нужно передать только функцию с действием. Метод - это функция, которая «принадлежит» значению и вызывается через точку: `prices.push(40)`, `names.join(", ")`.

## Одна новая идея: метод берёт функцию и сам выполняет цикл

Главные методы:

* **`map(f)`** («отобразить») - новый массив, в котором каждый элемент заменён результатом `f(элемент)`; длина та же.
* **`filter(test)`** («отфильтровать») - новый массив из тех элементов, для которых `test(элемент)` вернула `true`.
* **`find(test)`** («найти») - первый элемент, для которого `test` вернула `true`. Если такого нет, результат - `undefined`.
* **`includes(x)`** («содержит») - `true`, если в массиве есть элемент, равный `x`.
* **`join(разделитель)`** («соединить») - строка из элементов, между которыми вставлен разделитель.
* **`sort(сравнение)`** - упорядочивает массив **на месте**, меняя его. Поэтому сортируют **копию**: `[...values].sort(...)`.

Все они (кроме `sort`) создают **новый** массив или значение и оставляют исходный нетронутым.

<!-- section: examples -->
## Пример 1. `map` и `filter`

```typescript run
const prices: number[] = [30, 10, 20, 50];

const withDelivery: number[] = prices.map((p) => p + 5);
const affordable: number[] = prices.filter((p) => p <= 30);
const lengths: number[] = ["хлеб", "молоко"].map((s) => s.length);

console.log(withDelivery);
console.log(affordable);
console.log(lengths);
console.log(prices);
```
```output
[ 35, 15, 25, 55 ]
[ 30, 10, 20 ]
[ 4, 6 ]
[ 30, 10, 20, 50 ]
```

`map` прибавил 5 к каждой цене и вернул новый массив той же длины. `filter` оставил цены не выше 30: `(p) => p <= 30` - предикат, как `test` из прошлого урока. `map` может менять и тип элементов: `["хлеб", "молоко"].map((s) => s.length)` превращает строки в числа (длины слов). Исходный массив `prices` после всех вызовов не изменился.

## Пример 2. `find`, `includes`, `join`

```typescript run
const names: string[] = ["Борис", "Анна", "Виктор"];
const prices: number[] = [30, 10, 20];

console.log(names.includes("Анна"), names.includes("Ольга"));
console.log(names.join(", "));
console.log(prices.join("-"));
console.log(prices.find((p) => p > 15));
console.log(prices.find((p) => p > 100));
```
```output
true false
Борис, Анна, Виктор
30-10-20
30
undefined
```

`includes` отвечает на вопрос «есть ли такое значение». `join` склеивает элементы в строку с разделителем; числа превращаются в текст автоматически. `find` возвращает **первый** подходящий элемент (30, хотя 20 тоже больше 15, идёт позже) или `undefined`, когда подходящих нет. Что с таким результатом делать, чтобы программа не сломалась, расскажет урок 18; пока `find` достаточно уметь вызвать и напечатать результат.

## Пример 3. Сортировка копии

```typescript run
const prices: number[] = [30, 10, 20];

const ascending: number[] = [...prices].sort((a, b) => a - b);
const descending: number[] = [...prices].sort((a, b) => b - a);

console.log(ascending);
console.log(descending);
console.log(prices);

const names: string[] = ["Борис", "Анна", "Виктор"];
console.log([...names].sort());
```
```output
[ 10, 20, 30 ]
[ 30, 20, 10 ]
[ 30, 10, 20 ]
[ 'Анна', 'Борис', 'Виктор' ]
```

Запись `[...prices]` («развернуть массив в новый литерал») создаёт копию: значения из `prices` выписываются в новый массив. Метод `sort` меняет тот массив, у которого вызван, поэтому, сортируя копию, мы оставляем `prices` как был. Сравнивающая функция `(a, b) => a - b` получает два элемента и возвращает число: отрицательное, если `a` должно стоять раньше `b`, положительное - если позже, нуль - если равны. Для порядка по убыванию вычитают наоборот: `b - a`. Строки без сравнивающей функции сортируются по алфавиту.

## Пример 4. Ловушка `sort` без сравнения

```typescript run
const nums: number[] = [10, 9, 1, 100];
console.log([...nums].sort());
console.log([...nums].sort((a, b) => a - b));
```
```output
[ 1, 10, 100, 9 ]
[ 1, 9, 10, 100 ]
```

Без сравнивающей функции `sort` упорядочивает элементы **как строки**: `"10"` стоит раньше `"9"`, потому что первая цифра `1` меньше `9`. Для чисел функцию сравнения нужно указывать всегда. Проверка типов этого не замечает: массив чисел сортируется без ошибки, просто в странном порядке.

## Пример 5. Методы в функциях

```typescript run
function bigDoubled(values: number[], limit: number): string {
  return values
    .filter((v) => v > limit)
    .map((v) => v * 2)
    .join(", ");
}

function titles(words: string[]): string {
  return words.map((w) => `«${w}»`).join(" ");
}

console.log(bigDoubled([5, 12, 7, 20, 3], 6));
console.log(bigDoubled([1, 2], 6) === "");
console.log(titles(["один", "два"]));
```
```output
24, 14, 40
true
«один» «два»
```

Методы соединяют в **цепочку**: `filter(...)` возвращает массив, у него тут же вызывается `map`, у результата - `join`. Читать цепочку нужно слева направо: оставить числа больше 6 (12, 7, 20), удвоить (24, 14, 40), склеить через запятую. Если подходящих чисел нет, `filter` вернёт пустой массив, а `join` пустого массива даст пустую строку. В `titles` каждое слово заворачивается в кавычки-ёлочки, потом слова склеиваются через пробел.

**Попробуйте.** Из массива `[4, 15, 8, 30]` оставьте числа меньше 20, прибавьте к каждому 1 и склейте через дефис. Ответ предскажите до запуска, а затем сравните с выводом.

## Точные правила

* `values.map(f)` возвращает новый массив той же длины; `f` получает элемент (и, если нужно, индекс).
* `values.filter(test)` возвращает новый массив из элементов, для которых `test` вернула «истину».
* `values.find(test)` возвращает первый подходящий элемент или `undefined`; его тип `T | undefined`.
* `values.includes(x)` сравнивает через `===`; для массива чисел аргумент должен быть числом (`TS2345`).
* `values.join(sep)` возвращает строку; `join()` без аргумента ставит запятую, `join("")` склеивает без разделителя. Пустой массив даёт пустую строку.
* `values.sort(cmp)` меняет массив на месте и возвращает его же. Без `cmp` элементы сравниваются как строки.
* Сравнивающая функция: отрицательный результат - `a` раньше `b`, положительный - позже, ноль - порядок сохраняется. `a - b` даёт порядок по возрастанию, `b - a` - по убыванию.
* Копия массива: `[...values]`. В тип `es2022` методов `toSorted` и `toReversed` нет: вызов даёт `TS2550`.
* `map`, `filter` и `find` исходный массив не меняют. Результат вызова без присвоения теряется (`prices.map(...)` в одиночку ничего не делает).
* Типы выводятся: `map((s) => s.length)` на `string[]` даёт `number[]`.
* Цепочки читаются слева направо: `values.filter(...).map(...).join(", ")`.

## Типичные ошибки

**1. Метод, которого нет в языке нашей версии.**

```typescript
const nums: number[] = [3, 1, 2];
const sorted = nums.toSorted();
```

```text
main.ts(2,21): error TS2550: Property 'toSorted' does not exist on type 'number[]'. Do you need to change your target library? Try changing the 'lib' compiler option to 'es2023' or later.
```

Метод `toSorted` появился в новом стандарте JavaScript (ES2023), а в курсе проверка настроена на ES2022. Привычное решение: `[...nums].sort((a, b) => a - b)`.

**2. Результат `find` присвоен переменной типа `number`.**

```typescript
const nums: number[] = [3, 1, 2];
const first: number = nums.find((n) => n > 1);
```

```text
main.ts(2,7): error TS2322: Type 'number | undefined' is not assignable to type 'number'.
  Type 'undefined' is not assignable to type 'number'.
```

«Тип `number | undefined` нельзя присвоить типу `number`»: `find` может ничего не найти и вернуть `undefined`. Проверка нас предупреждает, и именно поэтому в TypeScript этого результата нельзя просто использовать как число. Как с ним работать, расскажет следующий урок.

**3. `includes` с аргументом другого типа.**

```typescript
const nums: number[] = [3, 1, 2];
console.log(nums.includes("3"));
```

```text
main.ts(2,27): error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
```

В массиве чисел искать можно только число; строка `"3"` и число 3 - разные значения.

**4. Неверный тип результата `map`.**

```typescript
const nums: number[] = [1, 2, 3];
const doubled: string[] = nums.map((n) => n * 2);
```

```text
main.ts(2,7): error TS2322: Type 'number[]' is not assignable to type 'string[]'.
  Type 'number' is not assignable to type 'string'.
```

`n * 2` - число, поэтому `map` вернёт массив чисел, а переменная объявлена как массив строк. Тип результата `map` определяется тем, что возвращает ваша функция.

**5. Метод вызван, результат потерян.**

```typescript
const prices: number[] = [30, 10, 20];
prices.map((p) => p + 1);
console.log(prices);
```

Ошибки нет, но напечатается исходный массив: `map` создаёт **новый** массив, и без присваивания он пропадает. Сохраняйте результат: `const raised = prices.map(...)`.

**6. `sort` без сравнения и сортировка оригинала.** `nums.sort()` для чисел `[10, 9, 1, 100]` даёт `[1, 10, 100, 9]`: сравнение идёт как по строкам. Кроме того, такой вызов меняет `nums`. Правильно: `[...nums].sort((a, b) => a - b)`.

**7. Забыли, что `find` возвращает первый.** `find` останавливается на первом подходящем элементе. Чтобы получить все, используйте `filter`.

<!-- section: summary -->
## Итоги

* `map(f)` преобразует каждый элемент, `filter(test)` отбирает подходящие, `find(test)` ищет первый подходящий или даёт `undefined`.
* `includes(x)` отвечает «есть ли значение», `join(sep)` склеивает элементы в строку.
* `map`, `filter`, `find` не меняют исходный массив; `sort` меняет, поэтому сортируйте копию `[...values]`.
* Для чисел в `sort` нужна сравнивающая функция `(a, b) => a - b` (по возрастанию) или `b - a` (по убыванию).
* Методы соединяют в цепочки: `filter(...).map(...).join(", ")`.
* Результат `find` имеет тип `T | undefined`: его нельзя использовать как `T` без проверки.

Разобраться с таким значением поможет следующий урок: [Необязательные значения](lesson:typescript.from-zero.optional-values).

## Для тех, кто уже программирует

* `map`, `filter`, `find` соответствуют Stream API в Java (`map`, `filter`, `findFirst`), LINQ в C# (`Select`, `Where`, `FirstOrDefault`), спискам-включениям в Python; но работают сразу (жадно) и создают промежуточные массивы.
* `sort` без компаратора сравнивает как строки (унаследовано от JavaScript): `[10, 9, 1].sort()` даёт `[1, 10, 9]`. Это самая известная ловушка.
* `sort` мутирует массив; в ES2023 для копии добавлены `toSorted`/`toReversed`, но в курсе (lib `es2022`) их нет - используйте `[...a].sort(...)`.
* `find` возвращает `T | undefined`, а не бросает исключение и не возвращает `Optional`; `strictNullChecks` заставляет обработать `undefined`.
* `join` у чисел и других значений вызывает приведение к строке; `[].join(",")` - пустая строка.
* `includes` сравнивает через `===` (кроме `NaN`: `includes(NaN)` находит `NaN`); для объектов сравнивает ссылки.
