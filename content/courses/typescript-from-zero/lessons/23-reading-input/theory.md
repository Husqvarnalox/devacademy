## Зачем это нужно

До сих пор данные были записаны прямо в программе: в массиве, в переменной. Настоящая программа получает их снаружи: пользователь вводит числа, другая программа передаёт список, файл содержит таблицу. Всё, что программа получает от внешнего мира, называется **вводом**. Ввод приходит **текстом**, даже если выглядит как числа, и ему нельзя доверять: в нём бывают пустые строки, лишние пробелы и слова вместо чисел. Этот урок учит прочитать ввод и аккуратно превратить его в данные.

## Одна новая идея: ввод - это строка, которую нужно разобрать

Текст попадает на **стандартный ввод** (stdin) вашей программы: это канал, по которому данные поступают в программу. В приложении вы вписываете его в специальное поле перед запуском (подробно - в подразделе «Как подать ввод своей программе» ниже), а при проверке решения его подаёт тест. Прочитать его целиком можно так:

```typescript
import { readFileSync } from "node:fs";

const text: string = readFileSync(0, "utf8");
```

Первая строка - **импорт**: команда `import` берёт из встроенного модуля `node:fs` (от file system, «файловая система») готовую функцию `readFileSync`, чтобы ею можно было пользоваться. Вторая строка вызывает её:

* `readFileSync` - «прочитать файл целиком и дождаться окончания чтения»; слово `Sync` значит, что программа ждёт.
* `0` - что читать. Операционная система нумерует каналы: 0 - стандартный ввод. Он считается файлом условно, но читается тем же способом.
* `"utf8"` - **кодировка**: правило превращения байтов в буквы. Без неё функция вернула бы сырые байты, а с ней - обычную строку; кириллица читается правильно.
* `const text: string` - результат сохранён в переменной: это одна длинная строка со всем вводом, строки разделены символом переноса `"\n"`.

Дальше ввод разбирают привычными средствами: `text.trim().split("\n")` даёт массив строк, `for...of` обходит их. Каждую строку превращают в число функцией **`Number`**. Если строка не похожа на число, `Number` возвращает особое значение **`NaN`** (от Not a Number, «не число»). Распознают его проверкой **`Number.isNaN(value)`**. Сравнение `value === NaN` не работает, потому что `NaN` не равно даже самому себе.

## Как подать ввод своей программе

1. Под редактором откройте вкладку **«Вывод»**.
2. Нажмите на строку **«Ввод программы (stdin)»**: под ней раскроется поле.
3. Впишите в поле весь ввод заранее: каждое число на своей строке, потому что программа разбивает текст по переводам строк. Например, для примера 1 впишите `10`, `20.5` и `30`, каждое на отдельной строке.
4. Нажмите **«Запустить»**.

Программа не останавливается и не ждёт, пока вы что-то напечатаете: `readFileSync(0, "utf8")` получает сразу весь текст из поля при запуске. Если поле пустое, `text` - пустая строка (что с ней делает `split`, показано в примере 2). Пока урок открыт, текст в поле остаётся, так что для следующего запуска достаточно поменять числа.

Кнопка **«Проверить решение»** это поле не использует: она запускает программу на вводе каждого теста по очереди.

## Пример 1. Прочитать и сложить

Эту программу нельзя запустить в окне примеров, потому что там нет ввода, поэтому приведены ввод и вывод. Программа читает цены по одной в строке и печатает сумму с двумя знаками после запятой.

```typescript
import { readFileSync } from "node:fs";

const text: string = readFileSync(0, "utf8");
const lines: string[] = text.trim().split("\n");

let total: number = 0;
for (const line of lines) {
  total = total + Number(line);
}
console.log("Итого: " + total.toFixed(2));
```

Ввод:

```text
10
20.5
30
```

Вывод:

```text
Итого: 60.50
```

`text` содержит `"10\n20.5\n30\n"`. `trim()` убирает завершающий перенос, `split("\n")` даёт `["10", "20.5", "30"]`, цикл превращает каждую строку в число и складывает. Если сложить сами строки без `Number`, получилась бы склейка. Метод `toFixed(2)` возвращает **строку** с двумя знаками после запятой: `60.5` превращается в `"60.50"`.

## Пример 2. Как ведёт себя разбиение

```typescript run
console.log("".trim().split("\n"));
console.log("a\nb\n".split("\n"));
console.log("a\nb\n".trim().split("\n"));
console.log("a\r\nb\r\n".trim().split("\n"));
console.log("  5 \r".trim() === "5");
```
```output
[ '' ]
[ 'a', 'b', '' ]
[ 'a', 'b' ]
[ 'a\r', 'b' ]
true
```

Пустая строка после `split` превращается не в пустой массив, а в массив из одной пустой строки. Завершающий перенос без `trim()` даёт лишний пустой элемент. В третьей строке видно, что после `trim()` лишнего элемента нет. Четвёртая показывает ловушку Windows: там строки заканчиваются парой символов `\r\n`, а `split("\n")` отрезает только `\n`, и в конце строки остаётся невидимый `\r`. Поэтому **каждую строку** тоже нужно очистить `trim()`: он убирает пробелы, переносы и `\r` по краям.

## Пример 3. Что даёт Number

```typescript run
console.log(Number("42"), Number("3.5"), Number("  7 "), Number("-12"));
console.log(Number(""), Number("   "));
console.log(Number("12px"), Number("3,5"), Number("abc"));
console.log(Number.isNaN(Number("abc")), Number.isNaN(Number("5")));
console.log((14.75 / 3).toFixed(2), (2).toFixed(2));
console.log("42" + 1, Number("42") + 1);
```
```output
42 3.5 7 -12
0 0
NaN NaN NaN
true false
4.92 2.00
421 43
```

`Number` понимает целые, дробные и отрицательные числа и сам убирает пробелы по краям. Строка с лишними символами (`"12px"`), запись с запятой (`"3,5"`) и слова превращаются в `NaN`. Пустая строка и строка из пробелов дают **0**, а не `NaN`, поэтому пустые строки нужно отсеивать **до** вызова `Number`: иначе они молча станут нулями. Проверка `Number.isNaN` отличает настоящие числа от неудач. Последняя строка показывает разницу между склейкой строки `"42" + 1` (получается `"421"`) и сложением чисел.

## Пример 4. Разбор с исключением

```typescript run
function parsePrice(line: string): number {
  const price: number = Number(line.trim());
  if (Number.isNaN(price)) {
    throw new Error("не число: " + line);
  }
  return price;
}

const text: string = "40\nabc\n 120 \n\n3,5\n";
let total: number = 0;
let skipped: number = 0;

for (const rawLine of text.trim().split("\n")) {
  if (rawLine.trim() === "") {
    continue;
  }
  try {
    total = total + parsePrice(rawLine);
  } catch (error) {
    skipped = skipped + 1;
  }
}

console.log("Итого: " + total.toFixed(2));
console.log("Пропущено: " + skipped);
```
```output
Итого: 160.00
Пропущено: 2
```

Это заготовка для настоящих программ: пустые строки пропускаются без подсчёта (`continue`), числа складываются, а строки, которые не удалось разобрать, считаются пропущенными. `parsePrice` выбрасывает ошибку для `"abc"` и `"3,5"` (десятичная запятая не поддерживается), а `try ... catch` в цикле не даёт одному плохому значению остановить программу. Здесь текст записан прямо в программе, чтобы пример можно было запустить; с настоящим вводом на его месте стоит `readFileSync(0, "utf8")`.

**Попробуйте.** Напишите программу, которая читает числа по одному в строке и печатает, сколько из них больше нуля. Нечисловые строки и пустые строки не считаются. Проверьте её на вводе из пустой строки и на вводе с Windows-переносами.

## Точные правила

* `import { readFileSync } from "node:fs";` стоит в начале файла. Без импорта имя неизвестно (`TS2304`); без установленных типов Node.js проверка сообщает `TS2591` (в приложении типы ставятся в настройках: «Среды выполнения»).
* `readFileSync(0, "utf8")` возвращает `string` со всем вводом сразу. Пустой ввод даёт `""`.
* `text.trim().split("\n")` - стандартный разбор на строки. Для пустого ввода получается массив из одной пустой строки.
* Каждую строку очищайте `line.trim()`: это убирает пробелы по краям и лишний `\r` из Windows-окончаний `\r\n`.
* Пустые и состоящие из пробелов строки обычно пропускают до разбора: `Number("")` равно 0.
* `Number(строка)` возвращает число или `NaN`. Допускаются целые, дробные (точка), отрицательные, экспонента (`"1e3"` даёт 1000) и шестнадцатеричная запись (`"0x10"` даёт 16).
* Десятичная запятая (`"3,5"`) и лишние символы (`"12px"`) дают `NaN`.
* `NaN` не равно ничему, в том числе себе: `value === NaN` всегда ложно (проверка типов сообщает `TS2845`). Для проверки есть `Number.isNaN(value)`.
* `Number.isNaN("abc")` вернёт `false`: он проверяет только значение `NaN`, и строку «abc» таковым не считает. Сначала преобразуйте строку: `Number.isNaN(Number("abc"))`.
* Результаты арифметики с `NaN` тоже `NaN`: одна непроверенная строка портит всю сумму.
* `x.toFixed(2)` возвращает строку с двумя знаками после запятой и округляет. Положить результат в переменную типа `number` нельзя.
* Деление на количество проверяйте: при нуле чисел среднее считать нельзя.
* Все числа в вашей программе - `number`: целые и дробные хранятся одинаково, поэтому проверка целого - `Math.floor(x) === x`.
* Вывод `console.log` добавляет перенос строки сам; числа печатаются в виде, который выбирает язык (`60.5`, а не `60.50`).

## Типичные ошибки

**1. Забыт импорт.**

```typescript
const text: string = readFileSync(0, "utf8");
console.log(text);
```

```text
main.ts(1,22): error TS2304: Cannot find name 'readFileSync'.
```

Имя `readFileSync` надо подключить строкой `import { readFileSync } from "node:fs";`.

**2. Тип результата перепутан с числом.**

```typescript
import { readFileSync } from "node:fs";
const n: number = readFileSync(0, "utf8");
```

```text
main.ts(2,7): error TS2322: Type 'string' is not assignable to type 'number'.
```

Ввод - всегда строка. Число получают явно: `Number(text.trim())`.

**3. Сравнение с `NaN`.**

```typescript
const value: number = Number("abc");
if (value === NaN) {
  console.log("не число");
}
```

```text
main.ts(2,5): error TS2845: This condition will always return 'false'.
```

Проверка типов сразу сообщает, что условие никогда не выполнится. Правильно: `Number.isNaN(value)`.

**4. Результат `toFixed` - строка.**

```typescript
const r: number = (3.14159).toFixed(2);
```

```text
main.ts(1,7): error TS2322: Type 'string' is not assignable to type 'number'.
```

`toFixed` годится для вывода, но не для дальнейших расчётов. Считайте на числах, а `toFixed` вызывайте в самом конце.

**5. Пустые строки стали нулями.** `Number("")` равно 0, и если не пропустить пустые строки заранее, они попадут в счёт как настоящие нули. Ошибки проверка не покажет: программа просто выдаст неверные итоги.

**6. Забыт `trim` у строки.** При вводе с Windows-окончаниями строка `"5\r"` без `trim()`: `Number("5\r")` случайно сработает, а сравнение `line === "5"` - нет. Всегда очищайте строку, прежде чем с ней работать.

**7. Среднее при отсутствии чисел.** `sum / count` при `count` равном 0 даёт `NaN` (для 0/0) и портит вывод. Проверяйте `if (count > 0)`.

**8. Импорт без установленных типов.** Если типы Node.js не установлены, проверка сообщает `TS2591: Cannot find name 'node:fs'. Do you need to install type definitions for node?`. Установите их в настройках приложения (раздел «Среды выполнения»).

## Итоги

* Ввод читается так: `import { readFileSync } from "node:fs";` и `readFileSync(0, "utf8")`; результат - одна строка.
* Разбор: `trim()` для всего текста, `split("\n")` на строки, `trim()` для каждой строки, пропуск пустых.
* `Number(строка)` даёт число или `NaN`; настоящую неудачу распознаёт `Number.isNaN`.
* Пустая строка превращается в 0, поэтому её отсеивают заранее.
* `toFixed(2)` форматирует число для вывода и возвращает строку.
* Исключения из прошлого урока удобны для плохих строк: цикл не останавливается, а счётчик пропущенных растёт.

## Для тех, кто уже программирует

* Ввод - это `string`: типы не проверяют данные извне. Если написать `JSON.parse(text) as Config`, проверки не будет (в курсе такого приёма нет специально).
* В Node.js нет «`input()` для строки»: читают весь поток (`readFileSync(0)`) либо строки по событиям (`readline`). Для упражнений удобнее первый способ.
* `Number("")` равно 0, `Number("0x10")` равно 16, `Number("1e3")` равно 1000: это прямое наследие JavaScript. Если нужны только десятичные целые, проверяйте строку (например, регулярным выражением) до преобразования.
* `parseInt("12px")` вернёт 12, а `Number("12px")` - `NaN`; в этом курсе выбран `Number`, потому что он строже.
* `NaN !== NaN` по стандарту IEEE 754; TypeScript даже ловит `x === NaN` (`TS2845`). `Number.isNaN` строже глобального `isNaN`, который сначала приводит аргумент к числу.
* `toFixed` округляет по двоичному представлению: `(1.005).toFixed(2)` даёт `"1.00"`, а не `"1.01"`. Для денег это известная ловушка; в курсе деньги считаются в простых случаях.
* `import ... from "node:fs"` - это модуль ECMAScript; в Node.js 22 он работает и для файлов `.ts` благодаря удалению типов (`--experimental-strip-types`). Типы самого модуля приходят из пакета `@types/node`.
* `\r\n` в конце строк - наследие Windows; `trim()` справляется, а `split("\r\n")` ломается на системах с `\n`. Универсальный путь - `split("\n")` и `trim()` для каждой строки.
