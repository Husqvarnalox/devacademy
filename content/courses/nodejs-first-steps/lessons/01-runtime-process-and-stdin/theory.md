## Node.js - это среда, в которой запускают JavaScript, а не отдельный язык

В курсе по JavaScript вы писали на языке. **Node.js** - это программа, которая умеет запустить этот язык вне браузера и даёт ему доступ к системе:
файлам, сети, процессам, переменным окружения, стандартным потокам ввода и вывода. Команда `node main.js` запускает процесс, внутри которого работают:

* **V8** - движок, выполняющий JavaScript (тот же, что в Chrome);
* **libuv** - библиотека, которая организует **цикл событий** и асинхронный ввод-вывод на разных операционных системах;
* **API Node.js** - модули `fs`, `path`, `http`, `stream`, `child_process` и глобальный объект `process`, написанные частично на JavaScript, частично на C++.

В браузере есть `window` и `document`, а в Node.js - `process` и `require`. Сам язык одинаков, а доступные объекты зависят от среды.

Объект `process` описывает ваш собственный процесс: аргументы командной строки (`process.argv`), переменные окружения (`process.env`),
потоки `process.stdin`, `process.stdout`, `process.stderr` и код завершения (`process.exitCode`).

## Процесс, потоки и цикл событий

**Аргументы.** `process.argv` - массив строк. Элемент `[0]` - путь к исполняемому файлу `node`, `[1]` - путь к вашему скрипту, пользовательские аргументы идут с `[2]`.
Значит, `process.argv.slice(2)` - то, что передали программе. Все элементы - строки; числа нужно преобразовывать самим.

**Потоки stdin/stdout/stderr.** В Node.js это объекты-потоки (streams). `process.stdout.write(text)` пишет текст как есть, без перевода строки;
`console.log` добавляет его и форматирует аргументы. `console.error` пишет в `stderr`. Автоматическая проверка читает только stdout.

**stdin - читаемый поток.** Данные приходят *порциями* (chunk). Если ввод большой, одна порция - не весь ввод. Поэтому «весь ввод» нужно собрать:

```javascript
async function readAll() {
  process.stdin.setEncoding("utf8");
  let text = "";
  for await (const chunk of process.stdin) text += chunk;
  return text;
}
```

`for await` берёт порции по мере их прихода и завершается, когда ввод закончился. Вызов `setEncoding("utf8")` важен: без него порции - `Buffer` (байты),
и если соединять их по одной, многобайтовый символ (например, русская буква, занимающая 2 байта в UTF-8) может оказаться разрезан на границе порций и испортиться. С `setEncoding` поток сам аккуратно склеивает байты в символы.

**Цикл событий.** JavaScript-код в Node.js выполняется в одном потоке. Пока вы ждёте ввод, программа не «зависает»: вы отдаёте операцию системе и регистрируете продолжение, а цикл событий вызывает его, когда данные готовы.
Поэтому пишут `await` и колбэки, а не блокирующие вызовы. Долгое вычисление в этом же потоке блокирует всё остальное, включая обработку ввода.
Часть работы (файловая система, DNS, сжатие, криптография) libuv выполняет в пуле потоков, но ваш JavaScript-код от этого остаётся однопоточным.

**Завершение.** Процесс завершается сам, когда в цикле событий не осталось ожидаемой работы: открытых потоков, таймеров, сокетов. Код выхода по умолчанию - `0`;
ошибку обозначают `process.exitCode = 1`. Вызов `process.exit()` завершает процесс немедленно и может оборвать ещё не записанный вывод, поэтому предпочитают задавать `exitCode` и дать программе дойти до конца.
Необработанное исключение завершает процесс с ненулевым кодом, а текст ошибки уходит в stderr.

**Версии и API.** Состав API зависит от версии Node.js: смотрите `process.version` и документацию нужной версии. Встроенные модули подключают с префиксом `node:` (`require("node:fs")`) - так видно, что это встроенный модуль, а не пакет из `node_modules`.

## Примеры

**Пример 1. Среда решает, какие объекты есть.**

```javascript run
console.log(typeof process, typeof window, typeof document);
console.log(typeof require, typeof setTimeout, typeof fetch);
```
```output
object undefined undefined
function function function
```

`window` и `document` относятся к браузеру и в Node.js не существуют; `typeof` для необъявленного имени безопасно возвращает `"undefined"`.

**Пример 2. Аргументы командной строки.**

```javascript run
console.log(process.argv.length);
console.log(process.argv.slice(2));
console.log(typeof process.versions.v8, typeof process.versions.uv);
```
```output
2
[]
string string
```

Запуск `node main.js` без параметров даёт в `argv` ровно два элемента: путь к `node` и путь к скрипту. В `process.versions` перечислены версии компонентов, в том числе V8 (`v8`) и libuv (`uv`).

**Пример 3. `write` и `console.log`.**

```javascript run
process.stdout.write("a");
process.stdout.write("b\n");
console.log("c", 1, { x: 2 });
console.error("не в stdout");
```
```output
ab
c 1 { x: 2 }
```

`write` ничего не добавляет, `console.log` ставит пробелы между аргументами и печатает объект в читаемом виде. Строка из `console.error` в stdout не попала.

**Пример 4. Колбэк вызывается позже.**

```javascript run
setTimeout(() => console.log("позже"), 0);
console.log("сначала");
```
```output
сначала
позже
```

Даже при задержке `0` колбэк таймера выполнится только после того, как текущий синхронный код закончится: цикл событий обрабатывает его на следующем шаге.

**Пример 5. Чтение всего stdin.**

```javascript
async function main() {
  process.stdin.setEncoding("utf8");
  let text = "";
  for await (const chunk of process.stdin) text += chunk;
  const words = text.split(/\s+/).filter(Boolean);
  console.log(words.length);
}
main();
```

## Типичные ошибки

* **Читать только первую порцию ввода.** Обработчик `data` вызывается много раз; результат нельзя считать, пока не пришло `end`. В конструкции `for await` код после цикла - как раз момент «ввод закончился».
* **Не задать кодировку.** Без `setEncoding("utf8")` порции - `Buffer`; `text += chunk` вызывает `toString()` для каждой порции отдельно и может испортить символ на стыке порций.
* **Вызвать `process.exit()` сразу после записи.** Вывод в канал может быть ещё не дописан. Лучше задать `process.exitCode` и дать циклу событий завершиться.
* **Ждать результат, не дождавшись `await`.** `const text = readAll();` вернёт промис, а не строку, и `text.split` упадёт с `TypeError`.
* **Забыть, что `process.argv` начинается с двух служебных элементов.** Пользовательские аргументы - с индекса 2.
* **Блокировать цикл событий.** Длинный синхронный цикл не даёт обработать ни ввод, ни таймеры. Такой код нужно разбивать или выносить в отдельный поток (`worker_threads`).
* **Путать `split(/\s+/)` с подсчётом слов.** Для пустого текста и ведущих пробелов появляются пустые элементы; уберите их через `.filter(Boolean)`.
* **Считать, что `lines` равно числу строк «по ощущениям».** Последняя строка без завершающего `\n` не добавляет перевода строки, и `wc -l` её не считает.

<!-- section: summary -->
## Итоги

* Node.js - среда выполнения: V8 исполняет JavaScript, libuv даёт цикл событий и асинхронный ввод-вывод, а API Node.js открывает доступ к системе.
* `process` описывает процесс: `argv` (пользовательские аргументы с индекса 2), `env`, потоки, код завершения.
* stdin - поток порций; весь ввод собирают через `for await`, предварительно вызвав `setEncoding("utf8")`.
* Ваш JavaScript-код работает в одном потоке; ожидание ввода-вывода не блокирует его благодаря циклу событий.
* Код выхода задавайте через `process.exitCode`, а не через резкий `process.exit()`.
