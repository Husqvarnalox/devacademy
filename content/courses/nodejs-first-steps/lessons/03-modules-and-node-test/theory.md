## Зачем делить код на модули и проверять его тестами

Когда программа вырастает за пределы одного файла, её делят на **модули**: каждый файл отвечает за свою часть. В Node.js с ES-модулями это выглядит так:

```javascript
// src/money.mjs
export function formatPrice(cents) {
  return `${Math.floor(cents / 100)}.${String(cents % 100).padStart(2, "0")}`;
}

// src/cart.mjs
import { formatPrice } from "./money.mjs";
export const label = (cents) => `К оплате: ${formatPrice(cents)}`;
```

Модуль открывает наружу только то, что помечено `export`. Всё остальное остаётся его внутренним делом, и менять это внутреннее можно, не ломая остальной код.

Но как убедиться, что после очередной правки всё продолжает работать? Перечитывать код глазами ненадёжно. Нужны **автоматические тесты**: маленькие программы, которые вызывают ваши функции с известными входами и сравнивают результат с ожидаемым. В Node.js для этого есть встроенный раннер `node:test`, ничего устанавливать не нужно.

## Точные правила: импорт, node:test и проверки

**Импорт в ESM.**

* Относительный путь пишется с расширением: `"./money.mjs"`, а не `"./money"`. Node.js не угадывает расширение и не ищет `index.js` сам.
* Расширение `.mjs` заставляет Node.js читать файл как ES-модуль, даже если рядом нет `package.json`.
* Импортируемые имена - **живые связи** с экспортом, а модуль выполняется один раз и кешируется.

**Структура теста.**

* `describe(название, () => {...})` - группа; `it(название, () => {...})` - один случай.
* Проверки берут из `node:assert/strict`: `assert.equal(a, b)` (строгое равенство), `assert.deepEqual(массив1, массив2)` (сравнение содержимого), `assert.throws(() => f(), RangeError)` (функция должна бросить исключение указанного типа).
* Тест падает, если внутри бросилось исключение. `assert.*` как раз бросают его при расхождении.

**Запуск.** `node --test "tests/*.test.mjs"` запускает каждый файл в отдельном процессе и печатает отчёт. Код возврата ненулевой, если хоть один тест упал. Шаблон с `*` в кавычках раскрывает сам Node.js, а не оболочка, поэтому команда ведёт себя одинаково на всех системах.

**Два вида неудач.**

1. *Упала проверка* - модуль загрузился, но результат не тот. В отчёте видно ожидаемое и фактическое значения.
2. *Не загрузился модуль* - синтаксическая ошибка или неверный путь импорта. Тесты этого файла вообще не запускаются, поэтому в проверке они считаются невыполненными.

**Деньги в копейках.** Дробные числа двоичны, и `0.1 + 0.2` равно `0.30000000000000004`. Поэтому суммы хранят целыми числами копеек, а в строку превращают только при выводе.

## Примеры

**Пример 1. Тест на значения и на ошибку.**

```javascript
import { describe, it } from "node:test";
import assert from "node:assert/strict";

const half = (n) => {
  if (!Number.isInteger(n)) throw new TypeError("нужно целое");
  return n / 2;
};

describe("half", () => {
  it("делит чётное", () => assert.equal(half(10), 5));
  it("отвергает дробь", () => assert.throws(() => half(1.5), TypeError));
});
```

Два случая: нормальный вход и ошибочный. Хороший набор тестов всегда содержит оба вида.

**Пример 2. Таблица случаев в цикле.**

```javascript
import { it } from "node:test";
import assert from "node:assert/strict";

const cases = [[1, "1.00"], [250, "2.50"], [7, "0.07"]];
for (const [input, want] of cases) {
  it(`format ${input}`, () => {
    const got = `${Math.floor(input / 100)}.${String(input % 100).padStart(2, "0")}`;
    assert.equal(got, want);
  });
}
```

Когда случаев много, их выносят в массив и создают по `it` на каждый. Название теста включает вход, и по отчёту сразу видно, какой случай упал.

**Пример 3. Разбор цены регулярным выражением.**

```javascript
const m = /^(\d+)(?:\.(\d{1,2}))?$/.exec("12.5");
console.log(m[1], m[2]);
```

```output
12 5
```

Группа 1 - рубли, группа 2 - необязательные копейки. Если строка не подходит, `exec` вернёт `null`, и это место надо обработать, а не обращаться к `m[1]`.

## Типичные ошибки

* **Нет расширения в import.** `import ... from "./money"` падает с `ERR_MODULE_NOT_FOUND`. Пишите `"./money.mjs"`.
* **Использование `require` в `.mjs`.** В ES-модуле его нет; применяйте `import`.
* **Передача результата вместо функции в `assert.throws`.** `assert.throws(f(-1), ...)` вызывает `f` до проверки, и исключение улетает мимо. Нужна стрелка: `() => f(-1)`.
* **Сравнение массивов через `equal`.** Два одинаковых по содержимому массива не равны по ссылке; используйте `deepEqual`.
* **Копейки как дробь.** `"12.5"` - это 12 рублей 50 копеек. Если сделать `Number("12.5") * 100`, получаются неточные значения вроде `1249.9999999999998` в других случаях. Разбирайте строку по частям.
* **Правка тестов вместо кода.** Тест фиксирует требование; если он упал, сначала ищите ошибку в модуле.

<!-- section: summary -->
## Итоги

* Модуль экспортирует нужное через `export`, а потребитель подключает его через `import` с полным путём и расширением.
* `node --test` запускает файлы тестов и сообщает, какие проверки прошли.
* В тестах проверяют и обычные входы, и граничные, и ошибки.
* Для денег используют целые копейки, а форматируют в строку только на выходе.
* Если модуль не загрузился, тесты из него не выполняются: сначала исправьте синтаксис и пути.
