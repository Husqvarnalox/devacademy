## Что проверяет эта проверка

Исключения (`try / except / else / finally`, `raise`, иерархия), чтение и запись файлов через `with open`, кодировки, а также импорт модулей: `import`, `from ... import ... as`, стандартные `os`, `math`, `random`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Исключения и работа с файлами](lesson:python.fundamentals.errors-and-files), [Модули и import](lesson:python.fundamentals.modules).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

## Пример того, что понадобится

```python run
def to_number(text):
    try:
        return float(text)
    except ValueError:
        return None

print([to_number(t) for t in ["3", "x", "1e2"]])
```
```output
[3.0, None, 100.0]
```

Функция преобразует строку и при ошибке `ValueError` возвращает `None`. `1e2` - допустимая запись числа, поэтому получается `100.0`.

<!-- section: precise -->
## Что нужно уметь

* перехватывать конкретные исключения и знать порядок веток `except`;
* понимать, когда выполняются `else` и `finally`;
* вызывать исключения через `raise` и сохранять причину через `from`;
* открывать файлы через `with` с явной кодировкой и итерироваться по строкам;
* импортировать модули разными способами и знать, что тело модуля выполняется при импорте.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Общий `except:` скрывает посторонние ошибки.
* Ветка для общего типа выше ветки для частного делает частную недостижимой.
* `open` без `with` и без `encoding` ненадёжен.
* Нумерация строк для сообщений об ошибках начинается с единицы и учитывает пустые строки.
