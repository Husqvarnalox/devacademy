## Что проверяет эта проверка

Объединённые типы (`string | number`), сужение с помощью `typeof`, проверок на `null` и `undefined`, `in` и `instanceof`, размеченные объединения (поле `kind` как метка) и исчерпывающий `switch`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок: [Объединения и сужение типов](lesson:typescript.fundamentals.unions-and-narrowing).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет этот урок как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```typescript run
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; side: number };

function size(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.round(Math.PI * shape.radius ** 2);
    case "square":
      return shape.side ** 2;
  }
}

function label(value: string | number | null): string {
  if (value === null) {
    return "пусто";
  }
  if (typeof value === "number") {
    return value.toFixed(1);
  }
  return value.toUpperCase();
}

console.log(size({ kind: "circle", radius: 2 }), size({ kind: "square", side: 3 }));
console.log(label(null), label(2), label("ok"));
```
```output
13 9
пусто 2.0 OK
```

В `size` поле `kind` служит меткой: внутри `case "circle"` компилятор знает, что у `shape` есть `radius`. Если добавить в `Shape` новый вариант и не обработать его, функция перестанет быть исчерпывающей, и `tsc` сообщит, что результат может оказаться `undefined`. В `label` каждая проверка сужает тип: после `null` остаётся `string | number`, после `typeof` - `string`.

<!-- section: precise -->
## Что нужно уметь

* читать и составлять тип-объединение и понимать, что общими для всех вариантов остаются только их общие члены;
* сужать тип через `typeof`, `=== null`, `=== undefined`, `in` и `instanceof` и видеть, какой тип остаётся в каждой ветке;
* описывать размеченное объединение и обрабатывать все его варианты в `switch`;
* знать, что сужение работает только для `const`, параметров и свойств без промежуточных присваиваний, а в замыканиях может сбрасываться;
* читать сообщения `TS2339`, `TS2322` и `TS2366`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Вызывают метод, которого нет у одного из вариантов: `value.toUpperCase()` для `string | number` даёт `TS2339`.
* Проверяют `typeof x === "object"` и забывают, что `null` тоже объект.
* Проверяют `if (x)` для `number | undefined` и теряют значение `0`.
* Забывают ветку для нового варианта: без `default` и без `never`-проверки компилятор может промолчать, если функция не требует результата.
* Ожидают, что тип сохранится после `await` или внутри колбэка: переменная могла измениться.
