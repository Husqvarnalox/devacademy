## Что проверяет эта проверка

Границы, на которых данные попадают в программу снаружи (ввод, `JSON.parse`, ответы сервера), и средства безопасной работы с ними: тип `unknown`, пользовательские предикаты `v is T`, проверка формы данных вручную, `catch (e)` как `unknown` и тип `never` для исчерпывающих проверок.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок: [unknown, never и границы данных](lesson:typescript.fundamentals.unknown-and-boundaries).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет этот урок как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```typescript run
function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}

function readTitle(text: string): string {
  try {
    const data: unknown = JSON.parse(text);
    if (isRecord(data) && typeof data.title === "string") {
      return data.title;
    }
    return "без названия";
  } catch (e) {
    return e instanceof Error ? "ошибка разбора" : "что-то другое";
  }
}

console.log(readTitle('{"title": "Отчёт"}'));
console.log(readTitle('{"title": 7}'));
console.log(readTitle("{"));
```
```output
Отчёт
без названия
ошибка разбора
```

`JSON.parse` возвращает `any`, поэтому результат сразу кладут в переменную типа `unknown`: компилятор потребует проверить его, прежде чем читать поля. Предикат `isRecord` сообщает компилятору, что в ветке `if` значение - объект со строковыми ключами. Переменная `e` в `catch` тоже имеет тип `unknown`, а проверка `instanceof Error` сужает её до `Error`.

<!-- section: precise -->
## Что нужно уметь

* объяснять разницу между `any` (проверки отключены) и `unknown` (читать можно только после проверки);
* писать функцию-предикат `value is T` и понимать, что компилятор верит ей без проверки: ошибка в теле предиката даёт ложную уверенность;
* проверять форму данных вручную: тип значения, наличие поля, диапазон, целое число; отдельно отделять синтаксическую ошибку JSON от неверной формы;
* использовать `never` для проверки того, что обработаны все варианты объединения;
* читать сообщения `TS18046` и `TS2322` для `never`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Приводят результат разбора через `as User`: проверки не происходит, и неверные данные проходят дальше.
* Забывают, что `typeof null === "object"` и массив тоже объект: предикат `isRecord` должен исключать оба случая.
* Пишут в `catch` `e.message` и ожидают, что исключение всегда `Error`: бросить можно любое значение.
* Принимают `NaN` и `Infinity` за число: `typeof NaN === "number"`, нужна проверка `Number.isFinite`.
* Проверяют только форму и забывают смысл (отрицательный возраст, пустое имя).
