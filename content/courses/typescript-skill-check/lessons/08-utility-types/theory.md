## Что проверяет эта проверка

Готовые утилитарные типы `Partial`, `Required`, `Readonly`, `Pick`, `Omit`, `Record`, `ReturnType`, их ограничения (поверхностность, отсутствие проверки ключей у `Omit`) и то, как они проявляются в обычном коде: частичное обновление объекта, выбор и исключение полей, словари.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок: [Утилитарные, отображаемые и условные типы](lesson:typescript.fundamentals.utility-types).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет этот урок как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```typescript run
interface Task {
  id: number;
  title: string;
  done: boolean;
}

function rename(task: Readonly<Task>, patch: Partial<Task>): Task {
  return { ...task, ...patch };
}

function summary(task: Pick<Task, "id" | "title">): string {
  return "#" + task.id + " " + task.title;
}

const original: Task = { id: 1, title: "Купить хлеб", done: false };
const updated = rename(original, { title: "Купить батон", done: true });
console.log(updated, original.title);
console.log(summary(updated));
const labels: Record<"low" | "high", string> = { low: "обычная", high: "срочная" };
console.log(labels.high);
```
```output
{ id: 1, title: 'Купить батон', done: true } Купить хлеб
#1 Купить батон
срочная
```

`Readonly<Task>` запрещает менять поля у параметра `task`, `Partial<Task>` делает все поля необязательными, `Pick` выбирает часть полей, `Record` задаёт объект с заранее известным набором ключей. Все эти типы существуют только при проверке: во время работы остаются обычные объекты.

<!-- section: precise -->
## Что нужно уметь

* выбирать нужный утилитарный тип и читать результат: какие поля остались, какие стали необязательными или `readonly`;
* знать, что `Partial` и `Readonly` поверхностные и не затрагивают вложенные объекты, а `readonly` не защищает объект во время работы;
* знать, что `Pick` требует существующие ключи, а `Omit` их не проверяет;
* помнить, что spread с `undefined` в патче перезаписывает значение;
* читать сообщения `TS2741`, `TS2540` и `TS2344`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Ожидают, что `Partial<Config>` сделает необязательными и вложенные поля: вложенный объект придётся задать целиком.
* Считают `Readonly` защитой от записи: он не работает после приведения типа и не влияет на выполнение (для защиты нужен `Object.freeze`).
* Опечатка в `Omit<User, "pasword">` проходит молча, а поле остаётся в типе.
* Объединяют объект и патч через `{ ...base, ...patch }` и получают `undefined`, если патч содержит ключ со значением `undefined`.
* Используют обычный объект как словарь с произвольными ключами: ключ `constructor` встречается в нём «сам по себе».
