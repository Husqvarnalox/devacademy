## Что проверяет эта проверка

Обобщённые функции и классы: параметр типа `<T>`, вывод `T` по аргументам, ограничения `extends`, связь ключей и значений через `keyof`, обобщённые контейнеры и то, что обобщения существуют только на этапе проверки типов.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок: [Обобщения](lesson:typescript.fundamentals.generics).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет этот урок как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

## Пример того, что понадобится

```typescript run
function last<T>(items: readonly T[]): T | undefined {
  return items[items.length - 1];
}

function field<T, K extends keyof T>(item: T, key: K): T[K] {
  return item[key];
}

class Queue<T> {
  #items: T[] = [];
  push(item: T): void {
    this.#items.push(item);
  }
  shift(): T | undefined {
    return this.#items.shift();
  }
}

console.log(last([1, 2, 3]), last(["a"]), last([]));
console.log(field({ title: "Отчёт", pages: 12 }, "pages"));
const queue = new Queue<string>();
queue.push("первый");
queue.push("второй");
console.log(queue.shift(), queue.shift(), queue.shift());
```
```output
3 a undefined
12
первый второй undefined
```

В `last([1, 2, 3])` компилятор сам выводит `T = number`, поэтому результат имеет тип `number | undefined`. Ограничение `K extends keyof T` разрешает передавать в `field` только имена существующих полей, а результат `T[K]` получает тип именно этого поля. Класс `Queue<string>` хранит строки: `queue.push(5)` была бы ошибкой.

<!-- section: precise -->
## Что нужно уметь

* писать функцию и класс с параметром типа и объяснять, какое значение `T` выведено в конкретном вызове;
* ограничивать параметр: `T extends { length: number }`, `K extends keyof T`;
* понимать, что `T` не существует во время работы: нельзя написать `new T()` или `typeof T`, а `make<number>()` не создаёт число;
* использовать готовые обобщённые типы: `Array<T>`, `Map<K, V>`, `Set<T>`, `Promise<T>`;
* читать сообщения `TS2322`, `TS2345` и `TS2536`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Пишут `T` там, где параметр типа не нужен: если тип встречается в сигнатуре один раз, обобщение ничего не связывает.
* Применяют `as T` для создания значения: компилятор молчит, но во время работы значения нужного типа нет.
* Ожидают, что `T` можно проверить: `if (x instanceof T)` невозможно, типов во время работы нет.
* Забывают ограничение и обращаются к полям: `item.length` для неограниченного `T` даёт ошибку.
* Путают порядок явных аргументов типа: `new Map<number, string>()` и `new Map<string, number>()` - разные типы.
