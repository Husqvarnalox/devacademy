## Что проверяет эта проверка

Что проверяет `tsc`, а что выполняет Node.js и почему типы стираются; вывод типов и расширение литералов (`const` и `let`, поля объектов); структурная совместимость, проверка лишних свойств у объектных литералов и необязательные свойства.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Как выполняется TypeScript: tsc, стирание типов, stdin](lesson:typescript.first-steps.how-typescript-runs), [Структурные типы, сужение и unknown против any](lesson:typescript.first-steps.structural-typing-and-narrowing), [Аннотации, вывод типов и структурная типизация](lesson:typescript.fundamentals.inference-and-structure).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```typescript run
interface Named {
  name: string;
}
class Dog {
  name = "Рекс";
  age = 3;
}
function hello(who: Named): string {
  return "Привет, " + who.name;
}
const mixed = { name: "Аня", admin: true };
console.log(hello(new Dog()), hello(mixed));

const fixed = "read";
let loose = "read";
const config = { mode: "fast" };
config.mode = "slow";
console.log(fixed, loose, config.mode);
```
```output
Привет, Рекс Привет, Аня
read read slow
```

Функция `hello` принимает любой объект с полем `name` типа `string`: экземпляр класса `Dog` и объект `mixed` подходят по форме. Для `const fixed = "read"` выводится литеральный тип `"read"`, для `let loose` и для поля `config.mode` - широкий `string`, поэтому поле можно изменить. Лишнее поле отвергается только у литерала, записанного прямо в вызове: `hello({ name: "Аня", admin: true })` даёт ошибку `TS2353`.

<!-- section: precise -->
## Что нужно уметь

* объяснять, что `tsc --strict` только проверяет, а выполняет код Node.js без типов, поэтому ошибка типов не меняет поведения, а данные снаружи типом не проверены;
* предсказывать выведенный тип: литерал для `const`, широкий тип для `let` и полей объекта, `T | undefined` для результата `find`;
* решать, где нужна аннотация (параметры, результаты функций, пустые коллекции), а где вывод достаточен;
* применять структурную совместимость и знать, что проверка лишних свойств касается только свежих литералов;
* читать сообщения `TS2322`, `TS2353`, `TS2741` и `TS18048`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Считают, что тип защищает во время работы. `as` и `any` отключают проверку, а `JSON.parse` возвращает `any`.
* Ожидают, что поле объекта получит литеральный тип: `{ mode: "fast" }` выводится как `{ mode: string }`.
* Ожидают ошибку на лишнем свойстве у переменной: проверка работает только для литерала на месте.
* Пишут `if (item.price)` для необязательного поля и теряют допустимое значение `0`.
* Забывают, что результат `find` и `at` включает `undefined`.
