## Null-безопасность: ошибка находится компилятором

В Java любая ссылка может оказаться `null`, и обращение к ней даёт `NullPointerException` во время работы. В Kotlin **тип сам говорит, допустим ли `null`**:

* `String` - значение есть всегда; присвоить `null` нельзя, компилятор не даст;
* `String?` - значение может быть `null`.

Чтобы использовать значение `String?`, нужно сначала разобраться с `null`:

* `s?.length` - безопасный вызов: если `s` равно `null`, всё выражение равно `null`, а не падает;
* `s ?: "по умолчанию"` - оператор Элвиса: берёт левую часть, а если она `null`, то правую;
* `s!!` - «я уверен, что не `null`»: если это не так, будет исключение;
* `if (s != null) { ... }` - внутри блока `s` уже имеет тип `String` (smart cast).

```kotlin
fun main() {
    val s: String? = null
    println(s?.length)        // null
    println(s?.length ?: -1)  // -1
}
```

## Подробнее

**Типы.** `T?` - это `T` плюс `null`. Тип `String` является подтипом `String?`, но не наоборот: передать `String?` туда, где ждут `String`, нельзя. Поэтому проверка `null` происходит при компиляции, а не при запуске.

**Безопасный вызов.** `a?.b` вычисляется как «если `a` не `null`, то `a.b`, иначе `null`». Цепочка `a?.b?.c` прерывается на первом `null`. Тип результата всегда допускает `null`, даже если `b` его не допускает.

**Оператор Элвиса.** `x ?: y` возвращает `x`, если он не `null`, иначе вычисляет `y`. Справа можно написать `return` или `throw`: `val name = map["k"] ?: return`. Это распространённый способ «выйти раньше».

**`!!`.** Оператор приводит `T?` к `T` и бросает `NullPointerException` при `null`. Он обходит защиту типов, поэтому его используют редко; чаще заменяют на `?:` или проверку.

**Smart cast.** После `if (s != null)` компилятор считает `s` типа `String`, если уверен, что значение не изменится между проверкой и использованием (например, `val` или локальный `var`, который не меняют в замыканиях). Поле класса, объявленное как изменяемое `var`, smart cast не получает: другой поток мог его поменять.

**Преобразования с возможной ошибкой.** `"12".toIntOrNull()` возвращает `12`, а `"abc".toIntOrNull()` - `null`, не бросая исключений. Сочетание `toIntOrNull() ?: 0` - типичный способ получить значение по умолчанию. Аналогично `toLongOrNull`, `toDoubleOrNull`. `map[key]` у `Map<K, V>` возвращает `V?`, потому что ключа может не быть.

**Платформенные типы.** Значения, пришедшие из Java-кода, имеют тип вида `String!`: компилятор не знает, допустим ли `null`, и не требует проверок. Если Java вернёт `null`, а вы используете значение как `String`, исключение появится при выполнении. Это граница, где защита Kotlin заканчивается.

**`val` и `var` и null.** Для `val s: String?` smart cast работает после проверки; `lateinit var` откладывает инициализацию, но обращение до неё бросает исключение. Это отдельная тема.

**Где всё же бывает NPE.** Кроме `!!`, источники: Java-код, явный `throw NullPointerException()` и несогласованная инициализация (обращение к свойству до его установки в конструкторе).

<!-- section: examples -->
## Примеры

Блоки ниже показывают вывод в комментариях.

**Пример 1. Безопасный вызов и Элвис.**

```kotlin
fun main() {
    val a: String? = "kotlin"
    val b: String? = null
    println(a?.uppercase())          // KOTLIN
    println(b?.uppercase())          // null
    println(b?.uppercase() ?: "нет") // нет
}
```

**Пример 2. Smart cast.**

```kotlin
fun describe(s: String?): String {
    if (s == null) return "пусто"
    return "длина ${s.length}"   // здесь s - String
}

fun main() {
    println(describe(null))   // пусто
    println(describe("abc"))  // длина 3
}
```

**Пример 3. `toIntOrNull` и значение по умолчанию.**

```kotlin
fun main() {
    println("12".toIntOrNull())        // 12
    println("abc".toIntOrNull())       // null
    println("abc".toIntOrNull() ?: 0)  // 0
}
```

**Пример 4. Map возвращает nullable.**

```kotlin
fun main() {
    val ages = mapOf("ann" to 30, "bob" to 25)
    println(ages["ann"])         // 30
    println(ages["zed"])         // null
    println(ages["zed"] ?: -1)   // -1
}
```

**Пример 5. `!!` падает.**

```kotlin
fun main() {
    val x: String? = null
    try {
        println(x!!.length)
    } catch (e: NullPointerException) {
        println("NPE")           // NPE
    }
}
```

<!-- section: mistakes -->
## Типичные ошибки

* **Ставить `!!` «чтобы скомпилировалось».** Ошибка уходит из компиляции в выполнение. Лучше `?:`, `?.` или явная проверка.
* **Забыть, что `a?.b` возвращает nullable.** Результат нельзя использовать как `Int`, пока не обработан `null`.
* **Ожидать smart cast для изменяемого поля.** Скопируйте значение в локальный `val` и проверяйте его.
* **Считать `map[key]` ненулевым.** Ключа может не быть.
* **Путать `?:` с тернарным оператором.** `x ?: y` подставляет `y` только при `null`; пустая строка и ноль - не `null`.
* **Полагаться на защиту для значений из Java.** Платформенные типы не проверяются компилятором.
* **Использовать `toInt()` на сомнительном вводе.** При нечисловой строке будет исключение; `toIntOrNull()` безопаснее.

<!-- section: summary -->
## Итоги

* `T` не допускает `null`, `T?` допускает; компилятор требует разобраться с `null` до использования.
* `?.` прерывает цепочку на `null`, `?:` задаёт значение по умолчанию (или выход), `!!` обходит защиту и бросает NPE.
* Smart cast работает после проверки для стабильных значений.
* `toIntOrNull()` и `map[key]` естественно возвращают nullable-типы.
