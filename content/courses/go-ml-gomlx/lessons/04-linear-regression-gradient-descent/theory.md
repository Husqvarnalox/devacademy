## Линейная регрессия и градиентный спуск

Задача знакома по урокам [«Линейная регрессия» из основ ML](lesson:ml.foundations.linear-regression) (там градиентный спуск написан на чистом Python) и [«Линейная регрессия на NumPy»](lesson:ml.numpy.linear-regression) (там то же решено векторно, плюс решение по формуле). Теперь вы реализуете её третий раз, на GoMLX, и главное отличие состоит в том, что **производные не выводятся вручную**: их строит `graph.Gradient`.

Модель: `y ≈ w * x + b`. Параметры `w` (наклон) и `b` (сдвиг) подбираются так, чтобы **среднеквадратичная ошибка** `MSE = mean((w x + b - y)^2)` была минимальной. Метод - градиентный спуск: повторять

```text
w ← w - lr * dMSE/dw
b ← b - lr * dMSE/db
```

где `lr` - **скорость обучения**. Один проход по всем данным с одним обновлением называется эпохой (здесь данные маленькие, поэтому используются целиком: «полный пакет»).

Вся эпоха записывается в граф **одной функцией**: на входе текущие `w`, `b` и данные, на выходе новые `w`, `b` и значение потери. Go-цикл вызывает её снова и снова, подставляя результат в качестве нового входа. Так устроено обучение в любой библиотеке этого класса, просто здесь цикл виден целиком.

Выбор `lr` критичен: слишком малый - обучение еле ползёт, слишком большой - ошибка не убывает, а **растёт**, и параметры расходятся.

## Точные правила

**Потеря и градиент.** Для данных `(x_i, y_i)`, `i = 1..n`, и `pred_i = w x_i + b`:

```text
MSE   = (1/n) Σ (pred_i - y_i)^2
dw    = (2/n) Σ (pred_i - y_i) x_i
db    = (2/n) Σ (pred_i - y_i)
```

В GoMLX эти формулы не пишутся: достаточно построить `loss` и вызвать `graph.Gradient(loss, w, b)`. Формулы нужны для проверки.

**Один шаг на бумаге.** Данные из примера: `x = 0..4`, `y = 2x + 1`, начало `w = b = 0`, `lr = 0.05`. Предсказания равны нулю, ошибки равны `-y = -1, -3, -5, -7, -9`, потеря равна `mean(y^2) = 33`. Тогда `dw = 2 * mean(-y x) = 2 * (-14) = -28`, `db = 2 * mean(-y) = -10`. После шага `w = 0 + 0.05 * 28 = 1.4`, `b = 0.5`. Именно эти числа печатает первый пример.

**Форма данных.** `x` и `y` - векторы `[n]`, `w` и `b` - скаляры. Операция `Mul(xs, w)` расширяет скаляр по вектору, `Add(.., b)` тоже. Формы не требуют ручного преобразования, потому что скаляр совместим с любым тензором.

**Скорость обучения и устойчивость.** Для квадратичной потери спуск сходится только при достаточно малом `lr`: если шаг превышает значение, определяемое кривизной потери (для полного пакета - наибольшее собственное значение гессиана), потеря начинает расти. На этих данных граница лежит между `0.05` и `0.3`: `lr = 0.3` расходится, как показывает второй пример.

**Масштаб признаков.** Чем сильнее различаются масштабы входов, тем меньше допустимый общий `lr` и тем медленнее сходимость по «пологим» направлениям. Стандартизация признаков (см. предыдущий урок) помогает.

**Замкнутая форма как эталон.** Для одной переменной `w = cov(x, y) / var(x)`, `b = mean(y) - w mean(x)`. В упражнении она вычисляется обычным Go в `float64` и служит ответом, к которому должен прийти спуск. Совпадение двух способов - самая надёжная проверка.

**Критерий остановки.** В упражнении число эпох задаётся вручную. В реальных задачах следят за потерей и останавливаются, когда она перестаёт заметно убывать.

**Тип `float32`.** Потеря на последних эпохах может оставаться порядка `1e-6`, а не нулём: это нормальная точность `float32`.

## Примеры

**Пример 1. Обучение на прямой `y = 2x + 1`.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
	"github.com/gomlx/gomlx/core/tensors"
)

func step(w, b, xs, ys, lr *graph.Node) []*graph.Node {
	pred := graph.Add(graph.Mul(xs, w), b)
	loss := graph.ReduceAllMean(graph.Square(graph.Sub(pred, ys)))
	grads := graph.Gradient(loss, w, b)
	return []*graph.Node{
		graph.Sub(w, graph.Mul(lr, grads[0])),
		graph.Sub(b, graph.Mul(lr, grads[1])),
		loss,
	}
}

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	train := graph.MustNewExec(backend, step)
	x := tensors.FromValue([]float32{0, 1, 2, 3, 4})
	y := tensors.FromValue([]float32{1, 3, 5, 7, 9}) // y = 2x + 1
	lr := tensors.FromValue(float32(0.05))
	w, b := tensors.FromValue(float32(0)), tensors.FromValue(float32(0))
	for epoch := 1; epoch <= 200; epoch++ {
		out := train.MustExec(w, b, x, y, lr)
		w, b = out[0], out[1]
		if epoch == 1 || epoch == 10 || epoch == 50 || epoch == 200 {
			fmt.Printf("epoch %3d: loss before step = %8.4f; after: w = %.3f b = %.3f\n", epoch, out[2].Value(), w.Value(), b.Value())
		}
	}
}
```

```output
epoch   1: loss before step =  33.0000; after: w = 1.400 b = 0.500
epoch  10: loss before step =   0.0137; after: w = 2.069 b = 0.804
epoch  50: loss before step =   0.0012; after: w = 2.020 b = 0.942
epoch 200: loss before step =   0.0000; after: w = 2.000 b = 0.999
```

Первая строка совпадает с расчётом на бумаге: потеря 33, после шага `w = 1.4`, `b = 0.5`. Потеря падает на порядки, а параметры стремятся к `2` и `1`. Обратите внимание, что `b` сходится медленнее `w` (за 200 эпох `0.999`, а не `1.000`): направление сдвига в этой задаче «положе».

**Пример 2. Скорость обучения.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
	"github.com/gomlx/gomlx/core/tensors"
)

func step(w, b, xs, ys, lr *graph.Node) []*graph.Node {
	pred := graph.Add(graph.Mul(xs, w), b)
	loss := graph.ReduceAllMean(graph.Square(graph.Sub(pred, ys)))
	grads := graph.Gradient(loss, w, b)
	return []*graph.Node{
		graph.Sub(w, graph.Mul(lr, grads[0])),
		graph.Sub(b, graph.Mul(lr, grads[1])),
		loss,
	}
}

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	train := graph.MustNewExec(backend, step)
	x := tensors.FromValue([]float32{0, 1, 2, 3, 4})
	y := tensors.FromValue([]float32{1, 3, 5, 7, 9})
	for _, rate := range []float32{0.001, 0.05, 0.3} {
		lr := tensors.FromValue(rate)
		w, b := tensors.FromValue(float32(0)), tensors.FromValue(float32(0))
		var loss *tensors.Tensor
		for epoch := 0; epoch < 30; epoch++ {
			out := train.MustExec(w, b, x, y, lr)
			w, b, loss = out[0], out[1], out[2]
		}
		fmt.Printf("lr = %-5v loss after 30 steps = %.2g\n", rate, loss.Value())
	}
}
```

```output
lr = 0.001 loss after 30 steps = 15
lr = 0.05  loss after 30 steps = 0.0041
lr = 0.3   loss after 30 steps = 2.3e+29
```

За 30 шагов: `lr = 0.001` почти не продвинулся (потеря 15), `lr = 0.05` дошёл до `0.0041`, а `lr = 0.3` разошёлся, потеря выросла до порядка `10^29`. Это не ошибка кода, а ожидаемое поведение метода: проверяйте потерю, а не только итоговые параметры.

## Типичные ошибки

* **Слишком большой `lr`.** Потеря растёт или становится `Inf`/`NaN`. Уменьшайте шаг в 3-10 раз.
* **Слишком малый `lr`.** Потеря убывает, но за разумное число эпох не доходит до минимума.
* **Выводят потерю после обновления, а не до.** Функция шага возвращает потерю, вычисленную на *старых* параметрах; не путайте её с потерей новой модели.
* **Забыли подставить результат шага в следующий вызов.** Если передавать в `MustExec` всё те же начальные `w` и `b`, обучение «не движется».
* **Знак обновления.** Параметр двигают *против* градиента: `w - lr * grad`, не `w + lr * grad`.
* **Суммирование вместо усреднения.** Тогда эффективный `lr` зависит от числа точек.
* **Сравнение с эталоном через `==`.** Между `float32` и `float64` всегда есть расхождение порядка `1e-6`; сравнивайте с допуском.
* **Градиент по `x` или `y`.** Дифференцируют по параметрам модели, а не по данным.
* **Разная длина `x` и `y`.** Тогда вычитание невозможно: граф сообщит о несовместимых формах уже при построении. Следите, чтобы входной файл содержал полные пары.

## Итоги

* Регрессия по MSE - минимизация среднего квадрата ошибки; градиентный спуск повторяет `w ← w - lr * dw`.
* В GoMLX шаг обучения - одна функция графа: новые параметры и потеря на выходе, цикл эпох на обычном Go.
* Градиент строит `graph.Gradient`; его правильность проверяется ручными формулами и замкнутым решением.
* Скорость обучения - главный гиперпараметр: слишком малая даёт медленный спуск, слишком большая - расхождение.

<!-- section: facts -->
## Факты

* Для линейной регрессии существует замкнутое решение (нормальные уравнения); градиентный спуск нужен там, где такого решения нет, например для нейронных сетей.
* Метод градиентного спуска сходится для выпуклой квадратичной потери при достаточно малом шаге; для слишком большого шага последовательность расходится.
