## Логистическая регрессия: от чисел к вероятностям

Линейная регрессия предсказывает число. Для **классификации** нужен ответ «класс 0 или класс 1», а лучше - вероятность класса. Логистическая регрессия получает её в два шага.

1. Вычисляется линейная комбинация признаков - **логит**: `z = x · w + b`. Это любое вещественное число.
2. Логит превращается в вероятность функцией **сигмоида**: `p = 1 / (1 + e^-z)`. Для `z = 0` вероятность равна `0.5`; чем больше `z`, тем ближе `p` к 1; чем меньше - тем ближе к 0.

Решение «класс 1» принимается, когда `p > 0.5`, то есть когда `z > 0`. Поэтому граница между классами - это прямая (плоскость) `x · w + b = 0`; модель линейна по границе, хотя вероятность и нелинейна. Вы уже реализовали эту модель на NumPy в уроке [«Логистическая регрессия на NumPy»](lesson:ml.numpy.logistic-regression), а метрики разбирали в уроке [«Метрики классификации»](lesson:ml.foundations.classification-metrics). Здесь важны две новые вещи: как GoMLX считает градиент по такой потере и почему потерю надо писать **через логиты**.

**Потеря - бинарная кросс-энтропия:** `BCE = -mean(y log p + (1 - y) log(1 - p))`. Она сильно штрафует уверенные ошибки: если метка 1, а модель дала `p = 0.001`, потеря огромна. Минимизируется она тем же градиентным спуском, что и в прошлом уроке, а `graph.Gradient` избавляет от ручного вывода.

Данные в упражнении - два перекрывающихся облака точек, поэтому идеальной точности не будет (около `0.92`): часть точек классов лежит с «чужой» стороны границы. Это не ошибка, а свойство задачи.

## Точные правила

**Потеря через логиты.** Если считать `log(sigmoid(z))` напрямую, то при очень отрицательном `z` сигмоид в `float32` округляется до нуля, и `log(0) = -Inf`. Эквивалентная устойчивая запись использует `softplus(z) = log(1 + e^z)`:

```text
-[y log σ(z) + (1 - y) log(1 - σ(z))]  =  softplus(z) - y z
```

В GoMLX это `graph.Sub(graph.Softplus(z), graph.Mul(y, z))`, затем `ReduceAllMean`. Проверьте вручную: для `y = 1` получается `softplus(z) - z = log(1 + e^-z) = -log σ(z)`, как в первом примере.

**Матрично-векторное произведение.** Для `x` формы `[n, 2]` и `w` формы `[2]` выражение `graph.Dot(x, w).Product()` даёт вектор `[n]`: по одному логиту на точку. Затем прибавляется скалярное смещение `b`. Результат имеет ту же форму, что и метки `y` (`[n]`), поэтому потеря считается поэлементно без перестановки осей.

**Точность (accuracy)** - доля точек, у которых предсказанный класс совпал с меткой. Предсказание: `z > 0`. В графе: `GreaterThan(z, ZerosLike(z))` даёт булев тензор, `ConvertDType` приводит его к типу меток, `Equal` сравнивает с метками, `ReduceAllMean` усредняет.

**Начальная потеря.** При `w = 0, b = 0` все логиты равны нулю, все вероятности `0.5`, и потеря равна `ln 2 ≈ 0.693` независимо от данных.

**Данные.** Генератор `rand.New(rand.NewSource(42))` задаёт одну и ту же выборку при каждом запуске: 100 точек, два класса с центрами `(-1, -1)` и `(1, 1)` и единичным разбросом. Воспроизводимость нужна, чтобы число из теста можно было сравнить с ответом.

**Рост весов.** Если классы полностью разделимы прямой, потерю можно уменьшать бесконечно, увеличивая веса: логиты растут, вероятности приближаются к 0 и 1. Спуск никогда не «останавливается» сам, поэтому веса продолжают расти (см. второй пример). Против этого применяют регуляризацию (последний урок) или раннюю остановку.

**Типы.** Метки хранятся как `float32` (0 или 1), чтобы умножаться на логиты без преобразования.

## Примеры

**Пример 1. Наивная и устойчивая потеря.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
)

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	// Loss of ONE example with label y = 1 for a logit z, written two ways.
	exec := graph.MustNewExec(backend, func(z *graph.Node) []*graph.Node {
		p := graph.Sigmoid(z)
		naive := graph.Neg(graph.Log(p))          // -log(sigmoid(z))
		stable := graph.Sub(graph.Softplus(z), z) // softplus(z) - y*z with y = 1
		return []*graph.Node{p, naive, stable}
	})
	for _, z := range []float32{2, -2, -20, -120} {
		out := exec.MustExec(z)
		fmt.Printf("z = %5v  p = %-10v naive = %-10v stable = %v\n", z, out[0], out[1], out[2])
	}
}
```

```output
z =     2  p = float32(0.8808) naive = float32(0.1269) stable = float32(0.1269)
z =    -2  p = float32(0.1192) naive = float32(2.127) stable = float32(2.127)
z =   -20  p = float32(2.061e-09) naive = float32(20) stable = float32(20)
z =  -120  p = float32(0) naive = float32(+Inf) stable = float32(120)
```

Для умеренных логитов оба способа дают одинаковые числа. Но при `z = -120` (метка 1, модель очень уверена в неверном ответе) `sigmoid(z)` равен нулю в `float32`, и наивная потеря бесконечна. Устойчивая запись возвращает честное значение `120`. Если такую потерю подставить в градиентный спуск, одна неудачная точка разрушит все параметры.

**Пример 2. Разделимые данные: веса растут без остановки.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
	"github.com/gomlx/gomlx/core/tensors"
)

func step(x, y, w, b *graph.Node) []*graph.Node {
	z := graph.Add(graph.Mul(x, w), b)
	loss := graph.ReduceAllMean(graph.Sub(graph.Softplus(z), graph.Mul(y, z)))
	g := graph.Gradient(loss, w, b)
	return []*graph.Node{graph.Sub(w, graph.MulScalar(g[0], 0.5)), graph.Sub(b, graph.MulScalar(g[1], 0.5)), loss}
}

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	// Perfectly separable data: every x < 0 is class 0 and every x > 0 is class 1.
	x := tensors.FromValue([]float32{-2, -1, 1, 2})
	y := tensors.FromValue([]float32{0, 0, 1, 1})
	train := graph.MustNewExec(backend, step)
	w, b := tensors.FromValue(float32(0)), tensors.FromValue(float32(0))
	for epoch := 1; epoch <= 1000; epoch++ {
		out := train.MustExec(x, y, w, b)
		w, b = out[0], out[1]
		if epoch == 10 || epoch == 100 || epoch == 1000 {
			fmt.Printf("epoch %4d: loss = %.4f w = %.2f\n", epoch, out[2].Value(), w.Value())
		}
	}
}
```

```output
epoch   10: loss = 0.1269 w = 1.56
epoch  100: loss = 0.0176 w = 3.38
epoch 1000: loss = 0.0020 w = 5.55
```

Четыре точки идеально разделяются нулём. Потеря падает от `0.69` вниз, но вес `w` продолжает расти: `1.56`, `3.38`, `5.55`. Убывающая потеря не означает, что модель стала «лучше» в смысле обобщения: уверенность растёт даже там, где данных немного.

## Типичные ошибки

* **Потеря через `Log(Sigmoid(z))`.** Получаете `Inf` и `NaN` на уверенных ошибках. Пишите через `Softplus`.
* **Потеря от вероятностей вместо логитов.** Это тот же приём, но с потерей точности; логиты нужны и для порога `z > 0`.
* **Среднеквадратичная ошибка на сигмоиде** вместо кросс-энтропии. Она формально работает, но градиент затухает на уверенных ошибках, и обучение идёт хуже. Это ловушка заготовки в упражнении.
* **Порог `p > 0.5` и порог `z > 0`** - одно и то же, но второй не требует вычисления сигмоида.
* **Метки не 0/1.** Формула `softplus(z) - y z` верна только для `y ∈ {0, 1}`; для `-1/+1` нужна другая запись.
* **Точность на обучающих данных как единственная метрика.** Она ничего не говорит об обобщении.
* **Слишком большой `lr`.** Потеря колеблется или растёт; начальная потеря всегда `0.693`, если что-то пошло не так, сначала проверьте её.
* **Ожидание 100% точности на перекрывающихся классах.** Часть ошибок неустранима для любой линейной модели.

## Итоги

* Логистическая регрессия: логит `z = x · w + b`, вероятность `σ(z)`, решение по знаку `z`.
* Потеря - бинарная кросс-энтропия, записанная через логиты как `mean(softplus(z) - y z)`: так нет `Inf` и `NaN`.
* Точность считается в графе: сравнение `z > 0` с метками и усреднение.
* На разделимых данных веса растут бесконечно, на перекрывающихся достигается предел точности (здесь около `0.92`).
* Градиент строит `graph.Gradient`; код шага почти не отличается от линейной регрессии.

<!-- section: facts -->
## Факты

* Бинарная кросс-энтропия совпадает с отрицательным логарифмом правдоподобия модели Бернулли, поэтому её минимизация - оценка максимального правдоподобия.
* В GoMLX есть готовая функция `graph.Softplus`; устойчивые формы потерь через логиты применяются и в других библиотеках.
