## Автоматическое дифференцирование

Обучение модели - это подбор параметров, при котором **потеря** (число, показывающее, насколько модель ошибается) становится меньше. Чтобы знать, в какую сторону двигать каждый параметр, нужна **производная** потери по этому параметру: она показывает, как сильно и в какую сторону изменится потеря при небольшом изменении параметра. Для нескольких параметров набор таких производных называется **градиентом**. Идея знакома вам по уроку [«Линейная регрессия» из курса основ ML](lesson:ml.foundations.linear-regression): там градиент выводили вручную.

Вручную вычислять производные для сети с тысячами параметров невозможно, и библиотека делает это за вас. Раз граф GoMLX - это записанная последовательность простых операций, каждая из которых умеет считать свою производную, то производная всей формулы получается **по правилу цепочки**: сначала вычисляется значение «вперёд», затем вклад каждой операции собирается «назад», от результата к параметрам. Это **обратное дифференцирование** (reverse-mode), основа алгоритма обратного распространения ошибки.

Для вас это выглядит так: вы пишете формулу потери, затем одну строку `graph.Gradient(loss, w, b)`, и получаете узлы с производными, которые можно выполнять так же, как любые другие.

Важно различать три способа получить производную.

1. **Вручную / символьно:** вывести формулу на бумаге. Точно, но не масштабируется.
2. **Численно (конечные разности):** посчитать формулу в двух близких точках и поделить разность на шаг. Просто и независимо от реализации, но неточно и дорого при многих параметрах.
3. **Автоматически:** точный результат в пределах арифметики с плавающей точкой, цена порядка одного дополнительного прохода по графу.

В упражнении вы сравните второй и третий способы: численная проверка конечными разностями - стандартный тест «градиент реализован верно».

## Точные правила

**Сигнатура.** `graph.Gradient(output *Node, wrt ...*Node) []*Node`. Выход `output` должен быть **скаляром** (форма без осей); для векторных выходов нужна матрица Якоби, которой в `v0.28.8` нет. Возвращается срез узлов: i-й элемент - производная `output` по i-му аргументу и имеет **такую же форму**, как этот аргумент. Если параметр - вектор из трёх элементов, градиент - вектор из трёх элементов.

**Что дифференцируется.** Аргументы и результат должны принадлежать одному графу, то есть строиться внутри одной функции. Параметры в этом курсе - обычные входные узлы функции графа. (В полной библиотеке есть пакеты `ml/layers` и `ml/train` со слоями и обучением; курс их не использует, чтобы обучение было видно целиком.)

**Правила вычисления производных.** Сумма: производные складываются. Произведение: `d(uv) = u dv + v du`. Сложная функция: `d f(g(x)) = f'(g(x)) g'(x)`. Для `sigmoid(z) = 1 / (1 + e^-z)` производная равна `sigmoid(z) (1 - sigmoid(z))`. Для `x^2` - `2x`.

**Если узел входит в формулу дважды**, вклады складываются. В примере из урока `f(x, y) = sigmoid(x y) + x^2` переменная `x` встречается и в сигмоиде, и в квадрате: `df/dx = y sigmoid'(xy) + 2x`, `df/dy = x sigmoid'(xy)`.

**`StopGradient(x)`** - тождественная операция, через которую градиент не проходит: для дифференцирования узел становится константой. Полезно, когда часть формулы должна считаться «замороженной».

**Конечные разности.** Центральная формула `(f(x+h) - f(x-h)) / (2h)` ошибается на величину порядка `h^2`, а ошибки округления растут при малых `h`. Для `float32` шаг `1e-5` слишком мал: значения `f(x±h)` почти совпадают, и разность теряет значащие цифры. Поэтому в упражнении численная проверка идёт в `float64`. Сравнение «автоматический и численный градиент совпали» делают с допуском, а не через `==`.

**Типы.** Скаляры Go типа `float64` превращаются в `Float64`-тензоры: градиент имеет тот же тип.

## Примеры

**Пример 1. Производная скаляра и градиент вектора.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
)

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	// d(x^2)/dx = 2x, so the slope at x = 3 is 6.
	slope := graph.MustNewExec(backend, func(x *graph.Node) *graph.Node {
		return graph.Gradient(graph.Square(x), x)[0]
	})
	fmt.Println("d(x^2)/dx at 3:", slope.MustExec(float32(3))[0])

	// For a vector input the gradient of a SCALAR has the shape of the input: one slope per element.
	// loss = sum(x^3), d loss / d x_i = 3 x_i^2.
	grad := graph.MustNewExec(backend, func(x *graph.Node) *graph.Node {
		loss := graph.ReduceAllSum(graph.Mul(x, graph.Square(x)))
		return graph.Gradient(loss, x)[0]
	})
	fmt.Println("d sum(x^3)/dx:", grad.MustExec([]float32{1, 2, 3})[0])
}
```

```output
d(x^2)/dx at 3: float32(6)
d sum(x^3)/dx: [3]float32{3, 12, 27}
```

Для `x^2` в точке 3 наклон равен `2 * 3 = 6`. Во втором случае функция скалярная (`sum(x^3)`), поэтому `Gradient` допустим; градиент имеет форму входа `[3]`: `3x^2` для каждого элемента, то есть `3, 12, 27`.

**Пример 2. Проверка вручную и `StopGradient`.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
)

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	// loss(w) = (w*x - y)^2 with x = 2, y = 10. By hand: d loss / d w = 2 (w x - y) x.
	exec := graph.MustNewExec(backend, func(w *graph.Node) []*graph.Node {
		x, y := graph.Const(w.Graph(), float32(2)), graph.Const(w.Graph(), float32(10))
		loss := graph.Square(graph.Sub(graph.Mul(w, x), y))
		auto := graph.Gradient(loss, w)[0]
		byHand := graph.MulScalar(graph.Mul(graph.Sub(graph.Mul(w, x), y), x), 2)
		// StopGradient makes a node a constant for differentiation: the slope with respect to w disappears.
		frozen := graph.Gradient(graph.Mul(w, graph.StopGradient(w)), w)[0]
		return []*graph.Node{auto, byHand, frozen}
	})
	for _, w := range []float32{0, 3, 5} {
		out := exec.MustExec(w)
		fmt.Printf("w = %v: autodiff %v, by hand %v, w*stop(w) -> %v\n", w, out[0], out[1], out[2])
	}
}
```

```output
w = 0: autodiff float32(-40), by hand float32(-40), w*stop(w) -> float32(0)
w = 3: autodiff float32(-16), by hand float32(-16), w*stop(w) -> float32(3)
w = 5: autodiff float32(0), by hand float32(0), w*stop(w) -> float32(5)
```

Для `loss(w) = (w x - y)^2` при `x = 2`, `y = 10` производная равна `2 (w x - y) x`. Автоматический и ручной результаты совпадают при каждом `w`. В точке `w = 5` потеря минимальна, и градиент равен нулю: именно там остановится градиентный спуск. В последнем столбце `w * StopGradient(w)`: производная этого выражения равна значению второго множителя, то есть `w`, а не `2w`, потому что второй множитель считается константой.

## Типичные ошибки

* **Вызов `Gradient` для не скалярного выхода.** Потерю нужно свернуть в число: `ReduceAllSum` или `ReduceAllMean`.
* **Нулевой градиент.** Если все производные нули, проверьте, что параметр действительно участвует в формуле и не закрыт через `StopGradient`. В точке минимума нулевой градиент - нормальный результат.
* **Численная проверка в `float32`.** Шум округления делает результат непригодным; проверяйте в `float64` и сравнивайте с допуском.
* **Сравнение градиентов через `==`.** Получаются расхождения порядка `1e-6`, нужно сравнение с допуском.
* **Слишком большой или слишком малый шаг `h`** в конечных разностях: первый даёт ошибку метода, второй - ошибку округления.
* **Забыли `StopGradient`**, когда часть формулы должна быть константой: градиент пойдёт и через неё.
* **Ожидание, что `Gradient` вернёт число.** Он возвращает узлы графа; значения появятся после `MustExec`.
* **Путаница порядка.** Градиенты возвращаются в порядке аргументов: `Gradient(loss, w, b)` даёт `[dw, db]`.

## Итоги

* Градиент показывает, как изменение каждого параметра влияет на потерю; обучение двигает параметры против градиента.
* `graph.Gradient(loss, params...)` строит узлы производных автоматически; потеря должна быть скаляром, форма градиента равна форме параметра.
* Обратное дифференцирование использует правило цепочки и даёт точный (в пределах арифметики) результат за цену порядка одного дополнительного прохода по графу.
* Конечные разности - проверка реализации, а не рабочий метод; их считают в `float64` и сравнивают с допуском.

<!-- section: facts -->
## Факты

* Для автоматического дифференцирования различают прямой режим (forward) и обратный (reverse); обратный эффективен, когда выходов мало, а параметров много, как в обучении моделей.
* В GoMLX `Gradient` требует скалярного выхода; матрица Якоби не реализована.
