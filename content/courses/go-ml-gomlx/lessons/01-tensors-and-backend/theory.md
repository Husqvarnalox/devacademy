## Что такое GoMLX и как он устроен

**GoMLX** - библиотека машинного обучения и математики на Go. Её часто сравнивают с PyTorch, JAX и TensorFlow: вы описываете вычисление над многомерными массивами, а библиотека умеет выполнять его и находить производные (этому посвящён третий урок). Прочитайте это сравнение осторожно: GoMLX - молодой проект с версией `v0.28.8`, а не зрелая экосистема размером с PyTorch.

В GoMLX всё держится на трёх понятиях.

1. **Тензор** (`tensors.Tensor`) - многомерный массив чисел с известной формой и типом элемента. Скаляр, вектор, матрица - частные случаи.
2. **Граф вычислений** (`graph`). Вы пишете обычную Go-функцию, но принимает и возвращает она не числа, а **узлы** `*graph.Node`. Вызывая `graph.Square(x)`, вы ничего не считаете, а *записываете* операцию в граф.
3. **Бэкенд** (`compute.Backend`) - движок, который компилирует граф и выполняет его над реальными данными. Один и тот же граф можно отдать разным бэкендам.

Поэтому программа на GoMLX делится на две фазы. В первой Go-код строит граф по описанию «что считать». Во второй бэкенд применяет граф к тензорам. Это принципиально отличается от обычного Go, где `x * x` считается сразу.

В этом курсе используется **чистый Go-бэкенд** (`go`): он не требует C-библиотек, cgo, видеокарты и скачиваний во время запуска упражнения. Платить за это приходится скоростью: документация проекта прямо называет его более медленным, чем XLA. Для учебных задач из шести уроков этого достаточно, для обучения больших сетей - нет.

## Точные правила

**Тензоры.**

* `tensors.FromValue(v)` создаёт тензор из значения Go: `[]float32{1, 2, 3}` даёт вектор, `[][]float64{{1, 2, 3}, {4, 5, 6}}` - матрицу. Форма определяется вложенностью срезов, тип элемента - типом Go: `float32` даёт `Float32`, `float64` - `Float64`, `int32` - `Int32`.
* `tensors.FromScalar(x)` создаёт скаляр (форма без измерений).
* Форма печатается как `(Float32)[2, 3]`: тип элемента, затем размеры по осям. Скаляр выглядит как `(Int32)`. У формы есть `DType`, `Dimensions`, `Rank()` (число осей) и `Size()` (число элементов).
* `t.Value()` копирует содержимое обратно в обычные срезы Go и возвращает `any`: нужно утверждение типа, например `t.Value().([]float32)`. Изменение этой копии тензор не меняет.
* Для машинного обучения основной тип - `float32`: он вдвое компактнее `float64`, и точности хватает. Но `float64` тоже доступен.

**Бэкенд.**

* `compute.NewWithConfig("go")` создаёт бэкенд по имени. Имя работает только тогда, когда пакет бэкенда подключён: для этого нужен пустой импорт `_ "github.com/gomlx/compute/gobackend"`. Он ничего не экспортирует, а при инициализации регистрирует бэкенд `go`. Без него `NewWithConfig("go")` не найдёт бэкенд и завершится паникой.
* Для неизвестного имени конфигурации `NewWithConfig` не возвращает `error`, а паникует с перечнем доступных бэкендов. Имя фиксируйте в коде или проверяйте заранее.
* Бэкенд `xla` (на основе OpenXLA) в этом курсе **не используется**: по описанию проекта он использует CGO и C++-библиотеку, зато поддерживает GPU и TPU. Для реальных нагрузок выбор между «портативный чистый Go» и «быстрый XLA» - главный компромисс при переходе от учебного кода к продакшену. Код графов при этом не меняется, меняется строка конфигурации и зависимости.

**Графы и `Exec`.**

* `graph.MustNewExec(backend, fn)` оборачивает функцию построения графа. Параметры `fn` - узлы `*graph.Node`, результат - один узел, несколько узлов или срез узлов. Варианты без `Must` (`graph.NewExec` и метод `exec.Exec`) возвращают `error` вместо паники.
* `exec.MustExec(args...)` принимает тензоры, а также обычные значения Go (скаляр, срез): они преобразуются в тензоры сами. Результат - срез `[]*tensors.Tensor`, по одному на каждый возвращённый узел.
* Граф компилируется **для конкретных форм и типов входов** и запоминается. Те же форма и тип - повторное выполнение без перестроения. Новая форма или тип - функция вызывается снова и строится новый граф.
* Типы в графе строгие: сложение `Float32` и `Float64` - ошибка построения графа. Преобразование явное: `graph.ConvertDType(x, dtypes.Float32)`.
* Скалярные константы удобно добавлять через `AddScalar`, `MulScalar`: они подстраиваются под тип узла.

## Примеры

**Пример 1. Тензор, форма, тип и выполнение графа.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
	"github.com/gomlx/gomlx/core/tensors"
)

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	fmt.Println("backend:", backend.Name())

	vec := tensors.FromValue([]float32{1, 2, 3})
	mat := tensors.FromValue([][]float64{{1, 2, 3}, {4, 5, 6}})
	scalar := tensors.FromScalar(int32(7))
	fmt.Println(vec.Shape(), mat.Shape(), scalar.Shape())
	fmt.Println(vec.Shape().DType, vec.Shape().Dimensions, mat.Shape().Rank(), mat.Shape().Size())

	f := graph.MustNewExec(backend, func(x *graph.Node) *graph.Node {
		return graph.AddScalar(graph.Mul(x, x), 1)
	})
	out := f.MustExec(vec)[0]
	fmt.Println(out)
	fmt.Println(out.Value().([]float32))
	fmt.Printf("%v\n", f.MustExec(float32(3))[0])
	m2 := f.MustExec(mat)[0]
	fmt.Println(m2.Shape(), m2.Value())
}
```

```output
backend: Go Backend
(Float32)[3] (Float64)[2, 3] (Int32)
Float32 [3] 2 6
[3]float32{2, 5, 10}
[2 5 10]
float32(10)
(Float64)[2, 3] [[2 5 10] [17 26 37]]
```

Обратите внимание на три вещи. `[3]float32{2, 5, 10}` - это сам тензор, напечатанный вместе с типом Go. Для скаляра `float32(3)` граф построился заново под скалярную форму (функция записана одна). А матрица `float64` дала `Float64` на выходе, хотя функция `x*x + 1` записана один раз.

**Пример 2. Целые на входе, дробные на выходе; Value() копирует.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	"github.com/gomlx/compute/dtypes"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
	"github.com/gomlx/gomlx/core/tensors"
)

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	// Integers in, float out: the graph decides the dtype of every node.
	mean := graph.MustNewExec(backend, func(x *graph.Node) *graph.Node {
		return graph.ReduceAllMean(graph.ConvertDType(x, dtypes.Float32))
	})
	counts := tensors.FromValue([]int32{1, 2, 4})
	fmt.Println(counts.Shape(), "->", mean.MustExec(counts)[0])

	// The same Exec is reused for another shape: the graph is traced again for it.
	grid := tensors.FromValue([][]int32{{1, 2}, {3, 4}, {5, 6}})
	fmt.Println(grid.Shape(), "->", mean.MustExec(grid)[0])

	// A tensor is a copy of data in the backend; Value() copies it back into plain Go slices.
	back := grid.Value().([][]int32)
	back[0][0] = 100
	fmt.Println(grid.Value())
}
```

```output
(Int32)[3] -> float32(2.333)
(Int32)[3, 2] -> float32(3.5)
[[1 2] [3 4] [5 6]]
```

Сначала целочисленный тензор приводится к `Float32` и усредняется: `(1+2+4)/3 = 2.333`. Затем тот же `Exec` получает матрицу другой формы, и граф строится заново. В конце видно, что изменение среза, полученного из `Value()`, исходный тензор не затронуло.

## Типичные ошибки

* **Забыли пустой импорт бэкенда.** Без `_ "github.com/gomlx/compute/gobackend"` бэкенд `go` не зарегистрирован, и `compute.NewWithConfig("go")` не найдёт его.
* **Опечатка в имени бэкенда.** `NewWithConfig` паникует, а не возвращает ошибку; текст паники показывает, какие бэкенды доступны.
* **Смешение `float32` и `float64`.** Ошибка сборки графа: `data types (DType) for BinaryOp Add must match, got (Float32) and (Float64)`. Приводите типы через `ConvertDType` или заводите все данные одним типом.
* **Ожидание, что `graph.Add` что-то считает.** Эта функция возвращает узел, а значение появится только после `MustExec`. Внутри функции графа числа ещё не существует, есть только описание операции.
* **Несовместимые формы.** Сложение `[3]` и `[2]` невозможно: `dimension of axis #0 doesn't match and cannot be broadcast`. Правила расширения форм - тема следующего урока.
* **Утверждение типа с неверным типом.** `t.Value().([]float64)` для `Float32`-тензора паникует; тип среза должен совпадать с типом тензора.
* **Попытка изменить тензор через `Value()`.** Это копия.
* **Бесконтрольное построение новых графов.** Каждая новая форма входа перекомпилирует граф; в цикле подавайте тензоры одной формы.

## Итоги

* GoMLX разделяет описание вычисления (граф из узлов) и его выполнение (бэкенд над тензорами).
* Тензор имеет форму и тип; `FromValue` создаёт его из срезов, `Value()` возвращает копию в виде срезов.
* Бэкенд `go` - чистый Go без cgo; он портативен, но медленнее XLA. Подключается пустым импортом.
* `MustNewExec` компилирует граф под форму и тип входов и переиспользует его; новая форма - новая компиляция.
* Типы строгие: смешивать `float32` и `float64` без `ConvertDType` нельзя.

## Факты

* Версия GoMLX в курсе - `v0.28.8` (с `github.com/gomlx/compute v0.1.6`); до `v1.0.0` совместимость API не гарантируется (см. правила версий модулей Go).
* Бэкенд `go` реализован в модуле `github.com/gomlx/compute/gobackend`; по описанию проекта он «очень портативен, но медленный» и частично использует SIMD для умножения матриц.
* Бэкенд XLA основан на OpenXLA, использует CGO и поддерживает GPU и TPU.
