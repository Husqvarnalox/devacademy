## Граф как формула над целыми массивами

В прошлом уроке вы построили по одной формуле и выполнили её. Теперь научимся описывать вычисления над **целыми массивами сразу**. Вместо цикла «для каждой строки, для каждого столбца» вы пишете одну операцию над всей матрицей: вычесть среднее, возвести в квадрат, поделить. Это называется **векторизацией**, и именно так устроены NumPy и PyTorch. Вы уже встречали идею в курсе [«Классическое ML с нуля на NumPy»](lesson:ml.numpy.linear-regression).

Функция графа - обычный Go-код, и это даёт два свойства, которые стоит усвоить сразу.

1. **Go-код исполняется один раз, при построении графа.** Цикл `for` внутри функции графа разворачивается в последовательность операций, а условие `if` на Go-переменной решается заранее. Если решение должно зависеть от *данных*, нужна операция графа, например `graph.Where`.
2. **Формы проверяются при построении.** Ошибка формы - это не неверное число, а паника с понятным сообщением ещё до вычислений.

Главная новая идея урока - **расширение (broadcasting)**: операция над тензорами разных форм допустима, если меньший тензор можно «растянуть» по осям размера 1. Пример: из матрицы `[строки, столбцы]` вычитается строка средних формы `[1, столбцы]` - она применяется к каждой строке.

## Точные правила

**Поэлементные операции.** `graph.Add`, `Sub`, `Mul`, `Div` применяют операцию к соответствующим элементам двух узлов одного типа. `graph.Square`, `Sqrt`, `Exp`, `Log`, `Tanh`, `Sigmoid` и другие принимают один узел. `AddScalar`, `MulScalar` работают с константой Go. Результат всегда новый узел, исходные узлы не меняются.

**Расширение форм.**

* Если формы совпадают, операция поэлементная.
* Скаляр (форма без осей) совместим с любым тензором.
* Для двух тензоров **одного ранга** ось можно расширить, если у одного из них на ней размер 1: `[2, 3]` и `[1, 3]` дают `[2, 3]`, а `[2, 3]` и `[2, 1]` дают `[2, 3]`.
* Тензоры **разных рангов** (например, `[2, 3]` и `[3]`) не расширяются: в версии `v0.28.8` такая операция даёт панику, и форму нужно привести вручную, чтобы ранги совпали. Поэтому в этом курсе параметры вроде смещений хранятся как `[1, n]`, а не `[n]`.
* Несовместимые размеры, например `[3]` и `[2]`, дают панику при построении: `dimension of axis #0 doesn't match and cannot be broadcast`.

**Редукции.** `graph.ReduceAllSum(x)`, `ReduceAllMean(x)` сворачивают все оси в скаляр. `graph.ReduceMean(x, оси...)` и `ReduceSum(x, оси...)` убирают перечисленные оси: для `[2, 3]` по оси 0 получится `[3]`. `graph.ReduceAndKeep(x, graph.ReduceMean, 0)` сохраняет ось размера 1: получится `[1, 3]`, и результат сразу пригоден для расширения. Ось 0 - строки (вдоль неё усредняют каждый столбец), ось 1 - столбцы.

**Стандартизация столбца** `z = (x - mean) / (std + eps)`:

* среднее по оси 0 даёт среднее каждого столбца;
* `std` здесь - **генеральное** отклонение (деление на `n`, а не `n-1`): `sqrt(mean((x - mean)^2))`;
* малая добавка `eps` (в упражнении `1e-6`) защищает от деления на ноль в постоянном столбце: там `std = 0`, числитель тоже ноль, и результат `0`, а не `NaN`.

**Условия по данным.** `graph.Where(cond, a, b)` выбирает поэлементно `a` там, где `cond` истинно, и `b` в остальных местах. Условие получают операциями сравнения: `graph.GreaterThan(x, y)`, `graph.Equal(x, y)`. Результат сравнения - булев тензор; для арифметики его приводят через `graph.ConvertDType`.

**Несколько результатов.** Функция графа может вернуть `[]*graph.Node`; `MustExec` вернёт столько же тензоров в том же порядке.

## Примеры

**Пример 1. Три способа редукции и расширение.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
	"github.com/gomlx/gomlx/core/tensors"
)

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	// Three ways to reduce a [2, 3] matrix over axis 0; they differ only in the output shape.
	exec := graph.MustNewExec(backend, func(x *graph.Node) []*graph.Node {
		flat := graph.ReduceMean(x, 0)                      // shape [3]
		kept := graph.ReduceAndKeep(x, graph.ReduceMean, 0) // shape [1, 3]
		centered := graph.Sub(x, kept)                      // [2, 3] - [1, 3] broadcasts
		return []*graph.Node{flat, kept, centered}
	})
	out := exec.MustExec(tensors.FromValue([][]float32{{1, 2, 3}, {3, 6, 9}}))
	for _, t := range out {
		fmt.Println(t.Shape(), t.Value())
	}
}
```

```output
(Float32)[3] [2 4 6]
(Float32)[1, 3] [[2 4 6]]
(Float32)[2, 3] [[-1 -2 -3] [1 2 3]]
```

`ReduceMean(x, 0)` дал форму `[3]`, `ReduceAndKeep` - `[1, 3]`. Только вторая форма имеет тот же ранг, что у `x`, поэтому `Sub(x, kept)` работает: строка средних вычитается из каждой строки. Результат центрирован: сумма каждого столбца равна нулю.

**Пример 2. Go-цикл исполняется при построении, а выбор по данным - в графе.**

```go run
package main

import (
	"fmt"

	"github.com/gomlx/compute"
	_ "github.com/gomlx/compute/gobackend"
	"github.com/gomlx/gomlx/core/graph"
)

func main() {
	backend, err := compute.NewWithConfig("go")
	if err != nil {
		panic(err)
	}
	// A Go loop and a Go if run once, while the graph is being built; the graph only contains the result.
	calls := 0
	exec := graph.MustNewExec(backend, func(x *graph.Node) *graph.Node {
		calls++
		for i := 0; i < 3; i++ {
			x = graph.Square(x) // x^2, then x^4, then x^8
		}
		return x
	})
	for _, v := range []float32{2, 1.5, 3} {
		fmt.Printf("%v^8 = %v\n", v, exec.MustExec(v)[0])
	}
	fmt.Println("after three scalars the graph function was called", calls, "time(s)")
	fmt.Println("vector input:", exec.MustExec([]float32{1, 2})[0])
	fmt.Println("after a vector it was called", calls, "times: a new shape means a new graph")

	// A decision that depends on the DATA must be a graph operation: Where picks element by element.
	relu := graph.MustNewExec(backend, func(x *graph.Node) *graph.Node {
		return graph.Where(graph.GreaterThan(x, graph.ZerosLike(x)), x, graph.ZerosLike(x))
	})
	fmt.Println(relu.MustExec([]float32{-2, -0.5, 0, 1.5})[0])
}
```

```output
2^8 = float32(256)
1.5^8 = float32(25.63)
3^8 = float32(6561)
after three scalars the graph function was called 1 time(s)
vector input: [2]float32{1, 256}
after a vector it was called 2 times: a new shape means a new graph
[4]float32{0, 0, 0, 1.5}
```

Цикл из трёх возведений в квадрат записал в граф три операции, получилась степень `x^8`. Функция графа вызвалась **один раз** для трёх скаляров, а вектор другой формы потребовал нового вызова. Значение `25.63` - это `1.5^8 = 25.6289...`, тензор печатается с четырьмя значащими цифрами. Вторая часть показывает `Where` для ReLU: «если больше нуля - сам x, иначе ноль».

## Типичные ошибки

* **Ранги не совпадают.** Попытка сложить `[2, 3]` и `[3]` падает на этапе построения. Решение: хранить параметры как `[1, 3]` или использовать `ReduceAndKeep`.
* **`ReduceMean` вместо `ReduceAndKeep`.** Форма `[3]` не подходит для вычитания из `[2, 3]`.
* **Не та ось.** Для среднего каждого столбца усредняют по оси 0 (строкам), а не по оси 1.
* **Выборочная дисперсия вместо генеральной.** Деление на `n-1` вместо `n` даёт другие числа; в курсе везде используется деление на `n`.
* **Деление на ноль в постоянном столбце.** Без `eps` получится `NaN` или `Inf`.
* **`if` по данным внутри функции графа.** Узел - не число, его нельзя сравнить в Go. Используйте `Where`.
* **Ожидание, что Go-цикл выполнится при каждом запуске.** Он выполняется один раз при построении; то же касается `fmt.Println` внутри функции графа.
* **Смешение типов.** Сложение `Float32` и `Float64` не пройдёт, приведите типы через `ConvertDType`.

## Итоги

* Функция графа - обычный Go-код, исполняемый один раз на каждую форму входа; вычисления идут в бэкенде.
* Векторизация заменяет циклы операциями над целыми массивами.
* Расширение требует совпадения рангов (или скаляра) и размера 1 на расширяемой оси; `ReduceAndKeep` сохраняет ось.
* Решения по данным принимают операциями `Where` и сравнения, а не Go-условием.
* Стандартизация столбцов: центрирование, деление на генеральное std с добавкой `eps`.

<!-- section: facts -->
## Факты

* Расширение форм в GoMLX требует одинакового ранга либо скаляра; это отличается от NumPy, где недостающие оси слева добавляются автоматически.
* Функция графа вызывается заново для каждой новой комбинации форм и типов входов.
