## Зачем это нужно

Данные бывают неправильными: в поле «количество» кто-то написал `abc`, число не помещается в `int`, функции передали пустую строку. Если программа к этому не готова, она падает. Нужен способ сказать: «здесь произошла ошибка, прервите обычный ход работы и передайте управление тому, кто знает, что с этим делать». В C++ для этого есть **исключения**.

## Одна новая идея: исключение - это сигнал об ошибке, который обходит обычный порядок выполнения

**Исключение** - объект, описывающий ошибку. Когда код **бросает** его (`throw`), выполнение немедленно прекращается и «поднимается» вверх по вызовам, пока не встретит блок `catch`, подходящий по типу. Блок `try` задаёт участок кода, где ошибки ожидаются:

```cpp
try {
    int n = std::stoi(text);       // может бросить исключение
    std::cout << "Число: " << n;   // выполнится, только если ошибки не было
} catch (const std::invalid_argument&) {
    std::cout << "Это не число";   // выполнится, если stoi бросил invalid_argument
}
```

Если в блоке `try` ошибки нет, `catch` пропускается. Если ошибка есть, оставшиеся строки блока `try` **не выполняются**, и сразу начинается `catch`.

Свои исключения бросают так: `throw std::invalid_argument("описание");`. Стандартный тип `std::invalid_argument` означает «функции передано неподходящее значение». Он объявлен в заголовке `<stdexcept>`, его подключают рядом с `<iostream>`.

## Пример 1. Перехват ошибки stoi

```cpp run
#include <iostream>
#include <stdexcept>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> inputs = {"42", "abc"};
    for (const std::string& text : inputs) {
        try {
            int n = std::stoi(text);
            std::cout << text << " -> " << n << "\n";
        } catch (const std::invalid_argument&) {
            std::cout << text << " -> не число\n";
        }
    }
    std::cout << "Программа продолжила работу\n";
}
```
```output
42 -> 42
abc -> не число
Программа продолжила работу
```

Разбор:

* Для `42` блок `try` выполняется целиком, `catch` пропускается.
* Для `abc` `std::stoi` бросает `std::invalid_argument`; присваивание `n` и печать внутри `try` не выполняются, управление переходит в `catch`.
* После `catch` программа идёт дальше обычным образом: ошибка обработана и не стала фатальной.
* Когда имя исключения в `catch` не нужно, его можно не писать: `catch (const std::invalid_argument&)`.

## Пример 2. Своя функция бросает исключение

```cpp run
#include <iostream>
#include <stdexcept>
#include <string>

int percentOf(int part, int whole) {
    if (whole == 0) {
        throw std::invalid_argument("всего не может быть нулём");
    }
    return part * 100 / whole;
}

int main() {
    try {
        std::cout << percentOf(30, 120) << "%\n";
        std::cout << percentOf(5, 0) << "%\n";
        std::cout << "сюда управление не дойдёт\n";
    } catch (const std::invalid_argument& e) {
        std::cout << "Ошибка: " << e.what() << "\n";
    }
}
```
```output
25%
Ошибка: всего не может быть нулём
```

Разбор:

* Функция сама проверяет данные и при проблеме бросает исключение. Вызывающий код решает, что делать дальше.
* Исключение выходит из `percentOf`, пропуская остаток функции (`return` не выполняется), и перехватывается в `main`. Вызывающих может быть несколько: исключение поднимается через все функции, пока не найдёт подходящий `catch`.
* `e.what()` возвращает текст, который был передан в конструктор.
* Третья строка `try` не напечаталась: после ошибки в блоке выполнение уходит в `catch`.

## Пример 3. stoi не проверяет «хвост» строки

```cpp run
#include <iostream>
#include <string>

int main() {
    std::cout << std::stoi("12abc") << "\n";
    std::cout << std::stoi("42 apples") << "\n";
    std::cout << std::stoi("  7") << "\n";
    std::cout << std::stoi("+5") << "\n";
    std::cout << std::stoi("-3") << "\n";
}
```
```output
12
42
7
5
-3
```

`stoi` пропускает пробелы в начале, принимает знак, читает цифры и останавливается на первом непонятном символе. Исключения нет: «хвост» просто игнорируется. Если нужна строка целиком, проверяйте её отдельно. Простой способ - превратить число обратно в текст и сравнить:

```cpp
int value = std::stoi(text);
if (std::to_string(value) != text) {
    throw std::invalid_argument("лишние символы в числе");
}
```

Эта проверка отвергнет `12abc`, `+5`, ` 7` и `007`, потому что `std::to_string(value)` печатает число в обычной записи.

## Пример 4. Когда подходящего catch нет

Следующая программа не запускается в примерах: она завершается аварийно.

```cpp
#include <stdexcept>

int main() {
    throw std::invalid_argument("плохое значение");
}
```

```text
libc++abi: terminating due to uncaught exception of type std::invalid_argument: плохое значение
```

Необработанное исключение завершает программу аварийно (код возврата 134). Тип и текст исключения в сообщении помогают найти причину. Для g++ сообщение выглядит иначе (`terminate called after throwing an instance of 'std::invalid_argument'` и строка `what(): ...`), но суть та же.

**Попробуйте.** Напишите функцию `int toAge(const std::string& text)`, которая бросает исключение для возраста меньше 0 и больше 150, и вызовите её в `try`. Прочитайте строки до конца ввода и посчитайте, сколько из них не удалось превратить в число. Сравните `std::stoi("99999999999")` с `std::stoi("abc")`: исключения разные (`std::out_of_range` и `std::invalid_argument`); обработайте оба двумя блоками `catch` подряд.

## Точные правила

* **`try { ... }`** - участок, где может возникнуть исключение. После него обязательно идёт хотя бы один **`catch`**.
* **`throw выражение;`** создаёт исключение и немедленно прекращает текущую функцию. Выполнение идёт вверх по цепочке вызовов к первому подходящему `catch`.
* **`catch (const Тип& имя)`** перехватывает исключения указанного типа и производных от него. Исключения принято перехватывать по константной ссылке. Если имя не нужно, его можно опустить.
* Блоков `catch` может быть несколько; выбирается **первый подходящий** сверху вниз. Специальные типы ставят выше общих.
* Стандартные типы из `<stdexcept>`: `std::invalid_argument` (неподходящее значение), `std::out_of_range` (значение вне допустимого диапазона), `std::runtime_error` (общая ошибка времени выполнения). Все они наследуют `std::exception`, поэтому `catch (const std::exception&)` ловит любой из них.
* `e.what()` возвращает текст сообщения. Для собственных исключений текст задаёте вы. **Тексты исключений стандартной библиотеки зависят от компилятора**: для `stoi("abc")` libc++ (Apple clang) сообщает `stoi: no conversion`, а libstdc++ (g++) - просто `stoi`. Не завязывайте логику программы на эти тексты.
* Функции стандартной библиотеки сообщают об ошибках так: `std::stoi` бросает `std::invalid_argument` (в начале строки нет числа) или `std::out_of_range` (число не помещается в `int`); `vector::at` и `map::at` бросают `std::out_of_range`; `string::substr` бросает `std::out_of_range` при позиции за концом строки.
* **Исключением не становится** то, что стандарт называет неопределённым поведением: выход за границы через `[]`, деление целого числа на ноль, чтение неинициализированной переменной. Там нет проверки, и перехватывать нечего.
* Если исключение не перехвачено, программа завершается аварийно (`std::terminate`).
* `catch` не должен молчать без причины. Пустой блок скрывает ошибки: как минимум сообщите о проблеме или посчитайте её.
* Исключения предназначены для **исключительных** ситуаций вроде плохих данных. Обычные ветвления (число чётное, слово найдено) оформляют через `if`.

## Типичные ошибки

Тексты сообщений получены от Apple clang 21 с ключами курса.

**1. Ожидание исключения от `stoi("12abc")`.** Пример 3: получится 12, ошибки не будет. Проверяйте строку целиком, если «хвост» недопустим.

**2. Вывод значения в одной цепочке с вызовом, который бросает.** Вычисления внутри цепочки `<<` могут уже частично напечатать текст:

```cpp
std::cout << "[" << text << "] -> " << std::stoi(text) << "\n";
```

Для `abc` на экране окажется `[abc] -> ` без перевода строки, и только потом сработает исключение. Сначала вычислите значение в переменную, затем печатайте.

**3. Исключение выбрасывается, а `catch` нет.**

```text
libc++abi: terminating due to uncaught exception of type std::invalid_argument: плохое значение
```

(пример 4). Решение - добавить `try`/`catch` в том месте, где известно, что делать с ошибкой.

**4. Общий `catch` стоит выше частного.**

```cpp
try {
    throw std::invalid_argument("x");
} catch (const std::exception& e) {
    std::cout << e.what();
} catch (const std::invalid_argument& e) {
    std::cout << "никогда";
}
```

```text
main.cpp:8:20: warning: exception of type 'const std::invalid_argument &' will be caught by earlier handler [-Wexceptions]
```

Первый подходящий `catch` забирает исключение, до второго очередь не дойдёт. Ставьте конкретные типы выше общих.

**5. `catch` без `try`.**

```cpp
try { std::cout << "a\n"; }
std::cout << "b\n";
```

```text
main.cpp:5:5: error: expected catch
```

Блок `try` обязан сопровождаться хотя бы одним `catch`.

**6. Бросок значения, которое никто не ловит.** `throw 5;` допустим, но `catch (const std::exception&)` его не перехватит:

```text
libc++abi: terminating due to uncaught exception of type int
```

Бросайте стандартные исключения вместо чисел.

**7. Надежда, что деление на ноль даст исключение.** Целочисленное деление на ноль - неопределённое поведение. На этом компьютере с `-O2` программа `10 / zero` напечатала мусор `88642944` без каких-либо сообщений, на других системах она обычно завершается аварийно с сообщением «Floating point exception». Проверяйте делитель через `if` до деления.

## Итоги

* Исключение - сигнал об ошибке: `throw` прерывает функцию и поднимает ошибку по цепочке вызовов до подходящего `catch`.
* Код, где ожидается ошибка, оборачивают в `try`; обработчик пишут как `catch (const Тип&)`.
* `std::stoi` бросает `std::invalid_argument` (нет числа) и `std::out_of_range` (число не помещается), но игнорирует «хвост» после числа - его нужно проверять самостоятельно.
* Свои функции сообщают о плохих входных данных через `throw std::invalid_argument("...")`; текст читают через `e.what()`.
* Неперехваченное исключение аварийно завершает программу.
* Неопределённое поведение (`[]` за границей, деление на ноль) исключением не является.

Теперь у вас есть всё для работы с данными: коллекции, строки, чтение ввода и обработка ошибок. Осталось научиться объединять данные в один тип - об этом [следующий урок про первую структуру](lesson:cpp.from-zero.first-struct).

<!-- section: programmer -->
## Для тех, кто уже программирует

* Синтаксис `try`/`catch`/`throw` близок к Java и JS, но блока `finally` в C++ нет: для освобождения ресурсов используется RAII (деструкторы), его разбирает курс «Язык и стандартная библиотека».
* Исключения не обязаны наследоваться от `std::exception`: можно бросить даже `int`. На практике бросают объекты типов из `<stdexcept>`, ловят по константной ссылке (чтобы не копировать и не терять производный тип).
* Нет `checked`-исключений, как в Java: сигнатура функции не сообщает, что она может бросить.
* Стандартная библиотека бросает не везде: `operator[]`, деление на ноль, разыменование недействительного итератора - неопределённое поведение, а не исключение. Сравните: Python и Java бросают в обоих случаях.
* Исключения C++ - «нулевой стоимости» на пути без ошибки (таблицы раскрутки), но дорогие при броске. Они не предназначены для управления обычным потоком; в некоторых проектах (игры, встраиваемые системы) их отключают совсем и возвращают коды ошибок или `std::expected` (C++23, в курсе не используется из-за запасной сборки C++20).
* `stoi` останавливается на первом неверном символе, как `parseInt` в JS, но в отличие от `int()` в Python и `Integer.parseInt` в Java, которые отвергают «12abc». Более строгая альтернатива - `std::from_chars` (C++17), разбирается далее в курсе.
* Сообщения `what()` библиотечных исключений не стандартизованы: на libc++ и libstdc++ они различаются. Тесты не должны сравнивать их.

## Что происходит при броске

Это необязательный раздел: для заданий он не нужен.

Когда выполняется `throw`, программа **раскручивает стек**: для каждой функции по пути вверх уничтожаются локальные объекты (вызываются их деструкторы), затем функция покидается. Так продолжается, пока не найден подходящий `catch`; если такого нет, вызывается `std::terminate`, и программа завершается аварийно.

Это важная причина, по которой в C++ ресурсы привязывают к объектам: файл, память или замок освободятся сами при раскрутке, где бы ни случилась ошибка. Курс «Язык и стандартная библиотека» (RAII и умные указатели) строится на этом свойстве. Пока достаточно знать, что исключение - не «прыжок» (как `goto`), а аккуратный подъём по цепочке вызовов с уборкой за собой.
