## Зачем это нужно

Все предыдущие уроки учили по одному приёму. В настоящей программе они работают вместе, а данные не бывают идеальными: в файле встречаются пустые строки, пропущенные разделители, буквы вместо чисел. Хорошая программа не падает на таких строках, а аккуратно их отбрасывает и сообщает, сколько было отброшено. Этот урок - небольшой проект, где вы соберёте такую программу сами.

## Одна новая идея: разделите задачу на маленькие проверяемые шаги

Новых конструкций в уроке нет. Идея в порядке работы: не пишите всё сразу, а идите слоями, проверяя каждый.

1. **Читать.** Цикл `while (std::getline(std::cin, line))`, пустые строки пропускаются.
2. **Разрезать.** `find(';')`; если разделителя нет или имя пусто, строка плохая.
3. **Проверить значение.** `stoi`, проверка «число целиком», диапазон; ошибки превращаются в «пропущена».
4. **Сохранить.** Положить пару в `std::map`, проверив, что имени ещё нет.
5. **Подвести итоги.** Обойти словарь, посчитать сумму, лучшего, количество сдавших; напечатать в заданном формате.

Каждый слой можно проверить отдельно: сначала выведите на экран только число принятых и пропущенных строк, затем добавьте ведомость, потом итоги.

## Пример. Тот же приём на другом материале

Ниже - прототип для похожей задачи: строки вида `товар;цена`. Цена - целое неотрицательное число. Программа проверяет каждую строку и считает принятые и пропущенные. Строки заданы прямо в программе, чтобы пример запускался без ввода.

```cpp run
#include <iostream>
#include <map>
#include <stdexcept>
#include <string>
#include <vector>

int parsePrice(const std::string& text) {
    int value = std::stoi(text);
    if (std::to_string(value) != text) {
        throw std::invalid_argument("лишние символы");
    }
    if (value < 0) {
        throw std::invalid_argument("цена отрицательная");
    }
    return value;
}

int main() {
    std::vector<std::string> lines = {
        "Хлеб;40", "Молоко;95", "Сыр;abc", "Чай", ";10", "Хлеб;50", "Кефир;-3", "Яйца;120"
    };

    std::map<std::string, int> prices;
    int skipped = 0;

    for (const std::string& line : lines) {
        std::size_t pos = line.find(';');
        if (pos == std::string::npos || pos == 0) {
            skipped++;
            continue;
        }
        std::string name = line.substr(0, pos);
        if (prices.count(name) == 1) {
            skipped++;
            continue;
        }
        try {
            prices[name] = parsePrice(line.substr(pos + 1));
        } catch (const std::exception&) {
            skipped++;
        }
    }

    for (const auto& [name, price] : prices) {
        std::cout << name << " - " << price << "\n";
    }
    std::cout << "Принято: " << prices.size() << "\n";
    std::cout << "Пропущено: " << skipped << "\n";
}
```
```output
Молоко - 95
Хлеб - 40
Яйца - 120
Принято: 3
Пропущено: 5
```

Разбор:

* `Сыр;abc` отбрасывается из-за `stoi`: исключение перехвачено блоком `catch`, строка засчитана как пропущенная.
* `Чай` - разделителя нет, `find` вернул `std::string::npos`. Проверка стоит **до** `substr`, иначе получился бы тихий неверный результат (урок 21).
* `;10` - имя пусто (`pos == 0`).
* Второй `Хлеб;50` - имя уже есть среди принятых.
* `Кефир;-3` отвергнут правилом диапазона внутри `parsePrice`.
* Словарь выводится по алфавиту, поэтому `Молоко` стоит раньше `Хлеба`.

Заметьте порядок проверок: самые дешёвые и самые вероятные идут первыми, а всё, что может бросить исключение, заключено в `try`. Теперь ту же схему нужно приложить к ведомости оценок из упражнения и добавить итоги.

**Попробуйте.** Сначала решите упражнение «на скелете»: в `main` сделайте только чтение и счётчики и сравните с тестом `empty` и `allbad`. Затем добавьте разбор, потом итоги. Когда все публичные тесты пройдут, придумайте свои крайние случаи: строку из одной `;`, два одинаковых имени подряд, имя с пробелами по краям.

## Точные правила

Подробная постановка - в условии упражнения. Ниже - то, на что стоит обратить внимание.

* **Что считается строкой.** Строка ввода - всё до перевода строки; пустая строка не принимается и не считается пропущенной (`if (line.empty()) { continue; }`).
* **Порядок проверок важен.** Сначала формат (`;` и имя), затем повтор имени, затем число. Строка `Анна;70`, где `Анна` уже принята, пропускается независимо от числа; строка `Борис;abc` пропускается из-за числа.
* **Что считается числом.** Целое в обычной записи: `85`, `0`, `100`. Недопустимы `+5`, ` 80`, `085`, `7x`, пустое значение, а также `101`, `-5` (вне диапазона) и числа, не помещающиеся в `int`.
* **Повтор имени** проверяется только среди **принятых** строк: если первая `Анна;abc` была плохой, то вторая `Анна;70` принимается.
* **Имя** - всё до первого `;`. В строке `Мила;Лаптева;90` имя `Мила`, а значением оказывается `Лаптева;90`, которое числом не является.
* **Итоги** зависят от наличия принятых записей. Если их нет, деления на ноль быть не должно, и три последние строки не печатаются.
* **Среднее** - вещественное число: `static_cast<double>(sum) / static_cast<double>(count)` и вывод через `std::fixed << std::setprecision(2)`.
* **Лучший** - запись с наибольшим баллом; при равенстве выигрывает первая в порядке обхода словаря (строгое `>`).
* Ввод может не заканчиваться переводом строки: последняя строка всё равно читается.

## Типичные ошибки

Тексты сообщений получены от Apple clang 21 с ключами курса.

**1. Работа с `substr(pos + 1)` до проверки `npos`.** Строка `Чай` без разделителя даст `pos == npos`, а `pos + 1` равно `0`, и `substr` молча вернёт всю строку (урок 21). Тест не упадёт, но ответ будет неверным.

**2. Положиться на `stoi` целиком.** `7x` и `12abc` проходят как `7` и `12`. Нужна проверка `std::to_string(value) != text`.

**3. Перевёрнутое условие повтора.** `scores.count(name) == 0` вместо `== 1`: пропускаются все новые имена. Прочтите условие вслух: «если имя уже есть - пропустить».

**4. Запись в словарь до проверки числа.** Если написать `scores[name] = ...` до разбора и разбор бросит исключение, имя уже окажется в словаре с нулевым баллом. Присваивание `scores[name] = parseScore(...)` безопасно: правая часть вычисляется первой, и при исключении запись в словарь не выполняется.

**5. Деление на ноль при пустой ведомости.** Для пустого вывода `sum / count` при целых `count == 0` - неопределённое поведение, при вещественных - нечисловое значение `nan`. Проверяйте `scores.empty()` до подсчёта среднего.

**6. Целочисленное деление среднего.** `sum / scores.size()` отбрасывает дробную часть (урок 6), а `scores.size()` ещё и беззнаковое. Приводите оба числа к `double`.

**7. Лишний `\n` или другой регистр слов в выводе.** Тесты сравнивают текст точно. Слова «Принято», «Пропущено», «Лучший», «Среднее» и «Сдали» пишутся ровно так, как в условии.

**8. Нет `#include <iomanip>`.**

```text
main.cpp:12:30: error: no member named 'setprecision' in namespace 'std'
```

Манипуляторы `setprecision` и `setw` живут в заголовке `<iomanip>` (урок 10).

## Итоги

* Законченная программа складывается из уже знакомых частей: чтение, разбор, проверка, хранение и итоги.
* Плохие данные - обычная ситуация: их проверяют, считают и пропускают, не роняя программу.
* Порядок проверок и точные правила формата важнее хитрых приёмов: сначала формат, потом повторы, потом значение.
* Крайние случаи (пустой ввод, все строки плохие, равные баллы, границы диапазона) нужно проверить самому.

На этом курс «C++ с нуля» заканчивается. ## Для тех, кто уже программирует

* Задача - классический «разбор строк с ошибками»: на Python это пара `try/except ValueError` и словарь, на Java - `Map<String, Integer>` и `NumberFormatException`, на Go - `strconv.Atoi` с возвратом ошибки.
* Ключевое отличие C++: проверка «число целиком» не встроена в `std::stoi`. Строгая альтернатива без исключений - `std::from_chars` из `<charconv>` (C++17): она возвращает код ошибки и позицию, где разбор остановился.
* Здесь используется `std::map` ради упорядоченного вывода. Если порядок не нужен, `std::unordered_map` быстрее.
* Для разбора строки по разделителю часто используют `std::istringstream` и `std::getline(stream, part, ';')`, но для одного разделителя `find`/`substr` проще и не требует потоков.
* Исключения как механизм «плохая строка» удобны, но на «горячем пути» (миллионы строк, из которых много плохих) дороги. Тогда проверку формата делают без исключений: `from_chars` или ручной разбор.
* Структура `Student` из урока 23 здесь не нужна: пары «имя - балл» хватает `std::map<std::string, int>`. Когда у записи появляется третье и четвёртое поле, словарь значений - структуры станет естественным решением.

## Как проверять такие программы

Это необязательный раздел: для заданий он не нужен.

Чем сложнее разбор, тем важнее набор тестов. Полезная привычка: прежде чем запускать программу на «настоящих» данных, составьте таблицу случаев «вход - ожидаемый результат» и пройдите по ней. Типичные группы:

* **нормальные данные** - несколько корректных строк;
* **крайние значения** - 0, 100, 101, -1, пустая строка, очень длинное число;
* **структура** - нет разделителя, два разделителя, пустое имя, пустое значение;
* **повторы** и порядок;
* **пустой ввод** и ввод без перевода строки в конце.

Автоматические тесты в этом курсе устроены так же: каждая группа - отдельный тест. Когда программа растёт, такие таблицы переносят в код (в виде тестов с библиотекой вроде GoogleTest) и запускают после каждого изменения. Курс «C++: первые шаги» покажет, как собирать программу из нескольких файлов, где тестам уже будет место.
