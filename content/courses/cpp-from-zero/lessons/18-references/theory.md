## Зачем это нужно

В прошлом уроке вы выяснили: параметр функции - копия аргумента, и изменение копии не затрагивает переменную в `main`. Обычно это удобно: функция не может испортить чужие данные. Но иногда копирование мешает:

* функция должна **изменить** переменную вызывающего (поменять два числа местами, увеличить цену);
* функция получает длинную строку или большую коллекцию, и копировать её при каждом вызове расточительно.

Для обоих случаев в C++ есть **ссылки**.

## Одна новая идея: ссылка - второе имя той же переменной

Если в заголовке функции после типа параметра поставить `&`, параметр становится **ссылкой**: не копией, а вторым именем переменной, которую передали:

```cpp
void addOne(int& n) {
    n = n + 1;
}
```

После `int x = 7; addOne(x);` внутри функции `n` и `x` - одна и та же переменная, поэтому `x` станет 8.

Три способа передать параметр запомните как таблицу:

| Запись | Что происходит | Когда использовать |
|---|---|---|
| `int n` | копия | функция только считает по значению; числа, `bool`, `char` |
| `int& n` | второе имя, можно менять | функция должна изменить переменную вызывающего |
| `const std::string& s` | второе имя, менять нельзя | функция только читает строку, копировать её незачем |

Слово `const` (урок 5) в `const std::string&` запрещает функции менять параметр. Получается безопасно (случайного изменения не будет) и быстро (копии нет).

## Пример 1. По значению и по ссылке

```cpp run
#include <iostream>

void byValue(int n) {
    n = n + 1;
}

void byReference(int& n) {
    n = n + 1;
}

int main() {
    int x = 7;
    byValue(x);
    std::cout << "После byValue: " << x << "\n";
    byReference(x);
    std::cout << "После byReference: " << x << "\n";
}
```
```output
После byValue: 7
После byReference: 8
```

Единственное отличие функций - символ `&` в заголовке. Вызов выглядит одинаково: `byReference(x)`, без особых знаков.

## Пример 2. Поменять местами

```cpp run
#include <iostream>

void swapInts(int& a, int& b) {
    int temp = a;
    a = b;
    b = temp;
}

int main() {
    int left = 3;
    int right = 8;
    swapInts(left, right);
    std::cout << left << " " << right << "\n";
}
```
```output
8 3
```

Временная переменная `temp` запоминает первое значение, пока оно не затёрлось. Так как `a` и `b` - вторые имена `left` и `right`, меняются именно переменные в `main`. Без `&` функция поменяла бы местами копии, и ничего бы не произошло.

## Пример 3. Выходные параметры

```cpp run
#include <iostream>

void divide(int a, int b, int& quotient, int& remainder) {
    quotient = a / b;
    remainder = a % b;
}

int main() {
    int q = 0;
    int r = 0;
    divide(17, 5, q, r);
    std::cout << "17 = 5 * " << q << " + " << r << "\n";
}
```
```output
17 = 5 * 3 + 2
```

Функция `return` может вернуть только одно значение. Когда результатов два, их передают в виде ссылок: переменные `q` и `r` служат «пустыми ящиками», которые функция заполняет. Такие параметры называют **выходными**. (В уроке 23 вы увидите более аккуратный способ: структуру.)

## Пример 4. Константная ссылка для строк

```cpp run
#include <iostream>
#include <string>

std::size_t countVowels(const std::string& text) {
    std::size_t count = 0;
    for (std::size_t i = 0; i < text.size(); i++) {
        char c = text[i];
        if (c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u') {
            count++;
        }
    }
    return count;
}

int main() {
    std::string word = "education";
    std::cout << word << ": " << countVowels(word) << "\n";
    std::cout << countVowels("rhythm") << "\n";
}
```
```output
education: 5
0
```

Разбор:

* `const std::string&` читается «ссылка на строку, которую нельзя менять». Строка не копируется, и функция не может её испортить.
* Константной ссылке можно передать и переменную (`word`), и литерал (`"rhythm"`): временную строку создаёт компилятор. Обычной ссылке `int&` литерал передать нельзя.

**Попробуйте.** Напишите функцию `void toZero(int& n)`, которая записывает ноль в переменную. Напишите `void minMax(int a, int b, int& smaller, int& bigger)`. Передайте `std::string` в функцию как `std::string s` и как `const std::string& s` и убедитесь, что внешне они работают одинаково. Затем в функции с `const` попробуйте изменить параметр и прочитайте сообщение компилятора.

## Точные правила

* **Передача по значению:** `void f(int n)`. Аргумент копируется; изменение параметра не затрагивает аргумент. Подходит для чисел, `bool`, `char`.
* **Ссылка:** `void f(int& n)`. Параметр - другое имя той же переменной. Аргумент должен быть переменной (или другим изменяемым объектом), литерал и результат выражения не подойдут.
* **Константная ссылка:** `void f(const std::string& s)`. Параметр читается, но не изменяется. Аргументом может быть и переменная, и литерал, и результат выражения.
* **Выбор по правилу:** для маленьких значений (`int`, `double`, `bool`, `char`) - копия; для `std::string` и коллекций, которые функция только читает, - `const T&`; для переменных, которые функция должна изменить, - `T&`.
* Ссылка должна быть связана с переменной сразу при создании и навсегда остаётся связанной с ней; пустых ссылок не бывает.
* Функция не должна возвращать ссылку на локальную переменную или параметр-копию: объект исчезнет при выходе из функции, и обращение к нему станет неопределённым поведением. Возвращайте значение: `std::string makeName()`.
* Ссылка в заголовке не меняет способа вызова: пишут `swapInts(a, b)`, а не `swapInts(&a, &b)` (такой синтаксис относится к указателям, это другая тема).
* Объявить обычную ссылочную переменную можно (`int& alias = x;`), но в этом курсе ссылки нужны в основном для параметров.
* Если функция с `T&` скрытно изменяет аргумент, это сюрприз для читателя. Дайте функции имя, которое подсказывает изменение (`addTax`, `swapInts`), и описывайте это в комментарии.

## Типичные ошибки

Тексты сообщений получены от Apple clang 21 с ключами курса.

**1. Литерал вместо переменной.**

```cpp
void bump(int& n) { n = n + 1; }

bump(5);
```

```text
main.cpp:18:5: error: no matching function for call to 'bump'
   18 |     bump(5);
      |     ^~~~
main.cpp:4:6: note: candidate function not viable: expects an lvalue for 1st argument
    4 | void bump(int& n) {
      |      ^    ~~~~~~
```

Ссылке нужна переменная («lvalue»): у числа `5` нет места, куда можно записать результат.

**2. Другой тип переменной.**

```cpp
double d = 2.5;
bump(d);
```

```text
main.cpp:22:5: error: no matching function for call to 'bump'
   22 |     bump(d);
      |     ^~~~
main.cpp:4:6: note: candidate function not viable: no known conversion from 'double' to 'int &' for 1st argument
    4 | void bump(int& n) {
      |      ^    ~~~~~~
```

Ссылка `int&` связывается только с настоящей переменной типа `int`: преобразование типа создало бы копию, а смысл ссылки - работать с оригиналом.

**3. Попытка изменить `const`-параметр.**

```cpp
void change(const int& n) {
    n = 1;
}
```

```text
main.cpp:5:7: error: cannot assign to variable 'n' with const-qualified type 'const int &'
    5 |     n = 1;
      |     ~ ^
main.cpp:4:24: note: variable 'n' declared const here
    4 | void change(const int& n) {
      |             ~~~~~~~~~~~^
```

Для `const std::string&` сообщение длиннее: перечисляются все варианты `=` или `+=`, не подходящие к константной строке. Смысл тот же: `const` защитил значение. Если функция должна менять параметр, уберите `const`; если нет, измените логику.

**4. Ссылка без переменной.**

```text
main.cpp:20:10: error: declaration of reference variable 'r' requires an initializer
   20 |     int& r;
      |          ^
```

Ссылка не может существовать «пустой»: при создании ей нужна переменная, к которой она привязана.

**5. Возврат ссылки на локальную переменную.**

```cpp
const std::string& makeName() {
    std::string local = "Anna";
    return local;
}
```

```text
main.cpp:10:12: warning: reference to stack memory associated with local variable 'local' returned [-Wreturn-stack-address]
   10 |     return local;
      |            ^~~~~
```

Это предупреждение указывает на неопределённое поведение: после выхода из функции `local` уничтожена, и ссылка «висит» на мёртвую память. Верните строку значением: `std::string makeName()`.

**6. Лишняя копия длинной строки.** `void print(std::string s)` вместо `const std::string& s` работает, но копирует строку при каждом вызове. Ошибки не будет, но для длинных текстов и вызовов в цикле это ощутимо.

**7. Незаметное изменение аргумента.** Если параметр `int& n` случайно изменён в функции, который «только считает», переменная вызывающего поменяется. Ставьте `&` только осознанно.

## Итоги

* Обычный параметр - копия: функция не меняет переменную вызывающего.
* `T&` - второе имя переменной: функция может её менять. Аргументом должна быть настоящая переменная того же типа.
* `const T&` - чтение без копирования и без права менять; идеальный выбор для строк и коллекций, которые функция только читает.
* Числа, `bool` и `char` передают по значению.
* Не возвращайте ссылку на локальную переменную.

Теперь у вас есть всё, чтобы работать с наборами значений. Следующий шаг - [вектор](lesson:cpp.from-zero.vector), который хранит много значений одного типа и растёт по мере необходимости.

## Для тех, кто уже программирует

* В Java, Python, JavaScript и C# объекты передаются «по ссылке на объект»: функция видит тот же объект, но не может переназначить переменную вызывающего. В C++ по умолчанию **всё** копируется, в том числе строки и контейнеры. Чтобы работать с оригиналом, нужна явная ссылка.
* `const T&` - стандартный способ передать «только для чтения» без копии. Аналог в других языках не нужен, потому что там объекты и так общие, но защиты от изменений нет.
* `T&` для выходных параметров встречается реже, чем `out`/`ref` в C# или возврат нескольких значений в Go и Python. В современном C++ несколько результатов чаще возвращают структурой (урок 23), `std::pair` или `std::tuple`.
* Ссылка не может быть `null` и не может быть переназначена: это отличает её от указателя. Присваивание `ref = other;` копирует значение в оригинал, а не перенаправляет ссылку.
* Привязка временного значения (`foo(5)`) допустима только к `const T&` (и к `T&&`, ссылкам на временные, которые здесь не рассматриваются). Временное значение живёт до конца выражения, а у `const` ссылки, ставшей переменной, - до конца её области видимости.
* Для маленьких типов (`int`, `char`, `double`) копия быстрее и проще ссылки: передача по `const int&` не даёт выигрыша.
* Висящие ссылки (на локальные переменные, на элементы контейнера после его роста) - один из главных источников неопределённого поведения в C++. Санитайзеры и предупреждения компилятора ловят часть таких случаев.

## Как реализуется ссылка

Это необязательный раздел: для заданий он не нужен.

Для программиста ссылка - второе имя переменной, но компилятор обычно реализует её через адрес: в параметр записывается местоположение оригинала, а каждое обращение `n` превращается в обращение по этому адресу. Поэтому передача `const std::string&` стоит столько же, сколько передача одного числа (адреса), а не копирование всех символов. При встраивании функции компилятор часто убирает и этот адрес, подставляя прямую работу с оригиналом.

Из этого устройства следуют правила безопасности. Объект, на который указывает ссылка, должен прожить дольше, чем ссылка: иначе в ней останется адрес освобождённой памяти. Именно это нарушает возврат ссылки на локальную переменную. Тема сроков жизни объектов, перемещения и умных указателей - в курсе «C++: первые шаги» и в курсе «Язык и стандартная библиотека».
