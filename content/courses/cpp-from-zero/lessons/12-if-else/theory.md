## Зачем это нужно

До сих пор программа выполняла все команды по порядку сверху вниз, и каждая выполнялась ровно один раз. Настоящие программы так не работают: они выбирают. Покупателю до 1000 рублей скидка не положена, а свыше 5000 положена другая; пароль подошёл или нет; температура требует куртки или нет. В этом уроке вы научитесь писать такие развилки: **условную команду** `if`.

## Одна новая идея: условие выбирает, выполнять ли блок

В прошлом уроке вы получили значения типа `bool`. Команда `if` берёт такое значение и решает, выполнять ли следующий за ним **блок** - несколько команд в фигурных скобках `{ }`:

```cpp
if (temperature < 10) {
    std::cout << "Наденьте куртку\n";
}
```

Если `temperature < 10` истинно, блок выполняется. Если ложно, он пропускается, и программа идёт дальше. К `if` можно добавить `else` («иначе»): тогда выполнится ровно один из двух блоков:

```cpp
if (temperature < 10) {
    std::cout << "Куртка\n";
} else {
    std::cout << "Без куртки\n";
}
```

Вариантов может быть больше двух. Тогда условия выстраивают в цепочку `if / else if / else`: компьютер проверяет их сверху вниз, находит первое истинное, выполняет его блок и **пропускает всё остальное**. Ветка `else` в конце ловит все случаи, которые не подошли ни под одно условие.

Фигурные скобки группируют команды в один блок. Их полезно писать всегда, даже когда в ветке всего одна команда: так добавленная позже вторая команда гарантированно окажется в той же ветке.

<!-- section: examples -->
## Пример 1. Две ветки

```cpp run
#include <iostream>

int main() {
    int temperature = 7;
    if (temperature < 10) {
        std::cout << "Куртка\n";
    } else {
        std::cout << "Без куртки\n";
    }
    std::cout << "Хорошего дня\n";
}
```
```output
Куртка
Хорошего дня
```

Разбор:

* `temperature < 10` истинно, поэтому выполнен блок после `if`, а блок `else` пропущен.
* Последняя строка стоит после `}` и выполняется в любом случае: она не входит ни в одну ветку.

## Пример 2. Цепочка else if

```cpp run
#include <iostream>
#include <string>

int main() {
    int score = 72;
    std::string grade = "";
    if (score >= 90) {
        grade = "отлично";
    } else if (score >= 70) {
        grade = "хорошо";
    } else if (score >= 50) {
        grade = "удовлетворительно";
    } else {
        grade = "неудовлетворительно";
    }
    std::cout << score << ": " << grade << "\n";
}
```
```output
72: хорошо
```

Разбор:

* `72 >= 90` ложно, `72 >= 70` истинно: переменной `grade` присваивается «хорошо», остальные условия не проверяются.
* Поэтому второе условие не пишут как `score >= 70 && score < 90`: верхний предел уже отсечён первой проверкой. Порядок условий - от самого строгого к самому мягкому.
* Переменная `grade` объявлена **до** `if` с пустой строкой: она нужна и внутри веток (там ей присваивают), и после них (там её печатают). Переменная, объявленная внутри блока, снаружи не видна.

## Пример 3. Условие из нескольких частей

```cpp run
#include <iostream>

int main() {
    int age = 16;
    bool hasTicket = true;
    if (age >= 18 && hasTicket) {
        std::cout << "Проходите\n";
    } else if (age < 18 && hasTicket) {
        std::cout << "Нужен взрослый\n";
    } else {
        std::cout << "Купите билет\n";
    }
}
```
```output
Нужен взрослый
```

Условие может быть любым выражением типа `bool`, в том числе с `&&`, `||` и `!`. Переменная типа `bool` уже готовое условие: пишут `if (hasTicket)`, а не `if (hasTicket == true)`.

## Пример 4. Блок можно вкладывать

```cpp run
#include <iostream>
#include <string>

int main() {
    std::string name = "";
    int hour = 14;
    if (name.empty()) {
        std::cout << "Имя не указано\n";
    } else {
        if (hour < 12) {
            std::cout << "Доброе утро, " << name << "\n";
        } else {
            std::cout << "Добрый день, " << name << "\n";
        }
    }
}
```
```output
Имя не указано
```

`name.empty()` (урок 7) возвращает `true` для пустой строки. Внутри `else` может стоять ещё один `if`; но если вложенность растёт, обычно лучше переписать условие через `&&` или цепочку `else if`.

**Попробуйте.** Поставьте `score = 90`, затем `89`: убедитесь, что граница работает так, как вы ожидаете. Поменяйте порядок первых двух проверок местами (`score >= 70` перед `score >= 90`) и объясните, почему результат для 95 станет неправильным. Затем уберите `{ }` вокруг одной из веток и добавьте в неё вторую команду.

## Точные правила

* Форма: `if (условие) { ... }`, при необходимости `else { ... }` или `else if (условие) { ... }`. Условие всегда в круглых скобках.
* Условие преобразуется к `bool`: ноль - ложь, любое другое число - истина. Не пользуйтесь этим для сравнений: пишите `if (n != 0)`, а не `if (n)`.
* Фигурные скобки задают **блок**. Без них к `if` относится ровно **одна** следующая команда, а отступы на выполнение не влияют.
* **Область видимости.** Переменная, объявленная внутри блока, существует только до закрывающей `}`. Переменную, которую нужно использовать и в ветках, и после них, объявляют до `if`.
* Цепочка `if / else if / else` выполняет **не больше одной** ветки (ровно одну, если есть завершающий `else`). Порядок условий важен: выполняется первая подходящая ветка.
* Если у переменной нет начального значения и ни одна ветка не присвоила ей значение, читать её нельзя: это неопределённое поведение (урок 4). Давайте начальное значение до `if`.
* Присваивание `x = 5` в условии допустимо, но почти всегда означает опечатку вместо `x == 5`. Компилятор предупреждает: `using the result of an assignment as a condition`.
* Точка с запятой сразу после `if (...)` - пустая команда: она и является телом `if`, а следующий блок выполняется всегда.
* Условие с дробными числами читается так же, но `==` для `double` использовать нельзя (урок 11).

## Типичные ошибки

Предупреждения ниже получены от Apple clang 21 с ключами курса. Компилятор g++ формулирует их иначе, но указывает то же место.

**1. `=` вместо `==`.**

```cpp
int x = 3;
if (x = 5) {
    std::cout << "пять\n";
}
```

```text
main.cpp:5:11: warning: using the result of an assignment as a condition without parentheses [-Wparentheses]
    5 |     if (x = 5) {
      |         ~~^~~
main.cpp:5:11: note: use '==' to turn this assignment into an equality comparison
    5 |     if (x = 5) {
      |           ^
      |           ==
```

Ветка выполнится всегда, а переменная `x` будет испорчена: теперь в ней `5`. Компилятор подсказывает, как исправить.

**2. Точка с запятой после условия.**

```cpp
if (x > 3);
{
    std::cout << "больше\n";
}
```

```text
main.cpp:8:15: warning: if statement has empty body [-Wempty-body]
    8 |     if (x > 3);
      |               ^
main.cpp:8:15: note: put the semicolon on a separate line to silence this warning
```

Условие проверяется, но тело у `if` пустое. Блок со словом «больше» теперь выполняется при любом `x`.

**3. Вторая команда без скобок.**

```cpp
if (x > 100)
    std::cout << "a\n";
    std::cout << "b\n";
```

```text
main.cpp:14:9: warning: misleading indentation; statement is not part of the previous 'if' [-Wmisleading-indentation]
   14 |         std::cout << "b\n";
      |         ^
main.cpp:12:5: note: previous statement is here
   12 |     if (x > 100)
      |     ^
```

Отступ создаёт впечатление, что обе строки относятся к `if`. Для компилятора это не так: «b» печатается всегда. Фигурные скобки вокруг ветки убирают двусмысленность.

**4. Переменная без значения в одной из веток.**

```cpp
int y;
if (x > 1) y = 1;
std::cout << y << "\n";
```

```text
main.cpp:16:9: warning: variable 'y' is used uninitialized whenever 'if' condition is false [-Wsometimes-uninitialized]
   16 |     if (x > 1) y = 1;
      |         ^~~~~
main.cpp:15:10: note: initialize the variable 'y' to silence this warning
   15 |     int y;
      |          ^
      |           = 0
```

Если `x > 1` ложно, `y` остаётся с мусором, а чтение мусора - неопределённое поведение (урок 4). Лечится начальным значением: `int y = 0;`.

**5. Неверный порядок условий.** Цепочка `if (score >= 50) ... else if (score >= 90) ...` никогда не дойдёт до второй проверки: любое число от 90 и выше уже подошло под первую. Предупреждения здесь нет, ошибку находят только тесты.

**6. Лишнее сравнение с `true`.** `if (ready == true)` работает, но читается хуже, чем `if (ready)`. Ошибкой это не считается, но в коде не принято.

## Итоги

* `if (условие) { ... }` выполняет блок, если `bool`-условие истинно; `else` - если ложно.
* Цепочка `if / else if / else` проверяет условия сверху вниз и выполняет **одну** первую подходящую ветку: порядок условий важен.
* Фигурные скобки пишите всегда. Без них к `if` относится только одна команда, отступы ничего не значат.
* Переменную, которая нужна и в ветках, и после них, объявляйте до `if` и сразу с начальным значением.
* `=` присваивает, `==` сравнивает; точка с запятой после `if (...)` превращает тело в пустое.

Когда вариантов много и все они - конкретные значения одной переменной, цепочка `else if` становится длинной. Для такого случая есть более компактная команда: [switch](lesson:cpp.from-zero.switch).

<!-- section: programmer -->
## Для тех, кто уже программирует

* Синтаксис как в Java, C#, JavaScript: условие в круглых скобках, блок в фигурных; ключевого слова `then` нет, `elif` пишется как `else if` (в отличие от Python). Отступы значения не имеют.
* В условии допустимо любое число (скаляр): `0` - ложь, остальное - истина. Строки и контейнеры так не проверяются: пустую строку проверяют `s.empty()`.
* Условие `if (x = 5)` в Java и C# не компилируется, в C++ компилируется (с предупреждением). Включайте `-Wall -Wextra` и читайте их.
* Начиная с C++17 в `if` можно объявить переменную, видимую только внутри: `if (int n = f(); n > 0) { ... }`. Это сокращает область видимости.
* В C++17 есть `if constexpr` для проверок во время компиляции (шаблоны), в этом курсе не нужен. В C++23 есть ещё `if consteval`.
* Тернарное выражение `условие ? a : b` есть, как в Java и JavaScript. Оба варианта должны приводиться к общему типу.
* `else` относится к ближайшему `if` слева. Это источник «висящего else»: фигурные скобки снимают вопрос.

## Что стоит за `if` и как компилятор его оптимизирует

Это необязательный раздел: для заданий он не нужен.

На уровне процессора `if` превращается в **условный переход**: сравнение выставляет флаги, а следующая команда либо переходит в другое место программы, либо нет. Современные процессоры угадывают, куда пойдёт переход, ещё до его выполнения (предсказание ветвлений), поэтому предсказуемые `if` почти бесплатны, а непредсказуемые в самом горячем цикле заметны в измерениях. При включённой оптимизации (`-O2`) компилятор вправе заменить небольшой `if` на ветвление без перехода, переставить ветки или убрать проверку, которая заведомо истинна.

Именно поэтому неопределённое поведение так опасно рядом с `if`: если из кода следует, что переменная ни при каком допустимом ходе событий не может быть, например, отрицательной, компилятор вправе выкинуть проверку «на всякий случай». Разбор неопределённого поведения - в курсе «C++: первые шаги» и в «Язык и стандартная библиотека».
