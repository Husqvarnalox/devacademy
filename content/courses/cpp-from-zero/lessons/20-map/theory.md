## Зачем это нужно

Вектор находит значение по номеру: «третий элемент». Но часто номер не подходит. Какая цена у яблок? Сколько раз слово «кот» встретилось в тексте? Какой балл у студента Иванова? Нужна коллекция, где значение ищется по **имени**, и для этого есть **словарь**: `std::map`.

## Одна новая идея: словарь хранит пары «ключ - значение»

Словарь - набор записей. У каждой записи есть **ключ** (по нему ищут) и **значение** (его хранят). Ключи не повторяются. В угловых скобках указывают два типа: `std::map<std::string, int>` читается как «словарь, где ключ - строка, а значение - целое».

```cpp
std::map<std::string, int> price;
price["apple"] = 50;       // запись: ключ "apple", значение 50
price["pear"] = 80;
std::cout << price["apple"];   // 50
```

Квадратные скобки здесь принимают не номер, а ключ. Если записать по ключу, который уже есть, значение **заменится**.

Обойти словарь можно знакомым range-for. На каждом шаге вы получаете сразу пару, и её удобно разложить на ключ и значение:

```cpp
for (const auto& [name, cost] : price) {
    std::cout << name << " " << cost << "\n";
}
```

Здесь два новых элемента:

* `auto` - «компилятор, подставь тип сам». Он знает, что элементы словаря - пары «строка + число», и сам подберёт нужный тип. Мы используем `auto` только в этом обходе: написать полный тип пары вручную громоздко.
* `[name, cost]` - запись, которая «раскладывает» пару на две переменные.

Словарь всегда хранит ключи **по порядку** (строки - по алфавиту, числа - по возрастанию), и обход идёт именно в этом порядке.

## Пример 1. Запись, чтение, размер

```cpp run
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> price;
    price["pear"] = 80;
    price["apple"] = 50;
    price["apple"] = 55;

    std::cout << "Записей: " << price.size() << "\n";
    std::cout << "Яблоки: " << price["apple"] << "\n";

    for (const auto& [name, cost] : price) {
        std::cout << name << " = " << cost << "\n";
    }
}
```
```output
Записей: 2
Яблоки: 55
apple = 55
pear = 80
```

Разбор:

* Ключ `apple` записан дважды: второе значение заменило первое, новой записи не появилось.
* Груша добавлена раньше яблока, но обход начинается с `apple`: словарь упорядочен по ключам.

## Пример 2. Подсчёт: частоты слов

```cpp run
#include <iostream>
#include <map>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> words = {"кот", "пёс", "кот", "кот", "пёс", "рыба"};
    std::map<std::string, int> counts;
    for (const std::string& w : words) {
        counts[w]++;
    }
    for (const auto& [word, n] : counts) {
        std::cout << word << ": " << n << "\n";
    }
}
```
```output
кот: 3
пёс: 2
рыба: 1
```

Это главный приём словарей: `counts[w]++`. При первом обращении к новому ключу словарь создаёт запись со значением по умолчанию (`0` для числа) и возвращает его; затем `++` увеличивает. Не нужно проверять, видели ли вы слово раньше.

## Пример 3. Ловушка: чтение создаёт ключ

```cpp run
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> stock = {{"apple", 5}, {"pear", 2}};

    std::cout << stock.count("plum") << " " << stock.size() << "\n";
    int n = stock["plum"];
    std::cout << n << " " << stock.size() << "\n";

    if (stock.count("fig") == 0) {
        std::cout << "фиг не найден\n";
    }
    std::cout << stock.size() << "\n";
}
```
```output
0 2
0 3
фиг не найден
3
```

Разбор:

* `count("plum")` честно отвечает: `0` записей с таким ключом, словарь не меняется.
* `stock["plum"]` ничего не находит, поэтому **создаёт** запись `plum` со значением `0`: размер вырос с 2 до 3. Просто посмотреть значение таким способом нельзя.
* `count("fig") == 0` проверяет наличие и словарь не трогает: размер остался 3.

## Пример 4. `at()` вместо `[]`

Следующий фрагмент не запускается в примерах. Он читает отсутствующий ключ методом `at`.

```cpp
std::map<std::string, int> stock = {{"apple", 5}};
std::cout << stock.at("pear") << "\n";
```

```text
libc++abi: terminating due to uncaught exception of type std::out_of_range: map::at:  key not found
```

Метод `at` ничего не создаёт: если ключа нет, он бросает исключение `std::out_of_range`. Для читателя это лучше тихого появления нулей. В g++ сообщение другое, но называет то же исключение. Перехватывать исключения вы научитесь в уроке 22.

**Попробуйте.** Посчитайте, сколько раз встречается каждая буква в слове «programming». Составьте словарь «страна - столица», запросите столицу через `count` и `at`. Прочитайте числа до конца ввода и найдите то, что встретилось чаще всего (обходом словаря).

## Точные правила

* Подключается заголовок `<map>`. Тип: `std::map<тип_ключа, тип_значения>`.
* Создание: `std::map<std::string, int> m;` - пустой; `std::map<std::string, int> m = {{"a", 1}, {"b", 2}};` - с записями.
* **`m[key]`** возвращает ссылку на значение. Если ключа нет, создаёт запись со значением по умолчанию (`0` для чисел, пустая строка для `std::string`, `false` для `bool`). Присваивание `m[key] = v` создаёт или заменяет значение.
* **`m.at(key)`** возвращает значение, не создавая записей; для отсутствующего ключа бросает `std::out_of_range`.
* **`m.count(key)`** возвращает `1`, если ключ есть, иначе `0`. Для проверки наличия используйте именно его (или `find`, который разбирается позже).
* **`m.size()`** - число записей, **`m.empty()`** - пуст ли словарь, **`m.erase(key)`** - удалить запись по ключу.
* Порядок обхода - по возрастанию ключей. Строки сравниваются по кодам байтов: заглавные латинские буквы идут раньше строчных (`Hi` раньше `hi`), а русские слова упорядочиваются по кодировке UTF-8.
* Каждый ключ встречается один раз; значения могут повторяться.
* `auto` (тип выводится из инициализатора) нужен в обходе словаря: `for (const auto& [key, value] : m)`. Запись `const auto&` означает «не копируй и не меняй». Если значение нужно менять, уберите `const`: `for (auto& [key, value] : m)`.
* Ключ нельзя менять: он определяет положение записи в упорядоченном словаре.
* Словарь можно передавать в функцию как `const std::map<std::string, int>&` (чтение) или `std::map<std::string, int>&` (изменение).
* Доступ к записи по ключу занимает время, растущее медленно (в словаре из миллиона записей это порядка двадцати сравнений). Для хешированного словаря существует `std::unordered_map`, который разбирается в курсе «Язык и стандартная библиотека».

## Типичные ошибки

Тексты сообщений получены от Apple clang 21 с ключами курса.

**1. Чтение через `[]` меняет словарь.** Пример 3: проверка `stock["plum"] == 0` добавила запись. Проверяйте наличие через `count`, читайте через `at`.

**2. Нет `#include <map>`.**

```text
main.cpp:5:10: error: no template named 'map' in namespace 'std'; did you mean 'max'?
```

За этим сообщением следует несколько побочных ошибок (`use of undeclared identifier 'm'`): компилятор не понял объявление и дальше ругается на все обращения к `m`. Исправляйте первую ошибку, остальные чаще всего исчезнут сами (урок 2). В g++ сообщение: `'map' is not a member of 'std'`.

**3. Значение не того типа.**

```cpp
std::map<std::string, int> m;
m["a"] = "x";
```

```text
main.cpp:7:14: error: assigning to 'mapped_type' (aka 'int') from incompatible type 'const char[2]'
```

Значение должно подходить к типу словаря. Имя `mapped_type` - тип значения в стандартной библиотеке.

**4. Попытка изменить значение через константную ссылку.**

```cpp
for (const auto& [k, v] : m) {
    v = 3;
}
```

```text
main.cpp:9:11: error: cannot assign to variable 'v' with const-qualified type 'std::tuple_element<1, const std::pair<const std::string, int>>::type' (aka 'const int')
```

Длинное имя типа говорит главное: это `const int`. Чтобы менять значения при обходе, пишут `auto&` вместо `const auto&`.

**5. Переменная с `auto` без значения.**

```text
main.cpp:6:10: error: declaration of variable 'x' with deduced type 'auto' requires an initializer
```

`auto` выводит тип из значения, которым переменная инициализируется. Без значения вывод невозможен.

**6. Ожидание порядка добавления.** Словарь обходится по порядку ключей, а не по порядку добавления. Нужен порядок ввода - храните слова ещё и в векторе.

**7. Лишняя запись при подсчёте.** Условие `if (counts[w] > 0)` внутри цикла создаёт записи с нулём. Спросите себя, не нужен ли `count`.

**8. Путаница ключа и значения.** `std::map<int, std::string>` (номер -> имя) и `std::map<std::string, int>` (имя -> номер) - разные словари. Тип ключа - первый в скобках.

## Итоги

* `std::map<K, V>` хранит пары «ключ - значение»; ключи не повторяются и всегда упорядочены.
* `m[key] = v` создаёт или заменяет запись; `m[key]++` - основной приём подсчёта.
* Чтение `m[key]` отсутствующего ключа **создаёт** запись; чтобы проверить наличие, используйте `count(key)`, чтобы прочитать без создания - `at(key)` (бросает `std::out_of_range`, если ключа нет).
* Обход: `for (const auto& [key, value] : m)`; `auto` подставляет тип сам.
* `size()` показывает число записей.

До сих пор мы читали слова и числа, разделённые пробелами. Но настоящие данные приходят строками вроде `Иванов;85`, в которых пробелы могут быть частью значения. Как читать и разбирать такие строки - в уроке про [работу с текстом](lesson:cpp.from-zero.text-lines).

## Для тех, кто уже программирует

* `std::map` - упорядоченный ассоциативный массив (обычно красно-чёрное дерево): доступ за O(log n), обход по возрастанию ключей. Для хеш-таблицы с доступом за O(1) в среднем есть `std::unordered_map` (порядок не определён).
* Оператор `m[key]` создаёт отсутствующий ключ - принципиальное отличие от `dict[key]` в Python (`KeyError`), `Map.get` в Java и JavaScript, `m[key]` в Go (нулевое значение без вставки). Аналог безопасного `get` - `count`/`find`/`at`.
* `at` бросает исключение `std::out_of_range`, как `KeyError`. `contains(key)` появился в C++20, но в курсе используется `count` как более старый и привычный вариант.
* `auto` - вывод типа из инициализатора (как `var` в Java и C#, `:=` в Go), статический, а не динамический.
* Разложение `[key, value]` (structured bindings, C++17) напоминает распаковку кортежей в Python. Элементы словаря - `std::pair<const K, V>`.
* Ключ должен поддерживать сравнение `<`; для своих типов оно задаётся отдельно. Строки сравниваются по байтам, локаль не учитывается.
* Ссылки и итераторы на элементы `std::map` не становятся недействительными при добавлении других записей (в отличие от `std::vector`).
* Для множества без значений есть `std::set`; для подсчёта пар - `std::map<std::pair<...>, ...>`; всё это в курсе «Язык и стандартная библиотека».

## Почему словарь упорядочен

Это необязательный раздел: для заданий он не нужен.

`std::map` обычно реализован как самобалансирующееся двоичное дерево поиска: каждая запись - узел, у которого «меньшие» ключи слева, а «большие» справа. Поиск спускается от корня, на каждом шаге отбрасывая половину записей, поэтому в миллионе записей достаточно около двадцати сравнений. Обход «слева направо» даёт ключи по возрастанию, откуда и упорядоченность - это не особая сортировка, а свойство структуры.

Цена - память (узлы разбросаны по куче) и скорость по сравнению с хеш-таблицей. Поэтому в программах, где порядок не нужен, часто выбирают `std::unordered_map`. Для задач курса важнее предсказуемость: упорядоченный вывод одинаков на любом компьютере, и его легко проверить.
