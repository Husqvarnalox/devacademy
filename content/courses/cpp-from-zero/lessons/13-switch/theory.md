## Зачем это нужно

Меню программы («1 - добавить, 2 - удалить, 3 - выйти»), номер дня недели, команда из одной буквы - во всех этих случаях одна и та же переменная сравнивается с набором конкретных значений. Это можно записать цепочкой `else if` (прошлый урок), но получится длинно и однообразно. Для такого случая в C++ есть более наглядная команда `switch`.

## Одна новая идея: switch выбирает ветку по значению

`switch` берёт значение в скобках и ищет среди меток `case` подходящую. Найдя, он выполняет команды этой ветки до слова `break`. Если ни одна метка не подошла, выполняется ветка `default` (если она есть).

```cpp
switch (day) {
    case 1:
        std::cout << "Понедельник\n";
        break;
    case 2:
        std::cout << "Вторник\n";
        break;
    default:
        std::cout << "Другой день\n";
}
```

Три слова нужно запомнить:

* `case 1:` - метка: «если значение равно 1, начни отсюда». После метки стоит двоеточие, а не фигурные скобки.
* `break;` - «выйди из switch». Без него выполнение **продолжится в следующей ветке**.
* `default:` - «если ничего не подошло». Это аналог `else`.

В отличие от `if`, `switch` работает только с целыми значениями (числа и символы `char`): строки и дробные числа в него не подставить.

<!-- section: examples -->
## Пример 1. Простой switch

```cpp run
#include <iostream>

int main() {
    int day = 3;
    switch (day) {
        case 1:
            std::cout << "Понедельник\n";
            break;
        case 2:
            std::cout << "Вторник\n";
            break;
        case 3:
            std::cout << "Среда\n";
            break;
        default:
            std::cout << "Другой день\n";
    }
    std::cout << "Конец\n";
}
```
```output
Среда
Конец
```

Разбор:

* Значение `3` совпало с `case 3`, напечатано «Среда», `break` вышел из `switch`, и программа продолжила со строки «Конец».
* В последней ветке `default` команда `break` не нужна: дальше всё равно конец `switch`. Но многие ставят его и там - так безопаснее, если позже добавится ещё ветка.

## Пример 2. Несколько значений в одной ветке

```cpp run
#include <iostream>

int main() {
    int month = 2;
    int days = 0;
    switch (month) {
        case 4:
        case 6:
        case 9:
        case 11:
            days = 30;
            break;
        case 2:
            days = 28;
            break;
        default:
            days = 31;
    }
    std::cout << "Дней в месяце " << month << ": " << days << "\n";
}
```
```output
Дней в месяце 2: 28
```

Метки `case 4:`, `case 6:`, `case 9:` и `case 11:` идут подряд без команд между ними, поэтому все четыре значения ведут к одной ветке. Это намеренное объединение, и компилятор его не критикует. (Для простоты февраль считаем из 28 дней.)

## Пример 3. switch по символу

```cpp run
#include <iostream>

int main() {
    char command = 'b';
    switch (command) {
        case 'a':
            std::cout << "Добавить\n";
            break;
        case 'b':
            std::cout << "Удалить\n";
            break;
        default:
            std::cout << "Неизвестная команда\n";
    }
}
```
```output
Удалить
```

Символ `char` - это маленькое целое число (код символа), поэтому `switch` с ним работает. Метки символов пишутся в **одинарных** кавычках.

## Пример 4. Забытый break

```cpp run
#include <iostream>

int main() {
    int n = 2;
    switch (n) {
        case 1:
            std::cout << "один\n";
        case 2:
            std::cout << "два\n";
        case 3:
            std::cout << "три\n";
            break;
        default:
            std::cout << "другое\n";
    }
}
```
```output
два
три
```

Метка `case 2` совпала, напечатано «два». Но `break` в этой ветке нет, поэтому программа «провалилась» в `case 3` и напечатала «три», пока не дошла до `break`. Это и есть главная ловушка `switch`: она определена языком, не вызывает ошибки и при этом обычно не нужна.

**Попробуйте.** Поставьте `n = 1` и посчитайте, сколько строк будет напечатано. Добавьте `break;` в `case 1` и `case 2` и проверьте результат. Затем напишите `switch` для команд `'+'`, `'-'`, `'*'`, который по символу печатает название операции.

## Точные правила

* Выражение в скобках `switch` должно иметь целый тип (`int`, `char`, `bool`, `long long` и их родственники). `double` и `std::string` не допускаются.
* Метки `case` должны быть **константами**, известными до запуска: числа и символы-литералы (`case 5:`, `case 'x':`). Переменная в метке не допускается. Две одинаковые метки в одном `switch` - ошибка компиляции.
* Выполнение начинается с совпавшей метки и идёт вниз, пока не встретится `break` или не закончится `switch`. Метки сами по себе выполнение не останавливают.
* Ветка `default` необязательна и может стоять где угодно, но принято ставить её последней. Без `default` непопавшее значение просто пропускается.
* Если нужно объявить переменную в ветке, оберните ветку в фигурные скобки: `case 1: { int k = 5; ... break; }`. Иначе переход к следующей метке «перепрыгивает» объявление, и компилятор отказывается собирать программу.
* Сравнение по цепочкам `else if` и `switch` дают одинаковый результат, если проверяется одна переменная на равенство. Диапазоны (`x > 10`) и составные условия в `switch` не записываются: используйте `if`.
* Провал в следующую ветку определён языком, это не неопределённое поведение. Компилятор предупреждает о нём только по просьбе: ключ `-Wimplicit-fallthrough` не входит в `-Wall -Wextra` у clang (g++ с `-Wextra` предупреждает).

## Типичные ошибки

Тексты сообщений получены от Apple clang 21; g++ формулирует иначе, но указывает то же место.

**1. Забытый break.** Программа из примера 4 собирается без единого предупреждения при ключах курса. Если включить проверку явно, компилятор находит проблему:

```text
$ clang++ -Wimplicit-fallthrough main.cpp
main.cpp:8:9: warning: unannotated fall-through between switch labels [-Wimplicit-fallthrough]
    8 |         case 2:
      |         ^
main.cpp:8:9: note: insert '[[fallthrough]];' to silence this warning
main.cpp:8:9: note: insert 'break;' to avoid fall-through
```

Компилятор предлагает два выхода: поставить `break` (почти всегда это и нужно) или честно пометить провал записью `[[fallthrough]];`, если он задуман.

**2. Объявление переменной внутри ветки.**

```cpp
switch (d) {
    case 1:
        int k = 5;
        std::cout << k << "\n";
        break;
    case 2:
        std::cout << "два\n";
        break;
}
```

```text
main.cpp:10:9: error: cannot jump from switch statement to this case label
   10 |         case 2:
      |         ^
main.cpp:7:17: note: jump bypasses variable initialization
    7 |             int k = 5;
      |                 ^
```

Метка `case 2` могла бы «перепрыгнуть» через объявление `k`. Решение - блок: `case 1: { int k = 5; ... break; }`.

**3. Строка вместо числа.**

```cpp
std::string s = "a";
switch (s) {
    case "a": break;
}
```

```text
main.cpp:5:5: error: statement requires expression of integer type ('std::string' (aka 'basic_string<char>') invalid)
    5 |     switch (s) {
      |     ^       ~
main.cpp:6:14: error: value of type 'const char[2]' is not implicitly convertible to 'int'
    6 |         case "a": break;
      |              ^~~
```

`switch` работает только с целыми значениями. Для строк пишите цепочку `if (s == "a") ... else if (s == "b") ...`. Дробное число в `switch` даёт то же сообщение `statement requires expression of integer type ('double' invalid)`.

**4. Одинаковые метки.**

```text
main.cpp:18:14: error: duplicate case value '1'
   18 |         case 1: break;
      |              ^
main.cpp:17:14: note: previous case defined here
   17 |         case 1: int k = 5; std::cout << k; break;
      |              ^
```

Каждое значение может встречаться в `switch` только один раз.

**5. Отсутствует default.** Если пользователь введёт команду, которой нет в списке, программа молча ничего не сделает. Ветка `default` с сообщением («неизвестная команда») превращает тишину в понятный ответ.

**6. Двойные кавычки в метке символа.** `case "a":` - это строка из двух символов `a` и конец строки, а не `char`. Метка символа - `case 'a':`.

## Итоги

* `switch (значение)` выбирает ветку `case`, совпавшую со значением; не совпало ничего - ветка `default`.
* Каждую ветку заканчивайте `break`. Без него выполнение «проваливается» в следующую ветку.
* Подряд идущие метки без команд между ними объединяют несколько значений в одну ветку.
* В скобках `switch` и в метках - только целые значения и символы: ни строк, ни `double`.
* Переменные внутри ветки объявляют в собственном блоке `{ }`.
* Для диапазонов и составных условий используйте `if`.

Дальше программа научится повторять действия: цикл [while](lesson:cpp.from-zero.while-loop) выполняет блок, пока условие истинно.

<!-- section: programmer -->
## Для тех, кто уже программирует

* Это классический `switch` из C: провал в следующую ветку без `break` по умолчанию, как в Java и JavaScript (и в отличие от Go, Rust и Kotlin, где ветки не проваливаются).
* Строки в `switch` не допускаются (в Java и C# допускаются). Перечисления `enum` работают, а для `enum class` компилятор предупреждает о непокрытых значениях (`-Wswitch`).
* Метки должны быть константами времени компиляции; ничего вроде диапазонов `case 1..5` нет (есть расширение GNU, но оно нестандартно).
* Объявление переменной в ветке требует блока `{ }`, иначе ошибка перехода. Начиная с C++17 есть атрибут `[[fallthrough]];` для намеренного провала.
* В C++17 в `switch` можно объявить переменную, как и в `if`: `switch (int c = f(); c) { ... }`.
* Выражения-выбор (`switch` как выражение с результатом, как в Java 14+ или Kotlin `when`) в C++ нет; результат записывают в переменную, как в примерах.
* Оптимизатор часто превращает плотный `switch` в таблицу переходов, так что он быстрее длинной цепочки `if`.

<!-- section: deep-dive -->
## Как `switch` выглядит для процессора

Это необязательный раздел: для заданий он не нужен.

Для небольшого набора значений компилятор строит обычную цепочку сравнений. Если метки идут плотно (например, от 0 до 20), он может создать **таблицу переходов**: массив адресов, где значение выступает индексом. Тогда выбор ветки занимает одно обращение к таблице вместо серии сравнений, независимо от числа веток. Если метки разбросаны (1, 1000, 100000), используется бинарный поиск по значениям или та же цепочка сравнений.

Из этого следует практическое правило: `switch` не медленнее цепочки `if`, а часто быстрее, но выбирать между ними стоит по читаемости. Если ветки сравнивают одну переменную с конкретными значениями, `switch` читается лучше; если условия разные, нужен `if`.
