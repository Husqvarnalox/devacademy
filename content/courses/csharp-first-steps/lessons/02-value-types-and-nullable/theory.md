## Копия или тот же объект: главный вопрос C#

В C# у каждого типа есть правило присваивания:

* **Значимый тип** (`int`, `double`, `bool`, `struct`, `enum`) - переменная хранит само значение. `b = a` создаёт независимую копию.
* **Ссылочный тип** (`class`, `string`, массивы, делегаты, `object`) - переменная хранит ссылку на объект. `b = a` копирует ссылку, и обе переменные указывают на один объект.

```csharp
var p1 = new PointS { X = 1 };   // struct
var p2 = p1;
p2.X = 9;
Console.WriteLine(p1.X);          // 1: p2 - отдельная копия

var c1 = new PointC { X = 1 };   // class
var c2 = c1;
c2.X = 9;
Console.WriteLine(c1.X);          // 9: один и тот же объект
```

Второй вопрос: может ли переменная быть «пустой». Для ссылочных типов пустое значение - `null`; чтобы компилятор помогал не забывать об этом, используются **nullable reference types**.
Для значимых типов «пустоту» выражает `Nullable<T>`, записываемый как `int?`.

## struct и class, Nullable<T> и nullable reference types

**Где хранятся данные.** Значение значимого типа лежит там, где объявлена переменная: в локальной переменной метода, в поле объекта, в элементе массива.
Поле `struct` внутри `class` хранится внутри объекта в куче; локальная переменная `struct` - в кадре вызова. Объект ссылочного типа всегда размещается в управляемой куче, а переменная хранит на него ссылку.
Фраза «структуры живут на стеке» неточна.

**Присваивание и передача.** Аргумент передаётся по значению: для `struct` копируется всё значение, для `class` - ссылка. Метод, получивший `struct`, меняет только свою копию.
Чтобы изменить исходную структуру, параметр объявляют с `ref` (или `out`). Метод, получивший ссылку на объект, наоборот, может изменить сам объект.

**Равенство.** `==` для ссылочных типов по умолчанию сравнивает ссылки (кроме `string`, у которого оператор сравнивает содержимое). Для `struct` оператор `==` не определён, пока вы его не добавите; метод `Equals` по умолчанию сравнивает поля.
`record`-типы получают сравнение по значению автоматически.

**Когда выбирать struct.** Небольшой неизменяемый тип с семантикой значения (точка, деньги, координаты) - кандидат на `readonly struct`. Крупные или изменяемые данные лучше делать классом: копирование большой структуры при каждой передаче дорого.
**Изменяемые структуры опасны:** `list[0].X = 5` для `List<PointS>` не компилируется, потому что индексатор возвращает копию; работа с копией приводила бы к потерянному изменению.

**Значения по умолчанию.** Поля и элементы массива сначала обнулены: у чисел это `0`, у ссылок - `null`. `default(PointS)` - структура со всеми обнулёнными полями; `new PointS()` даёт то же самое.

**Nullable<T> для значимых типов.** `int?` - это настоящий тип `Nullable<int>`, структура с полем-флагом `HasValue` и значением `Value`. Чтение `Value`, когда `HasValue` ложно, бросает `InvalidOperationException`.
Операторы: `x ?? 0` (значение по умолчанию), `x?.Property` (безопасный доступ, возвращает `null`, если `x` равно `null`), `x is { } v` (шаблон: «не null» с извлечением значения).

**Nullable reference types (NRT).** При включённом `#nullable enable` каждая ссылка считается ненулевой, если не помечена `?`: `string` - не должна быть `null`, `string?` - может.
Это **аннотации для компилятора**: он анализирует поток управления и предупреждает (warning), когда вы разыменовываете значение, которое может быть `null`. Во время работы `string?` и `string` - один и тот же тип;
ничего не проверяется, и `NullReferenceException` по-прежнему возможен, если обойти предупреждение. Оператор `!` («null-forgiving») подавляет предупреждение, но не меняет значения; ответственность на вас.
Для проверки аргументов есть `ArgumentNullException.ThrowIfNull(arg)`.

**Строки.** `string` - ссылочный тип, но **неизменяемый**: операции вроде `Replace` возвращают новую строку. Поэтому при присваивании строк путаницы с общим состоянием не возникает.

## Примеры

**Пример 1. struct копируется, class - нет.**

```csharp run
using System;

var s1 = new PointS { X = 1 };
var s2 = s1;
s2.X = 9;

var c1 = new PointC { X = 1 };
var c2 = c1;
c2.X = 9;

Console.WriteLine($"{s1.X} {s2.X}");
Console.WriteLine($"{c1.X} {c2.X}");
Console.WriteLine(ReferenceEquals(c1, c2));

struct PointS { public int X; }
class PointC { public int X; }
```
```output
1 9
9 9
True
```

После `var c2 = c1` обе переменные указывают на один объект, поэтому изменение через `c2` видно через `c1`.

**Пример 2. Параметры: копия и `ref`.**

```csharp run
using System;

var s = new PointS { X = 1 };
Bump(s);
Console.WriteLine(s.X);
BumpRef(ref s);
Console.WriteLine(s.X);

var c = new PointC { X = 1 };
BumpClass(c);
Console.WriteLine(c.X);

static void Bump(PointS p) { p.X += 10; }
static void BumpRef(ref PointS p) { p.X += 10; }
static void BumpClass(PointC p) { p.X += 10; }

struct PointS { public int X; }
class PointC { public int X; }
```
```output
1
11
11
```

Первая функция изменила копию, вторая - исходную структуру, потому что получила ссылку на переменную. Третья изменила объект, на который указывает ссылка.

**Пример 3. `Nullable<T>`.**

```csharp run
using System;

int? a = null;
int? b = 5;
Console.WriteLine(a.HasValue);
Console.WriteLine(a ?? -1);
Console.WriteLine(b + 1);
Console.WriteLine(a + 1 is null);
try
{
    Console.WriteLine(a.Value);
}
catch (InvalidOperationException)
{
    Console.WriteLine("нет значения");
}
```
```output
False
-1
6
True
нет значения
```

Арифметика с пустым значением даёт пустой результат, а не ошибку; `Value` у пустого значения бросает исключение.

**Пример 4. Nullable reference types.**

```csharp run
#nullable enable
using System;

string? name = null;
Console.WriteLine(name?.Length ?? -1);
name = "Ann";
Console.WriteLine(name.Length);
Console.WriteLine(typeof(string) == "x".GetType());
string? maybe = GetOrNull(false);
Console.WriteLine(maybe is null ? "null" : maybe);

static string? GetOrNull(bool ok) => ok ? "значение" : null;
```
```output
-1
3
True
null
```

После присваивания `name = "Ann"` компилятор знает, что значение не `null`, и разыменование безопасно. Аннотация `?` не создаёт отдельного типа.

**Пример 5. Изменяемая структура в списке.**

```csharp
var list = new List<PointS> { new PointS { X = 1 } };
// list[0].X = 5;  // ошибка компиляции CS1612: результат индексатора - копия
var item = list[0];
item.X = 5;
list[0] = item;   // записать копию обратно
```

## Типичные ошибки

* **Считать `class` значением.** `var b = a;` для класса не создаёт копию. Если нужна независимая копия, реализуйте копирование явно или используйте `record` с `with`.
* **Мутировать копию структуры.** Изменение значения, полученного из метода, свойства или индексатора, меняет временную копию. Делайте структуры неизменяемыми (`readonly struct`).
* **Игнорировать предупреждения о `null`.** Предупреждения CS8600-CS8604 - это ваш шанс найти `NullReferenceException` до запуска. Не подавляйте их оператором `!` без причины.
* **`if (x.HasValue) ... x.Value` везде вместо `??`/`is`.** Это работает, но шаблон `is { } v` и оператор `??` короче и надёжнее.
* **Предполагать, что `string?` проверяется во время работы.** Параметр `string` всё равно может получить `null` из кода без включённых NRT, из отражения или через `!`.
* **Сравнивать ссылочные объекты оператором `==`, ожидая сравнения по содержимому.** Для классов он сравнивает ссылки, кроме типов, переопределивших оператор (`string`, `record`).
* **Хранить большие данные в `struct`.** Каждая передача копирует всё значение.
* **Забыть `ref`.** Метод со структурным параметром без `ref` ничего не меняет у вызывающего.

## Итоги

* Значимые типы (`struct`, числа) копируются при присваивании и передаче; ссылочные (`class`, массивы) копируют ссылку.
* `ref` передаёт ссылку на переменную, а не на значение; изменяемые структуры порождают потерянные изменения.
* `int?` - реальная структура `Nullable<int>`; `string?` - только аннотация для компилятора, не меняющая тип во время работы.
* Для работы с пустыми значениями используйте `??`, `?.`, `is { } v` и `ThrowIfNull`.
