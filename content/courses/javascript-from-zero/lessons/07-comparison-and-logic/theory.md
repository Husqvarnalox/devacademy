## Зачем это нужно

Чтобы программа могла «подумать», ей нужно уметь отвечать на вопросы: хватает ли денег, совершеннолетний ли пользователь, совпал ли пароль. Ответ на такой вопрос - логическое значение `true` («да») или `false` («нет»). Его даёт **сравнение**. Несколько ответов можно объединять: «есть билет **и** возраст не меньше 18». Для этого служат **логические операторы**.

## Одна новая идея: сравнение даёт true или false

Операторы сравнения:

| Оператор | Вопрос | Пример | Результат |
|---|---|---|---|
| `===` | равны ли значение и тип? | `5 === 5` | `true` |
| `!==` | не равны? | `5 !== 6` | `true` |
| `<` | меньше? | `3 < 5` | `true` |
| `>` | больше? | `3 > 5` | `false` |
| `<=` | меньше или равно? | `5 <= 5` | `true` |
| `>=` | больше или равно? | `4 >= 5` | `false` |

Логические операторы работают с `true` и `false`:

* `&&` («и») - истинно, если истинны **обе** части;
* `||` («или») - истинно, если истинна **хотя бы одна** часть;
* `!` («не») - меняет значение на противоположное.

Обратите внимание на тройной знак `===`. Один знак `=` - присваивание («положить значение»), а три - вопрос «равны ли?». В JavaScript есть и более короткое `==`, но в этом курсе мы **его не используем**; причина объяснена в разделе «Точные правила».

<!-- section: examples -->
## Пример 1. Сравнения

```javascript run
console.log(5 > 3);
console.log(5 < 3);
console.log(5 >= 5);
console.log(5 === 5);
console.log(5 !== 6);
console.log("мир" === "мир");
console.log("Мир" === "мир");
```
```output
true
false
true
true
true
true
false
```

Разбор: каждое сравнение - выражение, результат которого `true` или `false`. Последние две строки сравнивают строки: они равны, только если совпадают все символы. Заглавная «М» и строчная «м» - разные символы.

## Пример 2. Тип тоже имеет значение

```javascript run
console.log(5 === 5);
console.log(5 === "5");
console.log(typeof 5, typeof "5");
```
```output
true
false
number string
```

`===` сравнивает и значение, и тип. Число `5` и строка `"5"` внешне похожи, но типы разные (урок про значения), поэтому результат `false`. Это именно то поведение, которое нужно: программа не должна путать цену с текстом цены.

## Пример 3. Логические операторы

```javascript run
const age = 20;
const hasTicket = true;

console.log(age >= 18 && hasTicket);
console.log(age < 18 || hasTicket);
console.log(!hasTicket);
console.log(!(age < 18));
console.log(age >= 18 && age < 65);
```
```output
true
true
false
true
true
```

Разбор:

* `age >= 18 && hasTicket` - обе части истинны, значит `true`.
* `age < 18 || hasTicket` - первая часть ложна, вторая истинна; для `||` хватает одной, значит `true`.
* `!hasTicket` - противоположное `true`, то есть `false`.
* `!(age < 18)` - скобки нужны, чтобы `!` относился ко всему сравнению; `age < 18` ложно, `!` превращает его в `true`.
* `age >= 18 && age < 65` - так проверяют, что значение лежит в диапазоне от 18 до 64.

**Попробуйте.** Поменяйте `age` на `70` и предскажите результат пяти команд. Затем замените `20` на `18` и посмотрите, как ведёт себя граница: `>=` включает 18, а `>` - нет.

## Точные правила

* Результат любого сравнения - `boolean`: `true` или `false`.
* `===` и `!==` сравнивают значение **и тип**. Значения разных типов никогда не равны: `5 === "5"` - `false`.
* `<`, `>`, `<=`, `>=` для чисел сравнивают числовое значение. Для строк сравнение идёт по порядку символов; оно полезно в основном для равенства, а для порядка слов не стоит на него полагаться (`"10" < "9"` даёт `true`, потому что сравниваются символы «1» и «9»).
* Строки сравниваются с учётом регистра: `"а" !== "А"`.
* Приоритет: арифметика, затем сравнения, затем `!`, затем `&&`, затем `||`. Скобки меняют порядок. В сложных условиях скобки лучше писать, даже когда они не нужны.
* `&&` и `||` вычисляются слева направо и **останавливаются**, как только ответ ясен: если левая часть `&&` ложна, правая даже не вычисляется.
* **Цепочку `a < x < b` писать нельзя.** `10 < 5 < 20` даёт `true`: сначала `10 < 5` - это `false`, затем `false < 20`, и `false` превращается в `0`. Диапазон записывают как `x > a && x < b`.
* **Почему не `==`.** Оператор `==` перед сравнением пытается привести значения к общему типу и делает это по сложным правилам. Из-за этого `"5" == 5` даёт `true`, `0 == ""` - тоже `true`, `null == 0` - `false`, `null == undefined` - `true`. Такие правила трудно помнить, и они прячут ошибки. `===` не приводит типы, результат предсказуем. Программисты, которые знают `==`, всё равно пишут `===`. `!=` по той же причине заменяйте на `!==`.

## Типичные ошибки

**1. Один знак `=` вместо трёх.**

```javascript
const x = 5;
x = 5;
```

Node.js: `TypeError: Assignment to constant variable.` Знак `=` присваивает, а не сравнивает. Для вопроса «равны ли?» нужно `x === 5`. Если бы переменная была объявлена через `let`, ошибки не было бы: значение молча присвоилось бы, а проверки не произошло.

**2. Цепочка сравнений, как в математике.**

```javascript
const x = 50;
console.log(1 < x < 10);
```

Печатает `true`, хотя 50 не меньше 10: `1 < 50` даёт `true`, а `true < 10` - это `1 < 10`. Нужно `x > 1 && x < 10`.

**3. Забыли скобки у `!`.**

```javascript
console.log(!3 > 2);
```

Печатает `false`: `!3` вычисляется первым и даёт `false`, а `false > 2` ложно. Чтобы отрицать всё сравнение, пишите `!(3 > 2)`.

**4. Сравнение строк без учёта регистра.**

`"Да" === "да"` - `false`. Если пользователь может написать по-разному, сначала приведите оба текста к одному регистру (команды для этого будут позже).

**5. Сравнение числа с текстом.**

`5 === "5"` - `false`, и ошибки при этом нет. Если сравнение «не срабатывает», проверьте `typeof` обеих частей.

**6. Знак `&` вместо `&&`.**

Одиночные `&` и `|` - другие операции (побитовые). Для логики всегда двойные: `&&`, `||`.

<!-- section: summary -->
## Итоги

* Сравнения `=== !== < > <= >=` дают `true` или `false`.
* `===` сравнивает значение и тип; в курсе всегда используется он, а не `==`.
* `&&` (и), `||` (или), `!` (не) собирают составные условия; диапазон пишут как `x > a && x < b`.
* Один знак `=` присваивает, три знака `===` сравнивают.

С сравнениями можно строить решения, но чтобы использовать их многократно, нужны функции: [Функции](lesson:javascript.from-zero.functions).

<!-- section: programmer -->
## Для тех, кто уже программирует

* `===` и `!==` - строгое сравнение без приведения типов, аналог `==` в Python/Java/C#. `==` приводит типы по сложным правилам (`0 == ""`, `"1" == 1`, `null == undefined`), поэтому в курсе он не используется. Исключение, которое иногда допускают, - `x == null` для проверки на `null` и `undefined`; этого мы касаться не будем.
* `NaN === NaN` - `false`; для проверки есть `Number.isNaN`. Объекты сравниваются по ссылке.
* Строки `<`/`>` сравнивают по кодовым единицам UTF-16, без учёта локали (для порядка слов позже используется `localeCompare`).
* `&&` и `||` работают по короткому замыканию и возвращают один из операндов, а не обязательно `boolean` (`"a" && 5` - `5`). В этом уроке операндами были логические значения.
* Цепочка `a < b < c` не проверяет диапазон, как в Python: она вычисляется слева направо.
* Логические операторы - `&&`, `||`, `!`, а не `and`/`or`/`not`.

<!-- section: deep-dive -->
## Что делает `==` и почему от него отказываются

Это необязательный раздел: для заданий он не нужен.

Когда типы операндов у `==` разные, язык по таблице правил приводит их к общему виду. Число и строка сравниваются как два числа: `"5" == 5` превращается в `5 == 5`. Логическое значение сначала превращается в число: `false` становится `0`, а `0 == ""` дальше превращает пустую строку в `0`. Правила последовательны, но их несколько десятков, и они не всегда согласованы между собой: `"0" == false` истинно, `"0"` само по себе в условии считается истинным, а `null == 0` ложно. Исторически `==` появился как «удобство» первых лет языка, которое позже начали считать недостатком проектирования.

`===` сначала сравнивает типы. Если они разные, ответ сразу `false`. Если одинаковые, сравниваются значения. Результат читается с первого взгляда, и поэтому современные проверяющие программы (линтеры) по умолчанию требуют `===`. Единственное значение, которое не равно самому себе, - `NaN`, «не число»; об этом вы узнаете в разделе про числа в следующих курсах.
