## Зачем читать ошибки

Ошибки в программах неизбежны: опечатка, забытая кавычка, неверное имя. Они случаются у новичков и профессионалов одинаково часто. Разница в том, что опытный человек читает сообщение об ошибке как подсказку, а не как приговор. Node.js не ругает вас: он сообщает, что именно и где не удалось понять.

## Одна новая идея: сообщение об ошибке состоит из четырёх частей

Когда программа не может выполниться, Node.js печатает **сообщение об ошибке**. В нём всегда есть:

1. **Файл и номер строки** - где искать: `main.js:3` значит «файл `main.js`, строка 3».
2. **Сама строка кода** и значки `^^^` под проблемным местом.
3. **Вид ошибки** - слово перед двоеточием: `SyntaxError`, `ReferenceError`, `TypeError`.
4. **Причина** - короткое пояснение после двоеточия.

Ниже сообщение выглядит так (путь к файлу у вас будет свой):

```text
/путь/к/main.js:2
consol.log("Молоко");
^

ReferenceError: consol is not defined
    at Object.<anonymous> (/путь/к/main.js:2:1)
    ...
Node.js v22.15.0
```

Строки, начинающиеся с `at`, - **стек вызовов**: цепочка мест, через которые шло выполнение. Для начала достаточно первой из них: после имени файла там указаны строка и столбец (`2:1`). Остальные описывают внутренности Node.js.

## Пример 1. Программа без ошибок

Сначала посмотрим на исправную программу, чтобы было с чем сравнивать.

```javascript run
console.log("Чек №1");
console.log("Хлеб - 45");
console.log("Итого: 45");
```
```output
Чек №1
Хлеб - 45
Итого: 45
```

## Пример 2. Три вида ошибки

Три коротких программы и то, что сообщит Node.js. Запускать их не нужно, но можно проверить самому.

**SyntaxError - текст не соответствует правилам языка.**

```javascript
console.log("Хлеб - 45");
console.log("Итого: 45);
```

```text
main.js:2
console.log("Итого: 45);
            ^^^^^^^^^^^^
SyntaxError: Invalid or unexpected token
```

Node.js не смог даже разобрать файл, поэтому не выполнил ни одной команды: строка «Хлеб - 45» тоже не напечатана. Знаки `^^^` показывают, с чего начинается непонятное место.

**ReferenceError - имя неизвестно.**

```javascript
console.log("Хлеб - 45");
consol.log("Итого: 45");
```

```text
main.js:2
consol.log("Итого: 45");
^

ReferenceError: consol is not defined
```

Разбор прошёл, первая команда выполнилась и напечатала «Хлеб - 45». На второй строке Node.js встретил слово `consol`, которого не знает, и остановил программу. Всё, что ниже, не выполняется.

**TypeError - действие не подходит к значению.**

```javascript
console.Log("Итого: 45");
```

```text
main.js:1
console.Log("Итого: 45");
        ^

TypeError: console.Log is not a function
```

Слово `console` существует, а `Log` у него нет, поэтому вызвать его как команду нельзя. Значок `^` указывает на `Log`.

**Попробуйте.** Скопируйте программу из примера 1 в редактор, уберите закрывающую кавычку в одной строке и запустите. Прочитайте сообщение: назовите номер строки, вид ошибки и причину, прежде чем исправлять.

<!-- section: precise -->
## Точные правила

* **SyntaxError** (синтаксическая ошибка): текст нарушает правила записи - не закрыта кавычка или скобка, лишний знак. Находится при разборе файла, до выполнения; **ни одна команда не выполняется**.
* **ReferenceError** (ошибка ссылки): используется имя, которое не определено. Возникает при выполнении; команды **до** этой строки уже выполнены.
* **TypeError** (ошибка типа): значение есть, но действие с ним невозможно, например вызов того, что не является командой.
* Номер строки указывает, где Node.js **заметил** проблему. Настоящая причина может быть на строку выше: незакрытая скобка в предыдущей строке проявится только на следующей.
* Если ошибок несколько, Node.js сообщает **одну**, первую, которую встретил. После исправления вы можете увидеть следующую. Это нормально, а не признак того, что исправили неправильно.
* Исправляйте по одной ошибке и запускайте программу после каждой правки.
* Сообщения написаны на английском. Ключевые слова: `not defined` - «не определено», `is not a function` - «не является функцией», `Unexpected token` - «неожиданный знак», `missing )` - «пропущена закрывающая скобка».

## Типичные ошибки при чтении сообщений

**1. Смотреть на первую строку и не дочитывать до конца.**
Вид и причина ошибки стоят в конце блока сообщения, а не в начале. Сначала запомните номер строки из первой строки, затем прочитайте строку с названием ошибки.

**2. Скобка не закрыта.**

```javascript
console.log("Хлеб"
```

Node.js: `SyntaxError: missing ) after argument list`. Перевод: «пропущена `)` после списка аргументов». Список в скобках - это то, что вы передаёте команде. Допишите `)`.

**3. Два текста подряд без запятой.**

```javascript
console.log("a" "b");
```

Node.js: `SyntaxError: missing ) after argument list`. Node.js ожидает после первого значения запятую или закрывающую скобку. Поставьте между значениями запятую: `console.log("a", "b");`.

**4. Лишняя скобка.**

```javascript
console.log("Хлеб"));
```

Node.js: `SyntaxError: Unexpected token ')'`. Одна `)` закрыла команду, а вторая оказалась лишней. Удалите её.

**5. Исправили одну ошибку, а появилась другая.**
Это не провал: Node.js показывает ошибки по одной, и после исправления вы просто продвинулись дальше. Если же сообщение повторилось один в один, правка не попала в нужное место.

Как проверять самому: прочитайте сообщение вслух по-русски, найдите строку, сравните её с рабочим примером символ за символом.

<!-- section: summary -->
## Итоги

* В сообщении об ошибке четыре части: файл и строка, сама строка со значками `^^^`, вид ошибки, причина.
* `SyntaxError` - текст не разобрать, ничего не выполнено; `ReferenceError` - неизвестное имя; `TypeError` - действие не подходит к значению.
* Ошибки показываются по одной, исправлять нужно по порядку, запуская программу после каждой правки.

Теперь, когда вы умеете читать сообщения, можно смело пробовать новое. Следующий шаг - узнать, какие бывают значения: [Значения и типы](lesson:javascript.from-zero.values-and-types).

## Для тех, кто уже программирует

* Ошибок компиляции нет: `SyntaxError` возникает при разборе файла (до первой команды), остальные - во время выполнения (`ReferenceError`, `TypeError`).
* Необработанное исключение печатает трассировку в stderr и завершает процесс с кодом 1. Перехват через `try/catch` будет позже.
* Опечатка в имени переменной - рантайм-ошибка, а не ошибка сборки, как в Go/Java/C#; статического анализа по умолчанию нет.
* Номер строки в трассировке - строка, где ошибка проявилась; для незакрытой скобки это может быть следующая строка.
* Сообщения V8 стабильны, но формулировки могут отличаться между версиями Node.js; в курсе приведены сообщения Node.js 22.

## Почему SyntaxError приходит до выполнения

Это необязательный раздел: для заданий он не нужен.

Перед выполнением Node.js разбирает весь файл: превращает текст в структуру, по которой потом идёт выполнение. Разбор следует грамматике языка, и если на каком-то месте очередной знак невозможен, дальше строить структуру нельзя. Отсюда два следствия: ошибка синтаксиса сообщается раньше всего, и в одном файле Node.js показывает только первую.

Ошибки `ReferenceError` и `TypeError` зависят от значений, которые появляются только во время работы: имя `consol` нигде не создавалось, а значит, узнать это можно, лишь дойдя до строки. Поэтому команды до неё успевают выполниться. Сообщение собирает объект `Error`: у него есть имя (`ReferenceError`), текст причины и стек вызовов, который вы видели строками `at ...`.
