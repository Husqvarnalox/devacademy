## Зачем это нужно

Функции получают данные, с которыми не могут работать: деление на ноль, возраст «-5», пустой список там, где нужен первый элемент. Что делать функции в такой ситуации? Вернуть `0` или `undefined` - значит спрятать проблему: вызывающий код примет это за настоящий ответ и продолжит с неверными данными. Напечатать сообщение - тоже плохо: функция не должна решать, что показывать человеку. Правильный путь - **сообщить об ошибке**, а решить, что с ней делать, предоставить тому, кто функцию вызвал.

## Одна новая идея: исключение прерывает выполнение и передаётся наверх

**Исключение** (ошибка времени выполнения) - это сигнал «дальше так работать нельзя». Его создают командой:

```javascript
throw new Error("Деление на ноль");
```

Слово `throw` («бросить») прекращает работу текущей функции на этой строке. Ошибка «всплывает» вверх по цепочке вызовов, пока кто-то её не **перехватит**. Если не перехватил никто, программа останавливается с сообщением, как все ошибки, которые вы видели с первого урока.

Перехватывает ошибку конструкция **`try/catch`**:

```javascript
try {
  // код, который может бросить ошибку
} catch (e) {
  // выполняется, если в try была ошибка; e - объект ошибки
}
```

Если в блоке `try` ошибки не было, `catch` пропускается. Если была, остаток `try` не выполняется, управление переходит в `catch`, а после него программа продолжается как обычно. В `e.message` лежит текст, который передали в `new Error(...)`.

## Пример 1. Бросить и перехватить

```javascript run
function divide(a, b) {
  if (b === 0) {
    throw new Error("Деление на ноль");
  }
  return a / b;
}

try {
  console.log(divide(10, 2));
  console.log(divide(1, 0));
  console.log("эта строка не выполнится");
} catch (e) {
  console.log("Поймали: " + e.message);
}
console.log("программа продолжает работу");
```
```output
5
Поймали: Деление на ноль
программа продолжает работу
```

Разбор:

* `divide` проверяет данные **в начале**. Если делитель 0, она бросает ошибку; строка `return a / b` для такого вызова не выполняется.
* Первый вызов благополучный: печатается 5.
* Второй вызов бросает ошибку внутри `divide`. Она «вылетает» из функции и из блока `try`: печать после неё пропущена.
* В `catch` переменная `e` - объект ошибки. `e.message` равно тексту «Деление на ноль».
* После `catch` программа живёт дальше.

## Пример 2. Проверять каждое значение отдельно

```javascript run
function checkAge(age) {
  if (typeof age !== "number") {
    throw new Error("Возраст должен быть числом");
  }
  if (age < 0 || age > 150) {
    throw new Error("Возраст вне диапазона 0-150");
  }
  return age;
}

for (const value of [25, -3, "30"]) {
  try {
    console.log("принято " + checkAge(value));
  } catch (e) {
    console.log("отклонено: " + e.message);
  }
}
```
```output
принято 25
отклонено: Возраст вне диапазона 0-150
отклонено: Возраст должен быть числом
```

`try/catch` внутри цикла: ошибка на одном значении не останавливает обработку остальных. Проверка типа стоит первой: для строки `"30"` сравнение `age < 0` не имело бы смысла.

## Пример 3. Ошибка как объект

```javascript run
const err = new Error("Нет данных");
console.log(err.message);
console.log(err.name);
console.log(err instanceof Error);

try {
  const user = undefined;
  console.log(user.name);
} catch (e) {
  console.log(e.name + ": " + e.message);
}
```
```output
Нет данных
Error
true
TypeError: Cannot read properties of undefined (reading 'name')
```

`new Error("...")` создаёт объект с полями `message` (сообщение) и `name` (вид ошибки; для своих ошибок `"Error"`). Те же поля есть у ошибок, которые создаёт Node.js: после `try` можно перехватить и их, например `TypeError`, знакомый по уроку про чтение ошибок.

## Пример 4. Значение по умолчанию

```javascript run
function firstOrThrow(items) {
  if (items.length === 0) {
    throw new Error("Список пуст");
  }
  return items[0];
}

function firstOrDefault(items, fallback) {
  try {
    return firstOrThrow(items);
  } catch (e) {
    return fallback;
  }
}

console.log(firstOrDefault(["чай", "кофе"], "нет"));
console.log(firstOrDefault([], "нет"));
```
```output
чай
нет
```

Одна функция сообщает о проблеме, другая решает, что с ней делать в её ситуации. Здесь подходит значение по умолчанию; в другой программе то же исключение показали бы пользователю или записали в журнал.

**Попробуйте.** В примере 1 уберите `try/catch` и запустите программу. Найдите в выводе строку с вашим сообщением и номер строки. Затем верните `try/catch` и замените в `throw` текст на любой другой.

## Точные правила

* `throw new Error("текст")` создаёт объект ошибки и бросает его. После `throw` в этом блоке и в этой функции ничего не выполняется.
* `try { ... } catch (e) { ... }`: если в `try` ошибки не было, `catch` не выполняется; если была - выполнение `try` обрывается и выполняется `catch`. Имя `e` можно выбрать любое; оно существует только внутри `catch`.
* `try` без `catch` (и без `finally`) - синтаксическая ошибка.
* Ошибка перехватывается и тогда, когда `throw` находится в функции, вызванной из `try`, на любой глубине.
* Необработанная ошибка завершает программу. В выводе указаны вид и сообщение (например, `Error: Деление на ноль`), затем «стек» - цепочка вызовов с номерами строк. Самая полезная строка - первая после сообщения: она указывает место, где ошибка возникла.
* `e.message` - текст сообщения, `e.name` - вид ошибки (`Error`, `TypeError`, `ReferenceError` и др.).
* Бросать можно любое значение, но принято бросать `Error`: у него есть `message` и информация о месте возникновения.
* Проверять входные данные принято **в начале** функции, «раннему выходу» помогает `throw`: недопустимое значение отсекается сразу, а дальше код работает с корректными данными.
* Вещественное деление на 0 в JavaScript само ошибки не даёт (получается `Infinity`), поэтому такую проверку пишут вручную.
* `try/catch` не заменяет проверок: ожидаемые ситуации (пустой список, пустая строка) обычно проверяют условием, а исключения оставляют для случаев, когда функция не может выполнить своё обещание.

## Типичные ошибки

**1. Пропущенный `catch`.**

```javascript
try {
  console.log(1);
}
```

Node.js: `SyntaxError: Missing catch or finally after try`. У `try` должен быть хотя бы `catch`.

**2. Использование `e` вне `catch`.**

```javascript
try {
  throw new Error("сбой");
} catch (e) {
  console.log("поймали");
}
console.log(e.message);
```

Node.js: `ReferenceError: e is not defined`. Переменная `e` существует только внутри блока `catch`.

**3. Бросили текст вместо ошибки.**

```javascript
try {
  throw "сбой";
} catch (e) {
  console.log(e.message);
}
```

Напечатается `undefined`: брошена строка, а у строки нет свойства `message`. Всегда бросайте `new Error("сбой")`.

**4. Вернули ошибку вместо того, чтобы бросить.**

```javascript
function divide(a, b) {
  if (b === 0) {
    return new Error("Деление на ноль");
  }
  return a / b;
}
```

Это не бросает ошибку: вызывающий код получит объект ошибки как обычный результат, и `try/catch` вокруг вызова не сработает. Нужно `throw`.

**5. Пустой `catch`.**

```javascript
try {
  riskyStep();
} catch (e) {
}
```

Ошибка проглочена: программа продолжит работу с неизвестным состоянием, и вы не узнаете, что случилось. В `catch` нужно хотя бы вернуть осмысленное значение или сообщить о проблеме.

**6. Слишком большой блок `try`.**
Если в `try` положить половину программы, непонятно, где возникла ошибка. Оборачивайте только тот вызов, который может её бросить.

**7. Сравнение с неподходящим типом.**
`checkAge("30")` без проверки типа сравнит строку с числом и вернёт `"30"`, хотя возраст должен быть числом. Проверяйте тип раньше диапазона.

## Итоги

* `throw new Error("сообщение")` прекращает выполнение функции и сообщает о проблеме; функция сама ничего не печатает и не возвращает «заглушку».
* `try { ... } catch (e) { ... }` перехватывает ошибку: остаток `try` пропускается, в `e.message` лежит текст, после `catch` программа продолжается.
* Неперехваченная ошибка останавливает программу и показывает сообщение и место.
* Входные данные проверяют в начале функции; тип - раньше диапазона.

Теперь у вас достаточно знаний, чтобы писать программы, которые получают данные снаружи и не падают от некорректных: [Чтение ввода](lesson:javascript.from-zero.reading-input).

## Для тех, кто уже программирует

* `throw`/`try`/`catch` как в Java и C#, но без проверяемых исключений и без типизированных `catch`: `catch (e)` ловит всё, различать виды нужно вручную (`e instanceof TypeError`, `e.name`). Блока `finally` в курсе нет; он работает как обычно.
* Бросить можно любое значение, не только `Error` (в отличие от Java/C#, аналогично Python 2 и C++). Хорошая практика - всегда `Error` или его подкласс: только у него есть стек (`e.stack`).
* Арифметика не бросает: `1 / 0` — `Infinity`, `Number("abc")` — `NaN`. Многие «ошибки» в JavaScript проходят молча и всплывают позже как `NaN` или `undefined`.
* Отсутствующие свойства и выход за границу массива тоже не бросают: исключением становятся только операции над `undefined`/`null` (`TypeError`), необъявленные имена (`ReferenceError`) и синтаксис (`SyntaxError`).
* Исключения в асинхронном коде ведут себя иначе (промисы, `async/await`); это тема курса `javascript-fundamentals`.

## Как ошибка «всплывает»

Это необязательный раздел: для заданий он не нужен.

Когда программа вызывает функции одну из другой, движок помнит цепочку вызовов - **стек вызовов**: функция `main` вызвала `process`, та вызвала `divide`. Команда `throw` внутри `divide` создаёт объект ошибки и начинает подниматься по этому стеку: сначала смотрит, нет ли `try` в `divide`, потом в `process`, потом в `main`. Первый найденный `catch` получает объект; все функции между местом броска и `catch` прекращают работу, их локальные переменные пропадают.

Если `try` нет нигде, ошибка достигает верха и превращается в аварийное завершение: Node.js печатает объект ошибки вместе со стеком вызовов, который и показывает, через какие функции программа пришла к ошибке. Строки стека - то, на что опираются при поиске причины: сверху вниз читается путь от места ошибки к началу программы.
