## Зачем это нужно

Большая часть работы с данными сводится к нескольким операциям над списками: преобразовать каждый элемент (перевести цены в доллары), оставить подходящие (только оплаченные заказы), найти нужный (первый товар дороже 500), склеить в текст (список покупок через запятую), упорядочить (по возрастанию цены). В прошлых уроках для этого нужен был цикл с накопителем. У массивов есть готовые **методы**, которые выполняют эти операции одной строкой, а вы лишь передаёте колбэк с правилом.

## Одна новая идея: метод массива принимает колбэк

Метод вызывают через точку после массива: `массив.метод(...)`. В скобки кладут колбэк - стрелочную функцию, которую метод сам вызывает для каждого элемента.

* **`map`** - «преобразовать»: новый массив той же длины, где каждый элемент - результат колбэка.
* **`filter`** - «отобрать»: новый массив из тех элементов, для которых колбэк вернул `true`.
* **`find`** - «найти»: первый элемент, для которого колбэк вернул `true`, или `undefined`, если таких нет.
* **`includes`** - «содержит ли»: `true` или `false`. Принимает не колбэк, а само значение.
* **`join`** - «склеить»: строка из элементов с заданным разделителем между ними.
* **`toSorted`** - «отсортировать»: новый массив, упорядоченный по правилу колбэка-компаратора.

Важное свойство: `map`, `filter` и `toSorted` **не меняют** исходный массив, а возвращают новый. Это удобно: исходные данные остаются целыми.

<!-- section: examples -->
## Пример 1. map и filter

```javascript run
const prices = [100, 250, 40, 90];
const doubled = prices.map((p) => p * 2);
const cheap = prices.filter((p) => p < 100);
console.log(doubled);
console.log(cheap);
console.log(prices);
```
```output
[ 200, 500, 80, 180 ]
[ 40, 90 ]
[ 100, 250, 40, 90 ]
```

Разбор:

* `prices.map((p) => p * 2)` - метод `map` берёт каждый элемент, передаёт в колбэк как `p` и собирает результаты. Из 4 элементов получается 4 результата.
* `prices.filter((p) => p < 100)` - колбэк здесь отвечает «да» или «нет». Остаются 40 и 90.
* Последняя строка показывает, что `prices` остался прежним.

## Пример 2. find и includes

```javascript run
const names = ["Анна", "Борис", "Вера"];
console.log(names.find((n) => n.length > 4));
console.log(names.find((n) => n.length > 10));
console.log(names.includes("Вера"));
console.log(names.includes("вера"));
```
```output
Борис
undefined
true
false
```

`find` останавливается на первом подходящем: «Борис» (5 букв). Для условия, которому никто не удовлетворяет, получаем `undefined`. `includes` сравнивает строго, как `===`, поэтому «Вера» и «вера» для него разные слова.

## Пример 3. join

```javascript run
const items = ["хлеб", "молоко", "сыр"];
console.log(items.join(", "));
console.log(items.join(" | "));
console.log([].join(", ").length);
```
```output
хлеб, молоко, сыр
хлеб | молоко | сыр
0
```

Разделитель ставится только **между** элементами, не в конце. Для пустого массива `join` возвращает пустую строку, её длина 0.

## Пример 4. Сортировка чисел

```javascript run
const nums = [10, 9, 100, 1];
console.log(nums.toSorted());
console.log(nums.toSorted((a, b) => a - b));
console.log(nums.toSorted((a, b) => b - a));
console.log(nums);
```
```output
[ 1, 10, 100, 9 ]
[ 1, 9, 10, 100 ]
[ 100, 10, 9, 1 ]
[ 10, 9, 100, 1 ]
```

Без аргумента `toSorted` сравнивает элементы **как строки**: «1», «10» и «100» стоят раньше «9», потому что первый символ «1» меньше «9». Для чисел нужен **компаратор** - функция от двух элементов `a` и `b`: если результат отрицательный, `a` ставится раньше `b`; если положительный - позже; если 0 - порядок не важен. `a - b` даёт по возрастанию, `b - a` - по убыванию.

## Пример 5. Цепочка

```javascript run
const numbers = [1, 2, 3, 4, 5, 6];
const result = numbers
  .filter((n) => n % 2 === 0)
  .map((n) => n * n);
console.log(result);
```
```output
[ 4, 16, 36 ]
```

Результат `filter` - обычный массив, поэтому к нему сразу можно применить `map`. Сначала отбираем чётные (2, 4, 6), затем возводим в квадрат.

**Попробуйте.** Измените в примере 5 порядок методов: сначала `map`, потом `filter`. Совпадёт ли результат? Затем отсортируйте `["Яна", "Анна", "Борис"]` обычным `toSorted()` и предскажите порядок.

## Точные правила

* `array.map(fn)` - массив той же длины; `fn(element)` вызывается для каждого элемента по порядку. Если в стрелке есть фигурные скобки, без `return` в результат попадут `undefined`.
* `array.filter(fn)` - массив из элементов, для которых `fn(element)` вернула истину. Если ничего не подошло, результат - пустой массив `[]`.
* `array.find(fn)` - первый подошедший элемент или `undefined`. Останавливается на первом совпадении.
* `array.includes(value)` - `true`/`false`; сравнение строгое. Для условия вместо значения нужен `find`.
* `array.join(separator)` - строка. Без аргумента разделителем будет запятая без пробела: `[1, 2].join()` даёт `"1,2"`; в курсе разделитель всегда указывают явно.
* `array.toSorted(compare)` - новая отсортированная копия; `compare(a, b)` возвращает число. Без `compare` элементы сравниваются как строки по кодам символов.
* Есть метод `sort`, который работает так же, но **меняет сам массив** и возвращает его. Предпочитайте `toSorted`, пока не нужна именно сортировка на месте. `toSorted` доступен в Node.js 20 и новее.
* Строки по умолчанию сортируются по кодам символов: заглавные буквы раньше строчных, «Ё» и «ё» стоят вне основной последовательности кириллицы. Для обычных слов одного регистра порядок получается ожидаемым.
* Колбэк получает элемент первым параметром; вторым (необязательно) приходит индекс. В курсе используется только элемент.

## Типичные ошибки

**1. Сортировка чисел без компаратора.**

```javascript
console.log([10, 9, 100, 1].toSorted());
```

Напечатается `[ 1, 10, 100, 9 ]`: числа сравнивались как текст. Добавьте компаратор: `.toSorted((a, b) => a - b)`.

**2. Фигурные скобки без `return`.**

```javascript
console.log([1, 2, 3].filter((x) => { x > 1; }));
```

Напечатается `[]`: колбэк ничего не возвращает, то есть возвращает `undefined`, а это «нет» для `filter`. Уберите скобки: `(x) => x > 1`, или напишите `return`.

**3. Метод массива у строки.**

```javascript
const text = "abc";
text.map((c) => c);
```

Node.js: `TypeError: text.map is not a function`. Метод `map` есть только у массивов. Проверьте, что в переменной именно массив.

**4. `find` вместо `filter` (и наоборот).**
`find` возвращает один элемент, `filter` - массив. Если нужны все подходящие, берите `filter`; результат `find` не получится ни пересчитать, ни склеить.

**5. Использование результата `find` без проверки.**

```javascript
const first = [1, 2].find((n) => n > 5);
console.log(first + 1);
```

Напечатается `NaN`: `find` вернул `undefined`, а `undefined + 1` - не число. Если подходящего элемента может не быть, проверьте результат перед использованием.

**6. Ждут, что `sort` оставит исходный массив.**
`numbers.sort(...)` изменит сам `numbers`. Если исходный порядок нужен потом, используйте `toSorted`.

<!-- section: summary -->
## Итоги

* `map` преобразует каждый элемент, `filter` отбирает подходящие, `find` возвращает первый подходящий или `undefined`, `includes` отвечает «да/нет», `join` склеивает в строку.
* `map`, `filter` и `toSorted` возвращают новые массивы и не меняют исходный.
* Числа без компаратора сортируются как строки; для числового порядка пишут `(a, b) => a - b`.
* Методы можно соединять в цепочку: результат одного - массив для следующего.

Те же идеи работают и со строками, у которых тоже есть свои методы: [Методы строк](lesson:javascript.from-zero.string-methods).

<!-- section: programmer -->
## Для тех, кто уже программирует

* `map`, `filter`, `find`, `includes`, `join` - обычные методы высшего порядка (как LINQ в C#, `stream()` в Java, list comprehension / `map` / `filter` в Python), но выполняются сразу, а не лениво, и каждый создаёт новый массив.
* `sort()` без компаратора сортирует по строковому представлению (UTF-16 коды), а не по значению - известная ловушка. `sort` мутирует; `toSorted` (ES2023, Node 20+) возвращает копию. Сортировка стабильна.
* Компаратор должен возвращать число (отрицательное, ноль, положительное), а не boolean. `(a, b) => a > b` - классическая ошибка.
* `find` возвращает `undefined` при отсутствии, `findIndex` - `-1`. `includes` использует `SameValueZero` (в отличие от `===`, находит `NaN`).
* Колбэки получают `(element, index, array)`; лишние параметры можно не объявлять.
* `join` на элементах `null`/`undefined` даёт пустую строку.

## Почему компаратор возвращает число

Это необязательный раздел: для заданий он не нужен.

Алгоритм сортировки умеет только одно: брать два элемента и спрашивать «кто из них должен стоять раньше?». Как отвечать на этот вопрос, он не знает: числа, слова, даты или заказы сравниваются по-разному. Компаратор - способ передать этот ответ. Отрицательное число означает «первый раньше», положительное - «второй раньше», ноль - «всё равно». Выражение `a - b` оказывается удобным ответом для чисел именно потому, что знак разности как раз сообщает, какое число больше.

Если компаратор не передан, у движка остаётся один универсальный способ сравнить что угодно: превратить в строки и сравнить побуквенно. Для слов это подходит, для чисел нет. Это не ошибка языка, а следствие того, что массив может хранить значения разных типов, и «по умолчанию» нужно правило, подходящее для любых из них.
