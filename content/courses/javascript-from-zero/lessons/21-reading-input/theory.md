## Зачем это нужно

До сих пор данные были записаны прямо в программе: в массиве, в переменной. Настоящая программа получает их снаружи: пользователь вводит числа, другая программа передаёт список, файл содержит таблицу. Всё, что программа получает от внешнего мира, называется **вводом**. Ввод всегда приходит **текстом**, даже если выглядит как числа, и ему нельзя доверять: в нём бывают пустые строки, лишние пробелы и слова вместо чисел. Этот урок учит прочитать ввод и аккуратно превратить его в данные.

## Одна новая идея: ввод - строка, которую нужно разобрать

Текст попадает на **стандартный ввод** (stdin) вашей программы: это канал, по которому данные поступают в программу. В приложении вы вписываете его в специальное поле перед запуском (подробно - в подразделе «Как подать ввод своей программе» ниже), а при проверке решения его подаёт тест. Прочитать его целиком можно так:

```javascript
const text = require("node:fs").readFileSync(0, "utf8");
```

Эта строка читается по частям:

* `require("node:fs")` - команда `require` («потребовать») подключает **встроенный модуль**: набор готовых средств, которые идут вместе с Node.js. Модуль `fs` (от file system, «файловая система») умеет читать и писать файлы.
* `.readFileSync(...)` - метод этого модуля: «прочитать файл целиком и дождаться, пока чтение закончится» (слово Sync означает «синхронно», то есть программа ждёт).
* `0` - что читать. Числа для операционной системы нумеруют каналы: 0 - стандартный ввод. Файлом он считается условно, но читается тем же методом.
* `"utf8"` - **кодировка**: правило, по которому байты превращаются в буквы. Без неё метод вернул бы сырые байты. С `"utf8"` результат - обычная строка, и кириллица в ней читается правильно.
* `const text = ...` - результат сохранён в переменную: в ней одна длинная строка со всем вводом, строки разделены символом переноса `"\n"`.

Дальше ввод разбирают привычными средствами: `text.trim().split("\n")` даёт массив строк, `for...of` обходит его, а каждую строку превращают в число функцией **`Number`**. Если строка не похожа на число, `Number` возвращает особое значение **`NaN`** (от Not a Number, «не число»). Распознают его проверкой **`Number.isNaN(value)`**: обычное сравнение с `NaN` не работает.

## Как подать ввод своей программе

1. Под редактором откройте вкладку **«Вывод»**.
2. Нажмите на строку **«Ввод программы (stdin)»**: под ней раскроется поле.
3. Впишите в поле весь ввод заранее: каждое число на своей строке, потому что программа разбивает текст по переводам строк. Например, для примера 1 впишите `10`, `20` и `30`, каждое число на отдельной строке.
4. Нажмите **«Запустить»**.

Программа не останавливается и не ждёт, пока вы что-то напечатаете: `readFileSync(0, "utf8")` получает сразу весь текст из поля при запуске. Если поле пустое, `text` - пустая строка. Пока урок открыт, текст в поле остаётся, так что для следующего запуска достаточно поменять числа.

Кнопка **«Проверить решение»** это поле не использует: она запускает программу на вводе каждого теста по очереди.

## Пример 1. Прочитать и сложить

Эта программа читает числа по одному в строке и печатает их сумму. Её нельзя запустить в окне примеров, потому что там нет ввода, поэтому приведены ввод и вывод.

```javascript
const text = require("node:fs").readFileSync(0, "utf8");
const lines = text.trim().split("\n");

let sum = 0;
for (const line of lines) {
  sum = sum + Number(line);
}
console.log(sum);
```

Ввод:

```text
10
20
30
```

Вывод:

```text
60
```

Разбор: `text` содержит `"10\n20\n30\n"`. `trim()` убирает завершающий перенос, `split("\n")` даёт `["10", "20", "30"]`, цикл превращает каждую строку в число и складывает. Если сложить сами строки без `Number`, получилась бы склейка `"0102030"`.

## Пример 2. Зачем нужен trim

```javascript run
const text = "10\n20\n30\n";
console.log(text.split("\n"));
console.log(text.trim().split("\n"));
```
```output
[ '10', '20', '30', '' ]
[ '10', '20', '30' ]
```

Ввод обычно заканчивается переносом строки. Если сначала не вызвать `trim`, после последнего переноса появится лишняя пустая «строка». Поэтому для чтения строк привычная форма - `text.trim().split("\n")`.

## Пример 3. Number и NaN

```javascript run
console.log(Number("42"));
console.log(Number("3.5"));
console.log(Number("  7  "));
console.log(Number("abc"));
console.log(Number("3,5"));
console.log(Number(""));
console.log(Number.isNaN(Number("abc")));
console.log(Number.isNaN(Number("42")));
console.log(NaN === NaN);
```
```output
42
3.5
7
NaN
NaN
0
true
false
false
```

Разбор:

* Целые и дробные числа в записи с **точкой** превращаются в числа; пробелы по краям `Number` игнорирует.
* `"abc"` и `"3,5"` (десятичная **запятая**) не числа: результат `NaN`.
* Неожиданность: пустая строка превращается в `0`, а не в `NaN`. Пустые строки из ввода отсеивают заранее.
* `Number.isNaN(...)` даёт `true` только для `NaN`.
* `NaN === NaN` даёт `false`: «не число» не равно даже самому себе, поэтому проверка `value === NaN` никогда не сработает.

## Пример 4. Число с двумя знаками

```javascript run
console.log((14.75 / 3).toFixed(2));
console.log((5).toFixed(2));
console.log((0.5).toFixed(2));
console.log(typeof (5).toFixed(2));
```
```output
4.92
5.00
0.50
string
```

Метод `toFixed(n)` округляет число до `n` знаков после запятой и возвращает **строку**. Он нужен, когда результат печатают в фиксированном формате, например денежную сумму. Число перед точкой оборачивают в скобки, если оно записано литералом.

## Пример 5. Разбор с отбраковкой

```javascript
const text = require("node:fs").readFileSync(0, "utf8");

let count = 0;
let bad = 0;
for (const rawLine of text.trim().split("\n")) {
  const line = rawLine.trim();
  if (line === "") {
    continue;
  }
  const value = Number(line);
  if (Number.isNaN(value)) {
    bad++;
  } else {
    count++;
  }
}
console.log("Чисел: " + count + ", плохих строк: " + bad);
```

Ввод:

```text
5
abc

12
```

Вывод:

```text
Чисел: 2, плохих строк: 1
```

Каждая строка проходит три проверки: пустая (пропустить), не число (посчитать как плохую), число (использовать). Пустая строка не считается плохой: её просто нет в данных.

**Попробуйте.** Выпишите на бумаге, что вернёт `Number` для `"12 "`, `"1 2"`, `"-4"` и `"1e3"`, затем проверьте в примере 3. Обратите внимание на запись `1e3`: это математическая запись числа 1000.

## Точные правила

* `require("node:fs").readFileSync(0, "utf8")` возвращает весь стандартный ввод одной строкой. Читается до конца ввода; если ввода нет, получится пустая строка `""`.
* `require` доступна в файле `main.js` (обычная программа Node.js). В файлах `.mjs` из упражнений-функций она недоступна; там ввод не нужен.
* Без второго аргумента `readFileSync` возвращает не строку, а набор байтов, и методы строк у него отсутствуют.
* Строки в вводе разделяет символ `"\n"`. В некоторых системах (Windows) строку заканчивает пара `"\r\n"`; `trim()` каждой строки убирает лишний `"\r"`, так что кроссплатформенный разбор: `rawLine.trim()`.
* `"".split("\n")` даёт `[""]`: массив из одной пустой строки. Поэтому пустой ввод после `trim().split("\n")` выглядит как одна пустая строка, которую нужно пропустить.
* `Number(строка)`: убирает пробелы по краям, понимает целые, дробные числа с точкой, знак и запись вида `1e3`. Строка из одних пробелов и пустая строка дают `0`. Всё остальное, включая запятую как десятичный разделитель, даёт `NaN`.
* `Number.isNaN(x)` - единственный надёжный способ проверить результат. `x === NaN` всегда ложно.
* Из `NaN` нельзя получить число арифметикой: любое вычисление с `NaN` даёт `NaN`. Поэтому одна плохая строка, попавшая в сумму, испортит весь итог.
* `Number("Infinity")` даёт бесконечность, а не `NaN`; такой ввод в курсе не встречается.
* `n.toFixed(k)` возвращает строку с `k` знаками после запятой; округление идёт по двоичному представлению числа, поэтому редкие значения вроде `2.675` округляются вниз (`"2.67"`). Для учебных задач этого достаточно.
* Среднее для нуля значений не считают: `0 / 0` даёт `NaN`. Сначала проверяют, что значения есть.

## Типичные ошибки

**1. Забыли кодировку.**

```javascript
const text = require("node:fs").readFileSync(0);
console.log(text.trim());
```

Node.js: `TypeError: text.trim is not a function`. Без `"utf8"` метод вернул байты, а не строку. Добавьте второй аргумент.

**2. Читают файл с именем вместо стандартного ввода.**

```javascript
const text = require("node:fs").readFileSync("input.txt", "utf8");
```

Node.js: `Error: ENOENT: no such file or directory, open 'input.txt'`. Такого файла рядом с программой нет. Ввод в упражнениях приходит со стандартного ввода, поэтому первым аргументом должен быть `0`.

**3. Забыли `Number`: строки склеиваются.**

```javascript
let sum = 0;
for (const line of ["5", "3"]) {
  sum = sum + line;
}
console.log(sum);
```

Напечатается `053`: `0 + "5"` - склейка, получилась строка `"05"`, затем `"05" + "3"`. Превращайте строки в числа до сложения: `sum = sum + Number(line);`.

**4. Сравнение с `NaN`.**

```javascript
const value = Number("abc");
if (value === NaN) {
  console.log("не число");
}
```

Сообщение никогда не напечатается, `value === NaN` всегда `false`. Пишите `Number.isNaN(value)`.

**5. Пустая строка стала нулём.**

```javascript
console.log(Number(""));
```

Напечатается `0`. Если в вводе есть пустые строки и они не отсеяны, они незаметно попадут в сумму и увеличат счётчик чисел. Пропускайте пустые строки до вызова `Number`.

**6. Десятичная запятая.**
`Number("3,5")` даёт `NaN`: JavaScript понимает только точку. Если в данных запятые, их нужно заменить заранее (`replaceAll(",", ".")`) или считать такие строки неверными, как делает упражнение.

**7. Не очистили `\r`.**
При вводе с окончаниями Windows в строке остаётся невидимый символ `\r`. `Number("5\r")` его убирает, но сравнение `line === "5"` - нет. Всегда делайте `line.trim()`.

**8. Деление на ноль при пустом вводе.**
Если чисел нет, `sum / count` - это `0 / 0`, то есть `NaN`, и в выводе появится слово `NaN`. Проверьте `count > 0` до деления.

## Итоги

* Ввод приходит текстом: `const text = require("node:fs").readFileSync(0, "utf8");` читает его целиком. `0` - стандартный ввод, `"utf8"` - кодировка для текста и кириллицы.
* Строки получают так: `text.trim().split("\n")`; каждую строку очищают `trim()`, пустые пропускают.
* `Number(строка)` даёт число или `NaN`; проверка - `Number.isNaN`. Пустая строка превращается в 0, поэтому её отсеивают заранее.
* `toFixed(2)` печатает число с двумя знаками после запятой. Среднее считают только при ненулевом количестве.
* Неверные строки можно пропускать и считать, не останавливая программу.

Дальше два урока: о том, где живут переменные ([Область видимости](lesson:javascript.from-zero.scope)), и мини-проект, который объединит всё изученное.

## Для тех, кто уже программирует

* `fs.readFileSync(0, "utf8")` - синхронное чтение всего stdin (аналог `sys.stdin.read()` в Python, `Console.In.ReadToEnd()` в C#). Работает, когда stdin - файл или канал; при интерактивном вводе в терминале читает до EOF. Для потоковой обработки больших входов есть `readline` и потоки, в курсе не используются.
* `require` - механизм модулей CommonJS (в `.js` без `"type": "module"`); в ES-модулях (`.mjs`) вместо него `import`. Префикс `node:` явно указывает встроенный модуль.
* `Number(s)` строже `parseFloat`/`parseInt`: `Number("12px")` — `NaN`, тогда как `parseInt("12px")` даёт `12`. `Number("")` и `Number(" ")` дают `0`, а `Number(null)` — `0`, `Number(undefined)` — `NaN`.
* `NaN !== NaN`; проверять `Number.isNaN` (а не глобальную `isNaN`, которая сначала приводит значение к числу). Бесконечности и `NaN` не являются исключениями: арифметика молча их распространяет.
* `toFixed` возвращает строку и использует двоичное представление: `(1.005).toFixed(2)` — `"1.00"`. Для денег в реальных программах используют целые числа в копейках.
* Окончания строк `\r\n` часто портят разбор на Windows; `trim()` построчно — простой способ.

## Что такое стандартный ввод

Это необязательный раздел: для заданий он не нужен.

Когда операционная система запускает программу, она автоматически подключает к ней три канала: стандартный ввод (номер 0), стандартный вывод (номер 1) и стандартный поток ошибок (номер 2). `console.log` пишет в канал 1; прочитать канал 0 можно как файл, потому что в системах семейства Unix «всё есть файл», а у открытых файлов есть числовые номера. Платформа запускает вашу программу, подключает к каналу 0 заранее подготовленный текст, а на канале 1 читает, что вы напечатали, и сравнивает с ожидаемым.

Поэтому одну и ту же программу можно запускать с вводом с клавиатуры, из файла или от другой программы: она об этом не знает и просто читает канал 0. Пользователь в терминале нажимает `Ctrl+D`, чтобы сообщить «ввод закончился», а при подаче из файла конец наступает сам. Метод `readFileSync` читает ровно до этого момента, а строкой возвращает всё, что пришло.
