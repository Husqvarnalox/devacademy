## Зачем это нужно

Считать - основная работа программ: сумма покупок, скидка, сдача, количество страниц, среднее значение. В JavaScript для этого есть **операторы** - знаки, которые выполняют действие над значениями. Значения, к которым оператор применяется, называют **операндами**, а запись вроде `3 + 4` - **выражением**: его можно вычислить и получить значение.

## Одна новая идея: выражение вычисляется по правилам математики

Основные арифметические операторы:

| Оператор | Что делает | Пример | Результат |
|---|---|---|---|
| `+` | сложение | `7 + 2` | `9` |
| `-` | вычитание | `7 - 2` | `5` |
| `*` | умножение | `7 * 2` | `14` |
| `/` | деление | `7 / 2` | `3.5` |
| `%` | остаток от деления | `7 % 2` | `1` |
| `**` | возведение в степень | `7 ** 2` | `49` |

Порядок действий тот же, что в школьной математике: сначала `**`, затем `*`, `/` и `%`, затем `+` и `-`. Скобки меняют порядок: то, что в скобках, считается первым.

Кроме операторов есть готовые команды для округления из набора **`Math`** (математика). `Math.floor(x)` отбрасывает дробную часть и округляет вниз, `Math.round(x)` округляет до ближайшего целого.

<!-- section: examples -->
## Пример 1. Операторы

```javascript run
console.log(7 + 2);
console.log(7 - 2);
console.log(7 * 2);
console.log(7 / 2);
console.log(7 % 2);
console.log(7 ** 2);
```
```output
9
5
14
3.5
1
49
```

Разбор: каждая строка вычисляет выражение и печатает результат. `7 / 2` - это `3.5`: JavaScript не округляет результат деления сам. Остаток `7 % 2` равен 1, потому что `7 = 2 * 3 + 1`.

## Пример 2. Порядок действий и скобки

```javascript run
console.log(10 - 2 * 3);
console.log((10 - 2) * 3);
console.log(2 ** 3 * 2);
```
```output
4
24
16
```

В первой строке умножение выполняется раньше вычитания: `2 * 3 = 6`, затем `10 - 6 = 4`. Во второй скобки заставляют сначала вычесть: `8 * 3 = 24`. В третьей сначала `2 ** 3 = 8`, затем `8 * 2 = 16`.

## Пример 3. Целая часть, остаток и округление

```javascript run
const minutes = 135;
const hours = Math.floor(minutes / 60);
const rest = minutes % 60;
console.log(hours, "ч", rest, "мин");
console.log(Math.round(2.4));
console.log(Math.round(2.5));
console.log(Math.floor(7.999));
```
```output
2 ч 15 мин
2
3
7
```

`135 / 60` равно `2.25`; `Math.floor` оставляет `2` полных часа. Остаток `135 % 60` - это `15` минут. Так целую часть и остаток используют вместе: «сколько полных и сколько осталось». `Math.round(2.5)` даёт `3` (половинки округляются вверх), `Math.floor(7.999)` не округляет к ближайшему, а отбрасывает дробную часть: `7`.

## Пример 4. Неточность дробных чисел

```javascript run
console.log(0.1 + 0.2);
console.log(0.1 * 3);
console.log(Math.round((0.1 + 0.2) * 100) / 100);
```
```output
0.30000000000000004
0.30000000000000004
0.3
```

Компьютер хранит дробные числа в двоичной системе, и числа вроде `0.1` в ней записываются бесконечной дробью, поэтому хранятся приближённо. Сумма отличается от `0.3` в 17-м знаке. Это не ошибка программы, а свойство хранения. Умножение `0.1 * 3` даёт тот же результат. Когда нужен «красивый» результат, его округляют: умножают на 100, округляют и делят обратно - так получаются сотые.

**Попробуйте.** Предскажите `console.log(2 + 3 * 4)`, `console.log((2 + 3) * 4)` и `console.log(-7 % 3)`, затем запустите. Если результат последнего удивил, прочитайте об остатке с отрицательными числами в разделе «Точные правила».

<!-- section: precise -->
## Точные правила

* Операторы `+ - * / % **` применяются к числам и дают число. Все они работают и с дробными числами.
* Приоритет: `**`, затем `* / %`, затем `+ -`. Равные по приоритету считаются слева направо (кроме `**`: `2 ** 3 ** 2` считается как `2 ** 9`, то есть `512`).
* Скобки `( )` всегда считаются первыми. Лучше поставить лишние скобки, чем гадать про порядок.
* `/` всегда даёт точный результат деления: `7 / 2` равно `3.5`. Для целой части используйте `Math.floor(a / b)`.
* `%` возвращает остаток, и его знак совпадает со знаком **делимого** (левого операнда): `-7 % 3` равно `-1`, `7 % -3` равно `1`. Остаток от деления на 2 равен 0 у чётных чисел и 1 у нечётных положительных.
* Деление на ноль не вызывает ошибки: `1 / 0` равно `Infinity` (бесконечность), `-1 / 0` - `-Infinity`, а `0 / 0` - `NaN` (от Not a Number, «не число»). Тип `NaN` при этом `number`.
* `Math.floor(x)` округляет вниз (к меньшему числу): `Math.floor(-2.5)` равно `-3`. `Math.round(x)` округляет к ближайшему целому, половинки - вверх: `Math.round(2.5)` равно `3`, `Math.round(-2.5)` равно `-2`.
* Дробные числа хранятся приближённо: `0.1 + 0.2` равно `0.30000000000000004`. Целые числа до `9007199254740991` хранятся точно.
* Выражение можно использовать везде, где можно значение: в `console.log`, справа от `=`, внутри скобок другой команды.

<!-- section: mistakes -->
## Типичные ошибки

**1. Ожидать целый результат от `/`.**

```javascript
console.log(10 / 4);
```

Печатает `2.5`, а не `2`. Для целой части нужно `Math.floor(10 / 4)`.

**2. Забыть скобки.**

```javascript
const total = 100 + 20 * 2;
```

Получается `140`, а не `240`. Умножение выполняется раньше сложения. Если нужно сложить первым, пишите `(100 + 20) * 2`.

**3. Перепутать `%` с процентами.**

`50 % 10` - это остаток от деления 50 на 10, то есть `0`, а не «50 процентов от 10». Чтобы найти пятьдесят процентов, пишут `10 * 50 / 100`.

**4. Написать `^` вместо `**`.**

`2 ^ 3` в JavaScript не степень (это побитовая операция), результат будет `1`, а не `8`. Степень - всегда `**`.

**5. Ожидать точной суммы дробных.**

`0.1 + 0.2` не равно `0.3`. Для денег обычно считают в копейках целыми числами, а дробный результат округляют: `Math.round(x * 100) / 100`.

**6. Опечатка в `Math`.**

```javascript
console.log(math.floor(7 / 2));
```

Node.js: `ReferenceError: math is not defined`. Имя `Math` пишется с заглавной буквы. Если написать `Math.Floor`, будет `TypeError: Math.Floor is not a function`: у команды тоже строчная первая буква.

## Итоги

* Операторы `+ - * / % **` работают как в математике; сначала степень, потом умножение/деление/остаток, потом сложение/вычитание; скобки меняют порядок.
* `/` даёт дробный результат; `Math.floor` берёт целую часть, `%` - остаток, `Math.round` - ближайшее целое.
* Дробные числа хранятся приближённо, поэтому `0.1 + 0.2` не равно `0.3`.

Числа считать умеем, теперь поработаем с текстом: [Строки](lesson:javascript.from-zero.strings).

## Для тех, кто уже программирует

* Один тип `number` (IEEE 754 double). `7 / 2` равно `3.5`: целочисленного деления нет, как в Python 3 (но без `//`); целая часть - `Math.floor`, `Math.trunc` (к нулю).
* `%` - остаток со знаком делимого, как в C/Java/Go; в Python знак у результата как у делителя.
* `**` - степень, правоассоциативная, как в Python. Побитовое исключающее ИЛИ - `^`.
* Деление на ноль не бросает исключения: `Infinity`, `-Infinity`, `NaN`.
* `Math.round` округляет половинки к `+∞` (`-2.5` даёт `-2`), в отличие от банковского округления в Python.
* Те же двойные числа, что в Java `double`; `0.1 + 0.2 !== 0.3` везде, где IEEE 754. Для больших целых есть `BigInt` (позже).

## Почему 0.1 не хранится точно

Это необязательный раздел: для заданий он не нужен.

В десятичной системе дробь `1/3` записывается бесконечно: `0.3333...`. Так и в двоичной системе число `0.1` - это бесконечная периодическая дробь. Число `number` занимает 64 бита, и на запись дробной части отведено 52 бита, поэтому бесконечную запись приходится обрезать. Получается ближайшее представимое число, которое очень близко к `0.1`, но не равно ему. То же с `0.2`. Сумма двух приближений даёт значение, ближайшее представимое к ним, которое не совпадает с ближайшим к `0.3`.

Поэтому программисты не сравнивают дробные результаты на точное равенство, а допускают небольшую погрешность, а деньги хранят в целых копейках. Никакого сбоя в JavaScript здесь нет: так работает формат, который используют почти все языки.
