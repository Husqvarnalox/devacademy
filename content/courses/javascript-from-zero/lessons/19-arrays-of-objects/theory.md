## Зачем это нужно

Настоящие данные почти всегда выглядят как список записей: заказы в магазине, ученики класса, строки выписки по карте. Одна запись - это объект (у неё есть названные поля), а список записей - массив таких объектов. Вопросы к такому списку всегда одни и те же: найти запись, посчитать итог, выбрать самую дешёвую, сгруппировать по клиенту. Умение отвечать на них - основа большинства прикладных программ.

## Одна новая идея: массив объектов обходят как массив, а поля читают как у объекта

Ничего принципиально нового в языке нет: вы соединяете то, что уже знаете. Цикл `for...of` по массиву даёт очередной объект; точка после него читает поле. Методы массивов `find`, `filter`, `map` принимают колбэк, в котором параметр - тоже объект, и можно писать `(item) => item.price > 100`.

Новая только техника **группировки**: чтобы подвести итог по каждому значению поля (по клиенту, по категории, по магазину), заводят пустой объект и на каждой записи обновляют в нём нужное свойство. Ключом служит значение поля (например, имя клиента), а значением - накапливаемая сумма. Перебирать такой объект позже можно через `Object.keys(obj)` (имена) и `Object.values(obj)` (значения): обе функции возвращают обычные массивы.

<!-- section: examples -->
## Пример 1. Обход и итог

```javascript run
const cart = [
  { name: "Чай", price: 120, qty: 2 },
  { name: "Хлеб", price: 40, qty: 1 },
  { name: "Сыр", price: 300, qty: 1 },
];

let total = 0;
for (const item of cart) {
  total = total + item.price * item.qty;
}
console.log(total);
console.log(cart[0].name);
console.log(cart.length);
```
```output
580
Чай
3
```

Разбор:

* Массив состоит из трёх объектов. Запятая после последнего объекта допустима и удобна: так проще добавлять строки.
* В цикле переменная `item` на каждом шаге - целый объект. Выражение `item.price * item.qty` - стоимость строки; накопитель `total` складывает их: 240 + 40 + 300 = 580.
* `cart[0].name` читается слева направо: сначала элемент массива с индексом 0, потом его свойство `name`.

## Пример 2. find, filter, map по свойствам

```javascript run
const cart = [
  { name: "Чай", price: 120 },
  { name: "Хлеб", price: 40 },
  { name: "Сыр", price: 300 },
];

console.log(cart.find((item) => item.name === "Хлеб"));
console.log(cart.find((item) => item.name === "Кофе"));
console.log(cart.filter((item) => item.price > 100).map((item) => item.name));
```
```output
{ name: 'Хлеб', price: 40 }
undefined
[ 'Чай', 'Сыр' ]
```

`find` вернул объект целиком и `undefined` для отсутствующего. Цепочка `filter` и `map` сначала оставляет товары дороже 100, потом берёт только их названия.

## Пример 3. Группировка в объект

```javascript run
const sales = [
  { shop: "Север", sum: 100 },
  { shop: "Юг", sum: 50 },
  { shop: "Север", sum: 70 },
];

const totals = {};
for (const sale of sales) {
  if (sale.shop in totals) {
    totals[sale.shop] = totals[sale.shop] + sale.sum;
  } else {
    totals[sale.shop] = sale.sum;
  }
}
console.log(totals);
```
```output
{ 'Север': 170, 'Юг': 50 }
```

Пошагово:

1. `totals` пустой. Первая запись: ключа `"Север"` ещё нет, условие `in` ложно, выполняется `else`: `totals["Север"] = 100`.
2. Вторая запись: ключа `"Юг"` нет, создаём его со значением 50.
3. Третья запись: `"Север"` уже есть, поэтому к нему прибавляется 70, итого 170.

Имя магазина лежит в поле записи, то есть в значении, поэтому обращение идёт через квадратные скобки: `totals[sale.shop]`, а не через точку.

## Пример 4. Обход объекта

```javascript run
const totals = { "Север": 170, "Юг": 50 };

for (const shop of Object.keys(totals)) {
  console.log(shop + ": " + totals[shop]);
}
console.log(Object.values(totals));
let all = 0;
for (const value of Object.values(totals)) {
  all = all + value;
}
console.log(all);
```
```output
Север: 170
Юг: 50
[ 170, 50 ]
220
```

`Object.keys(totals)` - массив `["Север", "Юг"]`, по нему идёт обычный `for...of`, а значение достаётся по ключу. `Object.values(totals)` сразу даёт числа - когда ключи не нужны, это проще.

**Попробуйте.** В примере 3 добавьте в `sales` ещё одну запись `{ shop: "Юг", sum: 10 }` и предскажите итоги. Затем в примере 2 найдите самый дорогой товар: условие в `find` подберите сами или используйте цикл с накопителем, как в уроке про обход массивов.

## Точные правила

* Массив объектов: `[{ ... }, { ... }]`. Элемент - `list[i]`, его поле - `list[i].field`.
* В `for (const item of list)` переменная `item` ссылается на сам объект из массива, а не на его копию: изменение `item.price = 0` изменит запись в массиве. (Присвоить самому `item` другое значение нельзя из-за `const`.)
* `list.find((item) => item.id === 3)` возвращает первую подходящую запись целиком или `undefined`.
* Группировка: `if (key in totals) { totals[key] = totals[key] + x; } else { totals[key] = x; }`. Ключ в квадратных скобках - переменная или выражение.
* Проверка `key in totals` истинна и для ключа со значением 0; условие вида `if (totals[key])` для такого ключа ложно, поэтому для проверки наличия используют `in`.
* Порядок ключей результата - порядок первого появления, пока ключи не похожи на целые числа (`"1"`, `"2"` идут по возрастанию и вперёд остальных).
* `Object.keys(obj)` - массив имён, `Object.values(obj)` - массив значений, оба в одном порядке. К ним применимы `for...of` и методы массивов.
* Минимум или максимум по полю ищут так же, как по числам, но сравнивают `item.price`, а в переменной хранят всю запись (или значение, если нужна только цена).
* Если массив может быть пустым, продумайте результат заранее: `undefined`, `0` или `{}`.

## Типичные ошибки

**1. Чтение свойства у результата `find`, который ничего не нашёл.**

```javascript
const users = [{ id: 1, name: "Вера" }];
const user = users.find((u) => u.id === 2);
console.log(user.name);
```

Node.js: `TypeError: Cannot read properties of undefined (reading 'name')`. Записи с `id` равным 2 нет, `find` вернул `undefined`. Проверьте результат: `if (user === undefined) { ... }`.

**2. Точка вместо скобок при группировке.**

```javascript
const totals = {};
totals.sale.shop = 1;
```

Node.js: `TypeError: Cannot set properties of undefined (setting 'shop')`. Нужно `totals[sale.shop] = 1`, где `sale` - переменная цикла. Точка ищет поле с буквальным именем.

**3. Сложили, не проверив, что ключ есть.**

```javascript
const totals = {};
totals["Север"] = totals["Север"] + 100;
console.log(totals);
```

Напечатается `{ 'Север': NaN }`: `totals["Север"]` было `undefined`, а `undefined + 100` не число. Сначала проверьте `in` и создайте ключ с начальным значением.

**4. Вернули свойство, а не запись.**
`return items.find(...).name` вместо `return items.find(...)` выдаст ошибку, если запись не найдена, и вернёт не то, о чём просили. Если в условии сказано «верните запись», верните объект.

**5. Забыли поле при суммировании.**
`total = total + item` (вместо `item.price`) склеит объект со строкой: получится что-то вроде `0[object Object]`. Если в итоге вместо числа длинная строка с `[object Object]`, проверьте, что прибавляете поле, а не весь объект.

**6. Проверка наличия по значению.**

```javascript
if (totals[key]) { ... }
```

Для ключа со значением 0 условие ложно, хотя ключ существует. Для проверки наличия используйте `key in totals`.

<!-- section: summary -->
## Итоги

* Список записей - массив объектов. Его обходят `for...of`, а поля читают через точку: `item.price`.
* `find` возвращает запись целиком или `undefined`; результат нужно проверять перед использованием.
* Группировка по ключу делается в пустом объекте: `in` проверяет, есть ли ключ, квадратные скобки позволяют брать имя из переменной.
* `Object.keys(obj)` и `Object.values(obj)` превращают объект в массивы, которые можно обходить.

Данные в реальных программах бывают неправильными: не нашлась запись, пришло не то значение. О том, как сообщать об ошибке и обрабатывать её, следующий урок: [Ошибки и исключения](lesson:javascript.from-zero.errors-and-exceptions).

<!-- section: programmer -->
## Для тех, кто уже программирует

* Массив объектов - это аналог списка словарей в Python или списка DTO/записей в Java и C#. Типов у полей нет: форма записи проверяется только временем выполнения, поэтому опечатка в имени поля даёт `undefined`, а не ошибку компиляции.
* Группировка вручную через `in`/`[]` — шаблон `defaultdict` / `Dictionary.TryGetValue`. Для таких задач также используют `Map` и `Object.groupBy` (Node 21+), в курсе пока не нужны.
* Элементы массива хранятся по ссылке: `for (const x of list)` даёт тот же объект, и его изменение видно в массиве. Копирование объекта — отдельная тема (`{ ...obj }`), в курсе не затрагивается.
* Порядок ключей объекта определён: целочисленные ключи по возрастанию, остальные по порядку добавления. Для упорядоченного словаря с произвольными ключами лучше `Map`.
* `Object.keys/values/entries` возвращают копии списков (снимки), изменять объект во время обхода можно, но не нужно.

## Почему поиск по массиву медленнее, чем по объекту

Это необязательный раздел: для заданий он не нужен.

`find` проверяет записи по очереди с начала: если нужная запись последняя, придётся проверить все. Для списка из сотни записей это мгновенно, для миллиона - уже заметно, и если искать часто, программа замедлится. Объект устроен иначе: движок хранит свойства так, чтобы по имени ключа находить значение почти сразу, без перебора всех свойств.

Поэтому программисты, которым нужно много раз искать записи по `id`, один раз раскладывают массив в объект вида `{ 1: запись, 2: запись, ... }` и потом читают `byId[3]`. Группировка из этого урока - ровно тот же приём: ключ превращается в быстрый адрес для накапливаемого итога. Для учебных данных разница не заметна, но привычка думать «где искать по ключу, а где перебирать» пригодится.
