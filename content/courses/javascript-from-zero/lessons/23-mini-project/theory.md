## Зачем это нужно

Вы изучили по отдельности: чтение ввода, цикл, условие, объект, сортировку, форматирование чисел. Настоящая программа складывает эти умения вместе. В этом уроке нет нового языка, есть новый навык: **разбить задачу на этапы** и сделать каждый этап отдельно. Такой подход работает для любой программы, даже когда она в десять раз больше.

## Одна идея: конвейер из этапов

Программа-отчёт почти всегда устроена как конвейер:

1. **Прочитать**: получить весь ввод одной строкой и разбить на строки.
2. **Разобрать**: для каждой строки решить, что это (пустая, верная, неверная) и достать из неё данные.
3. **Накопить**: прибавить данные к итогам (по категориям, общий итог, счётчики).
4. **Вывести**: оформить итоги в точном формате.

Пишите и проверяйте этапы по очереди. После этапа 1 напечатайте число строк. После этапа 2 напечатайте разобранные пары. Только когда каждый этап верен, переходите к следующему. Так ошибка всегда находится в последнем добавленном куске.

<!-- section: examples -->
## Пример 1. Этап «разобрать» отдельно

```javascript run
function parseLine(line) {
  const parts = line.trim().split(" ");
  if (parts.length !== 2) {
    return null;
  }
  const amount = Number(parts[1]);
  if (Number.isNaN(amount)) {
    return null;
  }
  return { category: parts[0], amount: amount };
}

console.log(parseLine("Еда 250.50"));
console.log(parseLine("Еда"));
console.log(parseLine("кино abc"));
console.log(parseLine("  Дом -5  "));
```
```output
{ category: 'Еда', amount: 250.5 }
null
null
{ category: 'Дом', amount: -5 }
```

Функция разбора возвращает либо запись, либо `null` («ничего»). Теперь главный цикл не думает о том, как устроена строка: он только спрашивает, получилась ли запись.

## Пример 2. Этап «накопить» отдельно

```javascript run
const records = [
  { category: "Еда", amount: 100 },
  { category: "Дом", amount: 500 },
  { category: "Еда", amount: 50.5 },
];

const totals = {};
let overall = 0;
for (const record of records) {
  if (!(record.category in totals)) {
    totals[record.category] = 0;
  }
  totals[record.category] = totals[record.category] + record.amount;
  overall = overall + record.amount;
}

console.log(totals);
console.log(overall);
```
```output
{ 'Еда': 150.5, 'Дом': 500 }
650.5
```

Объект `totals` и число `overall` объявлены **до** цикла (урок про область видимости), а внутри цикла только изменяются. Проверка `in` создаёт ключ с нулём при первой встрече категории.

## Пример 3. Этап «вывести» отдельно

```javascript run
const totals = { "Еда": 150.5, "Дом": 500, "авто": 80 };

const names = Object.keys(totals).toSorted();
console.log(names);

let largest = "";
let largestTotal = 0;
for (const name of names) {
  console.log(name + ": " + totals[name].toFixed(2));
  if (largest === "" || totals[name] > largestTotal) {
    largest = name;
    largestTotal = totals[name];
  }
}
console.log("Больше всего: " + largest);
```
```output
[ 'Дом', 'Еда', 'авто' ]
Дом: 500.00
Еда: 150.50
авто: 80.00
Больше всего: Дом
```

Максимум ищется по ходу вывода. Начальное значение - «ещё ничего не найдено» (`largest === ""`), а не число 0: иначе отрицательные суммы никогда бы не победили.

## Пример 4. Сборка целиком

Весь ввод читается из stdin, поэтому программу нельзя запустить в окне примеров. Вот каркас, из которого строится решение, - в нём нужные команды расставлены по этапам:

```javascript
const text = require("node:fs").readFileSync(0, "utf8");
const lines = text.trim().split("\n");

const totals = {};
let overall = 0;
let malformed = 0;

for (const rawLine of lines) {
  const line = rawLine.trim();
  if (line === "") {
    continue;
  }
  // разобрать line: если неверная - malformed++ и continue
  // накопить в totals и overall
}

// вывести категории, итого, самую большую, число неверных строк
```

Вы уже видели каждую часть в примерах 1-3. Осталось соединить.

**Попробуйте.** Придумайте три строки ввода, на которых простая программа ошибётся: например, пустой ввод, отрицательные суммы, одинаковые итоги у двух категорий. Именно такие случаи проверяют скрытые тесты.

<!-- section: precise -->
## Точные правила задачи

* Запись - это `категория сумма` с **ровно одним пробелом**. Категория - одно слово. Сумма - число с точкой, возможно отрицательное.
* Перед разбором строка очищается `trim()` (пробелы и `\r` по краям). Пустая строка не считается ни верной, ни неверной.
* `line.split(" ")` делит по каждому пробелу. Верная запись - ровно две части, вторая из которых `Number` превращает не в `NaN`. Иначе строка неверная: она учитывается в счётчике и больше нигде.
* Категории различаются точно (регистр важен): `Еда` и `еда` - разные.
* Порядок вывода категорий - `Object.keys(totals).toSorted()`: сравнение по кодам символов, заглавные раньше строчных.
* Суммы печатаются `toFixed(2)`. Если верных записей нет, печатаются три строки без категорий: `Итого: 0.00`, `Больше всего: нет`, `Неверных строк: N`.
* Самая большая категория - с наибольшей суммой (отрицательные суммы допустимы). При равенстве побеждает первая в отсортированном списке: сравнение строгое `>`.
* Все вычисления - обычные числа с плавающей точкой. Для таких сумм ошибки округления не видны после `toFixed(2)`.
* Для проверки устойчивости программа не должна падать ни на каком вводе из строк: пустой, одни неверные, окончания Windows.

<!-- section: mistakes -->
## Типичные ошибки

**1. Накопление без начального значения.**

```javascript
const totals = {};
totals["Еда"] = totals["Еда"] + 100;
console.log(totals);
```

Напечатается `{ 'Еда': NaN }`: у отсутствующего ключа значение `undefined`, а `undefined + 100` - не число. Сначала создайте ключ с нулём: `if (!(category in totals)) { totals[category] = 0; }`.

**2. Поле вместо ключа.**

```javascript
const totals = {};
const category = "Еда";
totals.category = 100;
console.log(totals);
```

Напечатается `{ category: 100 }`: точка ищет поле с буквальным именем. Для имени из переменной нужны квадратные скобки: `totals[category]`.

**3. Забыли `continue` после неверной строки.**
После `malformed++` программа продолжает выполнять следующие команды цикла и пытается накопить плохую запись. Результат - `NaN` в итогах. Всегда завершайте обработку неверной строки командой `continue`.

**4. Максимум с нуля.**
`let largestTotal = 0;` без проверки «ничего не найдено» делает победителем 0 при отрицательных суммах: имя останется пустым. Добавьте условие `largest === ""`.

**5. Пустая строка считается неверной (или верной).**
`Number("")` равно 0, но здесь пустая строка вообще не доходит до разбора: у неё нет двух частей. Если не отсеять её первой, она увеличит счётчик неверных строк. Пропускайте пустые строки сразу после `trim`.

**6. Не очистили строку.**
Без `trim` в окончаниях Windows сумма имеет вид `"50\r"`: `Number` это переживает, а проверка `line === ""` - нет. Очищайте каждую строку.

**7. Сумма как строка.**
`parts[1]` - текст. Если сложить `totals[category] + parts[1]`, получится склейка `"1005"` вместо `105`. Превращайте в число сразу: `Number(parts[1])`.

**8. Результат объявлен внутри цикла.**
`let overall = 0;` внутри цикла обнуляется на каждой строке, и итог равен последней сумме. Переменные для итогов объявляйте перед циклом.

<!-- section: summary -->
## Итоги

* Задача, состоящая из многих правил, решается конвейером: прочитать, разобрать, накопить, вывести.
* Каждый этап пишут и проверяют по отдельности, на маленьких входах.
* Итоги живут в переменных, объявленных перед циклом; внутри цикла они только изменяются.
* Крайние случаи - пустой ввод, одни плохие строки, отрицательные числа, равные суммы - нужно продумать заранее: по условию, до кода.

## Для тех, кто уже программирует

* Подход «разбери строку в запись или `null`, затем работай с записью» нужен для границы системы: данные снаружи нельзя считать верными. В больших программах это делают функциями-парсерами и валидаторами; здесь парсер - несколько строк в цикле.
* Объект как словарь: `in` проверяет и ключи прототипа (`"constructor" in {}` даёт `true`), поэтому для произвольных пользовательских ключей надёжнее `Map` или `Object.hasOwn`. В учебной задаче категории - обычные слова.
* `toSorted()` без компаратора сравнивает строки по кодовым единицам UTF-16, не по алфавиту языка. Для локализованной сортировки используют `localeCompare` или `Intl.Collator`.
* Деньги в `number` хранят в минимальных единицах (копейках) целыми числами, чтобы не накапливать ошибки двоичной дроби. В задаче суммы печатаются с округлением, чего достаточно.
* `fs.readFileSync(0)` читает весь ввод в память; для больших потоков нужны потоковые API.

<!-- section: deep-dive -->
## Почему этапы лучше одного большого цикла

Это необязательный раздел.

Можно записать решение одним циклом, который читает, разбирает, считает и печатает. Для небольшой задачи это работает, но каждое изменение условия затрагивает весь цикл. Если же этапы отделены (разбор в функции, накопление в объекте, вывод после цикла), то изменение формата вывода не трогает разбор, а новое правило проверки строки не трогает печать. Это та же идея, что и у функций: имя и границы для куска работы.

Заметьте также, что вывод происходит после цикла, когда все данные известны. Сортировку и поиск максимума невозможно сделать, пока не прочитаны все строки: категории могут встретиться в любом порядке. Если данные для следующего шага ещё не готовы, их нужно накопить, а не выводить сразу.
