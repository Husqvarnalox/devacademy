## Функции в Kotlin: меньше перегрузок, больше выразительности

Функция в Kotlin - полноправное значение, а её объявление умеет то, ради чего в Java приходится писать перегрузки и вспомогательные классы.

* **Параметры по умолчанию** (`fun f(x: Int, y: Int = 0)`) заменяют серию перегрузок.
* **Именованные аргументы** (`f(x = 1, y = 2)`) делают вызов читаемым и позволяют пропустить средние параметры по умолчанию.
* **Функции-расширения** (`fun String.shout()`) добавляют «метод» существующему типу, не наследуя его и не меняя исходного кода.
* **Scope-функции** `let`, `run`, `with`, `apply`, `also` выполняют блок кода в контексте объекта. Они различаются тем, как внутри блока называется объект (`it` или `this`) и что возвращается (результат блока или сам объект).

Выбирают scope-функцию не по вкусу, а по двум вопросам: «как я обращаюсь к объекту внутри?» и «что мне нужно получить снаружи?».

## Подробнее

**Параметры по умолчанию.** Значение вычисляется при каждом вызове и может зависеть от предыдущих параметров: `fun f(a: Int, b: Int = a * 2)`. Параметры по умолчанию удобно ставить в конец, но не обязательно: если пропущен средний, остальные аргументы передают по имени. Переопределяющий метод наследует значения по умолчанию базового и не может объявлять свои.

**Именованные аргументы.** Смешивать позиционные и именованные можно, но после первого именованного позиционные допустимы только если порядок не нарушен. Для `vararg` готовый массив разворачивают оператором `*`: `f(*array)`; параметры после `vararg` передают только по имени.

**Однострочные функции и `Unit`.** `fun sq(x: Int) = x * x` выводит тип результата. Функция без результата возвращает `Unit`; тип писать не нужно.

**Расширения.** `fun Type.name(...)` внутри видит публичные члены `Type` через `this`. Расширение **не вставляется в класс**: оно компилируется в статическую функцию, поэтому
* вызывается по **статическому** типу переменной, а не по динамическому;
* если у типа есть член с такой же сигнатурой, **побеждает член**;
* приватные члены типа ему недоступны.

Получатель расширения может быть nullable: `fun String?.orDash() = this ?: "-"` вызывается и на `null`. Можно объявлять и расширяющие свойства (без поля): `val String.lastChar get() = this[length - 1]`.

**Scope-функции.**

| Функция | Объект внутри | Результат |
|---|---|---|
| `let` | `it` | результат блока |
| `run` | `this` | результат блока |
| `with(obj)` | `this` | результат блока |
| `apply` | `this` | сам объект |
| `also` | `it` | сам объект |

`apply` подходит для настройки объекта при создании, `also` - для побочных действий (лог, проверка) в цепочке, `let` - для преобразования nullable (`x?.let { ... }`) и локальных имён, `run` и `with` - для вычисления значения на основе нескольких членов объекта. Не вкладывайте их друг в друга глубже одного-двух уровней: из-за неявного `this` легко запутаться, к какому объекту относится имя.

**`buildString` и ему подобные.** `buildString { append(...) }` - это функция высшего порядка с получателем: блок выполняется с `StringBuilder` в роли `this`. На этом же принципе устроены `apply`, `run` и построители коллекций (`buildList`, `buildMap`).

## Примеры

**Пример 1. Значения по умолчанию, имена и `vararg`.**

```kotlin run
fun connect(host: String, port: Int = 80, secure: Boolean = false, vararg tags: String): String =
    "${if (secure) "https" else "http"}://$host:$port tags=${tags.toList()}"

fun main() {
    println(connect("a.org"))
    println(connect("a.org", 8080))
    println(connect("a.org", secure = true))
    println(connect(host = "b.org", port = 1, tags = arrayOf("x", "y")))
    val extra = arrayOf("p", "q")
    println(connect("c.org", 22, true, *extra))
}
```
```output
http://a.org:80 tags=[]
http://a.org:8080 tags=[]
https://a.org:80 tags=[]
http://b.org:1 tags=[x, y]
https://c.org:22 tags=[p, q]
```

**Пример 2. Расширения: статическая диспетчеризация и приоритет членов.**

```kotlin run
open class Animal
class Dog : Animal()

fun Animal.name() = "animal"
fun Dog.name() = "dog"

class Box {
    fun size() = "member"
}
fun Box.size() = "extension"

fun String?.orDash(): String = this ?: "-"
val String.lastChar: Char get() = this[length - 1]

fun main() {
    val a: Animal = Dog()
    println(a.name())           // тип переменной Animal
    println(Dog().name())
    println(Box().size())       // член сильнее расширения
    val s: String? = null
    println(s.orDash())
    println("kotlin".lastChar)
}
```
```output
animal
dog
member
-
n
```

**Пример 3. Scope-функции: что видно внутри и что возвращается.**

```kotlin run
data class Person(var name: String = "", var age: Int = 0)

fun main() {
    val p = Person().apply { name = "Ann"; age = 30 }           // this, возвращает p
    println(p)
    val logged = p.also { println("also: ${it.name}") }          // it, возвращает p
    println(logged === p)
    val len = p.let { it.name.length }                            // it, результат блока
    println(len)
    val text = p.run { "$name is $age" }                          // this, результат блока
    println(text)
    val shout = with(p) { name.uppercase() }                      // this, результат блока
    println(shout)
    val maybe: String? = "12"
    println(maybe?.let { it.toInt() + 1 })
    val none: String? = null
    println(none?.let { it.toInt() + 1 })
}
```
```output
Person(name=Ann, age=30)
also: Ann
true
3
Ann is 30
ANN
13
null
```

## Типичные ошибки

* **Считать расширение «настоящим методом».** Оно не видит приватных членов и вызывается по статическому типу.
* **Ожидать, что расширение переопределит член.** При совпадении сигнатур всегда вызывается член; компилятор предупредит об этом.
* **Считать значение по умолчанию общим.** Выражение вычисляется при каждом вызове: `fun f(list: MutableList<Int> = mutableListOf())` создаёт новый список каждый раз.
* **Неудачный выбор scope-функции.** Для настройки объекта нужен `apply`, а `let` с `it` приведёт к лишнему `it.` в каждой строке.
* **Вкладывать несколько `run` и `apply`.** Неявный `this` внешнего блока смешивается с внутренним.
* **Лишний `let` на ненулевом значении.** Он только усложняет код; `let` оправдан для `?.` или для ограничения области видимости.
* **Забыть, что `apply` возвращает объект, а не результат блока.** Последнее выражение блока при этом игнорируется.

## Итоги

* Параметры по умолчанию и именованные аргументы заменяют перегрузки.
* Расширение - статическая функция: вызов по статическому типу, член побеждает, приватное недоступно.
* `let`/`run`/`with` возвращают результат блока, `apply`/`also` - сам объект; `it` у `let` и `also`, `this` у остальных.
* `buildString`, `buildList` и подобные - функции с получателем, на этой же идее построен DSL в Kotlin.

## Факты

* Переопределяющая функция использует значения по умолчанию базовой и не может задавать свои.
* Расширения разрешаются статически: по объявленному типу выражения.
