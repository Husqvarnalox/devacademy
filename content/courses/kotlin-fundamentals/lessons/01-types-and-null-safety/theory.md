## Типы, val/var и null: что проверяет компилятор

В Kotlin почти всё - объекты: `Int`, `Double`, `Boolean`, `String` выглядят как обычные классы, а на JVM компилятор сам превращает их в примитивы, где это возможно. От вас требуется только знать три правила.

* **`val` - значение без переприсваивания, `var` - переменная.** По умолчанию пишите `val`: код проще читать, а компилятор лучше выводит типы. Тип обычно выводится из правой части: `val n = 3` это `Int`.
* **Числовые типы не приводятся неявно.** `Int` не превращается в `Long` сам: пишите `x.toLong()`. Это защищает от тихих переполнений и от «чудес» вроде `Int + Long` в других языках.
* **`T?` - отдельный тип, допускающий `null`.** Вы уже знаете `?.`, `?:` и `!!` из [первого курса](lesson:kotlin.first-steps.null-safety-and-val-var). Здесь мы добавим то, что позволяет работать с типами уверенно: **smart cast** (компилятор сам сужает тип после проверки `is` или `!= null`), безопасное приведение `as?` и проверку типа `Any` в `when`.

Компилятор не разрешает «может быть, там `null`» и «может быть, там `Int`» оставлять без проверки. Поэтому ошибки типов выявляются при сборке, а не у пользователя.

## Подробнее

**`val` и `var`.** `val` запрещает присвоить переменной другое значение, но не делает неизменяемым сам объект: `val list = mutableListOf(1)` по-прежнему допускает `list.add(2)`. Верхнеуровневая константа времени компиляции объявляется как `const val` (только примитивы и `String`).

**Числа.** Литерал `3` - `Int`, `3L` - `Long`, `3.0` - `Double`, `3.0f` - `Float`. `Int` занимает 32 бита и переполняется молча: `Int.MAX_VALUE + 1` равно `Int.MIN_VALUE`. Для суммирования потенциально больших чисел берите `Long`. Целочисленное деление отбрасывает дробную часть: `7 / 2` равно `3`, а `7 / 2.0` равно `3.5`. Для явных преобразований есть `toInt()`, `toLong()`, `toDouble()`; `toInt()` у `Double` отбрасывает дробную часть.

**Равенство.** `==` вызывает `equals` (структурное равенство), `===` сравнивает ссылки. В отличие от Java, `==` на строках сравнивает содержимое.

**`Any`, `Any?` и `Nothing`.** `Any` - корень иерархии ненулевых типов; `Any?` - корень вообще всех. `Nothing` - тип выражения, которое не возвращается (`throw`, `return`), поэтому `x ?: return` и `x ?: throw ...` имеют тип `x` без `null`.

**Smart cast.** После `if (v is String)` внутри ветки `v` имеет тип `String`; то же после `v != null`. Условие: компилятор должен быть уверен, что значение не изменится между проверкой и использованием. Это работает для `val`, для локальных `var`, которые не захвачены изменяющим их замыканием, но не для изменяемых свойств класса и свойств с пользовательским геттером из другого модуля. В последнем случае скопируйте значение в локальный `val`.

**`as` и `as?`.** `x as String` бросает `ClassCastException`, если приведение невозможно. `x as? String` возвращает `null` вместо исключения, поэтому его удобно сочетать с `?:`.

**`let` для nullable.** `value?.let { ... }` выполняет блок только если значение не `null`, и внутри `it` уже без `?`. Подробнее о `let` в следующем уроке.

**Типы-источники `null`.** Кроме `toIntOrNull()` и `map[key]` стоит запомнить `firstOrNull()`, `getOrNull(i)` и `readlnOrNull()`.

## Примеры

**Пример 1. Числа не расширяются сами.**

```kotlin run
fun main() {
    val a = Int.MAX_VALUE
    println(a + 1)                 // переполнение Int
    println(a.toLong() + 1)        // явное расширение
    println(7 / 2)                 // целочисленное деление
    println(7 / 2.0)
    val x: Long = 5                // литерал подстраивается под объявленный тип
    println(x + 1)
    println(3.9.toInt())           // дробная часть отбрасывается
    println("a" == "a" && !("a" === "b"))
}
```
```output
-2147483648
2147483648
3
3.5
6
3
true
```

**Пример 2. Smart cast по `is` и по `!= null`.**

```kotlin run
fun len(v: Any?): String = when (v) {
    null -> "null"
    is String -> "строка из ${v.length}"      // v: String
    is Int -> "число ${v + 1}"                // v: Int
    is List<*> -> "список из ${v.size}"
    else -> "что-то другое"
}

fun main() {
    println(len(null))
    println(len("kotlin"))
    println(len(41))
    println(len(listOf(1, 2, 3)))
    println(len(2.5))

    val s: String? = "abc"
    if (s != null && s.length > 2) println("длинная: ${s.uppercase()}")
}
```
```output
null
строка из 6
число 42
список из 3
что-то другое
длинная: ABC
```

**Пример 3. `as?`, `let` и `?: return` вместо `!!`.**

```kotlin run
fun firstWord(x: Any?): String {
    val text = x as? String ?: return "не строка"
    val word = text.trim().split(" ").firstOrNull { it.isNotEmpty() } ?: return "пусто"
    return word
}

fun main() {
    println(firstWord(42))
    println(firstWord("   "))
    println(firstWord("  hello world"))

    val raw: String? = "12"
    raw?.toIntOrNull()?.let { println("число: ${it * 2}") }

    val bad: Any = 5
    try {
        println(bad as String)
    } catch (e: ClassCastException) {
        println("ClassCastException")
    }
}
```
```output
не строка
пусто
hello
число: 24
ClassCastException
```

## Типичные ошибки

* **Складывать `Int` до преобразования в `Long`.** `a * b` с двумя `Int` переполнится до того, как результат попадёт в `Long`. Преобразуйте операнд: `a.toLong() * b`.
* **Ждать smart cast для `var`-свойства класса.** Компилятор не может гарантировать, что другой код не изменит поле. Копируйте в локальный `val`.
* **Использовать `as` там, где можно `as?`.** Жёсткое приведение превращает ошибку данных в исключение.
* **Считать, что `val` делает объект неизменяемым.** `val` фиксирует ссылку, а не содержимое.
* **Писать `!!` ради компиляции.** Обычно достаточно `?:`, `?.let` или раннего `return`.
* **Сравнивать числа разных типов через `==`.** `1 == 1L` не компилируется: типы нужно привести явно.
* **Путать `toInt()` и `toIntOrNull()`.** Первая бросает `NumberFormatException` на мусоре, вторая вернёт `null`.

## Итоги

* По умолчанию `val`; `var` только когда значение действительно меняется.
* Числа не расширяются неявно; `Int` переполняется молча, большие суммы считайте в `Long`.
* `is` и `!= null` сужают тип (smart cast) для стабильных значений.
* `as?` вместе с `?:` заменяет небезопасное `as` и `!!`.
* `Nothing` позволяет писать `?: return` и `?: throw` без потери типа.

## Факты

* Умолчание `val` не означает глубокую неизменяемость: `val` лишь запрещает переприсваивание.
* `Nothing` - подтип любого типа, поэтому выражение `x ?: throw e` имеет тип `x` без `null`.
