## Заимствование и время жизни ссылки

Ссылка - это «взять на время». Время, в течение которого ссылка может безопасно использоваться, Rust называет **временем жизни** (lifetime). У каждой ссылки оно есть всегда, но чаще всего компилятор выводит его сам, и вы его не пишете. Аннотации `'a` нужны только тогда, когда компилятор не может понять, откуда взялась ссылка в результате.

Два правила, которые проверяет **borrow checker**:

1. В любой момент у значения либо любое число общих ссылок `&T`, либо ровно одна изменяемая `&mut T`.
2. Ссылка не может пережить значение, на которое она указывает.

Первое правило защищает от гонок данных и инвалидации (например, указатель на элемент вектора, пока вектор перераспределяется). Второе - от «висячих» указателей.

Ссылка «живёт» не до конца блока, а **до последнего использования** (так работает NLL, non-lexical lifetimes). Поэтому следующий код компилируется:

```rust run
fn main() {
    let mut text = String::from("Rust");
    let view = &text;               // общая ссылка
    println!("читаем: {view}");     // последнее использование view
    text.push('!');                 // можно: view больше не нужна
    println!("{text}");
}
```
```output
читаем: Rust
Rust!
```

Если же поменять порядок и использовать `view` после `push`, компилятор откажет. Вот настоящие сообщения `rustc 1.99` для четырёх ошибок, которые вы будете видеть чаще всего:

```
error[E0499]: cannot borrow `s` as mutable more than once at a time
error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable
error[E0106]: missing lifetime specifier
error[E0515]: cannot return reference to local variable `s`
```

## Правила заимствования и времена жизни точно

**Что считается заимствованием.** `&x` и `&mut x` создают заимствование на `x`. Обращение к полю или элементу (`&v[0]`, `&p.name`) заимствует родителя (весь вектор) либо только поле, если путь известен компилятору. Методы с `&self` и `&mut self` тоже заимствуют.

**Конфликты и коды ошибок.**

| Что вы сделали | Код |
|---|---|
| вторая `&mut` пока жива первая | `E0499` |
| `&mut` (например, `push`) пока жива `&` | `E0502` |
| записали или переместили, пока значение заимствовано | `E0506` / `E0505` |
| вернули ссылку на локальную переменную | `E0515` |
| ссылка пережила значение (например, во внешнем блоке) | `E0597` |
| в сигнатуре непонятно, откуда ссылка в результате | `E0106` |

**NLL.** Область жизни ссылки - это множество точек программы от создания до последнего использования, проходящее по графу потока управления. Поэтому конфликт возникает, только если ссылка ещё понадобится позже. Ещё одно удобство - **двухфазные заимствования** (two-phase borrows): `v.push(v.len())` компилируется, потому что `&mut v` для `push` «активируется» после вычисления аргументов.

**Параметры времени жизни.** Запись `fn longest<'a>(a: &'a str, b: &'a str) -> &'a str` говорит: результат живёт не дольше, чем **оба** аргумента (точнее, пересечение их времён жизни). Аннотация ничего не удлиняет и не создаёт; она лишь **связывает** времена жизни входов и выхода, чтобы вызывающий код проверялся правильно.

**Правила пропуска (elision).** В сигнатурах функций можно не писать времена жизни, если выполняются правила:

1. каждому пропущенному времени жизни во **входных** ссылках присваивается своё имя;
2. если входной параметр времени жизни ровно один, он присваивается всем пропущенным **выходным**;
3. если среди входов есть `&self` или `&mut self`, время жизни `self` присваивается всем пропущенным выходным.

Поэтому `fn first_word(s: &str) -> &str` работает (правило 2), метод `fn name(&self) -> &str` тоже (правило 3), а `fn longest(a: &str, b: &str) -> &str` - нет (два входа, нет `self`): `E0106`.

**Структуры со ссылками.** Структура, хранящая ссылку, обязана объявить параметр: `struct Excerpt<'a> { part: &'a str }`. Экземпляр не может пережить строку, на которую ссылается `part`. В `impl<'a> Excerpt<'a>` метод `fn part(&self) -> &'a str` возвращает ссылку, связанную с исходным текстом, а не с `self`, и поэтому её можно использовать после уничтожения самой структуры.

**`'static`.** Строковые литералы имеют тип `&'static str`: данные лежат в самой программе и живут всё время работы. Граница `T: 'static` означает «T не содержит коротких ссылок» (это не то же самое, что «живёт вечно»).

**Как исправлять E0515.** Ссылку на локальное значение вернуть нельзя: оно уничтожится при выходе. Возвращайте владение (`String`), принимайте буфер как `&mut` параметр или возвращайте ссылку на данные, пришедшие снаружи.

**Раздельные заимствования.** Компилятор различает непересекающиеся поля структуры (`&mut p.a` и `&mut p.b` одновременно допустимы) и не различает элементы среза: для двух `&mut` на разные элементы служит `split_at_mut`.

## Примеры

**Пример 1. Двухфазное заимствование и последовательные ссылки.**

```rust run
fn main() {
    let mut v = vec![1, 2, 3];
    v.push(v.len() as i32);          // E0502 не возникает: two-phase borrow
    let sum: i32 = v.iter().sum();   // общая ссылка живёт внутри выражения
    v.push(sum);                     // изменяемая - уже можно
    println!("{:?}", v);

    let (left, right) = v.split_at_mut(2);   // две &mut на непересекающиеся части
    left[0] += right[0];
    println!("{:?}", v);
}
```
```output
[1, 2, 3, 3, 9]
[4, 2, 3, 3, 9]
```

**Пример 2. Функция с явным временем жизни.**

```rust run
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() >= b.len() { a } else { b }
}

fn main() {
    let first = String::from("long string");
    let result;
    {
        let second = String::from("xyz");
        result = longest(first.as_str(), second.as_str());
        println!("внутри блока: {result}");
    }   // second уничтожена; result здесь уже использовать нельзя
    println!("{first}");
}
```
```output
внутри блока: long string
long string
```

Если после закрывающей скобки блока попытаться напечатать `result`, будет `E0597`:

```
error[E0597]: `b` does not live long enough
  |         result = longest(a.as_str(), b.as_str());
  |                                      ^ borrowed value does not live long enough
  |     }
  |     - `b` dropped here while still borrowed
  |     println!("{}", result);
  |                    ------ borrow later used here
```

**Пример 3. Разные времена жизни у входов.**

```rust run
fn pick_first<'a, 'b>(a: &'a str, _b: &'b str) -> &'a str {
    a    // результат не зависит от второго аргумента
}

fn main() {
    let a = String::from("alpha");
    let r;
    {
        let b = String::from("beta");
        r = pick_first(&a, &b);   // b может быть короче, чем r
    }
    println!("{r}");
}
```
```output
alpha
```

**Пример 4. Структура со ссылкой и метод.**

```rust run
struct Excerpt<'a> {
    part: &'a str,
}

impl<'a> Excerpt<'a> {
    fn new(text: &'a str) -> Self {
        let part = text.split('.').next().unwrap_or(text);
        Excerpt { part }
    }
    // Время жизни результата - 'a (текст), а не время жизни self
    fn part(&self) -> &'a str {
        self.part
    }
    // Правило 3: пропущенное время жизни результата берётся у self
    fn describe(&self) -> &str {
        self.part
    }
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let part;
    {
        let e = Excerpt::new(&novel);
        part = e.part();            // можно: связана с novel, а не с e
        println!("{}", e.describe());
    }
    println!("{part}");
}
```
```output
Call me Ishmael
Call me Ishmael
```

**Пример 5. Исправление E0515: вернуть владение.**

```rust run
// fn bad() -> &String { let s = String::from("x"); &s }   // E0106, а с 'static - E0515
fn good() -> String {
    let s = String::from("hello");
    s                       // владение уходит вызывающему
}

fn append_greeting(out: &mut String, name: &str) {
    out.push_str("привет, ");     // либо пишем в буфер, который дал вызывающий
    out.push_str(name);
}

fn main() {
    let a = good();
    let mut b = String::new();
    append_greeting(&mut b, "Ada");
    println!("{a} / {b}");
}
```
```output
hello / привет, Ada
```

**Пример 6. Раздельные поля и `&mut` через функцию.**

```rust run
struct Counters {
    hits: u32,
    misses: u32,
}

fn bump(n: &mut u32) {
    *n += 1;
}

fn main() {
    let mut c = Counters { hits: 0, misses: 0 };
    let h = &mut c.hits;       // заимствует только поле hits
    let m = &mut c.misses;     // и только поле misses: конфликта нет
    bump(h);
    bump(m);
    bump(h);
    println!("{} {}", c.hits, c.misses);
}
```
```output
2 1
```

## Типичные ошибки

* **Пытаться «удлинить» время жизни аннотацией.** `'a` не продлевает жизнь данным, она лишь описывает связь; чтобы данные жили дольше, измените владельца.
* **Вешать одно и то же `'a` на всё подряд.** `fn f<'a>(x: &'a str, y: &'a str) -> &'a str` связывает результат с обоими входами; если результат зависит только от `x`, дайте им разные имена.
* **Возвращать ссылку на локальную переменную** (`E0515`). Возвращайте `String`/`Vec`.
* **Хранить ссылку в структуре, когда достаточно владения.** Для структур, которые передаются между потоками или живут долго, обычно проще владеть данными (`String`), чем нести `<'a>`.
* **Держать ссылку на элемент коллекции и менять коллекцию** (`E0502`). Скопируйте нужное значение (`let x = v[0];` для `Copy`) или сократите область жизни ссылки.
* **Две `&mut` в одной области** (`E0499`). Разделите работу на последовательные блоки, используйте `split_at_mut` или поля.
* **Думать, что ошибка заимствования означает «исправьте компилятор».** Чаще всего структура данных предполагает неявный алиасинг; перенесите изменение в метод или разделите структуры.

## Итоги

* Ссылка живёт до последнего использования (NLL); конфликт - только если она ещё понадобится.
* `&T` - много читателей, `&mut T` - один писатель; ошибки `E0499` и `E0502` показывают нарушение первого правила, `E0515`, `E0597` и `E0106` - второго.
* Аннотации `'a` связывают входы и выходы и ничего не удлиняют; в простых сигнатурах работают три правила пропуска.
* Структуре со ссылкой нужен параметр `<'a>`; метод может вернуть ссылку с `'a`, не зависящую от `&self`.
* Исправление «висячей» ссылки - вернуть владение или заимствовать у вызывающего.

Сравните с [указателями и ссылками в C++](lesson:cpp.first-steps.value-semantics-references-and-raii), где висячая ссылка - неопределённое поведение, а в Rust - ошибка компиляции, и со [срезами в Go](lesson:go.fundamentals.maps-and-slices-deep-dive), где срез удерживает массив живым благодаря сборщику мусора.
