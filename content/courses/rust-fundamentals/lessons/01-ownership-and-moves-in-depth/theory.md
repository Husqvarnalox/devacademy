## Три способа передать значение

В [первом курсе](lesson:rust.first-steps.ownership-moves-and-borrowing) вы узнали правило «один владелец». Теперь разберём, что на самом деле происходит с данными, когда вы пишете `let b = a;`, и как выбрать между тремя вариантами:

* **Copy** - значение дёшево копируется побитово, оригинал остаётся рабочим. Так ведут себя `i32`, `f64`, `bool`, `char`, `&T` и кортежи из таких типов.
* **Move** - значение переезжает к новому владельцу, старое имя становится недоступным. Так ведут себя `String`, `Vec<T>`, `Box<T>` и ваши структуры, если вы не объявили их `Copy`.
* **Clone** - вы явно просите глубокую копию методом `.clone()`. Это может быть дорого, поэтому Rust никогда не делает её молча.

Перемещение - это не «медленное копирование»: перемещается только маленький «паспорт» значения (для `String` - указатель, длина и ёмкость), а буфер с текстом остаётся на месте. Просто после перемещения компилятор запрещает пользоваться старым именем, чтобы не освободить буфер дважды.

```rust run
fn main() {
    let a = String::from("rust");
    let heap = a.as_ptr();        // адрес буфера с текстом
    let b = a;                    // move: буфер не копируется
    println!("буфер на месте: {}", b.as_ptr() == heap);

    let c = b.clone();            // clone: новый буфер
    println!("после clone буфер другой: {}", c.as_ptr() != b.as_ptr());

    let x = 7;
    let y = x;                    // Copy: оба имени живы
    println!("{x} {y}");
}
```
```output
буфер на месте: true
после clone буфер другой: true
7 7
```

Ещё одна важная вещь - **порядок уничтожения**. Когда владелец выходит из области видимости, Rust вызывает `drop`. Локальные переменные уничтожаются в порядке, обратном объявлению, а это позволяет писать RAII-код (закрытие файлов, освобождение блокировок) без `finally`.

## Copy, Move, Clone и Drop точно

**Что такое перемещение.** Присваивание, передача аргумента, возврат из функции и захват в замыкание с `move` для не-`Copy` типов - это побайтовая передача значения новому владельцу плюс «пометка» старой переменной как неинициализированной. Дальше компилятор отслеживает это статически (ошибка `E0382`: *borrow of moved value* или *use of moved value*). Во время работы никаких флагов нет, кроме особого случая условных перемещений: тогда компилятор добавляет скрытый «флаг уничтожения» (drop flag), чтобы знать, нужно ли вызывать `drop`.

**Copy.** Маркерный трейт `Copy` разрешает неявное копирование при присваивании. Реализовать его можно только для типа, все поля которого `Copy`; тип с полем `String` не получит `Copy` (ошибка `E0204`). Тип не может быть одновременно `Copy` и иметь `Drop` (ошибка `E0184`): иначе деструктор вызывался бы для каждой побитовой копии. `Copy` требует `Clone`, поэтому пишут `#[derive(Clone, Copy)]`.

**Clone.** Трейт `Clone` описывает явное копирование: для `String` это выделение нового буфера, для `Rc<T>` - всего лишь увеличение счётчика. Поэтому `.clone()` на `Rc` дёшев, а на `Vec<String>` - нет: читайте тип, прежде чем решать, что клонирование «безобидно».

**Передача в функцию и возврат.** `fn f(s: String)` забирает владение; когда `f` завершится, `s` будет уничтожена внутри функции, если её не вернуть. Если функция возвращает значение, владение передаётся вызывающему.

**Захват в замыкание.** Замыкание само решает, как захватить переменную: по ссылке, по изменяемой ссылке или по значению, - в зависимости от того, что нужно телу. Ключевое слово `move` заставляет захватывать **всё** по значению. Для `Copy`-типов это копия, для остальных - перемещение. Замыкание, которое перемещает захваченное значение наружу (например, возвращает его), реализует только `FnOnce`: вызвать его можно один раз. Для `thread::spawn` и для замыканий, живущих дольше текущей функции, `move` обязателен (иначе `E0373`).

**Порядок уничтожения** (см. справочник по `destructors`):

1. Локальные переменные - в порядке, обратном объявлению.
2. Поля структуры - в порядке объявления полей, после вызова `Drop::drop` самой структуры.
3. Элементы `Vec`, массива и кортежа - от первого к последнему.
4. Временные значения - в конце содержащего их выражения-оператора.
5. `let _ = expr;` уничтожает значение **сразу**, а `let _x = expr;` - в конце блока.
6. `std::mem::drop(x)` - это обычная функция, принимающая `x` по значению; её тело пустое, значение уничтожается при выходе из неё.

**Частичное перемещение.** Из структуры (или кортежа) можно переместить одно поле: `let a = p.a;`. После этого `p.a` и `p` целиком использовать нельзя, но остальные поля (`p.b`) доступны. Если тип реализует `Drop`, частичное перемещение запрещено (`E0509`), потому что деструктор должен получить структуру целой. Из-за ссылки или индекса тоже нельзя забрать значение (`E0507`): `let s = v[0];` для `Vec<String>` не компилируется; нужны `&v[0]`, `.clone()`, `mem::take` или `Vec::remove`.

**Забрать значение из `&mut`.** Оставить «дыру» за ссылкой нельзя, поэтому есть три идиомы: `std::mem::take(&mut x)` (оставляет `Default`), `std::mem::replace(&mut x, новое)` и `Option::take()` (оставляет `None`).

## Примеры

**Пример 1. Порядок уничтожения: переменные, поля, элементы.**

```rust run
struct Noisy(&'static str);

impl Drop for Noisy {
    fn drop(&mut self) {
        println!("drop {}", self.0);
    }
}

struct Pair {
    first: Noisy,
    second: Noisy,
}

fn main() {
    let _a = Noisy("a");
    let _b = Noisy("b");
    let _pair = Pair { first: Noisy("p.first"), second: Noisy("p.second") };
    let _v = vec![Noisy("v0"), Noisy("v1")];
    let _ = Noisy("сразу");   // уничтожается на месте
    println!("конец main");
}
```
```output
drop сразу
конец main
drop v0
drop v1
drop p.first
drop p.second
drop b
drop a
```

**Пример 2. Функция забирает владение, возвращает его или заимствует.**

```rust run
fn consume(s: String) -> usize {
    s.len()
}   // s уничтожается здесь

fn pass_through(s: String) -> String {
    println!("получил {s}");
    s                       // владение возвращено
}

fn peek(s: &str) -> usize {
    s.len()
}

fn main() {
    let s = String::from("hello");
    let s = pass_through(s);        // новая привязка с тем же именем
    println!("{}", peek(&s));       // заимствуем - s жива
    println!("{}", consume(s));     // s перемещена, дальше недоступна
}
```
```output
получил hello
5
5
```

**Пример 3. Замыкания: захват по ссылке и `move`.**

```rust run
fn main() {
    let name = String::from("Ada");
    let greet = || println!("привет, {name}");   // захват по ссылке
    greet();
    greet();
    println!("{name} всё ещё наша");

    let owned = move || println!("владею: {name}");  // перемещение в замыкание
    owned();
    // println!("{name}");  // ошибка E0382: name перемещена в замыкание

    let text = String::from("один раз");
    let once = move || text;           // возвращает захваченное: FnOnce
    let back = once();
    println!("{back}");
}
```
```output
привет, Ada
привет, Ada
Ada всё ещё наша
владею: Ada
один раз
```

**Пример 4. Частичное перемещение.**

```rust run
struct User {
    name: String,
    email: String,
    age: u32,
}

fn main() {
    let u = User { name: "Ada".into(), email: "ada@example.com".into(), age: 36 };
    let name = u.name;          // перемещено только поле name
    println!("{} {}", u.email, u.age);   // остальные поля доступны
    println!("{name}");
    // println!("{}", u.name);  // ошибка: поле перемещено
    // let v = u;               // ошибка: u перемещена частично
}
```
```output
ada@example.com 36
Ada
```

**Пример 5. Забрать значение из изменяемой ссылки.**

```rust run
use std::mem;

struct Buffer {
    data: Vec<u8>,
    label: Option<String>,
}

impl Buffer {
    fn flush(&mut self) -> Vec<u8> {
        mem::take(&mut self.data)               // на месте остаётся пустой Vec
    }
    fn rename(&mut self, new: &str) -> Option<String> {
        self.label.replace(new.to_string())     // отдаёт старое значение
    }
    fn clear_label(&mut self) -> Option<String> {
        self.label.take()                       // на месте остаётся None
    }
}

fn main() {
    let mut b = Buffer { data: vec![1, 2, 3], label: Some("old".into()) };
    println!("{:?} {}", b.flush(), b.data.len());
    println!("{:?}", b.rename("new"));
    println!("{:?} {:?}", b.clear_label(), b.label);
}
```
```output
[1, 2, 3] 0
Some("old")
Some("new") None
```

**Пример 6. Copy для собственного типа.**

```rust run
#[derive(Debug, Clone, Copy)]
struct Point {
    x: i32,
    y: i32,
}

fn shifted(p: Point) -> Point {      // p скопирована, вызывающий её сохраняет
    Point { x: p.x + 1, ..p }
}

fn main() {
    let p = Point { x: 1, y: 2 };
    let q = shifted(p);
    println!("{:?} {:?}", p, q);
}
```
```output
Point { x: 1, y: 2 } Point { x: 2, y: 2 }
```

Что говорит компилятор в типичных случаях (в блоках без `run` показаны сообщения `rustc 1.99`):

```
error[E0382]: borrow of moved value: `s`        // использовали s после let t = s;
error[E0509]: cannot move out of type `Guard`, which implements the `Drop` trait
error[E0507]: cannot move out of index of `Vec<String>`
error[E0204]: the trait `Copy` cannot be implemented for this type
error[E0373]: closure may outlive the current function, but it borrows `v`
```

## Типичные ошибки

* **Считать, что `let b = a;` копирует данные.** Для `String`/`Vec` это перемещение; копирование - только `.clone()`.
* **Клонировать, чтобы заглушить `E0382`.** Сначала спросите: нужна ли функции именно собственность? Часто достаточно `&T`.
* **Вешать `#[derive(Copy)]` на тип с `String` или `Vec`.** Это `E0204`; такой тип можно только `Clone`.
* **Ожидать, что `_` и `_x` ведут себя одинаково.** `let _ = f();` уничтожает значение сразу, `let _guard = f();` держит до конца блока. Для блокировки (guard) это принципиально.
* **Забыть, что временное значение живёт только до конца оператора.** Ссылку на него нельзя сохранить в переменную на следующую строку (если только это не `let r = &make();`, где Rust продлевает время жизни временного значения).
* **Пытаться переместить поле у типа с `Drop` или значение из-за индекса.** Используйте `mem::take`, `Option::take`, `Vec::remove`/`swap_remove` или `.clone()`.
* **Передать замыкание в `thread::spawn` без `move`.** Получите `E0373`: замыкание захватило ссылку на локальную переменную.
* **Считать, что `Rc::clone` копирует данные.** Он увеличивает счётчик ссылок; подробнее в [уроке про умные указатели](lesson:rust.fundamentals.smart-pointers-and-interior-mutability).

## Итоги

* Copy - неявная побитовая копия, Move - передача владения, Clone - явная (возможно, дорогая) копия.
* Перемещается только «паспорт» значения; буфер данных не копируется.
* Локальные переменные уничтожаются в обратном порядке объявления, поля структуры и элементы `Vec` - в прямом; `let _ =` уничтожает немедленно.
* `move` у замыкания захватывает всё по значению; замыкание, отдающее захваченное, - `FnOnce`.
* Частичное перемещение допустимо для обычных структур, но не для типов с `Drop`; из `&mut` значение забирают через `mem::take`, `mem::replace` или `Option::take`.

Сравните с [семантикой значений и RAII в C++](lesson:cpp.first-steps.value-semantics-references-and-raii): там перемещение - это конструктор перемещения и «опустошённый» объект, а в Rust оно проверяется компилятором, и обратиться к «пустому» объекту невозможно. В Go присваивание структуры копирует её, а [срезы и карты](lesson:go.fundamentals.maps-and-slices-deep-dive) разделяют данные неявно.
