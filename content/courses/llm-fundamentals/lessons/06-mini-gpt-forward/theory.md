## Что происходит между списком номеров и вероятностями

Когда вы отправляете чату сообщение, токенизатор превращает его в список номеров. Дальше модель выполняет один и тот же набор операций, и на выходе для каждой позиции получается оценка того, какой токен вероятнее всего идёт следующим. Этот урок разбирает весь путь целиком: из номеров токенов в **логиты** (числа по одному на каждый токен словаря, из которых позже получаются вероятности). Зная этот путь, вы понимаете, чем чат-ассистент на основе LLM отличается от нескольких матриц: принципиально ничем, это те же операции в большем масштабе.

Устройство модели семейства GPT (**decoder-only** - «только декодер») можно описать пятью шагами:

1. **Эмбеддинги.** Каждому токену соответствует вектор из таблицы `wte` (word token embeddings). К нему прибавляется вектор позиции из таблицы `wpe`: сама по себе операция внимания не знает порядка токенов, и номер места нужно подать явно.
2. **Стопка блоков.** Через `N` одинаково устроенных **блоков** проходит матрица `x` формы `(T, d)`: по строке на токен. Блок состоит из внимания (токены обмениваются информацией) и небольшой сети MLP (каждый токен перерабатывается отдельно).
3. **Остаточный поток.** Блок не заменяет `x`, а **добавляет** к нему поправку: `x = x + attn(...)`, затем `x = x + mlp(...)`. Поэтому `x` удобно представлять потоком, в который каждый блок дописывает свои наблюдения.
4. **Финальная нормализация** LayerNorm.
5. **Логиты.** Результат умножается на транспонированную таблицу эмбеддингов: `logits = x @ wte.T`. Для позиции `t` получается строка из `V` чисел (`V` - размер словаря). Это оценка токена, который стоит на месте `t + 1`.

Веса в упражнении случайные, поэтому текст, который такая модель «сочиняет», бессмыслен. Это нормально: цель урока - механизм. Настоящая GPT-подобная модель имеет те же формы массивов и те же операции, только больше блоков, шире векторы и обученные веса.

## Прямой проход подробно

Обозначения: `T` - длина последовательности, `d` - ширина модели (`d_model`), `V` - размер словаря, `h` - число голов внимания, `L` - число блоков, `max_len` - максимальная длина контекста.

**Вход.** `x = wte[ids] + wpe[:T]`, форма `(T, d)`. Таблица `wpe` в GPT-2 **обучаемая**: у каждой позиции `0..max_len-1` свой вектор, подбираемый при обучении. Поэтому длина входа ограничена числом строк `wpe`: при `T > max_len` брать позиции нечем, и функция должна бросить `ValueError`. Столь же строгими должны быть идентификаторы токенов: `id` вне `0..V-1` означает ошибку токенизатора или словаря, и тихо «подправлять» его нельзя.

**LayerNorm.** Для каждой строки (токена) отдельно:

`LN(x) = (x - mean) / sqrt(var + eps) * g + b`

Среднее и дисперсия считаются по `d` числам одного токена, то есть по последней оси; дисперсия **смещённая** (деление на `d`, как в `np.var`). Параметры `g` (гейн) и `b` (смещение) обучаются. Зачем: у сумм многих вкладов масштаб `x` растёт от слоя к слою, а следующие матрицы работают лучше, когда вход имеет предсказуемый масштаб. Малое `eps` стоит под корнем, чтобы строка из одинаковых чисел (`var = 0`) не давала деления на ноль. В отличие от BatchNorm, статистика не зависит от других токенов и других примеров батча, поэтому во время генерации ничего «не подтягивается» из соседей (источник: [Ba и др., Layer Normalization](https://arxiv.org/abs/1607.06450)).

**Pre-LN блок** (так устроен GPT-2):

```
x = x + attn(ln1(x))
x = x + mlp(ln2(x))
```

Нормализация стоит **перед** подслоем, а сам остаток `x` проходит дальше без нормализации. Из-за этого поправка подслоя «добавляется» к потоку, и если подслой выдаёт ноль, блок превращается в тождественное преобразование. Это свойство проверяет один из скрытых тестов.

**MLP.** `d -> 4d -> d`: `mlp(x) = gelu(x @ w_fc + b_fc) @ w_proj + b_proj`. Расширение в четыре раза - стандартный выбор GPT-2, а не закон: ширина промежуточного слоя - гиперпараметр. Внимание смешивает информацию **между** токенами, MLP обрабатывает каждый токен **отдельно** одной и той же сетью; именно в MLP, по современным представлениям, хранится значительная часть «знаний» модели, но это гипотеза интерпретируемости, а не доказанный факт.

**GELU.** Гладкая версия ReLU. GPT-2 использует tanh-приближение:

`gelu(x) = 0.5 * x * (1 + tanh(sqrt(2 / pi) * (x + 0.044715 * x^3)))`

Для больших положительных `x` значение близко к `x`, для больших отрицательных - к 0, около нуля функция плавно изгибается (определение GELU: [Hendrycks и Gimpel](https://arxiv.org/abs/1606.08415)).

**Внимание.** Функция `causal_self_attention` уже написана: это то, что вы реализовали в уроке про [внимание](lesson:llm.fundamentals.attention). В этом уроке важна композиция: что подаётся на вход, куда добавляется выход.

**Выход.** `x = LN_f(x)`, затем `logits = x @ wte.T`, форма `(T, V)`. Использование той же таблицы `wte` на входе и на выходе называется **привязкой весов** (weight tying): токен, чей вектор похож на вектор в потоке, получает высокий логит. GPT-2 так и делает; это экономит `V * d` параметров, а у больших словарей это десятки миллионов.

**Какой токен предсказывает какая строка.** Строка `t` логитов - оценка для токена на позиции `t + 1`. При генерации используется только последняя строка (`logits[-1]`), но при обучении полезны **все** строки сразу: каждая позиция даёт свою пару «контекст -> следующий токен» из одного прохода. Это возможно благодаря причинной маске: позиция `t` не видит токенов правее, поэтому её логиты не зависят от «ответа». Проверяемое следствие: `forward(ids[:k])` равна первым `k` строкам `forward(ids)`.

**Число параметров.** Для одного блока: LayerNorm `2d` + qkv `3d^2 + 3d` + выход внимания `d^2 + d` + LayerNorm `2d` + MLP `4d^2 + 4d` и `4d^2 + d`, всего `12 d^2 + 13 d`. Для модели:

`V*d + max_len*d + L*(12*d^2 + 13*d) + 2*d`

Основной вклад при больших `d` даёт `12 L d^2`: параметры растут квадратично с шириной и линейно с глубиной.

## Примеры

**Пример 1. LayerNorm работает по строке.**

```python run
import numpy as np

def layer_norm(x, g, b, eps=1e-5):
    mean = x.mean(axis=-1, keepdims=True)
    var = x.var(axis=-1, keepdims=True)
    return (x - mean) / np.sqrt(var + eps) * g + b

x = np.array([[1.0, 2.0, 3.0, 4.0],
              [10.0, 20.0, 30.0, 40.0],
              [5.0, 5.0, 5.0, 5.0]])
y = layer_norm(x, np.ones(4), np.zeros(4))
print(np.round(y, 3) + 0.0)
print("средние:", np.round(y.mean(axis=-1), 3) + 0.0)
print("дисперсии:", np.round(y.var(axis=-1), 3) + 0.0)
```
```output
[[-1.342 -0.447  0.447  1.342]
 [-1.342 -0.447  0.447  1.342]
 [ 0.     0.     0.     0.   ]]
средние: [0. 0. 0.]
дисперсии: [1. 1. 0.]
```

Разбор:

* `axis=-1, keepdims=True` - статистика считается внутри каждого токена, а `keepdims` сохраняет форму `(T, 1)`, чтобы вычитание шло построчно.
* Строки `[1, 2, 3, 4]` и `[10, 20, 30, 40]` после нормализации одинаковы: LayerNorm убирает масштаб и сдвиг каждого токена.
* Третья строка состоит из одинаковых чисел. Числитель равен нулю, а `eps` не даёт разделить ноль на ноль, поэтому получился ноль, а не `nan`; дисперсия результата тоже 0, а не 1.

**Попробуйте:** замените `eps=1e-5` на `eps=0.0` и предскажите, что произойдёт с третьей строкой, прежде чем запускать.

**Пример 3. Мини-GPT целиком и причинность.**

```python run
import numpy as np

def layer_norm(x, eps=1e-5):
    return (x - x.mean(-1, keepdims=True)) / np.sqrt(x.var(-1, keepdims=True) + eps)

def gelu(x):
    return 0.5 * x * (1 + np.tanh(np.sqrt(2 / np.pi) * (x + 0.044715 * x ** 3)))

def attention(x, p):
    T, d = x.shape
    q, k, v = np.split(x @ p["qkv"], 3, axis=-1)
    scores = q @ k.T / np.sqrt(d)
    scores = np.where(np.tril(np.ones((T, T), bool)), scores, -np.inf)
    w = np.exp(scores - scores.max(-1, keepdims=True))
    w /= w.sum(-1, keepdims=True)
    return (w @ v) @ p["o"]

def forward(ids, params):
    x = params["wte"][ids] + params["wpe"][:len(ids)]
    for p in params["blocks"]:
        x = x + attention(layer_norm(x), p)
        x = x + gelu(layer_norm(x) @ p["fc"]) @ p["proj"]
    return layer_norm(x) @ params["wte"].T

rng = np.random.default_rng(0)
V, d, max_len = 10, 8, 6
def w(*shape):
    return rng.normal(0, 0.5, shape)
params = {
    "wte": w(V, d), "wpe": w(max_len, d),
    "blocks": [{"qkv": w(d, 3 * d), "o": w(d, d), "fc": w(d, 4 * d), "proj": w(4 * d, d)} for _ in range(2)],
}
ids = [3, 1, 4, 1, 5]
logits = forward(ids, params)
print("логиты:", logits.shape)
print("предсказание после каждой позиции:", logits.argmax(axis=-1))
print("префикс из 3 токенов совпадает:", np.allclose(forward(ids[:3], params), logits[:3]))
ids2 = ids[:-1] + [9]
print("замена последнего токена не меняет прежние позиции:", np.allclose(forward(ids2, params)[:-1], logits[:-1]))
print("но меняет последнюю:", not np.allclose(forward(ids2, params)[-1], logits[-1]))
```
```output
логиты: (5, 10)
предсказание после каждой позиции: [6 1 7 2 8]
префикс из 3 токенов совпадает: True
замена последнего токена не меняет прежние позиции: True
но меняет последнюю: True
```

Разбор:

* `attention` здесь с одной головой и без смещений, чтобы поместиться в экран; в упражнении вы используете готовую многоголовую версию. Маска `np.tril` и значение `-inf` обнуляют веса будущих позиций после softmax.
* В `forward` видно четыре шага из раздела «Подробно»: сумма эмбеддингов, цикл блоков с двумя остаточными добавлениями, нормализация, умножение на `wte.T`. Отдельных обучаемых гейнов у LayerNorm в примере нет, чтобы код был короче.
* Логиты имеют форму `(5, 10)`: по строке на позицию, по столбцу на токен словаря. `argmax` по последней оси даёт «лучший» следующий токен для каждой позиции; он случаен, потому что веса случайные.
* Префикс из трёх токенов даёт те же три строки, что и полная последовательность. Замена последнего токена не меняет прежние строки, но меняет последнюю: так выглядит причинность на практике.

**Попробуйте:** добавьте в `params["blocks"]` ещё один такой же блок (`for _ in range(3)`) и проверьте, что форма логитов и причинность сохранились.

## Типичные ошибки

* **Post-LN вместо pre-LN.** Запись `x = ln(x + attn(x))` - это другая архитектура (оригинальный Transformer). Для GPT-2 нормализуется вход подслоя, а остаток проходит дальше как есть. Результаты не совпадут с эталоном, хотя формы будут правильными.
* **Остаток от нормализованного значения.** Ошибка `h = ln1(x); x = h + attn(h)` теряет сам поток: прибавлять поправку нужно к `x`, а не к `h`.
* **Нормализация не по той оси.** `x.mean(axis=0)` усредняет токены друг с другом, и позиции начинают зависеть от соседних, в том числе будущих. Признак - провал проверки на причинность. Нужна `axis=-1`.
* **Дисперсия с `ddof=1`.** LayerNorm использует смещённую дисперсию (деление на `d`). Разница мала на больших `d`, но тест на `[1, 2, 3, 4]` её покажет.
* **`eps` за пределами корня.** Запись `(x - mean) / (sqrt(var) + eps)` - другая формула. Для обычных входов результаты различаются в пятом знаке, но тесты сравнивают с точностью `1e-10` и отличие заметят.
* **Логиты не той формы.** `x @ wte` (без транспонирования) либо не работает из-за форм, либо, при `V == d`, молча считает другое. Транспонировать нужно именно таблицу эмбеддингов.
* **Тихая обрезка длины.** Если `T > max_len`, срез `wpe[:T]` вернёт только `max_len` строк, и сложение упадёт с малопонятной ошибкой форм; для пустого `ids` проход вернёт пустой результат без предупреждения. Проверки и `ValueError` с понятным текстом нужно делать явно, в самом начале.

<!-- section: summary -->
## Итоги

* Прямой проход GPT: `wte[ids] + wpe[:T]` -> `L` pre-LN блоков -> LayerNorm -> `x @ wte.T`.
* Блок: `x = x + attn(ln1(x))`, `x = x + mlp(ln2(x))`; остаток сохраняет поток, поэтому нулевой подслой не меняет `x`.
* LayerNorm нормализует каждый токен отдельно по последней оси; MLP - `d -> 4d -> d` с GELU.
* Строка `t` логитов оценивает токен `t + 1`; причинная маска позволяет учить все позиции за один проход.
* Параметров примерно `V*d + max_len*d + L*(12*d^2 + 13*d)`; у реальных моделей те же формы, только больше числа.

Дальше: [RAG: чанкинг, поиск и recall@k](lesson:llm.fundamentals.rag-retrieval) - как дать модели знания, которых нет в её весах.

## KV-кэш: зачем генерации помнить прошлое

При генерации токен за токеном наивный подход пересчитывает весь `forward` для всей последовательности на каждом шаге. Но из-за причинной маски состояние прошлых позиций **не зависит** от новых токенов: ни их входы, ни ключи `K` и значения `V` в каждом слое не изменятся. Меняется только то, что нужно для нового токена: его запрос `q` должен посмотреть на все прошлые `K` и `V`.

Поэтому реализация держит **KV-кэш**: для каждого слоя и головы массивы `K` и `V` формы `(t, d_head)`. На каждом шаге:

1. для единственного нового токена считаются `q`, `k`, `v`;
2. `k` и `v` дописываются в кэш;
3. внимание нового токена - softmax от `q @ K.T / sqrt(d_head)` и сумма `V` с этими весами;
4. остальное (MLP, LayerNorm, логиты) выполняется для одного вектора.

Работа на шаг растёт линейно с длиной контекста, а не квадратично, а результат совпадает с полным пересчётом с точностью до ошибок округления. Эту эквивалентность вы проверите в дополнительной задаче.

Платой становится **память**. Размер кэша: `2 * L * h * d_head * t * размер_числа` (множитель 2 - ключи и значения):

```python run
n_layers, n_heads, d_head, context = 12, 12, 64, 1024
bytes_per_number = 2  # float16

per_token = 2 * n_layers * n_heads * d_head * bytes_per_number
print(f"на один токен: {per_token:,} байтов")
for t in (128, 1024, 8192):
    print(f"контекст {t:>5}: {per_token * t / 2**20:8.1f} МиБ")
```
```output
на один токен: 36,864 байтов
контекст   128:      4.5 МиБ
контекст  1024:     36.0 МиБ
контекст  8192:    288.0 МиБ
```

Расчёт для конфигурации, похожей на GPT-2 small, при хранении в `float16`: чем длиннее контекст и больше число одновременных диалогов на сервере, тем больше памяти занимают кэши, и это одна из причин, почему длинный контекст стоит дороже. Производственные системы используют приёмы, уменьшающие кэш (например, общие `K` и `V` для нескольких голов), но принцип тот же.

Две оговорки. Во-первых, при обработке **промпта** (префилла) все токены известны сразу, и их можно считать одним проходом `forward`, заполняя кэш; пошагово работает именно генерация. Во-вторых, кэш корректен, пока префикс не меняется: если изменить токен в середине, придётся пересчитать всё, что правее.
