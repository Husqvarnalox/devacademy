## Модель не видит букв

Языковая модель работает не с текстом, а с последовательностью целых чисел. Перед тем как текст попадёт в модель, его режет на кусочки **токенизатор**, и каждый кусочек (**токен**) заменяется номером из словаря. Ответ модели - тоже номера токенов, которые токенизатор превращает обратно в текст.

Почему не буквы и не слова? Если токен - отдельная буква, последовательности получаются длинными, а модели дорого обрабатывать длинный вход: время и память растут с длиной. Если токен - целое слово, словарь становится огромным, а любое новое слово («нейросетевой», опечатка, имя) оказывается неизвестным. Компромисс - **подслова**: частые слова становятся одним токеном, редкие собираются из нескольких кусочков.

Самый распространённый способ получить такой словарь - **BPE** (Byte Pair Encoding, кодирование пар байтов). Идея простая:

1. Начинаем с отдельных байтов текста в UTF-8 - их всего 256, поэтому любой текст на любом языке записывается без «неизвестных символов».
2. Находим пару соседних токенов, которая встречается чаще всех, и объявляем её новым токеном.
3. Повторяем, пока словарь не достигнет нужного размера.

Каждое такое объявление называется **слиянием** (merge). Список слияний и есть обученный токенизатор. Из этого вытекают вещи, которые вы видите у настоящих моделей: цены и лимиты API считаются в токенах, русский текст обычно «дороже» английского (одна буква кириллицы - два байта, а слияний для неё в словаре, обученном в основном на английском, меньше), а модели плохо считают буквы в словах - букв они просто не видят.

## Байтовый BPE

**Базовый словарь.** Текст кодируется в UTF-8, каждый байт - токен с номером `0..255`. Символы ASCII занимают 1 байт, кириллица - 2, большинство иероглифов - 3, эмодзи - 4. Байтовый базовый словарь гарантирует, что закодировать можно любую строку.

**Обучение.** Пусть `ids` - текущая последовательность номеров. Повторяем:

* `stats = get_stats(ids)` - число вхождений каждой пары соседей `(a, b)`. Пары считаются **с перекрытием**: в `[5, 5, 5]` пара `(5, 5)` встречается дважды.
* `pair = max(stats, key=stats.get)` - самая частая пара. Словари Python сохраняют порядок вставки, а `max` возвращает первый из равных, поэтому при ничьей выигрывает пара, встретившаяся в тексте раньше. Правило разрешения ничьих должно быть зафиксировано, иначе два «одинаковых» токенизатора дадут разные словари.
* `ids = merge(ids, pair, new_id)` - каждое вхождение пары заменяется одним новым токеном. Замена идёт слева направо **без перекрытий**: `[5, 5, 5]` превращается в `[9, 5]`, а не в `[9, 9]`.
* `merges[pair] = new_id`, где `new_id = 256, 257, ...`.

Обучение останавливается, когда словарь достиг `vocab_size = 256 + число слияний` или когда самая частая пара встречается меньше двух раз: такое слияние ничего не обобщает. В реальных библиотеках это порог частоты (`min_frequency` в Hugging Face tokenizers).

**Кодирование нового текста** - это не повторное обучение. Берём байты и применяем выученные слияния **в том порядке, в котором они выучены**: среди присутствующих пар выбираем ту, у которой номер в `merges` наименьший, сливаем, повторяем, пока ни одна пара не входит в `merges`. Порядок важен: слияние `257 = (256, 101)` имеет смысл только после того, как появился токен `256`.

**Декодирование.** Строим таблицу `vocab[id] -> bytes`: для `0..255` это один байт, для слияния `(a, b) -> id` - `vocab[a] + vocab[b]`. Склеиваем байты и декодируем UTF-8. Отдельный токен может оказаться половиной буквы (например, байт `0xD0`), поэтому декодирование произвольной последовательности id выполняется с `errors="replace"`: неполный символ заменяется на `U+FFFD` (�), а не роняет программу. Так ведут себя потоковые чаты, когда показывают текст по одному токену.

**Свойство без потерь:** `decode(encode(text)) == text` для любой строки - BPE ничего не теряет, он только меняет разбиение.

## Связь с настоящими LLM

* Словари реальных моделей - десятки и сотни тысяч токенов; обучение идёт на гигабайтах текста, но алгоритм тот же.
* Перед BPE текст обычно предварительно режут регулярным выражением на «слова», чтобы слияния не склеивали, например, конец слова с пробелом и знаком препинания. Мы этот шаг пропускаем.
* Помимо обычных токенов есть **специальные**: начало и конец текста, границы реплик в чате. Их вставляет не BPE, а код, собирающий запрос (об этом урок про шаблоны чата).
* **Контекстное окно** модели измеряется в токенах. Один и тот же документ на разных языках занимает разное число токенов, поэтому «влезает» в окно по-разному и стоит по-разному.

## Примеры

**Пример 1. Символы и байты.**

```python run
for text in ["cat", "кот", "日本", "🙂"]:
    data = text.encode("utf-8")
    print(f"{text!r}: символов {len(text)}, байтов {len(data)}, байты {list(data)}")
```
```output
'cat': символов 3, байтов 3, байты [99, 97, 116]
'кот': символов 3, байтов 6, байты [208, 186, 208, 190, 209, 130]
'日本': символов 2, байтов 6, байты [230, 151, 165, 230, 156, 172]
'🙂': символов 1, байтов 4, байты [240, 159, 153, 130]
```

`len(text)` считает символы Unicode, а `len(text.encode("utf-8"))` - байты. Байтовый BPE стартует с байтов, поэтому слово «кот» в начале обучения - шесть токенов, а «cat» - три.

**Попробуйте:** добавьте в список строку `"ё"` и строку `"e\u0301"` (буква e и комбинируемое ударение). Предскажите, сколько символов и байтов будет у каждой.

**Пример 2. Пять слияний вручную.**

```python run
def get_stats(ids):
    counts = {}
    for pair in zip(ids, ids[1:]):
        counts[pair] = counts.get(pair, 0) + 1
    return counts

def merge(ids, pair, new_id):
    out, i = [], 0
    while i < len(ids):
        if i + 1 < len(ids) and (ids[i], ids[i + 1]) == pair:
            out.append(new_id)
            i += 2
        else:
            out.append(ids[i])
            i += 1
    return out

ids = list("the cat sat on the mat".encode("utf-8"))
vocab = {i: bytes([i]) for i in range(256)}
for new_id in range(256, 261):
    stats = get_stats(ids)
    pair = max(stats, key=stats.get)
    ids = merge(ids, pair, new_id)
    vocab[new_id] = vocab[pair[0]] + vocab[pair[1]]
    print(f"{new_id}: {vocab[pair[0]]!r} + {vocab[pair[1]]!r} (встречалась {stats[pair]} раза), длина {len(ids)}")
print([vocab[i].decode("utf-8") for i in ids])
```
```output
256: b'a' + b't' (встречалась 3 раза), длина 19
257: b't' + b'h' (встречалась 2 раза), длина 17
258: b'th' + b'e' (встречалась 2 раза), длина 15
259: b'the' + b' ' (встречалась 2 раза), длина 13
260: b'at' + b' ' (встречалась 2 раза), длина 11
['the ', 'c', 'at ', 's', 'at ', 'o', 'n', ' ', 'the ', 'm', 'at']
```

Разбор:

* `get_stats` проходит по соседним парам (`zip(ids, ids[1:])`) и считает их; порядок ключей - порядок первого появления.
* Первой выигрывает пара `a + t`: она встречается трижды (c**at**, s**at**, m**at**).
* Слияние `258 = th + e` использует токен `257`, выученный шагом раньше: словарь растёт «снизу вверх».
* Каждое слияние укорачивает последовательность на число вхождений пары: 22 байта превратились в 11 токенов.
* Итоговые токены - осмысленные куски: `'the '`, `'at '`. Пробел прилипает к слову, как у настоящих токенизаторов.

**Попробуйте:** замените `range(256, 261)` на `range(256, 266)` и посмотрите, какие слияния появятся, когда частые пары закончатся (все оставшиеся встречаются по одному разу).

**Пример 3. Токенизатор, обученный на английском, и русский текст.**

```python run
def get_stats(ids):
    counts = {}
    for pair in zip(ids, ids[1:]):
        counts[pair] = counts.get(pair, 0) + 1
    return counts

def merge(ids, pair, new_id):
    out, i = [], 0
    while i < len(ids):
        if i + 1 < len(ids) and (ids[i], ids[i + 1]) == pair:
            out.append(new_id)
            i += 2
        else:
            out.append(ids[i])
            i += 1
    return out

def train(text, n_merges):
    ids, merges = list(text.encode("utf-8")), {}
    for new_id in range(256, 256 + n_merges):
        stats = get_stats(ids)
        if not stats or max(stats.values()) < 2:
            break
        pair = max(stats, key=stats.get)
        ids = merge(ids, pair, new_id)
        merges[pair] = new_id
    return merges

def encode(text, merges):
    ids = list(text.encode("utf-8"))
    while len(ids) >= 2:
        stats = get_stats(ids)
        pair = min(stats, key=lambda p: merges.get(p, float("inf")))
        if pair not in merges:
            break
        ids = merge(ids, pair, merges[pair])
    return ids

english = "the cat sat on the mat and the cat ate the rat " * 3
merges = train(english, 30)
for text in ["the cat sat", "the dog sat", "кот сидел"]:
    n_bytes = len(text.encode("utf-8"))
    print(f"{text!r}: байтов {n_bytes}, токенов {len(encode(text, merges))}")
```
```output
'the cat sat': байтов 11, токенов 2
'the dog sat': байтов 11, токенов 7
'кот сидел': байтов 17, токенов 17
```

Токенизатор, обученный только на английском, сжимает знакомую фразу до двух токенов, незнакомое слово `dog` - побайтно, а русскую фразу не сжимает вовсе: 17 байтов - 17 токенов. Это та же причина, по которой у многих моделей русский текст занимает больше токенов, чем английский того же смысла: в обучающих данных токенизатора его было меньше.

**Попробуйте:** добавьте в `english` одну русскую фразу, повторённую несколько раз, переобучите и снова посчитайте токены строки «кот сидел».

## Типичные ошибки

* **Слияние с перекрытием.** Если после замены пары не перепрыгнуть через оба элемента (`i += 2`), `[5, 5, 5]` превратится в `[9, 9]` - лишний токен «из воздуха», и `decode` вернёт другой текст.
* **Кодирование по частоте во входе.** При кодировании нового текста нельзя снова выбирать самую частую пару: применяются выученные слияния в порядке обучения. Иначе один текст в обучении и в применении разбивается по-разному.
* **Неустойчивые ничьи.** Если правило выбора среди равных пар не зафиксировано (например, перебор множества `set`), словарь зависит от порядка хеширования и не воспроизводится.
* **Декодирование без `errors="replace"`.** Отдельный токен может быть половиной символа UTF-8; строгое декодирование бросит `UnicodeDecodeError`.
* **Работа с символами вместо байтов.** Символьный BPE сталкивается с символами, которых не было в обучении (эмодзи, редкие иероглифы). Байтовый базовый словарь эту проблему снимает.
* **Число символов вместо числа токенов.** Лимиты контекста и цены API считают токены; оценка «примерно 4 символа на токен» верна лишь для английского текста и конкретного токенизатора.

<!-- section: summary -->
## Итоги

* Модель видит номера токенов; токенизатор переводит текст в номера и обратно без потерь.
* Байтовый BPE стартует с 256 байтов UTF-8 и жадно сливает самую частую пару соседей, пока не достигнет размера словаря.
* Новый текст кодируется применением слияний в порядке обучения; декодирование склеивает байты и декодирует UTF-8 с `errors="replace"`.
* Число токенов зависит от языка и от данных, на которых обучен токенизатор; от него зависят длина контекста и цена запроса.

## Как это устроено в библиотеках

* **Hugging Face tokenizers** и **tiktoken** (токенизатор моделей OpenAI) реализуют тот же байтовый BPE на Rust; обученный словарь хранится в файле вместе со списком слияний и регулярным выражением предварительного разбиения.
* В GPT-2 байты отображаются в печатные символы Unicode, чтобы словарь можно было хранить как текст; поэтому в словарях GPT-2 пробел перед словом виден как символ `Ġ`.
* Другие схемы: **WordPiece** (BERT) выбирает слияние не по частоте пары, а по тому, насколько оно повышает правдоподобие корпуса; **Unigram** (SentencePiece) начинает с большого словаря и выбрасывает лишние кусочки. Результат похож: подслова переменной длины.
* Наивное обучение, как у нас, пересчитывает все пары на каждом шаге: `O(N)` на слияние, где `N` - длина текста. Библиотеки хранят счётчики пар и обновляют только затронутые соседние пары, поэтому обучаются на гигабайтах.
* Кодирование в библиотеках тоже оптимизировано (кэш для частых слов, очередь с приоритетом по рангу слияния), но правило то же: слияния применяются по рангу.
