## Как из распределения получается текст

Языковая модель (урок 3) по контексту выдаёт распределение вероятностей следующего токена. Но текст - это конкретная последовательность токенов, поэтому на каждом шаге нужно **выбрать** один токен. От того, как выбирать, зависят и качество, и разнообразие ответа: одна и та же модель может отвечать скучно и повторяясь, а может - случайно и бессвязно. Параметры `temperature` и `top_p` в API нейросетевых сервисов - это ровно те ручки, которые реализует этот урок.

Генерация - это цикл:

1. Взять логиты следующего токена (для биграммной модели - строка таблицы для последнего токена).
2. Превратить их в распределение (**softmax**).
3. Выбрать токен.
4. Дописать его в текст и повторить, пока не выбран токен конца или не исчерпан лимит длины.

Способы выбрать токен:

* **Greedy** - всегда самый вероятный. Результат детерминирован, но часто повторяется и зацикливается: лучший токен после лучшего токена снова даёт тот же путь.
* **Выборка** (sampling) - случайный выбор в соответствии с вероятностями. Результат разнообразен, но редкие «плохие» токены иногда выпадают.
* **Temperature** - число `T`, на которое делят логиты до softmax. `T < 1` делает распределение острее (ближе к greedy), `T > 1` - плоским (ближе к равномерному), `T -> 0` - greedy.
* **Top-k** - оставить `k` самых вероятных токенов, остальным дать вероятность 0.
* **Top-p** (nucleus) - оставить наименьший набор самых вероятных токенов, суммарная вероятность которых не меньше `p`. В отличие от top-k число токенов подстраивается под распределение: если модель уверена, остаётся один-два токена, если нет - много.

Фиксированный `seed` генератора случайных чисел делает выборку воспроизводимой: тот же seed и те же параметры дают тот же текст.

## Строгое описание

**Softmax с температурой.** `softmax(z / T)_i = exp(z_i / T) / sum_j exp(z_j / T)`. Вычислять нужно устойчиво: из всех значений вычитают максимум (`z - max(z)`). Результат не меняется (числитель и знаменатель умножаются на одну константу), но `exp` получает аргументы `<= 0`, а значит, не переполняется. Без этого `exp(1000)` даёт `inf`, а отношение `inf / inf` - `nan`. Значение `-inf` даёт `exp(-inf) = 0`, то есть вероятность ровно 0. Температура должна быть положительной; `T = 0` обрабатывается отдельно как argmax.

**Top-k по логитам.** Оставляем `k` наибольших логитов, остальные заменяем на `-inf`; после softmax они получают 0. Ничьи на границе нужно разрешать детерминированно: `np.argsort(-z, kind="stable")[:k]` берёт из равных логитов меньший индекс. `k >= V` или `k is None` ничего не меняет, `k <= 0` - ошибка (пустого распределения не бывает).

**Top-p по вероятностям.** Сортируем вероятности по убыванию (устойчиво), считаем накопленные суммы и берём наименьший префикс, где накопленная сумма `>= p`. Всегда остаётся хотя бы один токен, поэтому при очень малом `p` результат - greedy. Остальные вероятности обнуляются, оставшиеся делятся на их сумму. `p = 1` оставляет все токены с ненулевой вероятностью. Допустимы `p` из диапазона `(0, 1]`.

**Порядок применения.** Для воспроизводимости результата порядок фиксирован: сначала логиты делятся на температуру, затем top-k, затем softmax, затем top-p, и только потом случайный выбор. От порядка зависит результат: top-p считает накопленную вероятность на уже перенормированном (после top-k) распределении. В Hugging Face Transformers фильтры применяются в похожем порядке.

**Случайный выбор.** `rng.choice(V, p=probs)` выбирает индекс с заданными вероятностями. Генератор `np.random.default_rng(seed)` содержит состояние: каждый вызов его продвигает. Поэтому режим `temperature = 0` не должен обращаться к `rng` - иначе последовательность в других местах программы сдвинется без видимой причины.

**Цикл генерации.** `generate` берёт логиты для последнего токена, выбирает следующий; если это токен конца - останавливается, не добавляя его; также останавливается после `max_new_tokens`. Лимит обязателен: у greedy-генерации цикл может не закончиться никогда.

## Связь с настоящими LLM

* Реальная модель на каждом шаге выдаёт логиты по всему словарю, и тот же цикл (выбор токена, добавление, повтор) генерирует ответ чата. Отличие в том, что логиты считает нейросеть по всему контексту, а не таблица по одному токену.
* Параметры `temperature`, `top_p`, `top_k` в API и библиотеках - это именно описанные здесь преобразования. Низкая температура подходит задачам, где нужен один точный ответ (извлечение данных, код); более высокая - когда нужно разнообразие (идеи, тексты).
* Токен конца (`<|endoftext|>` и подобные) - специальный токен словаря; модель сама решает, когда закончить, выдав его.
* Top-p приспосабливается к уверенности модели: на «лёгких» позициях в ядре один токен, на «трудных» - десятки. Фиксированный top-k так не умеет.

## Примеры

**Пример 1. Greedy: детерминированно и по кругу.**

```python run
import numpy as np

# Крошечный корпус на уровне слов; <s> - начало и конец предложения
sentences = ["дождь идёт дождь идёт дождь", "снег идёт снег идёт снег",
             "идёт дождь", "дождь идёт"]
vocab = ["<s>"] + sorted({w for s in sentences for w in s.split()})
stoi = {w: i for i, w in enumerate(vocab)}
V = len(vocab)

C = np.zeros((V, V))
for s in sentences:
    ids = [0] + [stoi[w] for w in s.split()] + [0]
    for a, b in zip(ids, ids[1:]):
        C[a, b] += 1
P = (C + 0.01) / (C + 0.01).sum(axis=1, keepdims=True)
logit_table = np.log(P)          # логиты: логарифмы вероятностей

last, out = 0, []
for step in range(8):            # жёсткий лимит длины
    nxt = int(np.argmax(logit_table[last]))     # greedy
    if nxt == 0:
        break
    out.append(vocab[nxt])
    last = nxt
print("greedy:", " ".join(out))
print("слов сгенерировано:", len(out))
```
```output
greedy: дождь идёт дождь идёт дождь идёт дождь идёт
слов сгенерировано: 8
```

Разбор:

* Корпус - четыре короткие фразы на уровне слов, `<s>` - начало и конец предложения. Счётчики превращаются в вероятности со сглаживанием `0.01`, как в уроке 3.
* `np.log(P)` даёт таблицу логитов: логарифм вероятностей. Softmax от логарифмов вероятностей возвращает те же вероятности.
* Цикл на каждом шаге берёт `np.argmax` строки последнего токена. После `дождь` самое частое продолжение - `идёт`, после `идёт` - `дождь`, и greedy ходит по кругу.
* Конец предложения (`<s>`) никогда не становится самым вероятным вариантом, поэтому цикл остановил лимит в 8 слов. Без лимита программа не завершилась бы.

**Попробуйте:** замените `range(8)` на `range(20)` и предскажите вывод. Затем добавьте в корпус ещё несколько предложений, заканчивающихся на `идёт`: после какого их числа greedy начнёт останавливаться?

**Пример 2. Температура.**

```python run
import numpy as np

def softmax(logits, temperature=1.0):
    z = np.asarray(logits, dtype=np.float64) / temperature
    e = np.exp(z - np.max(z))
    return e / e.sum()

logits = np.array([2.0, 1.0, 0.5, -1.0])
np.set_printoptions(precision=3, suppress=True)
for T in (0.2, 0.5, 1.0, 2.0, 5.0):
    print(f"T={T:<4}", softmax(logits, T))

# Что случится без вычитания максимума
big = np.array([1000.0, 999.0])
with np.errstate(all="ignore"):
    naive = np.exp(big) / np.exp(big).sum()
print("наивно:", naive, "| устойчиво:", softmax(big))
```
```output
T=0.2  [0.993 0.007 0.001 0.   ]
T=0.5  [0.842 0.114 0.042 0.002]
T=1.0  [0.609 0.224 0.136 0.03 ]
T=2.0  [0.434 0.263 0.205 0.097]
T=5.0  [0.322 0.263 0.238 0.177]
наивно: [nan nan] | устойчиво: [0.731 0.269]
```

Разбор:

* `logits / temperature` до softmax - единственное место, где участвует `T`. Порядок токенов не меняется, меняется «острота»: при `T=0.2` первый токен получает 0.993, при `T=5.0` распределение близко к равномерному.
* При `T=1.0` получаем обычный softmax: `[0.609, 0.224, 0.136, 0.03]`.
* Последняя строка показывает, зачем вычитать максимум: наивный `np.exp(1000)` даёт `inf`, и деление даёт `nan`. Устойчивая версия возвращает `[0.731, 0.269]`: важна разница логитов (1), а не их абсолютные значения.

**Пример 3. Top-k и top-p.**

```python run
import numpy as np

tokens = ["а", "б", "в", "г", "д", "е"]
probs = np.array([0.40, 0.25, 0.15, 0.10, 0.07, 0.03])

def top_k_probs(probs, k):
    keep = np.argsort(-probs, kind="stable")[:k]
    out = np.zeros_like(probs)
    out[keep] = probs[keep]
    return out / out.sum()

def top_p_probs(probs, p):
    order = np.argsort(-probs, kind="stable")
    cum = np.cumsum(probs[order])
    n_keep = min(int(np.searchsorted(cum, p, side="left")) + 1, probs.size)
    out = np.zeros_like(probs)
    out[order[:n_keep]] = probs[order[:n_keep]]
    return out / out.sum()

np.set_printoptions(precision=3, suppress=True)
print("исходное:    ", probs)
print("накопленная: ", np.cumsum(probs))
print("top-k, k=3:  ", top_k_probs(probs, 3))
print("top-p, p=0.8:", top_p_probs(probs, 0.8))
print("top-p, p=0.5:", top_p_probs(probs, 0.5))

flat = np.array([0.25, 0.25, 0.25, 0.15, 0.05, 0.05])
print("плоское, top-k, k=3:  ", top_k_probs(flat, 3))
print("плоское, top-p, p=0.8:", top_p_probs(flat, 0.8))
```
```output
исходное:     [0.4  0.25 0.15 0.1  0.07 0.03]
накопленная:  [0.4  0.65 0.8  0.9  0.97 1.  ]
top-k, k=3:   [0.5   0.312 0.187 0.    0.    0.   ]
top-p, p=0.8: [0.5   0.312 0.187 0.    0.    0.   ]
top-p, p=0.5: [0.615 0.385 0.    0.    0.    0.   ]
плоское, top-k, k=3:   [0.333 0.333 0.333 0.    0.    0.   ]
плоское, top-p, p=0.8: [0.278 0.278 0.278 0.167 0.    0.   ]
```

Разбор:

* `np.cumsum` по убыванию даёт накопленные вероятности: `0.4, 0.65, 0.8, ...`.
* `np.searchsorted(cum, p, side="left")` возвращает индекс первого места, где накопленная сумма достигает `p`; прибавив 1, получаем число сохраняемых токенов (первый токен, на котором сумма достигла `p`, тоже сохраняется).
* При `k=3` и `p=0.8` на этом распределении оставляются одни и те же три токена: после перенормировки `[0.5, 0.312, 0.187]`.
* При `p=0.5` остаётся два токена (`0.4 + 0.25 = 0.65 >= 0.5`), потому что один токен даёт только 0.4.
* На плоском распределении top-k всегда оставляет ровно `k` токенов, а top-p при `p=0.8` - четыре, потому что вероятности близки и ядро получается широким. Это и есть адаптивность top-p.

**Пример 4. Выборка символов и воспроизводимость.**

```python run
import numpy as np

names = ["анна", "иван", "мария", "марина", "ирина", "ольга", "олег", "игорь",
         "инна", "антон", "андрей", "нина", "никита", "роман", "алина", "мила"]
vocab = ["<s>"] + sorted(set("".join(names)))
stoi = {c: i for i, c in enumerate(vocab)}
V = len(vocab)
C = np.zeros((V, V))
for name in names:
    ids = [0] + [stoi[c] for c in name] + [0]
    for a, b in zip(ids, ids[1:]):
        C[a, b] += 1
P = (C + 0.1) / (C + 0.1).sum(axis=1, keepdims=True)
table = np.log(P)

def softmax(z):
    e = np.exp(z - z.max())
    return e / e.sum()

def top_k_filter(z, k):
    keep = np.argsort(-z, kind="stable")[:k]
    out = np.full_like(z, -np.inf)
    out[keep] = z[keep]
    return out

def sample_next(logits, rng, temperature=1.0, top_k=None):
    if temperature == 0:
        return int(np.argmax(logits))
    z = logits / temperature
    if top_k is not None:
        z = top_k_filter(z, top_k)
    return int(rng.choice(len(z), p=softmax(z)))

def generate(rng, **kw):
    out, last = [], 0
    for _ in range(12):
        nxt = sample_next(table[last], rng, **kw)
        if nxt == 0:
            break
        out.append(nxt)
        last = nxt
    return "".join(vocab[i] for i in out)

for label, kw in [("T=1.0", {}), ("T=0.5", {"temperature": 0.5}), ("T=2.0", {"temperature": 2.0}), ("top_k=3", {"top_k": 3})]:
    rng = np.random.default_rng(7)
    print(f"{label:8s}", [generate(rng, **kw) for _ in range(6)])

runs = []
for _ in range(2):
    rng = np.random.default_rng(3)          # один и тот же seed
    runs.append([generate(rng, top_k=3) for _ in range(3)])
print("запуск 1:", runs[0])
print("запуск 2:", runs[1])
print("совпадают:", runs[0] == runs[1])
```
```output
T=1.0    ['мнлвар', 'орилегадрянд', 'ь', 'ан', 'аинркина', 'ана']
T=0.5    ['иринан', 'на', 'а', 'а', 'интомин', 'иг']
T=2.0    ['мтоийт', 'орийгакйкяон', 'яа', 'ма', 'миялима', 'внае']
top_k=3  ['ина', 'арей', 'ина', 'инаромиг', 'ив', 'инина']
запуск 1: ['а', 'ма', 'ин']
запуск 2: ['а', 'ма', 'ин']
совпадают: True
```

Разбор:

* `table` - логиты символьной биграммной модели из урока 3. `sample_next` строго следует порядку: деление на температуру, top-k, softmax, `rng.choice`.
* `generate` повторяет выбор, пока не получит токен конца (`0`) или не наберёт 12 символов.
* Модель обучена на 16 именах и выдаёт бессвязные последовательности, но влияние параметров видно. При `T=0.5` имена короче и однообразнее; при `T=2.0` выбор ближе к случайному набору букв; `top_k=3` отрезает самые редкие продолжения.
* Два запуска с одним `seed=3` дали одинаковые результаты: воспроизводимость обеспечивает не `temperature`, а состояние генератора.

**Попробуйте:** замените `seed` на 4 и сравните. Затем создайте один `rng` и вызовите `generate` дважды: почему вторая строка отличается от первой?

## Типичные ошибки

* **Softmax без вычитания максимума.** На больших логитах `exp` переполняется, результат превращается в `nan`, а `rng.choice` падает с ошибкой о вероятностях.
* **Деление на температуру после softmax.** Температура применяется к логитам, а не к вероятностям; деление вероятностей на `T` не даёт распределения.
* **Температура 0 как деление на 0.** При `T = 0` формула `z / T` даёт `inf`. Нулевая температура - отдельная ветка: argmax.
* **Top-k по вероятностям после top-p** (или наоборот в другом порядке): порядок фильтров меняет результат. Фиксируйте его и документируйте.
* **Неустойчивая сортировка.** Без `kind="stable"` при равных логитах порядок не гарантирован, и результаты top-k и top-p отличаются между запусками.
* **Top-p без минимума в один токен.** Если сравнивать накопленную сумму до токена, а не после, при малом `p` ядро окажется пустым. Минимум один токен остаётся всегда.
* **Забытая перенормировка.** После top-k или top-p вероятности не суммируются в 1; `rng.choice` с такими `p` выдаст ошибку или искажённый результат.
* **Лишние обращения к `rng`.** Если greedy-ветка вызывает `rng`, воспроизводимость остальной программы ломается: последовательность случайных чисел сдвигается.
* **Генерация без лимита.** Токен конца может так и не выпасть, особенно у greedy. Лимит `max_new_tokens` нужен всегда.

<!-- section: summary -->
## Итоги

* Генерация - цикл «логиты - распределение - выбор токена - добавление»; способ выбора определяет стиль результата.
* Greedy детерминирован, но зацикливается; выборка разнообразна; температура меняет остроту распределения, top-k и top-p отсекают маловероятный «хвост».
* Порядок обработки фиксирован: температура, top-k, softmax, top-p, выбор; при фиксированном seed результат воспроизводим.
* Параметры `temperature`, `top_p`, `top_k` в API - это именно эти преобразования логитов.

## Как это устроено в библиотеках

* **Hugging Face Transformers.** Метод `generate` принимает `do_sample`, `temperature`, `top_k`, `top_p` и другие параметры; при `do_sample=False` используется greedy-декодирование. Стратегии (greedy, beam search, выборка) описаны в документации. Фильтры реализованы как отдельные обработчики логитов, применяемые по очереди.
* **Beam search.** Вместо одного пути поддерживается несколько лучших частичных последовательностей. Он хорошо подходит для перевода, но для открытой генерации даёт однообразный текст; в работе Холтцмана и соавторов о nucleus sampling показано, что выбор самых вероятных последовательностей приводит к повторам, а не похоже на человеческий текст.
* **Штрафы за повторы.** Часто добавляют репетиционный штраф: логиты уже использованных токенов уменьшают. Это ещё один фильтр в той же цепочке «логиты - логиты».
* **min-p и другие фильтры.** Существуют и другие способы отсечения хвоста (например, порог относительно вероятности лучшего токена). Идея та же: превратить распределение в более «безопасное» перед выбором.
* **Воспроизводимость на практике.** В нашем коде `seed` и параметры полностью определяют результат. В размещённых сервисах результат может зависеть и от других факторов, например от порядка вычислений на ускорителе или версии модели, поэтому точного повторения нельзя ожидать без гарантий провайдера.
* **Стоимость.** Выбор токена дёшев по сравнению с прямым проходом модели. Дорогой шаг цикла - вычисление логитов; поэтому в уроке про мини-GPT появится KV-кэш, который не пересчитывает контекст заново.
