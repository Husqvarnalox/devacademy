## Зачем форматировать вывод

Результат вычисления не всегда приятно читать. Сумма чека `179.70` в обычном выводе превратится в `179.7`, цена `15.0` останется `15.0` вместо `15.00`, а результат вроде `59.699999999999996` покажет «хвост» неточности `double`. Покупателю нужна запись с копейками, ровно с двумя знаками.

Значение при этом менять не нужно: оно остаётся прежним. Меняется только **запись** - то, как число превращается в текст. Для этого у Java есть форматированный вывод.

## Одна новая идея: шаблон с местами для значений

Метод `System.out.printf` принимает **строку формата** - шаблон с метками - и значения, которые нужно подставить:

```java
System.out.printf(Locale.ROOT, "Сумма: %.2f руб.%n", 179.7);
```

Выведет `Сумма: 179.70 руб.`

Метки, начинающиеся со знака `%`, называются **спецификаторами**. Главные:

| Спецификатор | Для чего | Пример значения |
|---|---|---|
| `%s` | текст (подходит и для любого значения) | `"Тетрадь"` |
| `%d` | целое число | `42` |
| `%.2f` | дробное число с двумя знаками после точки | `59.9` |
| `%n` | конец строки | - |
| `%%` | сам знак процента | - |

Значения подставляются по порядку: первое значение - в первый спецификатор, и так далее. Число в `%.2f` - это количество знаков после запятой: `%.1f` даст один, `%.0f` - ни одного.

Первый аргумент `Locale.ROOT` - «региональные настройки по умолчанию». Без него `printf` берёт настройки вашего компьютера, и разделитель в `%.2f` может оказаться запятой. С `Locale.ROOT` всегда точка. Для этого в начале файла добавляют `import java.util.Locale;`.

## Пример 1. Цена с копейками

```java run
import java.util.Locale;

public class Main {
    public static void main(String[] args) {
        double price = 19.9;
        int count = 3;
        System.out.println(price * count);
        System.out.printf(Locale.ROOT, "Итого: %.2f руб.%n", price * count);
        System.out.printf(Locale.ROOT, "Цена: %.2f, %.1f, %.0f%n", price, price, price);
    }
}
```
```output
59.699999999999996
Итого: 59.70 руб.
Цена: 19.90, 19.9, 20
```

Разбор:

* `System.out.println(price * count)` показывает «хвост» двоичной арифметики из урока об арифметике: `59.699999999999996`.
* `%.2f` выводит два знака после точки и аккуратно округляет последний.
* В последней строке одно число печатается трижды: с двумя знаками, с одним и без дробной части (`%.0f` округляет до `20`). Значение при этом не менялось.
* `%n` завершает строку: `printf` сам перевод строки не добавляет, в отличие от `println`.

## Пример 2. Название, количество и деньги

```java run
import java.util.Locale;

public class Main {
    public static void main(String[] args) {
        String title = "Тетрадь";
        int count = 3;
        double price = 59.9;
        System.out.printf(Locale.ROOT, "%s: %d шт. по %.2f руб.%n", title, count, price);
        System.out.printf(Locale.ROOT, "Скидка %d%%%n", 10);
    }
}
```
```output
Тетрадь: 3 шт. по 59.90 руб.
Скидка 10%
```

Разбор: три значения идут в три спецификатора в порядке записи: `title` в `%s`, `count` в `%d`, `price` в `%.2f`. Текст вокруг спецификаторов копируется как есть. Знак процента записан как `%%`, затем `%n` завершает строку.

## Пример 3. Выравнивание и String.format

```java run
import java.util.Locale;

public class Main {
    public static void main(String[] args) {
        System.out.println(String.format(Locale.ROOT, "[%5d]", 42));
        System.out.println(String.format(Locale.ROOT, "[%-5d]", 42));
        System.out.println(String.format(Locale.ROOT, "[%05d]", 42));
        System.out.println(String.format(Locale.ROOT, "[%8.2f]", 3.14159));
        String line = String.format(Locale.ROOT, "%.2f", 2.5);
        System.out.println("Итог: " + line);
    }
}
```
```output
[   42]
[42   ]
[00042]
[    3.14]
Итог: 2.50
```

Разбор:

* Число перед буквой - **ширина** поля: `%5d` отводит 5 позиций и прижимает число вправо, `%-5d` - влево, `%05d` заполняет нулями.
* `%8.2f` - ширина 8 и два знака после точки.
* `String.format` принимает те же аргументы, что `printf`, но не печатает, а **возвращает строку**. Её можно сохранить в переменную и склеить с другим текстом.

## Пример 4. Форматирование и округление - разные вещи

```java run
public class Main {
    public static void main(String[] args) {
        double x = 59.949;
        System.out.println(Math.round(x));
        System.out.println(Math.round(2.5));
        System.out.println(Math.round(x * 100) / 100.0);
        System.out.println((int) Math.round(2.6));
    }
}
```
```output
60
3
59.95
3
```

Разбор:

* `Math.round(x)` возвращает ближайшее целое (тип `long`): `60`. Половина округляется вверх: `Math.round(2.5)` равно `3`.
* `Math.round(x * 100) / 100.0` округляет до сотых **самим значением**: сначала `5994.9` превращается в `5995`, затем деление на `100.0` возвращает `59.95`. Здесь значение действительно изменилось.
* Результат `Math.round` имеет тип `long`; чтобы положить его в `int`, нужно приведение из прошлого урока.

Для вывода денег достаточно `printf` с `%.2f`: он округляет только запись, а само число остаётся точным. Округлять значение вручную нужно, когда округлённый результат потом используется в вычислениях.

**Попробуйте.** Напечатайте `Math.round(-2.5)` и предскажите результат. Затем выведите `3.14159` через `%.3f`, `%.0f` и `%8.1f`.

## Точные правила

* `System.out.printf(Locale.ROOT, "формат", значения...)` печатает, `String.format(Locale.ROOT, "формат", значения...)` возвращает строку. Правила формата у них одинаковы.
* Спецификатор записывается как `%[флаги][ширина][.точность]тип`. Нужные типы: `d` (целое), `f` (дробное), `s` (текст), `n` (конец строки), `%` (знак процента, пишется `%%`).
* Количество спецификаторов должно совпадать с количеством значений, а типы - подходить: для `%d` нужно целое, для `%f` - дробное. `%s` принимает любое значение.
* Точность в `%.2f` - число знаков после точки. Последний оставленный знак округляется «половина вверх»: `%.1f` для `2.25` выводит `2.3`.
* Флаги: `-` выравнивает влево, `0` дополняет нулями, `,` вставляет разделитель разрядов (`%,d` для `1234567` с `Locale.ROOT` даёт `1,234,567`).
* `printf` не добавляет перевод строки сам. Нужно `%n` в конце (предпочтительнее `\n`, потому что `%n` подходит для любой операционной системы).
* Строка формата проверяется только при выполнении: компилятор не заметит неверный спецификатор.
* `Locale.ROOT` лежит в пакете `java.util`: `import java.util.Locale;`. Без `Locale.ROOT` результат зависит от настроек компьютера: при русских настройках `%.2f` даёт запятую, при английских - точку.
* Форматирование не меняет значение: `printf("%.2f", x)` оставляет `x` прежним.
* `Math.round(double)` возвращает `long` (ближайшее целое, половина вверх: `Math.round(-2.5)` равно `-2`). Округление до сотых делают так: `Math.round(x * 100) / 100.0`.

## Типичные ошибки

**1. Забыли `import java.util.Locale;`.**

```java
System.out.printf(Locale.ROOT, "%.2f%n", 2.5);
```

```text
Main.java:3: error: cannot find symbol
System.out.printf(Locale.ROOT, "%.2f%n", 2.5);
                  ^
  symbol:   variable Locale
  location: class Main
```

Компилятор не знает имени `Locale`. Добавьте `import java.util.Locale;` в начало файла.

**2. Не тот спецификатор для типа.**

```java
System.out.printf("%d%n", 2.5);
```

```text
Exception in thread "main" java.util.IllegalFormatConversionException: d != java.lang.Double
	at java.base/java.util.Formatter$FormatSpecifier.failConversion(Formatter.java:4534)
	...
```

Сообщение читается так: `%d` (целое) не подходит к значению типа `Double`. Для дробного нужен `%f`. Обратная ошибка: `%.2f` и целое `5` дают `f != java.lang.Integer`. Целое в `%f` не превращается само: используйте `5.0` или `(double) n`.

**3. Значений меньше, чем спецификаторов.**

```java
System.out.printf(Locale.ROOT, "%d %d%n", 5);
```

```text
5 Exception in thread "main" java.util.MissingFormatArgumentException: Format specifier '%d'
	at java.base/java.util.Formatter.format(Formatter.java:2796)
	...
```

Первый `%d` подставил `5`, а для второго значения нет. Программа успела напечатать `5 `, затем остановилась. Значений может быть больше, чем спецификаторов: лишние молча игнорируются.

**4. Неизвестный спецификатор.**

```java
System.out.printf(Locale.ROOT, "%q%n", 5);
```

```text
Exception in thread "main" java.util.UnknownFormatConversionException: Conversion = 'q'
	at java.base/java.util.Formatter$FormatSpecifier.conversion(Formatter.java:2964)
	...
```

После `%` стоит буква, которой нет среди типов. Частая причина - забытый `%%` для знака процента: `"Скидка 10%"` не напечатается, потому что после `%` нет типа.

**5. Забыли `%n`.** `printf` не переводит строку, поэтому следующий вывод приклеится к предыдущему. Результат: `xy` вместо двух строк.

**6. Запятая вместо точки.** Если не передать `Locale.ROOT`, на компьютере с русскими настройками `String.format("%.2f", 2.5)` даст `2,50`, а на другом - `2.50`. Программа ведёт себя по-разному на разных машинах; для этого и нужен `Locale.ROOT`.

**7. Ожидают, что `printf` округлит значение.** После `printf("%.2f", x)` в переменной `x` по-прежнему лежит полное число. Если округлённое значение нужно дальше в вычислениях, используйте `Math.round`.

## Итоги

* `System.out.printf(Locale.ROOT, "шаблон", значения...)` подставляет значения в шаблон по порядку; `String.format` делает то же, но возвращает строку.
* Основные спецификаторы: `%s` (текст), `%d` (целое), `%.2f` (дробное с двумя знаками), `%n` (конец строки), `%%` (знак процента).
* Тип значения должен подходить спецификатору, а их количество - совпадать; иначе при выполнении возникает исключение.
* `Locale.ROOT` делает вывод одинаковым на любом компьютере: разделитель всегда точка. Нужен `import java.util.Locale;`.
* Форматирование меняет только запись; округлить само значение можно через `Math.round`.

В следующем уроке ([Сравнение и логические выражения](lesson:java.from-zero.comparison-and-logic)) программа научится сравнивать значения и принимать решения: операторы сравнения, логические выражения и `if`.

## Для тех, кто уже программирует

* `printf`/`format` - синтаксис в духе C, но проверяются типы: несоответствие даёт `IllegalFormatException` во время выполнения, а не неопределённое поведение. Компилятор строку формата не анализирует.
* Форматирование по умолчанию использует `Locale.getDefault(Locale.Category.FORMAT)`. Для машинно-читаемого вывода (файлы, сети, тесты) указывайте `Locale.ROOT` или `Locale.US` явно.
* `%.2f` использует режим округления `HALF_UP` по десятичному представлению значения, а не `HALF_EVEN`, как `round()` в Python. Для денег в реальных системах применяют `BigDecimal` или целые копейки, а не `double`.
* Переносы строки: `%n` даёт `System.lineSeparator()`, `\n` - всегда `LF`.
* `Math.round` возвращает `long` для `double` и `int` для `float`; округление по правилу «половина вверх» (`Math.floor(x + 0.5)`), поэтому `Math.round(-2.5)` равно `-2`. Для округления «к чётному» есть `Math.rint`.
* Для нескольких форматов в одном месте есть `java.text.DecimalFormat`; в простых программах достаточно `printf`.
* Блоки текста (`"""`) и `String.formatted(...)` с Java 15 позволяют писать `"%d".formatted(x)`; локаль при этом тоже по умолчанию.

## Почему округление при форматировании не совпадает с ожиданием

Это необязательный раздел: для заданий он не нужен.

Число `double` хранит двоичную дробь, а `%.2f` просит десятичную запись. Для этого `Formatter` берёт десятичное представление значения и округляет его по правилу «половина вверх». Поэтому результаты на границе иногда отличаются от результатов других языков: у `1.005` двоичное значение чуть меньше точной `1.005`, но Java, как правило, выведет `1.01`, а Python (`'%.2f' % 1.005`) - `1.00`. Не рассчитывайте на одинаковое поведение на границе округления; для сумм в рублях храните копейки в целых числах.

Региональные настройки (`Locale`) задают не только разделитель дробной части, но и разделитель тысяч, названия месяцев и порядок сортировки. Поэтому `String.format("%,d", 1234567)` без явной локали даёт `1 234 567` с неразрывным пробелом в России и `1,234,567` в США. `Locale.ROOT` - нейтральная локаль без привязки к стране, с точкой и запятой в английском стиле.
