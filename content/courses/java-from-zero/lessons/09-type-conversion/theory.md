## Зачем менять тип значения

Вы уже сталкивались с двумя ситуациями, где тип мешает.

1. Ввод приходит текстом. Слово `"42"` выглядит как число, но для Java это `String`: сложить его с другим числом или умножить нельзя.
2. Дробный результат нужен, а арифметика целая: `7 / 2` даёт `3`, хотя нужно `3.5`. В обратную сторону `int n = 3.5;` вообще не компилируется.

В обоих случаях нужно превратить значение одного типа в значение другого. Это называется **преобразованием типа**. В Java оно бывает двух видов: для текста есть специальные методы разбора, для чисел - **приведение типа**.

## Одна новая идея: преобразование всегда явное, когда можно что-то потерять

Правило такое: если значение гарантированно помещается в новый тип, Java преобразует его сама (`double d = 5;` даёт `5.0`). Если что-то может потеряться или превращение возможно не всегда, преобразование нужно написать явно, чтобы вы его заметили.

**Текст в число.** У типов-обёрток есть методы разбора:

* `Integer.parseInt("42")` даёт `int` `42`;
* `Double.parseDouble("2.5")` даёт `double` `2.5`.

**Число в другое число.** Перед значением в скобках пишут нужный тип - это **приведение**:

* `(int) 3.99` даёт `3` - дробная часть отбрасывается;
* `(double) 7` даёт `7.0`.

Для дробного деления целых приводят один из операндов: `(double) 7 / 2` даёт `3.5`.

<!-- section: examples -->
## Пример 1. Из текста в число

```java run
public class Main {
    public static void main(String[] args) {
        String text = "42";
        int n = Integer.parseInt(text);
        System.out.println(n + 1);
        System.out.println(text + 1);

        double price = Double.parseDouble("2.5");
        System.out.println(price * 4);
    }
}
```
```output
43
421
10.0
```

Разбор:

* `n + 1` складывает числа: `43`. `text + 1` - склейка текста и числа: `421`. Тип определяет, что делает `+`.
* `Double.parseDouble("2.5")` превращает текст с точкой в `double`; умножение даёт `10.0`.
* Метод вызывают через имя типа и точку: `Integer.parseInt(...)`. Результат нужно сохранить или использовать - как и результат любого метода.

## Пример 2. Приведение числа

```java run
public class Main {
    public static void main(String[] args) {
        System.out.println((int) 3.99);
        System.out.println((int) -3.99);
        System.out.println((double) 7);

        int a = 7;
        int b = 2;
        System.out.println(a / b);
        System.out.println((double) a / b);
        System.out.println((double) (a / b));
    }
}
```
```output
3
-3
7.0
3
3.5
3.0
```

Разбор:

* `(int) 3.99` равно `3`: дробная часть отбрасывается, а не округляется. Для `-3.99` результат `-3`, то есть отбрасывание идёт к нулю.
* `(double) a / b` читается так: сначала `a` становится `double`, затем делится на `b`. Деление уже дробное, получается `3.5`.
* `(double) (a / b)` - другое выражение. В скобках сначала выполняется целочисленное деление `3`, и только потом `3` превращается в `3.0`. Дробная часть потеряна ещё до приведения.

## Пример 3. Автоматическое и явное преобразование

```java run
public class Main {
    public static void main(String[] args) {
        int total = 5;
        double d = total;
        System.out.println(d);

        double exact = 8.75;
        int whole = (int) exact;
        System.out.println(whole);
        System.out.println(exact - whole);
    }
}
```
```output
5.0
8
0.75
```

Разбор: из `int` в `double` значение переходит само, ничего не теряя. Обратно - только с явным `(int)`. Разность `exact - whole` вычисляется в `double`, поэтому остаётся дробная часть `0.75`.

**Попробуйте.** Предскажите, что напечатает `System.out.println((int) 9.5 + (int) 2.5);`, а затем `System.out.println((int) (9.5 + 2.5));`. Скобки меняют момент, когда отбрасывается дробная часть.

## Точные правила

* `Integer.parseInt(строка)` возвращает `int`, `Double.parseDouble(строка)` возвращает `double`. Строка должна содержать **только** запись числа.
* `parseInt` принимает необязательный знак и цифры: `"42"`, `"-15"`, `"+4"`, `"007"` (даёт 7). Пробелы, дробная часть и пустая строка недопустимы.
* `parseDouble` принимает запись с **точкой**: `"2.5"`, `"7"`, `"1e3"`. Запятая как разделитель не принимается.
* Если строка не подходит, метод бросает `NumberFormatException` с текстом этой строки в сообщении.
* Приведение `(тип) значение` преобразует значение в указанный тип. Приведение `(int)` для `double` **отбрасывает** дробную часть (к нулю). Оно не округляет.
* Приведение имеет приоритет выше деления: `(double) a / b` значит `((double) a) / b`. Чтобы привести результат всего выражения, берут его в скобки: `(int) (x + y)`.
* Автоматические (неявные) преобразования идут от «меньшего» типа к «большему» без потерь: `int` в `double` (и в `long`). Обратные требуют приведения.
* Приведение `int` к `char` и `char` к `int` работает по числовому коду: `(char) 66` даёт `B`, `(int) 'A'` даёт `65`.
* Приведение большого числа к меньшему типу молча «заворачивает» значение: `(int) 3000000000L` даёт `-1294967296`. Приводите только тогда, когда уверены, что значение помещается.
* Нельзя привести `String` к `int` скобками: `(int) "5"` - ошибка компиляции. Для текста существуют только методы разбора.
* Для округления вместо отбрасывания есть `Math.round`; он возвращает `long`, поэтому для `int` нужно приведение: `(int) Math.round(2.6)`. Разберём его в уроке о форматировании.

## Типичные ошибки

**1. Строка не является числом.**

```java
int n = Integer.parseInt("abc");
```

```text
Exception in thread "main" java.lang.NumberFormatException: For input string: "abc"
	at java.base/java.lang.NumberFormatException.forInputString(NumberFormatException.java:67)
	at java.base/java.lang.Integer.parseInt(Integer.java:588)
	...
```

Программа скомпилировалась, но остановилась при выполнении. В сообщении названа строка, которую не удалось разобрать: `abc`. То же будет для `"3.5"` (не целое число), `" 5"` (пробел), `""` (пустая строка) и `"3,5"` в `parseDouble` (запятая).

**2. Дробь от деления целых.**

```java
int a = 7;
int b = 2;
double r = a / b;
System.out.println(r);
```

Напечатает `3.0`. Деление `a / b` целое, и тип переменной слева его не меняет. Нужно `(double) a / b`.

**3. Приведение не к тому месту.** `(double) (a / b)` даёт `3.0`: дробная часть пропала в скобках, до приведения. Привести нужно операнд: `(double) a / b`.

**4. Обратное преобразование без приведения.**

```java
double d = 5;
int n = d;
```

```text
Main.java:4: error: incompatible types: possible lossy conversion from double to int
        int n = d;
                ^
```

Java не делает преобразование, которое может потерять дробную часть. Напишите `int n = (int) d;` и помните, что дробная часть исчезнет.

**5. Приведение текста.**

```java
int x = (int) "5";
```

```text
Main.java:3: error: incompatible types: String cannot be converted to int
        int x = (int) "5";
                      ^
```

Скобки с типом работают для чисел и символов, но не для текста. Для текста нужен `Integer.parseInt("5")`.

**6. Ожидают округление.** `(int) 3.99` равно `3`, а не `4`. Приведение всегда отбрасывает дробную часть.

**7. Результат разбора не сохранён.** Строка `Integer.parseInt(text);` вычисляет число и отбрасывает его: переменная `text` остаётся текстом. Результат присваивают переменной или используют сразу.

## Итоги

* Текст превращают в числа методами `Integer.parseInt` и `Double.parseDouble`; запись должна быть точной, без пробелов и запятых.
* Неподходящая строка останавливает программу с `NumberFormatException`, в сообщении которого стоит эта строка.
* Приведение `(int)` отбрасывает дробную часть к нулю; `(double)` делает значение дробным.
* Дробный результат деления целых получают, приводя один из операндов: `(double) a / b`, а не `(double) (a / b)`.
* Преобразование без потерь (`int` в `double`) происходит само, с потерями - только явно.

В следующем уроке ([Форматированный вывод](lesson:java.from-zero.formatted-output)) мы научимся красиво оформлять числа в выводе: задавать число знаков после запятой.

## Для тех, кто уже программирует

* Приведение в стиле C: `(int) x`. Узкое приведение `double` в `int` отбрасывает дробь к нулю; значения за пределами диапазона насыщаются (`(int) 1e20` равно `Integer.MAX_VALUE`, `NaN` даёт 0). Приведение между целыми типами (`long` в `int`) отбрасывает старшие биты и не бросает исключений.
* Для безопасного сужения целых есть `Math.toIntExact(long)`: бросает `ArithmeticException` при выходе за диапазон.
* `Integer.parseInt` и `Double.parseDouble` бросают непроверяемое `NumberFormatException`. `Integer.parseInt(s, radix)` читает числа в других системах счисления. `Integer.valueOf` возвращает объект `Integer` (с кешем малых значений), а `parseInt` - примитив.
* `parseInt` не обрезает пробелы - в отличие от Python `int(" 5 ")`. Для текста из ввода используйте `trim()` или читайте токен через `next()`.
* `Double.parseDouble` всегда ожидает точку и не зависит от локали - в отличие от `Scanner.nextDouble()` и `String.format` по умолчанию.
* `(char)` и `(int)` для символов работают с числовым кодом UTF-16.
* Операторы вроде `+=` делают неявное приведение к типу левой части: `int i = 1; i += 1.9;` оставит `i` равным 2.
* Сравнение: в Python `int("3.5")` тоже ошибка, `int(3.9)` даёт 3; в JavaScript `Number("abc")` возвращает `NaN`, а не бросает исключение.

<!-- section: deep-dive -->
## Что происходит при приведении

Это необязательный раздел: для заданий он не нужен.

Для `(int)` от `double` процессор выполняет специальную команду, и Java определяет результат так: дробная часть отбрасывается, `NaN` превращается в 0, слишком большие значения превращаются в `Integer.MAX_VALUE` или `Integer.MIN_VALUE`. Для приведения между целыми типами вместо этого берутся младшие биты, поэтому `(int) 3000000000L` даёт отрицательное число.

Автоматическое расширение `int` в `double` без потерь работает, потому что `double` с 52 битами мантиссы точно хранит все 32-битные целые. Для `long` в `double` это уже не так: большие `long` приходят к ближайшему представимому `double`, и точность теряется, хотя Java разрешает такое преобразование без приведения. Это один из немногих случаев, когда «безопасное» расширение всё же может потерять младшие цифры.

Методы `parseInt` и `parseDouble` не используют приведение: они разбирают символы по одному, накапливая число, и бросают исключение при первом неподходящем символе.
