## Зачем уметь читать сообщения об ошибках

В программе из нескольких строк почти всегда есть ошибка, пока она не заработала в первый раз, и у опытных программистов тоже. Поэтому главное умение этого этапа - не писать без ошибок, а **быстро понять, что сообщает компилятор**. Он называет файл, строку и причину. Тот, кто умеет это прочитать, исправляет ошибку за минуту, а тот, кто не умеет, гадает час.

Если в программе есть ошибка, компилятор не создаёт программу вообще: ничего не запускается, и на экране только сообщения об ошибках. Это называется **ошибкой компиляции**. Она хороша тем, что случается до запуска и не оставляет частично выполненного результата.

## Одна новая идея: сообщение об ошибке состоит из нескольких частей

Возьмём программу, в которой забыта точка с запятой. Компилятор выведет:

```text
Main.java:3: error: ';' expected
        System.out.println("Заказ принят")
                                          ^
1 error
```

Части сообщения:

1. `Main.java:3` - файл и **номер строки**, около которой компилятор заметил проблему.
2. `error:` - это ошибка (программа не соберётся); дальше **описание**: здесь `';' expected`, то есть «ожидалась точка с запятой».
3. Следующая строка - копия вашей строки кода, а под ней значок `^`, который показывает **место** в строке.
4. `1 error` - сколько ошибок нашёл компилятор.

Читайте сообщения **сверху вниз и по одному**: исправьте первую ошибку, соберите программу заново, прочитайте новый список. Причина простая: первая ошибка может быть причиной следующих, а компилятор работает в несколько проходов и проблемы разных видов находит не одновременно.

## Пример 1. Ошибка, которая прячет другую

В этой программе две ошибки: пропущена точка с запятой и написано `system` с маленькой буквы.

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Добро пожаловать")
        system.out.println("Касса открыта");
    }
}
```

Первая сборка сообщает только об одной ошибке:

```text
Main.java:3: error: ';' expected
        System.out.println("Добро пожаловать")
                                              ^
1 error
```

Компилятор сначала проверяет, правильно ли записан текст (скобки, кавычки, точки с запятой), и пока такая ошибка есть, до проверки имён не доходит. Добавляем `;` и собираем заново:

```text
Main.java:4: error: package system does not exist
        system.out.println("Касса открыта");
              ^
1 error
```

Теперь видна вторая ошибка: имя `system` неизвестно. Правильно `System` с заглавной буквы. Каждое исправление не «чинит всё», а открывает следующий слой.

## Пример 2. Исправленная программа

```java run
public class Main {
    public static void main(String[] args) {
        System.out.println("Добро пожаловать");
        System.out.println("Касса открыта");
    }
}
```
```output
Добро пожаловать
Касса открыта
```

Разбор: после двух исправлений компилятор не нашёл ошибок, программа собралась и выполнилась сверху вниз. Номера строк в сообщениях относятся к файлу, который вы видите в редакторе, поэтому достаточно перейти на указанную строку.

**Попробуйте.** Сломайте эту программу по-своему: удалите закрывающую кавычку, поставьте лишнюю скобку, замените `println` на `Println`. Для каждой поломки сначала предскажите, на какую строку укажет компилятор, и только потом запустите.

## Точные правила

* **Ошибка компиляции** возникает до запуска. Программа не стартует, в выводе только сообщения с префиксом `Main.java:<строка>: error:`.
* **Ошибка времени выполнения** случается уже во время работы, когда программа собралась и начала выполняться. Выглядит иначе, например при делении на ноль (деление разберём в уроке про арифметику):

  ```text
  Exception in thread "main" java.lang.ArithmeticException: / by zero
  	at Main.main(Main.java:3)
  ```

  Здесь тоже есть номер строки: `Main.java:3` - то место, где программа остановилась. Всё, что она успела напечатать до этого, остаётся на экране.
* Номер строки в сообщении - место, где компилятор **заметил** проблему. Причина иногда стоит строкой раньше: пропущенная точка с запятой замечается уже в конце команды, а незакрытая скобка - только в конце файла.
* Частые описания: `';' expected` (не хватает `;`), `unclosed string literal` (не закрыта кавычка), `cannot find symbol` (имя неизвестно: опечатка, неверный регистр или оно нигде не объявлено), `package X does not exist` (имя `X` считается именем пакета, которого нет), `reached end of file while parsing` (файл закончился раньше, чем закрыты все скобки).
* Строки `symbol:` и `location:` после `cannot find symbol` называют, **чего** нет и **где** искали: это основная подсказка.
* Число в конце (`2 errors`) - общее число найденных ошибок. После исправления первой оно часто уменьшается сильнее, чем на единицу.

## Типичные ошибки

**1. Исправляют ошибки с конца или все сразу и не пересобирают программу.** Вторая и следующие ошибки могут быть следствием первой, а часть ошибок компилятор ещё не нашёл. Исправьте первую, запустите, прочитайте новый вывод.

**2. Имя класса не совпадает с именем файла.** Файл называется `Main.java`, а в нём написано `public class Hello`:

```text
Main.java:1: error: class Hello is public, should be declared in a file named Hello.java
public class Hello {
       ^
```

Компилятор сам объясняет правило: публичный класс должен лежать в файле с тем же именем. В этом курсе класс всегда называется `Main`.

**3. Не закрыта фигурная скобка.** Если в конце программы пропала последняя `}`:

```text
Main.java:5: error: reached end of file while parsing
    }
     ^
```

Номер строки здесь - **конец файла**, а не место, где скобка пропущена. Проверьте, что у каждой `{` есть парная `}`; редактор подсвечивает пары, если поставить курсор рядом со скобкой.

**4. Имя без кавычек.** Если написать `System.out.println(Спасибо);`, компилятор решит, что `Спасибо` - имя чего-то, и ответит `cannot find symbol` и `symbol: variable Спасибо`. Текст, который нужно напечатать, всегда в кавычках.

**5. Читают только последнюю строку вывода.** Строка `1 error` лишь подводит итог. Информация об ошибке стоит выше: в строках с `Main.java:` и `symbol:`.

Общее правило чтения: найдите в сообщении номер строки, посмотрите на неё и на предыдущую, сверьтесь с описанием и значком `^`.

## Итоги

* Ошибка компиляции останавливает сборку до запуска; сообщение состоит из файла, строки, описания, копии строки кода и значка `^`.
* Читайте первую ошибку, исправляйте, собирайте заново: следующие ошибки могут быть следствием первой или проявляться только после неё.
* `';' expected`, `unclosed string literal`, `cannot find symbol` и `reached end of file while parsing` - самые частые сообщения начинающих; теперь вы знаете, что за ними стоит.
* Ошибка времени выполнения выглядит иначе (`Exception in thread "main"`), но тоже называет строку.

В следующем уроке ([Вывод: print, println и соединение текста](lesson:java.from-zero.output)) мы научимся управлять выводом: печатать без перевода строки, переносить строки внутри текста и соединять текст со значениями.

## Для тех, кто уже программирует

* `javac` проверяет и синтаксис, и типы до запуска. В Python опечатка в имени проявится только при выполнении этой строки, в Java - при сборке.
* Формат сообщений: `File.java:<строка>: error: <описание>`, затем строка кода и каретка `^`. Обычно синтаксические ошибки компилятор находит первыми и только потом проверяет имена и типы, поэтому после исправления первой пачки могут появиться новые.
* `cannot find symbol` - универсальная ошибка «имя не объявлено»; строки `symbol` и `location` указывают класс, метод или переменную.
* Ошибки времени выполнения (исключения) печатаются в `stderr` вместе со стеком вызовов; первая строка стека, содержащая ваш файл, указывает ваш код.
* Предупреждения (`warning`) сборке не мешают, а ошибки (`error`) останавливают её.
* Связанные идеи: компилируемые языки (Go, Rust, C#) устроены так же, интерпретируемые (Python, JavaScript) находят многие такие ошибки позже.

## Как работает компилятор: проходы

Это необязательный раздел: для заданий он не нужен.

Компилятор Java работает несколькими проходами. Сначала **разбор** (parsing): текст разбивается на слова и знаки, и проверяется, что скобки, кавычки и точки с запятой стоят по правилам грамматики. Ошибки этого прохода - `';' expected`, `unclosed string literal`, `reached end of file while parsing`. Затем **анализ имён и типов**: для каждого имени проверяется, что оно объявлено, а типы согласованы. Здесь рождаются `cannot find symbol` и `incompatible types`. И только потом создаётся байткод.

Пока разбор находит ошибки, следующий проход не запускается, потому что по неправильно записанному тексту нельзя надёжно проверять имена. Отсюда эффект из примера 1: исправили первую ошибку - и увидели вторую, которая всё это время была в программе.
