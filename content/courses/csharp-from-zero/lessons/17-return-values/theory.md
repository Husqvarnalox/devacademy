## Зачем методу возвращать значение

Метод `void` только выполняет действие. Но чаще метод нужен, чтобы **вычислить** что-то и отдать результат тому, кто его вызвал: цену со скидкой, признак «совершеннолетний ли», наибольшее из двух чисел. Вычисленное значение метод передаёт обратно командой **`return`**, а вызывающий код может сохранить его в переменной, напечатать или использовать в другом выражении. Метод, который возвращает значение, не печатает: за вывод отвечает тот, кто его вызвал. Такие методы легко проверять и переиспользовать.

## Одна новая идея: вместо void пишется тип результата

```csharp
static int Square(int x)
{
    return x * x;
}
```

* вместо `void` в заголовке стоит **тип результата** (`int`, `string`, `bool`, `double`, ...);
* команда `return значение;` завершает метод и отдаёт значение. Тип значения должен подходить к типу результата;
* вызов `Square(5)` - это **выражение**: оно имеет значение (25) и может стоять там, где допустимо значение: `int a = Square(5);`, `Console.WriteLine(Square(3) + 1);`.

Метод типа `bool` называют **условием**: он отвечает «да» или «нет» и удобен в `if`: `if (IsAdult(age)) { ... }`.

Если тело метода - одно выражение, его можно записать короче через стрелку `=>`: `static int Square(int x) => x * x;`. Это эквивалент записи с `return`.

Методы `void` и методы с результатом различаются так: `void` вызывают как команду, метод с результатом вызывают там, где нужно значение.

## Пример 1. Метод возвращает число

```csharp run
int area = Square(7);
Console.WriteLine(area);
Console.WriteLine(Square(3) + Square(4));

static int Square(int x)
{
    return x * x;
}
```
```output
49
25
```

Разбор:

* `Square(7)` вычисляется и возвращает 49; результат попадает в `area`;
* во второй строке вызовы стоят прямо в выражении: `Square(3)` даёт 9, `Square(4)` - 16, сумма 25;
* печатает значение основная часть программы, а не метод.

## Пример 2. Скидка

```csharp run
int price = 2000;
int final = FinalPrice(price, 15);
Console.WriteLine($"Цена со скидкой: {final}");
Console.WriteLine($"Для 999 рублей и 10%: {FinalPrice(999, 10)}");

static int FinalPrice(int price, int percent)
{
    int discount = price * percent / 100;
    return price - discount;
}
```
```output
Цена со скидкой: 1700
Для 999 рублей и 10%: 900
```

Скидка вычисляется целочисленным делением, поэтому для 999 рублей и 10% она равна 99 (а не 99,9). Параметр `price` в методе и переменная `price` в основной части независимы.

## Пример 3. Метод-условие

```csharp run
Console.WriteLine(IsEven(10));
Console.WriteLine(IsEven(7));

int age = 16;
if (IsAdult(age))
{
    Console.WriteLine("Доступ разрешён");
}
else
{
    Console.WriteLine("Только с 18 лет");
}

static bool IsEven(int n) => n % 2 == 0;

static bool IsAdult(int age)
{
    return age >= 18;
}
```
```output
True
False
Только с 18 лет
```

Результат типа `bool` можно напечатать (будет `True` или `False`) или использовать в `if` вместо условия. Запись `IsEven` через `=>` равна записи с `return n % 2 == 0;`. Название метода-условия обычно начинается с `Is`, `Has` или `Can`: так сразу ясно, что это вопрос.

## Пример 4. Несколько return и ранний выход

```csharp run
Console.WriteLine(Grade(95));
Console.WriteLine(Grade(70));
Console.WriteLine(Grade(30));

static string Grade(int points)
{
    if (points >= 90)
    {
        return "отлично";
    }
    if (points >= 60)
    {
        return "хорошо";
    }
    return "плохо";
}
```
```output
отлично
хорошо
плохо
```

`return` сразу завершает метод, поэтому остальные команды не выполняются. Здесь после первой подходящей проверки метод возвращает значение, и `else` писать не нужно. Последний `return` без условия закрывает все остальные случаи: компилятор требует, чтобы каждый путь выполнения заканчивался `return`.

## Пример 5. Метод вызывает метод

```csharp run
Console.WriteLine(Max3(4, 9, 6));

static int Max(int a, int b)
{
    if (a > b)
    {
        return a;
    }
    return b;
}

static int Max3(int a, int b, int c)
{
    return Max(a, Max(b, c));
}
```
```output
9
```

Результат внутреннего вызова `Max(b, c)` становится аргументом внешнего. Мелкие методы, собираемые в более крупные, и есть главный способ упрощать программу.

## Точные правила

* Заголовок: `static ТипРезультата Имя(параметры)`. Тело заканчивается командой `return значение;` на каждом пути выполнения.
* Тип выражения после `return` должен подходить к типу результата. `int` можно вернуть из метода `double` (преобразование неявное), обратное - нет.
* `return` завершает метод немедленно; команды после него недостижимы (предупреждение `CS0162`).
* Метод `void` может содержать `return;` без значения: это ранний выход.
* Вызов метода с результатом - выражение. Если результат не используется, он просто отбрасывается: `Square(5);` ничего не выводит и ничего не меняет.
* Форма с `=>`: `static int Square(int x) => x * x;` равна записи с телом и `return`. Подходит, когда тело - одно выражение.
* Целочисленное деление действует и внутри методов: `static double Half(int n) { return n / 2; }` для 5 вернёт 2, потому что деление выполняется на `int`, и только потом результат превращается в `double`. Чтобы получить 2.5, делите на `2.0` или приводите к `double`.
* Имена параметров не должны совпадать с другими параметрами этого метода, но могут совпадать с переменными основной части.

## Типичные ошибки

**1. Не все пути возвращают значение.**

```csharp
static int Sign(int n)
{
    if (n > 0)
    {
        return 1;
    }
    else if (n < 0)
    {
        return -1;
    }
}
```

Компилятор: `error CS0161: 'Sign(int)': not all code paths return a value`. Для `n`, равного 0, ни один `return` не сработал. Добавьте `return 0;` в конце.

**2. Возврат значения из метода `void`.**

```csharp
static void Show(int n)
{
    return n * 2;
}
```

Компилятор: `error CS0127: Since 'Show(int)' returns void, a return keyword must not be followed by an object expression`. Либо измените `void` на `int`, либо уберите значение после `return`.

**3. Пустой `return` в методе с результатом.**

```csharp
static int Twice(int n)
{
    return;
}
```

Компилятор: `error CS0126: An object of a type convertible to 'int' is required`. После `return` должно стоять значение нужного типа.

**4. Неподходящий тип результата.**

```csharp
static int Name()
{
    return "Анна";
}
```

Компилятор: `error CS0029: Cannot implicitly convert type 'string' to 'int'`. Тип результата в заголовке и тип значения должны быть совместимы.

**5. Использование результата метода `void`.**

```csharp
int n = Show();
```

Компилятор: `error CS0029: Cannot implicitly convert type 'void' to 'int'`. Если значение нужно, метод не должен быть `void`.

**6. Результат вызова потерян.**

```csharp
Square(5);
Console.WriteLine("готово");
```

Компилятор не ругается, но вычисленное значение пропадает. Сохраните его в переменной или напечатайте: `int s = Square(5);`.

**7. Целочисленное деление в методе `double`.** `static double Half(int n) { return n / 2; }` для `n`, равного 5, вернёт 2. Исправьте деление: `return n / 2.0;`.

**8. Код после `return`.**

```csharp
static int F(int n)
{
    return n * 2;
    Console.WriteLine("после return");
}
```

Компилятор: `warning CS0162: Unreachable code detected`. Строка с `Console.WriteLine` не выполнится никогда.

## Итоги

* Метод с результатом: `static Тип Имя(параметры) { ... return значение; }`.
* Вызов такого метода - выражение; результат можно сохранить, напечатать или передать в другой метод.
* `return` немедленно завершает метод; каждый путь должен вернуть значение.
* Метод типа `bool` - условие для `if`; его имя начинают с `Is`, `Has`, `Can`.
* Для короткого тела удобна запись со стрелкой `=>`.
* Метод, который считает, ничего не печатает; печатает вызывающий код.

С этого урока упражнения устроены по-новому: чтение ввода и печать результата написаны за вас, а вы пишете методы. Теперь пора хранить много значений сразу: [Массивы](lesson:csharp.from-zero.arrays).

## Для тех, кто уже программирует

* Возврат работает как в Java, C и Go (в Go допускается несколько значений; в C# для этого есть кортежи, в курсе они не используются). Компилятор строго проверяет, что все пути заканчиваются `return` (определённое присваивание).
* Запись `=>` называется *expression-bodied member*. Не путайте с лямбда-стрелкой: синтаксис общий, смысл разный (здесь это сокращённое тело метода).
* Нет «неявного возврата последнего выражения», как в Rust или Kotlin: `return` обязателен, кроме формы `=>`.
* Метод `bool` пишут вместо повторяющихся сложных условий; в C# принято называть их `IsX`/`HasX`.
* `int` неявно расширяется до `double` при возврате, `double` в `int` без явного приведения не сужается: `return 3.7;` из метода `int` - ошибка `CS0266`.
* Возвращаемое значение можно не использовать; предупреждения для этого нет, кроме особых атрибутов вроде `[MustUseReturnValue]` в библиотеках.
* Методы без побочных эффектов (возвращают результат и ничего не меняют) называют «чистыми»; их проще всего тестировать, поэтому дальше упражнения проверяют именно такие методы.

## Куда уходит возвращаемое значение

Это необязательный раздел: для заданий он не нужен.

Для небольших значений (числа, `bool`) результат метода по соглашению о вызовах помещается в регистр процессора, и вызывающий код забирает его оттуда. Для больших значений место под результат выделяется в вызывающем коде. Ссылки на объекты (строки, массивы, списки) тоже возвращаются как «адрес», а сам объект остаётся в куче: возврат строки не копирует её символы.

Благодаря этому вызов небольшого метода почти бесплатен: JIT-компилятор часто просто подставляет тело метода в место вызова (inlining), и разница между `Square(x)` и `x * x` в готовом коде исчезает. Поэтому выделять мелкие методы ради читаемости не только можно, но и нужно.
