## Зачем читать сообщения об ошибках

Опечатки в программе неизбежны: пропущенная кавычка, лишняя буква, забытая точка с запятой. Компьютер не угадывает намерение, поэтому программа с опечаткой либо не запустится, либо поведёт себя не так, как вы хотели. Умение прочитать сообщение об ошибке и найти по нему проблему - один из самых полезных навыков: большая часть исправлений в реальной работе начинается именно с чтения сообщения.

У программы на C# два этапа жизни:

1. **Сборка.** Компилятор читает весь файл и проверяет его по правилам языка. Если находит ошибку, он сообщает о ней, и сборка останавливается: запускать нечего. Это **ошибка компиляции**.
2. **Запуск.** Собранная программа выполняется команда за командой. Если на какой-то команде что-то идёт не так (например, нужно превратить текст `abc` в число), программа останавливается с **ошибкой выполнения**. Всё, что она успела напечатать до этого, остаётся на экране.

Важное следствие: ошибка компиляции в любой строке файла, даже в последней, означает, что не выполнится **ни одна** команда. Ошибка выполнения случается позже, и команды перед ней успевают сработать.

## Одна новая идея: сообщение - это адрес и причина

Каждое сообщение компилятора устроено одинаково:

```
Program.cs(2,48): error CS1002: ; expected
```

Читается так: в файле `Program.cs`, в строке 2, на 48-м символе найдена **ошибка** (`error`) с кодом `CS1002`; описание - «ожидалась `;`». Сначала смотрят на номер строки, затем на описание.

## Пример 1. Ошибка компиляции: программа не запускается

Допустим, в программе пропущена точка с запятой:

```csharp
Console.WriteLine("Один")
Console.WriteLine("Два");
```

Компилятор сообщит:

```
Program.cs(1,26): error CS1002: ; expected
```

Разбор:

* `Program.cs` - имя файла;
* `(1,26)` - строка 1, символ 26: это место сразу после закрывающей скобки, где ожидалась `;`;
* `error` - сборка остановлена, программа не запускается; ни «Один», ни «Два» напечатаны не будут;
* `CS1002` - код ошибки: по нему можно найти пояснение в документации;
* `; expected` - описание: «ожидалась точка с запятой».

Описание может быть на русском, если на вашей системе включён русский язык; код и позиция те же.

## Пример 2. Ошибки приходят «волнами»

Компилятор проверяет программу этапами. Пока в тексте есть ошибки записи (не хватает `;`, не закрыта кавычка), проверку имён он ещё не выполняет. Возьмём программу:

```csharp
Console.WriteLine("Добро пожаловать в магазин");
console.WriteLine("Сегодня скидка 10%");
Console.WriteLine("Приходите ещё!");
```

Здесь на второй строке слово `console` написано с маленькой буквы. Сообщение:

```
Program.cs(2,1): error CS0103: The name 'console' does not exist in the current context
```

«Имя `console` в этом месте не существует». Позиция `(2,1)` - первый символ второй строки. Если бы в этой же программе была ещё и пропущена `;`, вы сначала увидели бы только ошибку про `;`, исправили её и лишь после этого получили сообщение про `console`. Это нормально: исправляйте ошибки по одной, начиная с первой, и после каждой правки запускайте сборку заново.

## Пример 3. Ошибка выполнения: часть вывода уже есть

```csharp
Console.WriteLine("Шаг 1");
Console.WriteLine(int.Parse("abc"));
Console.WriteLine("Шаг 3");
```

С точки зрения компилятора здесь всё верно, и программа запускается. Команда `int.Parse("abc")` пытается превратить текст `abc` в целое число (как это работает - в одном из следующих уроков) и не может. Что вы увидите:

```
Шаг 1
Unhandled exception. System.FormatException: The input string 'abc' was not in a correct format.
   at System.Number.ThrowFormatException[TChar](ReadOnlySpan`1 value)
   at System.Int32.Parse(String s)
   at Program.<Main>$(String[] args) in Program.cs:line 2
```

Разбор:

* `Шаг 1` напечатан: первая команда успела выполниться;
* `Unhandled exception` - «необработанное исключение»: программа столкнулась с ошибкой и не знает, что с ней делать;
* `System.FormatException` - тип ошибки («неверный формат»), затем описание причины;
* строки `at ...` - путь, по которому программа дошла до ошибки; для вас важна та, где стоит имя вашего файла: `Program.cs:line 2` - ошибка произошла на второй строке;
* «Шаг 3» не напечатан: после необработанной ошибки программа останавливается.

**Попробуйте.** Возьмите программу из примера 1, исправьте её, а затем намеренно сделайте другую ошибку: напишите `Console.WriteLine("Два";` (скобка не закрыта). Прочитайте сообщение и найдите по нему место.

## Точные правила

* Сообщение компилятора: `файл(строка,символ): уровень КОД: описание`.
* **Уровень** бывает `error` и `warning`. `error` останавливает сборку. `warning` («предупреждение») не мешает программе запуститься, но говорит, что компилятор что-то заподозрил; в этом курсе предупреждения считаются дефектом и исправляются так же, как ошибки. Первое предупреждение вы встретите, когда будете работать с переменными.
* **Номер строки** считается с единицы, **номер символа** - тоже. Это место, где компилятор понял, что что-то не так, а не всегда место самой опечатки: пропущенную `;` он замечает после конца команды, поэтому позиция может указывать на конец строки, а иногда на начало следующей.
* Одна опечатка нередко порождает несколько сообщений подряд (так бывает с незакрытой кавычкой). Исправляйте первое, остальные часто исчезают сами.
* Ошибки записи компилятор находит раньше, чем ошибки имён и типов, поэтому «волны» сообщений - обычное явление.
* **Ошибка выполнения** возникает в собранной программе. Её сообщение начинается с `Unhandled exception.`, затем тип и описание, затем список вызовов `at ...`. Нужная вам строка - та, где написано `Program.cs:line N`.
* Как искать самому: скопируйте код (`CS1002`) или тип ошибки (`FormatException`) в поиск и добавьте слово C#.
* Выполнение программы не начинается, пока есть хотя бы одна ошибка компиляции.

## Типичные ошибки

**1. Смотрят не на ту строку.**

```csharp
Console.WriteLine("Один")
Console.WriteLine("Два");
```

Сообщение `Program.cs(1,26): error CS1002: ; expected` указывает на конец строки 1, а новичок смотрит на строку 2. Если сообщение говорит «ожидалось», загляните в конец указанной строки и в предыдущую.

**2. Исправляют все сообщения подряд.** Если после одной незакрытой кавычки пришло три сообщения (`CS1010`, `CS1026`, `CS1002`), то причина одна. Исправьте первую, запустите сборку заново и посмотрите, что осталось.

**3. Не перезапускают сборку после правки.** Исправили одну ошибку, внесли ещё две правки и ждут, что всё заработает. Новые ошибки трудно отличить от старых. Одна правка - один запуск.

**4. Путают ошибку компиляции и ошибку выполнения.** Если в выводе нет ни одной строки программы - искали ошибку записи, программа не собралась. Если часть строк напечатана и затем появился `Unhandled exception` - программа собралась, а ошибка случилась на конкретной команде; ищите по `Program.cs:line N`.

**5. Игнорируют предупреждения.** Предупреждение не мешает запуску, но указывает на реальную проблему или бесполезный код. Относитесь к нему как к ошибке.

Общее правило: сначала номер строки, затем описание, затем код для поиска. Если непонятно, переведите описание дословно и сопоставьте со строкой.

## Итоги

* Программа проходит два этапа: сборка (компилятор проверяет весь файл) и запуск (команды выполняются по порядку).
* Ошибка компиляции означает, что программа не запускается вообще; ошибка выполнения случается на конкретной команде, команды до неё уже сработали.
* Сообщение компилятора: файл, строка и символ, уровень (`error` или `warning`), код `CSxxxx`, описание.
* Исправляйте ошибки по одной с самой первой и запускайте сборку после каждой правки: ошибки приходят волнами.

Теперь вы можете сами разбираться, почему программа не собирается. Дальше - более гибкий вывод: [Вывод: Write, WriteLine и специальные символы](lesson:csharp.from-zero.output).

## Для тех, кто уже программирует

* Как и в Java или Go, ошибки синтаксиса и типов в C# находятся при сборке, а не при запуске, как в Python или JavaScript. Программа с ошибкой компиляции не запускается совсем.
* Формат диагностики: `файл(строка,столбец): error CSxxxx: текст`; коды стабильны и подходят для поиска. Язык текста зависит от настроек системы.
* Предупреждения (`warning CS...`) не останавливают сборку. Включённая по умолчанию в новых проектах nullable-проверка порождает предупреждения о возможном `null` (`CS8600`-`CS8604`); в курсе код пишется без них.
* Необработанное исключение завершает процесс с ненулевым кодом и выводит `Unhandled exception.`, тип, сообщение и стек вызовов в stderr. Строка в стеке с номером доступна, потому что в отладочной сборке есть символы.
* Компилятор находит ошибки поэтапно (лексический/синтаксический разбор, затем семантический), поэтому исправление одной ошибки может «открыть» новые.

## Как устроена сборка

Это необязательный раздел: для заданий он не нужен.

В этом приложении кнопка «Запустить» выполняет две команды: сборку (`dotnet build Program.cs`) и запуск собранной сборки командой `dotnet`. Сообщения об ошибках сборки пишет компилятор Roslyn; каждое называется **диагностикой** и имеет уровень (информация, предупреждение, ошибка), код и позицию. Код `CS` означает «C Sharp», число - порядковый номер диагностики в списке компилятора.

Разбор программы идёт в несколько проходов. Сначала текст разбивается на лексемы (слова, числа, знаки) и строится дерево синтаксиса: на этом этапе находятся пропущенные `;`, скобки и кавычки. Затем компилятор связывает имена с объявлениями и проверяет типы: здесь находятся `CS0103` («имя не существует») и `CS0117` («нет такого члена»). Второй этап зависит от первого, поэтому при синтаксических ошибках семантические сообщения могут не появиться.

Необработанное исключение завершает процесс с ненулевым кодом возврата; система автоматической проверки сравнивает и вывод, и этот код. Подробнее об устройстве запуска - в уроке [Как выполняется C#](lesson:csharp.first-steps.how-csharp-runs).
