## Зачем нужны классы

До сих пор каждое значение жило в отдельной переменной: `string name`, `int price`, `int quantity`. Пока в программе один товар, это удобно. Когда товаров сорок, возникают три связанных набора переменных или три параллельных списка, и легко запутаться, какая цена от какого названия. Хотелось бы собрать название, цену и количество в **одно значение** «товар» и передавать его целиком.

Для этого в C# есть **классы**.

## Одна новая идея: класс - описание, объект - экземпляр

**Класс** (*class*) - это описание нового типа: какие данные он хранит и что умеет делать. Сам по себе класс ничего не хранит, как чертёж не есть дом. Конкретное значение этого типа называется **объектом** (*object*) и создаётся словом **`new`**. Данные объекта хранятся в его **свойствах** (*property*), поведение - в методах.

```csharp
class Item
{
    public string Name { get; set; } = "";
    public int Price { get; set; }
}
```

Читается так: тип `Item` имеет свойство `Name` типа `string` и свойство `Price` типа `int`. Слово `public` значит «доступно снаружи класса». Запись `{ get; set; }` значит «значение можно читать и записывать»; пока принимайте её как шаблон для свойства. Присваивание `= ""` задаёт начальное значение.

Объект создаётся так: `Item bread = new Item();`, а к свойствам обращаются через точку: `bread.Name`, `bread.Price`.

Второй важный вывод: объект класса - **ссылочный тип** (*reference type*). Переменная хранит не сам объект, а ссылку на него. Об этом подробно в примерах.

<!-- section: examples -->
## Пример 1. Первый класс

```csharp run
Item bread = new Item();
bread.Name = "Хлеб";
bread.Price = 45;

Console.WriteLine(bread.Name);
Console.WriteLine(bread.Price);

class Item
{
    public string Name { get; set; } = "";
    public int Price { get; set; }
}
```
```output
Хлеб
45
```

Разбор:

* `new Item()` создаёт новый объект типа `Item`; переменная `bread` ссылается на него;
* свойства задаются присваиванием `bread.Name = "Хлеб";` и читаются так же, как обычные переменные;
* **описание класса стоит после инструкций верхнего уровня** (в конце файла). Если поставить его раньше, будет ошибка компиляции (см. ниже).

## Пример 2. Значения по умолчанию и инициализатор

```csharp run
Item empty = new Item();
Console.WriteLine($"[{empty.Name}] {empty.Price}");

Item milk = new Item { Name = "Молоко", Price = 80 };
Console.WriteLine($"{milk.Name}: {milk.Price}");

class Item
{
    public string Name { get; set; } = "";
    public int Price { get; set; }
}
```
```output
[] 0
Молоко: 80
```

Свойство, которому ничего не присвоили, получает значение по умолчанию: для `int` это 0, для `string` - то, что вы написали после `=` (здесь пустая строка). Запись `new Item { Name = "Молоко", Price = 80 }` создаёт объект и сразу задаёт его свойства: это называется **инициализатор объекта**.

## Пример 3. Метод внутри класса

```csharp run
Item tea = new Item { Name = "Чай", Price = 120, Quantity = 3 };
Console.WriteLine($"{tea.Name}: {tea.Cost()}");

class Item
{
    public string Name { get; set; } = "";
    public int Price { get; set; }
    public int Quantity { get; set; }

    public int Cost()
    {
        return Price * Quantity;
    }
}
```
```output
Чай: 360
```

Метод `Cost` объявлен внутри класса **без слова `static`**. Такой метод принадлежит объекту: он вызывается через переменную (`tea.Cost()`) и внутри видит свойства именно этого объекта (`Price`, `Quantity`). Статические методы, которые вы писали раньше, не привязаны к объекту и видят только свои параметры.

## Пример 4. Список объектов

```csharp run
List<Item> items = new List<Item>();
items.Add(new Item { Name = "Хлеб", Price = 45, Quantity = 2 });
items.Add(new Item { Name = "Сыр", Price = 300, Quantity = 1 });
items.Add(new Item { Name = "Яйца", Price = 90, Quantity = 3 });

int total = 0;
foreach (Item item in items)
{
    Console.WriteLine($"{item.Name}: {item.Cost()}");
    total += item.Cost();
}
Console.WriteLine($"Итого: {total}");

class Item
{
    public string Name { get; set; } = "";
    public int Price { get; set; }
    public int Quantity { get; set; }

    public int Cost()
    {
        return Price * Quantity;
    }
}
```
```output
Хлеб: 90
Сыр: 300
Яйца: 270
Итого: 660
```

В `List<Item>` лежат объекты, и каждый знает свои название, цену и количество. Три параллельных списка заменил один.

## Пример 5. Создание объекта из строки

```csharp run
Item item = ReadItem("хлеб 45 2");
Console.WriteLine($"{item.Name} {item.Price} {item.Quantity} -> {item.Cost()}");

static Item ReadItem(string line)
{
    string[] parts = line.Split(' ', StringSplitOptions.RemoveEmptyEntries);
    Item result = new Item();
    result.Name = parts[0];
    result.Price = int.Parse(parts[1]);
    result.Quantity = int.Parse(parts[2]);
    return result;
}

class Item
{
    public string Name { get; set; } = "";
    public int Price { get; set; }
    public int Quantity { get; set; }

    public int Cost()
    {
        return Price * Quantity;
    }
}
```
```output
хлеб 45 2 -> 90
```

Метод может возвращать объект, как возвращал бы число. Строка разрезается на части, из частей собирается объект. Так получают объекты из строк ввода.

## Пример 6. Ссылки: две переменные - один объект

```csharp run
Item a = new Item { Name = "Хлеб", Price = 45 };
Item b = a;
b.Price = 50;

Console.WriteLine(a.Price);
Console.WriteLine(b.Price);

int x = 10;
int y = x;
y = 20;
Console.WriteLine(x);

class Item
{
    public string Name { get; set; } = "";
    public int Price { get; set; }
}
```
```output
50
50
10
```

Строка `Item b = a;` **не создаёт новый объект**, она копирует ссылку. `a` и `b` теперь указывают на один и тот же объект, поэтому изменение через `b` видно через `a`. С числами иначе: `int y = x;` копирует само значение, и изменение `y` не трогает `x`. Это различие между ссылочными и значимыми типами.

## Пример 7. Объект, переданный в метод

```csharp run
Item item = new Item { Name = "Хлеб", Price = 45 };
Discount(item);
Console.WriteLine(item.Price);

static void Discount(Item target)
{
    target.Price = target.Price - 5;
}

class Item
{
    public string Name { get; set; } = "";
    public int Price { get; set; }
}
```
```output
40
```

Метод получил копию **ссылки**, но она указывает на тот же объект. Метод изменил его цену, и вызывающий код это видит. Вспомните массивы и списки: они ведут себя точно так же, потому что тоже ссылочные типы.

## Пример 8. Сравнение объектов

```csharp run
Item a = new Item { Name = "Хлеб" };
Item b = new Item { Name = "Хлеб" };
Item c = a;

Console.WriteLine(a == b);
Console.WriteLine(a == c);

class Item
{
    public string Name { get; set; } = "";
}
```
```output
False
True
```

Операция `==` для объектов класса проверяет, **один ли это объект**, а не одинаково ли у них содержимое. Объекты `a` и `b` равны по данным, но это два разных объекта. Переменные `a` и `c` ссылаются на один объект. (Строки - исключение: `==` для них сравнивает содержимое.)

**Попробуйте.** Добавьте в `Item` свойство `Quantity` и метод, который возвращает строку вида `"Хлеб x2"`. Создайте второй список и положите в него те же объекты: измените цену одного и посмотрите, что изменилось в обоих списках. Опишите класс `Student` со свойствами `Name` и `Grade` и найдите в списке студента с наибольшей оценкой.

## Точные правила

* Класс описывается словом `class`, именем с заглавной буквы и телом в фигурных скобках. В файле с инструкциями верхнего уровня описания типов стоят **после** всех инструкций.
* Объект создаётся выражением `new ИмяКласса()`. До `new` переменная типа класса не содержит объекта; использовать её нельзя (`CS0165`).
* Свойство записывается `public Тип Имя { get; set; }`. Слово `get` разрешает чтение, `set` - запись. Без модификатора `public` член класса доступен только внутри класса (`CS0122` при обращении снаружи).
* Начальное значение свойства: `= значение` после скобок. Не заданное значение: 0 для чисел, `false` для `bool`, `null` для ссылочных типов.
* Свойство типа `string` без начального значения вызывает предупреждение `CS8618` (nullable включён): задайте `= ""`.
* Метод без `static` вызывается у объекта (`item.Cost()`) и видит его свойства. Метод с `static` вызывается у типа или напрямую и не видит свойств объекта; вызов метода экземпляра через имя типа даёт ошибку `CS0120`.
* **Значимые типы** (`int`, `double`, `bool`, `decimal`) хранят значение: присваивание копирует его. **Ссылочные типы** (классы, массивы, `List<T>`, `Dictionary<K,V>`) хранят ссылку: присваивание копирует ссылку, объект остаётся один.
* `==` для объектов класса сравнивает ссылки, если класс не переопределил оператор. Строка - ссылочный тип, но с переопределённым `==`.
* Ссылка может быть пустой (`null`). Обращение к свойству через `null` приводит к `NullReferenceException`. Массив ссылочных элементов, созданный через `new Item[3]`, вначале заполнен `null`.
* Объект, переданный в метод, не копируется: метод видит и может менять тот же объект.
* Поле - переменная, объявленная прямо в классе (`private int count;`). В этом курсе мы используем свойства; поля и конструкторы подробно разбираются дальше.

## Типичные ошибки

**1. Класс описан раньше инструкций верхнего уровня.**

```csharp
class Item
{
}
Console.WriteLine("привет");
```

Компилятор: `error CS8803: Top-level statements must precede namespace and type declarations.` Перенесите описание класса в конец файла.

**2. Объект не создан через `new`.**

```csharp
Item item;
item.Name = "Хлеб";
```

Компилятор: `error CS0165: Use of unassigned local variable 'item'`. Переменная есть, но объекта нет. Напишите `Item item = new Item();`.

**3. Свойство без `public`.**

```csharp
Item item = new Item();
item.Name = "Хлеб";

class Item
{
    string Name { get; set; } = "";
}
```

Компилятор: `error CS0122: 'Item.Name' is inaccessible due to its protection level`. Без слова `public` член класса виден только внутри класса.

**4. Метод объекта вызван без объекта.**

```csharp
Console.WriteLine(Item.Cost());

class Item
{
    public int Price { get; set; }
    public int Cost() { return Price * 2; }
}
```

Компилятор: `error CS0120: An object reference is required for the non-static field, method, or property 'Item.Cost()'`. Метод без `static` работает с конкретным объектом: вызывайте его как `item.Cost()`.

**5. Строковое свойство без начального значения.**

```csharp
class Item
{
    public string Name { get; set; }
}
```

Предупреждение: `warning CS8618: Non-nullable property 'Name' must contain a non-null value when exiting constructor.` Программа запустится, но в этом курсе предупреждения считаются дефектом: напишите `= "";`.

**6. Пустая ссылка.**

```csharp
Item[] items = new Item[2];
Console.WriteLine(items[0].Name);

class Item
{
    public string Name { get; set; } = "";
}
```

Во время работы: `Unhandled exception. System.NullReferenceException: Object reference not set to an instance of an object.` Массив только зарезервировал два места и заполнил их пустыми ссылками; объекты нужно создать: `items[0] = new Item();`.

**7. Ожидание копии при присваивании.** После `Item b = a;` изменение `b.Price` меняет и `a.Price`. Если нужен независимый объект, создайте второй через `new` и перенесите значения свойств.

**8. Сравнение содержимого через `==`.** Два объекта с одинаковыми свойствами не равны по `==`: оператор сравнивает ссылки. Сравнивайте нужные свойства: `a.Name == b.Name`.

## Итоги

* Класс - описание типа, объект - его экземпляр, создаваемый через `new`.
* Данные объекта - свойства (`public Тип Имя { get; set; }`), поведение - методы без `static`.
* Описание класса стоит после инструкций верхнего уровня.
* Классы - ссылочные типы: присваивание и передача в метод копируют ссылку, а не объект.
* `List<Item>` хранит набор объектов; `==` сравнивает ссылки.

Теперь у вас есть всё, чтобы собрать небольшую программу из нескольких частей: [Мини-проект: бюджет](lesson:csharp.from-zero.mini-project).

## Для тех, кто уже программирует

* Класс в C# - ссылочный тип, как в Java; структуры (`struct`) и записи (`record`) отложены. Для сравнения по значению у классов нужно переопределять `Equals` или использовать `record`.
* Свойство `{ get; set; }` - то, что в Java делают поля, геттеры и сеттеры, а в Python - `@property`. Компилятор сам создаёт скрытое поле.
* Конструкторы существуют (`public Item(string name) { ... }`), но здесь заменены инициализатором объекта `new Item { Name = "..." }`.
* Модификатор доступа по умолчанию у члена класса - `private`, а у самого класса верхнего уровня - `internal`. Многие по привычке из Python или JavaScript забывают `public`.
* С включённым nullable `string Name` без значения - предупреждение; в Kotlin аналог - обязательная инициализация. В Java такой проверки нет.
* Методы без `static` получают неявную ссылку `this`, как в Java, но не передают её явно, как `self` в Python.
* Описания классов в файле с инструкциями верхнего уровня идут после них; внутри `class Program { static void Main() }` порядок не важен.
* Присваивание объекта - копирование ссылки (как в Java и JavaScript), а `int` копируется по значению.

## Что скрывается за `{ get; set; }`

Это необязательный раздел: для заданий он не нужен.

Запись `public int Price { get; set; }` - сокращение. Компилятор создаёт скрытое поле, где хранится число, и два метода: один возвращает это поле (`get`), другой записывает в него (`set`). Когда вы пишете `item.Price = 5`, вызывается метод записи. Поэтому позже свойство можно усложнить, не меняя код, который им пользуется: например, в `set` проверять, что цена не отрицательна, и бросать исключение, как в уроке про исключения. С полем так сделать нельзя: проверка потребовала бы менять все места использования.

Ссылочные объекты живут в **куче** (*heap*), а ссылка на объект лежит в локальной переменной. Когда на объект не остаётся ни одной ссылки, **сборщик мусора** освобождает его память: вручную память освобождать не нужно.
