## Зачем превращать текст в число

В прошлом уроке вы прочитали из ввода две строки, `3` и `4`, и получили `34`: прочитанное - текст, а у текста `+` склеивает. Чтобы посчитать сумму, строки нужно превратить в числа. Эту операцию называют **разбором** (parse): компилятор читает символы и строит по ним число.

Для каждого числового типа есть свой метод разбора:

* `int.Parse(текст)` - целое число;
* `double.Parse(текст)` - дробное число для измерений;
* `decimal.Parse(текст)` - дробное число для денег.

Выбирайте тип по смыслу данных так же, как при объявлении переменной: количество - `int`, измерение - `double`, цена - `decimal`.

## Одна новая идея: разбор может не получиться

Метод `Parse` ожидает, что текст действительно записывает число нужного типа. Если это не так (буквы, пустая строка, дробь для `int`), программа останавливается с ошибкой **`FormatException`** («неверный формат»). Пока считайте, что данные во вводе правильные. Как обрабатывать неверные данные без остановки, вы узнаете в уроке про исключения.

## Пример 1. int.Parse

```csharp run
string text = "41";
int number = int.Parse(text);
Console.WriteLine(number + 1);
Console.WriteLine(text + 1);

string a = "3";
string b = "4";
Console.WriteLine(a + b);
Console.WriteLine(int.Parse(a) + int.Parse(b));
```
```output
42
411
34
7
```

Разбор:

* `int.Parse(text)` берёт текст `41` и возвращает число 41. С числом `number + 1` - это сложение: 42;
* `text + 1` - текст остаётся текстом, к нему приклеили `1`: `411`;
* для `a` и `b` то же самое: без `Parse` получается склейка `34`, с `Parse` - сумма `7`.

## Пример 2. double и decimal

```csharp run
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;

double height = double.Parse("1.75");
decimal price = decimal.Parse("19.90");
Console.WriteLine(height * 2);
Console.WriteLine(price * 3);
Console.WriteLine(int.Parse("7") / 2);
Console.WriteLine(double.Parse("7") / 2);
```
```output
3.5
59.70
3
3.5
```

Разбор:

* строки `using System.Globalization;` и `CultureInfo.CurrentCulture = ...` из урока про дробные числа здесь обязательны: от них зависит, как `Parse` читает точку. С ними `1.75` читается как 1,75 на любой системе. Без них на системе с русскими настройками `double.Parse("1.75")` может остановить программу;
* `decimal.Parse("19.90")` сохраняет два знака, поэтому `price * 3` печатается `59.70`;
* `int.Parse("7") / 2` - деление целых, `3`. `double.Parse("7") / 2` - деление дробных, `3.5`: тип результата зависит от того, во что превратили текст.

## Пример 3. Ввод и Parse вместе

Ввод:

```
12
5
```

```csharp
int width = int.Parse(Console.ReadLine() ?? "");
int height = int.Parse(Console.ReadLine() ?? "");
Console.WriteLine($"Площадь: {width * height}");
Console.WriteLine($"Периметр: {2 * (width + height)}");
```

Вывод:

```
Площадь: 60
Периметр: 34
```

Запись `int.Parse(Console.ReadLine() ?? "")` читается изнутри: сначала `ReadLine` берёт строку, `??` защищает от `null`, `Parse` делает из текста число. Результат сразу кладётся в переменную типа `int`.

## Пример 4. Когда текст не число

```csharp
int n = int.Parse("3.5");
```

Программа соберётся, но при запуске остановится: `Unhandled exception. System.FormatException: The input string '3.5' was not in a correct format.` Для `int` дробная запись недопустима. Нужно либо `double.Parse("3.5")`, либо `decimal.Parse("3.5")`.

**Попробуйте.** Напишите программу, которая читает цену (`decimal`) и скидку в процентах (`int`) и печатает цену после скидки с двумя знаками. Подсказка: цена умножить на (100 - скидка) и разделить на 100. Проверьте на 200 и 15: ответ 170.00.

## Точные правила

* **`int.Parse(string)`**, **`double.Parse(string)`**, **`decimal.Parse(string)`** возвращают число соответствующего типа.
* Пробелы в начале и в конце текста допустимы (`int.Parse(" 42 ")` даёт 42); знак `+` или `-` перед числом допустим. Пробелы внутри (`4 2`), буквы (`12abc`) и пустая строка недопустимы.
* Для `int` дробная часть запрещена: `"3.5"` - `FormatException`. Запись, выходящая за диапазон `int`, например `99999999999`, приводит к `OverflowException`.
* Дробные числа читаются по текущей культуре. После `CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;` разделителем дробной части служит точка.
* При этой культуре запятая в `double.Parse` и `decimal.Parse` трактуется как разделитель тысяч: `double.Parse("2,5")` даёт **25**, а не 2,5. Ошибки при этом нет, поэтому в данных используйте только точку.
* Тип результата определяет арифметику: `int.Parse("7") / 2` равно `3`, `double.Parse("7") / 2` равно `3.5`.
* Если `Parse` принимает `null`, компилятор предупредит (`warning CS8604`). Поэтому всегда `int.Parse(Console.ReadLine() ?? "")`.
* Прочитанная переменная типа `string` не превращается в число сама: `int n = Console.ReadLine() ?? "";` даёт `error CS0029`.

## Типичные ошибки

**1. Забыли Parse: сложение превратилось в склейку.**

```csharp
string a = Console.ReadLine() ?? "";
string b = Console.ReadLine() ?? "";
Console.WriteLine(a + b);
```

Для ввода `3` и `4` напечатается `34`. Если ожидали `7`, превратите строки в числа.

**2. Присвоили строку числовой переменной.**

```csharp
int n = Console.ReadLine() ?? "";
```

Компилятор: `error CS0029: Cannot implicitly convert type 'string' to 'int'`. Нужен `int.Parse(...)`.

**3. Parse без `?? ""`.**

```csharp
int n = int.Parse(Console.ReadLine());
```

Компилятор: `warning CS8604: Possible null reference argument for parameter 's' in 'int int.Parse(string s)'`. Допишите `?? ""` внутри скобок: `int.Parse(Console.ReadLine() ?? "")`.

**4. int.Parse для дробной записи.**

```csharp
int n = int.Parse("3.5");
```

Во время работы: `System.FormatException: The input string '3.5' was not in a correct format`. Если во вводе может быть дробь, выбирайте `double` или `decimal`.

**5. Пустая или лишняя строка.** Если ввод содержит меньше строк, чем вызовов `ReadLine`, последние вызовы вернут `null`, `??` даст `""`, а `Parse("")` - `FormatException`. Число вызовов должно соответствовать числу строк ввода.

**6. Запятая вместо точки.** `double.Parse("2,5")` при инвариантной культуре даст 25 и не сообщит об ошибке. Для проверки ввода всегда смотрите на запись числа: в тестах и условиях курса дробная часть отделяется точкой.

**7. Нет строки с культурой.** Без `CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;` на системе с русскими настройками `double.Parse("2.5")` может остановить программу, а вывод дробных чисел будет с запятой. Ставьте эти строки первыми в программе, где есть дробные числа.

**8. Не тот тип.** `double` для цены даёт ошибки округления на копейках (`0.1 + 0.2`), а `int` не вместит дробь. Деньги - `decimal`, количество - `int`.

## Итоги

* `ReadLine` возвращает текст; чтобы считать, текст нужно превратить в число.
* `int.Parse`, `double.Parse`, `decimal.Parse` разбирают целое, дробное и денежное значения.
* Привычная запись: `int.Parse(Console.ReadLine() ?? "")`.
* Если текст не подходит, будет `FormatException`; для дробных чисел помните про строки с культурой в начале программы.
* Тип выбирайте по смыслу: количество - `int`, измерение - `double`, деньги - `decimal`.

Теперь программа умеет получать числа. Следующий шаг - принимать решения на основе чисел: [Сравнения и логика](lesson:csharp.from-zero.comparison-and-logic).

## Для тех, кто уже программирует

* `int.Parse`, `double.Parse`, `decimal.Parse` - статические методы типов; аналоги - `Integer.parseInt` и `Double.parseDouble` в Java, `int()` и `float()` в Python, `Number()` и `parseInt` в JavaScript. Неверный формат бросает исключение, а не возвращает `NaN`.
* Без аргумента культуры используется `CultureInfo.CurrentCulture`. Для данных, которые должны читаться одинаково на любой машине, лучше явный вызов `double.Parse(text, CultureInfo.InvariantCulture)`; в курсе для краткости культура задана один раз в начале программы.
* Разбор допускает пробелы по краям и знак; для `double` и `decimal` разрешены тысячи (`1,234.5` по инвариантной культуре) - поэтому `"2,5"` даёт 25.
* Безопасный вариант без исключения - `int.TryParse(text, out int value)`; он возвращает `bool` и подробно разобран в уроке об исключениях.
* `Parse` на пустой строке бросает `FormatException`, на `null` - `ArgumentNullException`; из-за аннотаций nullable компилятор предупреждает заранее.
* Вызовы `Parse` выполняются на каждый запуск; если разбор повторяется в цикле на горячем пути, обычно используют `TryParse` или перегрузки со `ReadOnlySpan<char>`. Для заданий курса это не нужно.

## Что происходит внутри Parse

Это необязательный раздел: для заданий он не нужен.

`int.Parse` проходит по символам строки: пропускает ведущие пробелы, читает необязательный знак, затем цифры, накапливая значение `result = result * 10 + цифра`, и проверяет, что оно не вышло за пределы `int` (иначе `OverflowException`). Если встретился символ, не подходящий под правила, метод бросает `FormatException`. Для `decimal` и `double` разбор сложнее: учитывается разделитель дробной части и тысяч из текущей культуры, а также показатель степени у `double` (`1e3`).

Из-за зависимости от культуры одна и та же строка может по-разному читаться на разных компьютерах. Поэтому форматы обмена данными (JSON, CSV для программ, сетевые протоколы) почти всегда фиксируют инвариантную культуру. Для пользовательского ввода, наоборот, иногда нужна культура пользователя: тогда в программе оставляют `CurrentCulture` по умолчанию.
