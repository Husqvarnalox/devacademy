## Зачем нужны циклы

Многие задачи состоят из повторения: просуммировать все покупки в чеке, пересчитать строки ввода, повторять запрос, пока человек не ответит правильно. Писать одну и ту же команду сто раз нельзя, да и неизвестно заранее, сколько повторений потребуется. Для этого служит **цикл**: фрагмент программы, который выполняется снова и снова. Первый цикл C# - **`while`** («пока»).

## Одна новая идея: условие проверяется перед каждым проходом

```csharp
while (условие)
{
    // тело цикла
}
```

Цикл работает так:

1. Проверяется условие (выражение типа `bool`, как в `if`).
2. Если оно истинно, выполняется **тело** - команды в фигурных скобках, и цикл возвращается к шагу 1.
3. Если оно ложно, тело пропускается и программа идёт дальше, после закрывающей `}`.

Один проход тела называют **итерацией**. Чтобы цикл когда-нибудь закончился, тело должно менять что-то, от чего зависит условие. Обычно в цикле участвуют три вещи:

* **счётчик** - переменная, которая считает проходы или шаги (`int i = 1;` ... `i++`);
* **накопитель** - переменная, в которую на каждом проходе добавляется результат (`total += price;`);
* **условие** - когда продолжать.

Переменные для них объявляются **до** цикла, потому что переменная, объявленная в теле, живёт только до его конца.

<!-- section: examples -->
## Пример 1. Счётчик

```csharp run
int i = 1;
while (i <= 3)
{
    Console.WriteLine($"Шаг {i}");
    i++;
}
Console.WriteLine("Готово");
```
```output
Шаг 1
Шаг 2
Шаг 3
Готово
```

Разбор:

* `int i = 1;` - начальное значение счётчика;
* `i <= 3` проверяется перед каждым проходом. При `i` равном 1, 2, 3 условие истинно; когда `i++` делает его равным 4, условие ложно и цикл завершается;
* `i++` в конце тела - то самое изменение, без которого условие навсегда осталось бы истинным.

## Пример 2. Накопитель: пока не хватит

```csharp run
int savings = 0;
int months = 0;
while (savings < 5000)
{
    savings += 1500;
    months++;
}
Console.WriteLine($"Месяцев: {months}, накоплено: {savings}");
```
```output
Месяцев: 4, накоплено: 6000
```

Заранее неизвестно, сколько месяцев понадобится, поэтому счётчик месяцев не участвует в условии: цикл выполняется, пока накопленное меньше 5000. После трёх проходов накоплено 4500 (меньше 5000), после четвёртого 6000, и условие становится ложным.

## Пример 3. Цикл может не выполниться ни разу

```csharp run
int n = 10;
while (n < 5)
{
    Console.WriteLine("Эта строка не напечатается");
    n++;
}
Console.WriteLine($"n = {n}");
```
```output
n = 10
```

Условие проверяется до тела. Если оно ложно с самого начала, тело не выполняется вообще.

## Пример 4. Деление пополам

```csharp run
int n = 100;
int steps = 0;
while (n > 1)
{
    n /= 2;
    steps++;
}
Console.WriteLine($"Шагов: {steps}, осталось: {n}");
```
```output
Шагов: 6, осталось: 1
```

Значение `n` проходит путь 100, 50, 25, 12, 6, 3, 1 (целочисленное деление отбрасывает остаток). Это шесть делений.

## Пример 5. Чтение ввода до конца

Читать данные можно, пока они не закончились. Вспомните урок о вводе: когда строк больше нет, `ReadLine` возвращает `null`. Значит, условие цикла - «пока прочитанная строка не `null`».

Ввод:

```
120
80
300
```

```csharp
int total = 0;
int count = 0;
string? line = Console.ReadLine();
while (line != null)
{
    total += int.Parse(line);
    count++;
    line = Console.ReadLine();
}
Console.WriteLine($"Покупок: {count}, сумма: {total}");
```

Вывод:

```
Покупок: 3, сумма: 500
```

Разбор:

* первая строка читается **до** цикла, следующая - **в конце тела**. Так условие всегда проверяет только что прочитанное;
* здесь нужен тип `string?` и сравнение с `null`: запись `?? ""` из прошлого урока заменила бы `null` пустой строкой, и признак конца пропал бы;
* внутри цикла компилятор знает, что `line` не `null` (иначе тело бы не выполнялось), поэтому `int.Parse(line)` не вызывает предупреждения.

**Попробуйте.** В примере 1 замените `<= 3` на `< 3` и предскажите вывод. В примере 2 замените 5000 на 1000: сколько месяцев будет теперь? Для примера 5 подумайте, что напечатает программа на пустом вводе.

## Точные правила

* Синтаксис: `while (условие) { ... }`. Условие в круглых скобках и всегда типа `bool`.
* Условие проверяется **перед** каждой итерацией; тело может не выполниться ни разу.
* Если условие не становится ложным, цикл **бесконечный**: программа зависает и её приходится прерывать. Каждый проход тела должен приближать условие к ложному значению.
* Переменная, объявленная в теле, создаётся заново на каждой итерации и недоступна после `}`. Счётчики и накопители объявляют до цикла.
* Общая схема чтения до конца ввода: `string? line = Console.ReadLine(); while (line != null) { ...; line = Console.ReadLine(); }`. Чтение в конце тела обязательно, иначе строка не меняется и цикл не заканчивается.
* Сразу после условия нельзя ставить `;`: `while (x < 3);` - пустое тело (`CS0642`), цикл бесконечный.
* Скобки `{ }` в курсе пишут всегда. Без них телом считается только одна следующая команда.

## Типичные ошибки

**1. Забыли изменить переменную в условии.**

```csharp
int i = 1;
while (i <= 3)
{
    Console.WriteLine(i);
}
```

Компилятор молчит, но программа печатает `1` бесконечно: `i` не меняется, условие вечно истинно. Добавьте `i++` в тело. Перед запуском цикла полезно спросить себя: «что в теле приближает условие к ложному?»

**2. Точка с запятой после условия.**

```csharp
int i = 0;
while (i < 3);
{
    i++;
}
```

Компилятор: `warning CS0642: Possible mistaken empty statement`. Цикл `while (i < 3);` имеет пустое тело и бесконечен, а блок с `i++` стоит после него и недостижим. Уберите `;`.

**3. Присваивание вместо сравнения.**

```csharp
int i = 0;
while (i = 3)
{
    i++;
}
```

Компилятор: `error CS0029: Cannot implicitly convert type 'int' to 'bool'`. Условие должно быть логическим: `i == 3` или `i < 3`.

**4. Переменная из тела недоступна после цикла.**

```csharp
int i = 0;
while (i < 3)
{
    int square = i * i;
    i++;
}
Console.WriteLine(square);
```

Компилятор: `error CS0103: The name 'square' does not exist in the current context`. Объявите `square` до цикла.

**5. Условие с `?? ""` никогда не завершится.**

```csharp
string line = Console.ReadLine() ?? "";
while (line != null)
{
    line = Console.ReadLine() ?? "";
}
```

Когда ввод закончился, `ReadLine` возвращает `null`, а `?? ""` превращает его в `""`. Строка `""` не равна `null`, и цикл продолжается вечно. Для чтения до конца ввода используйте `string?` без `??`.

**6. Нельзя читать из строки после конца ввода.**

```csharp
string? line = Console.ReadLine();
while (line != null)
{
    line = Console.ReadLine();
}
Console.WriteLine(line.Length);
```

Компилятор предупреждает: `warning CS8602: Dereference of a possibly null reference.` Во время работы, после завершения цикла, `line` как раз равна `null`, и обращение к `Length` приводит к `System.NullReferenceException`. Работайте со строкой внутри цикла.

**7. Ошибка на единицу.** Условие `i < 3` даёт три прохода при старте с 0 и два прохода при старте с 1; `i <= 3` - наоборот. Проверяйте цикл на малых значениях: что происходит при первом проходе и при последнем?

**8. Две `ReadLine` в одном проходе.** Если тело читает строку и ещё раз вызывает `ReadLine` для другой цели, то одна из строк пропадает. Каждый вызов забирает новую строку ввода.

## Итоги

* `while (условие) { ... }` повторяет тело, пока условие истинно; проверка идёт перед каждым проходом.
* Тело должно менять то, от чего зависит условие, иначе цикл бесконечный.
* Счётчик и накопитель объявляют до цикла.
* Чтение до конца ввода: первая строка до цикла, следующая в конце тела, условие `line != null`, тип `string?`.
* Не ставьте `;` после условия.

Когда число повторений известно заранее, запись проще: [Цикл for](lesson:csharp.from-zero.for-loop).

## Для тех, кто уже программирует

* `while` в C# такой же, как в Java, C и JavaScript: условие в скобках, обязательно `bool` (никакого `while (n)` для числа). Цикл с проверкой после тела тоже есть: `do { ... } while (условие);`, в курсе он не используется.
* Распространённая идиома чтения до конца ввода из C-семейства `while ((line = Console.ReadLine()) != null)` в C# тоже работает (присваивание - выражение), но в курсе чтение вынесено в отдельные строки ради ясности.
* `Console.ReadLine()` возвращает `null` в конце ввода; в Python для этого `input()` бросает `EOFError`, в Go сканер возвращает `false`. С включёнными nullable-аннотациями компилятор C# напоминает о `null` предупреждением.
* Для бесконечного цикла пишут `while (true)` и выходят через `break` (следующие уроки); в серверных программах так и делается.
* Рядом есть `foreach` для обхода коллекций (урок о массивах) и `for` (следующий урок).
* Область видимости блочная, как в Java: переменная из тела недоступна снаружи, и имя из внешней области нельзя объявить заново (`CS0136`).

## Как цикл выглядит для процессора

Это необязательный раздел: для заданий он не нужен.

Компилятор превращает `while` в условные переходы: метка в начале, проверка условия, переход к концу при ложном значении, тело, безусловный переход обратно к началу. Никакого «встроенного повторения» в процессоре нет, есть только переходы назад. Поэтому бесконечный цикл - это просто переход, который всегда возвращается.

Среда выполнения умеет оптимизировать цикл: выносить за его пределы вычисления, которые не меняются, или заменять части итераций более широкими операциями. Для вас это означает, что писать нужно в первую очередь понятный цикл, а ускорением занимается компилятор.
