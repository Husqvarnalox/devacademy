## Зачем нужны условия

До сих пор программа выполняла команды по порядку, сверху вниз, всегда одни и те же. Но настоящие задачи требуют выбора: «если хватает денег, продать, иначе сообщить об этом», «если оценка выше 80, поставить отлично». Для выбора есть инструкция **`if`** («если»), а также ветки **`else`** («иначе») и **`else if`** («иначе если»).

Каждая ветка записывается блоком: командами в фигурных скобках `{ }`. Блок выполняется целиком или пропускается целиком.

## Одна новая идея: цепочка проверяет сверху вниз и берёт первую подходящую

```csharp
if (условие1)
{
    // команды, если условие1 истинно
}
else if (условие2)
{
    // команды, если условие1 ложно, а условие2 истинно
}
else
{
    // команды, если все условия выше ложны
}
```

Условия проверяются по порядку. Как только какое-то оказалось истинным, выполняется его блок, а все остальные ветки цепочки **пропускаются** - даже если их условия тоже были бы истинными. Поэтому порядок веток важен. Ветка `else` не имеет условия и ловит всё, что не подошло раньше.

<!-- section: examples -->
## Пример 1. if, else if, else

```csharp run
int temperature = 5;
if (temperature < 0)
{
    Console.WriteLine("Мороз");
}
else if (temperature < 15)
{
    Console.WriteLine("Прохладно");
}
else
{
    Console.WriteLine("Тепло");
}
```
```output
Прохладно
```

Разбор:

* условие в круглых скобках после `if` - выражение типа `bool` (прошлый урок);
* `temperature < 0` ложно, переходим дальше. `temperature < 15` истинно - выполняется блок `Прохладно`, остальное пропускается;
* в ветке `else if (temperature < 15)` уже известно, что `temperature >= 0`, поэтому писать `temperature >= 0 && temperature < 15` не нужно. Так цепочка избавляет от лишних проверок.

## Пример 2. Блок из нескольких команд

```csharp run
int balance = 300;
int price = 450;
if (balance >= price)
{
    balance = balance - price;
    Console.WriteLine("Покупка выполнена");
}
else
{
    Console.WriteLine("Не хватает денег");
    Console.WriteLine($"Нужно ещё: {price - balance}");
}
Console.WriteLine($"Остаток: {balance}");
```
```output
Не хватает денег
Нужно ещё: 150
Остаток: 300
```

В блоке может быть сколько угодно команд. Последняя команда стоит после всей цепочки и выполняется всегда, в обоих случаях. Попробуйте поменять `balance` на 500: сработает первая ветка, и остаток станет 50.

## Пример 3. Отдельные if и цепочка

```csharp run
int points = 85;
if (points >= 50)
{
    Console.WriteLine("Зачёт");
}
if (points >= 80)
{
    Console.WriteLine("Отлично");
}

int score = 85;
if (score >= 60)
{
    Console.WriteLine("C");
}
else if (score >= 80)
{
    Console.WriteLine("B");
}
```
```output
Зачёт
Отлично
C
```

Первые два `if` - независимые проверки, оба сработали. Во втором фрагменте `else if` продолжает цепочку, а потому до проверки `score >= 80` дело не доходит: печатается только `C`. Чтобы получить `B`, поменяйте ветки местами: сначала узкое условие (`score >= 80`), потом широкое. Это самая частая логическая ошибка: широкое условие, поставленное первым, «перекрывает» узкие.

## Пример 4. Ввод и условия вместе

Ввод:

```
1900
```

```csharp
int year = int.Parse(Console.ReadLine() ?? "");
if (year % 400 == 0 || (year % 4 == 0 && year % 100 != 0))
{
    Console.WriteLine("високосный");
}
else
{
    Console.WriteLine("обычный");
}
```

Вывод:

```
обычный
```

Год високосный, если делится на 400, либо делится на 4, но не на 100. Условие объединяет остатки `%` и логические операторы из прошлого урока. 1900 делится на 4 и на 100, но не на 400, поэтому обычный.

**Попробуйте.** Напишите программу, которая читает целое число и печатает `положительное`, `отрицательное` или `ноль`. Проверьте её на значениях -1, 0, 1. Затем уберите `else` в конце и посмотрите, что изменится для нуля.

## Точные правила

* Синтаксис: `if (условие) { ... }`, затем необязательные `else if (условие) { ... }` и необязательный `else { ... }`. Условие всегда в круглых скобках и всегда типа `bool`.
* В цепочке выполняется не более одного блока: первый, чьё условие истинно. Если ни одно не истинно, выполняется `else` (при его наличии).
* Блок `{ ... }` объединяет несколько команд в одну. Если команда одна, скобки можно опустить, но в курсе их всегда пишут: так не ломается код при добавлении второй команды.
* Переменная, объявленная в блоке, видна только внутри него и исчезает на закрывающей скобке.
* После `else` не может быть условия: `else (x < 3)` - ошибка; для проверки нужен `else if`.
* Часть `else` относится к ближайшему `if` выше.
* Сразу после условия нельзя ставить `;`: `if (x > 3);` означает «если x больше 3, ничего не делать» (предупреждение `CS0642`), а следующий блок выполняется всегда.
* Если переменная должна получить значение в каждой ветке, а ветки не покрывают все случаи, то после цепочки без `else` компилятор считает значение не присвоенным (`CS0165`).
* Условия можно вкладывать: `if` внутри блока другого `if`. Пока хватает `&&` и `else if`, вложения лучше избегать.

## Типичные ошибки

**1. Точка с запятой после условия.**

```csharp
int x = 5;
if (x > 3);
{
    Console.WriteLine("big");
}
```

Компилятор: `warning CS0642: Possible mistaken empty statement`. Блок после `;` выполняется всегда, при любом `x`. Уберите `;`.

**2. Нет круглых скобок вокруг условия.**

```csharp
if x > 3 { Console.WriteLine("b"); }
```

Компилятор: `error CS1003: Syntax error, '(' expected` и `error CS1026: ) expected`. Условие пишется в скобках: `if (x > 3)`.

**3. Условие у `else`.**

```csharp
if (x > 3) { Console.WriteLine("a"); }
else (x < 3) { Console.WriteLine("b"); }
```

Компилятор сообщает об ошибках в строке с `else`: у ветки `else` условия не бывает. Нужен `else if (x < 3)` или `else` без условия.

**4. Без фигурных скобок выполняется только одна команда.**

```csharp
if (x > 3)
    Console.WriteLine("a");
    Console.WriteLine("b");
```

Вторая команда стоит вне `if` и напечатается всегда, хотя отступ создаёт впечатление, что она внутри. Всегда ставьте скобки.

**5. Широкое условие первым.** В цепочке `if (score >= 60) ... else if (score >= 80)` вторая ветка недостижима. Идите от самого узкого условия к широкому или делайте условия непересекающимися.

**6. Ошибка на границе.** Различайте `<` и `<=`: «меньше 18» и «не больше 18» отличаются на возрасте 18. Для каждой границы проверяйте значение на границе и рядом с ней (17, 18, 19).

**7. Присваивание вместо сравнения.** `if (x = 5)` не скомпилируется: `error CS0029: Cannot implicitly convert type 'int' to 'bool'`. Нужно `==`.

**8. Переменная не получила значения во всех ветках.**

```csharp
string kind;
if (n > 0) { kind = "положительное"; }
else if (n < 0) { kind = "отрицательное"; }
Console.WriteLine(kind);
```

Компилятор: `error CS0165: Use of unassigned local variable 'kind'`: при `n == 0` ни одна ветка не сработала. Добавьте `else` или задайте значение при объявлении.

## Итоги

* `if (условие) { ... }` выполняет блок, когда условие (тип `bool`) истинно.
* `else` - ветка «иначе», `else if` - ещё одна проверка в цепочке. Выполняется ровно одна ветка: первая подходящая.
* Порядок условий важен: сначала узкие, потом широкие, либо непересекающиеся диапазоны.
* Отдельные `if` не связаны между собой, каждый проверяется независимо.
* Не ставьте `;` после условия и всегда пишите фигурные скобки.

Если веток много и все они сравнивают одно значение с набором вариантов, удобнее другая инструкция: [Выбор по значению: switch](lesson:csharp.from-zero.switch).

## Для тех, кто уже программирует

* Синтаксис как в Java и C: условие в скобках, блок в `{}`. Условие обязано быть `bool`: `if (n)` и `if (str)` не компилируются, нет приведения к истинности как в C, JavaScript и Python.
* Оператор `?:` (`a ? b : c`) есть, но в курсе не используется; про `switch`-выражение - следующий урок.
* Блок создаёт область видимости: переменная из блока не видна снаружи, а имя, уже занятое снаружи, во вложенном блоке заново объявить нельзя (`CS0136`).
* `else if` не отдельная конструкция, а `else`, за которым идёт новая `if`-инструкция. Отсюда «висячий else»: он относится к ближайшему `if`.
* Анализ потока (definite assignment) требует присваивания переменной во всех ветках перед чтением: компилятор понимает `if / else`, но не логику вашего домена (например, что остальные значения невозможны).
* Для выбора по паттернам есть `is`-выражения (`if (obj is string s)`), в курсе не рассматриваются.
* Однострочная форма без скобок (`if (x) Console.WriteLine("a");`) допустима, но при добавлении второй команды легко получить ошибку из-за обманчивого отступа, поэтому в курсе скобки всегда.

## Как if превращается в код

Это необязательный раздел: для заданий он не нужен.

Компилятор превращает `if` в условные переходы. Для `if (c) { A } else { B }` строится такая схема: вычислить `c`; если ложно - перейти к метке `B`; выполнить `A`; перейти в конец; метка `B`: выполнить `B`; конец. Цепочка `else if` - это та же схема, где блок `B` сам является `if`. Поэтому проверки идут строго по порядку и остановка на первой истинной происходит естественно.

Процессор дополнительно пытается угадать, какая ветка выполнится (предсказание переходов), и заранее подготовить её команды. Для курса это не важно, но объясняет, почему в высоконагруженном коде иногда заменяют ветвления на арифметику. Для остальных программ ясность важнее: пишите условия так, чтобы их было легко прочитать.
