## Зачем читать ввод

До сих пор программа печатала только то, что вы вписали в её текст. Полезные программы получают данные снаружи: имя пользователя, количество, строку с товаром. Самый простой источник данных для консольной программы - **ввод** (стандартный поток ввода, stdin): текст, который набирает пользователь или который подаёт проверяющая система. В этом приложении вы пишете ввод в отдельном поле, а в тестах он задан заранее.

Чтение одной строки выполняет `Console.ReadLine()`. Каждый вызов берёт **следующую** строку ввода (без символа перевода строки в конце) и возвращает её как значение типа `string`.

## Одна новая идея: строки может не быть

Если вызвать `ReadLine` третий раз, а во вводе всего две строки, читать уже нечего. Тогда `ReadLine` возвращает особое значение **`null`** - «ничего, значения нет». Это не пустая строка `""` (строка без символов), а именно отсутствие значения. Поэтому тип результата `ReadLine` записывают как `string?`: «строка или `null`».

Компилятор следит за этим. Если положить `string?` в обычную `string`-переменную, он выдаст предупреждение. Принятый способ - оператор **`??`**: `a ?? b` означает «возьми `a`, а если там `null` - возьми `b`».

```csharp
string name = Console.ReadLine() ?? "";
```

Читается: «прочитать строку; если ввод закончился, использовать пустую строку». После этого `name` всегда настоящая строка, и с ней можно работать как с любой другой. Эту запись вы будете использовать для каждого чтения.

## Как подать ввод своей программе

1. Под редактором откройте вкладку **«Вывод»**.
2. Нажмите на строку **«Ввод программы (stdin)»**: под ней раскроется поле.
3. Впишите в поле весь ввод заранее: каждое значение на своей строке, потому что один вызов `Console.ReadLine()` читает одну строку. Например, для примера 1 впишите `Анна` на первой строке и `Казань` на второй.
4. Нажмите **«Запустить»**.

Программа не останавливается и не ждёт, пока вы что-то напечатаете: всё, что записано в поле, она получает сразу при запуске. Если поле пустое, ввод пустой (что тогда происходит, показано в примере 4). Введённый текст в вывод не попадает: после приглашения из примера 2 в выводе будет только то, что напечатала сама программа. Пока урок открыт, текст в поле остаётся, так что для следующего запуска достаточно поменять данные.

Кнопка **«Проверить решение»** это поле не использует: она запускает программу на вводе каждого теста по очереди.

## Пример 1. Две строки ввода

Примеры с вводом показаны без запуска: в них перед кодом указан ввод, а после - вывод.

Ввод:

```
Анна
Казань
```

```csharp
string name = Console.ReadLine() ?? "";
string city = Console.ReadLine() ?? "";
Console.WriteLine($"Здравствуйте, {name}!");
Console.WriteLine($"Ваш город: {city}");
Console.WriteLine($"Длина имени: {name.Length}");
```

Вывод:

```
Здравствуйте, Анна!
Ваш город: Казань
Длина имени: 4
```

Разбор:

* первый вызов `ReadLine` забирает строку `Анна`, второй - строку `Казань`: порядок чтения совпадает с порядком строк ввода;
* символ перевода строки в переменную не попадает: `name.Length` равно 4, а не 5;
* прочитанное - обычные строки, поэтому с ними работает интерполяция и `Length` из прошлого урока.

## Пример 2. Приглашение к вводу

Ввод:

```
Борис
```

```csharp
Console.Write("Как вас зовут? ");
string name = Console.ReadLine() ?? "";
Console.WriteLine($"Приятно познакомиться, {name}!");
```

Вывод:

```
Как вас зовут? Приятно познакомиться, Борис!
```

`Console.Write` печатает вопрос и остаётся в той же строке. При ручном вводе пользователь печатает ответ сразу после вопроса. Здесь ответ берётся из заранее заданного ввода и в вывод не попадает, поэтому приглашение и следующая команда оказываются в одной строке. Если проверка ожидает только результат, приглашения лучше не печатать: лишний текст в выводе считается ошибкой.

## Пример 3. Прочитанное - это текст

Ввод:

```
3
4
```

```csharp
string a = Console.ReadLine() ?? "";
string b = Console.ReadLine() ?? "";
Console.WriteLine(a + b);
```

Вывод:

```
34
```

Строка `"3"` - это текст из одного символа, а не число три. Для строк `+` склеивает, поэтому получилось `34`, а не `7`. Как превратить текст в число - тема следующего урока.

## Пример 4. Ввод закончился

Ввод пуст (ни одной строки).

```csharp
string name = Console.ReadLine() ?? "";
Console.WriteLine($"[{name}] {name.Length}");
```

Вывод:

```
[] 0
```

`ReadLine` вернул `null`, `??` заменил его на `""`. Программа не упала, а работает с пустой строкой длиной 0.

**Попробуйте.** Напишите программу, которая читает фамилию и имя и печатает их в порядке «имя фамилия». Затем запустите её с пустым вводом и убедитесь, что программа не падает, а печатает только пробел.

## Точные правила

* `Console.ReadLine()` читает символы до конца строки и возвращает их **без** перевода строки. Следующий вызов продолжает со следующей строки.
* Тип результата - `string?`. Значение `null` приходит, когда во вводе больше нет строк. Пустая строка в середине ввода даёт `""`, а не `null`.
* **`a ?? b`** вычисляется как `a`, если `a` не `null`, иначе как `b`. Для чтения строк запись `Console.ReadLine() ?? ""` - стандартная.
* Если присвоить результат `ReadLine` переменной типа `string` без `??`, компилятор выдаст `warning CS8600: Converting null literal or possible null value to non-nullable type`.
* Если объявить `string? line = Console.ReadLine();` и затем обратиться к `line.Length`, будет `warning CS8602: Dereference of a possibly null reference`. При пустом вводе такая программа остановится с `NullReferenceException`.
* Строка с вопросительным знаком у типа (`string?`) может содержать `null`, а без него (`string`) - нет. Для `int` и других числовых типов аналог записывается иначе, об этом - в курсе `csharp-first-steps`.
* `ReadLine` читает всю строку целиком, включая пробелы внутри и по краям. Разбивать строку на части вы научитесь позже.
* Прочитанное всегда `string`, даже если выглядит как число.

## Типичные ошибки

**1. Без `??`.**

```csharp
string name = Console.ReadLine();
Console.WriteLine(name);
```

Программа запустится, но компилятор предупредит: `warning CS8600: Converting null literal or possible null value to non-nullable type`. В этом курсе предупреждения исправляют так же, как ошибки. Допишите `?? ""`.

**2. Обращение к возможному null.**

```csharp
string? line = Console.ReadLine();
Console.WriteLine(line.Length);
```

Компилятор: `warning CS8602: Dereference of a possibly null reference`. Если ввод пуст, программа остановится с `NullReferenceException`. Используйте `string line = Console.ReadLine() ?? "";`.

**3. Читают числа как числа.**

```csharp
int n = Console.ReadLine() ?? "";
```

Компилятор: `error CS0029: Cannot implicitly convert type 'string' to 'int'`. Прочитанное - текст, число из него нужно получить отдельным шагом (следующий урок).

**4. Слишком много или слишком мало вызовов `ReadLine`.** Если ввод из двух строк, а читается одна, вторая строка просто не будет использована. Если читается три, третий вызов даст `null` и после `??` пустую строку. Считайте вызовы по числу строк ввода.

**5. Лишний текст в выводе.** Когда программа печатает приглашение вроде `Введите имя: `, оно попадёт в вывод и не совпадёт с ожидаемым. Печатайте только то, что указано в условии.

**6. Забыли `Console.` перед `ReadLine`.** `ReadLine()` без `Console.` даёт `error CS0103: The name 'ReadLine' does not exist in the current context`.

<!-- section: summary -->
## Итоги

* `Console.ReadLine()` читает следующую строку ввода без перевода строки.
* Когда ввод закончился, результат - `null`; тип результата `string?`.
* `Console.ReadLine() ?? ""` заменяет `null` пустой строкой, и переменная остаётся обычной `string`.
* Прочитанное - всегда текст: `"3" + "4"` это `"34"`.
* Предупреждения компилятора про null исправляют сразу.

## Для тех, кто уже программирует

* `string?` - аннотация nullable reference types (включены в проекте по умолчанию): для ссылочных типов `T` означает «не null», `T?` - «может быть null». Это проверка на этапе компиляции в виде предупреждений; на выполнение она не влияет.
* `a ?? b` - оператор null-объединения (аналог `??` в JavaScript и `or` для None в Python); есть также `??=`, `?.` и `?[]`.
* `Console.ReadLine()` возвращает `null` на конец потока (EOF), как `readLine()` в Java и `input()` с `EOFError` в Python. Пустая строка в середине ввода - `""`.
* Оператор подавления `!` (`line!`) здесь не используется: он скрывает предупреждение, а не решает проблему.
* Для чтения всего ввода есть `Console.In.ReadToEnd()`; в курсе читают построчно.
* Кодировка ввода и вывода консоли по умолчанию UTF-8 в современном .NET; кириллица читается и печатается как есть.

## Как устроен ввод

Это необязательный раздел: для заданий он не нужен.

Операционная система даёт каждому процессу три стандартных потока: ввод (stdin), вывод (stdout) и поток ошибок (stderr). `Console.ReadLine()` читает байты из stdin, декодирует их в символы по кодировке консоли и накапливает до перевода строки. Если поток закрыт и данных больше нет, читать нечего, и метод сообщает об этом значением `null`: так один и тот же код работает и с клавиатурой, и с файлом, и с заранее подготовленным вводом проверяющей системы.

Аннотации `string` и `string?` существуют только для компилятора: во время выполнения это один и тот же тип `System.String`. Анализатор nullable отслеживает, где значение могло стать `null`, и предупреждает, если вы обращаетесь к нему без проверки. Подробнее о ссылочных типах и `null` - в уроке [Значимые и ссылочные типы](lesson:csharp.first-steps.value-types-and-nullable).
