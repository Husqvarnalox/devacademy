## Зачем нужны дробные числа

Длина стола 1.2 метра, вес покупки 0.75 килограмма, цена 19.90 рубля, среднее арифметическое оценок 4.25. `int` для этого не подходит: он хранит только целые числа. В C# для чисел с дробной частью есть два основных типа, и они решают разные задачи:

* **`double`** - число с плавающей точкой. Для измерений и расчётов (длина, масса, температура, доля). Работает быстро, но хранит многие дроби **приближённо**;
* **`decimal`** - десятичное число с точным хранением десятичных дробей. Для денег.

## Одна новая идея: тип определяет точность

Компьютер хранит `double` в двоичном виде, а многие десятичные дроби в двоичной системе записать точно нельзя (как 1/3 нельзя точно записать десятичной дробью). Поэтому `0.1` внутри `double` - очень близкое к 0.1 число, но не равное ему, и в сумме `0.1 + 0.2` получается `0.30000000000000004`. Для температуры это не страшно, для денег - недопустимо: копейки не должны «теряться». Тип `decimal` хранит число в десятичной записи, поэтому `0.1m + 0.2m` равно ровно `0.3`.

Литерал с точкой, например `2.5`, имеет тип `double`. Чтобы получить `decimal`, к числу добавляют **суффикс** `m`: `19.90m`.

## Строка, которую нужно знать с этого урока

Способ записи дробных чисел зависит от региональных настроек (**культуры**) системы: в России принято писать `3,5`, в программировании и во многих других странах - `3.5`. Если оставить всё по умолчанию, одна и та же программа напечатает `3.5` на одном компьютере и `3,5` на другом, а проверка ожидает точку. Поэтому программы с дробными числами начинаются так:

```csharp
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;
```

Первая строка подключает пространство имён `System.Globalization` - раздел .NET, где лежит `CultureInfo`. Вторая выбирает **инвариантную культуру**: набор правил, не зависящий от страны, где десятичный разделитель - точка. Эти строки должны стоять в самом начале файла, перед остальными командами. Позже (урок о строках) вы увидите и вариант для одного вызова.

## Пример 1. double и decimal

```csharp run
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;

double length = 2.5;
double width = 1.2;
double area = length * width;
Console.WriteLine(area);

Console.WriteLine(0.1 + 0.2);
Console.WriteLine(0.1m + 0.2m);

decimal price = 120.50m;
int quantity = 4;
decimal total = price * quantity;
Console.WriteLine(total);
```
```output
3
0.30000000000000004
0.3
482.00
```

Разбор:

* `using System.Globalization;` и следующая строка - закрепление точки (см. выше);
* `double area = length * width;` - 2.5 умножить на 1.2: ровно 3, и `double` печатает его как `3`, без лишних знаков после точки;
* `0.1 + 0.2` для `double` даёт `0.30000000000000004`: это не ошибка C#, так устроены двоичные дроби во всех языках;
* `0.1m + 0.2m` для `decimal` даёт `0.3`;
* `price * quantity`: `decimal` и `int` можно умножать без приведения, результат - `decimal`. `482.00` печатается с двумя нулями, потому что в литерале `120.50m` два знака после точки; `decimal` помнит количество знаков.

## Пример 2. Целое деление и приведение к double

```csharp run
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;

int a = 7;
int b = 4;
Console.WriteLine(a / b);
Console.WriteLine((double)a / b);
double average = (double)(a + b) / 2;
Console.WriteLine(average);
```
```output
1
1.75
5.5
```

* `a / b` - деление двух `int`, дробная часть отброшена: `1`;
* `(double)a` - **приведение типа** (cast): записанный в скобках тип требует превратить значение в `double`. Теперь `(double)a / b` делит `double` на `int` и даёт `1.75`;
* в `(double)(a + b) / 2` сначала в скобках суммируются `int` (получается 11), затем сумма приводится к `double`, и деление на 2 уже дробное: `5.5`. Приведение выполняется **до** деления; если привести результат деления (`(double)(a / b)`), дробная часть уже потеряна.

## Пример 3. Из дроби в целое

```csharp run
double d = 3.99;
int whole = (int)d;
Console.WriteLine(whole);
Console.WriteLine((int)-3.99);
```
```output
3
-3
```

Приведение `double` к `int` **отбрасывает** дробную часть (в сторону нуля), а не округляет: `3.99` становится `3`. Компилятор требует явного `(int)`, потому что часть информации теряется: `int whole = d;` не скомпилируется.

**Попробуйте.** В примере 1 замените `0.1m + 0.2m` на `0.1 + 0.2m` и прочитайте сообщение. Затем уберите первые две строки (`using` и выбор культуры) и посмотрите, что напечатает программа на вашей системе: если у вас русские настройки, увидите запятую.

## Точные правила

* Литерал с десятичной точкой - `double`; с суффиксом `m` - `decimal`; без точки - `int`. Литерал `19.90` нельзя присвоить `decimal` без `m` (ошибка `CS0664`).
* `int` неявно превращается в `double` и `decimal` (`double x = 3;` допустимо). Обратное требует явного приведения `(int)`: иначе ошибка `CS0266`.
* Если в операции участвуют `int` и `double`, результат - `double`; `int` и `decimal` - `decimal`. **`double` и `decimal` в одном выражении смешивать нельзя**: ошибка `CS0019`.
* Если оба операнда `int`, деление целочисленное, и присваивание результата переменной `double` дробную часть не вернёт: `double r = 7 / 2;` даёт `3`.
* **Приведение** `(тип)значение` меняет тип значения. `(int)3.99` равно `3`: дробная часть отбрасывается.
* `double` печатается в самой короткой записи, которая однозначно возвращает то же число: `3`, `2.5`, `0.30000000000000004`.
* `decimal` хранит число знаков после точки и печатает их: `120.50m * 4` даёт `482.00`.
* `double` имеет около 15-17 значащих цифр точности; `decimal` - 28-29.
* **Культура.** `CultureInfo.CurrentCulture` определяет, как печатаются и читаются дробные числа. `CultureInfo.InvariantCulture` - независимые от региона правила с точкой. Присваивание `CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;` в начале программы влияет на весь последующий вывод и разбор в основном потоке. Чтобы не зависеть от настроек системы, эту строку ставят первой в программах с дробными числами.
* Равенство дробных `double` проверять через `==` ненадёжно (`0.1 + 0.2 == 0.3` ложно); об этом - в уроке о сравнениях.

## Типичные ошибки

**1. Литерал decimal без суффикса.**

```csharp
decimal p = 19.90;
```

Компилятор: `error CS0664: Literal of type double cannot be implicitly converted to type 'decimal'; use an 'M' suffix to create a literal of this type`. Напишите `19.90m`.

**2. Смешали double и decimal.**

```csharp
double x = 1.5;
decimal y = 2m;
Console.WriteLine(x + y);
```

Компилятор: `error CS0019: Operator '+' cannot be applied to operands of type 'double' and 'decimal'`. Выберите один тип для величины. Деньги - всегда `decimal`.

**3. Дробное значение в int.**

```csharp
int n = 3.9;
```

Компилятор: `error CS0266: Cannot implicitly convert type 'double' to 'int'. An explicit conversion exists (are you missing a cast?)`. Если вы осознанно хотите отбросить дробную часть, напишите `(int)3.9`.

**4. Деление int и присваивание double.**

```csharp
double r = 7 / 2;
Console.WriteLine(r);
```

Ошибки нет, напечатается `3`: деление выполнилось над `int` и только потом результат превратили в `double`. Приведите операнд до деления: `double r = 7 / 2.0;` или `(double)7 / 2`.

**5. Приведение результата деления, а не операнда.** `(double)(a / b)` не лучше, чем `a / b`: дробная часть уже потеряна. Пишите `(double)a / b`.

**6. Запятая вместо точки в программе.** `double x = 2,5;` не скомпилируется: в тексте программы разделитель всегда точка, независимо от региональных настроек.

**7. Программа печатает `3,5`.** Если вы пропустили строку `CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;`, на системе с русскими настройками вывод будет `3,5`, и проверка не пройдёт. Поставьте строку первой в файле, а `using System.Globalization;` ещё выше.

## Итоги

* `double` - дробное число для измерений, хранится приближённо; `decimal` - десятичное число для денег, хранится точно; литерал `decimal` пишется с суффиксом `m`.
* `int` превращается в `double`/`decimal` автоматически; обратно - только явным приведением `(int)`, которое отбрасывает дробную часть.
* Деление двух `int` целочисленное; чтобы получить дробный результат, приведите операнд до деления: `(double)a / b`.
* `double` и `decimal` в одном выражении смешивать нельзя.
* Программы с дробными числами начинаются строками `using System.Globalization;` и `CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;`, чтобы разделителем всегда была точка.

## Для тех, кто уже программирует

* `double` - IEEE 754 binary64, `float` - binary32 (литерал `1.5f`), `decimal` - 128-битный десятичный тип с масштабом (28-29 цифр), аналог `BigDecimal` в Java или `Decimal` в Python, но значимый тип и намного быстрее.
* Нет неявных преобразований из `double` в `decimal` и обратно; `int` -> `double` и `int` -> `decimal` неявные. Сужающие приведения только явные `(int)x`, они усекают к нулю, как в Java и C, а не округляют; для округления - `Math.Round`.
* `Math.Round(2.5)` по умолчанию округляет к ближайшему чётному (`2`), а не «от нуля», в отличие от школьных правил и `round` в JavaScript; поведение задаётся параметром `MidpointRounding`.
* `double.ToString()`, интерполяция и `Console.WriteLine` используют `CultureInfo.CurrentCulture`; в отличие от Java, где `Locale` нужен для `String.format`, а `Double.toString` всегда с точкой, в .NET зависимость есть и у простого вывода. Для данных, которые читает другая система, указывают `CultureInfo.InvariantCulture`.
* Деление `double` на ноль не бросает исключение: результат `Infinity` или `NaN`; `decimal` бросает `DivideByZeroException`.
* Экспоненциальная запись печатается для очень малых и больших `double`: `0.000001` выводится как `1E-06`.

## Как устроен double

Это необязательный раздел: для заданий он не нужен.

`double` занимает 64 бита: 1 бит знака, 11 бит порядка и 52 бита мантиссы. Число хранится как мантисса, умноженная на степень двойки, поэтому точно представимы только дроби со знаменателем-степенью двойки (0.5, 0.25, 0.375). Остальные, в том числе 0.1, округляются до ближайшего представимого значения. При печати .NET выбирает самую короткую запись, которая однозначно возвращает то же самое число; именно поэтому `0.1 + 0.2` показывается как `0.30000000000000004`: ближайший `double` к сумме не равен ближайшему `double` к 0.3.

`decimal` хранит целое число (96 бит) и степень десяти (от 0 до 28), на которую его делят. Поэтому `120.50m` это 12050 с масштабом 2, и результат умножения на 4 сохраняет масштаб 2 (`482.00`). Операции выполняются в десятичной системе, потому и сложение дробей вроде 0.1 и 0.2 точное. Цена за точность - скорость: `decimal` заметно медленнее `double`, но для денег это нормальная плата.

Про `CultureInfo`: класс описывает правила региона (разделитель дробной части, формат даты, порядок сортировки). `CurrentCulture` хранится отдельно для каждого потока; программа из одной команды верхнего уровня выполняется в одном (основном) потоке, поэтому присваивание в начале действует на все дальнейшие вызовы.
