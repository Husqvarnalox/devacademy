## Зачем нужны исключения

Программа почти всегда получает данные, за которыми не уследить: строку ввода с опечаткой, число ноль в знаменателе, индекс за границей массива. Когда код сталкивается с такой ситуацией, он не может продолжить работу, и среда выполнения создаёт **исключение** (*exception*) - объект с описанием проблемы. Если никто его не перехватил, программа останавливается и печатает сообщение вида `Unhandled exception. System.FormatException: ...`. Вы уже видели такие остановки в уроках про `Parse` и массивы.

Остановка - не всегда то, что нужно. Если из ста строк ввода одна испорчена, разумно пропустить её и обработать остальные. Для этого в C# есть два инструмента.

## Одна новая идея: ожидаемые сбои обрабатывают

Первый инструмент - блок **`try`/`catch`**: «попробуй выполнить этот код, а если возникнет исключение такого-то вида, выполни вот это». Второй - метод **`int.TryParse`**, который превращает текст в число и вместо исключения сообщает об успехе значением `bool`.

```csharp
try
{
    // код, который может завершиться исключением
}
catch (FormatException)
{
    // что делать, если случилось именно FormatException
}
```

Правило выбора такое:

* если сбой - **обычное, ожидаемое событие** (пользователь ввёл не число), проверяйте заранее или используйте `TryParse`;
* если сбой означает, что произошло что-то неправильное, и вы можете осмысленно отреагировать в конкретном месте, используйте `try`/`catch`;
* если исправить ситуацию в этом месте нельзя, не перехватывайте исключение: пусть программа остановится с понятным сообщением.

Третий инструмент, **`throw`**, работает в обратную сторону: ваш код сам создаёт исключение, когда ему передали недопустимые данные.

## Пример 1. Перехватываем деление на ноль

```csharp run
int total = 100;
int people = 0;

try
{
    Console.WriteLine(total / people);
    Console.WriteLine("после деления");
}
catch (DivideByZeroException)
{
    Console.WriteLine("На ноль делить нельзя");
}

Console.WriteLine("программа продолжает работу");
```
```output
На ноль делить нельзя
программа продолжает работу
```

Разбор:

* деление `total / people` создаёт исключение `DivideByZeroException`, потому что `people` равно нулю;
* строка `"после деления"` не печатается: выполнение прыгает из `try` сразу в подходящий `catch`;
* после блока `catch` программа идёт дальше обычным порядком.

## Пример 2. Сообщение об ошибке

```csharp run
try
{
    int value = int.Parse("абв");
    Console.WriteLine(value);
}
catch (FormatException e)
{
    Console.WriteLine("Не число: " + e.Message);
}
```
```output
Не число: The input string 'абв' was not in a correct format.
```

После типа в `catch` можно написать имя переменной (`e`). Через неё доступны данные исключения, в первую очередь `e.Message` - текст сообщения. Обратите внимание, что текст сообщения написан на английском и принадлежит .NET; показывать его конечному пользователю обычно не стоит, а свой понятный текст лучше написать самим.

## Пример 3. TryParse без исключений

```csharp run
bool ok = int.TryParse("42", out int number);
Console.WriteLine($"{ok} {number}");

ok = int.TryParse("abc", out number);
Console.WriteLine($"{ok} {number}");

ok = int.TryParse("3.5", out number);
Console.WriteLine($"{ok} {number}");

ok = int.TryParse("", out number);
Console.WriteLine($"{ok} {number}");
```
```output
True 42
False 0
False 0
False 0
```

`int.TryParse(text, out int number)` принимает текст и пробует разобрать его. Если получилось, возвращает `true` и кладёт число в переменную `number`. Если не получилось, возвращает `false`, а `number` получает 0. Слово `out` вам знакомо по `TryGetValue`: результат метод кладёт в вашу переменную. Строка `"3.5"` для `int` не подходит, пустая строка тоже, и ни в одном случае программа не остановилась.

## Пример 4. Проверка в условии

```csharp run
string text = "17";
if (int.TryParse(text, out int age))
{
    Console.WriteLine($"Возраст: {age}");
}
else
{
    Console.WriteLine("Возраст указан неверно");
}
```
```output
Возраст: 17
```

Привычный способ использования - прямо в `if`. Ветка `else` обрабатывает неверные данные. Замените `"17"` на `"семнадцать"` и запустите снова: вы увидите второе сообщение.

## Пример 5. Исключение внутри метода

```csharp run
static int SafeDivide(int a, int b)
{
    try
    {
        return a / b;
    }
    catch (DivideByZeroException)
    {
        return 0;
    }
}

Console.WriteLine(SafeDivide(10, 2));
Console.WriteLine(SafeDivide(10, 0));
```
```output
5
0
```

Метод скрывает обработку внутри себя: вызывающий код получает число и не думает об исключении. Это удобно, но выбор значения `0` для ошибки - решение автора метода, и его нужно документировать: нуль бывает и настоящим результатом.

## Пример 6. throw: ваш метод сообщает о неверных данных

```csharp run
static int CheckAge(int age)
{
    if (age < 0)
    {
        throw new ArgumentException("Возраст не может быть отрицательным");
    }
    return age;
}

try
{
    Console.WriteLine(CheckAge(30));
    Console.WriteLine(CheckAge(-5));
}
catch (ArgumentException e)
{
    Console.WriteLine("Ошибка: " + e.Message);
}
```
```output
30
Ошибка: Возраст не может быть отрицательным
```

`throw new ArgumentException("...")` создаёт исключение и немедленно прерывает метод. `ArgumentException` - встроенный тип «неверный аргумент метода». Вызывающий код может его перехватить или оставить программе остановиться.

## Пример 7. Строки ввода с ошибками

Ввод:

```
12
abc
8
-
5
```

```csharp
int sum = 0;
int bad = 0;

string? line = Console.ReadLine();
while (line != null)
{
    if (int.TryParse(line, out int value))
    {
        sum += value;
    }
    else
    {
        bad++;
    }
    line = Console.ReadLine();
}

Console.WriteLine($"Сумма: {sum}");
Console.WriteLine($"Пропущено: {bad}");
```

Вывод:

```
Сумма: 25
Пропущено: 2
```

Две строки не разобрались и были посчитаны как пропущенные, программа дошла до конца и показала итог. С `int.Parse` она остановилась бы на второй строке. Такая схема - «посчитать и пропустить плохие строки» - основа последнего проекта курса.

**Попробуйте.** Дополните пример 7: печатайте номер каждой пропущенной строки. Измените метод `CheckAge` так, чтобы он также отвергал возраст больше 150. Проверьте, что `int.TryParse(" 42 ", out int v)` возвращает `true` (пробелы по краям допустимы).

## Точные правила

* Исключение - объект. Его тип (`FormatException`, `DivideByZeroException`, `ArgumentException`, `IndexOutOfRangeException` и другие) описывает вид проблемы. Все исключения происходят от типа `Exception`.
* Код в блоке `try` выполняется по порядку. При исключении остаток блока пропускается, и управление переходит в первый подходящий `catch`. Если исключения нет, все блоки `catch` пропускаются.
* `catch (Тип)` перехватывает исключения этого типа и всех производных. `catch (Тип e)` дополнительно создаёт переменную `e`. Если переменная не используется, лучше писать `catch (Тип)` без неё: иначе компилятор выдаст предупреждение `CS0168`.
* Блоков `catch` может быть несколько; проверяются они сверху вниз. Более общий тип (`Exception`) должен стоять **после** более частных, иначе ошибка `CS0160`.
* Исключение, которое никто не перехватил, поднимается к вызывающему коду, затем выше, и в конце останавливает программу.
* Переменная, объявленная внутри `try { }`, видна только внутри этих скобок.
* `int.TryParse(text, out int result)` возвращает `true` при успехе. При неудаче возвращает `false`, а `result` равно 0. Исключений он не создаёт.
* Для `double` и `decimal` существуют `double.TryParse` и `decimal.TryParse`. Они зависят от культуры так же, как `Parse` (см. урок о `double` и `decimal`).
* `throw new ИмяИсключения("сообщение")` создаёт и «бросает» исключение. Сообщение пишите для программиста, который будет читать ошибку.
* Деление целых на **константу** ноль (`10 / 0`) компилятор отвергает сразу (ошибка `CS0020`); исключение возникает, когда делитель - переменная со значением 0.
* Обработка исключений требует больше времени, чем обычная проверка: для частых событий (плохой ввод) используйте `TryParse` или `if`.
* Блок `finally`, освобождение ресурсов (`using`) и собственные типы исключений рассматриваются в курсе `csharp-fundamentals`.

## Типичные ошибки

**1. Забыли слово `out`.**

```csharp
int x = 5;
if (int.TryParse("12", x))
{
    Console.WriteLine(x);
}
```

Компилятор выдаёт несколько сообщений, среди них `error CS1620: Argument 2 must be passed with the 'out' keyword`. Правильно: `int.TryParse("12", out x)` или `out int x`.

**2. Переменная из `try` недоступна снаружи.**

```csharp
try
{
    int n = int.Parse("7");
}
catch (FormatException)
{
    Console.WriteLine("bad");
}
Console.WriteLine(n);
```

Компилятор: `error CS0103: The name 'n' does not exist in the current context`. Объявите переменную до `try` (`int n = 0;`) и присвойте внутри.

**3. Общий `catch` стоит выше частного.**

```csharp
try
{
    Console.WriteLine(1);
}
catch (Exception)
{
    Console.WriteLine("a");
}
catch (FormatException)
{
    Console.WriteLine("b");
}
```

Компилятор: `error CS0160: A previous catch clause already catches all exceptions of this or of a super type ('Exception')`. Второй блок никогда не сработал бы. Поставьте частный тип выше.

**4. Неиспользуемая переменная исключения.**

```csharp
try
{
    Console.WriteLine(1);
}
catch (FormatException e)
{
    Console.WriteLine("плохой формат");
}
```

Предупреждение: `warning CS0168: The variable 'e' is declared but never used`. Программа запустится, но предупреждение - сигнал: либо используйте `e.Message`, либо уберите имя.

**5. Исключение не перехвачено.**

```csharp
int a = 10;
int b = 0;
Console.WriteLine(a / b);
```

Во время работы: `Unhandled exception. System.DivideByZeroException: Attempted to divide by zero.` Это не ошибка компиляции: код формально правильный. Либо проверьте `b != 0` до деления, либо перехватите `DivideByZeroException`.

**6. Слишком широкий `catch` и «проглоченная» ошибка.** Запись `catch (Exception) { }` с пустым телом скрывает любую проблему, включая опечатки в вашем коде. Перехватывайте конкретный тип и говорите о проблеме.

**7. `TryParse` использован, а результат не проверен.** Если написать `int.TryParse(text, out int n);` и сразу применить `n`, то при неверном тексте `n` будет 0, и ошибка станет незаметной. Всегда проверяйте возвращённое значение `bool`.

## Итоги

* Исключение - объект, описывающий сбой. Без обработки оно останавливает программу.
* `try`/`catch (Тип)` перехватывает исключение и позволяет продолжить работу.
* `int.TryParse(text, out int n)` возвращает `bool`: успех или нет; при неудаче `n` равно 0.
* Для ожидаемых сбоев (плохой ввод) выбирайте `TryParse` и `if`, для неожиданных - `try`/`catch` в месте, где вы знаете, что делать.
* `throw new ...` позволяет вашему методу отвергнуть недопустимые данные.

Пока мы работали со значениями и строками. В следующем уроке данные и поведение собираются вместе в собственный тип: [Классы](lesson:csharp.from-zero.classes-basics).

## Для тех, кто уже программирует

* Исключения в C# непроверяемые (как в Python и Kotlin): нет аналога `throws` из Java, компилятор не требует их перехватывать.
* `try`/`catch`/`finally` знакомы по Java и JavaScript. Тип в `catch` обязателен для типизированного перехвата; пустой `catch` ловит всё. В отличие от Python, нет ветки `else`.
* Идиома `Try...(..., out result)` - замена кортежей и `Optional`: метод возвращает `bool`, результат кладёт в `out`-параметр. То же в `Dictionary.TryGetValue`, `int.TryParse`, `Enum.TryParse`. Go-программисту это напоминает пару `value, ok`.
* Сообщения стандартных исключений зависят от локали и версии .NET, поэтому не используйте их в логике; сравнивайте типы.
* `throw;` без выражения внутри `catch` пробрасывает то же исключение с сохранением стека вызовов, а `throw e;` затирает стек: это известная ловушка.
* Исключения для управления потоком (выход из цикла) считаются плохим стилем: они дороги, особенно в частых путях.
* Для деления `int` на 0 исключение есть, для `double` результат - `Infinity` или `NaN`, без исключения.

## Что делает среда выполнения при исключении

Это необязательный раздел: для заданий он не нужен.

Когда создаётся исключение, среда выполнения запоминает стек вызовов - цепочку методов, которая привела к проблеме, - и начинает поиск обработчика. Она проверяет блоки `catch` в текущем методе, потом в вызывающем, и так вверх по стеку. Найдя подходящий, она «разворачивает» стек: выходит из промежуточных методов и выполняет `catch`. Если обработчика нет, срабатывает обработчик верхнего уровня, который печатает `Unhandled exception`, показывает стек вызовов и завершает процесс.

Создание исключения относительно дорого, потому что нужно собрать трассу стека. Именно поэтому в .NET есть пары `Parse`/`TryParse`: для данных, которые часто бывают неверными, вариант без исключения заметно быстрее.
