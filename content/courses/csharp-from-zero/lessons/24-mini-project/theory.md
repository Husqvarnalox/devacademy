## Зачем это нужно

Вы изучили по отдельности: чтение ввода, циклы, условия, методы, словари, строки, обработку ошибок, классы. Настоящая программа складывает эти умения вместе. В этом уроке нет нового языка, есть новый навык: **разбить задачу на этапы** и сделать каждый отдельно. Такой подход работает для любой программы, даже когда она в десять раз больше.

## Одна идея: конвейер из этапов

Программа-отчёт почти всегда устроена как конвейер:

1. **Прочитать**: получить строки ввода до его конца.
2. **Разобрать**: для каждой строки решить, что это (пустая, верная, неверная), и достать из неё данные.
3. **Накопить**: прибавить данные к итогам (по категориям, общий итог, счётчики).
4. **Вывести**: оформить итоги в точном формате.

Пишите и проверяйте этапы по очереди. После этапа 1 напечатайте число строк. После этапа 2 напечатайте разобранные пары. Только когда каждый этап верен, переходите к следующему. Так ошибка всегда находится в последнем добавленном куске.

Задача этого урока - программа «Бюджет»: она читает записи расходов вида `категория сумма`, считает итоги по категориям и сообщает, сколько строк оказалось неверными.

## Пример 1. Этап «разобрать» отдельно

```csharp run
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;

string[] lines = { "Еда 250.50", "Еда", "кино abc", "  Дом -5  " };
foreach (string raw in lines)
{
    Entry? entry = ParseLine(raw.Trim());
    if (entry == null)
    {
        Console.WriteLine("неверная строка");
    }
    else
    {
        Console.WriteLine($"{entry.Category}: {entry.Amount:F2}");
    }
}

static Entry? ParseLine(string line)
{
    string[] parts = line.Split(' ');
    if (parts.Length == 2 && decimal.TryParse(parts[1], out decimal amount))
    {
        Entry result = new Entry();
        result.Category = parts[0];
        result.Amount = amount;
        return result;
    }
    return null;
}

class Entry
{
    public string Category { get; set; } = "";
    public decimal Amount { get; set; }
}
```
```output
Еда: 250.50
неверная строка
неверная строка
Дом: -5.00
```

Разбор:

* метод `ParseLine` возвращает либо объект `Entry`, либо `null` («ничего»). Запись `Entry?` с вопросительным знаком, как и `string?`, значит «объект или `null`»; проверка `entry == null` обязательна, иначе компилятор предупредит о возможном обращении через `null`;
* `Split(' ')` делит по каждому пробелу. Строка `"Еда"` даёт одну часть, а не две, и считается неверной;
* `decimal.TryParse` проверяет, что вторая часть - число; строка `"кино abc"` не проходит;
* перед разбором строка очищается через `Trim()`, поэтому пробелы по краям не мешают: `"  Дом -5  "` разбирается успешно.

Метод разбора скрывает подробности строки, главный цикл только спрашивает: «получилась запись или нет?».

## Пример 2. Этап «накопить» отдельно

```csharp run
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;

Dictionary<string, decimal> totals = new Dictionary<string, decimal>();
decimal overall = 0;

string[] categories = { "Еда", "Дом", "Еда" };
decimal[] amounts = { 100, 500, 50.5m };

for (int i = 0; i < categories.Length; i++)
{
    string category = categories[i];
    if (totals.ContainsKey(category))
    {
        totals[category] = totals[category] + amounts[i];
    }
    else
    {
        totals[category] = amounts[i];
    }
    overall = overall + amounts[i];
}

Console.WriteLine(totals["Еда"]);
Console.WriteLine(totals["Дом"]);
Console.WriteLine(overall);
```
```output
150.5
500
650.5
```

Для каждой записи сумма добавляется к категории: если категория уже есть, прибавляем к старому значению, иначе создаём запись. Общий итог `overall` объявлен **до** цикла, внутри он только меняется.

## Пример 3. Этап «вывести» отдельно

```csharp run
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;

Dictionary<string, decimal> totals = new Dictionary<string, decimal>();
totals["Транспорт"] = 120.25m;
totals["Еда"] = 350m;
totals["Дом"] = 1200m;

List<string> names = new List<string>(totals.Keys);
names.Sort(StringComparer.Ordinal);

string best = "";
decimal bestTotal = 0;
decimal overall = 0;
foreach (string name in names)
{
    decimal sum = totals[name];
    Console.WriteLine($"{name}: {sum:F2}");
    overall = overall + sum;
    if (best == "" || sum > bestTotal)
    {
        best = name;
        bestTotal = sum;
    }
}

Console.WriteLine($"Итого: {overall:F2}");
Console.WriteLine($"Больше всего: {best}");
```
```output
Дом: 1200.00
Еда: 350.00
Транспорт: 120.25
Итого: 1670.25
Больше всего: Дом
```

Ключи копируются в список и сортируются: порядок в самом словаре не гарантирован. `StringComparer.Ordinal` в `Sort` сравнивает строки по кодам символов, а не по правилам языка системы, поэтому порядок категорий одинаков на любом компьютере. Максимум ищется так: первая категория становится «лучшей» по условию `best == ""`, а дальше побеждает только строго большая сумма. Поэтому при равенстве остаётся та, что раньше в отсортированном списке. Начинать поиск с `bestTotal = 0` без проверки `best == ""` нельзя: при отрицательных суммах победителя бы не нашлось.

## Пример 4. Сборка целиком

Пока строки взяты из массива, чтобы пример запускался без ввода. В упражнении вместо массива вы читаете строки из `Console.ReadLine`.

```csharp run
using System.Globalization;

CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;

string[] lines =
{
    "Еда 250.50", "Транспорт 80", "Еда 99.50", "", "кино abc", "Дом 1200", "Транспорт 40.25"
};

Dictionary<string, decimal> totals = new Dictionary<string, decimal>();
decimal overall = 0;
int malformed = 0;

foreach (string raw in lines)
{
    string line = raw.Trim();
    if (line.Length == 0)
    {
        continue;
    }

    string[] parts = line.Split(' ');
    if (parts.Length != 2 || !decimal.TryParse(parts[1], out decimal amount))
    {
        malformed++;
        continue;
    }

    string category = parts[0];
    if (totals.ContainsKey(category))
    {
        totals[category] = totals[category] + amount;
    }
    else
    {
        totals[category] = amount;
    }
    overall = overall + amount;
}

List<string> names = new List<string>(totals.Keys);
names.Sort(StringComparer.Ordinal);
string best = "";
decimal bestTotal = 0;
foreach (string name in names)
{
    Console.WriteLine($"{name}: {totals[name]:F2}");
    if (best == "" || totals[name] > bestTotal)
    {
        best = name;
        bestTotal = totals[name];
    }
}
Console.WriteLine($"Итого: {overall:F2}");
Console.WriteLine($"Больше всего: {(best == "" ? "нет" : best)}");
Console.WriteLine($"Неверных строк: {malformed}");
```
```output
Дом: 1200.00
Еда: 350.00
Транспорт: 120.25
Итого: 1670.25
Больше всего: Дом
Неверных строк: 1
```

Что стоит заметить:

* пустая строка пропускается сразу после `Trim()` и не считается неверной;
* для неверной строки `malformed` увеличивается и выполняется `continue`: остальная часть цикла (накопление) пропускается;
* условие `parts.Length != 2 || !decimal.TryParse(...)`: если частей не две, правая часть не вычисляется (так работает `||`), и `TryParse` не вызывается; после проверки переменная `amount` доступна ниже в цикле;
* запись `(best == "" ? "нет" : best)` - условное выражение: «если категорий нет, напечатай `нет`, иначе имя». Это сокращённая запись `if`/`else`, которая возвращает значение;
* вывод идёт **после** цикла, когда все данные известны: сортировать и искать максимум можно только по полным итогам.

Теперь замените массив `lines` чтением ввода, как в упражнении.

**Попробуйте.** Добавьте в отчёт число верных записей. Выводите также среднюю сумму записи (с проверкой деления на ноль). Замените `Split(' ')` на `Split(' ', StringSplitOptions.RemoveEmptyEntries)` и посмотрите, как изменится судьба строки `"Еда  7"` (два пробела); подумайте, какое поведение вам нужнее.

## Точные правила задачи

* Запись - это `категория сумма` с **ровно одним пробелом**. Категория - одно слово. Сумма - число с точкой, возможно отрицательное (возврат).
* Перед разбором строка очищается через `Trim()`. Пустая строка не считается ни верной, ни неверной.
* `line.Split(' ')` делит по каждому пробелу. Верная запись - ровно две части, вторая из которых `decimal.TryParse` разбирает успешно. Иначе строка неверная: она учитывается в счётчике и больше нигде.
* Первая строка программы после `using` - `CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;`, иначе на системе с русскими настройками `TryParse` будет ждать запятую и отвергнет `250.50`.
* Порядок вывода категорий - `Sort(StringComparer.Ordinal)` списка названий: строки сравниваются по кодам символов, поэтому порядок не зависит от региональных настроек компьютера. Суммы печатаются через `:F2`.
* Если верных записей нет, печатаются три строки без категорий: `Итого: 0.00`, `Больше всего: нет`, `Неверных строк: N`.
* Самая большая категория - с наибольшей суммой (отрицательные суммы допустимы). При равенстве побеждает первая в отсортированном списке: сравнение строгое `>`.
* Деньги хранятся в `decimal`: сложение сумм с копейками не накапливает двоичных ошибок.
* Программа не должна падать ни на каком вводе из строк: пустом, содержащем только неверные строки, с пробелами по краям.

## Типичные ошибки

**1. Накопление без начального значения.**

```csharp
Dictionary<string, decimal> totals = new Dictionary<string, decimal>();
totals["Еда"] = totals["Еда"] + 100;
```

Во время работы: `Unhandled exception. System.Collections.Generic.KeyNotFoundException: The given key 'Еда' was not present in the dictionary.` Для новой категории сначала нужно создать запись: проверьте `ContainsKey` и положите первую сумму.

**2. Забыт `CultureInfo`.**

```csharp
using System.Globalization;

CultureInfo.CurrentCulture = new CultureInfo("ru-RU");
bool ok = decimal.TryParse("250.50", out decimal a);
Console.WriteLine($"{ok} {a}");
```

Вывод: `False 0`. На системе с русскими настройками число `250.50` не разбирается, и программа без единого сообщения считает **все** строки неверными. Эту ошибку легко принять за неправильную логику, но её причина - культура. Первой строкой программы нужен `CultureInfo.CurrentCulture = CultureInfo.InvariantCulture;`.

**3. `Parse` вместо `TryParse`.** `decimal.Parse("abc")` останавливает программу на первой же плохой строке: `System.FormatException: The input string 'abc' was not in a correct format.` Нужен вариант, который возвращает `bool`.

**4. Забыли `continue` после неверной строки.** После `malformed++` программа продолжает выполнять следующие инструкции цикла. Если `amount` при этом не задана, компилятор остановит сборку (`CS0165: Use of unassigned local variable`); если задана, плохая запись попадёт в итоги. Заканчивайте обработку неверной строки через `continue`.

**5. Максимум с нуля.**

```csharp
string best = "";
decimal bestTotal = 0;
decimal sum = -5;
if (sum > bestTotal)
{
    best = "Дом";
}
Console.WriteLine($"[{best}]");
```

Напечатается `[]`: сумма -5 не больше 0, и ни одна категория не победила. Добавьте условие `best == ""`, чтобы первая категория становилась лучшей без сравнения.

**6. Пустая строка считается неверной.** Если не отсеять её первой, она не пройдёт проверку «две части» и увеличит `malformed`. Пропускайте пустые строки сразу после `Trim()`.

**7. Итоги объявлены внутри цикла.** `decimal overall = 0;` внутри цикла обнуляется на каждой строке, и результат равен последней сумме. Все переменные для итогов - `totals`, `overall`, `malformed` - объявляйте перед циклом.

**8. Порядок словаря принят за алфавитный.** Перебор `foreach (var pair in totals)` не даёт гарантий порядка. Копируйте ключи в список и вызывайте `Sort(StringComparer.Ordinal)`.

## Итоги

* Задача, состоящая из многих правил, решается конвейером: прочитать, разобрать, накопить, вывести.
* Каждый этап пишут и проверяют отдельно, на маленьких входах.
* Итоги живут в переменных, объявленных перед циклом; внутри цикла они только изменяются.
* Крайние случаи - пустой ввод, одни плохие строки, отрицательные суммы, равные итоги - нужно продумать заранее, до кода.

## Для тех, кто уже программирует

* Подход «разбери строку в запись или `null`, затем работай с записью» нужен на границе системы: данные снаружи нельзя считать верными. В больших программах это парсеры и валидаторы; здесь парсер - несколько строк.
* Деньги в `decimal`, не в `double`: это тип с десятичным основанием, он подходит для сумм. Альтернатива - целые копейки.
* `Sort()` для строк использует сравнение с учётом региональных настроек, и порядок может отличаться на разных компьютерах; `StringComparer.Ordinal` сравнивает по кодам символов и даёт один и тот же порядок везде.
* Для настоящих программ ввод читают построчно через `Console.In` или файловые API; чтение до конца потока - обычный приём для фильтров в конвейере shell.
* В настоящем коде накопление по категориям часто выражают через LINQ `GroupBy`. Здесь выбраны простые конструкции, потому что их легко проверять шаг за шагом.
* Условный оператор `?:` знаком по Java и JavaScript; в Python это `a if c else b`.

## Почему этапы лучше одного большого цикла

Это необязательный раздел: для заданий он не нужен.

Можно записать решение одним циклом, который читает, разбирает, считает и печатает. Для небольшой задачи это работает, но каждое изменение условия затрагивает весь цикл. Если же этапы отделены (разбор в методе, накопление в словаре, вывод после цикла), то изменение формата вывода не трогает разбор, а новое правило проверки строки не трогает печать. Это та же идея, что у методов: имя и границы для куска работы.

Заметьте также, что вывод происходит после цикла, когда все данные известны. Сортировку и поиск максимума нельзя сделать, пока не прочитаны все строки: категории могут встретиться в любом порядке. Если данные для следующего шага ещё не готовы, их нужно накопить, а не печатать сразу.
