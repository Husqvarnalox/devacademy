## Зачем нужны методы

Когда одна и та же последовательность команд нужна в разных местах, её не копируют, а один раз оформляют как **метод** - именованный фрагмент программы - и вызывают по имени. Так меньше текста, ошибку достаточно исправить в одном месте, а программа читается как набор осмысленных действий: `PrintReceiptLine(...)` понятнее десяти строк с `Console.WriteLine`.

## Одна новая идея: метод получает данные через параметры

Метод записывается так:

```csharp
static void Greet(string name)
{
    Console.WriteLine($"Привет, {name}!");
}
```

Разберём каждую часть:

* **`static`** - пока достаточно такого объяснения: метод сам по себе не пользуется переменными программы снаружи, всё необходимое он получает через параметры. Подробно слово `static` объясняется в уроке о классах;
* **`void`** («пустота») - метод ничего не возвращает, он только выполняет действия (результат-значение разберём в следующем уроке);
* **`Greet`** - имя метода; его выбирают по действию, а начинают с заглавной буквы;
* **`(string name)`** - **параметр**: переменная, которая появляется внутри метода и получает значение при вызове;
* **`{ ... }`** - тело метода.

Вызов выглядит как `Greet("Анна");`. Значение в круглых скобках при вызове называют **аргументом**: аргумент `"Анна"` копируется в параметр `name`. Параметров может быть несколько, они перечисляются через запятую, и аргументы передаются в том же порядке.

Где писать методы: в нашем файле сначала идут команды программы (они выполняются сверху вниз), а методы записываются **ниже** них, в конце файла. Порядок вызова при этом не важен: метод можно вызвать выше того места, где он записан.

<!-- section: examples -->
## Пример 1. Метод с одним параметром

```csharp run
Greet("Анна");
Greet("Борис");

static void Greet(string name)
{
    Console.WriteLine($"Привет, {name}!");
}
```
```output
Привет, Анна!
Привет, Борис!
```

Разбор:

* программа вызывает `Greet` дважды с разными аргументами: сначала `name` равно `"Анна"`, затем `"Борис"`;
* тело метода написано один раз, а выполняется дважды;
* метод записан после вызовов, и это допустимо.

## Пример 2. Несколько параметров

```csharp run
PrintLine("Хлеб", 2, 45);
PrintLine("Молоко", 1, 89);

static void PrintLine(string item, int quantity, int price)
{
    int total = quantity * price;
    Console.WriteLine($"{item} x {quantity} = {total}");
}
```
```output
Хлеб x 2 = 90
Молоко x 1 = 89
```

Аргументы соответствуют параметрам по порядку: первый аргумент идёт в `item`, второй - в `quantity`, третий - в `price`. Типы тоже должны совпадать: на второй позиции нужно целое число. Переменная `total` создаётся внутри метода при каждом вызове заново.

## Пример 3. Метод вызывает метод, метод вызывается в цикле

```csharp run
for (int row = 1; row <= 3; row++)
{
    PrintStars(row);
}

static void PrintStars(int count)
{
    for (int i = 0; i < count; i++)
    {
        Console.Write("*");
    }
    Console.WriteLine();
}
```
```output
*
**
***
```

Цикл из прошлых уроков теперь спрятан за именем `PrintStars`. Внешний код читается как «напечатать звёздочки в количестве row».

## Пример 4. Область видимости: переменные метода живут в нём

```csharp run
int count = 100;
Show(5);
Console.WriteLine($"снаружи: {count}");

static void Show(int x)
{
    int count = x * 2;
    Console.WriteLine($"внутри: {count}");
}
```
```output
внутри: 10
снаружи: 100
```

Параметры и переменные, объявленные в методе, видны только в нём. `count` внутри метода - **другая** переменная, хотя имя совпадает с внешней. Изменение одной не затрагивает другую. Это правило называется **областью видимости** (scope): переменная существует и доступна только в том блоке `{ }`, где объявлена.

## Пример 5. Метод и ввод

Ввод:

```
Кофе
3
```

```csharp
string drink = Console.ReadLine() ?? "";
int cups = int.Parse(Console.ReadLine() ?? "");
Repeat(drink, cups);

static void Repeat(string text, int times)
{
    for (int i = 1; i <= times; i++)
    {
        Console.WriteLine($"{i}. {text}");
    }
}
```

Вывод:

```
1. Кофе
2. Кофе
3. Кофе
```

Чтение ввода остаётся в основной части программы, а метод занимается только печатью. Такое разделение пригодится в упражнениях: в заготовках чтение ввода написано за вас, а вы пишете методы.

**Попробуйте.** В примере 2 вызовите `PrintLine` с аргументами в другом порядке, например `PrintLine(2, "Хлеб", 45)`, и прочитайте сообщение компилятора. В примере 3 добавьте второй параметр - символ, которым рисуется линия (`string symbol`).

## Точные правила

* Заголовок метода: `static void Имя(тип1 параметр1, тип2 параметр2)`. Круглые скобки обязательны, даже если параметров нет: `static void PrintLine()`.
* Вызов: `Имя(аргумент1, аргумент2);`. Количество, порядок и типы аргументов должны совпадать с параметрами.
* Параметр - это новая переменная метода; она получает **копию** значения аргумента. Изменение параметра внутри метода не меняет исходную переменную при вызове (для чисел и строк).
* `void` означает, что метод не возвращает значения. Вызов такого метода - отдельная команда, значением в выражении он быть не может.
* Метод, объявленный со `static`, не может обращаться к переменным программы снаружи: компилятор сообщает об ошибке `CS8421`. Всё нужное передаётся через параметры.
* Переменные и параметры метода недоступны вне его. Одно и то же имя в разных методах - разные переменные.
* Методы пишут после команд программы; вызывать метод можно в любой точке файла.
* Имя метода - глагол с заглавной буквы (`PrintReceipt`, `ShowMenu`); метод делает одно понятное действие.

## Типичные ошибки

**1. Неверное количество аргументов.**

```csharp
Greet("Анна", 3);

static void Greet(string name)
{
    Console.WriteLine($"Привет, {name}!");
}
```

Компилятор: `error CS1501: No overload for method 'Greet' takes 2 arguments`. Передавайте столько аргументов, сколько параметров в заголовке.

**2. Неверный тип аргумента.**

```csharp
Greet(5);

static void Greet(string name)
{
    Console.WriteLine($"Привет, {name}!");
}
```

Компилятор: `error CS1503: Argument 1: cannot convert from 'int' to 'string'`. Первый параметр - строка, а передано число.

**3. Метод обращается к внешней переменной.**

```csharp
int bonus = 10;
Show(5);

static void Show(int x)
{
    Console.WriteLine(x + bonus);
}
```

Компилятор: `error CS8421: A static local function cannot contain a reference to 'bonus'`. Передайте значение параметром: `Show(5, bonus)` и добавьте параметр в заголовок.

**4. Переменная метода использована снаружи.**

```csharp
Show(5);
Console.WriteLine(doubled);

static void Show(int x)
{
    int doubled = x * 2;
    Console.WriteLine(doubled);
}
```

Компилятор: `error CS0103: The name 'doubled' does not exist in the current context`. Переменная `doubled` существует только в `Show`.

**5. Вызов без скобок.**

```csharp
Show;

static void Show()
{
    Console.WriteLine("x");
}
```

Компилятор: `error CS0201: Only assignment, call, increment, decrement, await, and new object expressions can be used as a statement`. Метод вызывают со скобками: `Show();`.

**6. Попытка использовать результат метода `void`.**

```csharp
int n = Show();

static void Show()
{
    Console.WriteLine("x");
}
```

Компилятор: `error CS0029: Cannot implicitly convert type 'void' to 'int'`. У метода `void` нет значения. Как вернуть значение - в следующем уроке.

**7. Аргументы в неправильном порядке.** Если типы совпадают (две строки или два числа), компилятор ошибку не покажет, но результат будет неверным: `PrintLine("Хлеб", 45, 2)` напечатает цену как количество. Сверяйте порядок с заголовком метода.

## Итоги

* Метод - именованный блок: `static void Имя(тип параметр) { ... }`. Вызов - `Имя(аргумент);`.
* Параметр получает значение аргумента при вызове; порядок и типы аргументов должны совпадать.
* Переменные метода существуют только в нём (область видимости); внешние переменные ему не видны, всё нужное передают параметрами.
* `void` - метод только выполняет действие и ничего не возвращает.
* Методы пишут ниже основных команд.

Часто от метода нужен не вывод, а результат вычисления: [Результат метода: return](lesson:csharp.from-zero.return-values).

## Для тех, кто уже программирует

* В файле с инструкциями верхнего уровня метод, объявленный среди них, - это **локальная функция** неявного метода `Main`. Модификатор `static` делает её «статической локальной функцией»: она не может захватывать локальные переменные. Без `static` метод разрешено вызывать так же, но он видит внешние переменные (замыкание). В курсе всегда пишут `static`, чтобы все данные шли через параметры.
* Параметры передаются по значению (для ссылочных типов копируется ссылка). Ключевые слова `ref`, `out`, `in` в курсе не используются, кроме `out` у `TryParse` в последующих уроках.
* Перегрузка (несколько методов с одним именем и разными параметрами) разрешена, как в Java; здесь не используется. Параметры по умолчанию (`int times = 1`) и именованные аргументы (`Repeat(times: 3, text: "a")`) тоже есть и не нужны на этом этапе.
* Имена методов в C# принято писать в `PascalCase`, а переменных и параметров - в `camelCase`.
* В классическом варианте методы живут внутри класса `Program`; файл с инструкциями верхнего уровня - его сокращённая запись, в которой `Main` создаётся компилятором. Подробно: курс «C#: первые шаги».
* Методы допускают рекурсию (вызов самого себя), как в других языках.

<!-- section: deep-dive -->
## Что происходит при вызове метода

Это необязательный раздел: для заданий он не нужен.

При вызове метода среда выполнения выделяет для него **кадр** (stack frame) на участке памяти, который называют стеком вызовов. В кадре хранятся параметры, локальные переменные и адрес возврата - место, куда продолжится выполнение после завершения метода. Когда метод заканчивается, кадр освобождается, а вместе с ним исчезают и все его переменные. Поэтому переменные метода нельзя использовать снаружи: их больше нет.

Отсюда же следует ограничение рекурсии: каждый вызов создаёт новый кадр, и слишком глубокая цепочка вызовов приводит к переполнению стека (`StackOverflowException`). Компилятор и JIT могут «встраивать» короткие методы прямо в место вызова, чтобы не создавать кадр, но на смысл программы это не влияет.
