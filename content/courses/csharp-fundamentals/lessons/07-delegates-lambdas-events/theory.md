## Код как значение

**Делегат** - тип, описывающий сигнатуру метода: переменная такого типа хранит ссылку на метод (или несколько) и позволяет вызвать его позже, передать как аргумент или вернуть. В .NET почти всегда используют готовые обобщённые делегаты: `Action<T>` (ничего не возвращает), `Func<T, TResult>` (возвращает значение), `Predicate<T>` (возвращает `bool`).

**Лямбда** - короткая запись анонимной функции: `x => x * 2`. Лямбды можно «захватывать» переменные окружающего метода: такая функция называется **замыканием** (closure). Именно поэтому LINQ-запросы и обработчики событий так выразительны, и именно здесь живут самые коварные ошибки (общий счётчик в цикле, «неотписанный» обработчик).

**Событие** (`event`) - делегат, к которому снаружи можно только подписаться (`+=`) и отписаться (`-=`); вызвать его может только сам издатель. Это шаблон «издатель - подписчики»: издатель не знает, кто слушает.

**Локальная функция** - именованный метод, объявленный внутри другого метода; она видит его переменные и удобна для вспомогательной логики (в том числе рекурсивной), не загрязняя класс.

## Точные правила

**Делегаты.**

* Делегат - ссылочный тип, неизменяемый: `+=` создаёт **новый** делегат, объединяющий списки вызова (**multicast**). `GetInvocationList()` возвращает отдельные делегаты.
* При вызове многоадресного делегата обработчики выполняются по порядку подписки; возвращаемое значение - от **последнего**. Исключение в одном обработчике прерывает вызов остальных.
* `-=` удаляет из списка последнее вхождение делегата, **равного** переданному (одинаковые цель и метод). Два лямбда-выражения с одинаковым текстом - это **разные** делегаты, поэтому `h -= x => ...` с новой лямбдой ничего не удаляет и не сообщает об этом.
* Преобразование группы методов (`handler = Method`) создаёт делегат, равный другому делегату на тот же метод и тот же экземпляр, поэтому `+= Method` / `-= Method` работают симметрично.
* `Action`, `Func<...>`, `Predicate<T>` покрывают почти все случаи; свои `delegate` нужны редко.

**Лямбды.**

* Естественный тип: `var f = (int x) => x * 2;` вводит `Func<int,int>` (C# 10). Для лямбды, которую нужно присвоить `var`, параметры должны быть с типами.
* Значения параметров по умолчанию в лямбдах: `(int x, int y = 5) => x + y` (C# 12).
* **Статическая лямбда** `static x => x * 2` (C# 9) запрещает захват: попытка обратиться к внешней переменной - ошибка CS8820.
* Выражение-тело (`x => x + 1`) и блок-тело (`x => { ...; return y; }`).

**Замыкания.**

* Лямбда захватывает **переменную**, а не её текущее значение. Пока лямбда жива, жива и переменная.
* Цикл `for (int i...)` создаёт **одну** переменную `i` на весь цикл: все лямбды, захватившие её, увидят итоговое значение. Цикл `foreach (var x in ...)` создаёт **новую** переменную на каждой итерации (это поведение C# 5+).
* Чтобы зафиксировать значение, скопируйте его в локальную переменную внутри тела цикла (`int copy = i;`).
* Захват порождает скрытый класс с полями, а лямбда превращается в его метод: каждый захваченный объект живёт, пока на него ссылается делегат.

**События.**

* `public event Action<string>? Changed;` снаружи допускает только `+=` и `-=`; вызов (`Changed?.Invoke(...)`) и присваивание доступны лишь внутри класса. Публичное поле-делегат дало бы всем право вызывать и перезаписывать.
* `Changed?.Invoke(x)` безопасен для события без подписчиков (оно равно `null`) и для гонок с отпиской.
* Стандартная форма: `event EventHandler<TEventArgs>?` с сигнатурой `(object? sender, TEventArgs e)`.
* **Утечка через событие.** Издатель хранит ссылки на подписчиков (поле `Delegate.Target`). Подписчик, который не отписался, не будет собран, пока жив издатель: классическая утечка памяти и источник «призрачных» вызовов. Правило: кто подписался - тот отписывается (в `Dispose()` или при закрытии).
* Отписываться нужно **тем же** делегатом: сохраняйте обработчик в переменную или поле либо используйте метод.

**Локальные функции.** Объявляются в теле метода (можно после `return`); видят локальные переменные и параметры; могут быть рекурсивными, обобщёнными и `static` (тогда захват запрещён). В отличие от лямбды у них есть имя и явные типы параметров.

## Примеры

**Пример 1. Что захватывает замыкание.**

```csharp run
using System;
using System.Collections.Generic;

var acts = new List<Action>();
for (int i = 0; i < 3; i++) acts.Add(() => Console.Write(i + " "));
foreach (var a in acts) a();
Console.WriteLine("  <- for: одна переменная i");

acts.Clear();
foreach (int i in new[] { 0, 1, 2 }) acts.Add(() => Console.Write(i + " "));
foreach (var a in acts) a();
Console.WriteLine("  <- foreach: новая переменная на каждой итерации");

acts.Clear();
for (int i = 0; i < 3; i++)
{
    int copy = i;
    acts.Add(() => Console.Write(copy + " "));
}
foreach (var a in acts) a();
Console.WriteLine("  <- копия внутри цикла");

Func<int> counter1 = MakeCounter();
Func<int> counter2 = MakeCounter();
counter1(); counter1();
Console.WriteLine($"{counter1()} {counter2()}");

static Func<int> MakeCounter()
{
    int count = 0;
    return () => ++count;
}
```
```output
3 3 3   <- for: одна переменная i
0 1 2   <- foreach: новая переменная на каждой итерации
0 1 2   <- копия внутри цикла
3 1
```

У каждого вызова `MakeCounter()` своя переменная `count`: счётчики независимы, и каждая переменная живёт, пока жив её делегат.

**Пример 2. События, `-=` и список вызова.**

```csharp run
using System;

var pub = new Publisher();
void Print(string s) => Console.WriteLine("Print " + s);

pub.Changed += Print;
pub.Changed += s => Console.WriteLine("лямбда " + s);
pub.Raise("a");
Console.WriteLine($"подписчиков: {pub.Count}");

pub.Changed -= s => Console.WriteLine("лямбда " + s);   // новая лямбда: ничего не удаляет
pub.Changed -= Print;                                   // та же группа методов: удаляет
Console.WriteLine($"подписчиков: {pub.Count}");
pub.Raise("b");

Func<int> f = () => 1;
f += () => 2;
f += () => 3;
Console.WriteLine($"multicast вернул {f()} из {f.GetInvocationList().Length}");

Action boom = () => Console.WriteLine("первый");
boom += () => throw new InvalidOperationException("упал второй");
boom += () => Console.WriteLine("третий");
try { boom(); } catch (InvalidOperationException e) { Console.WriteLine(e.Message); }

class Publisher
{
    public event Action<string>? Changed;
    public int Count => Changed?.GetInvocationList().Length ?? 0;
    public void Raise(string s) => Changed?.Invoke(s);
}
```
```output
Print a
лямбда a
подписчиков: 2
подписчиков: 1
лямбда b
multicast вернул 3 из 3
первый
упал второй
```

**Пример 3. Тип лямбды, `static`-лямбда и локальные функции.**

```csharp run
using System;
using System.Linq;

var twice = (int x) => x * 2;
Console.WriteLine(twice.GetType().Name + " " + twice(21));

var add = (int x, int y = 5) => x + y;
Console.WriteLine(add(1) + " " + add(1, 2));

Func<int, int> pure = static x => x + 1;
Console.WriteLine(pure(1));

Console.WriteLine(Sum([1, 2, 3, 4]));
Console.WriteLine(Fib(10));
Console.WriteLine(string.Join(",", new[] { "b", "a", "c" }.OrderBy(s => s)));

static int Sum(int[] xs)
{
    int total = 0;
    Accumulate();
    return total;

    void Accumulate()
    {
        foreach (int x in xs) total += x;
    }
}

static int Fib(int n)
{
    return Step(n);

    static int Step(int k) => k < 2 ? k : Step(k - 1) + Step(k - 2);
}
```
```output
Func`2 42
6 3
2
10
55
a,b,c
```

## Типичные ошибки

* **Захват переменной цикла `for`.** Все лямбды видят итоговое значение; делайте копию внутри цикла.
* **Отписка новой лямбдой.** `ev -= x => ...` не удаляет подписку и не даёт ошибки; сохраняйте обработчик в переменную или используйте метод.
* **Забытая отписка.** Издатель удерживает подписчика: долгоживущее событие плюс короткоживущие подписчики - утечка памяти.
* **Вызов события без проверки на `null`.** `Changed(x)` падает с `NullReferenceException`, если подписчиков нет; пишите `Changed?.Invoke(x)`.
* **Публичное поле-делегат вместо `event`.** Любой код сможет его вызвать или сбросить.
* **Исключение в обработчике.** Прерывает вызов остальных подписчиков; если это важно, перебирайте `GetInvocationList()` и вызывайте по одному.
* **Неожиданное значение многоадресной функции.** `Func` возвращает результат только последнего обработчика.
* **Побочные эффекты и общий счётчик в замыкании.** Общая переменная между обработчиками превращается в скрытое глобальное состояние.
* **Долгоживущее замыкание над большим объектом.** Лямбда удерживает всё, что захватила; `static`-лямбда явно запрещает захват.
* **`async void` обработчик.** Допустим только для событий; исключения из него нельзя перехватить снаружи (см. урок про [async/await](lesson:csharp.fundamentals.async-await)).

## Итоги

* Делегаты (`Action`, `Func`, `Predicate`) - значения-функции; многоадресные делегаты вызывают обработчики по порядку, возвращают последнее значение, а исключение прерывает цепочку.
* Лямбда захватывает переменные: `for` даёт одну общую, `foreach` - новую на итерацию; фиксируйте значение копией.
* `event` разрешает снаружи только `+=` и `-=`; отписывайтесь тем же делегатом, иначе подписчик останется в списке и в памяти.
* Естественный тип лямбды (C# 10), параметры по умолчанию (C# 12) и `static`-лямбда (C# 9) проверены компиляцией.
* Локальные функции - именованные вспомогательные методы внутри метода; их можно делать `static` и рекурсивными.

Сравните с [замыканиями в JavaScript](lesson:javascript.fundamentals.scope-and-closures). Предыдущий урок: [LINQ](lesson:csharp.fundamentals.linq) строится на делегатах. Дальше: [async/await](lesson:csharp.fundamentals.async-await).

## Факты

* Естественный тип лямбда-выражения (`var f = (int x) => x;`) появился в C# 10, значения параметров по умолчанию в лямбдах - в C# 12, статические анонимные функции - в C# 9.
* Делегат остаётся ссылочным неизменяемым типом: `+=` и `-=` создают новый объект, объединяя или усекая список вызова.
