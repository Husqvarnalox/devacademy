## От ноутбука к конвейеру

Первая версия обучения почти всегда живёт в ноутбуке: загрузить данные, разбить, обучить, оценить. Пока модель одна, это удобно. Потом появляются вопросы: «я поменял только метрику оценки, почему обучение запускается заново и занимает два часа?», «коллега запустил ячейки в другом порядке и получил другой результат», «какие ячейки надо перезапустить после правки разбиения?». У ноутбука есть скрытое состояние: переменные живут между ячейками, а результат зависит от того, в каком порядке и сколько раз их запускали.

**Конвейер** (pipeline) разбивает работу на **шаги** (steps) с явными зависимостями: шаг `train` берёт результат `split`, шаг `split` берёт результат `load`. Каждый шаг - **функция входов и параметров**: те же входы и параметры дают тот же результат, и больше ничего на него не влияет. Из этого контракта следуют две вещи:

* шаги можно выполнить в любом порядке, согласованном с зависимостями, - это **топологический порядок** графа (подробнее о нём в уроке про [сборку как граф зависимостей](lesson:devops.fundamentals.build-pipelines-as-dags));
* результат шага можно **кешировать**: если входы и параметры не менялись, повторять вычисление незачем.

Ключ кеша мы построим из того, что вы уже умеете: каноническая JSON-запись и хеш SHA-256 ([воспроизводимость](lesson:mlops.fundamentals.reproducibility)). В ключ войдёт имя шага, его параметры, версия кода и ключи шагов, от которых он зависит. Тогда изменение в начале графа автоматически меняет ключи всех шагов ниже, и ровно они пересчитываются. Версия данных из [прошлого урока](lesson:mlops.fundamentals.data-versioning) подаётся на вход корневого шага через его параметры.

## Примеры

**Пример 1. Мини-конвейер с кешем.** Четыре шага: загрузка, разбиение, обучение (подбор коэффициента `w` в модели `y = w * x` по методу наименьших квадратов) и оценка. Запустим конвейер четыре раза с общим кешем и посмотрим, что выполняется заново.

```python run
import hashlib
import json

def canonical_json(obj):
    return json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False)

def sha(text):
    return hashlib.sha256(text.encode("utf-8")).hexdigest()

def topo_order(steps):
    by_name = {s["name"]: s for s in steps}
    pending = {n: len(set(s["deps"])) for n, s in by_name.items()}
    ready, order = sorted(n for n, k in pending.items() if k == 0), []
    while ready:
        name = ready.pop(0)
        order.append(name)
        for other, s in by_name.items():
            if name in s["deps"]:
                pending[other] -= 1
                if pending[other] == 0:
                    ready.append(other)
        ready.sort()
    return order

def step_key(step, dep_keys):
    payload = {"name": step["name"], "version": step["version"], "params": step["params"],
               "deps": {d: dep_keys[d] for d in step["deps"]}}
    return sha(canonical_json(payload))[:16]

def run_pipeline(steps, cache):
    by_name = {s["name"]: s for s in steps}
    outputs, keys, executed, cached = {}, {}, [], []
    for name in topo_order(steps):
        step = by_name[name]
        key = step_key(step, keys)
        if key in cache:
            outputs[name] = cache[key]
            cached.append(name)
        else:
            outputs[name] = cache[key] = step["fn"]({d: outputs[d] for d in step["deps"]}, step["params"])
            executed.append(name)
        keys[name] = key
    return {"outputs": outputs, "keys": keys, "executed": executed, "cached": cached}

def load(inputs, params):
    return {"x": [1, 2, 3, 4, 5, 6, 7, 8], "y": [2.1, 3.9, 6.2, 7.8, 10.1, 12.2, 13.9, 16.1]}

def split(inputs, params):
    d, n = inputs["load"], int(8 * params["train_fraction"])
    return {"train": [d["x"][:n], d["y"][:n]], "test": [d["x"][n:], d["y"][n:]]}

def train(inputs, params):
    xs, ys = inputs["split"]["train"]
    return {"w": round(sum(x * y for x, y in zip(xs, ys)) / sum(x * x for x in xs), 4)}

def evaluate(inputs, params):
    xs, ys = inputs["split"]["test"]
    w = inputs["train"]["w"]
    return {"mse": round(sum((w * x - y) ** 2 for x, y in zip(xs, ys)) / len(xs), 4)}

def make_steps(train_fraction=0.75, train_version="1"):
    return [
        {"name": "load", "deps": [], "params": {}, "version": "1", "fn": load},
        {"name": "split", "deps": ["load"], "params": {"train_fraction": train_fraction}, "version": "1", "fn": split},
        {"name": "train", "deps": ["split"], "params": {}, "version": train_version, "fn": train},
        {"name": "evaluate", "deps": ["split", "train"], "params": {}, "version": "1", "fn": evaluate},
    ]

cache = {}
runs = [("первый запуск", make_steps()), ("тот же запуск", make_steps()),
        ("train_fraction 0.5", make_steps(train_fraction=0.5)), ("version train = 2", make_steps(train_fraction=0.5, train_version="2"))]
for title, steps in runs:
    res = run_pipeline(steps, cache)
    print(f"{title:20} выполнено: {res['executed']}  из кеша: {res['cached']}")
print("результат:", res["outputs"]["evaluate"], "| записей в кеше:", len(cache))
```
```output
первый запуск        выполнено: ['load', 'split', 'train', 'evaluate']  из кеша: []
тот же запуск        выполнено: []  из кеша: ['load', 'split', 'train', 'evaluate']
train_fraction 0.5   выполнено: ['split', 'train', 'evaluate']  из кеша: ['load']
version train = 2    выполнено: ['train', 'evaluate']  из кеша: ['load', 'split']
результат: {'mse': 0.0309} | записей в кеше: 9
```

Разбор:

* `step_key` хеширует каноническую запись из имени, версии, параметров и ключей зависимостей. Так ключ шага зависит от всей цепочки выше него;
* `run_pipeline` идёт по шагам в топологическом порядке. Если ключ уже в `cache`, берётся готовый результат, иначе вызывается `fn(inputs, params)`. В `inputs` попадают только результаты зависимостей шага, больше ничего;
* первый запуск выполняет все четыре шага, второй - ни одного: ключи те же, функции не вызываются;
* смена `train_fraction` в `split` пересчитывает `split`, `train` и `evaluate`, а `load` остаётся в кеше: его ключ от `train_fraction` не зависит;
* смена `version` у `train` пересчитывает `train` и `evaluate`, но не `split`: ключ `split` не зависит от шагов ниже него. Значения `version` мы поднимаем сами, когда меняется код шага;
* в кеше девять записей: четыре от первого запуска, три от запуска с `train_fraction=0.5` и две от запуска с новой версией. Прежние записи никуда не делись, поэтому возврат к старым параметрам снова даст попадание в кеш;
* `topo_order` здесь сокращена: проверок на цикл и неизвестные зависимости нет, в упражнении они нужны.

**Пример 2. Порядок выполнения и цикл.** Алгоритм Кана повторно выбирает шаг без непройденных зависимостей. Когда готовых шагов несколько, берём первый по алфавиту: тогда один и тот же граф всегда выполняется в одном и том же порядке.

```python run
def topo_order(deps):
    """deps: {шаг: [зависимости]}. Алгоритм Кана; из готовых шагов берём первый по алфавиту."""
    pending = {name: len(set(d)) for name, d in deps.items()}
    ready, order = sorted(n for n, k in pending.items() if k == 0), []
    while ready:
        name = ready.pop(0)
        order.append(name)
        for other, d in deps.items():
            if name in d:
                pending[other] -= 1
                if pending[other] == 0:
                    ready.append(other)
        ready.sort()
    if len(order) != len(deps):
        raise ValueError(f"цикл среди шагов {sorted(set(deps) - set(order))}")
    return order

diamond = {"report": ["left", "right"], "left": ["load"], "right": ["load"], "load": []}
print(topo_order(diamond))

try:
    topo_order({"a": ["b"], "b": ["c"], "c": ["a"], "free": []})
except ValueError as exc:
    print("ошибка:", exc)
```
```output
['load', 'left', 'right', 'report']
ошибка: цикл среди шагов ['a', 'b', 'c']
```

Разбор: из ромба `load -> left, right -> report` сначала выходит `load` (единственный готовый шаг), затем `left` и `right` по алфавиту, и только после обоих - `report`. Во втором вызове шаги `a`, `b`, `c` ждут друг друга по кругу, и ни один никогда не станет готовым: порядок получился короче числа шагов, это и есть признак цикла. Шаг `free` без зависимостей в порядок попал, но он не спасает граф. Самозависимость (`"a": ["a"]`) обнаруживается так же.

**Пример 3. Устаревший кеш.** Ключ не включает код функции. Исправили код, но не поменяли `version` - и получили старый результат.

```python run
import hashlib
import json

def key_of(name, version, params, dep_keys):
    payload = {"name": name, "version": version, "params": params, "deps": dep_keys}
    text = json.dumps(payload, sort_keys=True, separators=(",", ":"))
    return hashlib.sha256(text.encode("utf-8")).hexdigest()[:16]

cache = {}

def run(fn, version):
    key = key_of("scale", version, {"k": 2}, {})
    if key not in cache:
        cache[key] = fn(10, 2)
        return "выполнено", cache[key]
    return "из кеша", cache[key]

def scale_v1(x, k):
    return x * k

def scale_v2(x, k):      # исправили код: теперь добавляется смещение
    return x * k + 1

print(run(scale_v1, "1"))
print(run(scale_v2, "1"))    # код другой, version не меняли
print(run(scale_v2, "2"))    # version изменили
```
```output
('выполнено', 20)
('из кеша', 20)
('выполнено', 21)
```

Разбор: `scale_v1` вернула `10 * 2 = 20` и записала результат в кеш под ключом, зависящим от имени, версии и параметров. `scale_v2` отличается кодом (добавлено смещение `+ 1`), но ключ у неё тот же, поэтому второй вызов вернул `20` из кеша - результат устарел. Третий вызов с `version="2"` получил другой ключ и посчитал `21`. Вывод: изменили код шага - поднимите его `version`. Более надёжный, но и более дорогой путь - включать в ключ хеш исходного текста функции или файла со скриптом: тогда версию не забыть, зато лишний пробел в коде сбросит кеш.

**Попробуйте.** В примере 1 добавьте независимую ветку: шаг `stats` с `deps=["load"]`, который считает среднее значение `y`. Предскажите, какие шаги выполнятся при первом запуске, а какие при смене `train_fraction`. Проверьте, что `stats` берётся из кеша во втором случае.

## Контракт шага и ключ кеша

**Контракт шага.** Шаг - функция `fn(inputs, params)`:

* `inputs` содержит результаты ровно тех шагов, что перечислены в `deps`;
* результат зависит только от `inputs` и `params` (чистая функция): чтение «текущего времени», случайные числа без фиксированного seed, обращение к «последней выгрузке» нарушают контракт и делают кеш ненадёжным;
* результат сериализуется в JSON: так его можно положить в кеш, на диск или в удалённое хранилище, а не только в память процесса.

**Топологический порядок.** Граф шагов должен быть ациклическим. Алгоритм Кана хранит для каждого шага число непройденных зависимостей; шаги с нулём готовы. Берём готовый, добавляем в порядок и уменьшаем счётчики зависимых. Если порядок получился короче числа шагов - в графе цикл. Остальные ошибки - зависимость от несуществующего шага и повторяющееся имя - проверяются заранее, до запуска любой функции: нет смысла полчаса обучать модель, чтобы затем узнать, что граф описан неверно.

**Ключ кеша.** `key = sha256(canonical_json({name, version, params, deps: {dep: key_of_dep}}))[:16]`. Это дерево Меркла в миниатюре: ключ шага зависит от ключей зависимостей, те - от своих, и так до корня. Изменение любой «листовой» детали (параметр корневого шага) меняет ключи всех шагов ниже, а шаги вне этой цепочки остаются прежними, поэтому независимые ветки не пересчитываются.

**Что входит в ключ.**

| Вход шага | Как попадает в ключ |
|---|---|
| Параметры шага | напрямую, через `params` |
| Результаты зависимостей | через ключи зависимостей |
| Код функции | через вручную поднимаемую `version` (или хеш исходного текста) |
| Версия данных | как параметр корневого шага, например `{"data_version": "76917f82d3e0"}` |
| Окружение (версии библиотек, seed) | как параметры или часть `version` |

**Два способа решить, что пересчитывать.** Мы хешируем *описание* шага (версия, параметры, ключи зависимостей) и не смотрим на сами результаты. Это дёшево и не требует читать большие выходы. DVC и подобные инструменты хешируют *содержимое файлов*, которые шаг читает и пишет: надёжнее, когда результат зависит от файлов, но нужно хешировать большие данные. Есть и тонкость: если два разных набора параметров дали бы побайтово одинаковый результат, то по ключам описания следующий шаг всё равно пересчитается, а по хешу содержимого - нет. Выбор между способами - компромисс между стоимостью ключа и количеством лишних пересчётов.

**Соответствие инструментам.** В DVC конвейер описывается в `dvc.yaml`: у стадии есть команда, зависимости, параметры и выходы, а `dvc repro` пересчитывает только устаревшие стадии. Оркестраторы (Airflow, Prefect, Kubeflow Pipelines) занимаются другим: расписание, повторы при сбоях, распределённое выполнение, а граф зависимостей у них тот же. Конкретные возможности зависят от версии, сверяйтесь с документацией ([DVC](https://dvc.org/doc)).

| Наш код | DVC и оркестраторы (по общей идее) |
|---|---|
| шаг `{"name", "deps", "params", "version", "fn"}` | стадия в `dvc.yaml` или задача в графе оркестратора |
| `topo_order` | порядок выполнения стадий или задач по зависимостям |
| `step_key` и словарь `cache` | сравнение хешей зависимостей, параметров и команды; кеш выходов |
| `run_pipeline` | `dvc repro` или запуск графа оркестратором |

## Типичные ошибки

* **Изменили код шага, но не `version`.** Кеш вернёт старый результат (пример 3). Договоритесь: правка функции шага = новая `version`, и проверяйте это на ревью или автоматически, хешируя исходный текст.
* **Скрытый вход шага.** Функция читает файл по абсолютному пути, текущее время или переменную окружения, а в `params` об этом нет ни слова. Ключ не меняется при смене такого входа, и кеш устаревает. Все входы должны быть либо в `inputs`, либо в `params`.
* **Изменение входов внутри шага.** Если `fn` изменяет полученный в `inputs` список на месте, портится результат, лежащий в кеше и используемый другими шагами. Создавайте новые объекты, а не правьте входные.
* **Недетерминированный шаг.** Случайность без seed в параметрах даёт разные результаты для одного ключа: в кеш попадёт один из них, а остальные запуски его «воспроизведут». Seed - часть `params` ([воспроизводимость](lesson:mlops.fundamentals.reproducibility)).
* **Результат, который не сериализуется.** Если в кеш кладут объект модели прямо из памяти, им нельзя воспользоваться в другом процессе. Результат шага должен быть JSON-совместимым или ссылкой на файл с известным хешем.
* **Неполный граф.** Если шаг зависит от результата другого, но не указал его в `deps`, порядок выполнения не гарантирован, а ключ не отразит изменений. Зависимости объявляются явно.
* **Нестабильный порядок выбора готовых шагов.** Без правила (например, «первый по алфавиту») порядок зависит от порядка обхода словаря или множества, и логи двух запусков не сравнить.
* **Бесконечный кеш.** Старые записи копятся. Решите, когда их чистить: по возрасту, по размеру или при сборке мусора (как неиспользуемые объекты в уроке про версионирование данных).

## Итоги

* Конвейер - это шаги с явными зависимостями и контрактом «результат зависит только от входов и параметров»; без скрытого состояния ноутбука.
* Топологический порядок с детерминированным правилом выбора делает запуск повторяемым, а ошибки графа (цикл, неизвестная зависимость, дубликат имени) обнаруживаются до запуска.
* Ключ кеша = имя, версия, параметры и ключи зависимостей. Изменение расходится вниз по графу, независимые ветки остаются в кеше. Правка кода требует новой `version`.
* Мы собрали четыре детали платформы: отпечаток конфигурации, журнал запусков, версию данных и конвейер с кешем. Обученную модель нужно где-то хранить и выдавать в продакшен: [реестр моделей](lesson:mlops.fundamentals.model-registry).

## Кратко для тех, кто знаком с ML

* Шаг = чистая функция `(inputs, params) -> output`; граф шагов - DAG; порядок - алгоритм Кана с детерминированным выбором среди готовых.
* Ключ шага = `sha256(canonical_json({name, version, params, deps: {dep: dep_key}}))[:16]`; кеш `{key: output}`; пересчитывается шаг с изменённым ключом и всё ниже.
* DVC хеширует содержимое файлов, мы - описание шага; код должен быть частью ключа (`version` или хеш исходника).
* В DVC это стадии `dvc.yaml` и команда `dvc repro`; оркестраторы добавляют расписание и повторы.
