## Зачем MLOps начинается с воспроизводимости

Модель в продакшене - это не только файл с весами. Через месяц кто-то спросит: «на каких данных, с какими параметрами и каким кодом её обучили, и почему новая версия хуже?». Если ответить нельзя, модель нельзя ни исправить, ни честно сравнить с новой. **MLOps** (machine learning operations) - набор практик, который делает путь «данные → обучение → модель → обслуживание → мониторинг» повторяемым и проверяемым, как DevOps делает повторяемой поставку обычного кода.

В этом курсе мы шаг за шагом соберём мини-платформу на стандартной библиотеке Python: отпечатки конфигураций, журнал экспериментов, версии данных по хешам, конвейер с кешем, реестр моделей, функцию обслуживания и мониторинг дрейфа. Каждый урок добавляет одну деталь. Настоящие инструменты (MLflow, DVC, Docker, Kubernetes) мы разбираем в теории и показываем, какой их части соответствует наш код: упражнения выполняются без сети и без внешних сервисов, поэтому проверяются детерминированно.

Первая деталь - **воспроизводимость**: один и тот же запуск с той же конфигурацией и теми же данными должен давать тот же результат. Для этого нужны три вещи:

* **фиксированный seed** - начальное значение генератора случайных чисел, чтобы «случайные» решения (инициализация весов, перемешивание) повторялись;
* **отпечаток конфигурации** (fingerprint) - короткий идентификатор, который однозначно определяется параметрами запуска и меняется при любом их изменении;
* **устойчивое разбиение данных** - объект попадает в train или test по правилу, которое не зависит от того, какие ещё объекты есть в наборе.

## Примеры

**Пример 1. Seed делает «случайность» повторяемой.** Собственный генератор `random.Random(seed)` выдаёт одну и ту же последовательность при одном и том же seed.

```python run
import random

def train_model(seed):
    rng = random.Random(seed)
    weights = [round(rng.uniform(-1, 1), 3) for _ in range(3)]
    return weights

print("seed=7 :", train_model(7))
print("seed=7 :", train_model(7))
print("seed=8 :", train_model(8))
```
```output
seed=7 : [-0.352, -0.698, 0.302]
seed=7 : [-0.352, -0.698, 0.302]
seed=8 : [-0.547, 0.925, -0.747]
```

Разбор: `random.Random(seed)` создаёт генератор с собственным состоянием, поэтому соседний код, вызывающий `random.random()`, не сдвинет нашу последовательность. Первые два вызова совпадают до последней цифры; другой seed - другие «случайные» веса.

**Пример 2. Отпечаток конфигурации.** Два словаря с одинаковыми параметрами в разном порядке - это одна конфигурация. Обычный `json.dumps` сохраняет порядок вставки, поэтому строки различаются; каноническая запись сортирует ключи и убирает пробелы.

```python run
import hashlib
import json

def canonical_json(obj):
    return json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False)

def fingerprint(cfg):
    return hashlib.sha256(canonical_json(cfg).encode("utf-8")).hexdigest()[:12]

a = {"model": "logreg", "lr": 0.1, "seed": 42}
b = {"seed": 42, "lr": 0.1, "model": "logreg"}
print(json.dumps(a) == json.dumps(b))
print(canonical_json(a))
print(fingerprint(a), fingerprint(b))
print(fingerprint({**a, "lr": 0.01}))
print(fingerprint({**a, "seed": "42"}))
```
```output
False
{"lr":0.1,"model":"logreg","seed":42}
344ef8961401 344ef8961401
9ed071d22bc4
834336d7d2d9
```

Разбор построчно:

* `sort_keys=True` - ключи по алфавиту на всех уровнях вложенности, порядок вставки больше не важен;
* `separators=(",", ":")` - без пробелов, иначе две библиотеки с разным форматированием дали бы разные строки;
* `ensure_ascii=False` - кириллица пишется как есть, а не как `и`; хеш считаем от UTF-8 байтов;
* `allow_nan=False` - `NaN` и бесконечность не входят в стандарт JSON, и `json.dumps` по умолчанию пишет их нестандартным словом `NaN`; мы предпочитаем сразу получить `ValueError`;
* последние две строки: изменение `lr` и даже тип seed (`"42"` вместо `42`) меняют отпечаток. Это правильно: строка и число - разные конфигурации.

**Пример 3. Разбиение по хешу не «плывёт» при росте данных.** Случайное разбиение с тем же seed после добавления 100 новых пользователей перетасует и старых. Разбиение по хешу id решает судьбу каждого объекта независимо от остальных.

```python run
import hashlib
import random

def random_split(ids, test_frac, seed):
    idx = list(ids)
    random.Random(seed).shuffle(idx)
    n_test = int(len(idx) * test_frac)
    return set(idx[n_test:]), set(idx[:n_test])

def hash_split(ids, test_percent, salt):
    test = {i for i in ids
            if int(hashlib.sha256(f"{salt}:{i}".encode("utf-8")).hexdigest(), 16) % 100 < test_percent}
    return set(ids) - test, test

old = [f"user-{i}" for i in range(1000)]
new = old + [f"user-{i}" for i in range(1000, 1100)]   # пришли новые пользователи

_, t1 = random_split(old, 0.2, seed=1)
_, t2 = random_split(new, 0.2, seed=1)
print("случайное: старых объектов сменили часть:", len([i for i in old if (i in t1) != (i in t2)]))

_, h1 = hash_split(old, 20, "v1")
_, h2 = hash_split(new, 20, "v1")
print("по хешу:   старых объектов сменили часть:", len([i for i in old if (i in h1) != (i in h2)]))
print("по хешу:   доля test %.3f" % (len(h2) / len(new)))
```
```output
случайное: старых объектов сменили часть: 274
по хешу:   старых объектов сменили часть: 0
по хешу:   доля test 0.200
```

При случайном разбиении 274 старых объекта сменили часть: часть бывшего теста попала в обучение следующей модели, и сравнение «старая модель против новой на тесте» становится нечестным (это утечка из урока [про выборки](lesson:ml.foundations.what-is-ml)). По хешу ни один старый объект не переехал, а доля теста осталась около 20%.

**Попробуйте.** В примере 3 поменяйте соль `"v1"` на `"v2"`: разбиение станет другим, но по-прежнему стабильным. Предскажите, сколько старых объектов сменит часть между `h1` и `h2`, если обе вычислены с солью `"v2"`.

## Источники недетерминизма

Запуск обучения воспроизводим, если совпадают **код**, **данные**, **конфигурация** и **окружение**, а все случайные решения выведены из записанного seed. Типичные источники расхождений:

| Источник | Что делать |
|---|---|
| Глобальный генератор (`random.seed`, `np.random.seed`) | создавать собственный генератор из seed конфигурации: `random.Random(seed)`, `np.random.default_rng(seed)`, `torch.Generator().manual_seed(seed)` |
| Порядок файлов и ключей | сортировать списки файлов (`sorted(os.listdir(...))`), канонизировать словари |
| `hash()` строк в Python | рандомизирован между запусками (переменная `PYTHONHASHSEED`); для разбиений и ключей кеша использовать `hashlib` |
| Многопоточность и GPU | параллельное сложение чисел с плавающей точкой зависит от порядка; в PyTorch есть режим детерминированных алгоритмов, но он медленнее и покрывает не все операции |
| Версии библиотек | фиксировать точные версии (`requirements.txt` с `==`, lock-файлы), записывать их рядом с результатом |
| Данные «на сегодня» | ссылаться на версию данных (урок 3), а не на «последнюю выгрузку» |

Полная побитовая воспроизводимость на разных машинах часто недостижима (другая видеокарта, другая библиотека линейной алгебры). Практическая цель скромнее: один и тот же запуск на той же машине даёт тот же результат, а на другой - результат в пределах допуска, и все входы запуска записаны.

## Каноническая форма и отпечаток

**Каноническая форма** - единственная запись для множества эквивалентных представлений. Для конфигурации-словаря это JSON с ключами по алфавиту на всех уровнях и фиксированными разделителями. **Отпечаток** - криптографический хеш (SHA-256) канонической формы, обычно сокращённый до 8-12 шестнадцатеричных символов для удобства. SHA-256 детерминирован на всех платформах, а случайное совпадение отпечатков двух разных конфигураций при 12 символах (48 бит) для тысяч запусков практически исключено.

Отпечаток удобно использовать как имя каталога запуска, ключ кеша (урок 4) и поле в карточке модели: по нему видно, обучены ли две модели с одной конфигурацией.

## Разбиение по хешу

Объекту с идентификатором `id` назначается **корзина** `bucket = int(sha256(f"{salt}:{id}")) % 100`. Объект уходит в test, если `bucket < test_percent`. Свойства:

* решение зависит только от `id` и **соли** (salt), поэтому добавление и удаление других объектов его не меняет;
* доля test стремится к `test_percent`% при большом числе объектов, но для 10 объектов может заметно отличаться;
* смена соли даёт новое независимое разбиение (например, для нового эксперимента);
* идентификатор должен быть стабильным свойством объекта (id пользователя, а не номер строки в выгрузке): номер строки меняется при сортировке, и разбиение «поплывёт».

Если у объектов есть группы (несколько записей одного пользователя), хешируют идентификатор **группы**: тогда все записи пользователя окажутся в одной части.

## Типичные ошибки

* **`hash(id)` вместо `hashlib`.** Встроенный `hash` строк рандомизирован при каждом запуске интерпретатора, поэтому «стабильное» разбиение меняется от запуска к запуску. Проверить: запустите `python3 -c "print(hash('a'))"` дважды.
* **Отпечаток от `str(cfg)` или `json.dumps(cfg)` без `sort_keys`.** Два равных словаря с разным порядком ключей получают разные отпечатки, и кеш никогда не срабатывает.
* **`1` и `1.0` в конфигурации.** `canonical_json({"lr": 1})` даёт `{"lr":1}`, а `{"lr": 1.0}` - `{"lr":1.0}`; отпечатки разные. Приводите типы при чтении конфигурации, а не надейтесь на совпадение.
* **NaN в параметрах.** `json.dumps(float("nan"))` по умолчанию даёт `NaN`, который другие парсеры JSON не примут. С `allow_nan=False` ошибка `ValueError: Out of range float values are not JSON compliant: nan` появится сразу.
* **Разбиение по номеру строки.** После пересортировки выгрузки объекты меняют номера, и тест перемешивается с обучением. Хешируйте устойчивый id.
* **Один seed «на всё».** Если инициализация весов и перемешивание берут числа из одного генератора, добавление одного вызова `rng.random()` сдвинет всё остальное. Заводите отдельные генераторы для разных целей: `random.Random(f"{seed}:shuffle")` и `random.Random(f"{seed}:init")`.

<!-- section: summary -->
## Итоги

* Воспроизводимый запуск = записанные код, данные, конфигурация, окружение и seed.
* Каноническая JSON-форма (`sort_keys`, компактные разделители, UTF-8, без NaN) превращает эквивалентные конфигурации в одну строку, а SHA-256 от неё - в короткий отпечаток.
* Разбиение по хешу id с солью стабильно при росте данных и не требует хранить списки индексов.
* В следующем уроке отпечаток станет частью журнала экспериментов: [трекинг экспериментов](lesson:mlops.fundamentals.experiment-tracking).

## Кратко для тех, кто знаком с ML

* Seed - только в собственные генераторы (`random.Random`, `np.random.default_rng`), не в глобальное состояние.
* Отпечаток конфигурации: `sha256(json.dumps(cfg, sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False).encode())[:12]`. Похожим образом инструменты вроде DVC строят ключи кеша из хешей входов, хотя формат у них свой.
* Разбиение по хешу id (как в системах A/B-тестов) стабильно при дозагрузке данных; встроенный `hash()` для этого не годится.
