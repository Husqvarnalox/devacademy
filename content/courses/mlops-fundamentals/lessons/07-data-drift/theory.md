## Зачем следить за данными, а не только за моделью

Модель обучена на данных прошлого, а работает с данными настоящего. Пока мир похож на обучающую выборку, качество держится. Когда он меняется - новый канал привлечения пользователей, другая цена, сбой в источнике данных, сезон - модель продолжает отвечать, но уже на задачи, которых не видела. Такое изменение называется **дрейфом** (drift).

Различают три разных явления:

| Что изменилось | Обозначение | Пример |
|---|---|---|
| Распределение входных признаков | P(x), **дрейф данных** (covariate drift) | пришла аудитория помоложе, средний доход упал |
| Распределение целевой величины | P(y), **дрейф меток** (prior / label drift) | доля мошеннических операций выросла с 1% до 3% |
| Связь входов и ответа | P(y \| x), **дрейф концепции** (concept drift) | те же клиенты с тем же доходом стали чаще уходить из-за нового конкурента |

Измерить качество прямо сейчас обычно нельзя. Правильные ответы (метки) приходят с задержкой: исход кредита известен через месяцы, возврат товара - через недели. Зато входные данные известны в момент запроса. Поэтому дрейф входных признаков - **ранний сигнал**: он не доказывает, что модель стала хуже, но говорит, что она работает в условиях, на которые не рассчитана, и стоит присмотреться.

В этом уроке мы напишем две меры расхождения двух выборок одного признака и отчёт по набору признаков:

* **PSI** (population stability index, индекс стабильности популяции) - сравнивает доли объектов по бинам;
* **KS** (статистика Колмогорова-Смирнова) - наибольший зазор между двумя эмпирическими функциями распределения.

Обе меры считаются по эталонной выборке (обычно это обучающие данные) и текущей выборке (окно последних запросов).

## Примеры

**Пример 1. PSI для одинаковых, сдвинутых и «растянутых» данных.** Эталон - 2000 чисел из нормального распределения. Границы бинов берём из его квантилей, поэтому в эталоне в каждом из 10 бинов около 10% объектов. Текущая выборка тем сильнее отличается по долям, чем сильнее она отличается по форме.

```python run
import bisect
import math
import random


def quantile_edges(reference, bins):
    s = sorted(reference)
    n = len(s)
    return [s[(i * n) // bins] for i in range(1, bins)]


def fractions(values, edges):
    counts = [0] * (len(edges) + 1)
    for x in values:
        counts[bisect.bisect_right(edges, x)] += 1
    return [c / len(values) for c in counts]


def psi(reference, current, bins=10, eps=1e-4):
    edges = quantile_edges(reference, bins)
    total = 0.0
    for e, a in zip(fractions(reference, edges), fractions(current, edges)):
        e, a = max(e, eps), max(a, eps)
        total += (a - e) * math.log(a / e)
    return total


def sample(seed, n, mu=0.0, sigma=1.0):
    rng = random.Random(seed)
    return [rng.gauss(mu, sigma) for _ in range(n)]


reference = sample(1, 2000)
print("границы (бины по 10%):", [round(e, 2) for e in quantile_edges(reference, 10)])
for name, current in [
    ("та же форма, другая выборка", sample(2, 2000)),
    ("среднее выросло на 0.5", sample(3, 2000, mu=0.5)),
    ("разброс вырос в 1.5 раза", sample(5, 2000, sigma=1.5)),
    ("среднее выросло на 2", sample(4, 2000, mu=2.0)),
]:
    print(f"{name:28s} PSI = {psi(reference, current):.4f}")
```
```output
границы (бины по 10%): [-1.26, -0.85, -0.51, -0.24, 0.02, 0.31, 0.59, 0.89, 1.28]
та же форма, другая выборка  PSI = 0.0142
среднее выросло на 0.5       PSI = 0.2280
разброс вырос в 1.5 раза     PSI = 0.1806
среднее выросло на 2         PSI = 3.5122
```

Разбор построчно:

* `quantile_edges` сортирует эталон и берёт значения на позициях `i * n // bins`: это границы 10%-квантилей; бинов на один больше, чем границ;
* `bisect.bisect_right(edges, x)` возвращает номер бина числа `x`; число, равное границе, уходит в правый бин;
* `max(e, eps)` защищает от `ln(0)` и деления на ноль, если бин пуст;
* каждый бин даёт слагаемое `(a - e) * ln(a / e)`: оно неотрицательно (если доля выросла, обе части положительны, если упала - обе отрицательны), поэтому PSI не меньше нуля, а равен нулю только при совпадении долей;
* другая выборка той же формы даёт 0.0142: это шум, а не дрейф. Сдвиг среднего на 0.5 даёт 0.2280, сдвиг на 2 - 3.5122, то есть почти вся текущая выборка лежит правее большинства границ.

**Пример 2. KS: наибольший зазор между функциями распределения.** Эмпирическая функция распределения F(x) - доля значений не больше x. KS - максимум модуля разности двух таких функций, поэтому лежит от 0 до 1.

```python run
import bisect
import random


def ks_statistic(a, b):
    sa, sb = sorted(a), sorted(b)
    best, best_x = 0.0, None
    for x in sorted(set(sa) | set(sb)):
        gap = abs(bisect.bisect_right(sa, x) / len(sa) - bisect.bisect_right(sb, x) / len(sb))
        if gap > best:
            best, best_x = gap, x
    return best, best_x


def sample(seed, n, mu=0.0, sigma=1.0):
    rng = random.Random(seed)
    return [rng.gauss(mu, sigma) for _ in range(n)]


reference = sample(1, 2000)
for name, current in [
    ("та же форма", sample(2, 2000)),
    ("среднее выросло на 0.5", sample(3, 2000, mu=0.5)),
    ("разброс вырос в 1.5 раза", sample(5, 2000, sigma=1.5)),
    ("среднее выросло на 2", sample(4, 2000, mu=2.0)),
]:
    d, x = ks_statistic(reference, current)
    print(f"{name:26s} KS = {d:.4f}, максимальный зазор при x = {x:.2f}")

d, _ = ks_statistic([1, 2, 3, 4], [3, 4, 5, 6])
print("[1, 2, 3, 4] против [3, 4, 5, 6]: KS =", d)
```
```output
та же форма                KS = 0.0410, максимальный зазор при x = 0.28
среднее выросло на 0.5     KS = 0.1955, максимальный зазор при x = 0.09
разброс вырос в 1.5 раза   KS = 0.1065, максимальный зазор при x = -1.38
среднее выросло на 2       KS = 0.6780, максимальный зазор при x = 0.97
[1, 2, 3, 4] против [3, 4, 5, 6]: KS = 0.5
```

Разбор построчно:

* `bisect_right(sa, x) / len(sa)` - доля значений выборки, не превышающих `x`, то есть F(x);
* достаточно перебрать только значения из обеих выборок: между ними обе функции постоянны;
* для сдвига на 2 зазор достигает 0.678, для той же формы - 0.0410; растянутая выборка (разброс 1.5) даёт 0.1065 с максимумом в хвосте, при x = -1.38;
* для `[1, 2, 3, 4]` и `[3, 4, 5, 6]` зазор равен 0.5: например, при x = 2 доля значений не выше x равна 0.5 в первой выборке и 0 во второй.

Сравните столбцы: растянутая выборка получила PSI 0.1806 и KS 0.1065, сдвиг на 0.5 - PSI 0.2280 и KS 0.1955. Меры измеряют разное: PSI суммирует отличия по всем бинам, KS показывает только самое большое расхождение, поэтому по шкалам их нельзя сравнивать напрямую.

**Пример 3. Размер выборки и шум.** Даже две выборки из одного распределения отличаются друг от друга. Чем меньше выборка, тем это заметнее.

```python run
import bisect
import math
import random


def quantile_edges(reference, bins):
    s = sorted(reference)
    return [s[(i * len(s)) // bins] for i in range(1, bins)]


def fractions(values, edges):
    counts = [0] * (len(edges) + 1)
    for x in values:
        counts[bisect.bisect_right(edges, x)] += 1
    return [c / len(values) for c in counts]


def psi(reference, current, bins=10, eps=1e-4):
    edges = quantile_edges(reference, bins)
    total = 0.0
    for e, a in zip(fractions(reference, edges), fractions(current, edges)):
        e, a = max(e, eps), max(a, eps)
        total += (a - e) * math.log(a / e)
    return total


def ks_statistic(a, b):
    sa, sb = sorted(a), sorted(b)
    return max(abs(bisect.bisect_right(sa, x) / len(sa) - bisect.bisect_right(sb, x) / len(sb))
               for x in sorted(set(sa) | set(sb)))


def sample(seed, n, mu=0.0):
    rng = random.Random(seed)
    return [rng.gauss(mu, 1.0) for _ in range(n)]


print("   n     PSI(без сдвига)  PSI(сдвиг 0.05)  KS(без сдвига)  KS(сдвиг 0.05)")
for n in (100, 1000, 10000, 100000):
    ref = sample(1, n)
    same = sample(2, n)
    tiny = sample(3, n, mu=0.05)
    print(f"{n:6d}   {psi(ref, same):14.4f}  {psi(ref, tiny):15.4f}  {ks_statistic(ref, same):14.4f}  {ks_statistic(ref, tiny):14.4f}")
```
```output
   n     PSI(без сдвига)  PSI(сдвиг 0.05)  KS(без сдвига)  KS(сдвиг 0.05)
   100           0.1856           0.2335          0.1900          0.1400
  1000           0.0120           0.0141          0.0310          0.0250
 10000           0.0012           0.0044          0.0065          0.0246
100000           0.0001           0.0020          0.0035          0.0202
```

Разбор: при `n = 100` две выборки **из одного распределения** дают PSI 0.1856 - это уже «предупреждение» по общепринятой шкале, хотя дрейфа нет. При `n = 100000` тот же показатель около 0.0001. Сдвиг в 0.05 стандартного отклонения при малых `n` тонет в шуме (KS 0.14 для сдвинутых данных ниже, чем 0.19 для несдвинутых), а при больших `n` становится различимым: KS около 0.02 при шуме 0.0035. Отсюда два вывода: на маленьких окнах пороги PSI надо подбирать осторожнее, а ничтожный дрейф на огромной выборке статистически заметен, но может не требовать действий.

**Попробуйте.** В примере 1 замените `bins=10` на `bins=5` и `bins=20`: PSI для одной и той же пары выборок изменится. Предскажите, станет ли он больше или меньше при увеличении числа бинов, и проверьте; затем объясните, почему пороги 0.1 и 0.25 нельзя считать универсальными.

## Формулы

**Границы бинов.** По эталонной выборке `s` длины `n`, отсортированной по возрастанию, берём `bins - 1` границ `edges[i - 1] = s[(i * n) // bins]` для `i = 1 .. bins - 1`. Число `x` попадает в бин с номером `bisect_right(edges, x)`: всего `len(edges) + 1` бинов. Если в эталоне много повторяющихся значений, некоторые границы совпадают, и часть бинов остаётся пустой даже в эталоне. Это допустимо, пустые доли заменяются на `eps`.

**PSI.** Пусть `e_i` - доля эталона в бине `i`, `a_i` - доля текущей выборки. Обе величины ограничиваем снизу: `e_i = max(e_i, eps)`, `a_i = max(a_i, eps)`, `eps = 1e-4`. Тогда

`PSI = сумма по бинам (a_i - e_i) * ln(a_i / e_i)`.

Свойства:

* PSI не меньше нуля и равен нулю при одинаковых долях;
* PSI зависит от числа бинов и от размера выборок: на малых выборках шум даёт ненулевой PSI (пример 3);
* границы строятся по эталону, поэтому `psi(A, B)` и `psi(B, A)` в общем случае различаются;
* значения вне диапазона эталона попадают в крайние бины: сдвиг далеко вправо виден как «все объекты в последнем бине».

**Пороги 0.1 и 0.25.** Часто используют такую шкалу: PSI ниже 0.1 - распределения практически совпадают, от 0.1 до 0.25 - умеренный сдвиг, от 0.25 - существенный. Это **отраслевое соглашение** (по распространённой версии, оно пришло из практики кредитного скоринга), а не статистический закон. Подходящие пороги зависят от числа бинов, размера выборки и цены ошибки, поэтому в реальной системе их проверяют на своих данных, например смотрят, какие значения PSI давали «нормальные» недели.

**KS.** Для двух выборок `a` и `b` статистика `D = max_x |F_a(x) - F_b(x)|`: наибольшее вертикальное расстояние между эмпирическими функциями распределения. Она равна 0 при совпадающих функциях и 1, если все значения одной выборки меньше всех значений другой (диапазоны не перекрываются). В `scipy.stats.ks_2samp` рядом со статистикой возвращается ещё p-value, то есть вероятность увидеть такое расхождение при одинаковых распределениях. Мы p-value не считаем.

**Размер эффекта и статистическая значимость.** При очень больших выборках p-value критерия становится ничтожным даже для крошечного, практически не важного сдвига: критерий отвечает на вопрос «есть ли вообще различие», а не «насколько оно велико». Поэтому для мониторинга обычно следят за **размером эффекта** - самими значениями PSI и KS, а не только за p-value.

## Отчёт по признакам

`drift_report` проходит по признакам эталона в алфавитном порядке. Для каждого: если в текущих данных признака нет или список пуст - статус `missing` (это тоже сигнал: источник данных мог сломаться); иначе считаем PSI и KS и присваиваем статус по шкале: `ok` при `psi < psi_warn`, `warn` при `psi < psi_alert`, иначе `alert`. В отчёте PSI и KS округлены до четырёх знаков, а статус определяется по неокруглённому PSI.

## Как это соотносится с реальными инструментами

| В нашем коде | Что есть в реальных инструментах |
|---|---|
| `psi`, `ks_statistic` | готовые метрики и статистические тесты в библиотеках мониторинга (Evidently, whylogs, NannyML) и в `scipy.stats` |
| `drift_report` | отчёты и панели по дрейфу признаков, часто с настраиваемыми порогами и окнами |
| эталон из обучающих данных | «reference» набор: обучающая выборка или период, который считается нормальным |
| окно текущих запросов | логи предсказаний за последние часы или дни |

Evidently, whylogs и NannyML - открытые библиотеки для мониторинга данных и моделей; набор метрик, пороги по умолчанию и интерфейс различаются между инструментами и версиями, поэтому сверяйтесь с документацией выбранной библиотеки. NannyML, по описанию в документации, отдельно занимается оценкой качества без меток. Идея у всех общая: сравнить окно текущих данных с эталоном и сигнализировать о расхождении.

## Типичные ошибки

* **Границы бинов по текущим данным.** Тогда доли текущей выборки всегда равномерны, и сдвиг не виден. Границы строят по эталону и фиксируют.
* **Нет нижнего порога доли.** Пустой бин даёт `ln(0)` или деление на ноль. Заменяйте доли на `eps`, как в уроке.
* **Принимать 0.25 за закон.** Это соглашение. На окне из 100 объектов шум даёт PSI около 0.19 без всякого дрейфа (пример 3).
* **Считать дрейф входов дрейфом качества.** Высокий PSI говорит об изменении данных, но модель может по-прежнему работать хорошо, а при низком PSI возможен дрейф концепции, который PSI не заметит.
* **Смотреть только на p-value.** На больших выборках любой микроскопический сдвиг даёт «значимое» расхождение; ориентируйтесь на размер эффекта и на порог, выбранный под задачу.
* **Мерить только по одному признаку.** Каждый признак в норме, но их сочетания изменились: одномерные меры этого не видят.
* **Игнорировать пропавшие признаки.** Если признак перестал приходить, это не «нет дрейфа», а повод проверить источник; в отчёте такой признак получает статус `missing`.
* **Сравнивать с «вчера» вместо стабильного эталона.** Медленный дрейф при сравнении с соседними днями не накапливается, а сравнение с обучающими данными его показывает.

<!-- section: summary -->
## Итоги

* Дрейф данных P(x), меток P(y) и концепции P(y | x) - разные явления; по входам мы видим только первое и косвенно судим об остальных.
* Метки приходят с задержкой, поэтому дрейф входов служит ранним сигналом, но не заменяет измерение качества.
* PSI суммирует отличия долей по бинам эталона, KS показывает наибольший зазор между функциями распределения; обе меры зависят от выборки.
* Пороги PSI 0.1 и 0.25 - соглашение, а не закон; следите за размером эффекта и проверяйте пороги на своих данных.
* В следующем уроке соберём качество с запоздавшими метками, правила тревог и решение о переобучении: [мониторинг качества и тревоги](lesson:mlops.fundamentals.quality-monitoring-and-alerts).

## Кратко для тех, кто знаком с ML

* PSI: границы - квантили эталона (`s[i * n // bins]`), доли с нижним порогом `eps`, сумма `(a - e) * ln(a / e)`. Типичная шкала 0.1 / 0.25 - соглашение.
* KS: `max |F_a - F_b|` по объединённым точкам; p-value в `scipy.stats.ks_2samp` здесь не считаем.
* `drift_report`: статусы `ok` / `warn` / `alert` по PSI, `missing` для пропавших признаков; PSI и KS округляются до 4 знаков.
* Малые окна шумят: подбирайте пороги по историческим значениям и размеру окна.
