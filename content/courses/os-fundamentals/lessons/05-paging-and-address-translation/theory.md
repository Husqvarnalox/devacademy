## Иллюзия личной памяти

Каждый [процесс](lesson:os.fundamentals.processes-and-system-calls) видит собственное **виртуальное адресное пространство**: непрерывный диапазон адресов, начинающийся с нуля, в котором лежат код, куча и стек. Физическая память при этом общая, а процессов много, и они не должны видеть чужие данные. Решение - трансляция адресов: адрес в программе (виртуальный) аппаратура (MMU, memory management unit) переводит в физический адрес на лету, по таблице, которую ведёт ядро для каждого процесса.

Что это даёт:

* **Изоляция.** Процесс может адресовать только то, что для него отображено.
* **Удобство.** Каждая программа считает, что память начинается с нуля и непрерывна, хотя в физической памяти она разбросана.
* **Гибкость.** Часть пространства можно не отображать вовсе, отобразить один и тот же кадр в двух процессах (общая память), поместить страницу на диск ([следующий урок](lesson:os.fundamentals.virtual-memory-page-replacement)).

В C и C++ ошибка «обращение к невыделенной памяти» (см. [неопределённое поведение](lesson:cpp.fundamentals.undefined-behaviour)) - это часто и есть ошибка страницы: адрес, для которого таблица не содержит действительного отображения.

## Страницы и кадры

Память делится на блоки одного размера: виртуальные **страницы** и физические **кадры** (frames). Размер - степень двойки (обычно 4 КиБ, но зависит от системы). Виртуальный адрес из `a` бит при странице `2^k` байт делится:

```
| VPN (a - k бит) | смещение (k бит) |
```

Ключевое свойство: **смещение не меняется**, меняется только номер. Если страница `VPN` отображена на кадр `PFN`, то

`физический адрес = PFN * размер_страницы + смещение` (или в битах: `PFN << k | смещение`).

Для степеней двойки деление и остаток заменяются сдвигом и маской: `vpn = addr >> k`, `offset = addr & (page_size - 1)`.

## Таблица страниц

Таблица страниц - массив записей **PTE** (page table entry), индексируемый VPN. Запись содержит:

* **бит присутствия/валидности** (страница отображена на кадр);
* **номер кадра** PFN;
* **права**: чтение, запись, исполнение, доступ пользователя;
* служебные биты: «обращались» (accessed), «изменялась» (dirty).

Если запись недействительна или нарушены права, процессор вызывает **ошибку страницы** (page fault) - исключение, обработчик которого принадлежит ядру. Оно либо загрузит страницу (если она была вытеснена), либо завершит процесс сигналом (Unix: `SIGSEGV`).

**Стоимость.** Линейная таблица для 32-битного адреса и страниц по 4 КиБ содержит `2^20` записей. При 4 байтах на запись это 4 МиБ на каждый процесс, даже если используется малая часть. Для 64-битных адресов линейная таблица невозможна.

## TLB

Каждое обращение к памяти требовало бы ещё одного обращения к таблице страниц. Поэтому процессор держит **TLB** (translation lookaside buffer) - небольшой быстрый кэш трансляций `VPN -> PFN`. При обращении сначала ищут в TLB: **попадание** (hit) - физический адрес готов сразу; **промах** (miss) - проходим таблицу страниц, и если страница действительна, заносим запись в TLB (вытесняя старую, часто по LRU). TLB работает потому, что обращения локальны: программа много раз обращается к одним и тем же страницам. При переключении процесса записи TLB нужно сбросить либо пометить идентификатором адресного пространства; это одна из причин, по которым [переключение контекста](lesson:os.fundamentals.processes-and-system-calls) дорого.

## Многоуровневые таблицы

Чтобы не хранить таблицу для неиспользуемых областей, VPN делят на части. Двухуровневая схема для 32-битного адреса и страниц по 4 КиБ: `| 10 бит: каталог | 10 бит: таблица | 12 бит: смещение |`. Корневая таблица (каталог) содержит указатели на таблицы второго уровня; таблицы для неиспользуемых областей **не создаются** вовсе. Цена - дополнительные обращения к памяти при промахе TLB (по одному на уровень). В 64-битных системах уровней бывает четыре и больше.

<!-- section: examples -->
## Разбор адреса

Адрес 32 бита, страница 4 КиБ:

```python run
PAGE_SIZE = 4096                 # 2**12
K = 12

addr = 0x12345678
vpn, offset = divmod(addr, PAGE_SIZE)
print(hex(vpn), hex(offset))
print(hex(addr >> K), hex(addr & (PAGE_SIZE - 1)))
print("бит в VPN:", 32 - K, "записей в линейной таблице:", 2 ** (32 - K))
print("размер таблицы при 4 байтах на запись:", 2 ** (32 - K) * 4 // 2 ** 20, "МиБ")
```
```output
0x12345 0x678
0x12345 0x678
бит в VPN: 20 записей в линейной таблице: 1048576
размер таблицы при 4 байтах на запись: 4 МиБ
```

## Двухуровневая схема

Тот же адрес, но VPN разделён на два индекса по 10 бит:

```python run
addr = 0x12345678
directory = addr >> 22
table_index = (addr >> 12) & 0x3FF
offset = addr & 0xFFF
print(hex(directory), hex(table_index), hex(offset))
print(directory << 22 | table_index << 12 | offset == addr)
```
```output
0x48 0x345 0x678
True
```

## Трансляция по таблице

Учебный пример OSTEP: адресное пространство 64 байта, страницы по 16 байт, виртуальные страницы 0..3 отображены на кадры 3, 7, 5, 2:

```python run
PAGE = 16
table = {0: 3, 1: 7, 2: 5, 3: 2}


def translate(addr):
    vpn, offset = divmod(addr, PAGE)
    pfn = table.get(vpn)
    if pfn is None:
        raise LookupError(f"PAGE FAULT на странице {vpn}")
    return pfn * PAGE + offset


for va in (21, 0, 47, 63):
    print(va, "->", translate(va))

try:
    translate(64)
except LookupError as e:
    print(e)
```
```output
21 -> 117
0 -> 48
47 -> 95
63 -> 47
PAGE FAULT на странице 4
```

Адрес 21 (двоичное 010101): страница 1, смещение 5; кадр 7 даёт 117 (двоичное 1110101), как в учебнике.

## Размер страницы в системе

Размер страницы определяет система; он всегда степень двойки:

```python run
import mmap

size = mmap.PAGESIZE
print(size > 0 and size & (size - 1) == 0)
```
```output
True
```

## Типичные ошибки

* **Менять смещение при трансляции.** Меняется только номер страницы; смещение в кадре то же.
* **Путать системы счисления.** Смешение десятичной и шестнадцатеричной записи - самая частая ошибка в упражнениях; проверяйте на маленьком примере.
* **Считать, что физические кадры идут подряд.** Соседние виртуальные страницы обычно лежат в далёких кадрах.
* **Класть в TLB недействительные записи.** Ошибка страницы не должна оставлять следов в TLB.
* **Забывать, что TLB надо сбрасывать при смене адресного пространства.** Иначе процесс увидит чужие трансляции.
* **Предполагать размер страницы 4096.** Он зависит от системы и процессора.
* **Путать внутреннюю и внешнюю фрагментацию.** Страницы устраняют внешнюю, но оставляют внутреннюю: хвост последней страницы пропадает.

<!-- section: summary -->
## Итоги

* MMU переводит виртуальные адреса в физические по таблице страниц; адрес делится на VPN и смещение, смещение сохраняется.
* PTE хранит PFN, бит присутствия, права; нарушение вызывает ошибку страницы, а ядро решает, что с ней делать.
* TLB - кэш трансляций; его эффективность зависит от локальности.
* Многоуровневые таблицы экономят память для разреженных адресных пространств ценой дополнительных обращений при промахе.
* Что делать, когда нужная страница есть в таблице, но физической памяти не хватает, - [виртуальная память и замещение страниц](lesson:os.fundamentals.virtual-memory-page-replacement).
