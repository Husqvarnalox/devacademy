## Имя - это не файл

Когда вы пишете `open("report.txt")`, вы называете файл по имени, но сам файл с именем не связан. Имена лежат в **каталогах**, а файл - это структура на диске, **inode**: тип, владелец, права, размер, время изменения, счётчик ссылок и указатели на блоки с данными. Каталог - особый файл со списком пар «имя - номер inode». Отсюда следует всё интересное:

* у файла может быть несколько имён (**жёсткие ссылки**), и все они равноправны;
* переименование и перенос внутри одной файловой системы меняют только записи каталогов, данные не копируются;
* «удалить файл» на самом деле значит «удалить имя» (`unlink`); данные исчезают, когда имён не осталось.

Есть и второй вид ссылок - **символические**: маленький файл, в котором записан путь. Он ведёт себя как ярлык: следует за целью, но и сломаться может.

Работа с файлами из программы описана в уроке про [ошибки и файлы в Python](lesson:python.fundamentals.errors-and-files); здесь мы смотрим на то, что находится под ней. Опираемся на понятие [процесса и системного вызова](lesson:os.fundamentals.processes-and-system-calls): `link`, `unlink`, `symlink` - системные вызовы.

## Устройство на диске

Типичная файловая система (ext4, FFS и их родственники) делит диск на:

* **суперблок** - общие параметры (размер блока, число inode);
* **битовые карты** занятых inode и блоков данных;
* **таблицу inode**;
* **блоки данных**.

В inode лежат указатели на блоки данных: несколько прямых, затем косвенные (блок, содержащий указатели) и двойные косвенные, либо более современные экстенты (диапазон подряд идущих блоков). Малые файлы читаются быстро, большие стоят нескольких дополнительных обращений.

**Каталог** - файл, чьи данные - записи `(имя, номер inode)`. Каждый каталог содержит записи `.` (он сам) и `..` (родитель). Поэтому у каталога счётчик ссылок равен **2 плюс число подкаталогов**: одна ссылка - его имя в родителе, вторая - его собственная запись `.`, и ещё по одной даёт `..` каждого подкаталога.

## Разбор пути

Путь `/a/b/c` разбирается по компонентам. Начинают с корня (его inode известен заранее), читают каталог, ищут имя `a`, получают inode, читают его, и так далее. Если компонент оказался символической ссылкой, её содержимое подставляется в путь, и разбор продолжается. Чтобы цикл ссылок не завис, ядро считает раскрытия и после предела (в Linux порядка 40) возвращает ошибку `ELOOP`; в нашем упражнении предел равен 8.

## Жёсткие и символические ссылки

|  | жёсткая | символическая |
|---|---|---|
| что это | ещё одно имя того же inode | отдельный файл с путём внутри |
| цель должна существовать | да | нет (бывает висячей) |
| другая файловая система | нельзя | можно |
| на каталог | обычно запрещена (циклы) | можно |
| после удаления цели | данные живы, пока есть имена | ссылка остаётся и «ломается» |

Именно запрет жёстких ссылок на каталоги держит дерево деревом: иначе в каталоге могло бы появиться имя, указывающее на его предка, и обход файловой системы зациклился бы.

## unlink и открытые файлы

Освобождение inode и блоков требует двух условий: счётчик ссылок равен нулю **и** файл никто не держит открытым. Поэтому программа может открыть файл, удалить его имя и продолжать работать с содержимым: имени уже нет, а данные живут, пока не закрыт дескриптор. Так устроены временные файлы.

## Согласованность и журнал

Создание файла меняет сразу несколько структур: запись в каталоге, битовую карту inode, сам inode. Если питание пропадёт посередине, структуры разойдутся (запись есть, а inode не помечен занятым). Классический способ лечения - проверка всего диска при загрузке (`fsck`), долгая на больших дисках. Современный - **журнал**: сначала в отдельную область записывается описание всей операции, потом она применяется. После сбоя законченные записи журнала повторяются, незаконченные отбрасываются.

## Два имени - один inode

Работаем во временном каталоге, чтобы не трогать ваши файлы:

```python run
import os, tempfile

with tempfile.TemporaryDirectory() as d:
    a = os.path.join(d, "a.txt")
    b = os.path.join(d, "b.txt")
    with open(a, "w") as f:
        f.write("hello")
    print("links before:", os.stat(a).st_nlink)
    os.link(a, b)                           # жёсткая ссылка
    print("links after: ", os.stat(a).st_nlink)
    print("same inode:  ", os.stat(a).st_ino == os.stat(b).st_ino)
    os.unlink(a)                            # удаляем одно имя
    print("a exists:", os.path.exists(a))
    print("b data:  ", open(b).read(), "| links:", os.stat(b).st_nlink)
```
```output
links before: 1
links after:  2
same inode:   True
a exists: False
b data:   hello | links: 1
```

После `unlink(a)` данные никуда не делись: у них осталось имя `b.txt`.

## Висячая символическая ссылка

```python run
import os, tempfile

with tempfile.TemporaryDirectory() as d:
    target = os.path.join(d, "target.txt")
    link = os.path.join(d, "link.txt")
    with open(target, "w") as f:
        f.write("data")
    os.symlink(target, link)
    print("readlink matches:", os.readlink(link) == target)
    print("read via link:   ", open(link).read())
    print("link is symlink: ", os.path.islink(link))
    os.remove(target)
    print("exists (follows):", os.path.exists(link))
    print("islink (itself): ", os.path.islink(link))
    try:
        open(link)
    except FileNotFoundError as e:
        print("error:", type(e).__name__)
```
```output
readlink matches: True
read via link:    data
link is symlink:  True
exists (follows): False
islink (itself):  True
error: FileNotFoundError
```

`os.path.exists` следует за ссылкой и видит пустоту, а `islink` смотрит на саму ссылку.

## Счётчик ссылок каталога

```python run
import os, tempfile

with tempfile.TemporaryDirectory() as d:
    sub = os.path.join(d, "sub")
    os.mkdir(sub)
    print("dir links look classic:", os.stat(sub).st_nlink in (1, 2))
    print("file links:", end=" ")
    f = os.path.join(sub, "f")
    open(f, "w").close()
    print(os.stat(f).st_nlink)
```
```output
dir links look classic: True
file links: 1
```

Не все файловые системы ведут счётчик каталога по классическому правилу (некоторые показывают `1`), поэтому в упражнении правило задано явно.

## Заготовка интерпретатора

Ядро упражнения - функция разбора пути с раскрытием ссылок:

```python
def lookup(self, path, follow_last):
    parts = path.strip("/").split("/") if path != "/" else []
    cur, expansions = 1, 0
    i = 0
    while i < len(parts):
        node = self.inodes[cur]
        if node["type"] != "dir":
            raise FsError("not a directory", path)
        child = node["entries"].get(parts[i])
        if child is None:
            raise FsError("no such file or directory", path)
        last = i == len(parts) - 1
        if self.inodes[child]["type"] == "symlink" and (follow_last or not last):
            expansions += 1
            if expansions > MAX_SYMLINKS:
                raise FsError("too many levels of symbolic links", path)
            parts = self.inodes[child]["target"].strip("/").split("/") + parts[i + 1:]
            cur, i = 1, 0
            continue
        cur, i = child, i + 1
    return cur
```

Обратите внимание, как раскрытие ссылки заменяет уже пройденную часть пути и начинает разбор с корня: так цикл `a -> b -> a` быстро упирается в предел.

## Типичные ошибки

* **Считать, что `rm` стирает данные.** Он удаляет имя. Данные освобождаются, только когда имён не осталось и файл закрыт.
* **Путать счётчик ссылок файла и каталога.** У файла он равен числу имён, у каталога - 2 плюс число подкаталогов.
* **Ожидать, что символическая ссылка защищает цель.** Цель удаляется свободно, ссылка остаётся висячей.
* **Создавать жёсткую ссылку на несуществующий файл или каталог.** Первое невозможно по определению, второе запрещено.
* **Забывать, что в середине пути ссылки раскрываются всегда,** а в последнем компоненте - зависит от операции (`ls` и `open` следуют за ссылкой, `rm` и `ln` нет).
* **Не освобождать номер inode после удаления последнего имени** и тем самым ошибаться в номерах при повторном создании файлов.

<!-- section: summary -->
## Итоги

* Имя живёт в каталоге, остальное - в inode; у файла может быть несколько имён.
* Счётчик ссылок считает имена; на нуле (и без открытых дескрипторов) inode и блоки освобождаются.
* Жёсткая ссылка - ещё одно имя того же inode; символическая - файл с путём внутри, может быть висячей.
* У каталога счётчик равен 2 плюс число подкаталогов; жёсткие ссылки на каталоги запрещены, чтобы дерево осталось деревом.
* Разбор пути раскрывает ссылки с ограничением числа раскрытий.
* Журнал сохраняет согласованность структур при сбое.
