## Памяти всегда мало

Сумма виртуальных адресных пространств всех процессов обычно намного больше физической памяти. ОС выкручивается так: в оперативной памяти держит только нужные сейчас **страницы**, остальные лежат на диске (в разделе подкачки или в самом файле программы). Это и есть **виртуальная память**; предыдущий урок объяснял, как [адрес переводится по таблице страниц](lesson:os.fundamentals.paging-and-address-translation), теперь выясним, что делать, когда страницы в кадре нет.

**Подкачка по требованию** (demand paging): страница загружается при первом обращении.

1. Программа обращается к странице, у которой в PTE бит присутствия сброшен.
2. Процессор вызывает **ошибку страницы** и передаёт управление ядру.
3. Ядро проверяет, что обращение законно, находит свободный кадр (а если свободных нет - **выбирает жертву** и при необходимости записывает её на диск), читает нужную страницу.
4. Обновляет таблицу страниц и **перезапускает** прерванную инструкцию.

Чтение с диска стоит на много порядков дороже обращения к памяти, поэтому даже редкие ошибки заметны. Главный вопрос урока: **какую страницу вытеснить**, чтобы ошибок было меньше.

## Среднее время доступа

Пусть обращение к памяти занимает `m`, обслуживание ошибки - `s`, а вероятность ошибки - `p`. Среднее время `(1 - p) * m + p * s`. При `m = 100 нс`, `s = 10 мс` и `p = 1/100 000` среднее время вдвое больше `m`. Чтобы потери были малы (скажем, 10 %), ошибки должны быть чрезвычайно редкими: около одной на миллион обращений. Поэтому важны локальность обращений и хороший алгоритм замещения.

## Политики замещения

Работаем со **строкой обращений** (reference string) - последовательностью номеров страниц. Память пуста; каждая загрузка в свободный кадр тоже считается ошибкой.

* **FIFO** - вытесняется страница, раньше всех попавшая в память. Прост, но может вытеснить активно используемую страницу: возраст загрузки ничего не говорит о частоте использования. Попадания порядок не меняют.
* **LRU** (least recently used) - вытесняется страница, к которой дольше всего не обращались. Опирается на прошлое как на предсказание будущего (локальность). Точный LRU дорог, поэтому ядра приближают его битом обращения в PTE (алгоритм «часы»).
* **OPT** (оптимальная политика Беллади) - вытесняется страница, следующее обращение к которой произойдёт позже всех. Даёт минимально возможное число ошибок, но требует знания будущего; используется как **эталон** для оценки других политик.

Классический пример (3 кадра): `7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1` даёт FIFO 15, LRU 12, OPT 9. Различие между LRU и OPT показывает, сколько потеряно из-за незнания будущего.

## Аномалия Беллади

Интуитивно, чем больше кадров, тем меньше ошибок. Для FIFO это неверно. Строка `1 2 3 4 1 2 5 1 2 3 4 5`: при **трёх** кадрах FIFO даёт **9** ошибок, при **четырёх** - **10**. Объяснение: у FIFO нет **стекового свойства**. Для LRU и OPT множество страниц в памяти при `n` кадрах всегда входит в множество при `n + 1` кадрах, поэтому лишний кадр не может навредить. У FIFO состав памяти зависит от порядка загрузки, и дополнительный кадр меняет порядок вытеснений так, что нужные страницы вылетают как раз перед обращением.

Аномалия не говорит, что FIFO «всегда плох при росте памяти»: на большинстве строк она не проявляется. Но она показывает, что поведение политики нельзя доказывать одним примером, и мотивирует политики со стековым свойством.

## Thrashing и рабочее множество

Если процессам не хватает кадров под **рабочее множество** (страницы, которые нужны прямо сейчас), ошибки идут сплошным потоком, и система большую часть времени читает с диска, а не считает. Это **thrashing**. Лекарства: ограничить число одновременно работающих процессов, увеличить память, выделять кадры по рабочему множеству.

## Три политики в коде

Компактная реализация: все три считают число ошибок, и основа для упражнения. Сначала FIFO и LRU:

```python run
def fifo(refs, frames):
    mem, faults = [], 0
    for page in refs:
        if page not in mem:
            faults += 1
            if len(mem) == frames:
                mem.pop(0)          # самая ранняя загрузка
            mem.append(page)
    return faults


def lru(refs, frames):
    mem, faults = [], 0             # в начале списка - давно не использованные
    for page in refs:
        if page in mem:
            mem.remove(page)        # попадание освежает страницу
        else:
            faults += 1
            if len(mem) == frames:
                mem.pop(0)
        mem.append(page)
    return faults


refs = [7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1]
print("FIFO", fifo(refs, 3), "LRU", lru(refs, 3))
```
```output
FIFO 15 LRU 12
```

Теперь OPT: для каждой страницы в памяти смотрим вперёд.

```python run
def opt(refs, frames):
    mem, faults = [], 0
    for i, page in enumerate(refs):
        if page in mem:
            continue
        faults += 1
        if len(mem) == frames:
            def next_use(p):
                rest = refs[i + 1:]
                return rest.index(p) if p in rest else len(refs) + 1
            mem.remove(max(mem, key=next_use))
        mem.append(page)
    return faults


refs = [7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1]
print("OPT", opt(refs, 3))
```
```output
OPT 9
```

## Аномалия на строке Беллади

```python run
def fifo(refs, frames):
    mem, faults = [], 0
    for page in refs:
        if page not in mem:
            faults += 1
            if len(mem) == frames:
                mem.pop(0)
            mem.append(page)
    return faults


belady = [1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5]
for frames in (1, 2, 3, 4, 5):
    print(f"кадров {frames}: {fifo(belady, frames)} ошибок")
```
```output
кадров 1: 12 ошибок
кадров 2: 12 ошибок
кадров 3: 9 ошибок
кадров 4: 10 ошибок
кадров 5: 5 ошибок
```

Рост на отрезке 3 -> 4 (9 -> 10) - и есть аномалия. Проверьте себя: сколько ошибок даёт LRU на этой строке при 3 и 4 кадрах? Ответ: 10 и 8, поэтому у LRU аномалии нет.

## Поиск аномалии перебором

Идея задачи-вызова: пробегаем строки по возрастанию и ищем первую, на которой FIFO с `f + 1` кадрами хуже. Чтобы не перебирать `p^L` строк, учитываем симметрию: переименование страниц не меняет число ошибок, поэтому достаточно строк, где страницы встречаются впервые в порядке `1, 2, 3...`. Число таких строк - числа Стирлинга второго рода, оно растёт гораздо медленнее:

```python run
def restricted(length, p):
    """Строки, где каждая новая страница на единицу больше максимума."""
    def rec(prefix, used):
        if len(prefix) == length:
            yield tuple(prefix)
            return
        for page in range(1, min(used + 1, p) + 1):
            prefix.append(page)
            yield from rec(prefix, max(used, page))
            prefix.pop()
    return list(rec([], 0))


print(len(restricted(8, 5)), "против", 5 ** 8)
```
```output
3845 против 390625
```

## Типичные ошибки

* **Менять порядок страниц в FIFO при попадании.** Тогда вы реализуете не FIFO, а что-то близкое к LRU.
* **Не считать загрузку в свободные кадры ошибкой.** По определению каждая первая загрузка - ошибка.
* **В OPT искать будущее среди refs[:i].** Нужно `refs[i+1:]`.
* **Забыть, что страница без будущих обращений - лучшая жертва для OPT.** Её «расстояние» бесконечно.
* **Делать вывод по одному примеру.** Аномалия Беллади показывает, что «больше кадров» не всегда значит «меньше ошибок» для FIFO.
* **Путать OPT с реализуемым алгоритмом.** В ядре будущего нет; OPT служит линейкой.
* **Считать LRU бесплатным.** Точный LRU требует обновления на каждое обращение.

<!-- section: summary -->
## Итоги

* Виртуальная память: страницы подгружаются по требованию, ошибка страницы запускает обработчик ядра.
* Среднее время доступа очень чувствительно к частоте ошибок.
* FIFO дёшев, но неустойчив; LRU использует недавнее прошлое; OPT нереализуем и служит эталоном.
* Аномалия Беллади (FIFO: 9 ошибок при 3 кадрах, 10 при 4) возникает из-за отсутствия стекового свойства; у LRU и OPT её нет.
