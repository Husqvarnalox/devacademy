## Зачем нужна операционная система

Программа хочет читать файлы, говорить по сети, занимать память и работать «одновременно» с десятками других программ, хотя процессорных ядер всего несколько. Операционная система (ОС) решает три задачи:

1. **Абстракция.** Вместо секторов диска - файлы, вместо физической памяти - собственное адресное пространство, вместо ядра процессора - «процесс, который работает сам по себе».
2. **Мультиплексирование.** Одни и те же процессор, память и диск по очереди (или частями) достаются разным процессам.
3. **Защита.** Ошибка или злой умысел в одной программе не должны ломать другую программу или саму ОС.

Центр ОС - **ядро**. Оно работает в привилегированном **режиме ядра** и имеет полный доступ к устройствам. Ваши программы работают в **режиме пользователя**: обычные вычисления им доступны, а всё, что затрагивает общие ресурсы, они просят у ядра через **системные вызовы** (`open`, `read`, `write`, `fork`, `exit`...).

Запущенная программа называется **процессом**: это исполняющийся экземпляр программы со своей памятью, открытыми файлами и состоянием. Процессов обычно больше, чем ядер, поэтому ядро постоянно решает, кто сейчас на процессоре, и переключает их. Эта картина - основа всего курса: [планирование](lesson:os.fundamentals.cpu-scheduling) выбирает процесс, [память](lesson:os.fundamentals.paging-and-address-translation) создаёт иллюзию личного адресного пространства, [файловые системы](lesson:os.fundamentals.file-systems) прячут диск.

Об одновременности в Python мы уже говорили в уроке [«Модели конкурентности»](lesson:python.concurrency.concurrency-models). Здесь мы смотрим на то, что лежит под ним.

## Режимы, ловушки, системные вызовы

Процессор хранит в регистре бит текущего уровня привилегий. В режиме пользователя недоступны привилегированные инструкции (управление прерываниями, таблицами страниц, ввод-вывод на устройства), а память ядра защищена. Нарушение вызывает **исключение**, и управление переходит ядру: оно обычно завершает процесс.

Законный вход в ядро - **ловушка** (trap): специальная инструкция процессора (на x86-64 это `syscall`, на ARM64 - `svc`). Последовательность такая:

1. Обёртка из библиотеки кладёт номер вызова и аргументы в регистры и выполняет инструкцию входа.
2. Процессор сохраняет счётчик команд и режим, переключается в режим ядра и прыгает на обработчик, адрес которого настроило ядро при загрузке (**таблица ловушек**). Программа не выбирает точку входа сама.
3. Ядро проверяет аргументы (указатели - особенно строго), выполняет работу и кладёт результат или код ошибки в регистр.
4. Инструкция возврата (`sysret`, `eret`) восстанавливает режим пользователя и продолжает программу.

Это дороже вызова функции: меняются режим и (часто) кэши, поэтому библиотеки буферизуют ввод-вывод - `print` копит данные и вызывает `write` редко. Ошибки системных вызовов в C сообщаются отрицательным результатом и `errno`; Python превращает их в `OSError` и подклассы (`FileNotFoundError` для `ENOENT`).

Кроме ловушек в ядро ведут **прерывания** (асинхронные сигналы устройств, например таймера) и **исключения** (деление на ноль, ошибка страницы). Прерывание таймера - то, что позволяет ядру отнять процессор у программы, которая не собирается его отдавать.

## Процесс и PCB

**Процесс** = адресное пространство (код, данные, куча, стек) + один или несколько потоков исполнения + ресурсы ядра (открытые файлы, окружение). Ядро описывает его структурой **PCB** (process control block). В ней обычно есть:

* идентификатор процесса (pid), родитель, владелец;
* **состояние** процесса;
* сохранённые регистры и счётчик команд (когда процесс не на процессоре);
* данные планировщика (приоритет, учёт времени);
* описание памяти (таблицы страниц, [следующие уроки](lesson:os.fundamentals.paging-and-address-translation));
* таблица открытых файлов, обработчики сигналов.

### Состояния

В учебной модели пять состояний:

* `NEW` - создан, ресурсы ещё выделяются;
* `READY` - готов к исполнению, ждёт процессор;
* `RUNNING` - исполняется на ядре сейчас;
* `WAITING` (BLOCKED) - ждёт события: завершения ввода-вывода, мьютекса, сигнала;
* `TERMINATED` - завершился, но запись ещё не убрана (родитель должен прочитать код возврата, в Unix такой процесс называют зомби).

Переходы: `NEW -> READY` (admit), `READY -> RUNNING` (dispatch, выбор планировщика), `RUNNING -> READY` (timeout, вытеснение), `RUNNING -> WAITING` (block), `WAITING -> READY` (wake) и `RUNNING -> TERMINATED` (exit). Из `WAITING` в `RUNNING` напрямую нельзя: разбуженный процесс сначала становится `READY`. Это упражнение урока.

### Переключение контекста

Когда процесс уходит с процессора, ядро (1) сохраняет его регистры в PCB, (2) выбирает следующий процесс, (3) загружает его регистры и таблицу страниц, (4) возвращается в режим пользователя. Это чистые накладные расходы: полезной работы в этот момент не выполняется, а у нового процесса «холодные» кэши и TLB. Поэтому слишком частые переключения вредны ([кванты в следующем уроке](lesson:os.fundamentals.cpu-scheduling)).

## Системный вызов из Python

`os.write(fd, data)` - почти прямой вызов `write(2)`. Дескриптор 1 - стандартный вывод. Функция возвращает число реально записанных байт:

```python run
import os

n = os.write(1, "привет\n".encode("utf-8"))
print("записано байт:", n)
```
```output
привет
записано байт: 13
```

Строка из 7 символов занимает 13 байт в UTF-8: ядро знает только байты. Теперь ошибка: ядро отвечает кодом, а Python превращает его в исключение.

```python run
import errno
import os

try:
    os.open("/no/such/file", os.O_RDONLY)
except OSError as e:
    print(type(e).__name__, errno.errorcode[e.errno], e.errno == errno.ENOENT)
```
```output
FileNotFoundError ENOENT True
```

Идентификатор процесса меняется от запуска к запуску, поэтому печатать его нельзя, но свойства проверить можно:

```python run
import os

pid = os.getpid()
print(pid > 0, os.getppid() > 0, pid != os.getppid())
```
```output
True True True
```

## PCB и состояния в коде

Ядро хранит процесс как запись с состоянием; допустимые переходы - таблица. Так же устроено и решение упражнения:

```python run
ALLOWED = {
    ("NEW", "READY"), ("READY", "RUNNING"), ("RUNNING", "READY"),
    ("RUNNING", "WAITING"), ("WAITING", "READY"), ("RUNNING", "TERMINATED"),
}


class PCB:
    def __init__(self, pid):
        self.pid = pid
        self.state = "NEW"
        self.saved_pc = 0          # «счётчик команд», сохранённый при уходе с CPU

    def move(self, new_state):
        if (self.state, new_state) not in ALLOWED:
            raise ValueError(f"{self.state} -> {new_state}")
        self.state = new_state


p = PCB(1)
for s in ["READY", "RUNNING", "WAITING", "READY"]:
    p.move(s)
print(p.state)
try:
    p.move("WAITING")
except ValueError as e:
    print("недопустимо:", e)
```
```output
READY
недопустимо: READY -> WAITING
```

В упражнении вы дополните эту идею глобальным правилом «на одном процессоре RUNNING не больше одного процесса» и журналом ошибок.

## Типичные ошибки

* **Путать READY и WAITING.** READY - ждёт процессор, WAITING - ждёт событие. Разбуженный процесс идёт в READY, а не сразу в RUNNING.
* **Считать системный вызов бесплатным.** Тысячи мелких `write` по одному байту намного медленнее одного большого; поэтому существует буферизация.
* **Думать, что процесс и программа - одно и то же.** Одну программу можно запустить сто раз: это сто процессов с разной памятью и разными pid.
* **Забывать про TERMINATED.** Запись о завершённом процессе живёт, пока родитель не заберёт код возврата; события для такого pid всё равно недопустимы.
* **Ожидать от симулятора поведения реальной ОС.** Упражнение моделирует только одно ядро и пять состояний; реальные ядра различают больше состояний (например, приостановленные процессы и спящие с разной возможностью прерывания).

## Итоги

* ОС абстрагирует ресурсы, делит их между процессами и защищает их друг от друга.
* Режим пользователя ограничен аппаратно; в ядро ведут только ловушки (системные вызовы), прерывания и исключения.
* Процесс описывается PCB: pid, состояние, регистры, память, файлы; при переключении контекста регистры сохраняются в PCB одного процесса и загружаются из PCB другого.
* Жизненный цикл: `NEW -> READY -> RUNNING -> (READY | WAITING | TERMINATED)`, `WAITING -> READY`.
