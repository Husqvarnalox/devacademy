## Две структуры для «самого маленького» и «где вставить»

Часто нужно не отсортировать всё, а быстро ответить на один из двух вопросов: «какой элемент сейчас самый срочный (наименьший)?» и «на каком месте в упорядоченном списке находится значение?». Для этого в стандартной библиотеке есть два небольших модуля.

* **`heapq`** - *куча* (heap): способ хранить элементы в обычном списке так, чтобы наименьший всегда лежал в начале (`heap[0]`), а добавление и извлечение минимума были быстрыми. Это основа очередей с приоритетами: планировщик задач, алгоритм Дейкстры, «верни k самых больших».
* **`bisect`** - *бинарный поиск* в уже отсортированном списке: найти место вставки или границу диапазона за логарифмическое время, не просматривая все элементы.

Важно сразу запомнить: куча - не отсортированный список. Отсортирован только «верх». Это и делает её дешёвой. Списки вы уже знаете из урока [«Списки»](lesson:python.fundamentals.lists); `deque` и `Counter` из [предыдущего урока](lesson:python.stdlib.collections) решают другие задачи (очередь без приоритетов и подсчёт).

## Инварианты, API и стоимость

**Инвариант min-кучи.** Список `heap` является кучей, если для каждого индекса `k` выполняется `heap[k] <= heap[2*k + 1]` и `heap[k] <= heap[2*k + 2]` (если такие индексы существуют). Из этого следует, что `heap[0]` - наименьший элемент, но соседние элементы не упорядочены между собой. Список читается как бинарное дерево: у элемента `k` потомки `2k+1` и `2k+2`.

**Основные функции `heapq`** (куча всегда обычный `list`):

* `heappush(heap, x)` - O(log n); `heappop(heap)` - O(log n), возвращает наименьший элемент, на пустой куче `IndexError`.
* `heapify(lst)` - превращает список в кучу **на месте** за O(n). Это быстрее, чем n раз `heappush` (O(n log n)).
* `heap[0]` - посмотреть минимум без удаления, O(1).
* `heappushpop(heap, x)` - добавить и сразу извлечь минимум; быстрее, чем по отдельности, и не растит кучу.
* `heapreplace(heap, x)` - сначала извлечь минимум, потом добавить `x` (на пустой куче `IndexError`); основа для «кучи фиксированного размера».
* `nlargest(k, iterable, key=None)` и `nsmallest(...)` - k наибольших/наименьших; результат эквивалентен `sorted(iterable, key=key, reverse=True)[:k]`, в том числе по порядку равных элементов. Для небольшого k работают за O(n log k); если k близко к n, проще и быстрее `sorted(...)[:k]`; для k = 1 используйте `max`/`min`.
* `merge(*sorted_iterables)` - лениво сливает уже отсортированные входы.

**Максимум.** Модуль даёт только min-кучу. Для чисел кладите `-x`; для произвольных объектов - кортеж с отрицательным ключом `(-priority, ...)`, а для строк или несравнимых типов - обёртку с обратным сравнением.

**Равные приоритеты и несравнимые элементы.** Если в куче лежат кортежи `(priority, item)`, то при равных приоритетах Python сравнивает `item`. Если `item` несравним (словари, объекты без `__lt__`), возникает `TypeError`; если сравним - порядок равных приоритетов произволен. Стандартное решение (приём из документации): `(priority, counter, item)`, где `counter = itertools.count()` даёт уникальное возрастающее число. Так сравнение никогда не доходит до `item`, а среди равных приоритетов выигрывает пришедший раньше (FIFO).

**Изменение приоритета и удаление.** Куча не умеет искать произвольный элемент. Типичный приём - *ленивое удаление*: пометить запись как удалённую и пропускать её при `heappop`.

**`bisect`.** Работает только на списке, отсортированном по тому же критерию:

* `bisect_left(a, x)` - первая позиция, куда можно вставить `x` перед равными; `bisect_right(a, x)` (он же `bisect`) - после равных. Оба O(log n). `bisect_right(a, x) - bisect_left(a, x)` - число элементов, равных `x`.
* `insort_left` / `insort_right` (`insort`) - вставка с сохранением порядка. Поиск O(log n), но вставка в `list` сдвигает хвост, поэтому **итоговая стоимость O(n)**.
* Параметр `key=` (Python 3.10+) применяется к элементам списка, а не к `x`; `lo`/`hi` ограничивают диапазон поиска. Поиск в «таблице границ» (оценки по баллам) - классический случай: `bisect_right(границы, балл)` даёт индекс категории.

**Ограничения.** Куча не потокобезопасна и не поддерживает быстрый поиск и обновление произвольного элемента; `bisect` не проверяет, что список отсортирован (при нарушении результат бессмыслен, но исключения не будет); `insort` для частых вставок в большой список становится узким местом.

## Примеры

**Пример 1. Инвариант и порядок извлечения.**

```python run
import heapq

data = [5, 3, 8, 1, 9, 2]
heap = list(data)
heapq.heapify(heap)
print(heap, heap[0])
print(heap == sorted(heap))

out = []
while heap:
    out.append(heapq.heappop(heap))
print(out)

h = []
for x in [5, 3, 8]:
    heapq.heappush(h, x)
print(h)
print(heapq.heappushpop(h, 1), h)   # 1 меньше минимума: куча не изменилась
print(heapq.heapreplace(h, 10), h)   # вернули минимум 3, добавили 10

mx = [-x for x in data]        # max-куча через отрицание
heapq.heapify(mx)
print(-heapq.heappop(mx), -heapq.heappop(mx))
```
```output
[1, 3, 2, 5, 9, 8] 1
False
[1, 2, 3, 5, 8, 9]
[3, 5, 8]
1 [3, 5, 8]
3 [5, 10, 8]
9 8
```

**Пример 2. top-k и устойчивая очередь с приоритетами.**

```python run
import heapq
import itertools

words = ["pear", "fig", "banana", "kiwi", "apple"]
print(heapq.nlargest(2, words, key=len))
print(heapq.nsmallest(2, words, key=len))

try:
    heap = []
    heapq.heappush(heap, (1, {"job": "a"}))
    heapq.heappush(heap, (1, {"job": "b"}))
except TypeError as exc:
    print("TypeError:", exc)

counter = itertools.count()
heap = []
for priority, job in [(2, {"job": "a"}), (1, {"job": "b"}), (2, {"job": "c"}), (1, {"job": "d"})]:
    heapq.heappush(heap, (priority, next(counter), job))
print([heapq.heappop(heap)[2]["job"] for _ in range(4)])
```
```output
['banana', 'apple']
['fig', 'pear']
TypeError: '<' not supported between instances of 'dict' and 'dict'
['b', 'd', 'a', 'c']
```

**Пример 3. bisect: границы, дубликаты, оценки, insort.**

```python run
import bisect

a = [1, 2, 2, 2, 5, 9]
print(bisect.bisect_left(a, 2), bisect.bisect_right(a, 2), bisect.bisect_left(a, 4))
print(bisect.bisect_right(a, 2) - bisect.bisect_left(a, 2))

def grade(score, breaks=(60, 75, 90), names="DCBA"):
    return names[bisect.bisect_right(breaks, score)]

print([grade(s) for s in (59, 60, 74, 75, 89, 90, 100)])

b = [10, 20, 30]
bisect.insort(b, 25)
bisect.insort(b, 20)             # insort == insort_right: после равных
print(b)

people = [("ann", 21), ("bob", 30), ("cid", 35)]
print(bisect.bisect_left(people, 30, key=lambda p: p[1]))   # Python 3.10+
```
```output
1 4 4
3
['D', 'C', 'C', 'B', 'B', 'A', 'A']
[10, 20, 20, 25, 30]
1
```

**Пример 4. heapq.merge и «окно из k наибольших» через heapreplace.**

```python run
import heapq

print(list(heapq.merge([1, 4, 9], [2, 3, 10], [0, 5])))

def k_largest_stream(stream, k):
    heap = []
    for x in stream:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)
    return sorted(heap, reverse=True)

print(k_largest_stream(iter([4, 1, 7, 3, 9, 2, 8]), 3))
```
```output
[0, 1, 2, 3, 4, 5, 9, 10]
[9, 8, 7]
```

## Типичные ошибки

* **Считать кучу отсортированной.** `print(heap)` не показывает порядок; перебор `for x in heap` не даёт возрастающей последовательности. Извлекайте через `heappop` или берите `sorted`.
* **Вызывать `heappush` на списке, который не является кучей.** Сначала `heapify`, иначе инвариант нарушен, и результаты `heappop` будут неверны без всякой ошибки.
* **Сортировать «кучу» и продолжать с ней как с кучей после ручного изменения элементов.** Изменили `heap[i]` на месте - инвариант потерян; используйте удаление с повторной вставкой или `heapify`.
* **Кортежи `(priority, item)` с несравнимыми `item`.** Добавляйте счётчик: `(priority, next(counter), item)`.
* **Ожидать max-кучу.** У `heapq` нет `reverse`. Храните `-x` или обёртку.
* **`nlargest` вместо `sorted` при большом k.** Если k сравним с n, полная сортировка проще и быстрее; для k = 1 нужны `max`/`min`.
* **`bisect` по неотсортированному списку.** Нет ошибки, но результат бессмыслен. Отсортируйте список и поддерживайте порядок.
* **`insort` в цикле на большом списке.** Каждая вставка O(n); 10^5 вставок превращаются в миллиарды сдвигов. Лучше собрать список и один раз отсортировать, либо использовать кучу.
* **Путать `bisect_left` и `bisect_right`.** Для «сколько элементов строго меньше x» нужен `bisect_left`, для «не больше x» - `bisect_right`.
* **Передавать `key` в `bisect` как функцию от `x`.** `key` применяется к элементам списка, значение для поиска передаётся уже в ключевом виде.

## Итог

* Куча - список с инвариантом «родитель <= потомки»; `heap[0]` - минимум, но остальное не отсортировано.
* `heappush`/`heappop` - O(log n), `heapify` - O(n), `nlargest`/`nsmallest` выгодны при малом k; максимум - через отрицание.
* Для очереди с приоритетами используйте `(priority, counter, item)`: нет `TypeError` и сохраняется FIFO среди равных.
* `bisect_left`/`bisect_right` - O(log n) для поиска границ; `insort` ищет быстро, но вставляет за O(n).
* Выбирайте: один минимум - `min`; k лучших - `nlargest`; поток с приоритетами - куча; запросы по диапазону к статичному списку - `bisect`.
