## Зачем уметь читать ошибки

Первые программы почти всегда не собираются с первого раза: пропущена кавычка, не та буква, лишняя строка. Это нормально для любого человека, который пишет код, а не признак того, что вы чего-то не понимаете. Умение читать сообщение компилятора превращает ошибку из тупика в подсказку.

**Ошибка компиляции** - сообщение компилятора о том, что программу нельзя перевести в исполняемый файл. Пока она есть, программа не запускается вообще: ни одна строка не будет выполнена.

Весь путь от текста до результата называется **сборкой и запуском** (build and run): сначала компилятор переводит программу, потом запускается получившийся файл. Приложение выполняет оба шага при нажатии «Запустить». Если на первом шаге ошибка, вы видите её текст вместо результата.

## Одна новая идея: сообщение устроено по шаблону

```text
./main.go:6:2: undefined: fmt
```

Читается слева направо:

* `./main.go` - в каком файле;
* `6` - номер строки;
* `2` - номер символа в строке (столбец);
* `undefined: fmt` - что не так.

Читать нужно **первое** сообщение и исправлять **по одной ошибке**: следующие сообщения часто являются следствием первой.

<!-- section: examples -->
## Пример 1. Рабочая программа

```go run
package main

import "fmt"

func main() {
    fmt.Println("Склад открыт")
    fmt.Println("Товаров на складе нет")
}
```
```output
Склад открыт
Товаров на складе нет
```

Если сломать эту программу, сообщение покажет, где именно. Уберите букву `P` в `Println` у первой команды и запустите: компилятор ответит `undefined: fmt.println`. Теперь верните букву и уберите закрывающую кавычку: ответ станет другим, `newline in string`. Разные причины дают разные сообщения, и по ним можно узнать причину.

## Пример 2. Два вида ошибок в одной программе

```go
package main

import (
    "fmt"
    "os"
)

func main() {
    fmt.Println("Скидка"
}
```

Компилятор сообщит:

```text
./main.go:9:31: syntax error: unexpected newline in argument list; possibly missing comma or )
```

Об импорте `os` - ни слова, хотя он не используется. Сначала компилятор должен прочитать программу как текст по правилам языка (это проверка **синтаксиса**). Только потом он проверяет, что имена известны и импорты используются. Поэтому после исправления скобки появится новое сообщение: `"os" imported and not used`.

**Попробуйте.** Добавьте в рабочую программу из примера 1 под строкой `import "fmt"` ещё одну: `import "os"`. Предскажите сообщение, затем запустите.

## Точные правила

**Виды ошибок, которые встретятся в первых уроках:**

* *Синтаксические* - текст нарушает грамматику: не закрыты скобка или кавычка, не закрыта фигурная скобка (`unexpected EOF, expected }` - ожидалась скобка, а текст кончился), лишний символ. Сообщения начинаются со слов `syntax error`.
* *Неизвестное имя* - `undefined: ...`: имя не объявлено или написано с другой буквы. Регистр важен.
* *Неиспользуемый импорт* - `"пакет" imported and not used`. Go считает лишний импорт ошибкой, чтобы программы не накапливали мусор.

**Порядок проверки.** Сначала синтаксис, потом имена и типы. Поэтому исправление одной ошибки может открыть следующую.

**Строка и столбец.** Номер строки показывает, где компилятор понял, что что-то не так. Причина может быть строкой выше: незакрытая скобка проявится только на следующей строке. Если на указанной строке ничего не видно, проверьте предыдущую.

**Сколько сообщений.** Компилятор показывает несколько ошибок за раз (обычно не больше десяти). Первое - самое надёжное.

**Предупреждений нет.** В Go нет «предупреждений, которые можно игнорировать»: либо программа собирается, либо нет.

## Типичные ошибки при работе с ошибками

**1. Читать последнее сообщение вместо первого.** Одна пропущенная скобка может породить несколько сообщений ниже по тексту. Исправьте первую причину и соберите заново: остальные сообщения часто исчезнут сами. Как заметить: после исправления одной строки сразу исчезло несколько сообщений.

**2. Не закрыта фигурная скобка.**

```go
func main() {
    fmt.Println("a")
    fmt.Println("b")
```

Компилятор: `syntax error: unexpected EOF, expected }`. EOF (end of file) - конец файла: он дочитал текст, а закрывающей скобки так и не встретил. Дописывайте `}` в конец функции. Как заметить: сообщение указывает на последнюю строку файла, где ничего не написано.

**3. Фигурная скобка на новой строке.**

```go
func main()
{
    fmt.Println("a")
}
```

Компилятор: `syntax error: unexpected semicolon or newline before {`. В Go открывающая скобка должна стоять на той же строке, что и заголовок функции, иначе перевод строки считается концом команды. Верните `{` на строку `func main() {`.

**4. Лишняя закрывающая скобка.**

```go
fmt.Println("a"))
```

Компилятор: `syntax error: unexpected ) at end of statement`. Одна `)` закрыла вызов, вторая лишняя. Удалите её. Считайте скобки парами: сколько открыли, столько закрыли.

## Итоги

* Ошибка компиляции останавливает всё: программа не запускается, пока она не исправлена.
* Сообщение содержит файл, строку, столбец и описание.
* Читайте первое сообщение, исправляйте по одной ошибке и запускайте заново.
* Синтаксис проверяется раньше имён и импортов, поэтому ошибки приходят по очереди.

Теперь вы можете сами разобраться, почему программа не собирается. Дальше научимся выводить больше, чем одну строку текста: [Вывод: Println, Print и перевод строки](lesson:go.first-steps.output).

## Для тех, кто уже программирует

* Go отвергает программу с неиспользуемым импортом или (как увидим позже) неиспользуемой локальной переменной. В других языках это обычно предупреждение линтера.
* Сборка выдаёт ошибки типов до запуска, как в Java или C#, в отличие от Python или JS.
* Синтаксические ошибки останавливают проверку типов: типичная причина «ошибки приходят по очереди».
* Ошибки показывают `файл:строка:столбец`, формат понимают редакторы и IDE.
* Нет исключений и стек-трейсов на этапе сборки: это сообщения компилятора, программа ещё не запускалась.

<!-- section: deep-dive -->
## Из каких этапов состоит сборка

Необязательный раздел.

Компилятор Go работает примерно по такой схеме. Сначала **разбор**: текст превращается в структуру, где видно, что является функцией, что - вызовом, что - строкой. Здесь находятся синтаксические ошибки. Затем **проверка типов и имён**: каждое имя связывается с объявлением, проверяется, что значения подходят друг другу. Здесь находятся `undefined` и неиспользуемые импорты. Только потом идёт **генерация машинного кода** и компоновка в один файл.

Проверку имён нельзя начать, пока текст не разобран. Поэтому синтаксическая ошибка скрывает все последующие проблемы: компилятору нечего проверять.
