## Зачем это нужно

Когда входных данных много (тысячи и миллионы чисел), `fmt.Scan` становится заметно медленным, а суммы легко выходят за пределы привычных типов. В этом уроке два практических навыка: быстро читать большой ввод и считать суммы, которые не помещаются в маленький тип.

## Одна новая идея: читать через буфер и считать в int64

**Буфер** - область памяти, в которую данные собирают порциями. `bufio.NewReader(os.Stdin)` создаёт читателя, который забирает из стандартного ввода сразу много байтов и затем отдаёт значения из памяти. Читают из него функцией `fmt.Fscan` (то же, что `Scan`, но первым аргументом идёт источник):

```go
in := bufio.NewReader(os.Stdin)
var x int
fmt.Fscan(in, &x)
```

Второе: размеры целых типов ограничены. `int32` вмещает числа до примерно 2,1 миллиарда, `int64` - до примерно 9,2 · 10¹⁸. Если результат не помещается, Go **не сообщает об ошибке**: число «заворачивается» и становится неверным. Для сумм поэтому берут `int64`.

<!-- section: examples -->
## Пример 1. Переполнение без предупреждения

```go run
package main

import "fmt"

func main() {
    var small int32 = 2000000000
    fmt.Println(small + small)

    var big int64 = 2000000000
    fmt.Println(big + big)
}
```
```output
-294967296
4000000000
```

Две одинаковые суммы дали разные ответы: в `int32` результат не поместился и завернулся в отрицательное число, а `int64` справился. Программа не остановилась и ничего не сообщила.

## Пример 2. Приведение между целыми типами

```go run
package main

import "fmt"

func main() {
    var total int64 = 10
    count := 4
    total = total + int64(count)
    fmt.Println(total)
    avg := float64(total) / float64(count)
    fmt.Printf("%.2f\n", avg)
}
```
```output
14
3.50
```

`int64` и `int` разные типы, поэтому перед сложением нужно явное приведение `int64(count)`. Деление для среднего ведут в `float64`, а `%.2f` печатает два знака после точки.

## Пример 3. Чтение потока чисел через буфер

```go
package main

import (
    "bufio"
    "fmt"
    "os"
)

func main() {
    in := bufio.NewReader(os.Stdin)
    var n int
    fmt.Fscan(in, &n)
    var sum int64
    for i := 0; i < n; i++ {
        var x int64
        fmt.Fscan(in, &x)
        sum += x
    }
    fmt.Println(sum)
}
```

Для ввода `3` и затем `10 20 30` (в любой разбивке по строкам) программа напечатает `60`. Читатель `in` создан один раз и используется для всех чтений. `x` объявлена как `int64`, чтобы `Fscan` сразу записала значение в нужный тип. Блок без слова `run`, так как программе нужен ввод.

* `bufio.NewReader(os.Stdin)` оборачивает стандартный ввод в буфер; нужны пакеты `bufio` и `os`;
* `fmt.Fscan(in, &x)` читает следующее значение, пропуская пробелы и переводы строк;
* сумма в `int64` не переполнится до 9 · 10¹⁸.

**Попробуйте.** В примере 1 замените `2000000000` на `1000000000` в `small` и посмотрите, когда завернётся значение. В примере 3 добавьте поиск минимума: до цикла `min` не нужно задавать нулём, первый элемент становится начальным значением.

<!-- section: precise -->
## Точные правила

* **`bufio.NewReader(os.Stdin)`** возвращает читателя с буфером. Создавайте его один раз и читайте только через него: если смешать `fmt.Scan` и `Fscan(in, ...)`, часть данных окажется в буфере и `Scan` её не увидит.
* **`fmt.Fscan(reader, &a, &b)`** читает значения, разделённые любыми пробельными символами, включая переводы строк. Возвращает `(n, err)`: сколько значений прочитано и ошибку; в конце ввода `err` не `nil` (`EOF`).
* **Без `&`** `Fscan` не знает, куда записывать: ошибка `type not a pointer`. Адрес переменной обязателен.
* **Размеры**: `int8` (±127), `int16`, `int32` (до ±2,1 · 10⁹), `int64` (до ±9,2 · 10¹⁸), `int` равен 32 или 64 битам в зависимости от платформы. Для сумм и значений, о размере которых вы не уверены, выбирайте `int64`.
* **Переполнение** не вызывает ошибки или паники: старшие биты отбрасываются, и число «заворачивается» (максимум плюс один становится минимумом).
* **Разные целые типы не смешиваются**: `int64(x)` и `int(y)` преобразуют явно.
* **Среднее**: `float64(sum) / float64(n)`; формат `%.2f` всегда использует точку.
* **Минимум и максимум**: начальные значения берите из первого элемента (например, при `i == 0`), а не из нуля.
* **Скорость**: `Fscan` с буфером заметно быстрее `Scan` на больших вводах; для строк целиком есть `bufio.Scanner` (следующий урок).

<!-- section: mistakes -->
## Типичные ошибки

**1. Сумма в маленьком типе.**

```go
var sum int32
// ... складываем большие числа
```

Программа не падает и не предупреждает, а печатает неверное число (например, отрицательное при большой сумме). Для сумм используйте `int64`. Как заметить: ответ отрицательный или заметно меньше ожидаемого.

**2. Смешение int и int64.**

```go
var sum int64
n := 3
sum = sum + n
```

Компилятор: `invalid operation: sum + n (mismatched types int64 and int)`. Приведите: `sum + int64(n)`.

**3. Забыли & в Fscan.**

```go
fmt.Fscan(in, n)
```

Функция вернёт ошибку `type not a pointer: int`, а `n` не изменится. Программа продолжит работать с нулём. Пишите `&n` и проверяйте возвращаемое значение, если ввод может быть неполным.

**4. Неиспользуемый пакет.** Если импортировали `bufio` или `os`, но не использовали, компилятор сообщит, например, `"bufio" imported and not used`.

**5. Минимум и максимум, начатые с нуля.** Для набора отрицательных чисел `max := 0` даст `0`, которого нет во вводе. Инициализируйте первым прочитанным числом.

**6. Среднее целочисленным делением.** `sum / n` для `int64` отбросит дробную часть. Приводите оба операнда к `float64`.

<!-- section: summary -->
## Итоги

* `bufio.NewReader(os.Stdin)` и `fmt.Fscan(in, &x)` - способ быстро читать большой ввод; значения могут быть разбросаны по строкам как угодно.
* Целые типы имеют границы; переполнение молчаливое, поэтому суммы считают в `int64`.
* Разные целые типы приводят явно: `int64(x)`.
* Среднее считают в `float64` и печатают через `%.2f`.

Дальше - ввод, где важны строки целиком: [Построчное чтение текста](lesson:go.first-steps.text-lines).

<!-- section: programmer -->
## Для тех, кто уже программирует

* `fmt.Scan` без буфера делает много мелких системных вызовов; для больших входов используют `bufio.NewReader(os.Stdin)` и `fmt.Fscan`. Для ещё большей скорости пишут свой разбор на `Reader` или `Scanner`.
* Целочисленное переполнение в Go определено и тихо: арифметика по модулю 2ⁿ; нет исключений, как в C# `checked`. Константные выражения, не помещающиеся в тип, ловит компилятор.
* `int` зависит от платформы; для данных с гарантированным размером берите `int32`/`int64`.
* Нет неявных числовых преобразований, даже `int` и `int64` складывать нельзя без `int64(x)`.
* `Fscan` возвращает `(n, err)`; в конце ввода `err == io.EOF`.
* `%.2f` не зависит от локали и всегда печатает точку.

## Что делает go build

Вся эта работа выполняется в уже собранной программе. Команда `go build` переводит исходный код в машинный код и создаёт один исполняемый файл; внутри него находится и небольшая среда выполнения Go (рантайм) с планировщиком горутин и сборщиком мусора. Отдельный интерпретатор или виртуальная машина не нужны. Размеры типов (`int32`, `int64`) определяют, в какие регистры процессора и в какие ячейки памяти положит значение компилятор, а переполнение - просто отбрасывание лишних старших разрядов результата сложения на уровне процессора. Именно поэтому оно не вызывает ошибки.
