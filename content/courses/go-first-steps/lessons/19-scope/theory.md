## Зачем это нужно

В больших программах десятки функций и сотни переменных. Если бы любое имя было видно везде, переменные постоянно путались бы друг с другом: изменить `i` в одной функции означало бы сломать цикл в другой. Поэтому каждая переменная живёт только в части программы, называемой её **областью видимости**. Её правила нужны, чтобы понимать, какая именно переменная имеется в виду, и находить ошибки, когда программа компилируется, но работает неверно.

## Одна новая идея: переменная видна от объявления до конца своего блока

**Блок** - это код между `{` и `}`: тело функции, ветка `if`, тело цикла. Переменная существует с места объявления и до закрывающей скобки её блока. Блоки вкладываются друг в друга: внутренний видит переменные внешнего, а внешний внутренние - нет.

```go
func main() {
    total := 0              // видна во всём теле main
    if true {
        bonus := 5          // видна только внутри if
        total = total + bonus
    }
    // здесь bonus уже не существует
}
```

Если во внутреннем блоке написать `x := ...`, а `x` уже есть снаружи, создастся **новая** переменная с тем же именем. Она скроет внешнюю (это называется **затенением**), и после выхода из блока внешняя останется прежней.

<!-- section: examples -->
## Пример 1. Внутренний блок видит внешний

```go run
package main

import "fmt"

func main() {
    price := 100
    if price > 50 {
        discount := 10
        fmt.Println("цена", price, "скидка", discount)
    }
    fmt.Println("после if цена", price)
}
```
```output
цена 100 скидка 10
после if цена 100
```

Внутри `if` видны и `price` (внешняя), и `discount` (своя). После закрывающей скобки `discount` исчезает. Попытка напечатать её там - ошибка компиляции.

## Пример 2. Затенение

```go run
package main

import "fmt"

func main() {
    x := 1
    if true {
        x := 2
        fmt.Println("внутри:", x)
    }
    fmt.Println("снаружи:", x)
}
```
```output
внутри: 2
снаружи: 1
```

`x := 2` объявила новую переменную внутри `if`; внешняя `x` не изменилась. Замените `:=` на `=`, и обе строки напечатают `2`: теперь команда меняет уже существующую переменную.

## Пример 3. Переменная цикла и тело функции

```go run
package main

import "fmt"

func sumTo(n int) int {
    sum := 0
    for i := 1; i <= n; i++ {
        sum = sum + i
    }
    return sum
}

func main() {
    sum := 100
    fmt.Println(sumTo(4))
    fmt.Println(sum)
}
```
```output
10
100
```

В `sumTo` и в `main` есть переменные с именем `sum`, но это разные переменные в разных функциях: функция `sumTo` не видит и не меняет `sum` из `main`. Внутри `sumTo` счётчик `i` существует только в цикле, а `sum` объявлена снаружи цикла, поэтому накапливает результат и доступна в `return`.

**Попробуйте.** В примере 3 замените в цикле `sum = sum + i` на `sum := sum + i` и предскажите, что произойдёт. Подсказка: компилятор Go не любит переменные, которые объявлены и не использованы.

## Точные правила

* **Блок** задают фигурные скобки. Отдельные блоки: тело функции, тело `if`/`else`, тело `for`. Параметры функции принадлежат её телу.
* **Время жизни имени**: от строки объявления до закрывающей `}` блока. Использовать переменную выше её объявления нельзя.
* **Вложенные блоки** видят внешние имена. Внешний блок не видит имён внутренних.
* **Переменные заголовков** `for i := 0; ...` и `if x := f(); ...` принадлежат своей конструкции и не видны после неё.
* **`:=` в блоке всегда объявляет новую переменную** (хотя бы одну новую слева) и затеняет одноимённую внешнюю. `=` только присваивает уже объявленной.
* **Затенение не ошибка**. Компилятор не предупреждает, если новая переменная использована; ошибка проявляется как неверный результат.
* **Неиспользуемая локальная переменная** - ошибка компиляции `declared and not used`. Именно она часто выдаёт затенение: внутренняя переменная была объявлена, но осталась без дела.
* **Как избежать**: объявляйте переменную в самом внешнем блоке, где она нужна (`var word string` до `if`), а в ветках используйте `=`. Не называйте внутренние переменные так же, как внешние, без необходимости.
* Переменные, объявленные вне функций, называются пакетными и видны всему пакету. В этом курсе мы почти не используем их: изменяемые общие переменные затрудняют чтение.

## Типичные ошибки

**1. Использование переменной за пределами блока.**

```go
if n < 0 {
    word := "отрицательное"
}
fmt.Println(word)
```

Компилятор:

```text
declared and not used: word
undefined: word
```

Первая строка: внутри `if` переменная нигде не использована. Вторая: после `}` имени `word` уже не существует. Исправление: объявить `var word string` до `if`, а внутри писать `word = "отрицательное"`.

**2. Переменная цикла за пределами цикла.**

```go
for i := 0; i < 3; i++ {
}
fmt.Println(i)
```

Компилятор: `undefined: i`. Если значение нужно после цикла, объявите переменную перед циклом и меняйте её внутри.

**3. Затенение без ошибки компиляции.**

```go
sum := 0
for i := 1; i <= 3; i++ {
    if i%2 == 1 {
        sum := sum + i
        fmt.Println(sum)
    }
}
fmt.Println(sum)
```

Программа компилируется: внутренняя `sum` использована в `Println`. Напечатано `1`, `3` и затем `0`. Внешняя `sum` не менялась, потому что `:=` создавало новую переменную. Исправление: заменить `:=` на `=`.

Как заметить самому: если итог равен нулю или стартовому значению, а внутри цикла значения растут, ищите `:=` там, где должно быть `=`. Если в программе одно имя означает разные переменные, дайте им разные имена.

<!-- section: summary -->
## Итоги

* Переменная видна от своего объявления до конца блока `{ ... }`; внутренние блоки видят внешние имена.
* `:=` внутри блока создаёт новую переменную и скрывает внешнюю (затенение); `=` меняет существующую.
* Ошибка `undefined` говорит, что имя вне своей области видимости.
* Тихая ошибка затенения даёт неверный результат без сообщения компилятора, её ищут по `:=` вместо `=`.

Теперь вы знаете достаточно, чтобы работать с функциями, которые могут не справиться с задачей: [Ошибка как значение](lesson:go.first-steps.errors-first-look).

## Для тех, кто уже программирует

* Областью видимости служит блок (лексическая область), как в C и Java; в отличие от Python, `if` и `for` создают собственную область.
* `:=` в блоке объявляет новую переменную, даже если внешняя с таким именем есть. Это самый частый источник багов с затенением (`err :=` в блоке и т. п.); отдельный анализатор `shadow` ищет такие случаи, но в стандартный `go vet` не входит.
* Неиспользуемые локальные переменные и импорты - ошибка компиляции, а не предупреждение.
* Переменная заголовка `for` с Go 1.22 создаётся заново на каждой итерации.
* Уровень пакета: порядок объявлений не важен; локального объявления выше использования достаточно.
* Видимость между пакетами определяется регистром первой буквы идентификатора.
