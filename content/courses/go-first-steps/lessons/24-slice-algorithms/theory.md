## Зачем это нужно

С данными в срезах постоянно делают три вещи: **ищут** нужное значение, **отбирают** подходящие (оценки выше порога, покупки дороже тысячи) и **упорядочивают** (по возрастанию цены). Эти приёмы складываются из знакомых конструкций: `range`, `if`, `append`.

## Одна новая идея: фильтрация собирает подходящее в новый срез, а сортировка меняет срез на месте

**Фильтрация** - обход с условием, в котором подходящие элементы добавляются в новый срез:

```go
var big []int
for _, v := range nums {
    if v > 100 {
        big = append(big, v)
    }
}
```

**Сортировка** - вызов функции `slices.Sort` из стандартного пакета `slices`:

```go
slices.Sort(nums)   // nums теперь по возрастанию
```

Функция ничего не возвращает: она переставляет элементы того же среза. Пакет подключают через `import "slices"`.

<!-- section: examples -->
## Пример 1. Фильтрация

```go run
package main

import "fmt"

func main() {
    prices := []int{120, 45, 300, 80, 150}
    var expensive []int
    for _, p := range prices {
        if p >= 100 {
            expensive = append(expensive, p)
        }
    }
    fmt.Println(expensive, len(expensive))
}
```
```output
[120 300 150] 3
```

Исходный срез `prices` не меняется: подходящие значения копируются в `expensive`, порядок сохраняется.

## Пример 2. Поиск первого совпадения

```go run
package main

import "fmt"

func main() {
    names := []string{"Анна", "Борис", "Вера", "Борис"}
    pos := -1
    for i, name := range names {
        if name == "Борис" {
            pos = i
            break
        }
    }
    if pos == -1 {
        fmt.Println("не найден")
    } else {
        fmt.Println("индекс:", pos)
    }
}
```
```output
индекс: 1
```

`pos := -1` - признак «ничего не найдено»: настоящий индекс не бывает отрицательным. `break` останавливает поиск на первом совпадении.

## Пример 3. Сортировка

```go run
package main

import (
    "fmt"
    "slices"
)

func main() {
    nums := []int{42, 7, 19, 7, 3}
    slices.Sort(nums)
    fmt.Println(nums)

    words := []string{"вишня", "арбуз", "банан"}
    slices.Sort(words)
    fmt.Println(words)
}
```
```output
[3 7 7 19 42]
[арбуз банан вишня]
```

Числа сортируются по значению, строки - по алфавиту (точнее, по кодам символов). Повторы остаются. Исходный порядок после сортировки потерян: если он нужен, сначала скопируйте данные в другой срез.

**Попробуйте.** В примере 1 замените порог на 1000 и предскажите вывод. В примере 3 отсортируйте срез `[]float64{2.5, -1, 0}`.

## Точные правила

* **Фильтрация** создаёт новый срез: `var out []T`, обход с `if`, `out = append(out, v)`. Если ничего не подошло, `out` остаётся пустым (длина 0): проверяйте `len(out) == 0`.
* **Поиск** обычно использует `for i, v := range s`, сравнение и `break`; индекс, который нельзя перепутать с настоящим (например, `-1`), показывает, что ничего не найдено.
* **`slices.Sort(s)`** требует, чтобы элементы можно было сравнивать по порядку: числа и строки подходят. Результат - порядок по возрастанию; функция меняет `s` на месте и ничего не возвращает.
* **Порядок для убывания**: отсортируйте и пройдите срез с конца либо вызовите `slices.Reverse(s)` после сортировки.
* **Пакет `slices`** есть в Go с версии 1.21. Другие его функции (`slices.Contains`, `slices.Max`, `slices.Index`) не обязательны для этого урока.
* **Стабильность**: равные числа неразличимы, поэтому порядок повторов не важен. Для сложных данных эти вопросы появятся позже.
* **Вывод через пробел** — как раньше: разделитель перед каждым элементом, кроме первого.

<!-- section: mistakes -->
## Типичные ошибки

**1. Забыли import.**

```go
xs := []int{3, 1, 2}
slices.Sort(xs)
```

Компилятор: `undefined: slices`. Добавьте `import "slices"` (или внесите пакет в круглые скобки к `fmt`).

**2. Используют результат сортировки.**

```go
sorted := slices.Sort(xs)
```

Компилятор: `slices.Sort(xs) (no value) used as value`. Функция меняет сам срез: вызовите `slices.Sort(xs)` и работайте с `xs`.

**3. Забыли вывести «ничего не нашлось».** Если фильтр отобрал ноль элементов, цикл вывода не выполнится и программа напечатает пустую строку. Проверьте `len(out) == 0`.

**4. Меняют срез, который перебирают.** Сортировка или `append` в тот же срез, по которому идёт `range`, ведёт к путанице. Фильтруйте в другой срез.

**5. Лишний пробел на конце.** Печать `fmt.Print(x, " ")` в цикле оставляет пробел после последнего значения. Разделитель ставят перед значением, кроме первого.

Как заметить самому: проверьте крайние случаи: пустой результат, один элемент, значения ровно на границе условия, повторы.

<!-- section: summary -->
## Итоги

* Фильтрация: обход, условие, `append` в новый срез.
* Поиск: обход с `break` и признаком «не найдено» (например, `-1`).
* `slices.Sort(s)` сортирует срез по возрастанию на месте и ничего не возвращает.
* Всегда продумайте случай, когда подходящих значений нет.

Для поиска по ключу срезы неудобны: пришлось бы перебирать весь срез. Для этого в Go есть карты: [Карты](lesson:go.first-steps.maps).

## Для тех, кто уже программирует

* `slices.Sort` - обобщённая функция (generics) из стандартной библиотеки с Go 1.21; сортирует на месте, ничего не возвращает. Для своего порядка есть `slices.SortFunc`.
* До 1.21 использовали пакет `sort` (`sort.Ints`, `sort.Slice`); он остаётся в языке, но для нового кода рекомендуют `slices`.
* Нет `filter`/`map` в стандартной библиотеке: фильтрация пишется циклом и `append`.
* `slices.Contains`, `slices.Index`, `slices.Max` - готовые поиски; в уроке сделаны циклом, чтобы показать механику.
* `var out []T` нормален как пустой результат: `nil`-срез безопасен для `len`, `range` и `append`.
