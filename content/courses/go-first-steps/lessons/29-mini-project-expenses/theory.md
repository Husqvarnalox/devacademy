## Что мы делаем

Новых понятий в этом уроке нет. Вы пишете законченную программу из знакомых частей: читаете строки, разбираете их, считаете суммы по категориям в карте и печатаете результат в понятном порядке. Главное, что нужно показать: программа не падает, когда данные плохие.

Задача в миниатюре: журнал расходов в строках `категория сумма`, а на выходе сводка. Вся тонкость в том, что в реальных данных всегда встречаются странные строки: пустые, с лишними словами, с буквами вместо числа. Хорошая программа их замечает, считает и идёт дальше.

## План программы

1. Читаем строки через `bufio.Scanner`.
2. Делим строку через `strings.Fields`; пустую пропускаем.
3. Проверяем строку: ровно два слова, сумма - целое число больше нуля. Иначе увеличиваем счётчик пропусков и берём следующую строку.
4. Прибавляем сумму в карту по категории.
5. После цикла собираем ключи в срез, сортируем и печатаем.

<!-- section: examples -->
## Пример 1. Проверка записи в отдельной функции

```go run
package main

import (
    "fmt"
    "strconv"
    "strings"
)

func parse(line string) (string, int, bool) {
    fields := strings.Fields(line)
    if len(fields) != 2 {
        return "", 0, false
    }
    amount, err := strconv.Atoi(fields[1])
    if err != nil || amount <= 0 {
        return "", 0, false
    }
    return fields[0], amount, true
}

func main() {
    fmt.Println(parse("еда 350"))
    fmt.Println(parse("еда"))
    fmt.Println(parse("еда -5"))
}
```
```output
еда 350 true
 0 false
 0 false
```

Функция возвращает три значения: категорию, сумму и признак успеха. Так проверку можно написать один раз. В первой строке вывода пробелы стоят между значениями; в остальных первая пустая категория видна как пробел в начале.

## Пример 2. Суммы по категориям и сортировка ключей

```go run
package main

import (
    "fmt"
    "slices"
)

func main() {
    sums := map[string]int{}
    sums["яблоки"] += 10
    sums["арбуз"] += 20
    sums["арбуз"] += 1

    keys := []string{}
    for k := range sums {
        keys = append(keys, k)
    }
    slices.Sort(keys)
    for _, k := range keys {
        fmt.Println(k, sums[k])
    }
}
```
```output
арбуз 21
яблоки 10
```

Порядок обхода карты не определён, поэтому для стабильного вывода ключи собирают в срез и сортируют.

## Пример 3. Подсчёт плохих строк

```go
package main

import (
    "bufio"
    "fmt"
    "os"
    "strconv"
    "strings"
)

func main() {
    sc := bufio.NewScanner(os.Stdin)
    good, bad := 0, 0
    for sc.Scan() {
        fields := strings.Fields(sc.Text())
        if len(fields) == 0 {
            continue
        }
        if len(fields) != 2 {
            bad++
            continue
        }
        if _, err := strconv.Atoi(fields[1]); err != nil {
            bad++
            continue
        }
        good++
    }
    fmt.Println(good, bad)
}
```

Для ввода из строк `еда 5`, `кофе много`, пустой строки и `a b c` программа напечатает `1 2`. Пустая строка не считается плохой: её пропускают раньше проверки.

**Попробуйте.** В примере 3 добавьте проверку `amount <= 0` для сумм и убедитесь, что `еда 0` попадает в плохие.

## Точная спецификация задачи

* **Корректная строка**: ровно два слова; второе - целое число больше нуля.
* **Пустая строка** (из пробелов или совсем пустая) игнорируется и не считается плохой.
* **Плохая строка**: любое другое число слов, не число (в том числе `1.5`), ноль и отрицательное число. Её пропускают и увеличивают счётчик.
* **Порядок вывода**: категории по возрастанию кодов символов (так сортирует `slices.Sort`: русские буквы идут в алфавитном порядке, но заглавные раньше строчных), затем `Итого: ...`, затем `Пропущено: ...`.
* **Пустой результат**: если категорий нет, печатаются только две последние строки.
* Сумма хранится в `int`; для этой задачи её хватает.

## Типичные ошибки

**1. Проверка слов после обращения к индексу.** `strconv.Atoi(fields[1])` до проверки `len(fields)` даёт панику `index out of range [1] with length 1` на строке из одного слова. Сначала проверяйте длину.

**2. Печать прямо из `range` по карте.** Порядок случайный, тесты то проходят, то нет. Сортируйте ключи.

**3. Считать пустые строки плохими.** По условию они игнорируются; это самая частая причина расхождения со счётчиком.

**4. Забыть `amount <= 0`.** `Atoi` успешно разбирает `-5` и `0`, ошибки не будет. Это бизнес-правило, а не ошибка разбора.

**5. Неиспользуемая переменная или импорт.** Компилятор: `declared and not used: err` или `"os" imported and not used`. Если значение не нужно, пишите `_`.

**6. Объявить карту без инициализации.** `var sums map[string]int` создаёт nil-карту, запись в неё вызывает `panic: assignment to entry in nil map`. Создавайте её через `map[string]int{}`.

## Итоги

* Программу удобно строить по плану: прочитать, проверить, накопить, вывести.

* Карта накапливает суммы, а стабильный порядок вывода даёт отсортированный срез ключей.

## Для тех, кто уже программирует

* Здесь типичный приём «разбор с валидацией»: функция возвращает `(значение, ok)` или `(значение, error)`, а вызывающий решает, что делать с плохой записью.
* Порядок обхода `map` в Go намеренно рандомизируется; детерминированный вывод требует сортировки ключей.
* `slices.Sort` сортирует строки по байтам UTF-8, что для кириллицы совпадает с порядком кодовых точек.
* Для денег в реальных системах не используют `float64`: целые копейки или десятичный тип. Здесь суммы целые рубли.
* При больших объёмах вместо накопления всего в памяти потоково обновляют агрегаты, как в этой программе.
