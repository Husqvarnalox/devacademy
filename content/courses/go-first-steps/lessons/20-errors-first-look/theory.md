## Зачем это нужно

Реальные данные бывают неверными: пользователь вводит слово вместо числа, файла нет на диске, сумма отрицательна. Программа должна не падать, а заметить проблему и отреагировать: сообщить пользователю или отказаться продолжать. В Go для этого функции возвращают **ошибку** рядом с результатом.

## Одна новая идея: ошибка - это обычное значение, которое нужно проверить

У ошибок есть собственный тип `error`. Функция, которая может не справиться, возвращает два значения: результат и ошибку. Если всё в порядке, ошибка равна `nil` (особому значению «ничего»). Если нет - ошибка содержит текст о причине.

```go
n, err := strconv.Atoi("42")
if err != nil {
    // что-то пошло не так: n использовать нельзя
}
```

`strconv.Atoi` (от «ASCII to integer») переводит строку в целое число `int`. Вместе с числом она возвращает `err`: `nil`, если строка была числом, и ненулевую ошибку, если нет. Проверка `if err != nil` стоит сразу после вызова и в Go встречается постоянно.

Свою ошибку создают так: `errors.New("текст")`.

<!-- section: examples -->
## Пример 1. Atoi: успех и неудача

```go run
package main

import (
    "fmt"
    "strconv"
)

func main() {
    n, err := strconv.Atoi("42")
    fmt.Println(n, err)

    n, err = strconv.Atoi("сорок два")
    fmt.Println(n, err)
}
```
```output
42 <nil>
0 strconv.Atoi: parsing "сорок два": invalid syntax
```

* Блок `import ( ... )` подключает сразу два пакета.
* В первом вызове `err` равна `nil`, и `Println` печатает её как `<nil>`.
* Во втором вызове строка не число: `n` равно `0`, а `err` хранит описание причины. Присваивание `n, err = ...` без двоеточия использует уже объявленные переменные (см. урок про область видимости).

## Пример 2. Функция, возвращающая ошибку

```go run
package main

import (
    "errors"
    "fmt"
)

func safeDiv(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("деление на ноль")
    }
    return a / b, nil
}

func main() {
    q, err := safeDiv(10, 2)
    if err != nil {
        fmt.Println("ошибка:", err)
        return
    }
    fmt.Println("частное:", q)

    q, err = safeDiv(1, 0)
    if err != nil {
        fmt.Println("ошибка:", err)
        return
    }
    fmt.Println("сюда не дойдём", q)
}
```
```output
частное: 5
ошибка: деление на ноль
```

Шаблон: в функции проверка плохого случая, `return` нулевого значения и ошибки; в конце - `return` результата и `nil`. Вызывающий код проверяет `err`, и при ошибке `return` в `main` завершает программу раньше. Без проверки второго вызова мы продолжили бы работать с бессмысленным нулём.

## Пример 3. Чтение числа из ввода

```go
package main

import (
    "fmt"
    "strconv"
)

func main() {
    var text string
    fmt.Scan(&text)
    n, err := strconv.Atoi(text)
    if err != nil {
        fmt.Println("это не число")
        return
    }
    fmt.Println("вдвое больше:", n*2)
}
```

Если ввод `21`, программа напечатает `вдвое больше: 42`. Если ввод `abc`, - `это не число`. Слово читается как строка, а проверку числа выполняет `Atoi`. Блок без слова `run` потому, что программе нужен ввод.

**Попробуйте.** В примере 2 вызовите `safeDiv(7, 0)` первым и предскажите вывод. Затем в примере 1 замените строку на `" 7"` (с пробелом) и проверьте, считает ли Atoi её числом.

## Точные правила

* **Тип `error`** встроенный. Нулевое значение (`nil`) означает «ошибки нет». Печатая ошибку, `Println` выводит её текст.
* **Соглашение**: ошибка - последнее из возвращаемых значений. Вызывающий код проверяет `if err != nil` сразу после вызова.
* **При ошибке** остальные результаты по соглашению нулевые (`0`, `""`) и использовать их нельзя.
* **`strconv.Atoi(s)`** принимает строку и возвращает `(int, error)`. Допустим необязательный знак `+` или `-` и десятичные цифры. Пробелы, дробная часть, пустая строка и буквы дают ошибку; слишком большое число - ошибку `value out of range`.
* **`errors.New("текст")`** возвращает новую ошибку. Пакет `errors` нужно подключить в `import`. Текст пишут со строчной буквы, без точки в конце: ошибку часто вставляют в более длинное сообщение.
* **Ранний выход**: при ошибке функция сразу делает `return`, а основной путь остаётся без вложенных `else`.
* **Игнорировать ошибку** можно через `_`, но только осознанно: когда данные заведомо корректны. В остальных случаях пропущенная проверка скрывает проблему.
* **Каждый импорт нужно использовать**: лишний пакет в `import` - ошибка компиляции, как и неиспользуемая переменная.

## Типичные ошибки

**1. Один результат вместо двух.**

```go
n := strconv.Atoi("5")
```

Компилятор: `assignment mismatch: 1 variable but strconv.Atoi returns 2 values`. Возьмите оба значения: `n, err := strconv.Atoi("5")`.

**2. Ошибка получена, но не использована.**

```go
n, err := strconv.Atoi(text)
fmt.Println(n)
```

Компилятор: `declared and not used: err`. Это защита: ошибка не должна пропасть незамеченной. Добавьте `if err != nil { ... }`. Если проверка сознательно не нужна, пишут `n, _ := ...`, но для вводимых данных так делать нельзя: при `abc` вы получите `0` и тихий неверный результат.

**3. Не подключён пакет.**

```go
n, err := strconv.Atoi("5")
```

Без `import "strconv"` компилятор скажет `undefined: strconv`. Если же пакет подключён, но не используется, сообщение будет `"errors" imported and not used`. Подключайте ровно те пакеты, которые нужны.

**4. Использование значения при ненулевой ошибке.**

```go
age, err := strconv.Atoi("x")
if err != nil {
    fmt.Println("ошибка")
}
fmt.Println(age * 2)
```

Компилятор молчит. Но после сообщения об ошибке программа продолжает работать с нулём. Добавьте `return` внутрь `if`, чтобы остановить выполнение.

Как заметить самому: читайте текст ошибки, который печатает программа (`strconv.Atoi: parsing "x": invalid syntax` называет функцию, строку и причину), и проверяйте границы: пустую строку, пробел, минус, очень большое число.

## Итоги

* Функция, которая может не справиться, возвращает `(результат, error)`; `nil` означает успех.
* `strconv.Atoi` переводит строку в `int`; ошибку проверяют сразу: `if err != nil`.
* Собственную ошибку создают через `errors.New("текст")`; при ошибке возвращают нулевое значение и ошибку.
* Пропущенная проверка не останавливает программу - она работает с неверными данными.

С этим вы закрыли блок функций. Дальше работа с наборами значений: [Массивы](lesson:go.first-steps.arrays).

## Для тех, кто уже программирует

* Нет исключений для обычных ошибок: функция возвращает `error` последним значением, а вызывающий код проверяет `if err != nil`. `panic` зарезервирован для ошибок программиста.
* `error` - интерфейс с методом `Error() string`; `errors.New` создаёт простейшую реализацию. Обёртки (`%w`), `errors.Is` и `errors.As` будут в курсе `go-fundamentals`.
* `strconv.Atoi` не обрезает пробелы и не принимает дробную часть, как и `ParseInt`; для `int64` и других основ есть `ParseInt`, для `float64` - `ParseFloat`.
* Неиспользованная `err` - ошибка компиляции, поэтому проверку приходится написать или явно сбросить в `_`.
* Типичная ловушка: `if err := f(); err != nil {...}` объявляет `err` в области `if`; затенение внешней `err` - источник багов (см. урок про область видимости).
