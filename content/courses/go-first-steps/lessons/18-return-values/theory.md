## Зачем это нужно

Функция, которая только печатает, полезна, но ограничена: результат нельзя использовать дальше. Чаще функция должна **вычислить** значение и отдать его: цену со скидкой, длину пути, остаток от деления. Тогда вызывающий код решает, что с ним делать: напечатать, сравнить, сложить с другим.

## Одна новая идея: return отдаёт результат вызывающему коду

```go
func double(n int) int {
    return n * 2
}
```

После списка параметров записан **тип результата**: `int`. Команда `return` вычисляет выражение, завершает функцию и передаёт значение туда, откуда её вызвали. Вызов `double(5)` в выражении ведёт себя как значение `10`.

Функция может вернуть **несколько** значений. Тогда типы результатов перечисляют в скобках, а в `return` и при приёме значений - через запятую:

```go
func divMod(a, b int) (int, int) {
    return a / b, a % b
}

q, r := divMod(17, 5)   // q = 3, r = 2
```

<!-- section: examples -->
## Пример 1. Результат как значение

```go run
package main

import "fmt"

func square(n int) int {
    return n * n
}

func main() {
    x := square(4)
    fmt.Println(x)
    fmt.Println(square(3) + square(2))
    if square(5) > 20 {
        fmt.Println("больше двадцати")
    }
}
```
```output
16
13
больше двадцати
```

Разбор:

* `square(n int) int` - один параметр `int`, результат тоже `int`;
* `x := square(4)` сохраняет результат в переменную;
* `square(3) + square(2)` - вызовы используются как числа: 9 + 4;
* вызов можно ставить в условие `if`.

## Пример 2. Результат типа bool

```go run
package main

import "fmt"

func isAdult(age int) bool {
    return age >= 18
}

func main() {
    fmt.Println(isAdult(17))
    if isAdult(30) {
        fmt.Println("доступ разрешён")
    }
}
```
```output
false
доступ разрешён
```

Функция-проверка возвращает `bool`, а `return age >= 18` возвращает результат сравнения. Такие функции читаются в условии почти как фраза.

## Пример 3. Два результата

```go run
package main

import "fmt"

func divMod(a, b int) (int, int) {
    return a / b, a % b
}

func main() {
    q, r := divMod(17, 5)
    fmt.Println("частное", q, "остаток", r)
    onlyQ, _ := divMod(100, 7)
    fmt.Println("только частное", onlyQ)
}
```
```output
частное 3 остаток 2
только частное 14
```

`q, r := divMod(17, 5)` объявляет две переменные сразу, по одной на каждый результат, в том же порядке, что и в `return`. Если один из результатов не нужен, на его место ставят `_` (пустой идентификатор): значение отбрасывается, а компилятор не жалуется на неиспользуемую переменную.

**Попробуйте.** Добавьте в пример 3 вызов `divMod(9, 3)` и предскажите оба результата. Затем напишите функцию `abs(n int) int`, возвращающую модуль числа через `if n < 0`.

## Точные правила

* **Объявление результата**: тип записывают после скобок с параметрами - `func f(a int) int`. Для нескольких результатов - в скобках: `func f(a int) (int, string)`.
* **return завершает функцию сразу**. Команды после него в том же пути не выполняются. Несколько `return` в разных ветках `if` допустимы.
* **Каждый путь должен вернуть значение**. Если у функции есть тип результата, а в конце можно «дойти до конца» без `return`, компилятор сообщает `missing return`.
* **Тип и число значений** в `return` должны совпадать с объявлением: `return 1, 2` для `(int, int)`.
* **Приём нескольких результатов**: слева столько же имён, сколько результатов. Лишний результат отбрасывают через `_`.
* **Вызов как значение**: результат можно присвоить, передать в другую функцию, сравнить. Функцию с двумя результатами в одиночное выражение (`x + divMod(1, 2)`) подставить нельзя.
* **Функция без результата** не пишет тип после скобок и может вызывать просто `return` без значений, чтобы выйти раньше.
* **Печать и возврат - разные вещи**: `fmt.Println(n)` показывает значение на экране, но вызывающий код его не получает.

## Типичные ошибки

**1. Нет return на каком-то пути.**

```go
func sign(n int) int {
    if n > 0 {
        return 1
    }
}
```

Компилятор: `missing return`. При `n <= 0` функция дошла бы до конца без значения. Добавьте `return` в конце: `return 0` (или ветку `else`).

**2. Принимаем два результата в одну переменную.**

```go
x := divMod(7, 2)
```

Компилятор: `assignment mismatch: 1 variable but divMod returns 2 values`. Напишите `x, _ := divMod(7, 2)`, если нужен только первый результат.

**3. Объявили переменную для результата и не использовали.**

```go
q, r := divMod(7, 2)
fmt.Println(q)
```

Компилятор: `declared and not used: r`. Либо используйте `r`, либо замените на `_`.

**4. Вернули значение не того типа или не то число значений.**

```go
func f() int {
    return "5"
}
```

Компилятор: `cannot use "5" (untyped string constant) as int value in return statement`. Для функции `(int, int)` команда `return 1` даёт `not enough return values` со строками `have (number)` и `want (int, int)`.

**5. Печатаем вместо возврата.** Функция с `fmt.Println(a + b)` внутри не вернёт сумму: вызвать её в выражении нельзя, а результат нельзя проверить. Если от функции нужно значение, объявите тип результата и используйте `return`.

Как заметить самому: компилятор указывает строку; сравните число и типы значений в `return` с объявлением функции и число переменных слева от `:=` с числом результатов.

## Итоги

* `func f(параметры) тип { return значение }` - функция, которая вычисляет и отдаёт результат.
* Вызов функции с результатом используется как обычное значение.
* Несколько результатов: `(int, int)`, `return a, b`, `x, y := f()`; ненужный результат отбрасывают через `_`.
* Каждый путь выполнения функции с результатом должен заканчиваться `return`.

Следующий вопрос: где живут переменные, объявленные внутри функций и блоков, и почему одно и то же имя может означать разные переменные. Это тема урока [Область видимости](lesson:go.first-steps.scope).

<!-- section: programmer -->
## Для тех, кто уже программирует

* Несколько возвращаемых значений - обычная часть языка (не кортеж и не структура): `a, b := f()`. Так возвращают результат вместе с ошибкой.
* Результат отбрасывается через `_`; присвоить результат нескольких значений одной переменной нельзя.
* Бывают именованные результаты (`func f() (q, r int)` и голый `return`); в курсе они не используются, так как ухудшают читаемость в коротких функциях.
* Нет перегрузки, значений по умолчанию, исключений: ошибка - обычное значение (следующие уроки).
* Компилятор требует `return` на каждом пути (проверка завершаемости); `panic` и бесконечный `for {}` считаются завершающими.
* Передача по значению: параметры копируются.
