## TypeScript - это JavaScript плюс проверка типов до запуска

Ни один движок не умеет выполнять типы. Браузеры и Node.js исполняют **JavaScript**; TypeScript добавляет к нему описания типов
(`x: number`) и отдельную программу-проверяющего, которая находит ошибки, пока код ещё не запущен. Поэтому в работе с TypeScript участвуют две разные роли:

1. **Компилятор `tsc`** читает `.ts`, проверяет типы и сообщает об ошибках. Он же умеет выпустить обычный `.js`, **стерев** все аннотации типов.
2. **Среда выполнения** (Node.js) запускает JavaScript. Типов она не знает.

Именно так устроен запуск в этом приложении: сначала `tsc --noEmit --strict` проверяет все `.ts` файлы (`--noEmit` - ничего не создавать,
только проверить), и при ошибке типов запуска не будет. Затем Node.js выполняет ваш файл, удаляя аннотации типов при загрузке.

Ввод и вывод устроены так, как в курсе «TypeScript с нуля»: `console.log` пишет в stdout, `readFileSync(0, "utf8")` читает весь stdin. Разница в том, что теперь у переменных есть типы:

```typescript
import { readFileSync } from "node:fs";

const text: string = readFileSync(0, "utf8");
const n: number = Number(text.trim());
```

## Что именно делает компилятор и что остаётся в программе

**Стирание типов.** Аннотации, `interface` и `type` существуют только на этапе проверки. После компиляции (или после «срезания» типов Node.js) их нет:
в рабочей программе нельзя спросить «какого типа этот интерфейс», нельзя написать `if (x instanceof Point)` для `interface Point`. Типы не добавляют проверок и не ускоряют программу.
Если в `tsc` ошибка, он по умолчанию всё равно может выпустить JavaScript (флаг `noEmitOnError` это запрещает); поэтому «код скомпилировался» и «типы сошлись» - разные утверждения.

**Два способа превратить `.ts` в исполняемое.**

* `tsc` выпускает `.js`-файлы (с настройками целевой версии языка и модульной системы), и их запускает `node`.
* Node.js умеет выполнять `.ts` напрямую, **срезая типы** (type stripping): он удаляет аннотации и ничего не проверяет. С Node.js 22.6 это включается флагом
  `--experimental-strip-types`, в более новых версиях - по умолчанию. Срезание работает только с синтаксисом, который можно стереть без смысловых преобразований.
  Поэтому `enum`, `namespace` с кодом и сокращённая запись свойств в параметрах конструктора напрямую не поддерживаются (флаг TypeScript `erasableSyntaxOnly` ловит такие конструкции).
  В этом курсе вы их не используете.

**Вывод типов.** Типы не обязательно писать везде. `const n = 5` имеет тип литерала `5`, `let m = 5` - `number`, `[1, 2, 3]` - `number[]`.
Аннотации обязательны на границах: параметры функций, значения из внешнего мира. Результат функции обычно выводится, но явная запись возвращаемого типа документирует намерение.

**Режим `strict`.** Включает группу проверок, в первую очередь `strictNullChecks` (`null` и `undefined` не входят в остальные типы) и `noImplicitAny` (тип `any` не подставляется молча).
Именно с `strict` TypeScript заметно полезнее; в этом курсе он включён всегда.

**Что `tsc` не проверяет.** Индексация массива `arr[0]` имеет тип элемента, даже если массив пуст: без отдельной опции `noUncheckedIndexedAccess` (она не входит в `strict`) `undefined` не отслеживается.
Значения из stdin и `JSON.parse` приходят снаружи, и тип им приходится приписывать самому, поэтому такая «проверка» - обещание, которое программа должна выполнить.

**Типы стандартной среды.** `readFileSync(0, "utf8")` возвращает `string`, потому что объявления Node.js (пакет `@types/node`) описывают перегрузку: с указанной кодировкой результат - строка, без неё - `Buffer`.

## Примеры

**Пример 1. Тип не существует во время работы.** Приведение `as number` меняет мнение компилятора, но не значение.

```typescript run
const raw: unknown = JSON.parse('"hello"');
const n = raw as number;      // компилятор верит, значение не меняется
console.log(typeof n);        // выполнение видит строку
console.log(typeof raw === "string" ? raw.toUpperCase() : "не строка");
```
```output
string
HELLO
```

`as` не проверяет и не преобразует ничего. Безопасный путь - проверить `typeof raw === "string"`: после проверки компилятор знает тип в ветке.

**Пример 2. Типизированная функция и вывод типов.**

```typescript run
interface Stats {
  count: number;
  total: number;
}

function summarize(nums: number[]): Stats {
  return { count: nums.length, total: nums.reduce((a, b) => a + b, 0) };
}

const s = summarize([4, 5, 6]);
console.log(s.count, s.total);
```
```output
3 15
```

`interface Stats` пропадёт при запуске, а вот объект `{ count, total }` - обычный объект JavaScript - останется.

**Пример 3. Что видит `tsc` (не запускается: содержит ошибку).**

```typescript
function double(x: number): number {
  return x * 2;
}
double("21");
// error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
```

Программа с таким вызовом в JavaScript отработала бы и дала `42` (умножение строки на число приведёт её к числу). TypeScript останавливает её до запуска, потому что вы объявили параметр числом.

## Типичные ошибки

* **Считать, что типы защищают от плохих данных во время работы.** Они проверяют только то, что видно в коде. Входные данные (stdin, JSON, сеть) не проверены, пока вы сами не проверите их в программе.
* **Ставить `as` или `any`, чтобы «убрать красное».** Это выключает проверку именно там, где она нужна. Если значение приходит снаружи, используйте `unknown` и сужайте тип.
* **Забывать `import type` для чисто типовых импортов, которые не стираются.** Обычный `import { X }` для чего-то, что существует только как тип, при срезании типов может привести к ошибке при загрузке модуля, потому что в JavaScript такого имени нет. Пишите `import type { X }`.
* **Использовать `enum` и `namespace`.** При запуске через срезание типов они не поддерживаются. Вместо `enum` берите объединение литералов: `type Dir = "up" | "down"`.
* **Складывать результат `Number(...)` и строку.** Если `Number("abc")` даёт `NaN`, тип остаётся `number`. Проверка `Number.isNaN` по-прежнему нужна.
* **Читать `tokens[0]` как гарантированный `string`.** При пустом вводе это `undefined`, а компилятор молчит.
* **Думать, что TypeScript - отдельный язык со своей средой.** Это надстройка: любая ошибка семантики JavaScript (например, `==`, `NaN`, ссылки) остаётся.

## Итоги

* `tsc` проверяет типы и может выпустить JavaScript без аннотаций; Node.js выполняет JavaScript или `.ts` со срезанными типами.
* Типы (`interface`, `type`, аннотации) стираются; во время работы их нет и ничего не проверяется само.
* `strict` включает `strictNullChecks` и `noImplicitAny`; вывод типов позволяет писать аннотации только на границах.
* Для `enum`, `namespace` и параметров-свойств срезание типов недостаточно; используйте стираемые конструкции.
* Ввод читается так же, как в уроке «[Чтение ввода](lesson:typescript.from-zero.reading-input)»: `readFileSync(0, "utf8")`, `trim`, `split`, явное преобразование.
