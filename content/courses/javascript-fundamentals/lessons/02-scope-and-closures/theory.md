## Где живёт переменная

**Область видимости** (scope) отвечает на вопрос: из какого места программы имя переменной видно. В современном JavaScript три способа объявить переменную:

* `const` - имя нельзя переприсвоить; видно только в блоке `{ ... }`, где объявлено;
* `let` - можно переприсваивать; тоже видно только в своём блоке;
* `var` - старый способ; видно во всей **функции** целиком, блоки (`if`, `for`) для него не граница.

**Замыкание** (closure) - это функция вместе с ссылкой на окружение, в котором она создана. Функция «помнит» переменные снаружи, даже когда внешняя функция давно завершилась.

```javascript run
function makeGreeter(greeting) {
  return function (name) {
    return greeting + ", " + name + "!";
  };
}
const hello = makeGreeter("Привет");
console.log(hello("мир"));
```
```output
Привет, мир!
```

Здесь `greeting` принадлежит завершившемуся вызову `makeGreeter`, но внутренняя функция по-прежнему его видит. Правило выбора: по умолчанию `const`, `let` - когда значение нужно менять, `var` в новом коде не нужен.

## Области видимости, подъём, TDZ и замыкания

### Окружения и поиск имени

Когда код обращается к имени, движок ищет его в текущем окружении (environment), затем в объемлющем и так до глобального. Эта цепочка определяется **местом в тексте программы** (лексическая область видимости), а не тем, откуда функцию вызвали. Спецификация описывает это как Environment Record с ссылкой на внешнее окружение ([ECMAScript: Executable Code and Execution Contexts](https://tc39.es/ecma262/#sec-executable-code-and-execution-contexts)).

### var, let и const

* `var` создаёт переменную в окружении **функции** (или глобальном), не в блоке.
* `let` и `const` создают переменную в окружении **блока**.
* `const` фиксирует привязку имени, но не делает объект неизменяемым: `const a = []; a.push(1)` допустимо.

### Подъём (hoisting) и временная мёртвая зона

Объявления обрабатываются до выполнения кода области. Следствия:

* `var x` «поднимается»: переменная существует с начала функции со значением `undefined`. Присваивание остаётся на своём месте.
* **Объявление функции** (`function f() {}`) поднимается вместе с телом, поэтому её можно вызвать раньше по тексту. А `var f = function () {}` поднимает только `var f` (значение `undefined`), и ранний вызов даёт `TypeError`.
* `let`, `const` и `class` тоже создаются в начале блока, но **до строки объявления недоступны**. Этот промежуток называется временной мёртвой зоной (temporal dead zone, TDZ). Обращение к такой переменной даёт `ReferenceError`, а не `undefined`.

```javascript run
function demo() {
  console.log("var до объявления:", typeof a, a);
  var a = 1;
  try {
    console.log(b);
  } catch (e) {
    console.log(e.name + ": " + e.message);
  }
  let b = 2;
  console.log("функция вызвана раньше текста:", early());
  function early() { return "ok"; }
}
demo();
```
```output
var до объявления: undefined undefined
ReferenceError: Cannot access 'b' before initialization
функция вызвана раньше текста: ok
```

### Область блока и функции

Блок ограничивает `let`/`const`, а `var` его игнорирует. Параметры функции и её `var` живут в окружении функции.

```javascript run
if (true) {
  var fromVar = "видно снаружи";
  let fromLet = "видно только внутри";
}
console.log(fromVar);
console.log(typeof fromLet);
```
```output
видно снаружи
undefined
```

### Замыкания и привязка в цикле

Замыкание захватывает не **значение**, а **привязку** (binding) - место, где лежит переменная. Если за время жизни функции переменная изменилась, функция увидит новое значение.

Классический пример - цикл. Один `var i` на всю функцию делится всеми итерациями. А у `for (let i = ...)` на каждую итерацию создаётся **новая привязка** `i` (в спецификации это шаг CreatePerIterationEnvironment, [ECMAScript: for-loop evaluation](https://tc39.es/ecma262/#sec-forbodyevaluation)), значение копируется в неё из предыдущей.

```javascript run
const withVar = [];
for (var i = 0; i < 3; i++) withVar.push(() => i);
const withLet = [];
for (let j = 0; j < 3; j++) withLet.push(() => j);
console.log(withVar.map((f) => f()));
console.log(withLet.map((f) => f()));
```
```output
[ 3, 3, 3 ]
[ 0, 1, 2 ]
```

### Область видимости модуля

Файл с `import`/`export` (ES-модуль) и файл CommonJS в Node.js имеют **свою** область видимости: `var` и функции верхнего уровня не становятся свойствами глобального объекта. Доступ к глобальному объекту даёт `globalThis` ([MDN: globalThis](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/globalThis)). Код ES-модуля всегда выполняется в строгом режиме. Присваивание необъявленному имени в строгом режиме - `ReferenceError`.

## Примеры

**Приватное состояние через замыкание.** Переменная `count` недоступна снаружи, ей можно управлять только через возвращённые функции.

```javascript run
function createCounter() {
  let count = 0;
  return {
    inc: () => ++count,
    value: () => count,
  };
}
const a = createCounter();
const b = createCounter();
a.inc(); a.inc(); b.inc();
console.log(a.value(), b.value(), typeof a.count);
```
```output
2 1 undefined
```

**Старый способ починить цикл с `var`: IIFE.** Немедленно вызываемая функция создаёт своё окружение на каждой итерации. Сейчас достаточно `let`.

```javascript run
const fns = [];
for (var i = 0; i < 3; i++) {
  fns.push(((k) => () => k)(i));
}
console.log(fns.map((f) => f()));
```
```output
[ 0, 1, 2 ]
```

**Функция «видит» переменную, а не её копию.**

```javascript run
let level = 1;
const show = () => level;
level = 2;
console.log(show());
setTimeout(() => console.log("таймер:", level), 0);
level = 3;
```
```output
2
таймер: 3
```

**var в модуле не попадает в globalThis.**

```javascript run
var topLevel = 1;
console.log(typeof globalThis.topLevel, typeof topLevel);
```
```output
undefined number
```

## Типичные ошибки

* **`var` в цикле и асинхронный колбэк.** Все колбэки видят последнее значение `i`. Используйте `let` или `const` (для `for...of`).
* **Использование `let`/`const` до объявления.** Это `ReferenceError` (TDZ), даже если такое же имя есть снаружи: внутренняя привязка закрывает внешнюю с самого начала блока.
* **Вызов `var f = function(){}` раньше объявления.** Получите `TypeError: f is not a function`, а не работающую функцию.
* **Ожидание, что `const` защищает содержимое.** Защищено только имя; объект меняется свободно (`Object.freeze` защищает поверхностно).
* **Случайные глобальные переменные.** В нестрогом режиме `x = 5` без объявления создаёт глобальное свойство. В модулях это ошибка, в скриптах включайте `"use strict"`.
* **Утечки памяти через замыкания.** Долгоживущая функция удерживает всё окружение, на которое ссылается. Не храните в замыкании большие структуры без необходимости.

<!-- section: summary -->
## Итоги

* `let`/`const` - область блока, `var` - область функции; по умолчанию пишите `const`.
* Объявления поднимаются; `var` получает `undefined`, `let`/`const` недоступны до объявления (TDZ, `ReferenceError`).
* Замыкание - функция плюс её лексическое окружение; она захватывает привязки, а не копии значений.
* В `for (let ...)` у каждой итерации своя привязка, в `for (var ...)` она одна.
* У файла-модуля своя область видимости; ES-модули всегда в строгом режиме. `globalThis` - стандартное имя глобального объекта.
