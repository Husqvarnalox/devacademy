## Зачем этот урок

Если вы пишете на Python, Java, C# или Go, то циклы, условия и функции в JavaScript узнаете сразу. Сложности начинаются там, где язык делает «удобные» вещи молча: складывает число со строкой, считает `"0" == false` истинным, возвращает `undefined` вместо ошибки и разрешает использовать переменную до объявления. Урок собирает такие места в одном месте. Успешное прохождение (упражнение и квиз) засчитывает уроки 01-12 курса «JavaScript с нуля».

## Главная мысль

JavaScript динамически типизирован и **слабо** типизирован: операторы сами приводят значения к нужному типу. Поэтому три привычки решают большинство проблем: сравнивать только через `===`, проверять числа через `Number.isFinite` и `Number.isNaN`, а отсутствие значения различать через `??` и `?.`, а не через `||`.

<!-- section: examples -->
## Пример 1. Равенство и приведение типов

```javascript run
console.log(1 == "1", 0 == "", null == undefined, null == 0, "0" == false);
console.log(1 === "1", NaN === NaN, Object.is(NaN, NaN), [NaN].includes(NaN));
console.log(1 + "2", "3" * "4", "5" - 2, [] + {}, [1, 2] + [3]);
console.log(null >= 0, null > 0, undefined >= 0);
```
```output
true true true false true
false false true true
12 12 3 [object Object] 1,23
true false false
```

`==` приводит типы по сложным правилам, а `===` не приводит ничего. Исключение, которое используют намеренно, - `x == null`: это истина только для `null` и `undefined`. Оператор `+` при любой строке склеивает, а `-`, `*`, `/` всегда переводят операнды в числа. Операторы `>=` и `<` приводят `null` к `0`, поэтому `null >= 0` истинно, хотя `null == 0` ложно.

## Пример 2. Числа: один тип на всё

```javascript run
console.log(0.1 + 0.2, 0.1 + 0.2 === 0.3);
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON);
console.log(Math.round((0.1 + 0.2) * 100) / 100);
console.log(2 ** 53 === 2 ** 53 + 1, Number.MAX_SAFE_INTEGER);
console.log(typeof NaN, Number("abc"), Number(""), Number(" "), parseInt("42px"));
console.log(5 / 0, -5 / 0, 0 / 0, 7 / 2, Math.trunc(7 / 2), -7 % 3);
```
```output
0.30000000000000004 false
true
0.3
true 9007199254740991
number NaN 0 0 42
Infinity -Infinity NaN 3.5 3 -1
```

Все числа - `double` (64 бита, IEEE 754). Отдельного целочисленного типа нет: `7 / 2` равно `3.5`, а целую часть берут через `Math.trunc` или `Math.floor`. Деление на ноль не бросает исключение, а даёт `Infinity` или `NaN`. Тип `NaN` - `"number"`, и он не равен даже самому себе. Для денег хранят целые центы либо округляют результат; для очень больших целых есть `BigInt` (`123n`), но он не смешивается с обычными числами в одной арифметике.

## Пример 3. let, const и зона временной недоступности

```javascript run
try {
  console.log(a);
  let a = 1;
} catch (e) {
  console.log(e.name + ": " + e.message);
}
console.log(typeof neverDeclared);
console.log(hoisted);
var hoisted = 5;
const list = [1];
list.push(2);
console.log(list);
try {
  const k = 1;
  k = 2;
} catch (e) {
  console.log(e.name);
}
```
```output
ReferenceError: Cannot access 'a' before initialization
undefined
undefined
[ 1, 2 ]
TypeError
```

Объявление `let` и `const` «поднимается» в начало блока, но до строки с объявлением переменная находится в **зоне временной недоступности** (TDZ): обращение даёт `ReferenceError`. Старый `var` ведёт себя иначе: поднимается со значением `undefined`, видим во всей функции и не создаёт блочной области. Современный код использует `const` по умолчанию и `let` для переменных, которые переприсваиваются. `const` запрещает **переприсваивание**, но не изменение содержимого объекта или массива. `typeof` необъявленного имени безопасно возвращает `"undefined"`.

## Пример 4. undefined, null и значения по умолчанию

```javascript run
const pick = (x) => x ?? "по умолчанию";
console.log(pick(0), pick(""), pick(null), pick(undefined));
console.log(0 || "d", "" || "d", 0 ?? "d");
const user = { profile: {} };
console.log(user.profile.name, user.settings?.theme, user.settings?.theme ?? "light");
console.log(typeof null, typeof undefined, [1, 2, 3][5]);
function f(a, b = 10) { return [a, b]; }
console.log(f(1), f(1, undefined), f(1, null));
```
```output
0  по умолчанию по умолчанию
d d 0
undefined undefined light
object undefined undefined
[ 1, 10 ] [ 1, 10 ] [ 1, null ]
```

`undefined` - «значения нет» (необъявленное свойство, пропущенный аргумент, выход за границу массива); `null` - значение, которое поставили намеренно. Чтение отсутствующего свойства **не бросает ошибку**, а вот чтение свойства у самого `undefined` или `null` - бросает `TypeError`; для цепочек служит `?.`. Оператор `||` заменяет любое «ложное» значение (`0`, `""`, `false`, `NaN`), а `??` - только `null` и `undefined`. Значение по умолчанию параметра срабатывает на `undefined`, но не на `null`.

## Пример 5. Циклы: for...in и for...of

```javascript run
const arr = ["a", "b"];
arr.extra = 1;
for (const i in arr) console.log("in", i, typeof i);
for (const v of arr) console.log("of", v);
for (const [i, v] of arr.entries()) console.log("entries", i, v);
console.log([..."héy"].length, "héy".length, "😀".length);
let i = 0;
outer: for (; i < 3; i++) {
  for (let j = 0; j < 3; j++) {
    if (j === 1) continue outer;
    if (i === 2) break outer;
  }
}
console.log(i);
```
```output
in 0 string
in 1 string
in extra string
of a
of b
entries 0 a
entries 1 b
3 3 2
2
```

`for...in` перебирает **имена свойств** (строками, включая унаследованные и добавленные вручную), поэтому для массивов он почти всегда ошибка. `for...of` перебирает **значения** любого итерируемого объекта: массива, строки, `Map`, `Set`. Строка содержит UTF-16 единицы: символ вне базовой плоскости (эмодзи) имеет `length` 2, а `[...str]` разбирает её по кодовым точкам. Метки (`outer:`) нужны редко, но `break` и `continue` с меткой есть. Оператор `switch` сравнивает через `===` и «проваливается» без `break`.

<!-- section: precise -->
* Типы-примитивы: `number`, `string`, `boolean`, `undefined`, `null`, `symbol`, `bigint`. Всё остальное - объекты (массивы, функции, даты). `typeof null === "object"` - историческая ошибка языка; `typeof` функции - `"function"`.
* Ложные значения (falsy): `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`. Всё остальное истинно, включая `"0"`, `"false"`, `[]` и `{}`.
* `==` сначала приводит типы (`null == undefined`; строка и число сравниваются как числа; булево превращается в число; объект - в примитив), `===` сравнивает без приведения, `Object.is` отличает `NaN` от `NaN` (равны) и `0` от `-0` (различны).
* Проверка на `NaN`: `Number.isNaN(x)`. Глобальный `isNaN("abc")` сначала приводит к числу и потому истинно. Проверка «конечное число»: `Number.isFinite(x)` (не приводит типы, в отличие от глобального `isFinite`).
* `Number(s)` требует число во всей строке, но считает `""` и `"  "` нулём; `parseInt("42px")` читает ведущие цифры; `parseInt(s, 10)` всегда указывайте основание.
* `+` складывает числа или склеивает строки; унарный `+x` - краткая форма `Number(x)`; `%` сохраняет знак делимого (`-7 % 3 === -1`).
* `let`/`const` - блочная область видимости и TDZ; `const` запрещает только переприсваивание. Повторное объявление в той же области - `SyntaxError`.
* `&&`, `||`, `??` возвращают **один из операндов**, а не булево значение, и вычисляют правый операнд лениво.
* В `for (let i...)` каждая итерация получает собственную копию `i`; в `for (var i...)` переменная одна на всю функцию.
* Точка с запятой в конце строки необязательна (автоматическая вставка), но строка, начинающаяся с `(` или `[`, может «прилипнуть» к предыдущей. Дисциплина: ставьте `;` либо используйте форматтер.

<!-- section: mistakes -->
**1. `==` вместо `===`.** `"" == 0` и `"0" == false` истинны, а `"" == "0"` ложно: отношение не транзитивно. Используйте `===`; единственное намеренное исключение - `x == null`.

**2. Проверка `x === NaN`.** Всегда ложна. Нужны `Number.isNaN(x)` или `Object.is(x, NaN)`.

**3. Сравнение дробей напрямую.** `0.1 + 0.2 === 0.3` ложно. Сравнивайте с допуском, храните целые единицы (центы) или округляйте результат.

**4. `||` для значений по умолчанию.** `const port = config.port || 8080` превратит законный `0` в `8080`. Нужен `??`.

**5. Число пришло строкой.** `"5" + 1` равно `"51"`, а `"5" - 1` равно `4`; значения из ввода и JSON приводите явно и проверяйте результат `Number.isFinite`.

**6. `typeof x === "object"` для проверки объекта.** Истинно для `null` и массивов. Для массива: `Array.isArray(x)`; для «непустого объекта»: `x !== null && typeof x === "object"`.

**7. `for...in` по массиву.** Получаете индексы-строки и лишние свойства, а `i + 1` склеивает: `"0" + 1 === "01"`. Нужен `for...of` или `for (let i = 0; ...)`.

**8. `var` в цикле и «поднятие».** Переменная `var` видна вне блока, а чтение до присваивания даёт `undefined` без ошибки. Пишите `const`/`let`.

## Главное для тех, кто уже программирует

* Сравнивайте через `===`/`!==`. `==` приводит типы и нетранзитивен; допустим только `x == null`.
* Один числовой тип `number` (double). Целочисленного деления нет: `Math.trunc(a / b)`. Деление на ноль не бросает исключений. `NaN !== NaN`; проверяйте `Number.isNaN`. `0.1 + 0.2 !== 0.3`. `BigInt` - отдельный тип.
* `+` склеивает строки, если хотя бы один операнд строка; `-`, `*`, `/` приводят к числу. `Number("")` равно `0`.
* `const` не делает объект неизменяемым; `let`/`const` блочные и имеют TDZ; `var` функциональный и поднимается. Используйте `const` по умолчанию.
* Две «пустоты»: `undefined` (нет значения) и `null` (пусто намеренно). `??` и `?.` работают только с ними; `||` реагирует на все ложные значения.
* Ложные: `false 0 -0 0n "" null undefined NaN`; `[]`, `{}` и `"0"` истинны.
* `for...of` - значения, `for...in` - ключи-строки (не для массивов). `switch` использует `===` и проваливается без `break`.
* Строки - UTF-16 и неизменяемы; `length` считает единицы, а не символы.
