## Тип - это обещание о форме значения

В TypeScript у каждого значения есть **тип**: описание того, что с ним можно делать. Вы пишете тип сами (**аннотация**: `x: number`) или доверяете компилятору, и он **выводит** тип по коду (**вывод типов**, inference). Хороший стиль - это баланс: аннотации стоят на границах (параметры функций, экспортируемые значения), а внутри функций работает вывод.

Вторая идея урока - **структурная типизация**. Значение подходит туда, где ожидается тип, если у него есть все нужные свойства нужных типов. Откуда значение взялось и как называется его тип, неважно. Единственное исключение - проверка лишних свойств у свежего литерала объекта: она ловит опечатки в именах полей.

```typescript
interface Point2D { x: number; y: number }

function norm(p: Point2D): number {
  return Math.hypot(p.x, p.y);
}

const p = { x: 3, y: 4, label: "A" }; // лишнее поле label
norm(p);                               // 5, форма подходит
```

## Аннотация, вывод, структура

**Где типы пишут, а где выводят.** Компилятор выводит тип переменной по инициализатору, возвращаемый тип функции по её `return`, а типы параметров колбэка по тому, куда колбэк передан (**контекстная типизация**: в `[1, 2].map(x => x * 2)` параметр `x` получает тип `number` без аннотации). Параметр обычной функции без контекста вывести нельзя: в режиме `strict` (точнее, при `noImplicitAny`) `function f(x) {}` - ошибка TS7006. Типичное правило: аннотируйте параметры и публичный результат, остальное оставляйте выводу. Явный возвращаемый тип полезен на границе модуля: он фиксирует контракт, и случайное изменение тела не изменит его молча.

**Расширение литералов.** `const n = 42` имеет тип литерала `42`, потому что значение не может измениться. `let m = 42` получает широкий тип `number`: переменной позже могут присвоить другое число. То же происходит со свойствами объекта: в `{ mode: "dark" }` поле `mode` получает тип `string`, потому что поле можно перезаписать. Чтобы зафиксировать литералы, пишут `as const` (поля становятся `readonly` с литеральными типами) или аннотацию нужного типа.

**Структурная совместимость.** Тип `S` присваиваем в `T`, если у `S` есть все свойства `T` с совместимыми типами. Лишние свойства допустимы. Так же сравниваются функции: функция с меньшим числом параметров подходит туда, где ожидается функция с большим (лишние аргументы она игнорирует), но не наоборот.

**Проверка лишних свойств (excess property check).** Если *свежий литерал объекта* присваивается или передаётся туда, где ожидается объектный тип, любое неизвестное свойство - ошибка TS2353. «Свежий» значит, что литерал написан прямо в месте передачи. Как только объект побывал в переменной, он перестаёт быть свежим, и лишние свойства допускаются: проверка нужна, чтобы ловить опечатки в литералах, а не запрещать структурные подтипы. Для типов, у которых *все* свойства необязательные (**слабые типы**), есть дополнительное правило: значение без единого общего свойства - ошибка TS2559, даже если оно не свежий литерал.

**Где структурность заканчивается.** Классы с `private`/`protected` членами сравниваются номинально: два класса с одинаковыми приватными полями несовместимы, потому что объявления «раздельные». Типы во время работы не существуют, поэтому структурная совместимость - только договорённость компилятора, а не проверка значений.

**Типы стираются.** Аннотации исчезают при запуске, поэтому `x: number` не гарантирует, что внутри действительно число, если значение пришло извне (об этом - в уроке про `unknown`).

## Примеры

**Пример 1. Что вывел компилятор.** Типы нельзя напечатать, но их можно проверить присваиванием: вспомогательный тип `Equal` даёт `true`, только если типы тождественны, и присваивание `true` к переменной другого типа не скомпилируется.

```typescript run
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;

const n = 42;
let m = 42;
const names = ["a", "b"];
function double(x: number) {
  return x * 2;
}
const r = double(4);

const t1: Equal<typeof n, 42> = true;
const t2: Equal<typeof m, number> = true;
const t3: Equal<typeof names, string[]> = true;
const t4: Equal<typeof r, number> = true;
console.log(t1, t2, t3, t4, r);
```
```output
true true true true 8
```

`const` даёт литерал `42`, `let` - `number`, массив строк - `string[]`, а возвращаемый тип `double` выведен как `number` без аннотации. Если заменить одно из ожиданий (например, `Equal<typeof m, 42>`), программа перестанет компилироваться.

**Пример 2. Структура важнее имени.** Класс не объявляет, что реализует интерфейс, но подходит по форме. Лишнее поле допустимо, если объект передан через переменную.

```typescript run
interface Point2D { x: number; y: number }

class Vec {
  x: number;
  y: number;
  constructor(x: number, y: number) {
    this.x = x;
    this.y = y;
  }
}

function norm(p: Point2D): number {
  return Math.hypot(p.x, p.y);
}

const withLabel = { x: 3, y: 4, label: "A" };
console.log(norm(withLabel));
console.log(norm(new Vec(6, 8)));
```
```output
5
10
```

**Пример 3. Свежий литерал и проверка лишних свойств.** Тот же объект, но написанный прямо в вызове, компилятор отвергает. Сообщение приведено так, как его выдаёт `tsc` 7.0.2.

```typescript
norm({ x: 1, y: 2, label: "A" });
// error TS2353: Object literal may only specify known properties,
// and 'label' does not exist in type 'Point2D'.
```

Слабый тип ловит опечатку и без литерала:

```typescript
interface Options { color?: string; size?: number }
function setOptions(o: Options): void {}

const typo = { colour: "red" };
setOptions(typo);
// error TS2559: Type '{ colour: string; }' has no properties in common with type 'Options'.
```

**Пример 4. Расширение свойств объекта.** Поле `mode` у обычного объекта - `string`, а `as const` сохраняет литерал.

```typescript run
type Mode = "dark" | "light";
function setMode(m: Mode): string {
  return `mode=${m}`;
}

const loose = { mode: "dark" };
const fixed = { mode: "dark" } as const;

// setMode(loose.mode);  // ошибка: Argument of type 'string' is not assignable to parameter of type 'Mode'
console.log(setMode(fixed.mode));
```
```output
mode=dark
```

**Пример 5. Номинальность через private.**

```typescript
class A { private secret = 1; }
class B { private secret = 1; }
const a: A = new B();
// error TS2322: Type 'B' is not assignable to type 'A'.
//   Types have separate declarations of a private property 'secret'.
```

## Типичные ошибки

* **Аннотировать всё подряд.** `const total: number = items.length * 2` ничего не добавляет к выводу и шумит. Аннотируйте параметры, публичные возвращаемые значения и места, где вывод даёт слишком широкий или слишком узкий тип.
* **Лечить ошибку типов словом `any` или `as`.** `function distance(a: any, b: any)` компилируется, но тип перестаёт защищать: опечатка в имени поля или строка вместо числа проходят молча. Упражнение этого урока специально проверяет, что типы остаются точными.
* **Ожидать ошибку на лишнее поле у переменной.** Проверка лишних свойств касается только свежих литералов; для остальных объектов лишние поля нормальны.
* **Ожидать защиту во время работы.** Структурная совместимость и аннотации существуют только при компиляции.
* **Принимать `Point2D[]` там, где функция массив не меняет.** Массив `readonly Point2D[]` нельзя передать в параметр типа `Point2D[]`, потому что тот разрешает `push`. Если функция только читает, пишите `readonly Point2D[]`, и ей подойдёт любой массив.

<!-- section: summary -->
## Коротко

* Тип пишут сами (аннотация) или получают от компилятора (вывод). Параметры и границы модуля аннотируют, внутренности выводят.
* `const` сохраняет литерал (`42`), `let` и поля объектов расширяют (`number`, `string`); `as const` фиксирует литералы.
* Типы сравниваются по структуре: лишние свойства допустимы, имя и способ создания неважны.
* Свежий литерал проверяется строго (TS2353), слабый тип без общих свойств - ошибка (TS2559), `private` делает класс номинальным.
* `readonly T[]` в параметре говорит «функция не меняет массив» и принимает и обычные, и неизменяемые массивы.
