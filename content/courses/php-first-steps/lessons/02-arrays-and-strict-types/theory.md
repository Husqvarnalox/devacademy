## У PHP одна структура для списков и словарей

Работать с массивами и `declare(strict_types=1)` вы уже умеете по курсу «PHP с нуля». Этот урок объясняет, как они устроены внутри и где границы их поведения.

В PHP нет отдельных «списка» и «словаря». Есть один тип `array` - **упорядоченный ассоциативный массив**: набор пар «ключ -> значение»,
который помнит порядок вставки. Ключ - целое число или строка.

```php
$list = ["a", "b", "c"];                 // ключи 0, 1, 2
$map  = ["name" => "Ann", "age" => 30];  // ключи-строки
$map["city"] = "Riga";                   // добавили в конец
```

Второе отличие от многих языков: массив - это **значение**. Присваивание создаёт независимую копию (логически), и изменение копии не затрагивает оригинал.

Третье: директива `declare(strict_types=1);` в начале файла переключает правила приведения скалярных типов при вызове функций. Без неё `"5"` для параметра `int` молча станет `5`; с ней будет `TypeError`.

<!-- section: precise -->
## Массив как упорядоченная хеш-таблица

**Реализация.** Массив PHP - хеш-таблица, которая дополнительно хранит элементы в порядке вставки. Отсюда следуют свойства: доступ по ключу в среднем за O(1), `foreach` обходит в порядке вставки,
а «обычный список» - просто массив, у которого ключи 0, 1, 2, ... идут подряд.

**Нормализация ключей.** Ключ приводится к одному из двух типов:

* строка, похожая на десятичное целое без ведущих нулей и знака плюс (`"8"`, `"-3"`), становится **целым**; `"08"` и `"1.5"` остаются строками;
* `true` и `false` становятся `1` и `0`, `null` - пустой строкой `""`, дробные числа усекаются (в новых версиях такое неявное усечение помечено как устаревшее).

Поэтому `$a["1"]` и `$a[1]` - один и тот же элемент. А при чтении ключей через `foreach ($a as $k => $v)` или `array_keys` значение `"1"` вернётся **целым числом**.
Это важно вместе с `strict_types`: передача такого ключа в функцию, ожидающую `string`, вызовет `TypeError`.

**Добавление.** `$a[] = $x` добавляет элемент с ключом «наибольший целый ключ + 1» (или `0` для массива без целых ключей).
`unset($a[1])` удаляет элемент, но **не пересчитывает** остальные ключи: после этого массив уже не список. Чтобы получить новый список с ключами `0..n-1`, используйте `array_values`.

**Семантика значения (copy-on-write).** `$b = $a` не копирует данные сразу; копия делается при первом изменении. Для программиста это выглядит как независимые массивы.
Передача массива в функцию тоже по значению; чтобы изменить исходный, параметр объявляют ссылкой `&$arr`. Объекты (экземпляры классов) ведут себя иначе: переменная хранит идентификатор объекта, и копия переменной указывает на тот же объект.

**`foreach` по ссылке.** `foreach ($a as &$v)` оставляет `$v` ссылкой на последний элемент. Если после цикла снова использовать `$v` (например, в следующем `foreach`), последний элемент будет перезаписан. После цикла делайте `unset($v)`.

**`isset` и `array_key_exists`.** `isset($a["k"])` ложно, если ключа нет или значение равно `null`. `array_key_exists("k", $a)` проверяет именно наличие ключа. Оператор `??` ведёт себя как `isset`: `$a["k"] ?? 0`.

**Слияние.** `array_merge($x, $y)` перенумерует целые ключи и перезапишет совпадающие строковые; оператор `+` оставляет значения из левого массива для совпадающих ключей (включая числовые).

**Сортировка.** С PHP 8.0 сортировка **устойчивая**: равные по сравнению элементы сохраняют исходный порядок. `sort` перенумеровывает ключи, `asort`/`arsort` сохраняют пары ключ-значение и сортируют по значению (по возрастанию / по убыванию), `ksort` - по ключу.

**Сравнение `==` в PHP 8.** При сравнении числа со строкой PHP 8 приводит число к строке, если строка нечисловая. Поэтому `0 == "a"` в PHP 8 ложно (в PHP 7 было истинно). Две числовые строки сравниваются как числа: `"10" == "1e1"` истинно, `"1" == "01"` истинно.
Для проверки значения и типа используйте `===`. Функции `in_array` и `array_search` по умолчанию сравнивают нестрого: третий аргумент `true` включает строгое сравнение.

**`declare(strict_types=1)`.** Должна быть самой первой инструкцией файла. Действует только на вызовы, которые совершает *этот файл*: и на пользовательские функции, и на встроенные.
В строгом режиме скаляр не приводится: `"5"` для `int` - `TypeError`, `5` для `float` допустим (расширение `int` до `float` разрешено), `strlen(123)` - `TypeError`. Без неё скаляры приводятся, если приведение «без потерь».

## Примеры

**Пример 1. Нормализация ключей и добавление.**

```php run
<?php
$a = [];
$a["1"] = "one";        // ключ станет целым 1
$a["01"] = "zero-one";  // остаётся строкой
$a[true] = "bool";      // true -> 1, перезапишет элемент
$a[] = "next";          // следующий целый ключ: 2
echo json_encode(array_keys($a)), "\n";
echo $a[1], "\n";
```
```output
[1,"01",2]
bool
```

`"1"` и `true` попали в один ключ `1`, поэтому значение `"one"` было перезаписано. Ключ `"01"` не похож на каноническое целое и остался строкой.

**Пример 2. Массив - значение.**

```php run
<?php
$a = [1, 2];
$b = $a;
$b[] = 3;
echo count($a), " ", count($b), "\n";

function addOne(array $x): array { $x[] = 1; return $x; }
$c = addOne($a);
echo count($a), " ", count($c), "\n";
```
```output
2 3
2 3
```

Ни присваивание, ни передача в функцию не изменили `$a`. В JavaScript или Python такой код изменил бы один и тот же объект.

**Пример 3. Ловушка `foreach` по ссылке.**

```php run
<?php
$x = [1, 2, 3];
foreach ($x as &$v) {}
foreach ($x as $v) {}
echo json_encode($x), "\n";
```
```output
[1,2,2]
```

После первого цикла `$v` остаётся ссылкой на `$x[2]`. Второй цикл присваивает `$v` значения 1, 2 и снова 2 (уже изменённый элемент), и последний элемент перезаписывается.

**Пример 4. `isset` и `array_key_exists`, слияние.**

```php run
<?php
$m = ["a" => null];
var_dump(isset($m["a"]), array_key_exists("a", $m));
echo json_encode(array_merge([1, 2], [3])), json_encode([1, 2] + [5, 6, 7]), "\n";
echo json_encode(array_values(array_filter([5, 0, 7]))), "\n";
```
```output
bool(false)
bool(true)
[1,2,3][1,2,7]
[5,7]
```

`array_filter` без колбэка отбрасывает «ложные» значения вместе с ключами, `array_values` пересобирает список без пропусков.

**Пример 5. `strict_types`.**

```php run
<?php
declare(strict_types=1);

function add(int $a, int $b): int { return $a + $b; }
function half(float $x): float { return $x / 2; }

try {
    echo add("5", 3), "\n";
} catch (TypeError $e) {
    echo "TypeError\n";
}
echo add(5, 3), "\n";
var_dump(half(5));
```
```output
TypeError
8
float(2.5)
```

В строгом режиме строка для `int` отвергается, а целое для `float` допустимо. Без `declare` первая попытка вернула бы `8`.

**Пример 6. Устойчивая сортировка по значению.**

```php run
<?php
$counts = ["b" => 2, "a" => 2, "c" => 3, "d" => 1];
arsort($counts);
echo json_encode($counts), "\n";
```
```output
{"c":3,"b":2,"a":2,"d":1}
```

У `b` и `a` одинаковое значение, и они остались в исходном порядке (`b` перед `a`), потому что сортировка устойчивая.

## Типичные ошибки

* **Считать ключ `"1"` строкой.** При чтении он станет `int`. Если дальше он передаётся в функцию с типом `string` при `strict_types=1`, будет `TypeError`: приведите явно `(string) $k`.
* **Забыть, что массив копируется.** Изменение массива внутри функции не видно снаружи без `&` или возврата значения.
* **Оставить `&$v` после `foreach`.** Это приводит к перезаписи последнего элемента при следующем использовании `$v`. Добавляйте `unset($v)`.
* **Использовать `isset`, когда значение может быть `null`.** Для проверки именно наличия ключа берите `array_key_exists`.
* **`in_array("abc", $list)` без третьего аргумента.** Нестрогое сравнение может принять неожиданные совпадения (например, `"1e1"` и `"10"`).
* **Ожидать пересчёта ключей после `unset` или `array_filter`.** Ключи сохраняются; для списка применяйте `array_values`.
* **Ставить `declare(strict_types=1)` не первым оператором.** Это фатальная ошибка. Директива также не действует на файлы, которые вызывают вашу функцию: строгость определяется файлом *вызывающего*.
* **Думать, что `strict_types` проверяет всё.** Он касается только скалярных типов в вызовах и возвратах; содержимое `array` он не проверяет.

<!-- section: summary -->
## Итоги

* `array` - упорядоченная хеш-таблица: ключи `int` или `string`, порядок вставки сохраняется, строки вида `"8"` становятся целыми ключами.
* Массивы передаются и присваиваются как значения (copy-on-write); ссылка нужна только когда это нужно явно.
* `isset` и `??` не отличают отсутствующий ключ от `null`, `array_key_exists` отличает.
* Сортировка в PHP 8 устойчивая; `arsort` сортирует по значению с сохранением ключей.
* `declare(strict_types=1)` отключает неявное приведение скаляров в вызовах из этого файла, но допускает `int` для `float`.
