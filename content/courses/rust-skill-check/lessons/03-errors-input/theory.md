## Что проверяет эта проверка

Ввод и ошибки: чтение через `read_to_string`, `parse::<T>()` и его `Result`, различие `Ok` и `Err`, `unwrap`, `unwrap_or`, `match`, `.ok()` и оператор `?` внутри функций с `Option` и `Result`, поведение `f64::parse` с `nan` и `inf`.

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). ## Пример того, что понадобится

```rust run
fn parse_whole(text: &str) -> Option<i32> {
    text.parse::<i32>().ok()
}

fn parse_finite(text: &str) -> Option<f64> {
    let value: f64 = text.parse().ok()?;
    if value.is_finite() {
        Some(value)
    } else {
        None
    }
}

fn main() {
    for text in ["42", "4x", " 4", "+7", "-0", "99999999999", "2.5", ""] {
        println!("{:?} -> {:?}", text, parse_whole(text));
    }
    for text in ["2.5", "1e2", "nan", "inf", "1e999", ".5"] {
        println!("{:?} -> {:?}", text, parse_finite(text));
    }
    let n: u8 = "300".parse().unwrap_or(0);
    println!("{n}");
}
```

```output
"42" -> Some(42)
"4x" -> None
" 4" -> None
"+7" -> Some(7)
"-0" -> Some(0)
"99999999999" -> None
"2.5" -> None
"" -> None
"2.5" -> Some(2.5)
"1e2" -> Some(100.0)
"nan" -> None
"inf" -> None
"1e999" -> None
".5" -> Some(0.5)
0
```

Метод `parse` разбирает **всю** строку: `4x`, пробел в начале, дробь для целого типа и пустая строка дают `Err`, а знак `+` допустим. Число, которое не помещается в тип, - тоже `Err`, а не переполнение, поэтому `"300"` для `u8` превращается в запасное значение 0. Для `f64` слова `nan` и `inf` разбираются успешно, и огромное `1e999` превращается в бесконечность: если такие значения недопустимы, их отсекают проверкой `is_finite()`. Метод `.ok()` превращает `Result` в `Option`, а `?` внутри функции с `Option` возвращает `None` при неудаче.

## Что нужно уметь

* читать весь ввод через `read_to_string` и разбирать его построчно или по словам;
* использовать `parse::<T>()` и обрабатывать `Result` через `match`, `unwrap_or`, `.ok()` или `?`, а `unwrap` оставлять там, где ошибка невозможна;
* помнить, что `parse` разбирает строку целиком, не терпит пробелов и дробной части для целых типов и сообщает о выходе за диапазон ошибкой;
* отвергать `NaN` и бесконечность для `f64` через `is_finite()` и проверять знак (`> 0.0`);
* считать и пропускать плохие строки вместо аварийной остановки;
* возвращать из своих функций `Option` или `Result`, а не вызывать `panic!` из-за плохого ввода.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Оставить `unwrap()` на пользовательском вводе: первая же опечатка остановит программу.
* Забыть `trim()` и получить ошибку разбора из-за перевода строки или пробела.
* Считать, что `"12abc"` даст `12`: в Rust это `Err`.
* Принять `NaN` и `inf`: проверка `value > 0.0` для `inf` истинна, и бесконечная сумма попадёт в результат.
* Проверять `value > 0.0` для `NaN` и ждать `true`: сравнение с `NaN` всегда ложно.
* Разобрать число в `i32` и не заметить, что `99999999999` не помещается: это `Err`.
