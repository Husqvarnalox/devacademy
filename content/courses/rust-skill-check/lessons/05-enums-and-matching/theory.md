## Что проверяет эта проверка

Структуры и перечисления: поля и методы `struct`, `enum` с вариантами без данных, с кортежными и именованными полями, полный `match` (без пропущенных вариантов), охранные условия `if`, привязка значений из варианта и `if let`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Первая структура: поля и методы](lesson:rust.from-zero.first-struct), [Структуры, перечисления и сопоставление с образцом](lesson:rust.fundamentals.structs-enums-pattern-matching).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```rust run
#[derive(Debug)]
enum Ticket {
    Adult,
    Child { age: u32 },
    Group(u32),
}

fn price(ticket: &Ticket) -> u32 {
    match ticket {
        Ticket::Adult => 500,
        Ticket::Child { age } if *age < 6 => 0,
        Ticket::Child { .. } => 250,
        Ticket::Group(n) => n * 400,
    }
}

fn main() {
    let tickets = vec![
        Ticket::Adult,
        Ticket::Child { age: 4 },
        Ticket::Child { age: 9 },
        Ticket::Group(3),
    ];
    for t in &tickets {
        println!("{:?} -> {}", t, price(t));
    }
    if let Ticket::Group(n) = &tickets[3] {
        println!("group of {n}");
    }
}
```

```output
Adult -> 500
Child { age: 4 } -> 0
Child { age: 9 } -> 250
Group(3) -> 1200
group of 3
```

Вариант перечисления может нести данные: `Child { age }` хранит возраст, `Group(n)` - число людей. `match` обязан покрыть **все** варианты: если убрать ветку `Group`, программа не скомпилируется. Охранное условие `if *age < 6` уточняет ветку, а `{ .. }` означает «остальные поля нас не интересуют». Ветки проверяются сверху вниз, поэтому более узкая ветка должна стоять выше более общей. `if let` удобен, когда нужен только один вариант.

<!-- section: precise -->
## Что нужно уметь

* описать `enum` с вариантами разных видов: без данных, `Name(T)` и `Name { поле: T }`;
* написать `match`, который покрывает все варианты, и объяснить, почему компилятор требует полноты;
* извлекать данные из варианта в ветке `match` и использовать охранные условия `if`;
* учитывать порядок веток: первая подошедшая побеждает, а `_` ловит всё остальное;
* использовать `if let`, когда важен один вариант, и `Option` как результат разбора, который может не удаться;
* создавать структуру, читать её поля и вызывать метод из `impl`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Добавить новый вариант в `enum` и забыть ветку в `match` без `_`: компилятор укажет на все такие места (`E0004`), это полезно, а не мешает.
* Поставить `_ =>` слишком рано и перекрыть более конкретные ветки.
* Ставить широкую ветку выше узкой: узкая никогда не сработает (`unreachable pattern`).
* Забыть, что `match` по ссылке даёт ссылки на данные варианта (`*age`).
* Использовать `_` в `match` по собственному `enum` и этим отключить проверку полноты при добавлении вариантов.
* Путать вариант `Name(T)` с вызовом функции: `Ticket::Group(3)` - это конструктор значения.
