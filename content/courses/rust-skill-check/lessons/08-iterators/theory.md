## Что проверяет эта проверка

Коллекции и итераторы: `iter`, `iter_mut` и `into_iter`, адаптеры `map`, `filter`, `enumerate`, `zip`, `take_while`, потребители `sum`, `count`, `fold`, `collect`, `max_by_key`, ленивость итераторов и поведение при равных элементах, а также `BTreeMap` и `HashMap`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Коллекции и итераторы](lesson:rust.fundamentals.collections-and-iterators).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

## Пример того, что понадобится

```rust run
use std::collections::BTreeMap;

fn main() {
    let numbers = vec![1, 2, 3, 4, 5, 6];

    let squares: Vec<i32> = numbers.iter().filter(|n| *n % 2 == 0).map(|n| n * n).collect();
    println!("{:?}", squares);

    let total: i32 = numbers.iter().sum();
    let running: Vec<i32> = numbers
        .iter()
        .scan(0, |acc, n| {
            *acc += n;
            Some(*acc)
        })
        .collect();
    println!("{} {:?}", total, running);

    let words = ["tea", "cup", "tea", "pot", "tea"];
    let mut counts: BTreeMap<&str, usize> = BTreeMap::new();
    for w in words {
        *counts.entry(w).or_insert(0) += 1;
    }
    println!("{:?}", counts);

    let pairs: Vec<(usize, &str)> = words.iter().copied().enumerate().skip(3).collect();
    println!("{:?}", pairs);

    let lazy = numbers.iter().map(|n| n * 100);
    println!("nothing computed yet, then {}", lazy.count());
}
```

```output
[4, 16, 36]
21 [1, 3, 6, 10, 15, 21]
{"cup": 1, "pot": 1, "tea": 3}
[(3, "pot"), (4, "tea")]
nothing computed yet, then 6
```

Цепочка `filter` -> `map` -> `collect` описывает преобразование, а работа начинается только в потребителе (`collect`, `sum`, `count`, `for`): без него итератор ничего не делает. `scan` хранит состояние между шагами, поэтому подходит для накопленных сумм. `entry(w).or_insert(0)` возвращает ссылку на счётчик, которую обновляют через `*`. `BTreeMap` хранит ключи упорядоченно, а `HashMap` - в произвольном порядке, поэтому в тестах с выводом нужен именно `BTreeMap`.

## Что нужно уметь

* различать `iter()` (ссылки), `iter_mut()` (изменяемые ссылки) и `into_iter()` (владение);
* собирать результат цепочкой адаптеров и потребителя: `filter`, `map`, `enumerate`, `zip`, `sum`, `count`, `fold`, `collect`;
* знать, что итераторы ленивы: адаптеры не выполняются, пока их не потребует `collect`, `sum`, `count`, цикл `for` и подобные;
* помнить, что `max_by_key` и `max` возвращают **последний** из равных максимумов, а `min_by_key` - первый из равных минимумов;
* указывать тип для `collect` (`Vec<_>`, `HashMap<_, _>`, `Result<Vec<_>, _>`);
* выбирать `BTreeMap` для детерминированного порядка вывода и `HashMap` - когда порядок не важен.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Построить цепочку `map(...)` и не вызвать потребитель: функция внутри `map` не выполнится ни разу (будет предупреждение о неиспользованном значении).
* Итерироваться по вектору через `for x in v` и пытаться использовать `v` после цикла: вектор перемещён (`E0382`).
* Забыть тип у `collect()` и получить ошибку «type annotations needed».
* Рассчитывать, что `max_by_key` вернёт первый из равных: он возвращает последний.
* Печатать `HashMap` в тесте и получать разный порядок при разных запусках.
* Использовать `zip` и ожидать длину по длинному итератору: он останавливается на более коротком.
