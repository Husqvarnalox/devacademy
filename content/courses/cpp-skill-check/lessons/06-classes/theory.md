## Что проверяет эта проверка

Классы и конструкторы со списком инициализации, наследование, виртуальные функции и `override`, абстрактные классы (чисто виртуальные функции), виртуальный деструктор у базового класса, срезку объекта при передаче по значению, перегрузку `operator<<` и `operator==`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок [Классы, перегрузка операторов, наследование и виртуальные функции](lesson:cpp.fundamentals.classes-inheritance-virtual).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет этот урок как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

## Пример того, что понадобится

```cpp run
#include <iostream>
#include <memory>
#include <string>
#include <utility>
#include <vector>

class Animal {
public:
    virtual ~Animal() = default;
    virtual std::string sound() const = 0;
};

class Dog : public Animal {
public:
    explicit Dog(std::string name) : name_(std::move(name)) {}
    std::string sound() const override { return name_ + ": woof"; }
    const std::string& name() const { return name_; }

private:
    std::string name_;
};

class Puppy : public Dog {
public:
    explicit Puppy(std::string name) : Dog(std::move(name)) {}
    std::string sound() const override { return name() + ": yip"; }
};

bool operator==(const Dog& a, const Dog& b) { return a.name() == b.name(); }

std::ostream& operator<<(std::ostream& out, const Animal& animal) {
    return out << "[" << animal.sound() << "]";
}

std::string byValue(Dog d) { return d.sound(); }
std::string byReference(const Dog& d) { return d.sound(); }

int main() {
    std::vector<std::unique_ptr<Animal>> zoo;
    zoo.push_back(std::make_unique<Dog>("rex"));
    zoo.push_back(std::make_unique<Puppy>("tiny"));
    for (const auto& a : zoo) {
        std::cout << *a << "\n";
    }

    Puppy p("tiny");
    std::cout << byReference(p) << " " << byValue(p) << "\n";
    std::cout << (Dog("a") == Dog("a")) << (Dog("a") == Dog("b")) << "\n";
}
```
```output
[rex: woof]
[tiny: yip]
tiny: yip tiny: woof
10
```

Вызов через ссылку или указатель на базовый класс выбирает функцию по реальному типу объекта (`yip` у `Puppy`). Параметр `Dog d` по значению содержит только часть `Dog` и теряет остальное (срезка): виртуальный вызов даёт `woof`. Чтобы удалять объекты через указатель на базу, деструктор базы должен быть виртуальным.

## Что нужно уметь

* писать конструктор со списком инициализации и знать, что члены инициализируются в порядке объявления в классе, а не в порядке списка;
* различать перегрузку и переопределение, использовать `override` и понимать, что несовпадение сигнатуры (например, пропущенный `const`) - ошибка компиляции;
* объявлять базовый класс с виртуальным деструктором, если объекты удаляют через указатель на него;
* понимать, что класс с чисто виртуальной функцией (`= 0`) абстрактный и объект такого класса создать нельзя;
* знать, что передача производного объекта по значению в функцию с параметром базового типа его срезает;
* перегружать `operator<<(std::ostream&, const T&)` и `operator==` как свободные функции.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Базовый класс без виртуального деструктора, а удаление объекта через указатель на него: неопределённое поведение.
* Передача полиморфного объекта по значению вместо ссылки: срезка, виртуальные вызовы перестают работать.
* Пропущенный `const` или другая сигнатура у «переопределения»: без `override` получается новая функция, а не переопределение.
* Расчёт на порядок инициализации по списку: фактический порядок определяется объявлением членов.
* `operator<<`, объявленный внутри класса: аргументы поменяются местами, `std::cout << obj` не заработает.
* Попытка создать объект абстрактного класса.
