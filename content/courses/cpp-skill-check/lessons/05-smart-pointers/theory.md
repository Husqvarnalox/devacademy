## Что проверяет эта проверка

Умные указатели вместо `new`/`delete`: единоличное владение `std::unique_ptr` (перемещение, передача в функцию, фабрика), совместное владение `std::shared_ptr` и счётчик владельцев, слабая ссылка `std::weak_ptr` (`lock`, `expired`), создание через `std::make_unique` и `std::make_shared`, циклы из `shared_ptr` и почему они приводят к утечке.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок [RAII и умные указатели: unique_ptr, shared_ptr, weak_ptr](lesson:cpp.fundamentals.raii-smart-pointers).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет этот урок как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

## Пример того, что понадобится

```cpp run
#include <iostream>
#include <memory>
#include <string>
#include <utility>

struct Res {
    std::string name;
    explicit Res(std::string n) : name(std::move(n)) { std::cout << "make " << name << "\n"; }
    ~Res() { std::cout << "free " << name << "\n"; }
};

std::unique_ptr<Res> create(const std::string& name) {
    return std::make_unique<Res>(name);
}

void sink(std::unique_ptr<Res> res) {
    std::cout << "sink " << res->name << "\n";
}

int main() {
    auto u = create("u");
    sink(std::move(u));
    std::cout << (u == nullptr) << "\n";

    auto s = std::make_shared<Res>("s");
    std::weak_ptr<Res> w = s;
    {
        auto s2 = s;
        std::cout << s.use_count() << "\n";
    }
    std::cout << s.use_count() << "\n";
    s.reset();
    std::cout << w.expired() << "\n";
}
```
```output
make u
sink u
free u
1
make s
2
1
free s
1
```

`unique_ptr` нельзя скопировать, его можно только переместить: после `std::move(u)` указатель `u` пуст, а объект уничтожается там, где закончилась жизнь последнего владельца (здесь - в конце `sink`). У `shared_ptr` объект живёт, пока есть хотя бы один владелец; `weak_ptr` владельцем не является и не продлевает жизнь объекта, а `lock()` возвращает `shared_ptr` (пустой, если объекта уже нет).

<!-- section: precise -->
## Что нужно уметь

* создавать объекты через `std::make_unique` и `std::make_shared`, а не через голый `new`;
* знать, что `unique_ptr` не копируется, а передаётся в функцию и возвращается из неё перемещением; после `std::move` исходный указатель пуст;
* читать `use_count()`: копия `shared_ptr` увеличивает счётчик, `weak_ptr` его не меняет;
* получать доступ к объекту из `weak_ptr` только через `lock()` и проверять результат;
* понимать, что два `shared_ptr`, ссылающиеся друг на друга, никогда не освободятся, и разрывать цикл с помощью `weak_ptr`;
* принимать `unique_ptr` по значению, если функция забирает владение, и по ссылке или сырому указателю на объект, если не забирает.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Попытка скопировать `unique_ptr` вместо перемещения (ошибка компиляции).
* Использование указателя после `std::move`: он пуст, разыменование - неопределённое поведение.
* Цикл из `shared_ptr` (родитель владеет ребёнком, ребёнок владеет родителем): деструкторы не вызываются, память утекает.
* Чтение объекта через `weak_ptr` без `lock()` или без проверки его результата.
* Создание двух независимых `shared_ptr` из одного сырого указателя: объект будет освобождён дважды.
* Ожидание, что `weak_ptr` увеличивает `use_count()`.
