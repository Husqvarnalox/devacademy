## Что проверяет эта проверка

Как значения копируются и как передаются в функции: по значению, по ссылке `T&` и по константной ссылке `const T&`; что копирование `std::vector` и `std::string` создаёт независимый объект; в каком порядке вызываются конструкторы и деструкторы; идею RAII (ресурс освобождается деструктором при выходе из области видимости); опасность возврата ссылки на локальную переменную.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок [Значения, ссылки и RAII](lesson:cpp.first-steps.value-semantics-references-and-raii).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет этот урок как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

## Пример того, что понадобится

```cpp run
#include <iostream>
#include <string>
#include <utility>
#include <vector>

void byValue(std::vector<int> v) { v.push_back(0); }
void byReference(std::vector<int>& v) { v.push_back(0); }
std::size_t count(const std::vector<int>& v) { return v.size(); }

struct Guard {
    std::string name;
    explicit Guard(std::string n) : name(std::move(n)) { std::cout << "open " << name << "\n"; }
    ~Guard() { std::cout << "close " << name << "\n"; }
};

int main() {
    std::vector<int> a{1, 2};
    std::vector<int> b = a;
    b.push_back(3);
    byValue(a);
    std::cout << a.size() << " " << b.size() << "\n";
    byReference(a);
    std::cout << count(a) << "\n";

    Guard outer("a");
    {
        Guard inner("b");
        std::cout << "work\n";
    }
    std::cout << "end\n";
}
```
```output
2 3
3
open a
open b
work
close b
end
close a
```

Копия вектора независима от оригинала, а параметр `std::vector<int> v` - тоже копия, поэтому `byValue` ничего не меняет у вызывающего. `T&` меняет переменную вызывающего, `const T&` только читает и не копирует. Деструктор `Guard` вызывается автоматически при выходе из блока, в порядке, обратном созданию: сначала `inner`, потом `outer`.

<!-- section: precise -->
## Что нужно уметь

* предсказывать, изменится ли переменная вызывающего после вызова функции с параметром `T`, `T&` или `const T&`;
* знать, что присваивание и инициализация `std::vector`, `std::string` копируют содержимое;
* знать, что через `const T&` нельзя вызывать изменяющие методы (ошибка компиляции);
* называть порядок вызова конструкторов и деструкторов: конструкторы в порядке объявления, деструкторы в обратном порядке;
* написать простой RAII-класс: захват ресурса в конструкторе, освобождение в деструкторе;
* отличать безопасные возвраты ссылки (на аргумент, на `static`, на элемент контейнера вызывающего) от ссылки на локальную переменную.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Ожидание, что функция с параметром `std::vector<int> v` изменит вектор вызывающего.
* Передача больших объектов по значению там, где хватило бы `const T&`.
* Возврат ссылки или указателя на локальную переменную: после выхода из функции она уничтожена.
* Путаница с порядком деструкторов: объекты уничтожаются в порядке, обратном созданию.
* Ручное освобождение ресурса в конце функции: при раннем `return` или исключении оно пропускается.
