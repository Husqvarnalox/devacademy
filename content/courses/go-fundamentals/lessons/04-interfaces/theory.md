## Интерфейсы: поведение вместо иерархии

**Интерфейс** в Go - это набор методов. Любой тип, у которого есть все эти методы, **автоматически** удовлетворяет интерфейсу. Слова `implements` в языке нет: тип не объявляет, что он реализует интерфейс, и даже не обязан о нём знать.

```go
type Writer interface {
	Write(p []byte) (n int, err error)
}
```

Это объявление из пакета `io`. Файл, сетевое соединение, `bytes.Buffer`, HTTP-ответ - всё это `io.Writer`, потому что у них есть метод `Write` с такой подписью. Функция `fmt.Fprintf(w io.Writer, ...)` работает со всеми ними, не зная ни одного.

Идиома Go: **интерфейсы должны быть маленькими** и описываться на стороне **потребителя**. Пословица из Go Proverbs: «чем больше интерфейс, тем слабее абстракция». У `io.Reader` и `io.Writer` по одному методу, и именно поэтому из них собираются конвейеры: `io.Copy`, `bufio.Scanner`, `gzip.NewReader` принимают и возвращают такие интерфейсы.

У интерфейса есть особенность, на которой спотыкаются почти все: значение интерфейса - это пара «динамический тип + значение». Интерфейс, внутри которого лежит `nil`-указатель конкретного типа, **не равен `nil`**. Этой ловушке посвящён отдельный раздел ниже.

## Точные правила

**Объявление и удовлетворение.**

* `type Stringer interface { String() string }`. Тип удовлетворяет интерфейсу, если его **набор методов** содержит все методы интерфейса (для `T` - методы с получателем `T`, для `*T` - обоих видов; см. предыдущий урок).
* Интерфейсы встраиваются друг в друга: `type ReadWriter interface { Reader; Writer }`.
* Проверку «тип реализует интерфейс» на этапе компиляции часто пишут так: `var _ io.Reader = (*upperReader)(nil)`.
* **Принимайте интерфейсы, возвращайте конкретные типы.** Параметр функции описывают минимальным интерфейсом, а возвращают обычно конкретный тип: так вызывающий не теряет возможностей.
* Пустой интерфейс `interface{}` и его псевдоним `any` (с Go 1.18) удовлетворяется любым типом. Он снимает проверку типов, поэтому `any` применяют, когда тип действительно неизвестен (`fmt.Println`, JSON), а не по привычке.

**Что внутри значения интерфейса.**

* Значение интерфейса хранит пару (динамический тип, динамическое значение). Нулевое значение интерфейса - пара (`nil`, `nil`): это единственный случай, когда интерфейс `== nil`.
* Если в интерфейс положить `nil`-указатель, пара будет (`*T`, `nil`): тип задан, значит `iface != nil`. Вызов метода на таком значении допустим, а паника случится только при разыменовании внутри метода.
* Сравнение интерфейсов `==` сравнивает типы и значения; если динамический тип несравним (срез, карта, функция), сравнение вызывает панику во время выполнения.

**Утверждение типа и type switch.**

* `v := x.(T)` - утверждение типа: паника, если динамический тип не `T`. Форма `v, ok := x.(T)` паники не вызывает.
* Если `T` - интерфейс, утверждение проверяет, что динамический тип его реализует: `if s, ok := x.(fmt.Stringer); ok { ... }`.
* `switch v := x.(type) { case int: ...; case string, bool: ...; case nil: ...; default: ... }` выбирает ветвь по динамическому типу. В ветви с одним типом `v` имеет этот тип, в ветви с несколькими или в `default` - тип `x`. Ветви проверяются сверху вниз, поэтому порядок важен: тип, подходящий сразу двум интерфейсным веткам, попадёт в первую.
* Именованный тип `type celsius int` - это **другой** тип: ветка `case int` его не поймает.

**Практические рекомендации.**

* Определяйте интерфейс там, где его используют, а не там, где реализуют.
* Не создавайте интерфейс «на всякий случай» для типа с единственной реализацией.
* Реализуя `io.Reader`, помните контракт: `Read` может вернуть `n > 0` вместе с ошибкой (например, `io.EOF`), может вернуть меньше данных, чем помещается в буфер, и нельзя обращаться к `p[n:]`.

## Примеры

**Пример 1. Неявное удовлетворение и композиция `io.Reader`/`io.Writer`.**

```go run
package main

import (
	"fmt"
	"io"
	"os"
	"strings"
)

// shout оборачивает io.Writer и пишет текст заглавными буквами.
type shout struct{ w io.Writer }

func (s shout) Write(p []byte) (int, error) {
	return s.w.Write([]byte(strings.ToUpper(string(p))))
}

// Проверка на этапе компиляции.
var _ io.Writer = shout{}

func main() {
	w := shout{os.Stdout}
	fmt.Fprintf(w, "привет, %s!\n", "go") // Fprintf принимает io.Writer
	io.Copy(w, strings.NewReader("копируем из Reader в Writer\n"))

	// Комбинирование маленьких интерфейсов.
	var sb strings.Builder
	n, _ := io.Copy(io.MultiWriter(&sb, w), strings.NewReader("двойной вывод\n"))
	fmt.Println(n, sb.String() == "двойной вывод\n")
}
```

```output
ПРИВЕТ, GO!
КОПИРУЕМ ИЗ READER В WRITER
ДВОЙНОЙ ВЫВОД
26 true
```

Тип `shout` нигде не объявляет, что он `io.Writer`: достаточно метода `Write`. Поэтому `fmt.Fprintf`, `io.Copy` и `io.MultiWriter` принимают его без изменений.

**Пример 2. Интерфейс с `nil`-указателем не равен `nil`.**

```go run
package main

import "fmt"

type MyErr struct{ Code int }

func (e *MyErr) Error() string { return fmt.Sprint("код ", e.Code) }

// Ловушка: тип результата - error, а возвращаем (*MyErr)(nil).
func bad(fail bool) error {
	var e *MyErr
	if fail {
		e = &MyErr{500}
	}
	return e
}

// Правильно: при успехе возвращаем литерал nil.
func good(fail bool) error {
	if fail {
		return &MyErr{500}
	}
	return nil
}

func main() {
	err := bad(false)
	fmt.Println(err == nil)
	fmt.Printf("%T %v\n", err, err == (*MyErr)(nil))

	err = good(false)
	fmt.Println(err == nil)

	var e error // нулевое значение интерфейса: (nil, nil)
	fmt.Printf("%T %v\n", e, e == nil)
}
```

```output
false
*main.MyErr true
true
<nil> true
```

В `bad` интерфейс `error` получает пару (`*MyErr`, `nil`), и проверка `err != nil` в вызывающем коде сработает, хотя «ошибки нет». Правило: если функция возвращает интерфейс, возвращайте явный `nil`, а не переменную конкретного типа.

**Пример 3. Утверждения типа, type switch и `any`.**

```go run
package main

import (
	"fmt"
	"strconv"
	"time"
)

type celsius int

func (c celsius) String() string { return strconv.Itoa(int(c)) + "°C" }

func kind(v any) string {
	switch x := v.(type) {
	case nil:
		return "nil"
	case int:
		return "int " + strconv.Itoa(x)
	case string, bool: // в этой ветви x имеет тип any
		return fmt.Sprintf("string или bool: %v", x)
	case error:
		return "error " + x.Error()
	case fmt.Stringer:
		return "stringer " + x.String()
	default:
		return fmt.Sprintf("другое: %T", x)
	}
}

func main() {
	for _, v := range []any{nil, 42, "go", true, fmt.Errorf("сбой"), celsius(21), 3 * time.Second, 1.5} {
		fmt.Println(kind(v))
	}

	var x any = "строка"
	n, ok := x.(int)
	fmt.Println(n, ok)
	s := x.(string)
	fmt.Println(s)

	defer func() { fmt.Println("паника:", recover()) }()
	_ = x.(int) // без ok - паника
}
```

```output
nil
int 42
string или bool: go
string или bool: true
error сбой
stringer 21°C
stringer 3s
другое: float64
0 false
строка
паника: interface conversion: interface {} is string, not int
```

`celsius(21)` не попадает в `case int`: это другой тип, зато реализует `fmt.Stringer`. Без `ok` неудачное утверждение вызывает панику `interface conversion: interface {} is string, not int`.

## Типичные ошибки

* **Возврат `nil`-указателя через интерфейс.** `return e`, где `e` типа `*MyErr` со значением `nil`, делает `error` не-`nil`. Возвращайте литерал `nil`.
* **Слишком большие интерфейсы.** Интерфейс на десять методов трудно реализовать и подменить в тесте. Дробите на роли (`Reader`, `Closer`) и собирайте встраиванием.
* **Интерфейс рядом с реализацией «для моков».** Объявляйте интерфейс в пакете-потребителе и только с теми методами, что он вызывает.
* **Злоупотребление `any`.** Параметр типа `any` отключает проверки компилятора; для разных типов часто лучше дженерики или интерфейс с нужным методом.
* **Утверждение типа без `ok`.** `x.(T)` паникует при несовпадении; используйте форму `v, ok := x.(T)` или type switch.
* **Забыли, что именованный тип - другой тип.** `celsius` не попадёт в `case int`.
* **Неверный порядок ветвей в type switch.** Тип, удовлетворяющий и `error`, и `Stringer`, попадёт в ту ветвь, что выше.
* **Реализация `Read`, игнорирующая `n`.** Преобразовывать нужно `p[:n]`, а не весь буфер, иначе вы испортите байты, которые вызывающий ещё не заполнил.
* **Сравнение интерфейсов с несравнимым динамическим типом** (`[]int`, `map`): паника во время выполнения.
* **Метод на указателе, значение в интерфейсе.** `var s fmt.Stringer = Temp{}` не компилируется, если `String` объявлен на `*Temp`.

<!-- section: summary -->
## Итоги

* Интерфейс - набор методов; тип удовлетворяет ему неявно, и это позволяет описывать зависимости на стороне потребителя.
* Маленькие интерфейсы (`io.Reader`, `io.Writer`, `error`, `fmt.Stringer`) - главная идиома стандартной библиотеки; из них собираются конвейеры.
* Значение интерфейса - пара (тип, значение): интерфейс с `nil`-указателем внутри не равен `nil`. Возвращайте явный `nil`.
* Утверждение `v, ok := x.(T)` и `switch x.(type)` разбирают динамический тип; `any` отключает статическую проверку, применяйте его осознанно.
* Принимайте интерфейсы, возвращайте конкретные типы.

<!-- section: facts -->
## Факты

* Псевдоним `any` для `interface{}` появился вместе с дженериками в Go 1.18.
* В `io.Reader` написано в документации: вызывающий должен обрабатывать `n > 0` байтов до анализа ошибки, потому что `Read` вправе вернуть данные и `io.EOF` одновременно.
