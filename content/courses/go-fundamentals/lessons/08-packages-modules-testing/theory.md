## Пакеты, модули и тесты

**Модуль** - единица версионирования и распространения кода: дерево каталогов с файлом `go.mod` в корне. В `go.mod` записаны путь модуля (`module example.com/textkit`), минимальная версия языка (`go 1.26`) и зависимости. **Пакет** - каталог с `.go`-файлами с одним именем пакета; именно пакет импортируют: `import "example.com/textkit/slug"`.

Типичный модуль-библиотека выглядит так:

```text
textkit/
  go.mod
  slug/            # публичный пакет
    slug.go
    slug_test.go
  stats/
    stats.go
  internal/
    norm/          # доступен только внутри модуля
      norm.go
```

Правила видимости в Go минимальны:

* имя, начинающееся с **заглавной буквы** (`Slugify`), **экспортировано** и доступно из других пакетов; со строчной (`words`) - видно только внутри пакета;
* каталог **`internal`** добавляет ограничение на уровне импорта: пакет `.../internal/norm` могут импортировать лишь пакеты, чей путь начинается с родителя каталога `internal` (здесь - весь модуль `example.com/textkit`). Это способ спрятать реализацию, не раскрывая её как публичный API.

Тесты в Go - обычный код. Файл `имя_test.go` в том же каталоге, функция `TestXxx(t *testing.T)`, запуск `go test ./...`. Вы уже писали такие тесты в первом курсе; здесь добавляются приёмы, которые встречаются в каждом реальном проекте: **табличные тесты**, **подтесты** (`t.Run`), **бенчмарки** и **примеры** (`ExampleXxx`), которые одновременно служат документацией и проверяются командой `go test`.

## Точные правила

**Модули и пакеты.**

* `go mod init example.com/textkit` создаёт `go.mod`. Строка `go 1.26` задаёт минимальную версию языка и влияет на семантику (например, переменная цикла в Go 1.22+ создаётся на каждую итерацию).
* Имя пакета обычно совпадает с последним элементом пути импорта; `package main` с функцией `main` даёт исполняемую программу.
* Циклические импорты запрещены. Если два пакета нуждаются друг в друге, общее выносят в третий пакет.
* Экспортируемыми могут быть функции, типы, методы, константы, переменные **и поля структур**. Поле `name` недоступно снаружи пакета, даже если тип экспортирован.
* Каталог `internal` действует на любую глубину: `a/b/internal/c` доступен только из `a/b/...`.
* Зависимости добавляет `go get module@version`, лишние убирает `go mod tidy`; контрольные суммы хранятся в `go.sum`. Модули извне подчиняются семантическому версионированию, а для мажорных версий 2 и выше путь модуля получает суффикс `/v2`.

**Тесты.**

* Файлы `*_test.go` не попадают в обычную сборку. Тесты в том же пакете (`package slug`) видят неэкспортированные имена; тесты во **внешнем** пакете (`package slug_test`) используют только публичный API, как это делает пользователь библиотеки.
* **Табличный тест**: срез структур `{name, input, want}` и цикл, в котором каждая строка выполняется через `t.Run(tc.name, ...)`. Каждая строка получает собственное имя `TestSlugify/simple`; её можно запустить отдельно: `go test -run 'TestSlugify/simple'`.
* `t.Errorf` помечает тест проваленным и продолжает; `t.Fatalf` останавливает текущий тест. Сообщение включает вход, фактическое и ожидаемое значение.
* `t.Helper()` в вспомогательной функции делает так, что ошибка указывает на строку вызова. `t.Cleanup(f)` регистрирует очистку, `t.TempDir()` даёт временный каталог, удаляемый автоматически.
* `t.Parallel()` разрешает подтесту работать параллельно с другими такими же. В Go 1.22+ переменная цикла своя на каждую итерацию, поэтому замыкания в подтестах безопасны без копирования.
* **Бенчмарки**: `func BenchmarkXxx(b *testing.B)`. С Go 1.24 принят цикл `for b.Loop() { ... }`: он сам выбирает число итераций и не даёт компилятору выбросить измеряемый вызов. Старая форма - `for i := 0; i < b.N; i++`. Запуск: `go test -bench . -benchmem` (флаг `-benchmem` добавляет число аллокаций).
* **Примеры**: функция `ExampleXxx()` с комментарием `// Output: ...` выполняется как тест, сравнивая вывод; она же отображается в документации (`pkg.go.dev`). Без комментария `Output` пример только компилируется.
* `go vet ./...` находит типичные ошибки (форматные строки, копирование мьютекса, забытый `cancel`), `gofmt` форматирует код. Покрытие: `go test -cover`.
* `testing.AllocsPerRun(runs, f)` возвращает среднее число аллокаций на вызов; удобно для проверки гипотез об оптимизации.

## Примеры

**Пример 1. Что экспортируется.**

```go run
package main

import (
	"fmt"
	"go/token"
)

type Config struct {
	Name  string // экспортировано
	token string // нет
}

func main() {
	for _, name := range []string{"Slugify", "slugify", "_Hidden", "Ёж", "Δx", "x1"} {
		fmt.Printf("%-8s %v\n", name, token.IsExported(name))
	}
}
```

```output
Slugify  true
slugify  false
_Hidden  false
Ёж       true
Δx       true
x1       false
```

Правило проверяется по первой букве идентификатора: она должна быть заглавной буквой Unicode. Подчёркивание и строчные буквы (в том числе нелатинские) не экспортируются.

**Пример 2. Табличный тест (в файле `slug_test.go`).**

```go
package slug

import "testing"

func TestSlugify(t *testing.T) {
	tests := []struct {
		name, in, want string
	}{
		{"simple", "Hello World", "hello-world"},
		{"punctuation", "Go: язык!", "go-язык"},
		{"empty", "", ""},
	}
	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			if got := Slugify(tc.in); got != tc.want {
				t.Errorf("Slugify(%q) = %q, want %q", tc.in, got, tc.want)
			}
		})
	}
}

func BenchmarkSlugify(b *testing.B) {
	for b.Loop() {
		Slugify("Go: язык и идиомы")
	}
}

func ExampleSlugify() {
	fmt.Println(Slugify("Hello, World!"))
	// Output: hello-world
}
```

Новый случай добавляется одной строкой таблицы, а при падении имя подтеста сразу показывает, какая строка сломалась. В примере выше `ExampleSlugify` требует `import "fmt"` в файле, в остальном файл полный.

**Пример 3. Измерение аллокаций без бенчмарка.**

```go run
package main

import (
	"fmt"
	"strings"
	"testing"
)

var sink string

func concat(parts []string) string {
	s := ""
	for _, p := range parts {
		s += p
	}
	return s
}

func build(parts []string) string {
	var b strings.Builder
	b.Grow(64)
	for _, p := range parts {
		b.WriteString(p)
	}
	return b.String()
}

func main() {
	parts := []string{"alpha", "beta", "gamma", "delta", "epsilon"}

	fmt.Println(concat(parts) == build(parts))
	fmt.Println("concat allocs:", testing.AllocsPerRun(100, func() { sink = concat(parts) }))
	fmt.Println("builder allocs:", testing.AllocsPerRun(100, func() { sink = build(parts) }))
}
```

```output
true
concat allocs: 4
builder allocs: 1
```

Склейка в цикле выделяет память почти на каждом шаге (здесь 4 аллокации на 5 слов), `strings.Builder` с предварительным `Grow` - одну. Именно такие гипотезы проверяют бенчмарки с `-benchmem`; а тест на число аллокаций можно оформить обычным `TestXxx` через `testing.AllocsPerRun`.

## Типичные ошибки

* **Имя со строчной буквы там, где нужен публичный API**: функция работает внутри пакета, но компилятор в другом пакете сообщает `undefined` или `unexported`.
* **Импорт `internal` из чужого модуля.** Ошибка `use of internal package ... not allowed`: это не баг, а задуманное ограничение.
* **Путь модуля не совпадает с путём импорта** в `import`. Импорт начинается с `module` из `go.mod`.
* **Циклический импорт.** Вынесите общие типы в отдельный пакет.
* **Тест без проверки**: функция вызвана, но результат не сравнивается. Всегда проверяйте результат и пишите в сообщении вход и ожидаемое.
* **`t.Fatalf` в горутине**, отличной от тестовой: он завершает только вызвавшую горутину. Используйте `t.Errorf` и сигнал через канал.
* **Табличный тест без `name`**: при падении непонятно, какая строка виновата.
* **Бенчмарк, который оптимизатор выбросил.** С `b.Loop()` этого не случается; в старом цикле `b.N` сохраняйте результат в переменную пакетного уровня.
* **Пример с неверным `// Output:`.** Пробелы по краям игнорируются, но содержимое должно совпадать точно; порядок обхода карты в выводе примера нестабилен.
* **Тест, зависящий от порядка карты или времени.** Сортируйте ключи перед сравнением и не используйте `time.Sleep` для синхронизации.
* **Забытый `go mod tidy`** после добавления или удаления зависимостей: `go.mod` и `go.sum` расходятся с кодом.
* **Мнение, что `errgroup` есть в стандартной библиотеке.** Он находится в `golang.org/x/sync/errgroup`; это зависимость, которую подключают через `go get`.

## Итоги

* Модуль - дерево с `go.mod`; пакет - каталог; импортируют пакеты. Заглавная буква экспортирует имя, каталог `internal` ограничивает импорт модулем.
* Тесты: `TestXxx` + таблица + `t.Run` для читаемых отчётов, внешний пакет `_test` для проверки публичного API.
* Бенчмарки пишите с `b.Loop()` (Go 1.24+) и запускайте с `-benchmem`; примеры с `// Output:` проверяются и попадают в документацию.
* `go vet`, `gofmt`, `go mod tidy` и `go test ./...` - минимальный набор перед каждым коммитом.

<!-- section: facts -->
## Факты

* `testing.B.Loop` добавлен в Go 1.24.
* Каталог `internal` защищён правилом сборки инструмента `go`, а не соглашением об именах.
