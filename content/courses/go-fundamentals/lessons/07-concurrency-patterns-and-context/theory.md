## Паттерны конкурентности и пакет context

Горутины и каналы - строительные блоки. На практике из них собирают несколько устойчивых схем:

* **Пул воркеров** (worker pool): фиксированное число горутин берёт задания из общей очереди. Так ограничивают нагрузку: не «тысяча одновременных запросов», а «восемь за раз».
* **Fan-out / fan-in**: раздать работу нескольким горутинам (fan-out) и собрать результаты в один канал (fan-in).
* **Конвейер** (pipeline): цепочка этапов, каждый читает из предыдущего канала и пишет в следующий.

У любой конкурентной работы есть вопрос «как её остановить?»: пользователь закрыл вкладку, истёк тайм-аут, соседняя задача упала. В Go на него отвечает пакет **`context`**. `context.Context` - это объект, который передают первым параметром во все функции, способные работать долго: он несёт **сигнал отмены** (`ctx.Done()` - канал, который закрывается), **срок** и небольшие данные запроса.

```go
ctx, cancel := context.WithTimeout(parent, 2*time.Second)
defer cancel() // освободить ресурсы контекста, даже если уложились в срок
result, err := fetch(ctx, id)
```

Третья часть темы - **общая память**. Когда несколько горутин меняют одну переменную, нужна защита: `sync.Mutex`, атомарные операции или передача данных через канал. Без защиты возникает **гонка данных** (data race): результат непредсказуем, а компилятор не предупредит. Для её поиска у Go есть детектор гонок: `go test -race`.

Учтите: `errgroup` (удобная связка «запустить группу горутин, дождаться и получить первую ошибку») находится не в стандартной библиотеке, а в расширении `golang.org/x/sync/errgroup`. В этом курсе его нет, но в упражнении вы напишете то же самое вручную, чтобы понять, как оно устроено.

## Точные правила

**`context`.**

* Корневые контексты: `context.Background()` (для `main`, тестов и верхнего уровня) и `context.TODO()` («ещё не решено, какой контекст»). Они никогда не отменяются.
* Производные: `WithCancel(parent)` возвращает контекст и функцию `cancel`; `WithTimeout(parent, d)` и `WithDeadline(parent, t)` отменяются сами по сроку; `WithValue(parent, key, v)` добавляет значение. Отмена **родителя отменяет всех потомков**, но не наоборот.
* `ctx.Done()` - канал, закрываемый при отмене (у корневых контекстов он `nil`). `ctx.Err()` возвращает `nil` до отмены, затем `context.Canceled` (отмена) или `context.DeadlineExceeded` (истёк срок). Эти ошибки сравнивают через `errors.Is`.
* **Всегда вызывайте `cancel`** (обычно `defer cancel()`), даже если срок истечёт сам: иначе контекст и таймер живут дольше нужного. `go vet` ловит забытый `cancel` (проверка `lostcancel`).
* Соглашения: `ctx` - **первый параметр** функции, называется `ctx`; контекст **не хранят в полях структур**; не передают `nil`.
* Отмена **кооперативная**: контекст лишь сообщает о ней. Функция обязана сама проверять `ctx.Done()` или `ctx.Err()` (в `select` вместе с основной работой) или передавать `ctx` в вызовы, которые это делают (`http.NewRequestWithContext`, `db.QueryContext`).
* `context.WithCancelCause` и `context.Cause(ctx)` (Go 1.20) позволяют узнать причину отмены. `context.WithoutCancel` и `context.AfterFunc` появились в Go 1.21.
* `WithValue` предназначен для данных, привязанных к запросу и проходящих через API (идентификатор трассировки), а не для необязательных параметров функций. Ключ делают собственным неэкспортируемым типом, чтобы не пересекаться с другими пакетами.

**Паттерны.**

* **Пул воркеров:** канал заданий (или индексов), `N` горутин в цикле `for job := range jobs`, результаты - в канал либо в срез по индексу (каждая горутина пишет в свой элемент). Закрыватель ждёт `WaitGroup` и закрывает результаты.
* **Ограничение параллелизма:** буферизованный канал как семафор (`sem := make(chan struct{}, N)`; перед работой `sem <- struct{}{}`, после - `<-sem`).
* **Остановка при первой ошибке:** общий `ctx, cancel := context.WithCancel(...)`; первая ошибка запоминается (под мьютексом или `sync.Once`), затем вызывается `cancel()`. Это и делает `errgroup`.
* **Подача заданий с отменой:** отправка в канал заданий всегда в `select` с `case <-ctx.Done()`, иначе при остановке воркеров производитель зависнет.
* **Утечки горутин:** у каждой запущенной горутины должен быть путь завершения - закрытие входного канала или отмена контекста.

**Синхронизация общей памяти.**

* `sync.Mutex`: `Lock()`/`Unlock()` (почти всегда `defer mu.Unlock()`); нулевое значение готово к работе; **нельзя копировать** после использования. `sync.RWMutex` разрешает много читателей или одного писателя.
* `sync.Once` выполняет функцию ровно один раз; `sync/atomic` (`atomic.Int64`, `atomic.Bool`, `atomic.Pointer[T]`) даёт атомарные операции для отдельных значений.
* Мьютекс обычно кладут в структуру рядом с данными, которые он защищает, и защищают данные только через методы этой структуры.

**Гонка данных и детектор.**

* **Гонка данных** - два обращения к одной ячейке памяти из разных горутин без синхронизации, из которых хотя бы одно - запись. Результат не определён языком (модель памяти Go).
* `go test -race ./...`, `go run -race`, `go build -race` включают детектор гонок: программа замедляется в несколько раз и использует больше памяти, а гонки, которые *реально произошли* при этом запуске, печатаются с трассировками обеих горутин (`WARNING: DATA RACE`). Он не доказывает отсутствие гонок: непойманная гонка остаётся.
* **Ограничение платформы:** по документации детектор гонок поддерживается не на всех платформах и на ряде из них требует включённого cgo (`CGO_ENABLED=1`) и C-компилятора. Проверьте `go env CGO_ENABLED`. Встроенная в это приложение проверка упражнений может запускать Go без cgo, поэтому **упражнения курса не зависят от `-race`**: тесты проверяют результат детерминированно, а `-race` стоит запускать у себя в терминале.

## Примеры

**Пример 1. Пул воркеров с мьютексом и результатами по индексу.**

```go run
package main

import (
	"fmt"
	"sync"
)

type Stats struct {
	mu    sync.Mutex
	count map[string]int
}

func (s *Stats) Add(key string) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.count[key]++
}

func main() {
	jobs := make(chan int)
	results := make([]int, 10) // каждая горутина пишет только в свои элементы
	stats := &Stats{count: map[string]int{}}

	var wg sync.WaitGroup
	for range 3 { // три воркера
		wg.Go(func() {
			for n := range jobs {
				results[n] = n * n
				if n%2 == 0 {
					stats.Add("even")
				} else {
					stats.Add("odd")
				}
			}
		})
	}

	for i := range results {
		jobs <- i
	}
	close(jobs) // сигнал воркерам: заданий больше нет
	wg.Wait()

	fmt.Println(results)
	fmt.Println(stats.count["even"], stats.count["odd"])
}
```

```output
[0 1 4 9 16 25 36 49 64 81]
5 5
```

Какой воркер обработает какое задание, не определено, но итог детерминирован: индексы не пересекаются, а карта защищена мьютексом. После `wg.Wait()` все записи видны основной горутине.

**Пример 2. Контекст: отмена, срок, причина, значения.**

```go run
package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

type ctxKey string // собственный тип ключа

func worker(ctx context.Context) error {
	select {
	case <-ctx.Done():
		return ctx.Err()
	case <-time.After(time.Hour): // "долгая работа"
		return nil
	}
}

func main() {
	// 1. Отмена вручную.
	ctx, cancel := context.WithCancel(context.Background())
	fmt.Println(ctx.Err())
	cancel()
	err := worker(ctx)
	fmt.Println(err, errors.Is(err, context.Canceled))

	// 2. Срок.
	ctx2, cancel2 := context.WithTimeout(context.Background(), 20*time.Millisecond)
	defer cancel2()
	err = worker(ctx2)
	fmt.Println(err, errors.Is(err, context.DeadlineExceeded))

	// 3. Отмена родителя отменяет потомков.
	parent, cancelParent := context.WithCancel(context.Background())
	child, cancelChild := context.WithTimeout(parent, time.Hour)
	defer cancelChild()
	cancelParent()
	<-child.Done()
	fmt.Println(child.Err())

	// 4. Причина отмены.
	ctx4, cancel4 := context.WithCancelCause(context.Background())
	cancel4(errors.New("пользователь закрыл вкладку"))
	fmt.Println(ctx4.Err(), "|", context.Cause(ctx4))

	// 5. Значение запроса.
	ctx5 := context.WithValue(context.Background(), ctxKey("request-id"), "r-42")
	fmt.Println(ctx5.Value(ctxKey("request-id")), ctx5.Value(ctxKey("other")))
}
```

```output
<nil>
context canceled true
context deadline exceeded true
context canceled
context canceled | пользователь закрыл вкладку
r-42 <nil>
```

Функция `worker` реагирует на отмену, потому что сама ждёт `ctx.Done()` в `select`. Если бы она просто спала час, контекст не смог бы её прервать: отмена кооперативная.

**Пример 3. Семафор на буферизованном канале, `sync.Once` и атомарный счётчик.**

```go run
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

func main() {
	const limit = 3
	sem := make(chan struct{}, limit) // не более 3 одновременно

	var (
		cur, peak atomic.Int64
		total     atomic.Int64
		once      sync.Once
		wg        sync.WaitGroup
	)

	for i := 1; i <= 20; i++ {
		wg.Go(func() {
			sem <- struct{}{}        // занять слот
			defer func() { <-sem }() // освободить

			once.Do(func() { fmt.Println("первый запуск") })

			c := cur.Add(1)
			for {
				p := peak.Load()
				if c <= p || peak.CompareAndSwap(p, c) {
					break
				}
			}
			total.Add(int64(i))
			cur.Add(-1)
		})
	}
	wg.Wait()

	fmt.Println(total.Load(), peak.Load() <= limit)
}
```

```output
первый запуск
210 true
```

Сумма `1..20` равна 210 при любом порядке выполнения, а пик одновременно работающих горутин никогда не превышает размер семафора. `sync.Once` напечатал сообщение ровно один раз.

**Пример 4. Как выглядит гонка (не запускается).**

```go
var n int
var wg sync.WaitGroup
for range 2 {
	wg.Go(func() { n++ }) // чтение-изменение-запись без синхронизации
}
wg.Wait()
```

Итог зависит от расписания, а `go test -race` сообщит `WARNING: DATA RACE` с указанием обеих строк `n++` и горутин. Исправления: `sync.Mutex` вокруг `n++`, `atomic.Int64` или передача результатов через канал.

## Типичные ошибки

* **Забытый `cancel`.** Утекают таймер и ресурсы контекста. Пишите `defer cancel()` сразу после `WithCancel`/`WithTimeout`.
* **Игнорирование `ctx.Done()`.** Контекст отменён, а горутина продолжает работать: проверяйте `ctx.Done()` в циклах и блокирующих операциях.
* **Хранение контекста в структуре** и передача `nil`-контекста. Передавайте `ctx` параметром, а если не знаете какой - `context.TODO()`.
* **`WithValue` как способ передавать параметры функций.** Скрытые зависимости ломают читаемость; используйте явные аргументы.
* **Отправка в канал заданий без `select` с `ctx.Done()`.** После остановки воркеров производитель блокируется навсегда.
* **Потеря первой ошибки.** При параллельном завершении несколько горутин вернут ошибки; запоминайте первую и только потом отменяйте остальных.
* **Общая переменная без защиты** (`counter++` из многих горутин) - гонка данных. Защищайте мьютексом, атомиками или каналом.
* **Копирование мьютекса** (передача структуры по значению): копия имеет собственное состояние блокировки. `go vet` предупредит (`copylocks`).
* **Блокировка мьютекса и возврат без `Unlock`.** Используйте `defer mu.Unlock()`.
* **Вызов `wg.Add` внутри горутины** или отрицательный счётчик - `Wait` вернётся раньше времени либо будет паника.
* **Вера в `-race` как в доказательство корректности.** Он находит лишь гонки, случившиеся в этом запуске, зато без ложных срабатываний. Запускайте его на тестах, которые нагружают конкурентный код.
* **Расчёт на то, что `-race` везде доступен.** Проверьте `go env CGO_ENABLED` и поддержку платформы; не делайте проверку упражнений зависимой от него.
* **`time.Sleep` вместо синхронизации** в тестах конкурентного кода - источник нестабильных тестов.

<!-- section: summary -->
## Итоги

* Пул воркеров, fan-out/fan-in и конвейер строятся из горутин и каналов; результаты складывайте по индексам или собирайте в канал, а закрывает канал отдельная горутина после `wg.Wait()`.
* `context` передаёт отмену, срок и данные запроса: первым параметром, `defer cancel()` всегда, `ctx.Done()` в `select`, ошибки сравнивайте через `errors.Is(err, context.Canceled)` и `context.DeadlineExceeded`.
* Остановка при первой ошибке: запомнить ошибку под мьютексом, затем `cancel()`; `errgroup` - то же самое, но в `golang.org/x/sync`, не в стандартной библиотеке.
* `sync.Mutex`, `sync/atomic` и каналы защищают общую память; гонка данных - ошибка, а `go test -race` помогает её искать там, где платформа и cgo это позволяют.

## Факты

* `context.WithCancelCause` и `context.Cause` добавлены в Go 1.20; `context.WithoutCancel` и `context.AfterFunc` - в Go 1.21.
* Пакет `golang.org/x/sync/errgroup` развивается отдельно от стандартной библиотеки и подключается как внешняя зависимость.
