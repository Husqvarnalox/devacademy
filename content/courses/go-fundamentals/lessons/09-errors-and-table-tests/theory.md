## Пакеты, ошибки и тесты: три привычки Go

В Go код организован в **пакеты**: каталог с `.go`-файлами, у которых одинаковое объявление `package`. Группа пакетов с общим файлом `go.mod` называется **модулем**. В `go.mod` записано имя модуля и версия языка:

```go
module example.com/shop

go 1.21
```

Функции, имена которых начинаются с заглавной буквы (`Reserve`), видны другим пакетам, а строчные (`helper`) остаются внутри. Отдельного слова `public` в Go нет.

Вторая привычка: в Go нет исключений для обычных ошибок. Функция, которая может не получиться, возвращает **ошибку вторым значением**, а вызывающий код её проверяет:

```go
n, err := strconv.Atoi("12x")
if err != nil {
	fmt.Println("ошибка:", err)
}
```

Третья привычка: тесты живут рядом с кодом в файлах `*_test.go`, а запускает их команда `go test`. Отдельные библиотеки не нужны.

## Точные правила

**Ошибки-значения.**

* Тип `error` - интерфейс с одним методом `Error() string`. Значение `nil` означает отсутствие ошибки.
* `errors.New("текст")` создаёт новую ошибку. Такую ошибку, объявленную на уровне пакета, называют **сентинелом**: `var ErrNotFound = errors.New("не найдено")`.
* `fmt.Errorf("поиск %q: %w", name, ErrNotFound)` создаёт ошибку с контекстом и **оборачивает** исходную. Глагол `%v` вместо `%w` тоже даст текст, но связь с исходной ошибкой потеряется.
* `errors.Is(err, ErrNotFound)` просматривает цепочку оборачивания и сообщает, есть ли в ней целевая ошибка. Сравнение `err == ErrNotFound` сработает только для необёрнутой ошибки. Сравнивать тексты нельзя: они предназначены для людей.
* `errors.As(err, &target)` ищет в цепочке ошибку нужного типа.

**Тесты.**

* Файл `*_test.go`, функции `func TestXxx(t *testing.T)`; в обычную сборку пакета такие файлы не входят.
* `t.Errorf` помечает тест упавшим и продолжает, `t.Fatalf` прерывает текущий тест.
* `t.Run(имя, func(t *testing.T){...})` создаёт подтест. Его видно в отчёте как `TestReserve/ok`, и его можно запустить отдельно: `go test -run 'TestReserve/ok'`.
* **Табличный тест**: срез структур с входами и ожидаемыми результатами и один цикл с проверкой.
* `go test ./...` выполняет тесты всех пакетов модуля; `-count=1` отключает кеш результатов, `-json` печатает события в формате JSON, пригодном для обработки программами.

**Два вида неудач.** Если пакет не компилируется, тесты вообще не запускаются, и сообщает об этом сама сборка. Если компилируется, но проверка не прошла, `go test` печатает имя упавшего подтеста и сообщение.

## Примеры

**Пример 1. Функция с ошибкой и её вызов.**

```go
package main

import (
	"errors"
	"fmt"
)

var ErrEmpty = errors.New("пустое имя")

func greet(name string) (string, error) {
	if name == "" {
		return "", fmt.Errorf("greet: %w", ErrEmpty)
	}
	return "Привет, " + name, nil
}

func main() {
	_, err := greet("")
	fmt.Println(errors.Is(err, ErrEmpty))
	fmt.Println(err)
}
```

```output
true
greet: пустое имя
```

Текст получил контекст `greet:`, но `errors.Is` всё равно находит `ErrEmpty`.

**Пример 2. Табличный тест (в файле `abs_test.go`).**

```go
func TestAbs(t *testing.T) {
	tests := []struct {
		name string
		in   int
		want int
	}{
		{"positive", 5, 5},
		{"negative", -5, 5},
		{"zero", 0, 0},
	}
	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			if got := Abs(tc.in); got != tc.want {
				t.Fatalf("Abs(%d) = %d, want %d", tc.in, got, tc.want)
			}
		})
	}
}
```

Добавить новый случай - значит дописать одну строку таблицы. Имя случая попадёт в отчёт, и по нему сразу видно, что сломалось.

**Пример 3. Карта и признак наличия ключа.**

```go
stock := map[string]int{"tea": 0}
v, ok := stock["tea"]
w, ok2 := stock["milk"]
fmt.Println(v, ok, w, ok2)
```

```output
0 true 0 false
```

Значение `0` не отличает «товар закончился» от «товара нет». Для этого служит вторая переменная `ok`.

## Типичные ошибки

* **Игнорирование ошибки.** Запись `n, _ := strconv.Atoi(s)` скрывает проблему; в учебном коде проверяйте `err` всегда.
* **`%v` вместо `%w`.** Контекст добавлен, но `errors.Is` перестаёт работать.
* **Сравнение текстов.** `err.Error() == "не найдено"` сломается при первом же добавлении контекста.
* **Изменение состояния до проверок.** Если склад уменьшен, а потом обнаружилась ошибка, данные испорчены. Сначала проверки, потом изменение.
* **Путаница нуля и отсутствия.** `stock[item] == 0` не говорит, есть ли товар. Используйте `v, ok := stock[item]`.
* **Неверное имя файла.** `stock.test.go` или `test_stock.go` не считаются тестами: нужен суффикс `_test.go`.
* **Замыкание на переменную цикла в параллельных подтестах.** Начиная с Go 1.22 каждая итерация имеет свою переменную, но в старых версиях нужно было копировать `tc := tc`. Версия языка указана в `go.mod`.

## Итоги

* Пакет - каталог с `.go`-файлами, модуль - дерево пакетов с `go.mod`.
* Ошибка - обычное значение: функция возвращает `error`, вызывающий проверяет `err != nil`.
* Сентинелы объявляют в пакете, оборачивают через `fmt.Errorf("...: %w", ErrX)` и проверяют через `errors.Is`.
* Табличный тест хранит случаи в срезе, а `t.Run` даёт каждому имя, видимое в отчёте.
* `go test ./...` запускает тесты модуля; если пакет не собирается, сначала исправьте сборку.
