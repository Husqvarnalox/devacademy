## Функции, ошибки как значения и defer

В Go **нет исключений** в привычном по Java, Python или C# смысле: нет `try/catch` и нет «выброса» ошибки через несколько уровней стека. Функция, которая может не получиться, просто **возвращает ошибку как ещё одно значение**, и вызывающий код решает, что с ней делать:

```go
n, err := strconv.Atoi("12x")
if err != nil {
	return fmt.Errorf("читаю количество: %w", err)
}
```

Многословно, зато порядок выполнения виден прямо в тексте: каждая точка, где что-то может пойти не так, помечена `if err != nil`.

Три инструмента этого урока:

1. **Несколько возвращаемых значений** - обычный способ вернуть результат и ошибку: `func Atoi(s string) (int, error)`.
2. **Обёртывание ошибок.** Ошибка, поднимаясь вверх, обрастает контекстом («читаю количество: ...»), но исходную причину по-прежнему можно найти через `errors.Is` и `errors.As`.
3. **`defer`** откладывает вызов до выхода из функции. Так гарантированно закрывают файлы и отпускают мьютексы, даже если функция выходит рано.

И одно исключение из правила «нет исключений»: **`panic`** для действительно непредвиденных ситуаций (баг программиста, невозможное состояние). Для обычных ошибок - неверный ввод, недоступный файл, отсутствие записи - `panic` не используют.

## Точные правила

**Функции.**

* Функция может возвращать несколько значений: `func div(a, b int) (int, error)`. Принимать их можно только все сразу (`q, err := div(1, 2)`); ненужные отбрасывают через `_`.
* **Именованные результаты** (`func f() (n int, err error)`) объявлены как локальные переменные с нулевыми значениями, а «голый» `return` возвращает их текущие значения. Применяйте в коротких функциях и в связке с `defer`; в длинных голый `return` вредит читаемости.
* Функции - значения первого класса: их передают, возвращают и присваивают переменным; анонимная функция может **замыкать** переменные окружающей функции. Вариативные параметры: `func sum(nums ...int)`; вызов `sum(xs...)` передаёт срез без копирования.
* Аргументы всегда передаются **по значению**: копируются числа, структуры, заголовки срезов и карт, указатели. Срез и карта «ведут себя как ссылки» лишь потому, что копия заголовка указывает на те же данные.

**Тип `error`.**

* `error` - встроенный интерфейс `interface { Error() string }`. Любой тип с таким методом - ошибка. `nil` означает успех.
* `errors.New("текст")` создаёт новую ошибку. Каждый вызов даёт **отдельное** значение: две ошибки с одинаковым текстом не равны.
* **Сентинел** - ошибка уровня пакета (`var ErrNotFound = errors.New("not found")`), по идентичности которой проверяют ситуацию. **Типизированная ошибка** - собственный тип (обычно структура) с полезными полями: `type SyntaxError struct{ Line, Reason string }`.
* `fmt.Errorf("контекст: %w", err)` оборачивает `err`; результат содержит метод `Unwrap`. С `%v` вместо `%w` текст тот же, но цепочка разорвана. С Go 1.20 в одном `Errorf` можно несколько `%w`, а `errors.Join(a, b)` объединяет ошибки в одну.
* `errors.Is(err, target)` проходит по цепочке `Unwrap` и сравнивает каждое звено с `target`. `errors.As(err, &t)` ищет в цепочке звено, присваиваемое типу цели, и записывает его в `t`: цель - **указатель** на переменную нужного типа.
* Сравнивайте ошибки через `Is` и `As`, а не через `==` и не по `Error()`.
* Решение «оборачивать или нет» - часть API: обернув ошибку другого пакета через `%w`, вы обещаете, что она останется доступной для `Is/As`. Если не хотите, используйте `%v`.

**`defer`.**

* `defer f(args)` откладывает вызов до **возврата из окружающей функции** (нормального, через `return` или из-за паники).
* Отложенные вызовы выполняются в порядке **LIFO**: последний отложенный - первым.
* **Аргументы и получатель метода вычисляются в момент `defer`**, а не при выполнении. Но замыкание `defer func() { ... }()` читает переменные в момент выполнения.
* Отложенная функция может менять **именованные результаты**: она выполняется после вычисления выражения в `return`, но до фактического возврата.
* `defer` в цикле накапливает вызовы до конца функции, а не итерации: закрытие файлов в цикле выносят в отдельную функцию.

**`panic` и `recover`.**

* `panic(v)` прерывает обычное выполнение, запускает отложенные вызовы вверх по стеку и, если паника не перехвачена, завершает программу с кодом 2 и трассировкой.
* `recover()` останавливает панику и возвращает переданное в `panic` значение, но **только когда вызвана напрямую из отложенной функции**. Вне паники `recover` возвращает `nil`.
* Паники порождает и среда выполнения: индекс за границами, разыменование `nil`-указателя, запись в `nil`-карту, деление целых на ноль.
* Правило: `panic` - для ошибок программиста и невосстановимых состояний. `recover` разумен на границе, где одна неудача не должна ронять всё (например, обработчик запроса), либо внутри пакета, который сам использует `panic` как внутренний механизм и **не выпускает его наружу**.
* `os.Exit` завершает программу **немедленно, без запуска отложенных вызовов**.

## Примеры

**Пример 1. Сентинел, типизированная ошибка и обёртывание.**

```go run
package main

import (
	"errors"
	"fmt"
	"strconv"
)

var ErrNegative = errors.New("отрицательное число")

type RangeError struct {
	Value, Max int
}

func (e *RangeError) Error() string {
	return fmt.Sprintf("значение %d больше %d", e.Value, e.Max)
}

func check(s string) (int, error) {
	n, err := strconv.Atoi(s)
	if err != nil {
		return 0, fmt.Errorf("check %q: %w", s, err)
	}
	if n < 0 {
		return 0, fmt.Errorf("check %q: %w", s, ErrNegative)
	}
	if n > 100 {
		return 0, fmt.Errorf("check %q: %w", s, &RangeError{n, 100})
	}
	return n, nil
}

func main() {
	for _, s := range []string{"42", "x", "-5", "500"} {
		n, err := check(s)
		var re *RangeError
		var ne *strconv.NumError
		switch {
		case err == nil:
			fmt.Println("ok", n)
		case errors.Is(err, ErrNegative):
			fmt.Println("сентинел:", err)
		case errors.As(err, &re):
			fmt.Println("тип RangeError, Max =", re.Max)
		case errors.As(err, &ne):
			fmt.Println("тип NumError, Func =", ne.Func)
		}
	}

	// Разрыв цепочки: %v вместо %w.
	base := errors.New("база")
	fmt.Println(errors.Is(fmt.Errorf("ctx: %w", base), base))
	fmt.Println(errors.Is(fmt.Errorf("ctx: %v", base), base))
	// Равенство ошибок - это идентичность, а не текст.
	fmt.Println(errors.New("x") == errors.New("x"))
}
```

```output
ok 42
тип NumError, Func = Atoi
сентинел: check "-5": отрицательное число
тип RangeError, Max = 100
true
false
false
```

Сентинел ищут через `errors.Is`, а данные из типизированной ошибки достают через `errors.As`. Три последние строки: `%w` сохраняет цепочку (`true`), `%v` рвёт её (`false`), а две `errors.New` с одинаковым текстом не равны (`false`).

**Пример 2. Порядок `defer`, время вычисления аргументов и именованный результат.**

```go run
package main

import "fmt"

func order() {
	for i := 0; i < 3; i++ {
		defer fmt.Print("defer ", i, "; ")
	}
	fmt.Print("тело; ")
}

func args() {
	x := 1
	defer fmt.Println("аргумент вычислен сразу: x =", x)
	defer func() { fmt.Println("замыкание видит текущее: x =", x) }()
	x = 2
}

func double() (n int) {
	defer func() { n *= 2 }()
	return 21 // сначала n = 21, затем defer удваивает
}

func main() {
	order()
	fmt.Println()
	args()
	fmt.Println(double())
}
```

```output
тело; defer 2; defer 1; defer 0; 
замыкание видит текущее: x = 2
аргумент вычислен сразу: x = 1
42
```

Отложенные вызовы в `order` выполняются в обратном порядке. В `args` обычный `defer` запомнил `x = 1`, а замыкание выполнилось позже и увидело `2`.

**Пример 3. `panic` и `recover` на границе.**

```go run
package main

import (
	"errors"
	"fmt"
)

// safeIndex превращает панику среды выполнения в обычную ошибку.
func safeIndex(s []int, i int) (v int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("восстановились после паники: %v", r)
		}
	}()
	return s[i], nil
}

func mustPositive(n int) int {
	if n <= 0 {
		panic(errors.New("нарушен инвариант: n <= 0"))
	}
	return n
}

func main() {
	fmt.Println(safeIndex([]int{1, 2, 3}, 1))
	fmt.Println(safeIndex([]int{1, 2, 3}, 7))

	func() {
		defer func() { fmt.Println("recover вернул:", recover()) }()
		mustPositive(-1)
	}()

	// Вне паники recover возвращает nil.
	fmt.Println(recover())

	joined := errors.Join(errors.New("первая"), errors.New("вторая"))
	fmt.Println(joined)
}
```

```output
2 <nil>
0 восстановились после паники: runtime error: index out of range [7] with length 3
recover вернул: нарушен инвариант: n <= 0
<nil>
первая
вторая
```

`recover` получил значение, переданное в `panic`, а для паники среды выполнения - значение типа `runtime.Error`. В реальной программе `mustPositive` вызывали бы только с проверенными данными: это защита от бага, а не обработка ввода.

## Типичные ошибки

* **Игнорирование ошибки** через `_`. Запись `f, _ := os.Open(name)` отложит падение до первого обращения к `nil`-файлу.
* **`%v` вместо `%w`.** Контекст добавлен, но `errors.Is` и `errors.As` перестают находить причину.
* **Сравнение текстов.** `err.Error() == "not found"` ломается при добавлении контекста; используйте `errors.Is`.
* **Передача значения в `errors.As`.** Цель - указатель на переменную: `errors.As(err, &target)`. Без `&` код не пройдёт `go vet`, а в рантайме будет паника.
* **Возврат `nil`-указателя на тип ошибки.** Функция `func f() error`, возвращающая `(*MyErr)(nil)`, даёт **не**-`nil` ошибку (подробности - в уроке про интерфейсы). Возвращайте литерал `nil`.
* **`defer` в цикле.** `for ... { f := open(); defer f.Close() }` не закрывает файлы до выхода из функции; выносите тело в функцию.
* **Ожидание, что `defer` увидит новое значение.** Аргумент `defer fmt.Println(x)` фиксируется сразу; чтобы читать актуальное значение, используйте замыкание.
* **`panic` вместо `error`.** Неверный ввод пользователя или недоступный файл - это обычная ошибка, а не паника.
* **`recover` не в отложенной функции** (или внутри вложенного вызова из неё) ничего не перехватывает.
* **`os.Exit` или `log.Fatal` после `defer`.** Отложенные вызовы не выполнятся.

<!-- section: summary -->
## Итоги

* Ошибка в Go - обычное значение интерфейса `error`; функции возвращают её последним результатом, а вызывающий проверяет `err != nil`.
* Контекст добавляют через `fmt.Errorf("...: %w", err)`, причину ищут через `errors.Is` (сентинелы) и `errors.As` (типизированные ошибки).
* `defer` выполняется в порядке LIFO; аргументы вычисляются сразу, замыкание читает переменные позже, именованные результаты можно менять.
* `panic` и `recover` не заменяют исключения: паника - для багов и невосстановимых состояний, `recover` - на границах, не выпуская панику наружу.

## Факты

* Сочетание `%w` и `errors.Is/As` появилось в Go 1.13; `errors.Join` и несколько `%w` в одном `Errorf` - в Go 1.20.
* Неперехваченная паника завершает программу с кодом 2 и печатает трассировку.
