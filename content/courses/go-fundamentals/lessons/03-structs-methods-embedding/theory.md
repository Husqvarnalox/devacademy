## Структуры, методы и встраивание

В Go нет классов, наследования и ключевого слова `this`. Вместо этого есть три простых механизма:

1. **Структура** (`struct`) - набор именованных полей. Это обычный тип-значение.
2. **Метод** - функция с особым параметром, **получателем** (receiver), записанным перед именем: `func (a *Account) Deposit(n int)`. Метод можно объявить для любого именованного типа из вашего пакета, не только для структур.
3. **Встраивание** (embedding) - поле без имени, только с типом. Поля и методы встроенного типа «поднимаются» наружу, и внешний тип выглядит так, будто унаследовал их. Но это **композиция**: внутри нет скрытого родителя, а встроенный тип ничего не знает о том, что его встроили.

```go
type Logger struct{ lines []string }

type Account struct {
	Logger         // встраивание
	ID      string
	Balance int
}
```

Главный практический вопрос при написании метода: **получатель по значению или по указателю?** Метод с получателем по значению работает с **копией**, и изменения теряются. Метод с получателем по указателю меняет оригинал. Если метод что-то меняет, ему нужен указатель.

Поэтому конструкторы в Go обычно возвращают указатель, а вместо специальных конструкторов-слов используется соглашение: функция `NewAccount(id string) *Account`.

## Точные правила

**Структуры.**

* Литерал: `Account{ID: "a", Balance: 5}` (лучше с именами полей) или `Point{1, 2}` (порядок полей). Нулевая структура - все поля нулевые.
* Структуры сравниваются через `==`, если все поля сравнимы; копируются целиком при присваивании и передаче в функцию.
* `&Account{...}` создаёт значение и берёт его адрес; `new(Account)` даёт указатель на нулевую структуру. Доступ к полю через указатель пишется так же: `p.Balance` вместо `(*p).Balance`.
* Анонимная структура `struct{ X, Y int }{1, 2}` удобна для табличных тестов и разовых данных.

**Методы и получатели.**

* `func (v T) M()` - получатель по значению: метод получает копию. `func (p *T) M()` - по указателю: метод видит оригинал.
* Выбирайте указатель, если метод меняет получателя, если структура большая или содержит то, что нельзя копировать (`sync.Mutex`, `bytes.Buffer`). Для единообразия, если хоть один метод типа с указателем, остальные тоже обычно делают с указателем.
* **Адресуемость.** Вызов `x.M()` для метода с указателем в получателе записывается компилятором как `(&x).M()`, если `x` - адресуемая переменная (локальная переменная, поле адресуемой структуры, элемент среза, разыменованный указатель). Если `x` **не** адресуем - элемент карты, результат вызова функции, литерал-значение - возникает ошибка компиляции `cannot call pointer method`.
* **Наборы методов** (method sets): у типа `T` в наборе только методы с получателем `T`; у типа `*T` - методы с получателями `T` **и** `*T`. Это правило определяет, удовлетворяет ли значение интерфейсу: значение `C{}` не реализует интерфейс, чей метод объявлен на `*C`.
* Метод - обычная функция: выражение `acc.Deposit` (метод-значение) привязывает получателя в момент вычисления; `(*Account).Deposit` (метод-выражение) принимает получателя первым аргументом.
* Тип `Stringer` (`String() string`) используется пакетом `fmt` при печати. Если `String` объявлен на `*T`, то при печати значения `T` он **не** вызывается.

**Встраивание.**

* Встроенное поле называется по имени типа (`Logger`, для `*Logger` - тоже `Logger`). К нему можно обратиться явно: `a.Logger`.
* Поля и методы встроенного типа **продвигаются**: `a.Count()` означает `a.Logger.Count()`. Получателем внутри метода остаётся встроенное значение `Logger`, а не `Account`.
* **Это не наследование.** Нет полиморфизма: если метод `Logger` вызывает другой метод `Logger`, внешний тип не может его «переопределить». Внешний тип может объявить **свой** метод с тем же именем - он скроет (shadow) продвинутый, и тогда явный вызов `a.Logger.Name()` всё ещё доступен.
* Встроенный `*Logger` (указатель) тоже допустим, но тогда нулевое значение внешней структуры содержит `nil`-указатель: обращение к продвинутому методу, разыменовывающему получателя, вызовет панику.
* Если два встроенных типа на одной глубине дают одинаковое имя, ошибка компиляции возникает только при попытке использовать **неоднозначный** селектор.
* Встроенные типы-**интерфейсы** позволяют «переопределять» часть методов интерфейса в обёртке (шаблон «декоратор»).
* Методы продвигаются и в набор методов: у `Account` есть методы `Logger` с получателем `Logger`, а у `*Account` - ещё и методы `*Logger`.

**Конструкторы.** В Go нет специального синтаксиса. По соглашению пишут `NewT(...) *T` (или `(*T, error)`, если проверка может провалиться) и стараются, чтобы нулевое значение типа тоже было пригодно к работе.

## Примеры

**Пример 1. Получатель по значению и по указателю.**

```go run
package main

import "fmt"

type Counter struct{ n int }

func (c Counter) IncValue()    { c.n++ } // меняет копию
func (c *Counter) IncPointer() { c.n++ } // меняет оригинал

func main() {
	var c Counter
	c.IncValue()
	fmt.Println(c.n)
	c.IncPointer() // компилятор вычислит (&c).IncPointer()
	fmt.Println(c.n)

	// Элементы карты не адресуемы, поэтому храним указатели.
	m := map[string]*Counter{"a": {}}
	m["a"].IncPointer()
	m["a"].IncPointer()
	fmt.Println(m["a"].n)

	// Метод-значение привязывает получателя сразу.
	inc := c.IncPointer
	inc()
	inc()
	fmt.Println(c.n)
}
```

```output
0
1
2
3
```

Компилятор отказался бы от `map[string]Counter` с вызовом `m["a"].IncPointer()`: `cannot call pointer method IncPointer on Counter`. Запись `m["a"].n = 1` тоже невозможна: `cannot assign to struct field m["a"].n in map`.

**Пример 2. Встраивание: продвижение, затенение, не наследование.**

```go run
package main

import "fmt"

type Animal struct{ Name string }

func (a Animal) Describe() string { return "животное " + a.Name }
func (a Animal) Intro() string    { return "Я - " + a.Describe() }

type Dog struct {
	Animal
	Breed string
}

// Dog затеняет продвинутый метод Describe своим.
func (d Dog) Describe() string { return "собака " + d.Name + " (" + d.Breed + ")" }

func main() {
	d := Dog{Animal: Animal{Name: "Рекс"}, Breed: "овчарка"}
	fmt.Println(d.Name)            // поле продвинуто
	fmt.Println(d.Describe())      // метод Dog
	fmt.Println(d.Animal.Describe()) // явный доступ к встроенному
	fmt.Println(d.Intro())         // Intro принадлежит Animal и вызывает Animal.Describe
}
```

```output
Рекс
собака Рекс (овчарка)
животное Рекс
Я - животное Рекс
```

Последняя строка показывает отличие от наследования: `Intro` - метод `Animal`, и внутри него `a` всегда `Animal`. Он не знает про `Dog` и не вызывает `Dog.Describe`. В языках с виртуальными методами результат был бы другим.

**Пример 3. `Stringer`, наборы методов и интерфейс.**

```go run
package main

import "fmt"

type Temp struct{ Deg float64 }

func (t *Temp) String() string { return fmt.Sprintf("%.1f°C", t.Deg) }

type Resetter interface{ Reset() }

type Box struct{ items []int }

func (b *Box) Reset() { b.items = nil }

func main() {
	t := Temp{21.5}
	fmt.Println(t)  // String определён на *Temp: для значения не вызывается
	fmt.Println(&t) // для указателя - вызывается

	b := &Box{items: []int{1, 2}}
	var r Resetter = b // *Box реализует Resetter; Box - нет
	r.Reset()
	fmt.Println(len(b.items), b.items == nil)

	// Конструктор и нулевое значение.
	var z Box
	z.Reset()
	fmt.Println(z.items == nil)
}
```

```output
{21.5}
21.5°C
0 true
true
```

`fmt.Println(t)` печатает поля структуры, так как `Temp` (значение) не имеет метода `String` в наборе методов. Присвоение `var r Resetter = Box{}` не скомпилируется: `Box does not implement Resetter (method Reset has pointer receiver)`.

## Типичные ошибки

* **Метод изменяет копию.** `func (a Account) Deposit(n int)` с `a.Balance += n` ничего не меняет у вызывающего. Если метод что-то меняет, пишите `*Account`.
* **Карта структур.** `map[string]Account` не позволяет вызвать метод с указателем и изменить поле. Храните `*Account` или записывайте копию обратно в карту.
* **Смешивание типов получателей** без причины: часть методов по значению, часть по указателю - путает наборы методов и ломает реализацию интерфейсов.
* **Копирование структур с мьютексом.** `sync.Mutex` нельзя копировать после первого использования; передавайте такие структуры по указателю (`go vet` предупреждает о копировании).
* **Принять встраивание за наследование.** Нет `super`, нет виртуальных вызовов, и `Dog` не может быть передан туда, где ожидается `Animal`: типы разные. Для общего поведения используйте интерфейсы.
* **Встраивание «ради удобства» чужого типа.** Все его экспортируемые методы становятся частью вашего API; часто лучше именованное поле и явная делегация.
* **Встроенный указатель, который никто не инициализировал.** `type A struct{ *B }` создаёт `A` с `nil` внутри.
* **Метод `String` на указателе при печати значения** (пример 3): `fmt` не вызовет его.
* **Конструктор, возвращающий значение и мутирующий копию.** Если тип нужно менять, возвращайте `*T`.

<!-- section: summary -->
## Итоги

* Структура - значение; присваивание и передача копируют её. Нулевая структура состоит из нулевых полей.
* Получатель по указателю нужен, если метод меняет объект; элементы карты, результаты функций и литералы-значения не адресуемы.
* Набор методов `T` содержит методы с получателем `T`, набор `*T` - обоих видов; от этого зависит реализация интерфейсов.
* Встраивание продвигает поля и методы, но это композиция: встроенный тип не знает о внешнем и не участвует в виртуальной диспетчеризации; внешний тип может затенить метод своим.
* Конструктор - обычная функция `NewT(...) *T`; хорошие типы работают и с нулевым значением.
