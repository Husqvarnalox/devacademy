## Зачем нужен мини-проект

До сих пор каждый урок давал один инструмент: ввод, цикл, функцию, `Option`, `HashMap`, структуру. Настоящая программа складывается из них всех. Трудность не в отдельных строках, а в том, чтобы разделить задачу на части и собрать части в порядке, при котором ошибка в одном месте не ломает остальное.

В этом уроке нет новых конструкций языка. Есть **конвейер из этапов**, который подходит для любой программы, обрабатывающей строки ввода.

## Одна идея: четыре этапа

1. **Прочитать.** Получить весь ввод и пройти по строкам.
2. **Разобрать.** Каждую строку превратить в структуру или в описание ошибки. Пустые строки пропустить, неверные посчитать.
3. **Накопить.** Верные записи добавлять в общую таблицу (`HashMap`), складывая значения по ключу.
4. **Вывести.** Отсортировать ключи и напечатать отчёт в точно заданном формате.

Каждый этап пишется и проверяется отдельно. Тогда, если отчёт неверен, видно, на каком этапе: данные не разобрались, не накопились или неправильно напечатались.

## Пример. Пошагово на другой задаче: остатки на складе

Чтобы показать конвейер, разберём похожую задачу: строки `товар;число` (положительное число - приход, отрицательное - расход), и нужен отчёт по остаткам. В упражнении будет другая задача: средние баллы студентов. Приёмы те же.

### Этап «разобрать»

```rust run
struct Entry {
    item: String,
    qty: i32,
}

fn parse_entry(line: &str) -> Result<Entry, String> {
    match line.split_once(';') {
        Some((item_text, qty_text)) => {
            let item = item_text.trim();
            if item == "" {
                return Err(String::from("пустое название"));
            }
            match qty_text.trim().parse::<i32>() {
                Ok(qty) => Ok(Entry { item: String::from(item), qty }),
                Err(_) => Err(format!("не число: {}", qty_text.trim())),
            }
        }
        None => Err(String::from("нет разделителя")),
    }
}

fn main() {
    for line in vec!["молоко;10", " хлеб ; -3 ", "сыр;много", ";5", "без разделителя"] {
        match parse_entry(line) {
            Ok(e) => println!("{:?} -> {} x {}", line, e.item, e.qty),
            Err(msg) => println!("{:?} -> ошибка: {}", line, msg),
        }
    }
}
```
```output
"молоко;10" -> молоко x 10
" хлеб ; -3 " -> хлеб x -3
"сыр;много" -> ошибка: не число: много
";5" -> ошибка: пустое название
"без разделителя" -> ошибка: нет разделителя
```

Функция `parse_entry` не печатает и не накапливает: она только превращает строку в `Entry` или в `Err` с причиной. Правила неверной строки выбраны явно: нет `;`, пустое название, число не разобралось. Пробелы вокруг частей убираются `trim`.

### Этап «накопить»

```rust run
use std::collections::HashMap;

struct Entry {
    item: String,
    qty: i32,
}

fn add_entry(table: &mut HashMap<String, i32>, entry: Entry) {
    *table.entry(entry.item).or_insert(0) += entry.qty;
}

fn main() {
    let mut table: HashMap<String, i32> = HashMap::new();
    add_entry(&mut table, Entry { item: String::from("хлеб"), qty: 5 });
    add_entry(&mut table, Entry { item: String::from("молоко"), qty: 10 });
    add_entry(&mut table, Entry { item: String::from("хлеб"), qty: -2 });

    println!("позиций: {}", table.len());
    println!("хлеб: {}", table["хлеб"]);
    println!("молоко: {}", table["молоко"]);
}
```
```output
позиций: 2
хлеб: 3
молоко: 10
```

`*table.entry(entry.item).or_insert(0) += entry.qty` - уже знакомый приём из урока про словари: для новой позиции начать с нуля и прибавить. Запись `entry.item` передаёт название в словарь (оно перемещается), а `entry.qty` ещё доступно: число копируется.

### Этап «вывести»

```rust run
use std::collections::HashMap;

fn report(table: &HashMap<String, i32>) {
    let mut names: Vec<&String> = Vec::new();
    for name in table.keys() {
        names.push(name);
    }
    names.sort();

    let mut best = String::new();
    let mut best_qty = 0;
    for name in names {
        let qty = table[name];
        println!("{name}: {qty}");
        if best == "" || qty > best_qty {
            best = name.clone();
            best_qty = qty;
        }
    }
    println!("Больше всего: {best}");
}

fn main() {
    let mut table: HashMap<String, i32> = HashMap::new();
    table.insert(String::from("яблоки"), 7);
    table.insert(String::from("груши"), 7);
    table.insert(String::from("сливы"), 3);
    report(&table);
}
```
```output
груши: 7
сливы: 3
яблоки: 7
Больше всего: груши
```

Ключи собираются в вектор и сортируются. Поэтому порядок строк предсказуем независимо от того, как `HashMap` хранит данные. «Самая большая» позиция ищется строгим `>` при проходе по отсортированным именам: при равенстве остаётся первая по алфавиту. Здесь у яблок и груш по 7, побеждают груши: они раньше в алфавите.

### Сборка целиком

Программа читает ввод, поэтому приведены ввод и вывод.

```rust
use std::collections::HashMap;

struct Entry {
    item: String,
    qty: i32,
}

fn parse_entry(line: &str) -> Result<Entry, String> {
    match line.split_once(';') {
        Some((item_text, qty_text)) => {
            let item = item_text.trim();
            if item == "" {
                return Err(String::from("пустое название"));
            }
            match qty_text.trim().parse::<i32>() {
                Ok(qty) => Ok(Entry { item: String::from(item), qty }),
                Err(_) => Err(format!("не число: {}", qty_text.trim())),
            }
        }
        None => Err(String::from("нет разделителя")),
    }
}

fn main() {
    let input = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut table: HashMap<String, i32> = HashMap::new();
    let mut valid = 0;
    let mut bad = 0;

    for raw in input.lines() {
        let line = raw.trim();
        if line == "" {
            continue;
        }
        match parse_entry(line) {
            Ok(e) => {
                *table.entry(e.item).or_insert(0) += e.qty;
                valid += 1;
            }
            Err(_) => bad += 1,
        }
    }

    let mut names: Vec<&String> = Vec::new();
    for name in table.keys() {
        names.push(name);
    }
    names.sort();
    for name in names {
        println!("{name}: {}", table[name]);
    }
    println!("Записей: {valid}");
    println!("Неверных строк: {bad}");
}
```

Ввод:

```text
молоко;10
хлеб;5

молоко;-3
сыр;abc
  хлеб ; 4 
;7
```

Вывод:

```text
молоко: 7
хлеб: 9
Записей: 4
Неверных строк: 2
```

* Строки обрабатываются в цикле: `trim`, пустая пропускается через `continue` (и не считается ни верной, ни неверной).
* Верная запись добавляется в таблицу, неверная только увеличивает `bad`.
* Строки `сыр;abc` и `;7` неверные. Строка `  хлеб ; 4 ` верная: пробелы убраны.

**Попробуйте.** Добавьте во ввод строку `молоко;5;6`. Верная она или нет, и почему? Сначала предскажите ответ, затем проверьте.

## Точные правила задачи

* Пустая строка (после `trim`) пропускается и не входит ни в верные, ни в неверные.
* Неверная строка не участвует в итогах, но увеличивает счётчик неверных. Программа продолжает работать.
* Ключи таблицы - `String`; для вывода сортируются вызовом `names.sort()` (порядок кодов символов: заглавные кириллические буквы раньше строчных).
* Среднее считается как `f64`: `sum as f64 / count as f64`, потому что деление целых отбрасывает дробь.
* Для вывода числа с двумя знаками - `{:.2}`; формат не зависит от настроек системы.
* Лучший определяется строгим `>` при проходе по отсортированным ключам: при равенстве побеждает ключ, который раньше по алфавиту.
* Если верных записей нет, отчёт состоит только из итоговых строк, а лучшего нет.
* Входные данные не считаются доверенными: любая строка может оказаться неверной, и это не должно приводить к панике. `unwrap` допустим только для чтения ввода.

## Типичные ошибки

**1. Использование значения после того, как оно перемещено в словарь.**

```rust
use std::collections::HashMap;

fn main() {
    let mut table: HashMap<String, i32> = HashMap::new();
    let name = String::from("Анна");
    *table.entry(name).or_insert(0) += 1;
    println!("{name}");
}
```

```text
error[E0382]: borrow of moved value: `name`
 --> main.rs:7:16
  |
5 |     let name = String::from("Анна");
  |         ---- move occurs because `name` has type `String`, which does not implement the `Copy` trait
6 |     *table.entry(name).or_insert(0) += 1;
  |                  ---- value moved here
7 |     println!("{name}");
  |                ^^^^ value borrowed here after move
  |
help: consider cloning the value if the performance cost is acceptable
  |
6 |     *table.entry(name.clone()).or_insert(0) += 1;
  |                      ++++++++
```

`entry(name)` забирает строку во владение словаря. Если она нужна после этого, передайте копию: `entry(name.clone())`, либо выведите её раньше.

**3. Среднее: деление целых.** Ошибки нет, но дробь отбрасывается:

```rust run
fn main() {
    let sum = 171;
    let count = 2;
    let avg = sum / count;
    println!("{avg}");
}
```
```output
85
```

`171 / 2` - это `85` без `.5`. Программа напечатала ответ, который неверен, и компилятор не предупредил. Приводите числа к `f64` до деления.

**4. Сравнение `f64` с целым числом.**

```rust
fn main() {
    let avg: f64 = 85.5;
    let mut best = 0;
    if avg > best {
        best = 1;
    }
    println!("{best}");
}
```

```text
error[E0308]: mismatched types
 --> main.rs:4:14
  |
4 |     if avg > best {
  |        ---   ^^^^ expected `f64`, found integer
  |        |
  |        expected because this is `f64`
```

Начальное значение для поиска максимума среди дробных пишите дробным литералом: `let mut best = -1.0;`.

**5. Логические ошибки без сообщений компилятора.** Для них нет красных строк, поэтому проверяйте на примере из условия:

* Пустые строки посчитаны как неверные (нужно пропускать их до проверки).
* `trim` вызван после проверки на пустоту, и строка из одних пробелов попала в разбор.
* Для ключа не учтён регистр: `Анна` и `анна` - разные ключи.
* Лучший выбран нестрогим сравнением `>=`: при равенстве победил последний, а не первый по алфавиту.

## Итоги

* Программу удобно собирать как конвейер: прочитать, разобрать, накопить, вывести. Каждый этап проверяется отдельно.
* Разбор возвращает `Result<Структура, String>`; неверные строки считаются и пропускаются, пустые игнорируются.
* Накопление - `HashMap` с `entry().or_insert()`; вывод - отсортированные ключи, чтобы порядок был предсказуем.
* Среднее значение считается через `f64`; лучший выбирается строгим сравнением по отсортированному списку.
* Это завершает курс «Rust с нуля». Дальше в `rust-first-steps` разберём, что на самом деле делает компилятор и почему программа работает так, как вы видели.

Следующий шаг: [как Rust запускает программу](lesson:rust.first-steps.how-rust-runs): `rustc`, сборка и то, чего вы пока не видели - от `-O` до арифметики с переполнением.

## Для тех, кто уже программирует

* Это стандартная форма «ETL в малом»: разбор в типизированные записи, свёртка в таблицу, детерминированный вывод. В идиоматичном Rust этапы выражают цепочками итераторов (`lines().filter(...).map(...)`) и `?` в `main() -> Result<...>`; здесь они раскрыты циклами, чтобы ничего не скрывать.
* Разбор формата вынесен в чистую функцию `parse_entry`: она не имеет побочных эффектов и легко тестируется отдельными вызовами.
* Правила неверных строк (пустое имя, лишние `;`, диапазон) - часть спецификации, а не обработки исключений. В продакшен-коде описывают ошибку собственным `enum` вместо `String`.
* Детерминизм вывода достигается сортировкой ключей `HashMap`. Альтернатива - `BTreeMap`, который хранит ключи упорядоченными.
* Среднее в `f64` может давать накопленную погрешность; для денег используют целые числа в минимальных единицах. Равные рациональные значения (например, `170 / 2` и `85 / 1`) дают одинаковые `f64`, потому что деление округляется корректно.
* Весь ввод читается в память целиком (`read_to_string`); для больших файлов читают построчно через `BufRead`.

## Почему этапы лучше одного большого цикла

Это необязательный раздел: для заданий он не нужен.

Можно написать всю программу одним циклом: читать строку, разбирать её тут же, тут же обновлять таблицу и печатать. Для примера из пяти строк это работает. Но по мере роста требований каждое правило (пустые строки, неверные строки, порядок вывода) приходится вплетать в один тот же блок, и ошибка в любом из них проявляется как «отчёт неправильный» без указания причины.

Разделение даёт три выгоды. **Проверяемость:** `parse_entry` можно вызвать на десятке строк без ввода и таблицы. **Локальность изменений:** другой формат строки меняет только этап разбора. **Единая точка принятия решения:** что считать неверной строкой, определяет только `parse_entry`, а счётчик увеличивается в одном месте.

Есть и тонкость владения. В `*table.entry(e.item).or_insert(0) += e.qty` поле `item` перемещается из структуры `e`, а поле `qty` остаётся: Rust допускает частичное перемещение из значения, которым вы владеете, пока вы не используете структуру целиком. Это одна из причин, почему поля удобнее брать по отдельности, а не передавать структуру туда и обратно.
