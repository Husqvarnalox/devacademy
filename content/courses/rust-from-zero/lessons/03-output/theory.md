## Зачем управлять выводом

Результат работы программы нужно показать так, чтобы его можно было прочитать: чек с отдельными строками, сообщение «Итого: 134 руб.», слова в кавычках. В этом уроке вы научитесь печатать текст частями, добавлять в него переходы на новую строку и кавычки, подставлять в него числа и оставлять в программе заметки для людей.

## Одна новая идея: `{}` - место для значения

Команда `println!` умеет больше, чем печатать готовую строку. Если в тексте записать пару фигурных скобок `{}`, а после текста через запятую указать значение, то `println!` подставит значение на место скобок:

```rust
println!("Итого: {} руб.", 134);
```

Это печатает `Итого: 134 руб.`. Фигурные скобки здесь называются **подстановкой** (в документации - *placeholder*, «заместитель»). Текст в кавычках, в котором есть подстановки, называется **строкой формата**: она показывает, как будет выглядеть результат.

Кроме того, в этом уроке вы увидите три мелочи, которые пригодятся в любой программе: `print!` (печать без перехода на новую строку), **управляющие последовательности** (`\n`, `\"`, `\\`) и **комментарии**.

<!-- section: examples -->
## Пример 1. `print!` и `println!`

```rust run
fn main() {
    print!("Привет, ");
    print!("мир");
    println!("!");
    println!("Следующая строка");
}
```
```output
Привет, мир!
Следующая строка
```

* `print!` печатает текст и **остаётся в той же строке**. Три команды в начале собирают одну строку «Привет, мир!».
* `println!` печатает текст и **переходит на следующую строку**. Название читается как *print line*, «напечатать строку».
* Пробел после запятой в первом `print!` нужен: компьютер не добавляет пробелов сам.

## Пример 2. Управляющие последовательности

```rust run
fn main() {
    println!("Меню:\n1. Чай\n2. Кофе");
    println!("Он сказал: \"Добро пожаловать\"");
    println!("Файл: C:\\Магазин\\чек.txt");
}
```
```output
Меню:
1. Чай
2. Кофе
Он сказал: "Добро пожаловать"
Файл: C:\Магазин\чек.txt
```

Обратная косая черта `\` внутри текста начинает **управляющую последовательность**: два символа, которые вместе означают один особый:

* `\n` - переход на новую строку (в первой команде текст разбивается на три строки);
* `\"` - двойная кавычка как часть текста, а не конец литерала;
* `\\` - сама обратная косая черта.

На экране остаётся только результат: `\n` становится переходом на новую строку, а `\"` и `\\` - одним символом.

## Пример 3. Несколько подстановок

```rust run
fn main() {
    println!("Хлеб: {} руб., молоко: {} руб.", 45, 89);
    println!("Всего товаров: {}", 2);
    println!("{} - это число, а {} - это текст", 7, "слово");
}
```
```output
Хлеб: 45 руб., молоко: 89 руб.
Всего товаров: 2
7 - это число, а слово - это текст
```

Значения подставляются по порядку: первое значение - в первую пару скобок, второе - во вторую. Количество скобок и количество значений должно совпадать. Подставлять можно и числа, и текст: `println!` сам знает, как напечатать значение.

Если нужны сами фигурные скобки как символы, их удваивают:

```rust run
fn main() {
    println!("Шаблон: {{имя}}, цена: {}", 45);
}
```
```output
Шаблон: {имя}, цена: 45
```

## Пример 4. Комментарии

```rust run
fn main() {
    // Эта строка - комментарий, программа её пропускает.
    println!("Начало");
    /* Так можно закомментировать
       сразу несколько строк */
    println!("Конец"); // комментарий можно писать и после команды
}
```
```output
Начало
Конец
```

**Комментарий** - заметка для читателя программы. Всё от `//` до конца строки компилятор пропускает; блок между `/*` и `*/` тоже. Комментарии объясняют, **зачем** сделано то или иное, и позволяют временно «выключить» команду, не стирая её.

**Попробуйте.** Измените в примере 3 числа, добавьте вторую подстановку в последнюю строку и предскажите вывод до запуска. Затем уберите одно значение и посмотрите на сообщение компилятора.

## Точные правила

* `println!` после текста добавляет переход на новую строку, `print!` не добавляет. В этом курсе вывод принято завершать переходом на новую строку, то есть последней командой ставить `println!`.
* Управляющая последовательность начинается с `\`. Допустимые: `\n` (новая строка), `\t` (табуляция), `\"` (двойная кавычка), `\\` (обратная косая черта). Неизвестная последовательность (например, `\q`) - ошибка компиляции.
* Перенос строки прямо внутри кавычек тоже становится частью текста; в этом курсе переносы записывают через `\n`: так видно, где они.
* `{}` - подстановка. Количество `{}` и количество значений после запятой должно совпадать; иначе - ошибка компиляции, программа не запустится.
* Значения подставляются по порядку слева направо. Они разделяются запятыми и идут после строки формата.
* Чтобы напечатать символ `{` или `}`, пишут `{{` или `}}`.
* Первый аргумент `print!`/`println!` всегда строковый литерал в кавычках, а не имя и не число: `println!(45)` не соберётся.
* Склеивать строки оператором `+`, как в Python или Java, Rust не позволяет: `"a" + "b"` - ошибка. Вместо этого значения подставляют в `{}`; другие способы - в уроке про строки.
* `// ...` - комментарий до конца строки, `/* ... */` - блочный комментарий.
* Подстановка `{}` печатает значение в простом виде. Как задать ширину и число знаков после запятой, например `{:.2}`, - в уроке про форматирование.

## Типичные ошибки

**1. Число `{}` и число значений не совпадает.**

```rust
fn main() {
    println!("{} и {}", 5);
}
```

```text
error: 2 positional arguments in format string, but there is 1 argument
 --> main.rs:2:15
  |
2 |     println!("{} и {}", 5);
  |               ^^   ^^   -
```

«Две подстановки в строке формата, но один аргумент». Под скобками и значением стоят указатели: видно, какие подстановки остались без значения. Добавьте значение или уберите скобки.

**2. Лишнее значение.**

```rust
fn main() {
    println!("Итого: {}", 134, 2);
}
```

```text
error: argument never used
 --> main.rs:2:32
  |
2 |     println!("Итого: {}", 134, 2);
  |              -----------       ^ argument never used
  |              |
  |              formatting specifier missing
```

«Аргумент нигде не используется». Компилятор подсказывает, что в строке формата нет подстановки, куда это значение можно было бы поставить.

**3. Нет кавычек.**

```rust
fn main() {
    println!(Привет);
}
```

```text
error: format argument must be a string literal
 --> main.rs:2:14
  |
2 |     println!(Привет);
  |              ^^^^^^
  |
help: you might be missing a string literal to format with
  |
2 |     println!("{}", Привет);
  |              +++++
```

«Аргумент формата должен быть строковым литералом». Первым аргументом `println!` должен быть текст в кавычках. Слово без кавычек Rust воспринимает как имя, а не как текст (подробно об именах - в следующем уроке).

**4. Склейка строк знаком `+`.**

```rust
fn main() {
    println!("Привет, " + "мир");
}
```

```text
error: expected `,`, found `+`
 --> main.rs:2:25
  |
2 |     println!("Привет, " + "мир");
  |                         ^ expected `,`
```

В Rust строки нельзя складывать знаком `+`, как в других языках. Внутри `println!` запятая отделяет следующий аргумент, поэтому компилятор ждёт её. Напишите одну строку `"Привет, мир"` или подставьте части: `println!("{}, {}", "Привет", "мир")`.

**5. Обратная косая черта не там.** Путь `"C:\Магазин"` не соберётся: `\М` - неизвестная управляющая последовательность (сообщение `unknown character escape`). Нужно `"C:\\Магазин"`. Кавычка внутри текста без `\` закрывает литерал раньше времени, и остаток текста превращается в ошибку.

**6. Забытый пробел или перенос.** `print!("Итого:")` и следующий `print!("134")` дадут `Итого:134`. Пробел нужно написать самому, внутри кавычек.

## Итоги

* `print!` печатает текст и остаётся в той же строке; `println!` печатает и переходит на новую строку.
* `\n`, `\"` и `\\` - управляющие последовательности: перенос строки, кавычка и обратная косая черта внутри текста.
* `{}` - место для значения; значения указывают после запятой, их число равно числу `{}`; сами скобки печатают как `{{` и `}}`.
* Склеивать строки знаком `+` в Rust нельзя: используют подстановки.
* Комментарии `//` и `/* */` пропускаются программой и пишутся для людей.

Подставлять в текст пока удобно только значения, записанные прямо в команде. Чтобы хранить значения и использовать их несколько раз, нужны переменные: [Переменные: let и let mut](lesson:rust.from-zero.variables).

## Для тех, кто уже программирует

* `println!` - макрос с проверкой формата при компиляции: число и совместимость подстановок проверяются сразу, так что ошибки `printf`-стиля (не тот спецификатор, не то число аргументов) невозможны.
* Подстановка всегда `{}`, независимо от типа значения; для `Display`-значений (числа, строки) используется `{}`, для отладочного вывода структур - `{:?}` (урок 19). Спецификаторы `%d`, `%s` не нужны.
* Строки не склеиваются `+` между двумя `&str`: левая часть должна быть `String` (и она при этом перемещается). Идиома - `format!` или `push_str` (уроки 7 и 10).
* Литерал в двойных кавычках - `&'static str` в UTF-8. Управляющие последовательности как в C: `\n`, `\t`, `\\`, `\"`, а также `\u{1F600}`.
* Комментарии `//` и `/* */` как в C; блочные комментарии вкладываются. Документирующие `///` и `//!` попадают в `cargo doc`.
* В отличие от `printf`, `println!` не принимает формат-строку из переменной: первый аргумент должен быть литералом.

<!-- section: deep-dive -->
## Во что превращается `println!`

Это необязательный раздел: для заданий он не нужен.

Макрос `println!("Итого: {} руб.", 134)` раскрывается на этапе компиляции. Компилятор разбирает строку формата, делит её на куски текста (`"Итого: "`, `" руб."`) и подстановки, проверяет, что каждой подстановке соответствует значение, которое умеет печататься, и генерирует код, записывающий куски и значения в стандартный вывод по очереди. Поэтому ошибки в формате превращаются в ошибки компиляции, а не в сбои при запуске.

Стандартный вывод в Rust построчно буферизован: текст копится в буфере и отправляется получателю, когда в нём встретился переход на новую строку, а остаток отправляется при завершении программы. Поэтому `print!` без `println!` в конце тоже ничего не теряет, но текст может появиться на экране не сразу. Строку принято завершать переходом на новую строку, чтобы вывод не склеивался с приглашением терминала или с выводом следующей программы.

Фигурные скобки удваиваются потому, что `{` уже имеет в строке формата особое значение. Это общий приём: один и тот же символ, который нужно напечатать как есть, «экранируют» повтором или обратной косой чертой.
