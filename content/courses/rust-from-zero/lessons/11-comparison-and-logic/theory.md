## Зачем нужны сравнения

Чтобы программа могла принимать решения, она сначала должна уметь отвечать на вопросы: «возраст больше 18?», «введено слово "да"?», «число чётное?». Ответ на такой вопрос - одно из двух значений: **правда** (`true`) или **ложь** (`false`). Вы уже встречали такой тип: это `bool`.

Выражение, которое даёт `true` или `false`, называется **условием**. В этом уроке вы научитесь их составлять. Потом, когда мы дойдём до `if`, эти условия будут управлять тем, какие команды выполнятся.

## Одна новая идея: оператор сравнения даёт `bool`

Операторы сравнения ставят между двумя значениями и получают `true` или `false`:

| Запись | Смысл |
|---|---|
| `a == b` | равно |
| `a != b` | не равно |
| `a < b` | меньше |
| `a <= b` | меньше или равно |
| `a > b` | больше |
| `a >= b` | больше или равно |

Обратите внимание на **два** знака равенства. Один знак `=` - это присваивание («положи в переменную»), а два `==` - вопрос «равны ли эти значения?». Путать их - самая частая ошибка новичков.

Простые условия можно соединять логическими операторами:

* `&&` - «и»: истинно, если истинны **оба** условия;
* `||` - «или»: истинно, если истинно **хотя бы одно**;
* `!` - «не»: меняет `true` на `false` и наоборот.

## Пример 1. Сравнение чисел и текста

```rust run
fn main() {
    let a = 7;
    let b = 3;
    println!("{} {} {} {} {} {}", a == b, a != b, a < b, a <= b, a > b, a >= b);
    println!("{}", a % 2 == 1);

    let s = String::from("кот");
    println!("{} {} {}", s == "кот", s == "Кот", "кот" == s);
    println!("{}", 'a' < 'b');
}
```
```output
false true false false true true
true
true false true
true
```

* Первая строка печатает шесть сравнений двух чисел подряд, в порядке таблицы выше.
* `a % 2 == 1` - сначала считается остаток от деления (приоритет арифметики выше, чем у сравнения), потом он сравнивается с 1. Это стандартная проверка нечётности.
* Строки сравниваются на точное совпадение, **регистр важен**: `"кот"` и `"Кот"` - разные.
* `String` и текст в кавычках сравнивать можно в любом порядке: `s == "кот"` и `"кот" == s` оба работают.
* Символы сравниваются по их номерам в таблице Unicode: `'a' < 'b'` истинно.

## Пример 2. Порядок строк

```rust run
fn main() {
    println!("{} {}", "apple" < "banana", "Zebra" < "apple");
    println!("{} {}", "кот" < "пёс", "абв" < "абвг");
}
```
```output
true true
true true
```

Строки сравниваются **по символам слева направо**, как слова в словаре: первое различие решает. Но порядок задаёт таблица символов, а не алфавит: все заглавные латинские буквы стоят раньше строчных, поэтому `"Zebra" < "apple"` истинно. Более короткая строка, совпадающая с началом длинной, считается меньше (`"абв" < "абвг"`). Для русских слов порядок почти алфавитный, но буква «ё» стоит после «я», поэтому на неё полагаться не стоит.

## Пример 3. Логические операторы

```rust run
fn main() {
    let t = true;
    let f = false;
    println!("{} {} {}", t && f, t || f, !t);
    println!("{} {}", !f && t, !(f || t));

    let age = 20;
    println!("{}", age >= 18 && age <= 65);
    println!("{}", age < 18 || age > 65);
}
```
```output
false true false
true false
true
false
```

* `t && f` ложно, потому что `f` ложно; `t || f` истинно, потому что хватает `t`; `!t` - противоположное значение.
* `age >= 18 && age <= 65` - способ записать диапазон «от 18 до 65 включительно». В математике пишут `18 <= age <= 65`, но в Rust так нельзя: нужно два отдельных сравнения, соединённых `&&`.
* `age < 18 || age > 65` - противоположный вопрос: «вне диапазона». Он ложен, потому что 20 не меньше 18 и не больше 65.

## Пример 4. Приоритет и скобки

```rust run
fn main() {
    let t = true;
    let f = false;
    println!("{}", t || f && f);
    println!("{}", (t || f) && f);
    println!("{}", !true == false);
}
```
```output
true
false
true
```

* `&&` связывает **сильнее**, чем `||`, как умножение сильнее сложения. Поэтому `t || f && f` читается как `t || (f && f)` и истинно. Если вы хотите другой порядок, ставьте скобки: `(t || f) && f` ложно.
* `!` связывает сильнее всех: `!true == false` читается как `(!true) == false`, то есть `false == false`.
* Порядок от сильного к слабому: арифметика, затем `!`, затем сравнения, затем `&&`, затем `||`. Не заучивайте: скобки делают выражение понятным и тому, кто будет читать его потом.

**Попробуйте.** Придумайте значения `a` и `b`, при которых `a > 0 && b > 0` ложно, а `a > 0 || b > 0` истинно. Затем замените `&&` на `||` в примере с возрастом и сравните результаты.

## Точные правила

* Сравнения `== != < <= > >=` всегда возвращают `bool`. Печатаются как `true` и `false`.
* **Типы должны совпадать.** `5 == 5.0` (целое и дробное) и `a == b` для `i32` и `i64` - ошибки компиляции. Приведите одно значение к типу другого через `as` (урок про преобразование) или запишите литерал в нужном виде (`5.0`).
* Числа сравниваются по значению. Символы (`char`) - по номеру в Unicode. Строки - по символам слева направо, с учётом регистра.
* `String` и `&str` можно сравнивать между собой оператором `==`, но нельзя сравнить текст с числом: `"5" == 5` - ошибка.
* **Диапазон** записывают через `&&`: `a >= 1 && a <= 10`. Цепочка `1 <= a <= 10` - ошибка компиляции (`comparison operators cannot be chained`).
* `&&` и `||` вычисляются **лениво**: если ответ уже ясен по левой части, правая часть не вычисляется (для `false && ...` и `true || ...`). Пока это не заметно, но пригодится позднее.
* Операнды `&&`, `||` и `!` должны быть `bool`: Rust не считает число истиной или ложью. `x && true` для числа `x` - ошибка. Пишите `x != 0`.
* Приоритет: арифметика, `!`, сравнения, `&&`, `||`. Скобки меняют порядок.
* **Дробные числа сравнивать на `==` опасно**: из-за ошибок округления `0.1 + 0.2 == 0.3` ложно. Для таких сравнений проверяют, что разность мала: `(a - b).abs() < 1e-9`. Целые числа и текст сравниваются точно.
* Пока условие только вычисляется и печатается. Использовать его для выбора действия мы будем с оператором `if`.

## Типичные ошибки

**1. Целое сравнивается с дробным.**

```rust
fn main() {
    let a = 5;
    let b = 5.0;
    println!("{}", a == b);
}
```

```text
error[E0277]: can't compare `{integer}` with `{float}`
 --> main.rs:4:22
  |
4 |     println!("{}", a == b);
  |                      ^^ no implementation for `{integer} == {float}`

error[E0308]: mismatched types
 --> main.rs:4:25
  |
4 |     println!("{}", a == b);
  |                         ^ expected integer, found floating-point number
```

«Нельзя сравнивать целое с дробным», и «ожидалось целое, найдено дробное». Это одна ошибка, показанная двумя сообщениями. Приведите одно число к типу другого: `a as f64 == b`, или сразу пишите `let a = 5.0;`.

**2. Разные целые типы.**

```rust
fn main() {
    let a: i32 = 5;
    let b: i64 = 5;
    println!("{}", a == b);
}
```

```text
error[E0308]: mismatched types
 --> main.rs:4:25
  |
4 |     println!("{}", a == b);
  |                    -    ^ expected `i32`, found `i64`
  |                    |
  |                    expected because this is `i32`
  |
help: you can convert `a` from `i32` to `i64`, matching the type of `b`
  |
4 |     println!("{}", i64::from(a) == b);
  |                    ++++++++++ +
```

Компилятор подсказывает один из способов привести тип. Знакомый вам: `a as i64 == b`.

**3. Текст сравнивают с числом.**

```rust
fn main() {
    let s = "5";
    println!("{}", s == 5);
}
```

```text
error[E0277]: can't compare `&str` with `{integer}`
 --> main.rs:3:22
  |
3 |     println!("{}", s == 5);
  |                      ^^ no implementation for `&str == {integer}`
```

Строка `"5"` и число `5` - разные вещи. Либо сравнивайте с текстом (`s == "5"`), либо сначала разберите строку в число через `parse()`.

**4. Цепочка сравнений.**

```rust
fn main() {
    let x = 3;
    println!("{}", 1 < x < 5);
}
```

```text
error: comparison operators cannot be chained
 --> main.rs:3:22
  |
3 |     println!("{}", 1 < x < 5);
  |                      ^   ^
  |
help: split the comparison into two
  |
3 |     println!("{}", 1 < x && x < 5);
  |                          ++++
```

«Операторы сравнения нельзя соединять цепочкой». Компилятор сам показывает правильную запись: два сравнения через `&&`.

**5. Слово вместо оператора.**

```rust
fn main() {
    let x = 3;
    println!("{}", x > 1 and x < 5);
}
```

```text
error: `and` is not a logical operator
 --> main.rs:3:26
  |
3 |     println!("{}", x > 1 and x < 5);
  |                          ^^^
  |
  = note: unlike in e.g., Python and PHP, `&&` and `||` are used for logical operators
help: use `&&` to perform logical conjunction
```

В Rust пишут `&&`, `||`, `!`, а не `and`, `or`, `not`.

**6. Одиночный знак равенства вместо двойного.**

```rust
fn main() {
    let x = 3;
    let same: bool = x = 3;
    println!("{same}");
}
```

```text
error[E0308]: mismatched types
 --> main.rs:3:22
  |
3 |     let same: bool = x = 3;
  |                      ^^^^^ expected `bool`, found `()`
  |
help: you might have meant to compare for equality
  |
3 |     let same: bool = x == 3;
  |                         +
```

«Ожидался `bool`, найдено `()`»: присваивание `x = 3` ничего не возвращает, а нужно сравнение. Компилятор сам предлагает `==`.

**7. Сравнение с неправильной границей.** Условие «не младше 18» - это `age >= 18`, а не `age > 18`: ровно 18 тоже подходит. Всегда проверяйте граничные значения вслух: «а при 18? а при 17?».

**8. Приоритет `&&` и `||`.** Условие `a || b && c` читается как `a || (b && c)`. Если вам нужно `(a || b) && c`, поставьте скобки.

## Итоги

* Операторы `== != < <= > >=` сравнивают значения и возвращают `bool` (`true` или `false`). Один знак `=` - присваивание, два `==` - сравнение.
* Сравнивать можно только значения одного типа: `5 == 5.0` и `i32 == i64` не компилируются, нужен `as`.
* Текст сравнивается по символам и различает регистр; `String` можно сравнивать с текстом в кавычках.
* `&&` - «и», `||` - «или», `!` - «не». Операнды должны быть `bool`.
* Диапазон записывают через `&&`: `age >= 7 && age <= 17`. Цепочка `7 <= age <= 17` не работает.
* `&&` сильнее, чем `||`; скобки делают порядок явным.
* Пока мы только вычисляем и печатаем такие значения. Чтобы программа выбирала, что делать, условия нужны оператору `if`.

Вы прошли первый блок курса: умеете выводить результат, хранить значения, считать, читать ввод, превращать типы, форматировать вывод и сравнивать. Следующий шаг - научить программу выбирать между действиями: [условный оператор if](lesson:rust.from-zero.if-else) и ветвления, которые работают на условиях из этого урока.

## Для тех, кто уже программирует

* Операторы те же, что в C-подобных языках; `bool` - отдельный тип, никакого «истинного числа». `if x` для целого не скомпилируется, нужно `x != 0`.
* Сравнение требует одинаковых типов у обеих сторон (точнее, реализации `PartialEq<Rhs>`/`PartialOrd<Rhs>`). Нет неявного расширения `i32` в `i64` или целого в `f64`. Для `String` и `&str` реализованы взаимные `PartialEq`, поэтому `s == "x"` работает.
* Строки сравниваются побайтово (лексикографически по UTF-8), что для UTF-8 совпадает с порядком кодовых точек. Это не алфавитный порядок локали; для него нужны внешние библиотеки.
* Цепочки сравнений запрещены на уровне грамматики (`a < b < c`) - в отличие от Python. Операторы сравнения не ассоциативны.
* `&&` и `||` ленивые, как в C; побитовые версии для `bool` - `&`, `|`, `^` (ленивыми не являются). Оператор `!` на целых типах - **побитовое** отрицание (`!5i32 == -6`), а на `bool` - логическое; эта разница сбивает с толку опытных программистов.
* `f64` реализует только `PartialEq`/`PartialOrd` (не `Eq`/`Ord`): `NaN != NaN`. Сравнение на равенство с допуском - ручное.
* Присваивание `=` - выражение типа `()`, поэтому `if x = 3` - ошибка типов, а не опечатка, которая «работает», как в C.

## Почему `5 == 5.0` не компилируется

Это необязательный раздел: для заданий он не нужен.

В математике 5 и 5.0 - одно число, но в компьютере это значения двух разных типов с разным устройством: целое хранится как двоичное число, дробное - как мантисса и порядок. Языки с неявным преобразованием (C, JavaScript) молча приводят одно к другому, и это порождает целый класс тонких ошибок: целое число больше 2^53 не помещается в `double` точно, сравнение знаковых и беззнаковых чисел даёт неожиданные результаты, `NaN` ведёт себя странно. Rust выбирает простое правило: **преобразование всегда видно в коде**. Если вы пишете `a as f64 == b`, читатель знает, что сравнение дробное и что целое было приведено.

Ленивость `&&` и `||` важна тогда, когда правая часть может быть опасной или дорогой. В условии `y != 0 && x / y > 2` деление на ноль не произойдёт: если `y` равен нулю, левая часть ложна, и правая не вычисляется. Это стандартный приём защиты от ошибок.

Наконец, приоритеты. Они подобраны так, чтобы естественные записи читались «по-человечески»: `a > 0 && b > 0 || c` - это `((a > 0) && (b > 0)) || c`. Но автору кода всегда легче прочитать скобки, чем вспоминать таблицу. Привычка добавлять скобки в сложных условиях стоит дешевле любой ошибки в приоритете.
