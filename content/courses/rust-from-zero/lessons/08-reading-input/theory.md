## Зачем нужен ввод

До сих пор все данные были записаны прямо в программе. Такая программа каждый раз делает одно и то же. Настоящая программа получает данные снаружи: от пользователя, из файла, от другой программы. Всё, что программа получает извне, называется **вводом**.

В упражнениях платформа подаёт текст на **стандартный ввод** (по-английски *stdin*, «стандартный вход») вашей программы. Это канал, по которому данные поступают в программу, как по трубе. Ввод всегда приходит **текстом**: даже число сначала записано цифрами, и программе нужно их прочитать (как превратить текст в число - в следующем уроке).

## Одна новая идея: прочитать весь ввод одной командой

В Rust есть готовая команда, которая забирает весь ввод целиком и складывает его в строку `String`:

```rust
let text = std::io::read_to_string(std::io::stdin()).unwrap();
```

Читать её удобно справа налево по смыслу:

* `std::io::stdin()` - «стандартный ввод» (`std` - стандартная библиотека Rust, `io` - её раздел ввода-вывода, пути записывают через `::`);
* `std::io::read_to_string(...)` - «прочитать всё до конца в строку»;
* `.unwrap()` - пока можно считать формальностью: чтение может не удаться, и `unwrap` говорит «если всё хорошо - дай результат; если нет - остановись». Подробнее ниже.

Эту строку достаточно списать как заготовку: она одинаково работает во всех упражнениях курса. В переменной `text` теперь лежит весь ввод, а строки в нём разделены символом перехода на новую строку.

Чтобы работать со строками по одной, у `text` вызывают метод `lines()` («строки»): он разбивает текст на отдельные строки и позволяет брать их по очереди.

```rust
let mut lines = text.lines();
let first = lines.next().unwrap();
```

* `lines.next()` - «дай следующую строку». Первый вызов даёт первую строку, второй - вторую, и так далее.
* `lines` запоминает, на какой строке остановились. Запоминание - это изменение переменной, поэтому она объявлена `let mut`.
* `.unwrap()` снова достаёт саму строку из результата `next()` (почему так, объяснено ниже).

## Пример 1. Две строки

Эту программу нельзя запустить в окне примеров, потому что там нет ввода, поэтому приведены ввод и вывод.

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut lines = text.lines();
    let name = lines.next().unwrap();
    let city = lines.next().unwrap();
    println!("Привет, {name} из города {city}!");
}
```

Ввод:

```text
Анна
Минск
```

Вывод:

```text
Привет, Анна из города Минск!
```

Первый `next()` вернул `Анна`, второй - `Минск`. Порядок вызовов - это порядок строк ввода.

## Пример 2. Строка с пробелами читается целиком

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut lines = text.lines();
    let full_name = lines.next().unwrap();
    println!("Букв: {}", full_name.chars().count());
    println!("{}", full_name.to_uppercase());
}
```

Ввод:

```text
Анна Смирнова
```

Вывод:

```text
Букв: 13
АННА СМИРНОВА
```

`lines()` делит текст только по переходам на новую строку, а не по пробелам. Пробел внутри строки - обычный символ, он вошёл в подсчёт: 4 буквы, пробел и 8 букв дают 13. Здесь пригодились методы из прошлого урока: `chars().count()` и `to_uppercase()` работают с прочитанной строкой, как с любой другой.

## Пример 3. `trim()` убирает лишние пробелы по краям

Пользователи часто случайно оставляют пробелы в начале или в конце строки. Для программы это отдельные символы, которые портят сравнения и вывод. Метод `trim()` («подрезать») возвращает строку без пробельных символов по краям.

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut lines = text.lines();
    let raw = lines.next().unwrap();
    let clean = raw.trim();
    println!("[{raw}] {}", raw.chars().count());
    println!("[{clean}] {}", clean.chars().count());
}
```

Ввод (в начале строки два пробела, в конце три):

```text
  Минск   
```

Вывод:

```text
[  Минск   ] 10
[Минск] 5
```

`trim()` убрал пробелы по краям (пять символов), а пробелы внутри строки остались бы. Привычная запись для чтения строки: `lines.next().unwrap().trim()` - вызовы выстраиваются цепочкой слева направо.

## Пример 4. Что делает `unwrap`

`lines.next()` возвращает не сразу строку, а значение вида «строка, **или ничего**, если строки закончились». Это правильно: заранее неизвестно, сколько строк пришлёт ввод. Поэтому результат нужно «развернуть». Это и делает `unwrap` (от *unwrap*, «развернуть»): если строка есть, он отдаёт её, а если её нет, **останавливает программу** с сообщением об ошибке.

Допустим, программа просит три строки, а пришли две:

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut lines = text.lines();
    let a = lines.next().unwrap();
    let b = lines.next().unwrap();
    let c = lines.next().unwrap();
    println!("{a} {b} {c}");
}
```

Ввод:

```text
раз
два
```

Результат работы:

```text
thread 'main' panicked at main.rs:6:26:
called `Option::unwrap()` on a `None` value
```

«Паника» (*panic*) - аварийная остановка программы. `None` - это то самое «ничего»: третьей строки нет. Для упражнений это нормально: их ввод всегда соответствует условию. Как проверить ввод и не падать, вы увидите позже, в уроках про `Option` и `Result`.

**Попробуйте.** В примере 1 подайте на вход всего одну строку и посмотрите на сообщение. Затем в примере 3 добавьте пробелы в середину строки и убедитесь, что `trim()` их не трогает.

## Точные правила

* Весь ввод читается заготовкой `let text = std::io::read_to_string(std::io::stdin()).unwrap();`. Результат - `String` со всем текстом ввода, включая переходы на новую строку.
* `text.lines()` возвращает разбиение текста на строки. Символы перехода на новую строку (`\n`, а также `\r\n`) в строки не входят. Пустая строка ввода даёт пустую строку (`""`), а не пропуск.
* `lines.next()` выдаёт строки по очереди, начиная с первой. Переменная `lines` должна быть объявлена `let mut`: `next()` меняет её.
* Результат `next()` - «строка или ничего» (тип `Option<&str>`). `unwrap()` достаёт строку; если «ничего» (строки кончились), программа аварийно останавливается с паникой. Код выхода при этом ненулевой, и в упражнении такой запуск считается неудачным.
* `trim()` убирает пробельные символы (пробелы, табуляции, переходы на новую строку) в начале и в конце строки. Пробелы внутри строки остаются. Для убирания только слева или только справа есть `trim_start()` и `trim_end()`.
* Типы: `lines.next().unwrap()` даёт `&str` - вид на часть текста в `text`; `.trim()` тоже даёт `&str`. Пока `text` существует, все такие значения доступны. В этом курсе `text` живёт до конца `main`, поэтому проблем нет.
* Ввод всегда текст. Если в строке записано число `42`, то это пока три символа: две цифры не готовы к арифметике (преобразование - урок 9).
* Команда чтения весь ввод забирает один раз. Вторая такая же команда получит пустую строку, поэтому читайте ввод единожды, в начале `main`.
* Один из принципов упражнений: ввод подчиняется условию. Поэтому проверок на отсутствие строк пока не пишут; `unwrap` здесь означает «я знаю, что строка будет».

## Типичные ошибки

**1. Забыли `mut` у `lines`.**

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let lines = text.lines();
    let first = lines.next().unwrap();
    println!("{first}");
}
```

```text
error[E0596]: cannot borrow `lines` as mutable, as it is not declared as mutable
 --> main.rs:4:17
  |
4 |     let first = lines.next().unwrap();
  |                 ^^^^^ cannot borrow as mutable
  |
help: consider changing this to be mutable
  |
3 |     let mut lines = text.lines();
  |         +++
```

«Нельзя изменять `lines`: она объявлена без `mut`». `next()` двигает позицию внутри `lines`, то есть меняет её. Исправление - в `help`: `let mut lines`.

**2. Забыли `unwrap()` после `next()`.**

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut lines = text.lines();
    let first = lines.next();
    println!("{first}");
}
```

```text
error[E0277]: `Option<&str>` doesn't implement `std::fmt::Display`
 --> main.rs:5:15
  |
5 |     println!("{first}");
  |               ^^^^^^^ `Option<&str>` cannot be formatted with the default formatter
  |
  = help: the trait `std::fmt::Display` is not implemented for `Option<&str>`
```

«Тип `Option<&str>` нельзя напечатать обычным образом». `Option<&str>` - это «строка или ничего»; пока не вызван `unwrap`, у вас не сама строка, а обёртка вокруг неё. Допишите `.unwrap()`.

**3. Забыли `unwrap()` после `read_to_string`.**

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin());
    let mut lines = text.lines();
    println!("{:?}", lines.next());
}
```

```text
error[E0599]: no method named `lines` found for enum `Result<T, E>` in the current scope
 --> main.rs:3:26
  |
3 |     let mut lines = text.lines();
  |                          ^^^^^ method not found in `Result<String, std::io::Error>`
  |
help: consider using `Result::expect` to unwrap the `String` value, panicking if the value is a `Result::Err`
```

«У `Result` нет метода `lines`». Чтение тоже возвращает обёртку: «строка или ошибка чтения». Развернуть её нужно тем же `.unwrap()`.

**4. Строк в вводе меньше, чем вызовов `next().unwrap()`.** Во время работы программа останавливается с сообщением `called `Option::unwrap()` on a `None` value` и номером строки кода, где это случилось. Сравните число вызовов `next()` с числом строк ввода из условия.

**5. Пробелы по краям попали в результат.** Если не вызвать `trim()`, пробелы из ввода окажутся в выводе и в подсчёте длины. Тесты с пробелами по краям - частая причина «верно же работает, но не принимается». Привычка: `lines.next().unwrap().trim()`.

**6. Слово вместо строки.** Новички ожидают, что слова на одной строке (`Анна Минск`) окажутся в разных переменных. `lines()` делит по переходам на новую строку, а не по пробелам. Деление строки на слова - позже, в уроках про коллекции.

## Итоги

* Ввод приходит в программу через stdin и всегда является текстом.
* Весь ввод читается заготовкой `let text = std::io::read_to_string(std::io::stdin()).unwrap();`.
* `let mut lines = text.lines();` разбивает текст на строки; `lines.next().unwrap()` берёт их по очереди. `mut` нужен, потому что `lines` запоминает позицию.
* `unwrap()` достаёт значение из результата, который может оказаться «пустым» или ошибкой; если значения нет, программа аварийно останавливается.
* `trim()` убирает пробельные символы по краям строки.

Прочитанная строка пока остаётся текстом. Чтобы складывать, сравнивать и умножать введённые числа, их нужно превратить из текста в числа: [Преобразование типов: parse и as](lesson:rust.from-zero.type-conversion).

## Для тех, кто уже программирует

* `std::io::read_to_string(stdin())` - функция из стандартной библиотеки (стабильна с Rust 1.65): читает stdin до конца в `String`. Альтернативы - `stdin().read_line(&mut buf)` и `stdin().lock().lines()` - требуют `mut`-буфера, `use std::io::...` и обработки `Result` для каждой строки; в этом курсе они не нужны.
* Чтение всего ввода сразу удобно для небольших входов. Для потоковой обработки больших данных используют `BufRead::lines()` на `stdin().lock()`.
* `str::lines()` разбивает по `\n` и убирает завершающий `\r`; последний перевод строки не создаёт пустой строки в конце.
* `lines()` - итератор (подробнее - в `rust-first-steps`): `next()` требует `&mut self`, отсюда `let mut`. Возвращаемый `Option<&str>` ссылается на буфер `text`, поэтому `text` должен жить дольше всех полученных `&str`.
* `unwrap()` - сокращение для «развернуть или паниковать»: `Option::None` и `Result::Err` приводят к панике. В продакшн-коде используют `?`, `match` или `expect("сообщение")`; здесь он осознанно используется для краткости, пока ввод гарантирован условием.
* `trim()` обрезает Unicode-пробельные символы (`char::is_whitespace`), а не только ASCII-пробелы.
* Нет аналога `scanf`: токенизация (`split_whitespace`) и преобразование (`parse`) выполняются отдельными шагами.

## Почему `next()` возвращает «строку или ничего»

Это необязательный раздел: для заданий он не нужен.

Во многих языках функция чтения строки при исчерпании ввода возвращает специальное значение: `null`, `-1`, `EOF`. Это удобно, пока о нём помнят, и приводит к ошибкам, когда забывают проверить. В Rust такая возможность записана в **типе**: `Option<T>` бывает либо `Some(значение)`, либо `None`. Компилятор не даст использовать значение внутри `Option`, пока вы не рассмотрели оба варианта; `unwrap()` - самый короткий способ ответить «я уверен, что здесь `Some`» и принять последствия, если это не так. Подробно `Option` и `match` разобраны в одном из следующих уроков.

То же с `Result<T, E>`: либо `Ok(значение)`, либо `Err(ошибка)`. Чтение из stdin может завершиться ошибкой (например, ввод не является корректным UTF-8), и функция честно возвращает `Result`. `unwrap()` на `Err` тоже паникует.

Паника в Rust по умолчанию раскручивает стек: программа выполняет очистку и завершается с ненулевым кодом (101). В заданиях платформа видит этот код и сообщение в потоке ошибок, поэтому паника отличается от обычного неправильного ответа: вы получите текст `panicked at ...` с номером строки, в которой остановка произошла.
