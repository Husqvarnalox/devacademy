## Зачем преобразовывать типы

Из прошлого урока вы знаете, что ввод приходит текстом. Строка `"42"` выглядит как число, но для программы это два символа, и умножить её на 2 нельзя. Чтобы считать, текст нужно **превратить в число**. Бывает и наоборот: число нужно превратить в текст, чтобы узнать, сколько в нём цифр. А ещё Rust не смешивает числа разных типов: `i32` и `i64`, целое и дробное придётся согласовывать самим.

Все эти превращения называются **преобразованием типов**. В Rust оно всегда явное: компилятор сам ничего не превращает, зато вы всегда видите, где это происходит.

## Три способа

1. **Текст в число - `parse()`** («разобрать»). `"42".parse()` пытается прочитать число из текста. Попытка может не удаться (например, для `"abc"`), поэтому, как и `next()`, `parse()` возвращает «результат или ошибку», и вы добавляете `.unwrap()`.
2. **Число в число - `as`**. Запись `x as f64` читается «`x`, как `f64`» и превращает число в число другого типа: `i32` в `f64`, `f64` в `i32` и так далее.
3. **Число в текст - `to_string()`**. `42.to_string()` даёт строку `"42"`.

И одна приятная мелочь, которая нужна при разборе: **затенение**. Можно объявить новую переменную с тем же именем, что у старой, - это называется затенением (*shadowing*), - и тогда новая «закрывает» старую. Значит, текст можно превратить в число, не придумывая второе имя.

<!-- section: examples -->
## Пример 1. `parse()`: текст в число

```rust run
fn main() {
    let a: i32 = "42".parse().unwrap();
    let b = "7".parse::<i32>().unwrap();
    let price: f64 = "2.5".parse().unwrap();
    println!("{}", a + b);
    println!("{}", price * 2.0);
}
```
```output
49
5
```

* `"42".parse()` можно вызвать у любого текста. Но во что превращать - число какого типа? Компилятор должен знать. Подсказать тип можно двумя способами: написать его у переменной (`let a: i32 = ...`) или прямо у метода (`parse::<i32>()`). Запись `::<i32>` с двоеточиями читается «в тип `i32`»; её называют «турбофиш» (*turbofish*) за форму `::<>`. Выбирайте любой из двух способов.
* `.unwrap()` развёртывает результат: число, если текст разобрался, или остановка программы, если нет (как в уроке про ввод).
* `price * 2.0` печатается как `5`, а не `5.0`: `println!` не добавляет `.0` у дробного числа, если дробная часть нулевая. Как управлять таким выводом, мы разберём в следующем уроке.

## Пример 2. Чтение числа из ввода

Эту программу нельзя запустить в окне примеров, потому что там нет ввода, поэтому приведены ввод и вывод.

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut lines = text.lines();
    let a: i32 = lines.next().unwrap().trim().parse().unwrap();
    let b: i32 = lines.next().unwrap().trim().parse().unwrap();
    println!("Сумма: {}", a + b);
}
```

Ввод:

```text
17
25
```

Вывод:

```text
Сумма: 42
```

Цепочка `lines.next().unwrap().trim().parse().unwrap()` выглядит длинной, но читается слева направо: взять строку, достать, убрать пробелы по краям, разобрать как число, достать. `trim()` здесь необязателен для чистых данных, но обязателен для разбора с пробелами: `" 42".parse::<i32>()` вернёт ошибку, потому что пробел не цифра.

## Пример 3. Затенение: то же имя, новый тип

```rust run
fn main() {
    let value = "  15 ";
    let value = value.trim();
    let value: i32 = value.parse().unwrap();
    let value = value * 2;
    println!("{value}");
}
```
```output
30
```

Каждый `let value` создаёт **новую** переменную. Новая «затеняет» старую: с этого места имя `value` относится к ней. Сначала `value` - текст с пробелами, потом тот же текст без пробелов, потом число 15, потом число 30. Старые значения никуда не мешают, и придумывать `value_trimmed`, `value_number` не нужно.

Чем это отличается от `let mut` с присваиванием `value = ...`? Присваивание меняет значение, а **тип остаётся прежним**: в переменную с числом нельзя записать текст. Затенение создаёт новую переменную, и тип у неё может быть любой. Вот почему для «текст в число» используют именно затенение.

## Пример 4. `as`: число в число

```rust run
fn main() {
    let items = 7;
    let people = 2;
    println!("Целое деление: {}", items / people);
    println!("Дробное деление: {}", items as f64 / people as f64);

    let price = 3.99;
    println!("Дробное в целое: {}", price as i32);
    println!("Отрицательное: {}", -3.99_f64 as i32);

    let big: i64 = 5_000_000_000;
    println!("i64 в i32: {}", big as i32);
}
```
```output
Целое деление: 3
Дробное деление: 3.5
Дробное в целое: 3
Отрицательное: -3
i64 в i32: 705032704
```

* `items as f64 / people as f64` - перед делением оба целых превращены в дробные, поэтому результат дробный: 3.5. `as` связывает сильнее, чем `/`, так что `as f64` относится к ближайшему числу слева.
* `price as i32` **отбрасывает** дробную часть, а не округляет: 3.99 превращается в 3, -3.99 - в -3.
* `big as i32` - значение 5 000 000 000 не помещается в `i32` (максимум около 2,1 миллиарда), и `as` молча обрезает его до «хвоста»: получается 705032704. Здесь `as` не сообщает об ошибке. Поэтому приводите к меньшему типу, только если уверены, что значение поместится.

## Пример 5. `to_string()`: число в текст

```rust run
fn main() {
    let n = 12345;
    let text = n.to_string();
    println!("Число {} состоит из {} цифр", n, text.len());
    println!("{} {}", 3.5.to_string(), true.to_string());
}
```
```output
Число 12345 состоит из 5 цифр
3.5 true
```

`to_string()` создаёт новую строку (`String`) с записью значения. Цифры занимают по одному байту, поэтому `text.len()` равно числу цифр. Минус у отрицательного числа - тоже символ в строке.

**Попробуйте.** В примере 4 вычислите `items as f64 / people as f64` для 10 и 4 и предскажите результат. Затем попробуйте разобрать `"3.5"` как `i32` в примере 1 и посмотрите на сообщение.

## Точные правила

* `текст.parse::<Тип>()` и `let x: Тип = текст.parse()...` разбирают текст в число. Тип нужно указать одним из двух способов; без него компилятор сообщит `type annotations needed`.
* Результат `parse()` - «число или ошибка» (тип `Result`). `unwrap()` достаёт число или останавливает программу при ошибке. Пока ввод соответствует условию, `unwrap()` безопасен.
* Что не разбирается как `i32`: пустая строка, буквы, дробная запись (`3.5`), пробелы по краям (`" 42"`), число, которое не помещается в `i32`. Знак `-` в начале допустим (`"-5"`), знак `+` тоже. Для `f64` допустимы записи `2.5`, `-0.5`, `3`, `1e3`.
* Строки из ввода нужно подготовить: `trim()` убирает пробелы, и только затем `parse()`.
* **Оператор `as`**: `выражение as Тип` приводит число к другому числовому типу. Он связывает сильнее арифметики: `a as f64 / 2.0` значит `(a as f64) / 2.0`.
* Целое в дробное: точное для небольших значений. Дробное в целое: дробная часть отбрасывается (в сторону нуля); если значение вне диапазона, получается ближайший предел типа (для NaN - 0).
* Целое в целое меньшего размера: старшие биты просто отбрасываются (значение «заворачивается»), ошибки нет. `300 as u8` равно 44; `-1_i32 as u32` равно 4294967295.
* Rust не смешивает числовые типы в одном выражении: `i32 + i64`, `f64 * i32`, `i32 + f64` - ошибки компиляции. Нужно привести одно из чисел так, чтобы типы совпали.
* Целый литерал без точки не становится `f64`: `let x: f64 = 10;` - ошибка, пишите `10.0`.
* `значение.to_string()` работает для чисел, символов, `bool` и строк; возвращает `String`.
* **Затенение**: `let x = ...;` с уже существующим именем создаёт новую переменную. Тип новой может отличаться. Старая переменная недоступна в этой области видимости после затенения. Изменяемость (`mut`) у новой своя: `let x` создаёт неизменяемую, даже если прежняя была `mut`.
* Присваивание `x = ...;` без `let` не меняет тип: записать текст в переменную с числом нельзя.

## Типичные ошибки

**1. Смешали разные числовые типы.**

```rust
fn main() {
    let a: i32 = 5;
    let b: i64 = 10;
    println!("{}", a + b);
}
```

```text
error[E0308]: mismatched types
 --> main.rs:4:24
  |
4 |     println!("{}", a + b);
  |                        ^ expected `i32`, found `i64`

error[E0277]: cannot add `i64` to `i32`
 --> main.rs:4:22
  |
4 |     println!("{}", a + b);
  |                      ^ no implementation for `i32 + i64`
  |
  = help: the trait `Add<i64>` is not implemented for `i32`
```

«Ожидался `i32`, найден `i64`», и «нельзя прибавить `i64` к `i32`». (После этих двух сообщений компилятор печатает длинный список других комбинаций - его можно пропустить.) Исправление: привести одно число к типу другого, например `a as i64 + b`.

**2. Дробное умножено на целое.**

```rust
fn main() {
    let x: f64 = 2.5;
    let n: i32 = 3;
    println!("{}", x * n);
}
```

```text
error[E0277]: cannot multiply `f64` by `i32`
 --> main.rs:4:22
  |
4 |     println!("{}", x * n);
  |                      ^ no implementation for `f64 * i32`
```

Здесь верно то же самое. Решение: `x * n as f64`.

**3. Тип для `parse()` не указан.**

```rust
fn main() {
    let n = "5".parse().unwrap();
    println!("{n}");
}
```

```text
error[E0284]: type annotations needed
 --> main.rs:2:9
  |
2 |     let n = "5".parse().unwrap();
  |         ^       ----- type must be known at this point
  |
help: consider giving `n` an explicit type
  |
2 |     let n: /* Type */ = "5".parse().unwrap();
  |          ++++++++++++
```

«Нужно указать тип». `parse()` умеет разбирать разные типы чисел, и компилятор не угадывает, какое вы хотите. Допишите `let n: i32` или `parse::<i32>()`.

**4. Целое поделено на дробное без приведения.**

```rust
fn main() {
    let half = 10 as f64 / 4;
    println!("{half}");
}
```

```text
error[E0277]: cannot divide `f64` by `{integer}`
 --> main.rs:2:26
  |
2 |     let half = 10 as f64 / 4;
  |                          ^ no implementation for `f64 / {integer}`
  |
help: consider using a floating-point literal by writing it with `.0`
  |
2 |     let half = 10 as f64 / 4.0;
  |                             ++
```

После `as f64` левая часть дробная, а `4` - целое. Компилятор сам предлагает `4.0`.

**5. Дробное число записано в целую переменную.**

```rust
fn main() {
    let n: i32 = 3.7;
    println!("{n}");
}
```

```text
error[E0308]: mismatched types
 --> main.rs:2:18
  |
2 |     let n: i32 = 3.7;
  |            ---   ^^^ expected `i32`, found floating-point number
  |            |
  |            expected due to this
```

Дробное в целое неявно не превращается. Если вам нужна целая часть, пишите `3.7_f64 as i32` или объявите переменную `f64`.

**6. Арифметика над текстом.**

```rust
fn main() {
    let t = "12";
    println!("{}", t * 2);
}
```

```text
error[E0369]: cannot multiply `&str` by `{integer}`
 --> main.rs:3:22
  |
3 |     println!("{}", t * 2);
  |                    - ^ - {integer}
  |                    |
  |                    &str
```

«Нельзя умножить `&str` на число». Текст нужно сначала превратить в число: `let t: i32 = t.parse().unwrap();`.

**7. `parse()` не принимает запись, и программа останавливается.**

```rust
fn main() {
    let s = " 42";
    let n: i32 = s.parse().unwrap();
    println!("{n}");
}
```

```text
thread 'main' panicked at main.rs:3:28:
called `Result::unwrap()` on an `Err` value: ParseIntError { kind: InvalidDigit }
```

Сообщение читается так: «`unwrap` у ошибки: ошибка разбора целого, причина - недопустимая цифра». Недопустимой цифрой здесь стал пробел. Та же ошибка будет для `"3.5"` и `"abc"`. Ставьте `trim()` перед `parse()` и убеждайтесь, что тип подходит: дробное не разбирается как целое.

**8. Присваивание вместо затенения.** Код `let mut n = "5"; n = n.parse::<i32>().unwrap();` не соберётся: переменная осталась текстовой (`expected &str, found i32`). Нужно создать новую переменную через `let n: i32 = ...`.

## Итоги

* Ввод - текст; чтобы считать, его превращают в числа: `let n: i32 = line.trim().parse().unwrap();`. Тип обязателен.
* `x as f64`, `x as i32` и так далее приводит число к другому числовому типу. Дробное в целое отбрасывает дробную часть; при приведении к меньшему целому лишние биты обрезаются без ошибки.
* Rust не смешивает числовые типы: `i32 + i64` и `f64 * i32` не компилируются, нужен `as`.
* Деление дробное, если хотя бы один из операндов приведён к `f64` (и второй тоже дробный): `a as f64 / 2.0`.
* `to_string()` превращает число в текст.
* Затенение (`let x = x.trim(); let x: i32 = x.parse().unwrap();`) позволяет сохранить имя при смене типа.

Чтобы напечатать дробное число с нужным количеством знаков и выровнять колонки, нужны правила форматирования: [Форматированный вывод](lesson:rust.from-zero.formatted-output).

## Для тех, кто уже программирует

* Нет неявных числовых преобразований, даже расширяющих (`i32` в `i64`). Явные приведения: `as` (всегда успешное, но может терять данные) и `From`/`Into` (`i64::from(x)` - без потерь; `u8::try_from(x)` - с проверкой, возвращает `Result`). Для проверки диапазона предпочитайте `try_from`; `as` в этом курсе используется для коротких вычислений.
* Семантика `as`: целое в целое - усечение/расширение по двоичному представлению (знаковое расширение для знаковых), float -> int - насыщение и усечение в сторону нуля, `NaN -> 0`; int -> float - ближайшее представимое.
* Приоритет: `as` выше `*` `/`, ниже унарных операторов. `-3.99_f64 as i32`: сначала унарный минус у литерала, затем `as`.
* `str::parse::<T>()` работает для любого типа с `FromStr`; для чисел он строгий: нет пробелов по краям, нет пустой строки, нет скрытой локали (десятичный разделитель - только точка).
* Затенение - не мутация: новая привязка, возможно другого типа. Идиоматично для цепочки «сырой ввод -> очищенный -> разобранный».
* Литералы без суффикса выводятся по контексту (`let x: f64 = 1.0`), но целый литерал не становится `f64` (`let x: f64 = 1;` - ошибка).
* `to_string()` доступен через трейт `ToString` для любого `Display`-типа; `format!("{}", x)` делает то же. Подробности о трейтах - в `rust-first-steps`.

## Почему Rust так строг к числам

Это необязательный раздел: для заданий он не нужен.

В C и многих других языках `int + long` или `double * int` работают сами: компилятор расширяет меньший тип до большего. Удобно, но источник тонких ошибок: знаковое и беззнаковое сравнение, потеря точности при переходе `int` в `float`, неожиданное целочисленное деление там, где ждали дробь. Rust выбирает требовать явной записи: каждое превращение видно в тексте программы, и читатель знает, где значение может измениться.

Поэтому же `as` нельзя считать «безопасным по умолчанию»: он явный, но не проверяющий. `300 as u8` даёт 44, и никакого предупреждения не будет. Когда потеря данных недопустима, используют `try_from`, который возвращает `Result`: «получилось» или «не поместилось». В этом курсе мы остаёмся на `as`, потому что значения в упражнениях небольшие и подобраны заранее.

Затенение же решает типичную проблему с вводом: строка и число - одно и то же значение в разных обличьях, и разные имена для них только мешают. Компилятор следит, чтобы после затенения вы не обратились к старой переменной по ошибке: старая переменная просто больше недоступна.

Откуда берутся числа с «хвостами» вроде 705032704 при `big as i32`? Число 5 000 000 000 в двоичной записи занимает 33 бита, и `i32` оставляет младшие 32; остаток по модулю 2^32 и есть результат.
