## Зачем нужны функции

Допустим, в программе трижды нужно посчитать цену со скидкой. Копировать одни и те же строки три раза неудобно: нашли ошибку - исправляйте в трёх местах. Лучше записать этот кусок кода один раз, дать ему **имя** и затем вызывать по имени. Именованный кусок кода называется **функцией**.

Вы уже пользовались функциями: `main` - это функция, которую вызывает система при запуске программы, а `to_uppercase()` и `parse()` - функции, написанные авторами языка. Теперь вы научитесь создавать свои.

## Одна новая идея: функция принимает данные и возвращает результат

```rust
fn square(x: i32) -> i32 {
    x * x
}
```

* `fn` («function») объявляет функцию, `square` - её имя.
* В скобках - **параметры**: входные данные функции. У каждого параметра есть имя и тип (`x: i32`). Несколько параметров разделяют запятой.
* `-> i32` после скобок - тип **результата**, то, что функция отдаёт обратно.
* Тело в фигурных скобках. Его **последнее выражение без точки с запятой** становится результатом.

Вызов: `square(7)`. Значение в скобках называется **аргументом**; оно попадает в параметр `x`. Результат вызова можно положить в переменную, напечатать или использовать в выражении, как обычное число.

## Пример 1. Функция без результата

```rust run
fn greet(name: &str) {
    println!("Здравствуйте, {name}!");
    println!("Рады вас видеть.");
}

fn main() {
    greet("Анна");
    greet("Борис");
}
```
```output
Здравствуйте, Анна!
Рады вас видеть.
Здравствуйте, Борис!
Рады вас видеть.
```

* `greet(name: &str)` принимает одно значение: текст. Запись `&str` пока можно читать как «текст в кавычках»; почему перед `str` стоит `&`, объяснит следующий урок.
* Стрелки `->` нет, значит функция ничего полезного не возвращает. Формально она возвращает «пустое значение» `()`, которое называют **unit** (по-русски «единица»; смысл - «ничего»).
* Строки в теле выполняются при **каждом вызове**: `greet("Анна")`, затем `greet("Борис")`. Параметр `name` в каждом вызове свой.

**Попробуйте.** Добавьте третий вызов `greet("Вера")`. Затем добавьте функции второй параметр `age: i32` и напечатайте его.

## Пример 2. Функции с результатом

```rust run
fn square(x: i32) -> i32 {
    x * x
}

fn average(a: f64, b: f64) -> f64 {
    (a + b) / 2.0
}

fn is_even(n: i32) -> bool {
    n % 2 == 0
}

fn main() {
    let s = square(7);
    println!("7 в квадрате: {s}");
    println!("Площадь: {}", square(3) + square(4));
    println!("Среднее: {}", average(4.0, 9.0));
    println!("Чётное ли 10: {}", is_even(10));
    if is_even(s) {
        println!("{s} чётное");
    } else {
        println!("{s} нечётное");
    }
}
```
```output
7 в квадрате: 49
Площадь: 25
Среднее: 6.5
Чётное ли 10: true
49 нечётное
```

* `x * x` - последнее выражение тела **без `;`**, поэтому оно и есть результат функции. Если добавить `;`, получится ошибка (см. ниже).
* `square(3) + square(4)` - вызовы можно использовать внутри выражений.
* `average` принимает два `f64` и возвращает `f64`. Типы входа и выхода придётся указывать всегда: компилятор не выводит их для функций.
* Функция, возвращающая `bool`, обычно называется как вопрос: `is_even`. Её удобно ставить прямо в условие `if`.
* Порядок функций в файле не важен: `main` может стоять выше или ниже функций, которые вызывает.

## Пример 3. Досрочный выход через `return`

```rust run
fn grade(score: i32) -> String {
    if score >= 90 {
        return String::from("отлично");
    }
    if score >= 60 {
        return String::from("зачёт");
    }
    String::from("не зачёт")
}

fn describe(name: &str, score: i32) -> String {
    format!("{name}: {score} ({})", grade(score))
}

fn main() {
    println!("{}", describe("Анна", 95));
    println!("{}", describe("Борис", 72));
    println!("{}", describe("Вера", 40));
}
```
```output
Анна: 95 (отлично)
Борис: 72 (зачёт)
Вера: 40 (не зачёт)
```

* `return значение;` немедленно завершает функцию и возвращает значение. Он полезен, когда ответ ясен раньше конца: в `grade` сначала проверяются особые случаи.
* Если ни один `return` не сработал, результатом становится последнее выражение: `String::from("не зачёт")` без `return` и без `;`.
* Функции возвращают `String`, а не `&str`, потому что текст нужно создать внутри функции. Почему нельзя вернуть `&str`, объясняется в ошибках.
* `describe` вызывает `grade`: функции могут вызывать друг друга. Команда `format!` собирает строку так же, как `println!` её печатает.

## Пример 4. Область видимости

```rust run
fn main() {
    let total = 5;
    {
        let local = 10;
        println!("внутри блока: {total} и {local}");
    }
    println!("снаружи: {total}");
    show(total);
}

fn show(value: i32) {
    let doubled = value * 2;
    println!("show получила {value}, удвоила до {doubled}");
}
```
```output
внутри блока: 5 и 10
снаружи: 5
show получила 5, удвоила до 10
```

Переменная существует только в **области видимости**: от `let` до закрывающей `}` блока, в котором она объявлена.

* `local` создана во вложенном блоке и после его `}` недоступна.
* `doubled` принадлежит функции `show` и снаружи не видна. Функция не видит и переменных `main`: `total` доступна ей только потому, что передана аргументом в параметр `value`.

Поэтому внутри функции можно не бояться совпадения имён: `x` в одной функции и `x` в другой - разные переменные.

## Пример 5. Задание с готовым `main`

Дальше в упражнениях `main` написан за вас: он читает ввод, вызывает ваши функции и печатает ответ. Ваша задача - написать функции. Так выглядит такая программа; она читает ввод, поэтому приведены ввод и вывод.

```rust
fn price_with_tax(price: f64, tax_percent: f64) -> f64 {
    price + price * tax_percent / 100.0
}

fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut lines = text.lines();
    let price: f64 = lines.next().unwrap().trim().parse().unwrap();
    let tax: f64 = lines.next().unwrap().trim().parse().unwrap();
    println!("{:.2}", price_with_tax(price, tax));
}
```

Ввод:

```text
250
20
```

Вывод:

```text
300.00
```

## Точные правила

* Объявление: `fn имя(параметр: Тип, ...) -> ТипРезультата { тело }`. Имена функций и переменных пишут строчными буквами со знаком подчёркивания: `price_with_tax`.
* **Типы параметров и результата указываются всегда.** Тип результата можно опустить только у функций, которые ничего не возвращают.
* Результат - последнее выражение тела без `;`, либо `return значение;`.
* Если `->` нет, функция возвращает `()`. Если после последнего выражения поставить `;`, тело превращается в инструкцию и тоже возвращает `()` - это ошибка, когда ожидался другой тип.
* Аргументов при вызове должно быть ровно столько, сколько параметров, и их типы должны совпадать с объявленными. Неявных преобразований нет: `square(2.5)` для `i32` - ошибка.
* Параметр - это обычная переменная внутри функции. По умолчанию она неизменяемая.
* Области видимости: переменная видна от объявления до конца блока; функция не видит переменные вызывающего кода, кроме полученных в аргументах.
* Объявление функции может стоять до или после её вызова.
* Возвращать `&str` из функции, не принимающей ссылок, нельзя без дополнительного обозначения (времена жизни, это позже). Пока возвращайте `String`.

## Типичные ошибки

**1. Нет типа у параметра.**

```rust
fn double(x) -> i32 {
    x * 2
}

fn main() {
    println!("{}", double(4));
}
```

```text
error: expected one of `:`, `@`, or `|`, found `)`
 --> main.rs:1:12
  |
1 | fn double(x) -> i32 {
  |            ^ expected one of `:`, `@`, or `|`
  |
help: if this is a parameter name, give it a type
  |
1 | fn double(x: TypeName) -> i32 {
  |            ++++++++++
help: if this is a type, explicitly ignore the parameter name
  |
1 | fn double(_: x) -> i32 {
  |           ++
```

Тип параметра обязателен: `fn double(x: i32) -> i32`.

**2. Лишняя `;` после результата.**

```rust
fn double(x: i32) -> i32 {
    x * 2;
}

fn main() {
    println!("{}", double(4));
}
```

```text
error[E0308]: mismatched types
 --> main.rs:1:22
  |
1 | fn double(x: i32) -> i32 {
  |    ------            ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
2 |     x * 2;
  |          - help: remove this semicolon to return this value
```

Функция обещала вернуть `i32`, но тело закончилось инструкцией, которая значения не даёт. Компилятор точно указывает на лишнюю точку с запятой.

**3. Нет `-> Тип`, но значение возвращается.**

```rust
fn double(x: i32) {
    x * 2
}

fn main() {
    println!("{:?}", double(4));
}
```

```text
error[E0308]: mismatched types
 --> main.rs:2:5
  |
1 | fn double(x: i32) {
  |                  - help: try adding a return type: `-> i32`
2 |     x * 2
  |     ^^^^^ expected `()`, found `i32`
```

Без стрелки функция считается возвращающей `()`, и результат типа `i32` несовместим с ней. Добавьте `-> i32`.

**4. Неверное число аргументов.**

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b
}

fn main() {
    println!("{}", add(1));
}
```

```text
error[E0061]: this function takes 2 arguments but 1 argument was supplied
 --> main.rs:6:20
  |
6 |     println!("{}", add(1));
  |                    ^^^--- argument #2 of type `i32` is missing
  |
note: function defined here
 --> main.rs:1:4
  |
1 | fn add(a: i32, b: i32) -> i32 {
  |    ^^^         ------
help: provide the argument
  |
6 |     println!("{}", add(1, /* i32 */));
  |                         +++++++++++
```

Нужно ровно два аргумента: `add(1, 2)`.

**5. Аргумент не того типа.**

```rust
fn square(x: i32) -> i32 {
    x * x
}

fn main() {
    println!("{}", square(2.5));
}
```

```text
error[E0308]: mismatched types
 --> main.rs:6:27
  |
6 |     println!("{}", square(2.5));
  |                    ------ ^^^ expected `i32`, found floating-point number
  |                    |
  |                    arguments to this function are incorrect
  |
note: function defined here
 --> main.rs:1:4
  |
1 | fn square(x: i32) -> i32 {
  |    ^^^^^^ ------
```

Параметр объявлен как `i32`, а передано дробное число. Автоматического преобразования нет: запишите подходящее значение или измените тип параметра.

**6. Функция возвращает `&str`.**

```rust
fn label(n: i32) -> &str {
    if n < 0 { "минус" } else { "плюс" }
}

fn main() {
    println!("{}", label(5));
}
```

```text
error[E0106]: missing lifetime specifier
 --> main.rs:1:21
  |
1 | fn label(n: i32) -> &str {
  |                     ^ expected named lifetime parameter
  |
  = help: this function's return type contains a borrowed value, but there is no value for it to be borrowed from
help: consider using the `'static` lifetime, but this is uncommon unless you're returning a borrowed value from a `const` or a `static`
  |
1 | fn label(n: i32) -> &'static str {
  |                      +++++++
help: instead, you are more likely to want to change the argument to be borrowed...
  |
1 | fn label(n: &i32) -> &str {
  |             +
help: ...or alternatively, you might want to return an owned value
  |
1 - fn label(n: i32) -> &str {

```

Компилятор просит указать, как долго будет жить возвращаемый текст. Это тема из `rust-first-steps` и дальше. Пока сделайте функцию возвращающей `String`: `String::from("минус")`.

**7. Переменная из другой функции.**

```rust
fn calc() -> i32 {
    let result = 42;
    result
}

fn main() {
    calc();
    println!("{result}");
}
```

```text
error[E0425]: cannot find value `result` in this scope
 --> main.rs:8:16
  |
8 |     println!("{result}");
  |                ^^^^^^ not found in this scope
```

`result` существует только внутри `calc`. Чтобы получить значение снаружи, запомните результат вызова: `let result = calc();`.

## Итоги

* `fn имя(параметр: Тип) -> Тип { ... }` объявляет функцию; вызов - `имя(аргумент)`.
* Типы параметров и результата указываются всегда; число и типы аргументов должны совпадать с объявлением.
* Результат - последнее выражение без `;` или `return значение;`. Лишняя `;` ломает результат.
* Функция без `->` возвращает `()` («ничего»).
* Переменные живут до конца своего блока; функция видит только свои параметры и локальные переменные.
* Тексты пока возвращайте как `String`, а принимайте как `&str`.

Следующий урок: [владение](lesson:rust.from-zero.ownership-basics): почему функции иногда «забирают» переменную и как давать им только посмотреть.

## Для тех, кто уже программирует

* Синтаксис `fn name(p: T) -> R { ... }` похож на Go и Kotlin. Типы обязательны; вывод типов работает внутри тела, но не в сигнатурах.
* Последнее выражение без `;` - значение блока (как в Ruby и Scala); `return` нужен для раннего выхода. Лишняя `;` даёт ошибку типов, а не молчаливо возвращает `()`.
* Нет перегрузки по типам и значений параметров по умолчанию, нет именованных аргументов. Для нескольких вариантов используют разные имена функций.
* Функции - значения первого класса (можно хранить и передавать), но замыкания и функциональные типы пока не изучаются.
* Порядок объявления не важен, как в Go и Java; в отличие от C, прототипы не нужны.
* Параметры по умолчанию неизменяемы (`fn f(mut x: i32)` разрешает менять локальную копию). Примитивные типы передаются копированием; `String` и коллекции - переносом владения (следующий урок).
* Нельзя вернуть `&str` без времени жизни, если нет ссылки-аргумента, из которой оно берётся; для литерала подходит `&'static str`. `rust-first-steps` объясняет времена жизни; здесь достаточно возвращать `String`.
* `fn main()` - обычная функция без параметров; возвращать `Result` из неё можно, но в курсе это не используется.

## Почему типы обязательны именно в сигнатуре

Это необязательный раздел: для заданий он не нужен.

Внутри тела компилятор выводит типы переменных по тому, как они используются. Но сигнатура функции - это **договор** между автором функции и теми, кто её вызывает. Если бы типы выводились по телу, то любое изменение внутри функции могло бы тихо изменить тип её результата и сломать вызовы в другой части программы. Поэтому Rust требует записать договор явно: компилятор проверяет, что тело его выполняет, а вызывающий код - что он его соблюдает. Обе проверки идут по записанной сигнатуре, и тело при проверке вызовов не читается.

Тот же принцип объясняет, зачем нужен `-> String`, а не `-> &str`. Ссылка - это не текст, а указание на текст, который лежит где-то ещё. Функция, возвращающая ссылку, обязана сказать, на чьи данные она указывает и сколько они проживут. Если в аргументах ссылок нет, указывать не на что, кроме текста, зашитого в программу.
