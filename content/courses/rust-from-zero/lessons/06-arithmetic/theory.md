## Зачем нужна арифметика

Программа чаще всего что-то считает: сумму в чеке, сдачу, среднюю оценку, число часов и минут. Для этого в языке есть знакомые операции над числами: сложение, вычитание, умножение, деление. Их называют **операциями** (или **операторами**), а числа, над которыми они работают, - **операндами**.

## Одна новая идея: тип чисел определяет, как работает деление

| Операция | Знак | Пример | Результат |
|---|---|---|---|
| сложение | `+` | `7 + 2` | `9` |
| вычитание | `-` | `7 - 2` | `5` |
| умножение | `*` | `7 * 2` | `14` |
| деление | `/` | `7 / 2` | `3` |
| остаток от деления | `%` | `7 % 2` | `1` |

Строка с делением выглядит странно: `7 / 2` даёт `3`, а не `3.5`. Это не ошибка, а правило: **при делении двух целых чисел результат тоже целый**, дробная часть отбрасывается. Такое деление называется **целочисленным**. Остаток от него получают операцией `%`: `7 = 3 * 2 + 1`, остаток 1.

Если оба числа дробные (`f64`), деление обычное: `7.0 / 2.0` даёт `3.5`.

Второе важное правило: оба операнда должны быть **одного типа**. `i32 + i64` или целое умножить на дробное Rust не позволяет: нужно явно привести числа к одному типу (как это сделать - в уроке про преобразование типов). Это кажется строгостью, но защищает от скрытых потерь точности.

## Пример 1. Четыре действия и остаток

```rust run
fn main() {
    let price = 120;
    let count = 3;
    let total = price * count;
    let paid = 500;
    let change = paid - total;
    println!("Итого: {total}");
    println!("Сдача: {change}");
    println!("{} + {} = {}", price, count, price + count);
}
```
```output
Итого: 360
Сдача: 140
120 + 3 = 123
```

Разбор:

* `price * count` - умножение двух переменных. Результат сохраняется в новой переменной `total`.
* `paid - total` - вычитание; результат - сдача.
* В последней команде вычисление стоит прямо среди значений после запятой: `price + count`. Внутри самих `{}` вычислять нельзя (там только имя), а вот в списке значений - можно.

## Пример 2. Целочисленное деление и остаток

```rust run
fn main() {
    let total_minutes = 135;
    let hours = total_minutes / 60;
    let minutes = total_minutes % 60;
    println!("{total_minutes} минут = {hours} ч {minutes} мин");
    println!("{}", 7 / 2);
    println!("{}", 7 % 2);
    println!("{}", 7.0 / 2.0);
}
```
```output
135 минут = 2 ч 15 мин
3
1
3.5
```

`135 / 60` даёт `2` (дробная часть отброшена), `135 % 60` даёт `15` (то, что осталось: 135 - 2 * 60). Эта пара пригодится везде, где нужно разложить «всё» на «целые части и остаток»: минуты на часы и минуты, рубли на купюры и сдачу, дни на недели и дни. Последняя команда делит дробные числа и получает `3.5`.

Деление отбрасывает дробную часть, а не округляет: `9 / 10` равно `0`, а не `1`. У отрицательных чисел результат тоже отбрасывается в сторону нуля: `-17 / 5` равно `-3`, а остаток `-17 % 5` равен `-2`.

## Пример 3. Приоритет и скобки

```rust run
fn main() {
    println!("{}", 2 + 3 * 4);
    println!("{}", (2 + 3) * 4);
    println!("{}", 10 - 4 - 3);
    println!("{}", 100 / 5 * 2);
}
```
```output
14
20
3
40
```

Как в математике, `*`, `/` и `%` выполняются раньше `+` и `-`. Операции одного приоритета идут слева направо: `10 - 4 - 3` - это `(10 - 4) - 3 = 3`, а `100 / 5 * 2` - это `(100 / 5) * 2 = 40`. Скобки меняют порядок и делают намерение явным; добавлять их «для читаемости» полезно.

## Пример 4. Составное присваивание

```rust run
fn main() {
    let mut score = 10;
    score += 5;
    println!("{score}");
    score -= 3;
    println!("{score}");
    score *= 2;
    println!("{score}");
    score /= 4;
    println!("{score}");
    score %= 4;
    println!("{score}");
}
```
```output
15
12
24
6
2
```

`score += 5;` - сокращение для `score = score + 5;`: «прибавить 5 к текущему значению». Аналогично `-=`, `*=`, `/=`, `%=`. Переменная должна быть `mut`: ведь её значение меняется. Операторов `++` и `--`, как в C или Java, в Rust нет: пишут `x += 1;`.

**Попробуйте.** Замените в примере 2 `135` на `200` и предскажите часы и минуты. Затем в примере 4 поменяйте местами строки `score += 5;` и `score *= 2;` и посмотрите, как изменится итог.

## Точные правила

* Операции: `+`, `-`, `*`, `/`, `%`. Унарный минус записывает отрицательное число: `-5`.
* **Оба операнда одного типа.** `i32 + i32`, `i64 * i64`, `f64 / f64` допустимы; `i32 + i64`, `i32 * f64` - ошибка компиляции. Числовые литералы (`5`, `2.0`) подстраиваются под другой операнд: `let x: i64 = 10; x + 5` допустимо, потому что `5` становится `i64`.
* **Деление целых** отбрасывает дробную часть (в сторону нуля). `a % b` - остаток, его знак совпадает со знаком `a`: `-17 % 5 = -2`. Всегда верно `a == (a / b) * b + a % b`.
* **Деление дробных** обычное. Деление дробного на ноль не ошибка: результат бесконечность (`inf`) или `NaN`.
* **Деление целого на ноль**: если на ноль делит литерал или переменная, значение которой компилятор знает, программа не соберётся. Если ноль появляется только во время работы (например, из ввода), программа аварийно остановится с сообщением `attempt to divide by zero`. Такая остановка называется **паникой**.
* **Приоритет**: `* / %` выше `+ -`; равные - слева направо; скобки - всегда первыми.
* **Составное присваивание** `+= -= *= /= %=` требует `mut`-переменную; `x op= y` равносильно `x = x op y`.
* **Нет `++` и `--`**: пишут `x += 1` и `x -= 1`.
* **Переполнение.** `i32` вмещает числа до 2 147 483 647. Если результат вычисления выходит за предел, говорят о **переполнении**. Если компилятор видит его заранее, он отвергает программу. Если оно возникает во время работы, поведение зависит от режима сборки: в отладочной сборке программа паникует, а в оптимизированной (как в этом приложении) значение молча «заворачивается» (`2147483647 + 1` даёт `-2147483648`). Поэтому для сумм, которые могут оказаться большими, берут `i64`. Подробно - в [первых шагах](lesson:rust.first-steps.how-rust-runs).
* Результат вычисления можно использовать сразу: `println!("{}", a + b)`, или сохранить в переменную: `let total = a + b;`. Внутри `{}` вычислять нельзя, только подставлять имя.

## Типичные ошибки

**1. Ожидают дробный результат от деления целых.**

```rust
fn main() {
    println!("{}", 7 / 2);
}
```

Эта программа соберётся и напечатает `3`, а не `3.5`: ошибки нет, но результат другой, чем ожидали. Чтобы получить `3.5`, нужны дробные числа: `7.0 / 2.0`. Если исходные числа целые, их сначала приводят к `f64` (урок 9). Правило: деление целых всегда целое.

**2. Смешивают разные типы.**

```rust
fn main() {
    let a: i32 = 5;
    let b: i64 = 10;
    println!("{}", a + b);
}
```

```text
error[E0308]: mismatched types
 --> main.rs:4:24
  |
4 |     println!("{}", a + b);
  |                        ^ expected `i32`, found `i64`

error[E0277]: cannot add `i64` to `i32`
 --> main.rs:4:22
  |
4 |     println!("{}", a + b);
  |                      ^ no implementation for `i32 + i64`
  ...
```

«Ожидался `i32`, найден `i64`» и «нельзя прибавить `i64` к `i32`». Две ошибки об одном и том же. Дальше компилятор перечисляет много текста о том, какие сложения допустимы, но для вас главное - первая строка: типы не совпали. Решение - привести числа к одному типу (урок 9) или сразу объявить их одинаково.

**3. Целое с дробным.**

```rust
fn main() {
    let a = 5;
    let b = 2.5;
    println!("{}", a * b);
}
```

```text
error[E0277]: cannot multiply `{integer}` by `{float}`
 --> main.rs:4:22
  |
4 |     println!("{}", a * b);
  |                      ^ no implementation for `{integer} * {float}`
```

«Нельзя умножить целое на дробное». Достаточно записать `5.0` вместо `5`, если оба числа должны быть дробными.

**4. Деление на ноль.**

```rust
fn main() {
    let a = 10;
    println!("{}", a / 0);
}
```

```text
error: this operation will panic at runtime
 --> main.rs:3:20
  |
3 |     println!("{}", a / 0);
  |                    ^^^^^ attempt to divide `10_i32` by zero
  |
  = note: `#[deny(unconditional_panic)]` on by default
```

Компилятор видит деление на ноль заранее и отвергает программу. Если делитель станет известен только во время работы, программа соберётся, но остановится словами `thread 'main' panicked ... attempt to divide by zero`. Перед делением на значение, которое может оказаться нулём, его проверяют (урок про `if`).

**5. Пишут `x++`.**

```rust
fn main() {
    let mut x = 10;
    x++;
}
```

```text
error: Rust has no postfix increment operator
 --> main.rs:3:6
  |
3 |     x++;
  |      ^^ not a valid postfix operator
  |
help: use `+= 1` instead
```

«В Rust нет постфиксного инкремента». Компилятор сразу называет замену: `x += 1;`.

**6. Забыли `mut` у переменной с `+=`.** `let score = 10; score += 5;` даёт ту же ошибку, что и обычное повторное присваивание (`cannot assign twice to immutable variable`, урок про переменные). Решение то же: `let mut score`.

**7. Пишут `1 000 000` или `1,5`.** Пробелы и запятые внутри числа недопустимы. Для разрядов используйте `_` (`1_000_000`), для дроби - точку (`1.5`).

## Итоги

* Арифметика: `+`, `-`, `*`, `/`, `%`; приоритет как в математике, порядок меняют скобками.
* Деление целых чисел даёт целое (дробная часть отбрасывается), `%` даёт остаток; для обычного деления нужны дробные числа.
* `+=`, `-=`, `*=`, `/=`, `%=` обновляют `mut`-переменную; `++` и `--` в Rust нет.
* Операнды должны быть одного типа: `i32` и `i64` или целое и дробное без явного приведения не смешиваются.
* Деление целого на ноль приводит к ошибке компиляции или к панике; слишком большой результат может «заворачиваться».

Теперь, когда вы умеете считать с числами, пора познакомиться с текстом: [Строки: &str и String](lesson:rust.from-zero.strings).

## Для тех, кто уже программирует

* Нет неявных преобразований между числовыми типами, даже `i32` -> `i64` (расширяющих): нужен `as` или `i64::from(x)` (урок 9). Это отличается от C, Java и JavaScript.
* `/` для целых - деление с отбрасыванием к нулю, как в C, Java и Go; `%` - остаток со знаком делимого (как `%` в Java, не как `%` в Python). Деление `i32::MIN / -1` - паника.
* Целое на ноль - паника `attempt to divide by zero` (`unconditional_panic`-lint для константного случая); дробное на ноль - `inf` или `NaN`, как в IEEE 754.
* Переполнение: в debug-сборке паника, в release-сборке (`-O`, как в приложении) - заворачивание по модулю 2ⁿ. Явные варианты: `checked_add`, `wrapping_add`, `saturating_add`, `overflowing_add`.
* Нет `++`/`--`; `x += 1`. Операции над `mut`-переменными возможны только если объявлено `mut`.
* Приоритеты операций как в C; нет оператора `**`, степень - метод `pow` или `powi` (`powf` для дробной степени).
* Литералы подбирают тип по контексту: в `x + 5` литерал становится типом `x`.

## Почему так строго

Это необязательный раздел: для заданий он не нужен.

Многие языки молча превращают `int` в `double`, а `long` в `int`. Из-за таких преобразований бывали потери данных: большое число становилось неправильным, дробное теряло дробную часть, а программа продолжала работать и выдавала ошибочный результат. В Rust любое преобразование видно в тексте программы: `a as i64`. Читатель сразу видит, где тип меняется, а компилятор не принимает решений за вас.

Целочисленное деление и остаток - две операции, связанные тождеством `a == (a / b) * b + a % b`. Поэтому остаток у отрицательных чисел отрицателен: деление отбрасывает дробную часть в сторону нуля, остаток обязан «дополнить» результат до исходного числа.

Переполнение выбрано зависящим от режима сборки намеренно. В отладочной сборке паника быстро выявляет ошибку при разработке. В оптимизированной сборке проверка каждой операции стоила бы времени, поэтому используется дешёвое заворачивание, которое для процессора - обычное сложение. Если нужно определённое поведение, его выбирают явно: `checked_add` возвращает `Option`, `saturating_add` останавливается на границе, `wrapping_add` заворачивает намеренно.
