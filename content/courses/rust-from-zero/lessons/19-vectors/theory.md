## Зачем нужен вектор

До сих пор одна переменная хранила одно значение. Но настоящие данные - это обычно много значений: оценки группы, цены в чеке, строки входного файла. Заранее неизвестно, сколько их будет, и заводить `score1`, `score2`, `score3` невозможно.

**Вектор** (`Vec`) - это изменяемый список значений **одного типа**, расположенных друг за другом. Он умеет расти: можно добавить элемент в конец. У каждого элемента есть **индекс** - номер позиции, который начинается с нуля: первый элемент имеет индекс 0, второй - 1.

## Одна новая идея: тип `Vec<i32>`

Запись `Vec<i32>` читается «вектор из `i32`»: в угловых скобках указан тип элементов. Создать вектор можно двумя способами:

* `vec![72, 85, 90]` - сразу с элементами; тип `Vec<i32>` компилятор определит сам.
* `Vec::new()` - пустой вектор; тогда тип нужно указать, например `let v: Vec<i32> = Vec::new();`, потому что из пустоты его не вывести.

Как и у всякой переменной, изменяемость задаётся словом `mut`: добавлять и менять элементы можно только у `let mut`.

## Пример 1. Создание, `push`, индекс

```rust run
fn main() {
    let mut scores = vec![72, 85, 90];
    println!("{:?}", scores);
    scores.push(64);
    println!("{:?}, элементов: {}", scores, scores.len());
    println!("первый: {}, последний: {}", scores[0], scores[scores.len() - 1]);
    scores[1] = 88;
    println!("{scores:?}");

    let empty: Vec<i32> = Vec::new();
    println!("{:?} {}", empty, empty.len());
}
```
```output
[72, 85, 90]
[72, 85, 90, 64], элементов: 4
первый: 72, последний: 64
[72, 88, 90, 64]
[] 0
```

* `{:?}` - **отладочный вывод**: для вектора он печатает `[72, 85, 90]`. Обычный `{}` для вектора не работает (см. ошибки ниже). Внутри строки можно писать и `{scores:?}`.
* `push(64)` добавляет элемент в конец; для этого вектор должен быть `mut`.
* `len()` возвращает количество элементов, а последний элемент лежит по индексу `len() - 1`.
* `scores[0]` читает элемент, `scores[1] = 88` записывает новое значение на его место.

**Попробуйте.** Добавьте `scores.push(50);` и выведите `scores.len()`. Затем попробуйте вывести `scores[10]`: что покажет программа?

## Пример 2. Обход, сумма, `sort`, `contains`

```rust run
fn main() {
    let mut prices = vec![40, 15, 30, 15];

    let mut total = 0;
    for p in &prices {
        total += p;
    }
    println!("всего: {total}");
    println!("сумма методом: {}", prices.iter().sum::<i32>());

    let mut expensive = 0;
    for p in &prices {
        if *p > 20 {
            expensive += 1;
        }
    }
    println!("дороже 20: {expensive}");

    for i in 0..prices.len() {
        println!("позиция {i}: {}", prices[i]);
    }

    prices.sort();
    println!("{:?}", prices);
    println!("{} {}", prices.contains(&30), prices.contains(&99));
}
```
```output
всего: 100
сумма методом: 100
дороже 20: 2
позиция 0: 40
позиция 1: 15
позиция 2: 30
позиция 3: 15
[15, 15, 30, 40]
true false
```

* `for p in &prices` перебирает элементы по очереди. Амперсанд значит «смотреть, не забирая»: после цикла вектор остаётся доступным. Переменная `p` - **ссылка** на элемент, поэтому при сравнении пишут `*p > 20` (звёздочка берёт само число). Для сложения и умножения звёздочка не нужна: `total += p` работает.
* `prices.iter().sum::<i32>()` - готовая сумма: `iter()` отдаёт элементы по очереди, `sum` складывает, а `::<i32>` указывает тип результата.
* `for i in 0..prices.len()` перебирает индексы, а не элементы; тогда элемент берут как `prices[i]`. Диапазон `0..n` не включает `n`.
* `prices.sort()` сортирует по возрастанию на месте (нужен `mut`), `contains(&30)` отвечает `true`/`false`, есть ли значение в векторе.

## Пример 3. Вектор в функции

```rust run
fn total(values: &Vec<i32>) -> i32 {
    let mut sum = 0;
    for v in values {
        sum += v;
    }
    sum
}

fn add_bonus(values: &mut Vec<i32>, bonus: i32) {
    for i in 0..values.len() {
        values[i] += bonus;
    }
}

fn main() {
    let mut grades = vec![80, 90, 70];
    println!("сумма: {}", total(&grades));
    add_bonus(&mut grades, 5);
    println!("после бонуса: {:?}, сумма: {}", grades, total(&grades));
    println!("{:?} {:?}", grades.get(1), grades.get(10));
}
```
```output
сумма: 240
после бонуса: [85, 95, 75], сумма: 255
Some(95) None
```

* `values: &Vec<i32>` - функция смотрит на вектор по ссылке и ничего не забирает. Вызывают её с `&grades`, как в уроке про владение. Внутри функции `for v in values` не нуждается в `&`: `values` уже ссылка.
* `values: &mut Vec<i32>` разрешает менять вектор; вызывают с `&mut grades`. Запись `values[i] += bonus` меняет элемент прямо в переданном векторе.
* `grades.get(1)` возвращает `Option`: `Some(95)` если элемент есть и `None` если индекс за границами. Это безопасная альтернатива `grades[10]`, которая не останавливает программу.

## Пример 4. Собираем числа из ввода

Программа читает ввод, поэтому приведены ввод и вывод.

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut numbers: Vec<i32> = Vec::new();
    let mut skipped = 0;
    for line in text.lines() {
        match line.trim().parse::<i32>() {
            Ok(n) => numbers.push(n),
            Err(_) => skipped += 1,
        }
    }
    numbers.sort();
    println!("{:?}", numbers);
    println!("принято: {}, пропущено: {skipped}", numbers.len());
}
```

Ввод:

```text
7
-2
abc
 15 
7
```

Вывод:

```text
[-2, 7, 7, 15]
принято: 4, пропущено: 1
```

Это обычная схема обработки ввода: строки по одной превращаются в числа, верные попадают в вектор через `push`, неверные считаются и пропускаются. После сортировки видно, что дубликат `7` остался: вектор хранит все добавленные значения.

## Точные правила

* `Vec<T>` хранит элементы типа `T`; все элементы одного типа. Размер меняется во время работы.
* `vec![a, b, c]` создаёт вектор с элементами; `Vec::new()` - пустой (тип нужен из аннотации или из последующих `push`).
* Индексы начинаются с 0 и имеют тип `usize` (целое без знака). `v.len()` тоже `usize`. Индекс типа `i32` не принимается: нужен `usize`.
* `v[i]` при `i >= v.len()` останавливает программу паникой `index out of bounds`. `v.get(i)` вместо паники возвращает `None`.
* `push`, `sort`, присваивание `v[i] = ...` требуют `mut`; параметр, который функция меняет, объявляется `&mut Vec<i32>`.
* `for x in &v` даёт ссылки на элементы и оставляет `v` доступным; `for x in v` **забирает** вектор (он перемещается), и после цикла `v` использовать нельзя.
* `x` из `for x in &v` - ссылка на элемент: для сравнения с числом нужен `*x`; в арифметике (`+`, `*`, `+=`) ссылку на число можно использовать напрямую.
* `{:?}` печатает вектор как `[1, 2, 3]`; для строк внутри он добавляет кавычки. Обычный `{}` для `Vec` не определён.
* `v.sort()` сортирует по возрастанию, `v.contains(&x)` проверяет наличие, `v.iter().sum::<i32>()` суммирует; `v.is_empty()` - `true`, если элементов нет.
* Для функций над списком чисел используйте `&Vec<i32>` (читать) и `&mut Vec<i32>` (менять).

**7. Выход за границы.** Программа компилируется, но падает при запуске:

```rust
fn main() {
    let v = vec![1, 2, 3];
    println!("начало");
    println!("{}", v[5]);
}
```

Ввод:

```text

```

Результат работы:

```text
thread 'main' (2037537) panicked at main.rs:4:21:
index out of bounds: the len is 3 but the index is 5
```

Сообщение называет длину вектора (`3`) и запрошенный индекс (`5`). Часть вывода, напечатанная до паники, остаётся. Для индекса, который мог выйти за границы, используйте `v.get(i)` или проверку `i < v.len()`.

## Итоги

* `Vec<i32>` - растущий список значений одного типа; создаётся `vec![...]` или `Vec::new()`.
* `push` добавляет в конец, `len()` считает, `v[i]` читает и пишет по индексу (с нуля, тип `usize`); выход за границы - паника, `get(i)` возвращает `Option`.
* `for x in &v` перебирает элементы по ссылке (сравнивать нужно `*x`); `for x in v` забирает вектор.
* `sort`, `contains`, `iter().sum::<i32>()` покрывают частые задачи; печатать вектор нужно через `{:?}`.
* В функции вектор передают как `&Vec<i32>` или `&mut Vec<i32>`.

Следующий урок: [словари HashMap](lesson:rust.from-zero.hash-maps): значения, к которым обращаются по ключу, а не по номеру.

## Для тех, кто уже программирует

* `Vec<T>` - аналог `ArrayList` / `list` / `[]` в JS / slice в Go, но с одним типом элементов и владением: вектор принадлежит переменной, а `for x in v` передаёт владение циклу.
* Индексация проверяется во время выполнения: `v[i]` за границами - паника (завершение с понятным сообщением), а не неопределённое поведение, как в C/C++. Безопасный доступ - `v.get(i)` с `Option`.
* Индекс - `usize`, неявных преобразований из `i32` нет; приводите явно через `as usize` (урок про преобразования) или храните индексы как `usize`.
* Идиоматичная сигнатура принимает срез `&[i32]` (читать) вместо `&Vec<i32>`; в этом курсе используется `&Vec<i32>`, чтобы не вводить срезы. Они - в `rust-fundamentals`.
* В идиоматичном коде вместо цикла с накоплением часто пишут цепочки итераторов: `v.iter().sum::<i32>()`, а также `map`, `filter`, `collect` с замыканиями. Они в этом курсе отложены (`rust-fundamentals`, `collections-and-iterators`).
* `v.iter()` - ссылки, `v.iter_mut()` - изменяемые ссылки, `v.into_iter()` (и `for x in v`) - владение. Это то же различие, что `&v`, `&mut v` и `v`.
* `Vec::with_capacity(n)` резервирует память заранее; для обычных задач не нужен.

<!-- section: deep-dive -->
## Как устроен вектор в памяти

Это необязательный раздел: для заданий он не нужен.

Переменная типа `Vec<i32>` занимает на стеке три числа: указатель на буфер, **длину** (`len`, сколько элементов лежит сейчас) и **ёмкость** (`capacity`, сколько помещается без перевыделения). Сами элементы лежат подряд в одном блоке памяти в куче - поэтому доступ по индексу быстрый: адрес элемента `i` вычисляется арифметикой.

Когда `push` обнаруживает, что места нет (`len == capacity`), вектор выделяет новый, больший блок (стандартная библиотека увеличивает ёмкость пропорционально, обычно примерно вдвое), переносит туда элементы и освобождает старый блок. Поэтому добавление в конец в среднем дёшево, а вставка в начало дорога: все элементы приходится сдвигать.

Это объясняет и правила владения. Переменная владеет блоком памяти: когда она уходит из области видимости, блок освобождается. Если бы `for x in v` не забирал вектор, а оставлял его доступным, одновременно существовало бы два владельца одного блока - поэтому компилятор считает вектор перемещённым. Ссылка `&v` указывает на тот же вектор, не владея им, и поэтому вектор нельзя расширять, пока ссылка на его элементы жива: после перевыделения ссылка указывала бы в освобождённую память. Эти правила подробно разбираются в `rust-first-steps`.
