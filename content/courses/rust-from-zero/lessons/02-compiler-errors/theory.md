## Зачем уметь читать ошибки

Ошибки в программе бывают у всех, у новичков и у опытных разработчиков. Разница в том, как быстро человек находит причину. Компилятор Rust не просто говорит «не получилось»: он указывает **место** и **вид** ошибки, а часто сам предлагает исправление. Если уметь читать такое сообщение, исправление занимает минуту, а не час.

**Ошибка компиляции** - проблема, которую `rustc` обнаруживает до запуска программы. Пока она не исправлена, исполняемый файл не создаётся и программа не запустится вообще. Это удобно: ошибка не успевает причинить вреда, а вы видите её сразу. Rust проверяет заранее больше, чем большинство языков, поэтому сообщений вы увидите много. Это нормальная часть работы, а не признак того, что вы делаете что-то не так.

## Одна новая идея: сообщение состоит из заголовка, адреса, указателя и подсказки

Типичное сообщение выглядит так:

```text
error[E0423]: cannot find function `println` in this scope
 --> main.rs:3:5
  |
3 |     println("Сумма: 450 руб.");
  |     ^^^^^^^ not found in this scope
  |
  = note: a macro named `println` exists in another namespace
help: use `!` to invoke the macro
  |
3 |     println!("Сумма: 450 руб.");
  |            +
```

В нём четыре части:

1. **Заголовок** `error[E0423]: cannot find function ...`. Слово `error` говорит, что это ошибка. В квадратных скобках - **код ошибки** `E0423`: у каждой ошибки Rust с кодом есть подробное описание в документации, и код хорошо работает как запрос для поиска. После двоеточия - краткая суть: «не найдена функция `println`».
2. **Адрес** `--> main.rs:3:5` - файл, номер строки и номер столбца: ошибка найдена в третьей строке, начиная с пятого символа. Нумерация идёт с единицы.
3. **Указатель** - сама строка кода и значки `^^^^^^^` под тем фрагментом, который не понравился компилятору. Справа от значков - короткая пометка («не найдено в этой области»).
4. **Подсказки** `note` и `help`. `note` - дополнительное пояснение. `help` - совет, и часто в нём показан уже исправленный код: знак `+` под строкой отмечает, что нужно добавить (знак `-` - что убрать).

Читать сообщение нужно в таком порядке: адрес (куда смотреть), указатель (на что именно), заголовок (что не так), `help` (как исправить). Совет `help` стоит прочитать внимательно: он основан на том, что компилятор знает о вашем коде, и верен очень часто, но решение остаётся за вами.

## Пример 1. Читаем и исправляем одну ошибку

Программа с ошибкой:

```rust
fn main() {
    println!("Счёт оплачен");
    println("Спасибо!");
}
```

Сообщение (то самое, что разобрано выше):

```text
error[E0423]: cannot find function `println` in this scope
 --> main.rs:3:5
```

Адрес - строка 3, столбец 5, то есть начало слова `println`. Заголовок: функция с таким именем не найдена. В `help` компилятор показывает, что нужен восклицательный знак. Исправленная программа:

```rust run
fn main() {
    println!("Счёт оплачен");
    println!("Спасибо!");
}
```
```output
Счёт оплачен
Спасибо!
```

## Пример 2. Две ошибки, и сообщения идут не по порядку строк

```rust
fn main() {
    println!("Чек №17");
    println("Хлеб - 45 руб.");
    println!("Молоко - 89 руб.")
    println!("Итого: 134 руб.");
}
```

```text
error: expected `;`, found `println`
 --> main.rs:4:33
  |
4 |     println!("Молоко - 89 руб.")
  |                                 ^ help: add `;` here
5 |     println!("Итого: 134 руб.");
  |     ------- unexpected token

error[E0423]: cannot find function `println` in this scope
 --> main.rs:3:5
  ...

error: aborting due to 2 previous errors
```

Обратите внимание на порядок. Сообщение про строку 4 стоит выше, чем про строку 3. Компилятор работает стадиями: сначала проверяет, правильно ли «написана» программа (знаки, скобки, точки с запятой), потом - существуют ли использованные имена. Ошибки первой стадии показываются раньше. Последняя строка `aborting due to 2 previous errors` («прерываю из-за 2 ошибок») подводит итог: ошибок две.

Первое сообщение: «ожидалась `;`, но встретилось `println`». Стрелка `^` стоит в конце четвёртой строки, и рядом написано `help: add ';' here` («добавьте `;` сюда»). Второе - то же, что в примере 1. После обеих правок программа собирается:

```rust run
fn main() {
    println!("Чек №17");
    println!("Хлеб - 45 руб.");
    println!("Молоко - 89 руб.");
    println!("Итого: 134 руб.");
}
```
```output
Чек №17
Хлеб - 45 руб.
Молоко - 89 руб.
Итого: 134 руб.
```

## Пример 3. Ошибка указана в конце, а причина - в начале

Здесь не закрыта фигурная скобка функции:

```rust
fn main() {
    println!("Чек №17");
    println!("Итого: 134 руб.");
```

```text
error: this file contains an unclosed delimiter
 --> main.rs:3:34
  |
1 | fn main() {
  |           - unclosed delimiter
2 |     println!("Чек №17");
3 |     println!("Итого: 134 руб.");
  |                                 ^
```

«Файл содержит незакрытую скобку». Компилятор дочитал файл до конца и только там понял, что `}` нет. Поэтому `^` стоит в последней строке, а вот пометка `unclosed delimiter` («незакрытый разделитель») стоит у открывающей скобки в первой строке. Rust часто показывает на экране обе точки: и где нашёл проблему, и где она началась. Смотрите на все пометки в сообщении, а не только на строку, названную в адресе.

**Попробуйте.** Возьмите программу из примера 1, замените `println!` в первой команде на `Println!` и прочитайте новое сообщение: найдите заголовок, адрес, указатель и `help`. Затем сделайте две ошибки в разных местах и убедитесь, что компилятор показывает обе.

## Точные правила

* Сообщение `error` означает, что исполняемый файл не создан. Пока в программе есть хотя бы одна ошибка, запуска не будет.
* Сообщение `warning` (предупреждение) не останавливает сборку: программа запустится, но компилятор советует проверить код (например, переменную, которую нигде не используют). С предупреждениями вы встретитесь в уроке про переменные; читать их так же полезно, как ошибки.
* Адрес `main.rs:3:5` - строка и столбец, обе нумерации с единицы. Столбец считает символы (русская буква - один символ).
* Код `E....` не у всех ошибок: простые синтаксические ошибки, как пропущенная `;`, его не имеют, и это нормально.
* Один раз найдя ошибки на какой-то стадии, компилятор нередко останавливается. Поэтому после исправления сообщений может появиться новая порция, относящаяся к следующей стадии. Это не значит, что вы ошиблись при исправлении.
* Одна причина может вызывать несколько сообщений: незакрытая кавычка или скобка «съедает» код дальше. Исправляйте **по одной**, начиная с первой, и запускайте заново.
* Номер строки в сообщении - место, где компилятор **понял**, что что-то не так. Причина может быть в строке выше или в начале блока (пример 3). Смотрите на указанную строку и предыдущую.
* Строки `help` и подсказки в виде `+`/`-` - предложения. Применяйте их, поняв, что они значат.
* Текст сообщений - на английском, но слова повторяются часто: `expected` (ожидалось), `found` (найдено), `cannot find` (не удаётся найти), `unclosed` (не закрыто), `mismatched types` (несовпадающие типы). Их можно выучить.

## Типичные ошибки

**1. Исправляют сразу все ошибки, не перечитывая сообщения.** После первой правки сообщения меняются: часть исчезает, появляются новые. Правьте одну ошибку, запускайте, читайте снова.

**2. Читают сообщение сверху, а начинать нужно с первого `error`.** Если сообщений много, листайте к началу: главное чаще всего там. Строки внизу (`aborting due to ...`, `For more information about this error ...`) - итог, исправлять там нечего.

**3. Правят не ту строку.** Номер строки в адресе - это место, где компилятор споткнулся. Если в этой строке всё верно, проверьте строку выше (нет ли там пропущенной `;` или незакрытой скобки).

**4. Исправляют текст, а не код.** Сообщение называет конструкцию, например `println`, а не фразу в кавычках. Менять нужно имя, знак или скобку; текст, который программа печатает, трогать не нужно.

**5. Копируют `help` не читая.** Совет компилятора верен часто, но не всегда. Сравните предложенный код с тем, что вы хотели написать.

Если сообщение непонятно: прочитайте заголовок слово за словом, найдите код `E....` в поиске, посмотрите на подчёркнутое `^^^` и уберите из программы всё, что не относится к ошибке, оставив самый короткий пример, где она воспроизводится.

## Итоги

* Сообщение `rustc` состоит из заголовка (`error[E0423]: ...`), адреса (`--> main.rs:3:5`), указателя (`^^^`) и подсказок `note`/`help`.
* Адрес даёт файл, строку и столбец; нумерация с единицы. Причина ошибки может находиться выше указанной строки.
* Ошибка мешает сборке; предупреждение - нет.
* Ошибки исправляют по одной, начиная с первой, запуская программу после каждой правки: часть сообщений исчезает вместе с причиной.

Теперь, когда сообщения не страшны, можно учиться выводить текст по-разному: [Вывод: print!, println! и подстановки](lesson:rust.from-zero.output).

## Для тех, кто уже программирует

* Сообщения `rustc` намного подробнее, чем у `gcc` или `javac`: с метками на коде, пометками, причинами и готовыми исправлениями (`help`). Часто достаточно применить `help`, но прочтите, что именно меняется.
* Код `E....` можно расшифровать командой `rustc --explain E0423` или найти в Rust Compiler Error Index; описания содержат примеры.
* Ошибки идут по стадиям (разбор текста, имена, типы, заимствования): типичная картина - исправили синтаксис, и появилась порция ошибок имён, а потом типов и владения.
* Lint-проверки (`warning`, а часть - `deny` по умолчанию, например переполняющий литерал) встроены в компилятор, а не в отдельный линтер. Подробнее `cargo clippy` - в курсе профессионального уровня.
* Паника во время работы (`thread 'main' panicked at ...`) - другое дело: программа собралась, но упала при запуске. Такие сообщения вы разберёте в уроках 8 и 9.

## Откуда берутся подсказки

Это необязательный раздел: для заданий он не нужен.

Подсказки `help` формирует тот же компилятор, который проверяет программу. Когда он не находит имя, то сравнивает его с известными ему именами по похожести написания (поэтому для `Println` предлагается `println`), а для случаев вроде пропущенного `!` в нём есть отдельные правила. Поэтому совет бывает точным, а бывает и мимо: компилятор не знает, что вы хотели.

Каждое сообщение о проблеме - структура данных с основной меткой (она подчёркнута `^^^`), дополнительными метками (`-----`, как на строке `unexpected token`) и набором предложений по исправлению. Приложения вроде редакторов кода читают эту же структуру, поэтому подчёркивание и всплывающие подсказки в редакторе устроены так же, как сообщение в терминале.
