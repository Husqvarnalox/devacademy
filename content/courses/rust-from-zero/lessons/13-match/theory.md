## Зачем нужен ещё один способ выбирать

Цепочка `else if` хорошо работает, когда вариантов два-три. Но представьте, что нужно по номеру месяца назвать время года или по номеру дня недели - его название. Придётся писать двенадцать или семь проверок `month == 1`, `month == 2` и так далее. Для таких случаев в Rust есть оператор `match` («сопоставить»).

## Одна новая идея: сравнить значение с образцами по очереди

```rust
match значение {
    образец1 => результат1,
    образец2 => результат2,
    _ => результат_для_всех_остальных,
}
```

* `match` берёт значение и сравнивает его с **образцами** сверху вниз. Образец - это то, на что значение должно быть похоже: например, число `3` или диапазон `1..=5`.
* Каждая строка вида `образец => результат` называется **веткой** (по-английски *arm*). После `=>` стоит результат ветки; ветки разделяются запятыми.
* Выполняется **первая** подошедшая ветка, остальные пропускаются.
* Образец `_` («что угодно») подходит к любому значению. Его ставят последним: он ловит все случаи, которые не перечислены выше.

Как и `if`, `match` является выражением: его результат можно положить в переменную.

<!-- section: examples -->
## Пример 1. Число и ветка `_`

```rust run
fn main() {
    let day = 3;
    let name = match day {
        1 => "понедельник",
        2 => "вторник",
        3 => "среда",
        4 => "четверг",
        5 => "пятница",
        6 => "суббота",
        7 => "воскресенье",
        _ => "такого дня нет",
    };
    println!("День {day}: {name}");
}
```
```output
День 3: среда
```

* `let name = match day { ... };` - результат подошедшей ветки становится значением переменной `name`. Точка с запятой стоит один раз, после закрывающей скобки.
* Для `day = 3` подходит ветка `3 => "среда"`.
* Ветка `_` отвечает за все числа, которых нет в списке: 0, 8, -5. Без неё программа не скомпилируется (см. ошибки ниже).

**Попробуйте.** Поставьте `day = 9` и посмотрите, какая ветка сработает. Затем уберите ветку `7` и проверьте, что для 7 тоже будет «такого дня нет».

## Пример 2. Диапазоны и несколько вариантов

```rust run
fn main() {
    let month = 7;
    let season = match month {
        12 | 1 | 2 => "зима",
        3..=5 => "весна",
        6..=8 => "лето",
        9..=11 => "осень",
        _ => "неверный номер месяца",
    };
    println!("Месяц {month}: {season}");

    let score = 82;
    match score {
        90..=100 => println!("отлично"),
        75..=89 => println!("хорошо"),
        60..=74 => println!("удовлетворительно"),
        0..=59 => println!("неудовлетворительно"),
        _ => println!("ошибка: балл вне диапазона"),
    }
}
```
```output
Месяц 7: лето
хорошо
```

* `3..=5` - образец-диапазон: подходит число от 3 до 5 включительно (знак `=` значит «включая конец»). Он заменяет условие `m >= 3 && m <= 5`.
* `12 | 1 | 2` - образец «или»: подходит любое из перечисленных значений. Это способ дать несколько значений одной ветке.
* Во втором фрагменте результатом веток служат команды `println!`. Здесь `match` стоит как отдельная команда, поэтому после его `}` точка с запятой не нужна.
* Диапазоны не должны пересекаться; если пересекутся, победит первая ветка сверху.

## Пример 3. Текст и ввод

Пользователь вводит команду, программа реагирует. Программа читает ввод, поэтому приведены ввод и вывод.

```rust
fn main() {
    let text = std::io::read_to_string(std::io::stdin()).unwrap();
    let mut lines = text.lines();
    let command = lines.next().unwrap().trim();

    match command {
        "старт" => println!("Запускаем"),
        "стоп" => println!("Останавливаем"),
        "пауза" | "ожидание" => println!("Ждём"),
        _ => println!("Неизвестная команда: {command}"),
    }
}
```

Ввод:

```text
ожидание
```

Вывод:

```text
Ждём
```

* `trim()` возвращает `&str`, то есть «текст в кавычках» того же вида, что и литералы `"старт"`. Поэтому его можно сопоставлять с такими литералами.
* `"пауза" | "ожидание"` - две команды с одним действием.
* В ветке `_` слово `command` можно использовать, как обычную переменную: вывод показывает, что именно ввёл пользователь.

## Пример 4. Условие в ветке и символы

```rust run
fn main() {
    let balance = -40;
    match balance {
        0 => println!("Счёт пуст"),
        n if n < 0 => println!("Долг: {} руб.", -n),
        n if n < 1000 => println!("На счёте мало: {n} руб."),
        n => println!("На счёте {n} руб."),
    }

    let letter = 'о';
    let kind = match letter {
        'а' | 'е' | 'ё' | 'и' | 'о' | 'у' | 'ы' | 'э' | 'ю' | 'я' => "гласная",
        'a'..='z' | 'а'..='я' => "согласная или другая буква",
        _ => "не строчная буква",
    };
    println!("{letter}: {kind}");
}
```
```output
Долг: 40 руб.
о: гласная
```

* `n if n < 0 => ...` - образец-имя `n` подходит к любому значению и сохраняет его под именем `n`, а условие после `if` («охрана», *guard*) дополнительно проверяется. Если оно ложно, `match` переходит к следующей ветке.
* Последняя ветка `n =>` ловит все оставшиеся значения (в данном случае от 1000 и выше) и тоже заменяет `_`; разница лишь в том, что значение доступно по имени.
* Символы (`char`) сопоставляют так же, как числа: `'а'..='я'` - диапазон по таблице Unicode. Первая ветка перечисляет гласные через `|`.
* Порядок веток важен: частные случаи (`0`, отрицательные) стоят выше общих.

<!-- section: precise -->
## Точные правила

* Форма: `match значение { образец => выражение, ... }`. Запятая после ветки нужна, кроме веток с блоком `{ ... }` (там её можно опустить).
* **Все возможные значения должны быть учтены** (*исчерпываемость*). Если компилятор не может доказать это, он отказывается собирать программу. Обычно для этого достаточно ветки `_`.
* Ветки проверяются сверху вниз; побеждает первая подошедшая. Ветка, которая не может сработать, потому что выше стоит более общая, даёт предупреждение «unreachable pattern».
* Образцы: литерал (`3`, `"старт"`, `'а'`), диапазон `a..=b` (оба конца входят), несколько образцов через `|`, `_`, имя (оно **вводит новую переменную**, а не сравнивает с существующей), имя с условием `имя if условие`.
* Диапазон вида `1..5` (без `=`) в образцах тоже разрешён и не включает 5, но в курсе мы пишем только `..=`, чтобы граница читалась однозначно.
* Условие `if` в ветке компилятор не анализирует: ветки с условиями не считаются полным покрытием, ему нужна ветка без условия (`_` или имя).
* Результаты всех веток, если match используется как значение, должны быть **одного типа**.
* Сопоставлять текст можно с `&str`. Для `String` сначала берут `&str` (метод `as_str()`; подробнее позже).

## Типичные ошибки

**1. Не все значения учтены.**

```rust
fn main() {
    let n = 3;
    let word = match n {
        1 => "один",
        2 => "два",
        3 => "три",
    };
    println!("{word}");
}
```

```text
error[E0004]: non-exhaustive patterns: `i32::MIN..=0_i32` and `4_i32..=i32::MAX` not covered
 --> main.rs:3:22
  |
3 |     let word = match n {
  |                      ^ patterns `i32::MIN..=0_i32` and `4_i32..=i32::MAX` not covered
  |
  = note: the matched value is of type `i32`
help: ensure that all possible cases are being handled by adding a match arm with a wildcard pattern, a match arm with multiple or-patterns as shown, or multiple match arms
  |
6 ~         3 => "три",
7 ~         i32::MIN..=0_i32 | 4_i32..=i32::MAX => todo!(),
  |
```

Компилятор называет значения, которые остались без ветки, и сам предлагает добавить `i32::MIN..=0_i32` или `_`. Самый простой ответ - ветка `_ => ...`.

**2. Ветки с условием не считаются покрытием.**

```rust
fn main() {
    let n = 5;
    let sign = match n {
        x if x < 0 => "минус",
        x if x >= 0 => "плюс",
    };
    println!("{sign}");
}
```

```text
error[E0004]: non-exhaustive patterns: `i32::MIN..=i32::MAX` not covered
 --> main.rs:3:22
  |
3 |     let sign = match n {
  |                      ^ pattern `i32::MIN..=i32::MAX` not covered
  |
  = note: the matched value is of type `i32`
  = note: match arms with guards don't count towards exhaustivity
help: ensure that all possible cases are being handled by adding a match arm with a wildcard pattern or an explicit pattern as shown
  |
5 ~         x if x >= 0 => "плюс",
6 ~         i32::MIN..=i32::MAX => todo!(),
  |
```

Нам очевидно, что `x < 0` и `x >= 0` вместе покрывают все числа, но компилятор условия в `if` не разбирает. Замените вторую ветку на `_ =>` или `x =>`.

**3. Сопоставление `String` с текстом в кавычках.**

```rust
fn main() {
    let command = String::from("стоп");
    match command {
        "старт" => println!("Запускаем"),
        "стоп" => println!("Останавливаем"),
        _ => println!("Неизвестно"),
    }
}
```

```text
error[E0308]: mismatched types
 --> main.rs:4:9
  |
3 |     match command {
  |           ------- this expression has type `String`
4 |         "старт" => println!("Запускаем"),
  |         ^^^^^^^ expected `String`, found `&str`
  |
help: consider converting the `String` to a `&str` using `.as_str()`
  |
3 |     match command.as_str() {
  |                  +++++++++

error[E0308]: mismatched types
 --> main.rs:5:9
  |
3 |     match command {
  |           ------- this expression has type `String`
4 |         "старт" => println!("Запускаем"),
5 |         "стоп" => println!("Останавливаем"),
  |         ^^^^^^ expected `String`, found `&str`
  |
help: consider converting the `String` to a `&str` using `.as_str()`
  |
3 |     match command.as_str() {
  |                  +++++++++
```

Образец `"старт"` имеет тип `&str`, а `command` - это `String`. Сопоставить их напрямую нельзя. Сделайте из `String` вид текста: `match command.as_str() { ... }`, либо работайте с результатом `trim()`, который уже `&str`.

**4. Стрелка `->` вместо `=>`.**

```rust
fn main() {
    let n = 2;
    match n {
        1 -> println!("один"),
        _ => println!("другое"),
    }
}
```

```text
error: expected one of `...`, `..=`, `..`, `=>`, `if`, or `|`, found `->`
 --> main.rs:4:11
  |
4 |         1 -> println!("один"),
  |           ^^ expected one of `...`, `..=`, `..`, `=>`, `if`, or `|`
  |
help: use a fat arrow to start a match arm
  |
4 -         1 -> println!("один"),
4 +         1 => println!("один"),
  |
```

В ветках `match` пишут `=>`: «образец => результат».

**5. Результаты веток разных типов.**

```rust
fn main() {
    let n = 2;
    let result = match n {
        1 => "один",
        _ => 0,
    };
    println!("{result}");
}
```

```text
error[E0308]: `match` arms have incompatible types
 --> main.rs:5:14
  |
3 |       let result = match n {
  |  __________________-
4 | |         1 => "один",
  | |              ------ this is found to be of type `&str`
5 | |         _ => 0,
  | |              ^ expected `&str`, found integer
6 | |     };
  | |_____- `match` arms have incompatible types
```

Если `match` стоит справа от `let`, то все его ветки обязаны давать значения одного типа, как у `if`.

**6. Общая ветка выше частных.**

```rust
fn main() {
    let n = 2;
    match n {
        _ => println!("что угодно"),
        1 => println!("один"),
    }
}
```

```text
warning: unreachable pattern
 --> main.rs:5:9
  |
4 |         _ => println!("что угодно"),
  |         - matches any value
5 |         1 => println!("один"),
  |         ^ no value can reach this
  |
  = note: `#[warn(unreachable_patterns)]` (part of `#[warn(unused)]`) on by default
```

Ветка `_` подходит всегда, поэтому ветка `1 => ...` не может сработать. Компилятор предупреждает об этом, но программу собирает.

**7. Имя переменной в образце.**

```rust
fn main() {
    let limit = 10;
    let n = 3;
    let answer = match n {
        limit => "равно лимиту",
        _ => "не равно лимиту",
    };
    println!("{answer}");
}
```

```text
warning: unreachable pattern
 --> main.rs:6:9
  |
5 |         limit => "равно лимиту",
  |         ----- matches any value
6 |         _ => "не равно лимиту",
  |         ^ no value can reach this
  |
note: there is a binding of the same name; if you meant to pattern match against the value of that binding, that is a feature of constants that is not available for `let` bindings
 --> main.rs:2:9
  |
2 |     let limit = 10;
  |         ^^^^^
  = note: `#[warn(unreachable_patterns)]` (part of `#[warn(unused)]`) on by default

warning: unused variable: `limit`
 --> main.rs:2:9
  |
2 |     let limit = 10;
  |         ^^^^^ help: if this is intentional, prefix it with an underscore: `_limit`
  |
  = note: `#[warn(unused_variables)]` (part of `#[warn(unused)]`) on by default

warning: unused variable: `limit`

  |
5 |         limit => "равно лимиту",
  |         ^^^^^ help: if this is intentional, prefix it with an underscore: `_limit`
```

Эта программа напечатает «равно лимиту», хотя `n` равно 3, а `limit` равно 10. Имя `limit` в образце - это **новая** переменная, которая принимает любое значение и затеняет внешнюю. Предупреждения компилятора подсказывают, что ветка `_` недостижима. Сравнить значение с переменной можно условием: `n if n == limit => ...`, а в простых случаях - обычным `if`.

<!-- section: summary -->
## Итоги

* `match значение { образец => результат, ... }` выбирает первую подошедшую ветку и тоже является выражением.
* Образцы: литералы, диапазоны `a..=b`, несколько вариантов через `|`, `_` для всех остальных и имя, к которому можно добавить условие `if`.
* Компилятор требует учесть все возможные значения; обычно для этого ставят в конце ветку `_`.
* Результаты веток должны иметь один тип, а `String` перед сопоставлением с текстом нужно превратить в `&str`.
* Имя в образце не сравнивает, а создаёт новую переменную.

Следующий урок: [циклы while и loop](lesson:rust.from-zero.while-loop), с которых начнётся повторение действий.

<!-- section: programmer -->
## Для тех, кто уже программирует

* `match` похож на `switch`, но: нет «проваливания» между ветками, не нужен `break`, ветки - выражения, результат можно присвоить.
* Исчерпываемость проверяется компилятором. Забытый случай - ошибка компиляции `E0004`, а не поведение по умолчанию. Это главная причина, почему в Rust обычно не нужны «значения по умолчанию», которые прячут ошибки.
* Образцы богаче, чем в `switch`: диапазоны `1..=5`, альтернативы `|`, привязка значения к имени, охрана `if`. Позже появятся образцы для кортежей, структур и перечислений.
* Образец-имя вводит новую переменную. Сравнение с существующей переменной через образец невозможно: используйте охрану.
* Для `String` нужно `.as_str()`: образцы-литералы имеют тип `&str`.
* Охрана `if` исключается из анализа исчерпываемости: компилятор требует ветку без охраны.
* Диапазон `a..b` в образце допустим (стабилен с Rust 1.80) и исключает правый конец, `a..=b` включает.

<!-- section: deep-dive -->
## Исчерпываемость как проверка при сборке

Это необязательный раздел: для заданий он не нужен.

Идея в том, что компилятор строит для значения множество «всех возможных вариантов» и проверяет, что образцы вместе покрывают его целиком. Для `i32` это четыре миллиарда значений, но проверка не перебирает их: диапазоны `i32::MIN..=0` и `1..=i32::MAX` складываются в целый тип за константное время.

Выгода проявится позже, когда вы встретите перечисления с несколькими вариантами. Если в перечисление добавят новый вариант, все `match` без ветки `_` перестанут собираться - и компилятор сам укажет места, которые нужно дополнить. Для этого `_` стоит использовать осмотрительно: «ловить всё остальное» там, где вы хотите, чтобы новые варианты требовали решения, значит терять эту защиту.
