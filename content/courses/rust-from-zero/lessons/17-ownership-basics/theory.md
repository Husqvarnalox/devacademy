## Зачем в Rust правила о владении

Каждое значение в памяти нужно когда-то освободить. В одних языках за этим следит сборщик мусора - фоновая программа, которая ищет ненужные данные. В других программист освобождает память вручную и иногда ошибается: освобождает дважды или продолжает пользоваться уже освобождённым. Rust выбрал третий путь: у каждого значения есть **один владелец** - переменная, за которой это значение закреплено. Когда владелец исчезает (кончается его блок), значение освобождается автоматически, и компилятор заранее проверяет, что никто не пользуется данными после этого.

Для вас сейчас важны не детали, а три следствия, которые видны в обычных программах.

## Одна новая идея: передача в функцию может «забрать» значение

* **Числа, `bool` и `char` копируются.** Передали число в функцию - у вас осталось своё, функция получила копию.
* **`String` перемещается.** Строка хранит текст отдельно в памяти и принадлежит одной переменной. Передав её в функцию «по значению», вы отдаёте владение: у вас её больше нет, использовать переменную нельзя.
* **Чтобы просто показать значение, передают ссылку.** Ссылка `&` - это «пропуск для просмотра»: функция может прочитать данные, но не владеет ими. Ссылка `&mut` позволяет ещё и изменять.

Полная картина (три правила владения, когда копируются другие типы, почему нельзя иметь две изменяющие ссылки одновременно) - в курсе [Rust: первые шаги](lesson:rust.first-steps.ownership-moves-and-borrowing). Здесь вы узнаете достаточно, чтобы читать сообщения компилятора и писать функции над текстом и числами.

## Пример 1. Копирование и перемещение

```rust run
fn main() {
    let a = 5;
    let b = a;
    println!("{a} {b}");

    let s1 = String::from("привет");
    let s2 = s1;
    println!("{s2}");
}
```
```output
5 5
привет
```

* `let b = a;` копирует число: обе переменные работают.
* `let s2 = s1;` **перемещает** строку: после этой строки пользоваться `s1` нельзя, остаётся `s2`. Попытка напечатать `s1` - ошибка компиляции (ниже).

## Пример 2. Ссылка `&`: функция только читает

```rust run
fn word_length(text: &str) -> usize {
    text.chars().count()
}

fn main() {
    let name = String::from("Мария");
    let n = word_length(&name);
    println!("{name} - {n} букв");
    println!("{}", word_length("кот"));
}
```
```output
Мария - 5 букв
3
```

* Параметр `text: &str` значит: «функция читает текст, но не забирает его». Поэтому в `main` переменная `name` после вызова остаётся нашей и печатается.
* При вызове перед аргументом пишут `&`: `word_length(&name)`. Это значит «одолжить `name` на время вызова». Компилятор сам превращает ссылку на `String` в `&str`, поэтому одна функция принимает и `String`, и литерал.
* `"кот"` - это уже `&str`, `&` не нужен.

Принимайте `&str`, если функции нужно лишь прочитать текст: так она работает и с литералами, и со строками.

## Пример 3. Ссылка `&mut`: функция меняет значение

```rust run
fn add_greeting(text: &mut String) {
    text.push_str(", добро пожаловать!");
}

fn double_in_place(x: &mut i32) {
    *x *= 2;
}

fn main() {
    let mut message = String::from("Привет");
    add_greeting(&mut message);
    println!("{message}");

    let mut count = 21;
    double_in_place(&mut count);
    println!("{count}");
}
```
```output
Привет, добро пожаловать!
42
```

* Чтобы функция изменила строку, она принимает `&mut String`, а вызывающий пишет `&mut message`. Переменная должна быть объявлена `let mut`.
* Для числа записывают `&mut i32`. Внутри функции ссылка - это не само число, а «адрес» числа; чтобы поработать со значением по ссылке, ставят звёздочку: `*x *= 2` значит «значение, на которое указывает x, умножить на 2». Для методов вроде `push_str` звёздочка не нужна: компилятор добавляет её сам.
* Все три слова на месте вызова - `&mut`, `mut` у переменной и `&mut` в параметре - согласованы: изменения видны в `main` после вызова.

## Пример 4. `clone()`: честная копия

```rust run
fn print_and_forget(text: String) {
    println!("получено: {text}");
}

fn main() {
    let draft = String::from("черновик");
    let copy = draft.clone();
    print_and_forget(copy);
    println!("у меня осталось: {draft}");
}
```
```output
получено: черновик
у меня осталось: черновик
```

`draft.clone()` создаёт независимую копию текста. Копию отдали функции (она её «съела»), а оригинал остался у нас. Копирование настоящее: оно занимает память и время, пропорциональные размеру текста. Для коротких строк это ничего не стоит, но вставлять `.clone()` везде, лишь бы убрать ошибку компилятора, - дурная привычка. Сначала подумайте, нельзя ли передать ссылку.

**Попробуйте.** Уберите `.clone()` и передайте `draft` напрямую: что скажет компилятор? Затем замените параметр функции на `&str` и вызывайте её как `print_and_forget(&draft)`.

## Точные правила

* У каждого значения один владелец (переменная). Когда владелец выходит из области видимости, значение освобождается.
* `let b = a;` и передача аргумента **копируют** значения простых типов (`i32`, `f64`, `bool`, `char`) и **перемещают** значения `String`, `Vec` и других типов с собственной памятью. После перемещения исходная переменная недоступна.
* `&значение` - общая (только для чтения) ссылка; `&mut значение` - изменяющая ссылка. Для `&mut` переменная должна быть объявлена `mut`.
* Одновременно допустимо либо любое число общих ссылок, либо одна изменяющая (подробнее - в `rust-first-steps`). Поэтому нельзя, пока существует `&mut`, читать то же значение другим путём.
* Функция принимает ссылку, если ей нужно прочитать или изменить значение, а владеть им не нужно. Для текста выбирайте `&str`, для изменяемого текста - `&mut String`.
* `&String` автоматически превращается в `&str` при вызове функции.
* Чтобы изменить число по `&mut i32`, пользуйтесь `*`: `*x += 1`.
* `.clone()` создаёт полную независимую копию. Это явный и дорогой шаг, поэтому он всегда виден в коде.
* Функция может вернуть владение: `fn f(s: String) -> String`. Но обычно ссылка проще.

## Типичные ошибки

**1. Использование значения после перемещения.**

```rust
fn print_and_forget(text: String) {
    println!("получено: {text}");
}

fn main() {
    let name = String::from("Анна");
    print_and_forget(name);
    println!("{name}");
}
```

```text
error[E0382]: borrow of moved value: `name`
 --> main.rs:8:16
  |
6 |     let name = String::from("Анна");
  |         ---- move occurs because `name` has type `String`, which does not implement the `Copy` trait
7 |     print_and_forget(name);
  |                      ---- value moved here
8 |     println!("{name}");
  |                ^^^^ value borrowed here after move
  |
note: consider changing this parameter type in function `print_and_forget` to borrow instead if owning the value isn't necessary
 --> main.rs:1:27
  |
1 | fn print_and_forget(text: String) {
  |    ----------------       ^^^^^^ this parameter takes ownership of the value
  |    |
  |    in this function
help: consider cloning the value if the performance cost is acceptable
  |
7 |     print_and_forget(name.clone());
  |                          ++++++++
```

Это самое известное сообщение Rust. Переменная `name` была передана в функцию, которая её забрала; печатать её после этого нельзя. Компилятор называет два способа исправить: принять в функции ссылку (`&str`, вызов `print_and_forget(&name)`) или передать копию (`name.clone()`).

**2. Забыли `&` при вызове.**

```rust
fn word_length(text: &str) -> usize {
    text.chars().count()
}

fn main() {
    let name = String::from("Анна");
    println!("{}", word_length(name));
}
```

```text
error[E0308]: mismatched types
 --> main.rs:7:32
  |
7 |     println!("{}", word_length(name));
  |                    ----------- ^^^^ expected `&str`, found `String`
  |                    |
  |                    arguments to this function are incorrect
  |
note: function defined here
 --> main.rs:1:4
  |
1 | fn word_length(text: &str) -> usize {
  |    ^^^^^^^^^^^ ----------
help: consider borrowing here
  |
7 |     println!("{}", word_length(&name));
  |                                +
```

Функция ожидает ссылку `&str`, а передана сама `String`. Компилятор предлагает добавить `&`.

**3. `&mut` для переменной без `mut`.**

```rust
fn add_mark(text: &mut String) {
    text.push_str("!");
}

fn main() {
    let message = String::from("Привет");
    add_mark(&mut message);
    println!("{message}");
}
```

```text
error[E0596]: cannot borrow `message` as mutable, as it is not declared as mutable
 --> main.rs:7:14
  |
7 |     add_mark(&mut message);
  |              ^^^^^^^^^^^^ cannot borrow as mutable
  |
help: consider changing this to be mutable
  |
6 |     let mut message = String::from("Привет");
  |         +++
```

Чтобы дать изменяющую ссылку, переменную нужно объявить `let mut`.

**4. Передали `&`, а функция ждёт `&mut`.**

```rust
fn add_mark(text: &mut String) {
    text.push_str("!");
}

fn main() {
    let mut message = String::from("Привет");
    add_mark(&message);
    println!("{message}");
}
```

```text
error[E0308]: mismatched types
 --> main.rs:7:14
  |
7 |     add_mark(&message);
  |     -------- ^^^^^^^^ types differ in mutability
  |     |
  |     arguments to this function are incorrect
  |
  = note: expected mutable reference `&mut String`
                     found reference `&String`
note: function defined here
 --> main.rs:1:4
  |
1 | fn add_mark(text: &mut String) {
  |    ^^^^^^^^ -----------------
```

Ссылка «только для чтения» и ссылка «для изменения» - разные типы. На вызове нужно написать `&mut message`.

**5. Меняем через ссылку только для чтения.**

```rust
fn add_mark(text: &String) {
    text.push_str("!");
}

fn main() {
    let message = String::from("Привет");
    add_mark(&message);
}
```

```text
error[E0596]: cannot borrow `*text` as mutable, as it is behind a `&` reference
 --> main.rs:2:5
  |
2 |     text.push_str("!");
  |     ^^^^ `text` is a `&` reference, so it cannot be borrowed as mutable
  |
help: consider changing this to be a mutable reference
  |
1 | fn add_mark(text: &mut String) {
  |                    +++
```

Параметр `&String` не разрешает менять строку. Если функция должна менять, тип параметра - `&mut String`.

**6. Забыли звёздочку.**

```rust
fn bump(x: &mut i32) {
    x += 1;
}

fn main() {
    let mut n = 1;
    bump(&mut n);
    println!("{n}");
}
```

```text
error[E0368]: binary assignment operation `+=` cannot be applied to type `&mut i32`
 --> main.rs:2:5
  |
2 |     x += 1;
  |     -^^^^^
  |     |
  |     cannot use `+=` on type `&mut i32`
  |
help: `+=` can be used on `i32` if you dereference the left-hand side
  |
2 |     *x += 1;
  |     +
```

`x` - ссылка, а не число. Чтобы изменить число, на которое она указывает, пишут `*x += 1`.

**7. `.clone()` ради тишины компилятора.** Если вы везде добавляете `.clone()`, программа компилируется, но каждая копия стоит памяти и времени. Копия нужна, когда вам действительно нужны два независимых значения. Если нужно только прочитать - передавайте `&`.

<!-- section: summary -->
## Итоги

* У каждого значения один владелец. `String` при передаче по значению **перемещается** и после этого недоступна; числа, `bool` и `char` копируются.
* `&` даёт функции право читать, `&mut` - читать и менять; для `&mut` переменная должна быть `let mut`, а на вызове пишется `&mut`.
* Тексты принимайте как `&str`, изменяемые строки - как `&mut String`, числа по ссылке меняйте через `*x`.
* `.clone()` делает честную независимую копию; пользуйтесь им осознанно.
* Ошибка `borrow of moved value` означает: значение уже отдали, используйте ссылку или копию.

## Для тех, кто уже программирует

* Это главное отличие Rust. Нет сборщика мусора и нет ручного `free`: деструктор вызывается компилятором в конце области видимости владельца (RAII, как в C++), а доступ после перемещения запрещён статически.
* Перемещение (`let b = a` для `String`) - поведение **по умолчанию**; в C++ оно запрашивается явно через `std::move`. Типы с копированием (`Copy`) - числа, `bool`, `char`, кортежи из них; `String` и `Vec` копируются явно через `clone()`.
* `&T` и `&mut T` - ссылки с проверкой во время компиляции (не указатели с неопределённым поведением). Правило «много читателей или один писатель» исключает гонки данных и недействительные итераторы.
* Для read-only параметров принято `&str` (а не `&String`) и `&[T]` (а не `&Vec<T>`); в этом курсе для векторов используется `&Vec<i32>`, срезы - в `rust-fundamentals`.
* Разыменование `*x` нужно для скаляров по `&mut`; для вызова методов компилятор делает это автоматически («auto-deref»).
* Время жизни ссылки не может превышать время жизни владельца: ссылку на локальную переменную нельзя вернуть из функции. Это тема `rust-first-steps` и `rust-fundamentals`.
* `clone()` - не сбой дизайна, а знак: «здесь есть копия, и она стоит ресурсов». Для `Rc`/`Arc` `clone()` дёшев (счётчик ссылок).

## Что скрывается за «перемещением»

Это необязательный раздел: для заданий он не нужен.

`String` - это небольшая структура на стеке (указатель на текст, длина, ёмкость), а сами символы лежат в куче. Перемещение копирует только эту структуру из трёх чисел, а не текст, поэтому оно дёшево. Если бы разрешалось пользоваться обеими переменными после `let s2 = s1;`, обе указывали бы на один и тот же текст и при выходе из области видимости обе попытались бы его освободить: двойное освобождение, классическая ошибка в C. Rust запрещает обращаться к старой переменной, и проблема исчезает без накладных расходов во время работы программы.

У чисел структуры и кучи нет: копия `i32` - это четыре байта, поэтому «скопировать» дешевле, чем следить за владением. Этот признак (дёшево и безопасно копируется побитово) закреплён за типами особым свойством, `Copy`; `String` его не имеет. Подробно об этом - в курсе `rust-first-steps`.
