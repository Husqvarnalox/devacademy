## Ошибки - это нормально, важно знать, что с ними делать

Программы ломаются: пользователь вводит букву вместо числа, файл не найден, делитель оказался нулём. Когда Python встречает такую ситуацию, он не молчит - он **бросает исключение**: создаёт объект-описание ошибки
и начинает «раскручивать» вызовы вверх, пока кто-нибудь не обработает его. Если не обработал никто, программа останавливается и печатает **traceback** - цепочку вызовов, приведших к ошибке:

```text
Traceback (most recent call last):
  File "main.py", line 7, in <module>
    print(average([]))
  File "main.py", line 3, in average
    return sum(items) / len(items)
ZeroDivisionError: division by zero
```

Читать его нужно **снизу вверх**: последняя строка говорит, *что* случилось (`ZeroDivisionError`) и почему, а строки выше показывают, *где* - от места падения (`average`, строка 3) до того, кто её вызвал.

Чтобы обработать ошибку, пишут `try ... except`:

```python
try:
    number = int(text)
except ValueError:
    number = 0
```

Правило безопасности: ловите **конкретные** ошибки, которых ждёте, и не прячьте остальные. Дальше мы научимся и вызывать ошибки сами (`raise`), и создавать собственные.

Вторая половина урока - файлы. Файл нужно открыть, прочитать или записать, а затем **закрыть**. Забытое закрытие приводит к потерянным данным и утечкам, поэтому используется конструкция `with`, которая закрывает файл за вас, что бы ни случилось.

## Как устроены исключения и файлы

**Исключение** - объект класса, унаследованного от `BaseException`. Прикладные ошибки наследуются от `Exception`. Иерархия имеет смысл: `FileNotFoundError` является подклассом `OSError`, `KeyError` и `IndexError` - подклассами `LookupError`,
`ZeroDivisionError` - подкласс `ArithmeticError`. Блок `except Родитель` ловит и всех потомков. `KeyboardInterrupt` (Ctrl+C) наследуется от `BaseException`, а не от `Exception`, поэтому `except Exception` его не перехватывает, а голый `except:` - перехватывает.

**Конструкция try.**

```text
try:        # код, где может случиться ошибка
except A:   # выполняется, если брошено A (или потомок); можно "except A as exc"
else:       # выполняется, если исключения НЕ было
finally:    # выполняется ВСЕГДА, даже при return/break/continue внутри try или except
```

Блоки `except` проверяются сверху вниз, срабатывает первый подходящий - значит, частные исключения указывают раньше общих. В `try` держите только тот код, который может бросить ожидаемую ошибку; остальное - в `else`,
иначе вы перехватите ошибки, которых не ждали. `finally` предназначен для освобождения ресурсов.

**raise.** `raise ValueError("текст")` бросает исключение. Внутри `except` пустой `raise` пробрасывает текущее исключение дальше. `raise Новое(...) from None` скрывает исходную причину,
`raise Новое(...) from exc` явно связывает их в цепочку (она видна в traceback). Исключение, которое вы не умеете осмысленно обработать, лучше не перехватывать.

**Собственные исключения.** Класс, унаследованный от подходящего встроенного (`class BadLineError(ValueError)`). Они удобны, когда нужно сообщить вызывающему коду структурированную причину: в атрибутах можно хранить номер строки, значение и т. п.
Это не новый синтаксис, а обычный класс: `__init__` вызывает `super().__init__(сообщение)` и сохраняет нужные поля.

**Файлы.** `open(path, mode, encoding=...)` возвращает файловый объект. Режимы: `"r"` чтение (по умолчанию), `"w"` запись с очисткой, `"a"` дописывание. Текстовый режим преобразует байты в строки по указанной кодировке;
если `encoding` не указан, берётся кодировка платформы, поэтому одинаковый код может вести себя по-разному - **всегда указывайте `encoding="utf-8"`**.
Файловый объект итерируем: `for line in f` даёт строки вместе с символом `\n` на конце (используйте `strip()`, если он не нужен).

**with.** Конструкция `with open(...) as f:` вызывает закрытие файла при выходе из блока - и при обычном завершении, и при исключении. Без `with` пришлось бы писать `try/finally` вручную. Закрытие важно: данные записи могут оставаться в буфере и не попасть на диск, пока файл не закрыт.

**pathlib.** `Path("dir") / "file.txt"` строит путь независимо от ОС; у `Path` есть методы `exists()`, `read_text(encoding=...)`, `write_text(text, encoding=...)`, `unlink()`, `mkdir(parents=True, exist_ok=True)`.
Относительные пути отсчитываются от **рабочей папки** процесса - в нашей среде программа может записывать файлы только внутри неё.

## Примеры

**Пример 1. Порядок выполнения try/except/else/finally.**

```python run
def divide(a, b):
    try:
        result = a / b
    except ZeroDivisionError:
        print("делить на ноль нельзя")
        return None
    else:
        print("деление прошло")
        return result
    finally:
        print("finally выполнен")

print(divide(6, 3))
print(divide(1, 0))
```
```output
деление прошло
finally выполнен
2.0
делить на ноль нельзя
finally выполнен
None
```

`finally` сработал в обоих случаях - раньше, чем вызывающий код получил возвращённое значение.

**Пример 2. Конкретные исключения и иерархия.**

```python run
try:
    int("abc")
except ValueError as exc:
    print("ValueError:", exc)

print(issubclass(FileNotFoundError, OSError), issubclass(KeyError, LookupError))
print(issubclass(KeyboardInterrupt, Exception))

try:
    open("no_such_file_123.txt", encoding="utf-8")
except FileNotFoundError as exc:
    print("нет файла", exc.filename)
```
```output
ValueError: invalid literal for int() with base 10: 'abc'
True True
False
нет файла no_such_file_123.txt
```

**Пример 3. Собственное исключение.**

```python run
class NegativeAmountError(ValueError):
    def __init__(self, amount):
        super().__init__(f"сумма не может быть отрицательной: {amount}")
        self.amount = amount

def deposit(balance, amount):
    if amount < 0:
        raise NegativeAmountError(amount)
    return balance + amount

try:
    deposit(100, -5)
except ValueError as exc:
    print(type(exc).__name__, exc.amount, exc)
```
```output
NegativeAmountError -5 сумма не может быть отрицательной: -5
```

Исключение поймано как `ValueError` (родитель), но сохранило свой тип и атрибут.

**Пример 4. Файлы: with, кодировка, pathlib.**

```python run
from pathlib import Path

path = Path("demo_notes.txt")
path.write_text("первая\nвторая\n", encoding="utf-8")

with open(path, encoding="utf-8") as f:
    for number, line in enumerate(f, start=1):
        print(number, line.strip())
print(f.closed)

print(path.read_text(encoding="utf-8").splitlines())
print(len(path.read_bytes()))
path.unlink()
print(path.exists())
```
```output
1 первая
2 вторая
True
['первая', 'вторая']
26
False
```

Файл закрыт после блока `with` (`f.closed` равно `True`). Размер 26 байтов - кириллица в UTF-8 занимает по два байта на букву, а не по одному.

**Пример 5. Исключение внутри with: файл всё равно закрывается.**

```python run
try:
    with open("demo_tmp.txt", "w", encoding="utf-8") as f:
        f.write("данные")
        raise RuntimeError("сбой во время записи")
except RuntimeError as exc:
    print("поймали:", exc)
print(f.closed)

from pathlib import Path
print(Path("demo_tmp.txt").read_text(encoding="utf-8"))
Path("demo_tmp.txt").unlink()
```
```output
поймали: сбой во время записи
True
данные
```

## Типичные ошибки

* **Голый `except:` или `except Exception: pass`.** Это скрывает реальные ошибки (в том числе опечатки в именах), и программа продолжает работу с неверными данными. Перехватывайте конкретные классы и обрабатывайте их осмысленно (логируйте, возвращайте значение по умолчанию, преобразуйте в своё исключение).
* **Слишком много кода в `try`.** Если внутри пять строк, а ошибки ждёте только от одной, вы поймаете чужие сбои под видом ожидаемого. Оставьте в `try` одну операцию, остальное перенесите в `else`.
* **Неверный порядок `except`.** Если `except Exception` стоит выше `except ValueError`, вторая ветка недостижима. Ставьте частные случаи раньше общих.
* **Открывать файл без `with` и без закрытия.** Данные могут остаться в буфере, а дескриптор - утечь. Используйте `with`.
* **Не указать `encoding`.** Программа работает у вас и ломается (`UnicodeDecodeError` или «кракозябры») на другой системе. Указывайте `encoding="utf-8"` явно.
* **Режим `"w"` вместо `"a"`.** `"w"` стирает файл при открытии - даже если после этого с записью что-то пошло не так. Для дописывания используйте `"a"`.
* **Забыть про символ `\n`.** Строки из файла содержат перевод строки в конце: `"12\n" == "12"` ложно. Для числа `int("12\n")` сработает, а для сравнения строк нужен `strip()`.
* **Перехватить `FileNotFoundError` и «забыть» его.** Если функция читает файл, а файла нет, вызывающий код обычно должен узнать об этом. Не превращайте реальную проблему в пустой результат без необходимости.
* **Считать, что finally можно пропустить через `return`.** `finally` выполнится даже при `return` внутри `try` - не размещайте там `return`, если не хотите перекрыть результат.

## Итоги

* Исключение - объект; его бросают `raise`, ловят `try/except`. Traceback читается снизу вверх: тип и причина в последней строке, место - в ближайшем к ней фрейме вашего кода.
* `else` выполняется без исключения, `finally` - всегда. Ловите конкретные классы, частные раньше общих; голый `except` скрывает ошибки.
* Собственное исключение - класс-наследник встроенного, который может хранить полезные атрибуты.
* Файлы открывают через `with` и явно указывают `encoding="utf-8"`; `pathlib.Path` упрощает работу с путями. Запись возможна только в рабочей папке программы.
