## Программа - это инструкция, а Python - исполнитель

Программа - это текстовый файл с инструкциями. Сам по себе текст ничего не делает: ему нужен исполнитель.
Для Python-программ исполнитель называется **интерпретатором**. Когда вы запускаете `python main.py`,
операционная система создаёт процесс, в нём стартует интерпретатор, читает ваш файл и выполняет инструкции сверху вниз.

Самая простая инструкция - вывести текст. Для этого есть функция `print`:

```python
print("Привет!")
```

Результат появляется в консоли. Это не магия экрана: `print` отправляет текст в **стандартный вывод** (stdout) -
поток, который процесс получает от операционной системы. Консоль просто показывает то, что туда попало.
Поэтому те же слова можно «перенаправить» в файл или в другую программу, не меняя код. Именно так наша система
проверяет ваши упражнения: она запускает программу и читает её stdout.

Если в тексте программы ошибка записи (например, пропущена скобка), Python не станет ничего выполнять и сразу
сообщит о ней. Это не каприз: файл сначала целиком разбирается, и только потом исполняется.

## От исходника к результату: что делает CPython

Самая распространённая реализация Python называется **CPython** (она написана на C). Запуск файла проходит три этапа.

1. **Разбор и компиляция.** Исходный текст разбирается в дерево, проверяется синтаксис и из дерева строится
   **объект кода** с **байткодом** - списком простых инструкций вроде «положить константу на стек» или «вызвать функцию».
   Синтаксическая ошибка находится именно на этом этапе, поэтому в программе с ошибкой в последней строке не выполнится даже первая.
2. **Выполнение.** **Виртуальная машина** CPython - обычный цикл на C - берёт инструкции байткода по одной и выполняет их.
   Это и есть «интерпретация». Машинный код вашей программы при этом не создаётся: процессор выполняет код виртуальной машины,
   а та уже выполняет ваш байткод.
3. **Кэш.** Для *импортируемых* модулей CPython сохраняет байткод в `__pycache__/*.pyc`, чтобы пропустить компиляцию при следующем импорте,
   если исходный файл не менялся. Главный запускаемый файл так не кэшируется.

Из этого следуют практические выводы:

* Компиляция есть всегда. «Python не компилируется» - ошибочное упрощение.
* Байткод привязан к версии интерпретатора: `.pyc` от одной версии Python не подходит для другой.
* Скорость Python определяется тем, что на каждую простую операцию виртуальная машина тратит заметно больше работы, чем процессор на машинную инструкцию.
  Это цена гибкости (динамические типы), а не признак «плохого кода».

**Потоки вывода.** У процесса три стандартных потока: stdin (ввод), stdout (вывод) и stderr (сообщения об ошибках).
`print` по умолчанию пишет в stdout, а необработанное исключение интерпретатор печатает в stderr. Разделение полезно:
вывод программы можно сохранить в файл, а ошибки по-прежнему увидеть на экране.

**Параметры print.** `print(*objects, sep=" ", end="\n", file=sys.stdout)`: каждый аргумент превращается в строку
через `str()`, аргументы соединяются через `sep`, в конце добавляется `end`. Возвращаемое значение - `None`.

## Примеры

**Пример 1. Компиляция и выполнение по отдельности.** Встроенная функция `compile` выполняет первый этап, а `exec` - второй.

```python run
source = "print(1 + 2)"
code = compile(source, "<строка>", "exec")
print(type(code).__name__)
exec(code)
```
```output
code
3
```

Строка `source` - это просто текст. Только после `compile` появляется объект кода, который можно выполнить.

**Пример 2. Параметры print.**

```python run
print("a", "b", "c")
print("a", "b", "c", sep="-")
print("без перевода строки", end=" | ")
print("продолжение")
print(2 + 3, "ошибок:", 0)
```
```output
a b c
a-b-c
без перевода строки | продолжение
5 ошибок: 0
```

Число `5` печатается без кавычек: `print` вызвал `str(5)`. Вычисление `2 + 3` произошло *до* вызова,
в `print` попал уже результат.

**Пример 3. stdout и stderr - разные потоки.**

```python run
import sys
print("попадёт в stdout")
print("попадёт в stderr", file=sys.stderr)
```
```output
попадёт в stdout
```

В проверке сравнивается только stdout. В консоли обычного терминала вы увидите обе строки, но они идут разными каналами.

## Типичные ошибки

* **Пропущена кавычка или скобка** (`print("Привет)`). Файл не проходит этап компиляции, поэтому Python сообщает `SyntaxError` ещё до начала выполнения -
  ни одна строка программы не отработает. Читайте сообщение: оно указывает на строку, где разбор споткнулся (иногда это строка *после* настоящей ошибки).
* **Путают текст и имя.** `print(Привет)` без кавычек ищет *переменную* с именем `Привет` и падает с `NameError`; кавычки превращают слово в строковые данные.
* **Ожидают, что print вернёт текст.** `x = print("a")` напечатает `a`, а в `x` окажется `None`: `print` выводит наружу, но ничего не возвращает программе.
* **Регистр и пробелы.** `Print("a")` - `NameError`, потому что имена чувствительны к регистру. Лишний пробел перед числом тоже
  меняет вывод, а автоматическая проверка сравнивает его с эталоном.
* **«Python сам проверит всё заранее».** Синтаксис проверяется до запуска, а вот ошибки *значений* (деление на ноль, неверный тип) проявляются
  только когда выполнение доходит до нужной строки.

## Итоги

* Программа - текст; интерпретатор CPython компилирует его в байткод и выполняет виртуальной машиной.
* Синтаксические ошибки находятся до запуска, ошибки значений - во время выполнения.
* `print` преобразует аргументы в строки, соединяет через `sep`, добавляет `end` и пишет в stdout; возвращает `None`.
* У процесса три стандартных потока: stdin, stdout и stderr.
