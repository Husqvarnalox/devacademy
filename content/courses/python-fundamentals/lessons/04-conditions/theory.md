## Программа выбирает путь

До сих пор программа шла по одной дороге: строка за строкой. Условие позволяет выбрать дорогу: «если пошёл дождь, взять зонт, иначе не брать».

```python
if temperature < 0:
    print("мороз")
elif temperature < 20:
    print("прохладно")
else:
    print("тепло")
```

Python проверяет условия сверху вниз и выполняет **первую** ветку, условие которой истинно; остальные пропускаются. Поэтому порядок важен:
если сначала проверить `temperature < 20`, то значение -5 тоже попадёт сюда, а «мороз» уже никогда не сработает.

Условием может быть не только сравнение. В Python любое значение можно спросить «ты истинно или ложно?». Ложными считаются «пустые» значения:
`0`, `0.0`, пустая строка, пустой список, `None`. Всё остальное истинно. Благодаря этому вместо `if len(items) > 0` пишут `if items`.

Условия можно соединять словами `and`, `or`, `not`. Нужно только помнить маленькую, но важную особенность: `and` и `or` в Python возвращают не `True`/`False`,
а один из своих операндов.

<!-- section: precise -->
## Что происходит внутри условия

**Тип bool.** `True` и `False` - единственные два значения типа `bool`, который является подтипом `int`: `True == 1`, `False == 0`, `True + True == 2`.
Операторы сравнения (`==`, `!=`, `<`, `<=`, `>`, `>=`) возвращают `bool`.

**Цепочки сравнений.** `a < b < c` означает `(a < b) and (b < c)`, причём `b` вычисляется один раз. Это не `(a < b) < c`.

**Истинность (truthiness).** При проверке в `if`/`while`, а также в `not`, `and`, `or` объект приводится к `bool`. Ложными считаются: `None`, `False`, ноль любого числового типа
(`0`, `0.0`), пустые последовательности и коллекции (`""`, `[]`, `()`, `{}`, `set()`, `range(0)`). Остальные значения истинны, включая строку `"0"` и список `[0]`.
Собственные классы могут определять поведение через методы `__bool__` или `__len__`.

**and / or.** Выражение `x or y` возвращает `x`, если `x` истинно, иначе `y`. Выражение `x and y` возвращает `x`, если `x` ложно, иначе `y`.
Правый операнд вычисляется *только если нужен* (короткое замыкание). Поэтому `n != 0 and 10 / n > 1` безопасно: при `n == 0` деления не происходит.
Типичное применение `or` - значение по умолчанию: `name = user_input or "аноним"`; но осторожно - `0 or 5` вернёт `5`, а `0` может быть допустимым значением.
Приоритет: `not` выше `and`, `and` выше `or`; скобки делают намерение явным.

**if / elif / else.** Тело ветки определяется отступом (обычно 4 пробела); двоеточие в конце строки с условием обязательно. Ветка `else` необязательна и срабатывает, если не подошла ни одна из предыдущих.
Тернарное выражение: `value = a if условие else b`.

**match (Python 3.10+).** Оператор `match` сопоставляет значение с образцами сверху вниз: литералы, последовательности (`["go", direction]`), с захватом имён и необязательным условием-охранником `if`.
Образец `_` подходит к любому значению. Это не `switch` из C: образец разбирает *структуру* значения и привязывает имена к его частям. Для простых проверок диапазонов `if/elif` по-прежнему уместнее.

## Примеры

**Пример 1. Цепочки сравнений и истинность.**

```python run
x = 5
print(1 < x < 10, 1 < x < 3)
for value in [0, 0.0, "", [], {}, None, "0", [0]]:
    print(repr(value), bool(value))
```
```output
True False
0 False
0.0 False
'' False
[] False
{} False
None False
'0' True
[0] True
```

**Пример 2. and и or возвращают операнд.**

```python run
print("" or "по умолчанию")
print("abc" or "x")
print(0 and 1)
print(3 and 4)
print([] or None)
n = 0
print(n != 0 and 10 / n > 1)
```
```output
по умолчанию
abc
0
4
None
False
```

Последняя строка не падает с `ZeroDivisionError`: правая часть не вычисляется, потому что `n != 0` уже ложно.

**Пример 3. Порядок веток.**

```python run
def category(age):
    if age >= 65:
        return "пенсионер"
    elif age >= 18:
        return "взрослый"
    else:
        return "несовершеннолетний"

for age in [10, 18, 40, 65, 90]:
    print(age, category(age))
```
```output
10 несовершеннолетний
18 взрослый
40 взрослый
65 пенсионер
90 пенсионер
```

**Пример 4. match с образцами.**

```python run
def parse(cmd):
    match cmd.split():
        case ["go", direction]:
            return "идём " + direction
        case ["take", item, *rest] if rest:
            return "берём " + item + " и ещё " + str(len(rest))
        case ["take", item]:
            return "берём " + item
        case []:
            return "пусто"
        case _:
            return "непонятно"

for text in ["go north", "take key", "take key map lamp", "", "dance now"]:
    print(parse(text))
```
```output
идём north
берём key
берём key и ещё 2
пусто
непонятно
```

## Типичные ошибки

* **Перепутать `=` и `==`.** `if x = 5:` - синтаксическая ошибка: `=` присваивает, `==` сравнивает.
* **Неверный порядок веток.** Если общее условие стоит выше частного, частное недостижимо. Пишите от самых узких условий к самым широким.
* **Сравнивать с `True` и `False`.** `if flag == True` избыточно, а для не-bool значений даёт неожиданный результат: `[1] == True` ложно, хотя `bool([1])` истинно. Пишите `if flag:`.
* **Опираться на `or` как на «значение по умолчанию» для чисел.** `count = user_count or 10` заменит корректный `0` на 10. Если ноль допустим, проверяйте `is None`.
* **Забыть про граничные случаи.** В классификации важны равенства: «сумма двух сторон *строго* больше третьей». Условие `>=` вместо `>` пропускает вырожденные случаи. Выписывайте границы явно.
* **Писать `if a == 1 or 2:`.** Это читается как `(a == 1) or 2`, и `2` всегда истинно. Правильно: `a == 1 or a == 2` либо `a in (1, 2)`.

<!-- section: summary -->
## Итоги

* Ветки `if/elif/else` проверяются сверху вниз; срабатывает первая подошедшая, поэтому порядок задаёт смысл.
* Ложны `None`, `False`, нули, пустые строки и коллекции; остальное истинно (включая `"0"`).
* `and` и `or` возвращают операнд и вычисляют правую часть лениво.
* `a < b < c` - цепочка, а не сравнение результата с числом; `match` разбирает структуру значения (Python 3.10+).
