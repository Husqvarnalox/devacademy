## Ошибки можно ожидать и обрабатывать

Вы уже знаете, что программа останавливается, когда встречает ошибку. Но есть ошибки, которые не означают баг в программе: человек ввёл «abc» вместо числа, нужного файла нет на диске.
Такие ситуации можно предвидеть и сообщить о них аккуратно, не позволяя программе упасть.

Ошибка времени выполнения в Python называется **исключением** (exception). Чтобы его обработать, опасный код оборачивают в `try` («попробовать»), а реакцию на ошибку пишут в `except` («кроме случая»):

```python
try:
    number = int(text)
except ValueError:
    number = 0
```

Если внутри `try` случилась ошибка указанного типа, остаток `try` пропускается и выполняется `except`. Если ошибки нет, `except` пропускается. Дальше программа идёт как обычно.

Иногда ошибку нужно, наоборот, **создать самому**: функция получила недопустимые данные и должна об этом сообщить. Для этого есть `raise` («возбудить»): `raise ValueError("сообщение")`.

И третья тема: **файл** - именованные данные на диске. Python открывает файл командой `open`, а блок `with` гарантирует, что файл будет закрыт, даже если внутри случилась ошибка:

```python
with open("notes.txt", encoding="utf-8") as source:
    text = source.read()
```

Зачем это нужно: данные программы должны переживать её завершение, а реальные данные почти всегда содержат неожиданности, которые нужно обработать, а не проигнорировать.

## Примеры

**Пример 1. try/except.**

```python run
def to_number(text):
    try:
        return int(text)
    except ValueError:
        return None

print(to_number("42"))
print(to_number("сорок два"))
print(to_number("3.5"))
```
```output
42
None
None
```

Разбор: для `"42"` ошибки нет, возвращается число. Для остальных `int` вызывает `ValueError`; управление переходит в `except`, и функция возвращает `None`.

**Пример 2. Порядок выполнения.**

```python run
try:
    print("1. начало")
    value = 10 / 0
    print("2. не дойдём сюда")
except ZeroDivisionError:
    print("3. деление на ноль")
print("4. программа продолжается")
```
```output
1. начало
3. деление на ноль
4. программа продолжается
```

Разбор: после ошибки остаток `try` пропущен. Тип в `except` должен совпадать с типом ошибки.

**Пример 3. raise.**

```python run
def percent(part, total):
    if total == 0:
        raise ValueError("total не может быть нулём")
    return part / total * 100

print(percent(1, 4))
try:
    print(percent(1, 0))
except ValueError as error:
    print("Ошибка:", error)
```
```output
25.0
Ошибка: total не может быть нулём
```

Разбор: `raise` останавливает функцию и передаёт ошибку вызывающему коду. Запись `as error` даёт имя объекту ошибки, его текст можно вывести.

**Пример 4. Запись и чтение файла.**

```python run
with open("shopping.txt", "w", encoding="utf-8") as target:
    target.write("хлеб\n")
    target.write("молоко\n")

with open("shopping.txt", encoding="utf-8") as source:
    for line in source:
        print(line.strip())
```
```output
хлеб
молоко
```

Разбор: режим `"w"` открывает файл для записи (создаёт или очищает). `write` не добавляет перевод строки сам, поэтому `\n` пишут явно. При чтении цикл `for` даёт строки файла вместе с `\n` на конце, и `strip()` убирает его.

**Пример 5. Файла нет.** Если открыть несуществующий файл для чтения:

```python
with open("missing.txt", encoding="utf-8") as source:
    text = source.read()
```

```
FileNotFoundError: [Errno 2] No such file or directory: 'missing.txt'
```

Эту ошибку можно перехватить: `except FileNotFoundError:` и сообщить человеку, что файл не найден.

**Попробуйте.** В примере 1 вызовите `to_number("")` и `to_number(" 7 ")` и предскажите результат.

## Подробнее

**Структура try.** `try` выполняет блок. Если произошло исключение, Python ищет подходящий `except` (по типу) и выполняет его. Если подходящего нет, исключение идёт дальше и в итоге останавливает программу.
Можно написать несколько `except` для разных типов или объединить типы в скобках: `except (ValueError, TypeError):`.

**Перехватывайте только то, что ожидаете.** Пустой `except:` или `except Exception:` скрывает и опечатки в коде, и настоящие баги. Выбирайте конкретный тип: `int` ошибается через `ValueError`, поиск ключа - через `KeyError`, открытие файла - через `FileNotFoundError`.

**Где ставить try.** Оборачивайте минимальный код: ровно ту строку, которая может упасть. Большой блок под `try` затрудняет понимание, что именно обрабатывается.

**Когда лучше `if`, а когда `try`.** Если проверка простая (`if total == 0`), используйте `if`. Если проверить заранее трудно (корректна ли строка как число), проще попробовать и обработать ошибку.

**`raise`.** Создаёт исключение: `raise ТипОшибки("сообщение")`. Для некорректных значений обычно `ValueError`, для неверного типа - `TypeError`. Сообщение должно объяснять, что не так и с чем.

**Файлы.**

| Запись | Что делает |
|---|---|
| `open(path, encoding="utf-8")` | чтение (режим `"r"` по умолчанию) |
| `open(path, "w", encoding="utf-8")` | запись, файл очищается или создаётся |
| `open(path, "a", encoding="utf-8")` | дописывание в конец |
| `f.read()` | весь текст одной строкой |
| `for line in f` | строки по очереди, каждая с `\n` на конце |
| `f.write(text)` | записать текст (без автоматического перевода строки) |

**Кодировка.** Всегда указывайте `encoding="utf-8"`: иначе используется кодировка системы, и русский текст может прочитаться неправильно на другом компьютере.

**`with`.** Закрывает файл при выходе из блока. Незакрытый файл может не дописаться на диск.

**Пути.** Путь без каталога (`notes.txt`) указывает на рабочую папку программы. Путь может быть неверным, файла может не быть, прав может не хватать: все это ошибки времени выполнения.

## Типичные ошибки

**1. Перехват не того типа.**

```python
try:
    print(10 / 0)
except ValueError:
    print("не число")
```

Программа упадёт с `ZeroDivisionError`: этот тип не указан в `except`. Тип берут из сообщения об ошибке.

**2. Слишком широкий `except`.** `except:` без типа скроет даже опечатку в имени переменной, и программа молча продолжит неправильную работу. Указывайте тип.

**3. Забыли `\n` при записи.**

```python
target.write("хлеб")
target.write("молоко")
```

В файле окажется `хлебмолоко` в одной строке. `write` не переводит строку сам.

**4. Забыли `strip()` при чтении.** Строка из файла заканчивается на `\n`: `"12\n"`. `int("12\n")` работает, но сравнение `line == "итог"` не сойдётся, и в `print(line)` появятся лишние пустые строки.

**5. Режим `"w"` вместо `"a"`.** `"w"` стирает содержимое, и данные теряются при каждом запуске. Для дописывания используйте `"a"`.

**6. Отсутствующий файл при чтении.**

```
FileNotFoundError: [Errno 2] No such file or directory: 'nope.txt'
```

Проверьте имя и папку, из которой запущена программа.

**7. Нет отступа после `except`.**

```
IndentationError: expected an indented block after 'except' statement on line 3
```

**8. Чтение из файла после выхода из `with`.** После блока файл закрыт, и `source.read()` вызовет `ValueError: I/O operation on closed file`. Читайте внутри блока.

## Итоги

* `try/except ТипОшибки` обрабатывает ожидаемые ошибки; перехватывайте конкретный тип и минимум кода.
* `raise ТипОшибки("сообщение")` сообщает об ошибке; для неверных значений обычно `ValueError`.
* `with open(путь, режим, encoding="utf-8")` открывает и гарантированно закрывает файл; `"w"` стирает, `"a"` дописывает.
* Строки файла приходят с `\n`; `write` его не добавляет.

## Для тех, кто уже программировал

* Исключения - основной механизм ошибок; нет разделения на checked/unchecked. `try/except/else/finally`, `raise ... from ...`; в курсе показаны только `try/except` и `raise`.
* Идиома EAFP («проще попросить прощения»): сначала попробовать, потом обработать, вместо предварительных проверок.
* Все исключения - объекты классов, наследующих `BaseException`; пользовательские классы исключений существуют, но в этом курсе не вводятся.
* `with` - менеджер контекста: вызывает закрытие ресурса при любом выходе из блока.
* Текстовые файлы читаются как `str`; кодировка по умолчанию зависит от системы, поэтому `encoding="utf-8"` указывайте явно.
* Итерация по файлу ленивая: строки читаются по мере необходимости.

<!-- section: deep-dive -->
## Что происходит внутри (необязательно)

Когда возникает исключение, интерпретатор создаёт объект ошибки и начинает подниматься по цепочке вызовов вверх, пока не найдёт блок `except`, способный его принять.
Если такого нет, поднимается до самого верха, и программа завершается с traceback. Блок `with` вызывает у файла метод закрытия независимо от того, выход обычный или через исключение.
Файловые операции буферизуются: `write` сначала копит данные в памяти и отправляет на диск порциями, поэтому незакрытый файл может потерять последние записи.
