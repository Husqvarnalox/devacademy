## Сообщение об ошибке - это подсказка

Каждый, кто пишет программы, постоянно видит ошибки. Это нормальная часть работы, а не признак неумелости.
Важнее другое: умеете ли вы читать сообщение. Python сообщает, **что** случилось, **где** (файл и строка) и часто **почему**.

Сообщение о сбое во время работы называется **traceback** («след»): оно показывает путь, по которому выполнение дошло до сбоя.
Для коротких программ читать его просто:

```
Traceback (most recent call last):
  File "main.py", line 3, in <module>
    print(total)
          ^^^^^
NameError: name 'total' is not defined
```

Читайте снизу вверх:

1. **Последняя строка** - главное. До двоеточия стоит тип ошибки (`NameError`), после него - описание.
2. **Строка выше** показывает код, на котором остановилась программа, а знаки `^` отмечают нужное место.
3. **Строка `File ... line 3`** говорит, в каком файле и в какой строке это случилось.

Зачем это нужно: умение быстро прочитать сообщение экономит больше времени, чем любая другая привычка начинающего.

## Примеры

В этом уроке примеры - это сообщения, а не запускаемые программы: они специально содержат ошибки.

**Пример 1. Ошибка записи: программа не стартует.**

```python
print("Один")
print("Два"
print("Три")
```

```
  File "main.py", line 2
    print("Два"
         ^
SyntaxError: '(' was never closed
```

Разбор: `SyntaxError` (синтаксическая ошибка) означает, что нарушено правило записи. Слова «Traceback» нет, потому что программа не стартовала:
слово «Один» тоже не выведено. Скобка открыта в строке 2 и нигде не закрыта.

**Пример 2. Ошибка отступа.**

```python
x = 5
  print(x)
```

```
  File "main.py", line 2
    print(x)
IndentationError: unexpected indent
```

Разбор: перед `print` два лишних пробела. Отступ - это пробелы в начале строки. В Python он часть записи: когда в программе нет блоков, строки должны начинаться с первого символа. Блоки появятся в уроке про условия.

**Пример 3. Ошибка во время работы.**

```python
price = input()
print(price + 1)
```

Если ввести `50`, получим:

```
Traceback (most recent call last):
  File "main.py", line 2, in <module>
    print(price + 1)
          ~~~~~~^~~
TypeError: can only concatenate str (not "int") to str
```

Разбор: запись верна, поэтому программа стартовала и дошла до строки 2. `TypeError` - «неподходящий тип». Прочитано дословно: можно присоединять только строку, а справа `int`. Причина: `input` вернул текст. Исправление: `int(price) + 1`.

**Пример 4. Проверка догадки выводом.** Если непонятно, что лежит в переменной, выведите её:

```python run
text = "42 "
print(f"[{text}]")
print(len(text))
```
```output
[42 ]
3
```

Скобки вокруг значения показали пробел в конце, а `len` подтвердил: символов три, а не два. Такой приём пригодится, когда сообщение сказано в общих чертах.

**Попробуйте.** Возьмите программу из примера 3 и предскажите, что изменится, если вместо `price + 1` написать `int(price) + 1`.

## Типичные виды ошибок

| Тип | Что значит | Типичная причина |
|---|---|---|
| `SyntaxError` | нарушено правило записи | незакрытая кавычка или скобка, лишний или пропущенный символ |
| `IndentationError` | неверный отступ | лишние или недостающие пробелы в начале строки |
| `NameError` | имя не определено | опечатка, имя использовано до присваивания, забыты кавычки |
| `TypeError` | операция неприменима к такому типу | сложение текста с числом, неверное число аргументов |
| `ValueError` | тип верный, значение неподходящее | `int("abc")` |
| `ZeroDivisionError` | деление на ноль | делитель стал нулём |
| `EOFError` | данные для `input()` закончились | `input()` вызван чаще, чем есть строк ввода |

**Две категории.** Ошибки записи (`SyntaxError`, `IndentationError`) Python находит до выполнения, и ни одна строка не запускается. Остальные - ошибки времени выполнения:
программа работает, пока не дойдёт до проблемного места, поэтому часть вывода может появиться до сбоя.

**Где настоящая причина.** Указанная строка - то место, где Python понял, что что-то не так. Иногда причина раньше. Например, пропущенная закрывающая скобка
проявляется в следующей строке. Если в указанной строке всё верно, смотрите на строку выше.

**Одна ошибка за раз.** Исправляйте первую по порядку и запускайте снова: остальные часто были следствием, а часть откроется только после исправления первой.

**Не угадывайте.** Прежде чем менять код, назовите себе тип ошибки, строку и причину. Если не получилось, выведите значения переменных вокруг строки.

## Типичные ошибки при чтении

**1. Паника при виде длинного сообщения.** Для программы из 10-20 строк сообщение почти всегда умещается в 4-5 строк. Читайте последнюю, потом номер строки.

**2. Исправление не той строки.** Номер в сообщении относится к файлу, в котором вы сейчас работаете. Если в редакторе есть пустые строки сверху, считайте их тоже.

**3. Игнорирование подсказки `Did you mean`.** Python сам предлагает близкое имя:

```
NameError: name 'Print' is not defined. Did you mean: 'print'?
```

В большинстве случаев подсказка точна.

**4. Перепутаны ошибки записи и выполнения.** Если сообщение начинается с `Traceback`, программа уже работала. Если с `File "main.py", line N` без этого слова, это ошибка записи.

**5. Запуск без чтения.** Повторный запуск без изменений даст то же сообщение. Меняйте программу только после того, как поняли причину.

**6. Незакрытая скобка в многострочной записи.**

```
  File "main.py", line 1
    print(f"Итого: {total} руб."
         ^
SyntaxError: '(' was never closed
```

Стрелка указывает на скобку, которую нужно закрыть, а не на место, где её не хватает.

## Итоги

* Сообщение читают снизу вверх: тип и описание, затем строка и код.
* `SyntaxError` и `IndentationError` находятся до запуска, остальные - во время работы программы.
* Исправляйте по одной ошибке и после каждой запускайте снова.
* Если причина непонятна, выведите значения переменных через `print`.

Теперь вы можете сами разбирать большую часть сбоев. Дальше: [условия](lesson:python.fundamentals.conditions) - программа научится выбирать, что делать.

## Для тех, кто уже программировал

* Нет этапа компиляции в привычном смысле, но синтаксис проверяется до выполнения: `SyntaxError` и `IndentationError` не дают программе стартовать.
* Типы проверяются только при выполнении, поэтому `TypeError` появляется на конкретной строке, когда она выполняется, а не заранее.
* Traceback читается снизу вверх: последняя строка - исключение, выше - цепочка вызовов (самый глубокий вызов внизу). Для короткого скрипта цепочка из одного кадра `<module>`.
* Метки `~~^^` в современных версиях Python показывают часть выражения, вызвавшую ошибку.
* Ошибки - это исключения, их можно перехватывать; об этом в уроке про `try/except`.
* Отступ значим: смешивание табуляции и пробелов даёт `TabError`; принято 4 пробела.

## Что происходит внутри (необязательно)

Ошибка в Python - это объект-**исключение**. Когда выполнение доходит до проблемного места, интерпретатор создаёт такой объект
(`NameError`, `TypeError` и так далее) и начинает «раскручивать» цепочку вызовов в поисках кода, который умеет с ним справиться.
Если такого кода нет, выполнение останавливается, а интерпретатор печатает traceback в стандартный поток ошибок (`stderr`), отдельный
от обычного вывода (`stdout`). Поэтому в проверке упражнения видно только stdout, а текст ошибки показывается отдельно.
Знаки `^` и `~` под кодом вычисляются из позиций, которые компилятор сохраняет вместе с байткодом.
