## Собираем программу целиком

В этом уроке нового синтаксиса нет. Вы уже умеете читать ввод, проверять условия, повторять действия, хранить данные в словаре, писать функции и обрабатывать ошибки. Теперь нужно собрать из этого законченную программу - **дневник тренировок**.

Реальная программа - не одна идея, а несколько небольших частей, которые работают вместе:

1. **Разбор** - из строки `бег 30` получить название и число минут или понять, что строка ошибочна.
2. **Накопление** - прибавить минуты к итогу по этому виду занятия.
3. **Вывод** - показать итоги в предсказуемом порядке.

Чем яснее разделены части, тем проще их писать и проверять по отдельности. Такой подход называется **декомпозицией** - разбиением задачи на подзадачи.

<!-- section: examples -->
## Как строить решение по шагам

**Шаг 1. Разбор строки как функция.**

```python run
def parse_line(line):
    parts = line.split()
    if len(parts) != 2:
        return None
    try:
        minutes = int(parts[1])
    except ValueError:
        return None
    if minutes <= 0:
        return None
    return parts[0], minutes

print(parse_line("бег 30"))
print(parse_line("бег"))
print(parse_line("бег много"))
print(parse_line("бег -5"))
```
```output
('бег', 30)
None
None
None
```

Разбор: функция возвращает пару «название, минуты» либо `None`, если строка не подходит. Три проверки: два слова, второе - целое число, число больше нуля.

**Шаг 2. Накопление в словаре.**

```python run
totals = {}
for name, minutes in [("бег", 30), ("йога", 45), ("бег", 15)]:
    totals[name] = totals.get(name, 0) + minutes

for name in sorted(totals):
    print(f"{name}: {totals[name]}")
```
```output
бег: 45
йога: 45
```

Разбор: `get(name, 0)` возвращает 0 для вида, которого ещё нет. `sorted(totals)` даёт ключи в алфавитном порядке.

**Шаг 3. Чтение до слова «конец».** Ввод читают в цикле `while True`, как в уроке про `while`:

```python
number = 0
while True:
    line = input().strip()
    if line == "конец":
        break
    number += 1
    # здесь разбор строки и накопление итога
```

**Шаг 4. Склейка.** Подставьте разбор и накопление внутрь цикла, а вывод итогов поместите после цикла. Ошибочную строку сообщите через `print` и перейдите к следующей командой `continue`.

**Шаг 5. Проверка граничных случаев.** Перед сдачей проверьте на своих данных: пустой дневник, только ошибочные строки, два вида занятий с одинаковой суммой, лишние пробелы.

**Попробуйте.** Допишите в `parse_line` отказ для минут больше 600 и проверьте на `parse_line("бег 700")`.

## Подробнее: как не запутаться в большой программе

* **Один шаг - одна проверка.** Добавили разбор - запустите на трёх строках. Добавили накопление - выведите словарь. Не пишите всё сразу.
* **Сначала счастливый путь**, потом ошибки: добейтесь верного ответа на корректных данных, затем добавляйте обработку плохих.
* **Выводите промежуточные значения** с помощью `print`, пока ищете ошибку; убирайте их в конце.
* **Читайте условие как список требований.** Здесь их несколько: формат строки, нумерация, порядок вывода, правило при равенстве, особый случай «Занятий нет». Отметьте каждое.
* **Нумерация.** Номер строки увеличивается для каждой строки, кроме «конец», в том числе ошибочной.
* **Правило при равенстве.** Если обновлять лучший вид только при строго большей сумме, а перебирать в алфавитном порядке, победит первый по алфавиту.
* **Порядок сортировки.** `sorted` сравнивает строки по кодам символов, поэтому заглавные буквы идут раньше строчных.

## Типичные ошибки

**1. Смешали счётчики.** Номер строки и количество правильных записей - разные величины: первая растёт на каждой строке, вторая только на правильной.

**2. `int` без `try`.**

```
ValueError: invalid literal for int() with base 10: 'много'
```

Строка «бег много» должна быть пропущена, а не остановить программу.

**3. Не учли отрицательные и нулевые минуты.** `int("-5")` работает, поэтому одной проверки на ValueError недостаточно.

**4. Пропустили `strip()`.** Пробелы по краям мешают сравнению с «конец» и выводу ошибочной строки.

**5. Обращение к ключу без `get`.**

```
KeyError: 'бег'
```

Обычное `totals[name] += minutes` для нового ключа вызывает KeyError.

**6. Вывод в цикле вместо вывода после цикла.** Итоги нужно печатать один раз, после «конец».

**7. Забыли случай пустого дневника.** Без проверки программа напечатает `Занятий: 0` и найдёт «лучшее» занятие в пустом словаре.

## Что происходит внутри (необязательно)

Словарь Python хранит пары в хеш-таблице: по ключу вычисляется число (хеш), которое указывает, где искать значение, поэтому поиск почти не зависит от размера словаря.
Ключом может быть только то, что не меняется, например строка или число. С версии 3.7 словарь запоминает порядок добавления ключей, но в этой программе порядок задаётся явно через `sorted`.
