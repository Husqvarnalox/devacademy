## Как работает цикл for и зачем нужны генераторы

Когда вы пишете `for x in something`, Python не знает, список ли это. Он лишь просит `something` выдавать значения по одному, пока значения не закончатся. Всё, что так умеет, называется **iterable** (итерируемый объект): списки, строки, словари, файлы, `range`. А тот, кто реально выдаёт значения по очереди и помнит, где остановился, называется **iterator** (итератор).

Писать итераторы вручную классом долго. Для этого есть **генераторы**: обычная функция, в которой вместо `return` стоит `yield`. Она не завершается после выдачи значения, а *приостанавливается*, запоминая локальные переменные, и продолжает с того же места при следующем запросе. Результат - ленивая последовательность: значения вычисляются по мере необходимости. Благодаря этому можно обрабатывать файл на гигабайты строка за строкой или описывать бесконечную последовательность, не храня её в памяти.

Главная ловушка: итератор **одноразовый**. Пройдя по нему один раз, второй раз вы получите пустоту. Это не ошибка Python, а следствие того, что итератор «помнит позицию».

Модуль `itertools` в стандартной библиотеке - набор готовых ленивых «деталей» (срез, склейка, группировка, нарастающие итоги, декартово произведение), которые удобно соединять в конвейеры. Основы циклов и списков вы уже знаете из [«Циклов»](lesson:python.fundamentals.loops) и [«Списков»](lesson:python.fundamentals.lists); здесь мы заглядываем внутрь.

## Протокол итерации

**Iterable** - объект с методом `__iter__()`, возвращающим итератор (на деле достаточно и `__getitem__` для старой схемы, но опирайтесь на `__iter__`). **Iterator** - объект с методами `__next__()` (возвращает следующее значение или поднимает `StopIteration`) и `__iter__()` (возвращает сам объект). Встроенные функции: `iter(obj)` вызывает `obj.__iter__()`, `next(it)` вызывает `it.__next__()`, `next(it, default)` вместо `StopIteration` возвращает `default`.

Цикл `for x in obj: body` эквивалентен:

```python
it = iter(obj)
while True:
    try:
        x = next(it)
    except StopIteration:
        break
    body
```

Поэтому список можно обходить много раз (каждый `iter(lst)` создаёт новый независимый итератор), а итератор - один раз (его `__iter__` возвращает его же).

**Генераторная функция** - любая функция, в теле которой есть `yield`. Её вызов не выполняет тело, а возвращает объект-генератор. Это итератор: `next(g)` запускает (или возобновляет) тело до очередного `yield`, значение справа от `yield` становится результатом `next`. Генератор хранит собственный *кадр* - локальные переменные и текущую позицию - между вызовами `next`. Когда тело заканчивается (или выполняется `return`), поднимается `StopIteration`, и генератор переходит в состояние «закрыт» (`inspect.getgeneratorstate` показывает `GEN_CREATED`, `GEN_SUSPENDED`, `GEN_CLOSED`). Если внутри тела случайно возникнет `StopIteration`, начиная с Python 3.7 оно превращается в `RuntimeError`.

**Ленивость и память.** Генератор держит только текущее состояние, а не все значения. `sum(x * x for x in range(10**7))` не создаёт список из десяти миллионов чисел. Бесконечную последовательность (`itertools.count`, генератор с `while True`) можно безопасно использовать, если потребитель берёт конечную часть (`islice`, `zip` с конечным партнёром, `break`).

**Генераторное выражение** `(выражение for x in iterable if условие)` - короткая запись безымянного генератора. В скобках функции с единственным аргументом их можно опустить: `sum(x for x in data)`. Отличие от списка `[...]`: список строится сразу целиком, генератор - лениво и одноразово.

**yield from.** `yield from sub` делегирует выдачу вложенному итерируемому объекту: выдаёт все его значения и передаёт управление обратно. Это краткая и корректная замена цикла `for x in sub: yield x` (и поддерживает `send`/`throw`/возвращаемое значение подгенератора).

**Исчерпание.** Итератор после последнего элемента остаётся пустым. Функции `sum`, `list`, `max`, `sorted`, `for` потребляют итератор целиком. Если нужно пройти дважды, создайте итератор заново или материализуйте результат в `list`/`tuple` (`itertools.tee` делает независимые копии, но буферизует данные).

**itertools (основное).**

* `islice(it, stop)` / `islice(it, start, stop, step)` - ленивый срез, не копирует; отрицательные индексы не поддерживаются.
* `chain(a, b, ...)` - последовательно итерирует несколько iterable; `chain.from_iterable(xs)` - для итерируемого набора итерируемых.
* `groupby(it, key=None)` - группирует **подряд идущие** элементы с одинаковым ключом. Для группировки «всех одинаковых» вход нужно отсортировать по тому же ключу. Итератор группы связан с исходным: его надо потребить до перехода к следующей группе.
* `accumulate(it, func=operator.add, initial=None)` - нарастающие итоги (или иная бинарная операция).
* `product(a, b, ...)` - декартово произведение; `repeat=n` повторяет один и тот же iterable.

## Примеры

**Пример 1. Протокол вручную и итератор классом.**

```python run
nums = [10, 20]
it = iter(nums)
print(next(it), next(it))
try:
    next(it)
except StopIteration:
    print("StopIteration")
print(next(iter(nums), "default"), next(it, "default"))

class Countdown:
    def __init__(self, start):
        self.current = start
    def __iter__(self):
        return self
    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        self.current -= 1
        return self.current + 1

c = Countdown(3)
print(iter(c) is c, list(c), list(c))
```
```output
10 20
StopIteration
10 default
True [3, 2, 1] []
```

**Пример 2. Генератор хранит состояние: тело запускается лениво.**

```python run
import inspect

def numbers():
    print("старт")
    n = 0
    while True:
        print("перед yield", n)
        yield n
        n += 1

g = numbers()
print(inspect.getgeneratorstate(g))
print("значение:", next(g))
print("значение:", next(g))
print(inspect.getgeneratorstate(g))
g.close()
print(inspect.getgeneratorstate(g))
```
```output
GEN_CREATED
старт
перед yield 0
значение: 0
перед yield 1
значение: 1
GEN_SUSPENDED
GEN_CLOSED
```

**Пример 3. Ленивость, память и конвейеры.**

```python run
import sys
from itertools import count, islice

big_list = [x for x in range(1_000_000)]
big_gen = (x for x in range(1_000_000))
print("список больше 1 МБ:", sys.getsizeof(big_list) > 1_000_000)
print("генератор меньше 1 КБ:", sys.getsizeof(big_gen) < 1_000)

def squares():
    for n in count(1):
        yield n * n

evens = (s for s in squares() if s % 2 == 0)
print(list(islice(evens, 4)))

def flatten(items):
    for item in items:
        if isinstance(item, list):
            yield from flatten(item)
        else:
            yield item

print(list(flatten([1, [2, [3, 4]], 5])))
```
```output
список больше 1 МБ: True
генератор меньше 1 КБ: True
[4, 16, 36, 64]
[1, 2, 3, 4, 5]
```

**Пример 4. Исчерпание и itertools.**

```python run
from itertools import accumulate, chain, groupby, product

gen = (x * x for x in range(4))
print(sum(gen), list(gen))

words = ["apple", "avocado", "banana", "blueberry", "apricot"]
print([(k, len(list(g))) for k, g in groupby(words, key=lambda w: w[0])])
ordered = sorted(words, key=lambda w: w[0])
print([(k, len(list(g))) for k, g in groupby(ordered, key=lambda w: w[0])])

print(list(accumulate([1, 2, 3, 4])))
print(list(chain([1, 2], (3,), "ab")))
print(list(product("ab", [1, 2])))
```
```output
14 []
[('a', 2), ('b', 2), ('a', 1)]
[('a', 3), ('b', 2)]
[1, 3, 6, 10]
[1, 2, 3, 'a', 'b']
[('a', 1), ('a', 2), ('b', 1), ('b', 2)]
```

## Типичные ошибки

* **Повторный обход итератора.** `sum(gen)`, а затем `list(gen)` даёт `[]`. Пересоздайте генератор или сохраните список.
* **`groupby` без сортировки.** Равные ключи, разделённые другими, попадают в разные группы. Сначала `sorted(data, key=ключ)`.
* **Использование группы после перехода дальше.** `list(groupby(...))` превращает итераторы групп в уже недействительные: сохраняйте `list(group)` внутри цикла.
* **Превращение ленивого в жадное.** `list(gen)` на бесконечном генераторе не завершится и съест всю память. Берите `islice`.
* **`return` со значением и ожидание его в `for`.** Значение `return` генератора доступно только через `StopIteration.value` или `yield from`; цикл `for` его не видит.
* **`StopIteration` внутри генератора.** Начиная с Python 3.7 превратится в `RuntimeError`; завершайте генератор через `return`.
* **Изменение коллекции во время итерации** по ней же: поведение сбивает позицию итератора. Обходите копию.
* **Бесконечный `__next__`** без условия остановки, когда нужен конечный итератор.

<!-- section: summary -->
## Итог

* `for` вызывает `iter()` и повторяет `next()` до `StopIteration`. Iterable создаёт итератор, итератор помнит позицию и одноразов.
* Генераторная функция (есть `yield`) возвращает генератор; тело выполняется лениво, состояние хранится в его кадре.
* Ленивость экономит память и позволяет бесконечные последовательности при условии конечного потребителя.
* `yield from` делегирует вложенному iterable; генераторное выражение - ленивый аналог списка.
* `itertools`: `islice`, `chain`, `groupby` (только подряд идущие ключи - сортируйте вход), `accumulate`, `product`.
* Дальше: [контекстные менеджеры](lesson:python.advanced.context-managers), где генераторы применяются через `@contextmanager`.
