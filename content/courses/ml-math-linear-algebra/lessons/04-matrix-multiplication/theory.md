## Два отображения - одно произведение

Нейронная сеть - это цепочка слоёв: выход одного слоя становится входом следующего. Если слои линейные, спрашивается: можно ли заменить цепочку одним слоем и сколько это стоит? Ответ даёт **умножение матриц**. Оно же описывает переходы марковской цепи (например, как меняется погода день за днём) и пакетные вычисления в обучении.

В прошлом уроке матрица `B` формы `n × p` превращала вектор `x ∈ ℝᵖ` в вектор `B x ∈ ℝⁿ`. Пусть теперь за `B` следует матрица `A` формы `m × n`: она превращает `B x` в `A (B x) ∈ ℝᵐ`. Результат применения двух отображений подряд - снова линейное отображение, и у него есть матрица. Эту матрицу называют **произведением** `A B`, она имеет форму `m × p`, и по определению `(A B) x = A (B x)`.

Как вычислить `A B`. Элемент в строке `i` и столбце `j` - скалярное произведение `i`-й строки `A` на `j`-й столбец `B`:

`(A B)_ij = a_i1·b_1j + a_i2·b_2j + ... + a_in·b_nj`.

Для этого число столбцов `A` должно равняться числу строк `B` (это число `n`). Правило форм: `(m × n) · (n × p) = (m × p)`; внутренние размеры совпадают и «исчезают», внешние остаются.

Важное отличие от чисел: порядок множителей имеет значение. Произведение `A B` означает «сначала `B`, потом `A`», и обычно `A B ≠ B A`. Например, «повернуть, затем растянуть» даёт не то же, что «растянуть, затем повернуть». Зато скобки можно расставлять как угодно: `(A B) C = A (B C)`.

Матрица, у которой единицы стоят на главной диагонали, а остальные элементы равны нулю, называется **единичной** и обозначается `I`: `I x = x`, `A I = I A = A`. Это аналог числа 1.

## Примеры

**Пример 1. Умножение матриц тремя циклами и неперестановочность.** Форма `2 × 3` на `3 × 2` даёт `2 × 2`; в обратном порядке получается `3 × 3`.

```python run
def matmul(A, B):
    m, n, p = len(A), len(B), len(B[0])
    C = [[0.0] * p for _ in range(m)]
    for i in range(m):
        for j in range(p):
            for k in range(n):
                C[i][j] += A[i][k] * B[k][j]
    return C


A = [[1.0, 2.0, 0.0],
     [0.0, 1.0, 3.0]]          # 2 x 3
B = [[1.0, 0.0],
     [2.0, 1.0],
     [0.0, 4.0]]               # 3 x 2
print("AB =", matmul(A, B))    # 2 x 2
print("BA =", matmul(B, A))    # 3 x 3

S = [[1.0, 1.0], [0.0, 1.0]]
T = [[1.0, 0.0], [1.0, 1.0]]
print("ST =", matmul(S, T))
print("TS =", matmul(T, S))
```
```output
AB = [[5.0, 2.0], [2.0, 13.0]]
BA = [[1.0, 2.0, 0.0], [2.0, 5.0, 3.0], [0.0, 4.0, 12.0]]
ST = [[2.0, 1.0], [1.0, 1.0]]
TS = [[1.0, 1.0], [1.0, 2.0]]
```

Разбор:

* Внешние циклы по `i` и `j` перебирают клетки результата, внутренний по `k` суммирует произведения `A[i][k] * B[k][j]`: это скалярное произведение строки `i` на столбец `j`.
* Пример клетки: `(AB)_11 = 1·1 + 2·2 + 0·0 = 5`, `(AB)_22 = 0·0 + 1·1 + 3·4 = 13`.
* `AB` и `BA` вообще разной формы (`2 × 2` и `3 × 3`), хотя оба произведения определены.
* Квадратные `S` и `T` (сдвиги вдоль осей) перемножаются в обоих порядках, но результаты разные: `ST ≠ TS`. Порядок преобразований важен.

**Пример 2. Два линейных слоя сворачиваются в один.** Слои `h = W1 x + b1`, `y = W2 h + b2` без нелинейности между ними.

```python run
def matvec(A, x):
    return [sum(a * v for a, v in zip(row, x)) for row in A]


def matmul(A, B):
    return [[sum(a * b for a, b in zip(row, col)) for col in zip(*B)] for row in A]


W1 = [[1.0, -1.0, 2.0],
      [0.5, 0.0, 1.0]]         # 3 входа -> 2 нейрона
b1 = [1.0, -1.0]
W2 = [[2.0, 1.0],
      [0.0, -1.0],
      [1.0, 3.0]]              # 2 -> 3 нейрона
b2 = [0.0, 0.5, -2.0]
x = [1.0, 2.0, 3.0]

h = [v + c for v, c in zip(matvec(W1, x), b1)]
two_layers = [v + c for v, c in zip(matvec(W2, h), b2)]

W = matmul(W2, W1)                                    # 3 x 3
b = [v + c for v, c in zip(matvec(W2, b1), b2)]
one_layer = [v + c for v, c in zip(matvec(W, x), b)]

print("два слоя:   ", two_layers)
print("один слой:  ", one_layer)
print("форма W:", (len(W), len(W[0])))
```
```output
два слоя:    [14.5, -2.0, 11.5]
один слой:   [14.5, -2.0, 11.5]
форма W: (3, 3)
```

* `W2 (W1 x + b1) + b2 = (W2 W1) x + (W2 b1 + b2)`: матрица единого слоя - произведение `W2 W1`, сдвиг - `W2 b1 + b2`. Порядок: первый слой стоит **справа**.
* `zip(*B)` отдаёт столбцы `B`, поэтому `matmul` умещается в одну строку: каждая клетка - скалярное произведение строки `A` на столбец `B`.
* Вывод для обучения: без нелинейной функции между слоями глубина ничего не добавляет - вся сеть эквивалентна одному слою. Поэтому после слоёв ставят ReLU и подобные функции.

**Пример 3. Марковская цепь и порядок вычислений в NumPy.** Погода: состояния «солнечно» и «дождь»; строка `i` матрицы `P` - вероятности перехода из состояния `i` (сумма в строке равна 1).

```python run
import numpy as np

P = np.array([[0.9, 0.1],
              [0.5, 0.5]])
p = np.array([0.0, 1.0])               # сегодня дождь
for step in (1, 2, 3):
    p = p @ P
    print("день", step, np.round(p, 4))

P50 = np.linalg.matrix_power(P, 50)
print(np.round(P50, 4))
print(np.round(np.array([0.0, 1.0]) @ P50, 4), np.round(np.array([1.0, 0.0]) @ P50, 4))

n = 1000                               # для квадратных A, B и вектора x размера n
print("(A @ B) @ x:", n**3 + n**2, "умножений")
print("A @ (B @ x):", 2 * n**2, "умножений")
```
```output
день 1 [0.5 0.5]
день 2 [0.7 0.3]
день 3 [0.78 0.22]
[[0.8333 0.1667]
 [0.8333 0.1667]]
[0.8333 0.1667] [0.8333 0.1667]
(A @ B) @ x: 1001000000 умножений
A @ (B @ x): 2000000 умножений
```

* Распределение вероятностей `p` (строка) за шаг умножается справа на `P`: `p_{k+1} = p_k P`. Поэтому за `k` шагов получаем `p_0 Pᵏ`.
* `np.linalg.matrix_power(P, 50)` - пятидесятая степень. Обе строки результата почти одинаковы, `(5/6, 1/6)`: через много дней вероятность погоды не зависит от того, с чего начали. Такое распределение называется стационарным; на языке следующих уроков это собственный вектор матрицы.
* Последние строки считают число умножений, а не время. Сначала перемножить две матрицы `n × n` стоит `n³` умножений, затем вектор - ещё `n²`. Если же сначала умножить `B` на вектор, а потом `A` на результат, получится `2·n²`. Результат одинаков (ассоциативность), стоимость различается в 500 раз.

**Попробуйте.** В примере 1 вычислите по формуле вручную клетку `(BA)_23` и проверьте по выводу (она равна `3`). В примере 3 замените `P` на `[[0.5, 0.5], [0.5, 0.5]]` и предскажите распределение после одного шага из любого начального состояния.

## Определения

**Произведение.** Для `A` формы `m × n` и `B` формы `n × p` матрица `C = A B` имеет форму `m × p`, `c_ij = Σₖ a_ik·b_kj`. Если число столбцов `A` не равно числу строк `B`, произведение не определено.

Три способа читать `C = A B`:

* клетка `c_ij` - скалярное произведение строки `i` матрицы `A` на столбец `j` матрицы `B`;
* столбец `j` матрицы `C` равен `A` на столбец `j` матрицы `B`: `C[:, j] = A B[:, j]` (так матрица `A` применяется сразу к нескольким векторам);
* `C` - композиция отображений: `(A B) x = A (B x)`, сначала действует `B`.

## Свойства

* **Ассоциативность:** `(A B) C = A (B C)`.
* **Дистрибутивность:** `A (B + C) = A B + A C`, `(A + B) C = A C + B C`.
* **Единичная матрица:** `I A = A I = A`, где `I` - квадратная, с единицами на диагонали.
* **Транспонирование меняет порядок:** `(A B)ᵀ = Bᵀ Aᵀ`.
* **Неперестановочность:** в общем случае `A B ≠ B A`; даже форма может отличаться или одно из произведений может быть не определено.
* **Степень** квадратной матрицы: `A⁰ = I`, `Aᵏ = A · A · ... · A` (`k` множителей).

## Сложность и порядок вычислений

Произведение матриц `m × n` и `n × p` требует `m·n·p` умножений. Для цепочки это важно: `A (B x)` стоит две операции «матрица на вектор» - `O(n²)`, а `(A B) x` - сначала умножение матриц `O(n³)`. Результат одинаков, но если вектор всего один, раскрывать скобки в пользу умножения матриц невыгодно. Возведение в степень `k` повторным умножением стоит `(k - 1)` произведений; **быстрое возведение в степень** (по двоичной записи `k`) обходится `O(log k)` произведениями.

## Где это встречается

* **Свёртка слоёв:** `W2 (W1 x + b1) + b2 = (W2 W1) x + (W2 b1 + b2)`. Поэтому в сетях между линейными слоями ставят нелинейные активации; в трансформерах оценки внимания `Q Kᵀ` - тоже произведение матриц, посчитанное сразу для всех пар слов.
* **Пакетные вычисления:** строки `X` - объекты, `X Wᵀ + b` применяет слой ко всем сразу; видеокарты специально ускоряют умножение матриц.
* **Марковские цепи:** `p_{k+1} = p_k P`, `p_k = p_0 Pᵏ`; в PageRank вероятность оказаться на странице считается тем же способом.
* **Композиция преобразований:** поворот, затем масштабирование, затем сдвиг в компьютерной графике и аугментации изображений - произведение матриц.

## Типичные ошибки

* **Перемножение поэлементно.** В NumPy `A * B` умножает элементы на одинаковых позициях, а не матрицы. Признак: результат той же формы, что и `A`, и числа не те. Исправление: `A @ B` или `np.matmul`.
* **Несовпадение внутренних размеров.** `(2 × 3) · (2 × 3)` не определено. Признак: `ValueError` в NumPy. Исправление: выписать формы `(m × n)(n × p)` и проверить, что два средних числа равны. Часто нужна транспонированная матрица.
* **Порядок множителей.** `A B` вместо `B A` даёт другой результат или другую форму. Признак: поворот выполняется после масштабирования, хотя нужен до. Исправление: читать произведение справа налево - ближе всего к вектору действует правый множитель.
* **Порядок при свёртке слоёв.** Для слоёв, применяемых в порядке `W_1, W_2, ..., W_k`, итоговая матрица - `W_k ... W_2 W_1`, а не `W_1 W_2 ... W_k`. Признак: ошибка формы или неверные числа. Исправление: накапливать результат как `W = W_i @ W`.
* **Сдвиг при свёртке аффинных слоёв.** Забыть, что сдвиг тоже меняется: `b = W2 b1 + b2`, а не `b1 + b2`. Признак: совпадение при `x = 0` нарушено. Исправление: проверить свёртку на случайных `x`.
* **Тройной цикл и порядок индексов.** В вычислении `C[i][j] += A[i][k] * B[k][j]` легко перепутать индексы и получить `A[i][k] * B[j][k]` (это произведение с транспонированной `B`). Признак: результат верен только для симметричных матриц. Исправление: проверить на несимметричной матрице малых размеров.
* **Нулевая степень и единичная матрица.** `A⁰` - единичная матрица той же формы, а не нулевая и не `A`. Признак: цикл возведения в степень начинает с нулей. Исправление: начинать накопление с `I`.
* **Строки, не суммирующиеся в 1.** Матрица переходов должна быть строчно-стохастической: если сумма в строке не равна 1, вероятности «утекают» или растут. Признак: сумма элементов `p_k` отличается от 1. Исправление: проверять суммы строк до вычислений.

<!-- section: summary -->
## Итоги

* `(A B)_ij` - скалярное произведение строки `i` матрицы `A` на столбец `j` матрицы `B`; формы `(m × n)(n × p) = (m × p)`.
* `A B` - композиция: `(A B) x = A (B x)`, сначала `B`. Умножение ассоциативно и дистрибутивно, но не перестановочно; `(A B)ᵀ = Bᵀ Aᵀ`.
* Стоимость произведения - `m·n·p`; порядок скобок влияет на время: `A (B x)` дешевле `(A B) x`.
* Два линейных слоя сворачиваются в один: `W = W2 W1`, `b = W2 b1 + b2`. Нелинейность между слоями нужна, чтобы глубина имела смысл.
* Степени матрицы описывают многошаговые процессы, например марковские цепи: `p_k = p_0 Pᵏ`.

## Умножение матриц быстрее, чем `n³`

Тройной цикл выполняет `n³` умножений. Алгоритм Штрассена (1969) разбивает матрицы на блоки `2 × 2` и обходится семью, а не восемью умножениями блоков; сложность падает до `O(n^2.81)`. Асимптотически ещё более быстрые алгоритмы известны, но в практике почти не применяются: большие константы и сложность реализации съедают выигрыш. Реальное ускорение даёт другое - работа с блоками, помещающимися в кэш процессора, векторные инструкции и видеокарты. Библиотеки BLAS, на которые опирается NumPy, устроены именно так, поэтому `A @ B` в NumPy в сотни раз быстрее тройного цикла на Python.

Ещё одно наблюдение: ранг произведения не превышает рангов множителей, `rank(A B) ≤ min(rank A, rank B)`. Если слой «сжимает» данные до малого числа измерений (`d_out < d_in`), никакое последующее произведение не восстановит потерянную информацию. На этом основаны низкоранговые приближения: большую матрицу весов заменяют произведением двух узких матриц `U V` - это экономит память и вычисления (в методе LoRA для дообучения моделей добавку к весам ищут именно в виде произведения двух узких матриц), а общий разговор о приближениях матриц ждёт нас в уроке про SVD.
