## Как измерить длину и похожесть

Линейная модель предсказывает цену квартиры, умножая каждый признак на свой вес и складывая результаты. Поиск похожих текстов сравнивает два эмбеддинга, а регуляризация следит за тем, чтобы веса не разрастались. Во всех трёх случаях работают две идеи этого урока: **скалярное произведение** (мера согласованности двух векторов) и **норма** (длина вектора).

**Скалярное произведение** двух векторов одной длины - число: перемножаем компоненты на одинаковых местах и складываем. Для `u = [1, 2, 3]` и `v = [4, 5, 6]` получаем `1·4 + 2·5 + 3·6 = 32`. Записывают `u · v`. Результат - одно число, а не вектор.

Предсказание линейной модели - именно скалярное произведение: если `w` - вектор весов, `x` - вектор признаков объекта, `b` - свободный член (сдвиг), то ответ модели `w · x + b`. Каждый признак вносит вклад `w_i · x_i`, и вклады суммируются.

У скалярного произведения есть геометрический смысл. Если `|u|` и `|v|` - длины векторов, а `θ` - угол между ними, то

`u · v = |u| · |v| · cos θ`.

Отсюда видно, как читать знак результата:

* больше нуля - векторы смотрят в одну сторону (угол меньше 90°);
* ноль - векторы **ортогональны** (перпендикулярны, угол 90°): один не имеет составляющей вдоль другого;
* меньше нуля - векторы смотрят в разные стороны (угол больше 90°).

**Норма** вектора - его длина. Чаще всего используют три нормы:

* **L2** (евклидова): `|v|₂ = √(v_1² + ... + v_n²)` - привычная длина стрелки; для `[3, 4]` это `5`;
* **L1**: `|v|₁ = |v_1| + ... + |v_n|` - сумма модулей;
* **L∞**: `|v|∞ = max |v_i|` - наибольший по модулю компонент.

**Расстояние** между точками `u` и `v` - норма их разности: `|u - v|`. Если поделить скалярное произведение на обе длины, получится **косинусное сходство** `cos θ = (u · v) / (|u| · |v|)` - число от `-1` до `1`, которое зависит только от направления, а не от длины векторов.

## Примеры

**Пример 1. Скалярное произведение и нормы на чистом Python.** Сначала предсказание линейной модели, затем нормы и расстояние.

```python run
import math

w = [0.5, -2.0, 1.5]     # веса: за м², за расстояние до метро (км), за этаж
x = [54.0, 1.2, 7.0]     # признаки квартиры
b = 10.0
pred = sum(wi * xi for wi, xi in zip(w, x)) + b
print("предсказание:", pred)

u = [3.0, 4.0]
v = [4.0, -3.0]
print("u . v =", sum(a * c for a, c in zip(u, v)))
print("|u| =", math.sqrt(sum(a * a for a in u)))
print("|u|_1 =", sum(abs(a) for a in u), " |u|_inf =", max(abs(a) for a in u))
print("|u - v| =", math.hypot(u[0] - v[0], u[1] - v[1]))
```
```output
предсказание: 45.1
u . v = 0.0
|u| = 5.0
|u|_1 = 7.0  |u|_inf = 4.0
|u - v| = 7.0710678118654755
```

Разбор:

* `wi * xi for wi, xi in zip(w, x)` - вклады признаков; `sum(...)` складывает их, `+ b` добавляет сдвиг: `27 - 2.4 + 10.5 + 10 = 45.1`.
* `u · v = 3·4 + 4·(-3) = 0`: векторы `[3, 4]` и `[4, -3]` ортогональны.
* Длина `[3, 4]` по L2 равна `√(9 + 16) = 5`, по L1 - `3 + 4 = 7`, по L∞ - `max(3, 4) = 4`.
* `math.hypot` считает `√(a² + b²)` аккуратнее, чем возведение в квадрат вручную. Расстояние между `u` и `v`: разность `[-1, 7]`, длина `√50 ≈ 7.07`.

**Пример 2. Косинусное сходство для поиска.** Три «документа» заданы эмбеддингами из четырёх чисел; сравниваем их с запросом.

```python run
import math


def dot(u, v):
    return sum(a * b for a, b in zip(u, v))


def cosine(u, v):
    return dot(u, v) / (math.sqrt(dot(u, u)) * math.sqrt(dot(v, v)))


query = [1.0, 0.0, 2.0, 1.0]
docs = {
    "A": [2.0, 0.0, 4.0, 2.0],     # то же направление, вдвое длиннее
    "B": [1.0, 1.0, 1.0, 0.0],
    "C": [-1.0, 0.0, -2.0, -1.0],  # противоположное направление
}
for name, d in docs.items():
    print(name, "dot =", dot(query, d), " cos =", round(cosine(query, d), 4))

print("ортогональны:", dot([1.0, 2.0], [2.0, -1.0]))
```
```output
A dot = 12.0  cos = 1.0
B dot = 3.0  cos = 0.7071
C dot = -6.0  cos = -1.0
ортогональны: 0.0
```

* Документ `A` - тот же вектор, растянутый вдвое: скалярное произведение у него большое (12), но косинус ровно `1` - направление совпадает. Косинус не реагирует на длину.
* `B` частично согласован с запросом (`cos ≈ 0.71`), `C` направлен противоположно (`cos = -1`).
* `dot(u, u)` - это квадрат длины, поэтому `math.sqrt(dot(u, u))` - норма L2. Деление на обе нормы и есть нормализация.

**Пример 3. То же в NumPy.** Оператор `@` между одномерными массивами - скалярное произведение, `np.linalg.norm` - нормы. Нормализовав все строки, сходство со всеми документами получаем одним умножением.

```python run
import numpy as np

u = np.array([3.0, 4.0])
v = np.array([4.0, -3.0])
print(u @ v, np.dot(u, v))
print(np.linalg.norm(u), np.linalg.norm(u, 1), np.linalg.norm(u, np.inf))

X = np.array([[1.0, 0.0, 2.0, 1.0],
              [2.0, 0.0, 4.0, 2.0],
              [1.0, 1.0, 1.0, 0.0],
              [-1.0, 0.0, -2.0, -1.0]])
q = X[0]
unit = X / np.linalg.norm(X, axis=1, keepdims=True)
print(np.round(unit @ (q / np.linalg.norm(q)), 4))
```
```output
0.0 0.0
5.0 7.0 4.0
[ 1.      1.      0.7071 -1.    ]
```

* Второй аргумент `np.linalg.norm` выбирает норму: `1` - L1, `np.inf` - L∞; без него считается L2.
* `axis=1` считает норму каждой строки отдельно, `keepdims=True` сохраняет форму `(4, 1)`, чтобы деление применилось к каждой строке.
* `unit @ (q / |q|)` - матрица единичных строк на единичный вектор запроса: каждая строка даёт косинус. Первая строка - сам запрос, поэтому `1`.

**Попробуйте.** В примере 2 добавьте документ `"D": [0.0, 5.0, 0.0, 0.0]` и предскажите его косинус с запросом до запуска (подсказка: чему равно скалярное произведение?). Затем умножьте `query` на 10 и убедитесь, что косинусы не изменились, а `dot` вырос в 10 раз.

## Определения

**Скалярное произведение** векторов `u, v ∈ ℝⁿ`: `u · v = u_1·v_1 + ... + u_n·v_n`. Определено только для одинаковых длин. Свойства: `u · v = v · u`; `u · (a·v + c·w) = a·(u · v) + c·(u · w)` (линейность по каждому аргументу); `u · u = |u|₂² ≥ 0`, и ноль только для нулевого вектора.

**Нормы.** Для `p ∈ {1, 2, ∞}`:

* `|v|₁ = Σ |v_i|`;
* `|v|₂ = √(Σ v_i²) = √(v · v)`;
* `|v|∞ = max |v_i|`.

Любая норма неотрицательна, равна нулю только у нулевого вектора, `|c·v| = |c| · |v|` и удовлетворяет неравенству треугольника `|u + v| ≤ |u| + |v|`. Расстояние `d(u, v) = |u - v|`.

**Неравенство Коши - Буняковского:** `|u · v| ≤ |u|₂ · |v|₂`. Поэтому `cos θ = (u · v) / (|u|₂ |v|₂)` всегда лежит в `[-1, 1]`. Равенство достигается, когда векторы лежат на одной прямой.

**Косинусное сходство** определено, если оба вектора ненулевые: у нулевого вектора нет направления, и деление дало бы `0 / 0`.

**Связь расстояния и косинуса.** Из `|u - v|² = |u|² + |v|² - 2·(u · v)` для векторов единичной длины получаем `|u - v|² = 2 - 2·cos θ`. После нормализации ранжирование по косинусу, по скалярному произведению и по евклидову расстоянию даёт один и тот же порядок.

## Сложность

Скалярное произведение и любая из норм - `O(n)` операций. Поиск ближайшего среди `N` документов размерности `n` перебором - `O(N · n)`; если строки заранее нормализованы, поиск сводится к одному умножению матрицы на вектор.

## Где это встречается в моделях

* **Линейная и логистическая регрессия, нейрон:** `w · x + b`.
* **Поиск по эмбеддингам, рекомендации, RAG:** косинусное сходство запроса и документов; нормализованные эмбеддинги хранят заранее.
* **Механизм внимания:** оценки `q · k` - скалярные произведения запроса и ключей.
* **L2-регуляризация:** к функции потерь добавляют `λ · |w|₂²`, что удерживает веса малыми. **L1-регуляризация** `λ · |w|₁` обнуляет часть весов и даёт разреженную модель.
* **Обрезка градиента по норме (gradient clipping):** если `|g|₂ > c`, градиент заменяют на `g · (c / |g|₂)` - направление сохраняется, длина становится равной `c`.
* **Ошибки модели:** метрика MAE - это L1-норма вектора ошибок (поделённая на `n`), RMSE - L2-норма (поделённая на `√n`), максимальная ошибка - L∞.

## Типичные ошибки

* **Разные длины векторов.** `sum(a * b for a, b in zip(u, v))` молча отбросит лишние компоненты. Признак: результат не меняется при дописывании чисел в конец более длинного вектора. Исправление: сравнить длины и выбросить `ValueError`.
* **Косинус с нулевым вектором.** Получим `ZeroDivisionError` (или `nan` в NumPy с предупреждением). Признак: пустой или нулевой эмбеддинг в базе. Исправление: заранее отфильтровать такие векторы или договориться, что сходство с ними равно `0`.
* **Сравнение скалярных произведений вместо косинусов.** Длинный вектор получает большое `u · v` просто из-за длины. Признак: «лучшим» оказывается самый длинный документ. Исправление: нормализовать векторы или делить на нормы.
* **Квадрат нормы вместо нормы.** `dot(u, u)` - это `|u|²`. Признак: расстояния выросли в неожиданное число раз. Исправление: извлечь корень `math.sqrt` либо сознательно сравнивать квадраты (порядок тот же, и корень не нужен).
* **`u * v` вместо `u @ v` в NumPy.** Оператор `*` перемножает покомпонентно и возвращает вектор, а не число. Признак: на выходе массив вместо одного числа. Исправление: `u @ v`, `np.dot(u, v)` или `(u * v).sum()`.
* **Косинус чуть больше 1.** Из-за округления `cos` может оказаться `1.0000000000000002`, и `math.acos` выбросит `ValueError`. Исправление: ограничить значение отрезком `[-1, 1]` (`max(-1.0, min(1.0, c))`).
* **Путаница норм.** `np.linalg.norm(A)` для матрицы по умолчанию считает норму Фробениуса по всем элементам, а не длины строк. Исправление: для строк указывать `axis=1`.

## Итоги

* Скалярное произведение `u · v = Σ u_i·v_i` - число; `w · x + b` - предсказание линейной модели; геометрически `u · v = |u|·|v|·cos θ`.
* Знак `u · v` показывает согласованность направлений, ноль означает ортогональность.
* Нормы L1, L2, L∞ измеряют длину; расстояние - это норма разности; L1 и L2 появляются в регуляризации, L2 - в обрезке градиента.
* Косинусное сходство `(u · v) / (|u| |v|)` лежит в `[-1, 1]`, не зависит от длины векторов и не определено для нулевого вектора.
* После нормализации строк поиск по эмбеддингам - одно умножение матрицы на вектор.

## Почему в высоких размерностях всё «почти ортогонально»

У эмбеддингов сотни и тысячи измерений. Случайные векторы в таком пространстве почти всегда близки к ортогональным: косинус двух независимых случайных направлений в размерности `n` имеет разброс порядка `1/√n`. Поэтому косинус `0.3` между двумя эмбеддингами в 768 измерениях уже говорит о заметной связи, а в двух измерениях - ни о чём.

Второе следствие - **концентрация расстояний**: в большой размерности расстояния от запроса до случайных точек становятся почти одинаковыми, и «ближайший» сосед отличается от «дальнего» на малую долю. Именно поэтому для поиска по эмбеддингам нужны обученные представления, где смысловая близость превращена в близость направлений, а не случайные признаки.

Норму и скалярное произведение можно ввести на любом векторном пространстве, в том числе на функциях: скалярным произведением функций служит интеграл от их произведения. Метод главных компонент и разложения в следующих уроках используют ту же геометрию.
