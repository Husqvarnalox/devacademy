## Список — это массив ссылок, ndarray — это массив чисел

Список Python `[1, 2, 3]` хранит не сами числа, а **ссылки** на отдельные объекты `int`. Каждый такой объект — полноценный `PyObject` со счётчиком ссылок, указателем на тип и значением. Поэтому сложение двух списков поэлементно — это цикл интерпретатора: для каждой пары достать объекты, определить их тип, найти нужный метод сложения, создать новый объект с результатом.

**ndarray** из NumPy устроен иначе. Это один непрерывный кусок памяти, в котором подряд лежат числа одного типа (например, восемь байт на каждое `int64`), плюс небольшая «обёртка»: форма (`shape`), тип элементов (`dtype`) и шаги по памяти (`strides`). Когда вы пишете `a + b`, NumPy запускает один скомпилированный цикл на C по этому буферу. Интерпретатор Python в этом цикле не участвует, а проверка типов выполняется один раз на весь массив, а не на каждый элемент.

Отсюда два следствия. Во-первых, **массив однороден**: все элементы одного `dtype`, и NumPy при необходимости приводит данные к общему типу. Во-вторых, **быстрый код на NumPy — это код без Python-циклов по элементам**. Такой стиль называют **векторизацией**: вы описываете операцию над массивом целиком, а цикл выполняет библиотека.

## Устройство ndarray

Массив состоит из двух частей: **буфера данных** (непрерывный блок байтов) и **метаданных**.

* `dtype` — тип одного элемента (`int64`, `float32`, `bool`, ...). `itemsize` — число байтов на элемент.
* `shape` — кортеж длин по каждой оси. Число осей — `ndim`, число элементов — `size`.
* `nbytes = size * itemsize` — размер буфера данных (без метаданных).
* `strides` — для каждой оси число **байтов**, на которое нужно сместиться в буфере, чтобы перейти к следующему элементу вдоль этой оси.

Адрес элемента `a[i, j, k]` вычисляется как `base + i*strides[0] + j*strides[1] + k*strides[2]`. Для C-непрерывного массива (порядок «строка за строкой», `order='C'`) шаги считаются справа налево: последний шаг равен `itemsize`, а каждый предыдущий — предыдущий шаг, умноженный на длину оси. Для `shape=(3, 4)` и `itemsize=8` получается `strides=(32, 8)`.

Шаги позволяют многим операциям не копировать данные. Транспонирование просто переставляет `strides`: `a.T` для `a` формы `(3, 4)` имеет `shape=(4, 3)` и `strides=(8, 32)`, а память та же. Срез `a[:, ::2]` увеличивает шаг вдоль оси и тоже не копирует, но получившийся массив уже **не** C-непрерывный (`flags['C_CONTIGUOUS']` равен `False`). Эту тему продолжает урок про [представления и копии](lesson:python.numpy.views-and-copies).

## Почему векторизация быстрее

Время операции над списком складывается из накладных расходов на каждый элемент: чтение ссылки, проверка типа, диспетчеризация метода (`int.__add__`), выделение результата, подсчёт ссылок. Для массива NumPy проверка типа и выбор «ядра» (скомпилированной функции для пары `dtype`) делаются один раз, а затем цикл на C идёт по плотному буферу без обращений к интерпретатору. Плотные данные хорошо ложатся в кэш процессора, а компилятор и библиотека могут применять SIMD-инструкции, где это возможно.

Важно, что выигрыш — это не «магия»: он достигается только пока цикл остаётся внутри NumPy. Если вы в `for` обращаетесь к `a[i]`, каждый элемент превращается в скалярный объект NumPy, и код может оказаться даже медленнее списка.

## Как измерять

Для оценки времени используйте `time.perf_counter()` (монотонные часы высокого разрешения). Один замер ненадёжен: на результат влияют другие процессы, частота процессора, прогрев кэшей, сборщик мусора. Поэтому делают несколько повторов и берут **минимум** (наименее зашумлённое значение) или медиану. Абсолютные числа зависят от машины и версии NumPy; устойчиво лишь **отношение** и порядок величины. Для серьёзных замеров есть модуль `timeit`.

## Примеры

**Пример 1. Метаданные массива.** Все атрибуты — это просто числа и кортежи, они дёшево читаются.

```python run
import numpy as np

a = np.arange(12, dtype=np.int32).reshape(3, 4)
print("shape:", a.shape, "ndim:", a.ndim, "size:", a.size)
print("dtype:", a.dtype, "itemsize:", a.itemsize, "nbytes:", a.nbytes)
print("strides:", a.strides)
print("a.T strides:", a.T.strides, "C-непрерывный:", a.T.flags["C_CONTIGUOUS"])
print("a[:, ::2] shape/strides:", a[:, ::2].shape, a[:, ::2].strides)
```
```output
shape: (3, 4) ndim: 2 size: 12
dtype: int32 itemsize: 4 nbytes: 48
strides: (16, 4)
a.T strides: (4, 16) C-непрерывный: False
a[:, ::2] shape/strides: (3, 2) (16, 8)
```

Строка в 4 элемента по 4 байта даёт шаг 16 по первой оси и 4 по второй. Транспонирование и срез с шагом поменяли только метаданные.

**Пример 2. Размер в памяти.** Список из миллиона `int` хранит миллион ссылок и ещё миллион объектов; массив — миллион восьмибайтных значений.

```python run
import sys
import numpy as np

n = 1_000_000
lst = list(range(n))
arr = np.arange(n, dtype=np.int64)
print("ndarray nbytes:", arr.nbytes)
print("список: только массив ссылок >= 8 байт на элемент:", sys.getsizeof(lst) >= 8 * n)
print("один объект int тяжелее элемента ndarray:", sys.getsizeof(1000) > arr.itemsize)
```
```output
ndarray nbytes: 8000000
список: только массив ссылок >= 8 байт на элемент: True
один объект int тяжелее элемента ndarray: True
```

Точный размер списка зависит от версии CPython, поэтому мы печатаем сравнение, а не число.

**Пример 3. Замер времени.** Сумма квадратов миллиона чисел циклом по списку и одной операцией над массивом.

```python run
import time
import numpy as np

n = 1_000_000
lst = list(range(n))
arr = np.arange(n, dtype=np.int64)

def best(fn, repeat=5):
    times = []
    for _ in range(repeat):
        t0 = time.perf_counter()
        fn()
        times.append(time.perf_counter() - t0)
    return min(times)

t_list = best(lambda: sum(x * x for x in lst))
t_np = best(lambda: int(np.dot(arr, arr)))
assert sum(x * x for x in lst) == int(np.dot(arr, arr))
print("результаты совпадают")
print("NumPy быстрее более чем в 5 раз:", t_list / t_np > 5)
```
```output
результаты совпадают
NumPy быстрее более чем в 5 раз: True
```

Мы печатаем булево значение, а не секунды: точные числа меняются от запуска к запуску и от машины к машине. Реальное отношение обычно составляет десятки раз, но порог 5 надёжен на любом компьютере. Разброс возникает из-за конкуренции с другими процессами, динамической частоты процессора, состояния кэша и работы сборщика мусора, поэтому берётся минимум из нескольких повторов. Заметьте и то, что `np.dot(arr, arr)` для `int64` не использует BLAS, но всё равно проходит цикл на C.

**Пример 4. Список умножается не так, как массив.**

```python run
import numpy as np

print([1, 2, 3] * 2)
print(np.array([1, 2, 3]) * 2)
print(np.asarray([1, 2, 3], dtype=np.float64) * 2.5)
```
```output
[1, 2, 3, 1, 2, 3]
[2 4 6]
[2.5 5.  7.5]
```

## Типичные ошибки

* **Цикл по элементам массива.** `for x in a: total += x` медленнее суммы по списку: каждый `x` превращается в объект NumPy. Используйте `a.sum()` или другую векторную операцию.
* **Считать, что `list * 2` и `ndarray * 2` — одно и то же.** Для списка это повторение, для массива — поэлементное умножение. Преобразуйте входные данные через `np.asarray`.
* **Мерить время один раз.** Один замер не показывает ничего; берите несколько повторов и минимум или медиану, и сравнивайте отношения, а не секунды.
* **Путать `nbytes` с размером всего объекта.** `nbytes` — только буфер данных; метаданные ndarray в него не входят.
* **Ожидать, что любой массив C-непрерывен.** После `a.T` или `a[:, ::2]` это не так; некоторые операции сначала делают копию.
* **Класть в один массив разнотипные данные и ждать скорости.** Массив из объектов (`dtype=object`) хранит ссылки, как список, и теряет все преимущества.

## Итоги

* ndarray — непрерывный буфер однотипных значений плюс метаданные `shape`, `dtype`, `strides`.
* `nbytes = size * itemsize`; шаги `strides` задают, как индексы превращаются в смещение в байтах.
* Транспонирование и срезы меняют только метаданные, поэтому они дёшевы.
* Векторизация быстра, потому что цикл идёт на C по типизированному буферу, а не через диспетчеризацию методов для каждого `PyObject`.
* Измеряйте время через `time.perf_counter`, с повторами и минимумом, и сравнивайте отношения.
