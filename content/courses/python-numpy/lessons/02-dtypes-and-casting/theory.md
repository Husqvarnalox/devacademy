## Тип элемента определяет всё

В списке Python каждое число — отдельный объект, и целое число может быть сколь угодно большим. В массиве NumPy у всех элементов один фиксированный **dtype**, например `int8` (один байт со знаком), `uint8` (один байт без знака), `int64` (восемь байт), `float32` или `float64`. Размер типа фиксирован, поэтому у значения есть **диапазон**: `int8` хранит числа от -128 до 127. Если результат арифметики выходит за диапазон, Python-целое просто станет больше, а целое в массиве **«заворачивается»**: 127 + 1 в `int8` даёт -128. Ошибки при этом нет, и вы получите неверный результат молча.

С вещественными числами другая проблема — не диапазон, а **точность**. `float64` хранит около 16 значащих десятичных цифр, `float32` — около 7. Поэтому `0.1 + 0.2` не равно `0.3`, а к большому `float32` небольшое число может вовсе не прибавиться.

Когда вы смешиваете в одной операции разные типы, NumPy сам выбирает общий тип по правилам **приведения (promotion)**. А когда вы просите явно (`astype`), вы отвечаете за последствия: дробная часть отбрасывается, а значения вне диапазона целевого типа превращаются в мусор.

## Фиксированные типы и их границы

Для целых типов диапазоны берутся из `np.iinfo(dtype)`: для `intN` от `-2^(N-1)` до `2^(N-1) - 1`, для `uintN` от `0` до `2^N - 1`. Арифметика в массивах выполняется **по модулю `2^N`**: результат — это младшие `N` бит точного значения. Поэтому `uint8(250) + uint8(10)` равно 4, а `int8(127) + int8(1)` равно -128. В отличие от этого, обычный `int` Python имеет произвольную точность, и `2**64` — нормальное число. Переполнение скаляров NumPy сопровождается предупреждением `RuntimeWarning`, а в операциях над массивами оно происходит без предупреждений.

## Приведение типов в операциях (type promotion)

Результат бинарной операции над двумя массивами имеет dtype, определяемый `np.result_type(a.dtype, b.dtype)`: это наименьший тип, способный представить значения обоих. Примеры: `int8` и `uint8` дают `int16`; `int64` и `float32` дают `float64`; `bool` и `int8` дают `int8`; `uint64` и `int64` дают `float64` (общего целого типа нет). Целое с вещественным даёт вещественный тип; поэтому `np.array([1, 2, 3]) / 2` — это `float64`, ведь деление `/` всегда вещественное.

Начиная с NumPy 2 (NEP 50), Python-скаляры в операциях с массивами считаются «слабо типизированными»: результат сохраняет dtype массива. `np.array([1], dtype=np.int8) * 2` остаётся `int8`, а не расширяется. Если же Python-число не помещается в dtype массива, вместо молчаливого переполнения выбрасывается `OverflowError`.

## Явное приведение

`a.astype(dtype)` создаёт **копию** с новым типом. Приведение вещественного к целому **отбрасывает дробную часть к нулю** (`1.9` становится `1`, `-1.9` становится `-1`), а не округляет; для округления используйте `np.rint` или `np.round`. Если значение не помещается в целевой тип, поведение для вещественных чисел не определено языком C: не полагайтесь на него, а сначала ограничьте значения (`np.clip`). Приведение целого к более узкому целому берёт младшие биты. Явный `dtype=` в конструкторе (`np.array(..., dtype=...)`, `np.zeros(..., dtype=...)`) задаёт тип при создании.

## Точность вещественных чисел

`np.finfo(np.float64).eps` примерно равно `2.2e-16` — это расстояние от 1.0 до следующего представимого числа; для `float32` оно примерно `1.2e-7`. Большие числа представимы ещё грубее: у `float32` целые выше `2^24 = 16777216` уже не все представимы. Сравнивайте вещественные результаты через `np.isclose` / `np.allclose` с явными `rtol` и `atol`, а не через `==`.

## Примеры

**Пример 1. Заворачивание целых и Python-int.**

```python run
import numpy as np

a = np.array([100, 127, -128], dtype=np.int8)
b = np.array([100, 1, -1], dtype=np.int8)
print((a + b).tolist())
print(np.iinfo(np.int8).min, np.iinfo(np.int8).max, np.iinfo(np.uint8).max)

u = np.array([250, 255], dtype=np.uint8)
print((u + np.uint8(10)).tolist())
print("Python int без границ:", 250 + 10, 2 ** 64)
wide = u.astype(np.int64) + 10
print("после расширения:", wide.tolist(), wide.dtype)
```
```output
[-56, -128, 127]
-128 127 255
[4, 9]
Python int без границ: 260 18446744073709551616
после расширения: [260, 265] int64
```

Первый результат: `100 + 100 = 200` превратилось в -56, `127 + 1` — в -128, `-128 + (-1)` — в 127. Обратите внимание, что ошибки не было.

**Пример 2. Правила приведения.**

```python run
import numpy as np

pairs = [("int8", "uint8"), ("int64", "float32"), ("bool", "int8"), ("uint64", "int64"), ("int16", "float32")]
for x, y in pairs:
    print(f"{x:>6} + {y:<8}->", np.result_type(x, y))

a = np.array([1, 2, 3], dtype=np.int8)
print((a * 2).dtype, (a * 2.5).dtype, (a / 2).dtype)
print((np.array([1.5], dtype=np.float32) * 2).dtype)
```
```output
  int8 + uint8   -> int16
 int64 + float32 -> float64
  bool + int8    -> int8
uint64 + int64   -> float64
 int16 + float32 -> float32
int8 float64 float64
float32
```

**Пример 3. astype и округление.**

```python run
import numpy as np

x = np.array([1.9, -1.9, 0.5, 2.5, 3.5])
print("astype:", x.astype(np.int64).tolist())
print("rint:  ", np.rint(x).astype(np.int64).tolist())
print("целое в узкий тип:", np.array([300, -1, 255]).astype(np.uint8).tolist())

y = x.astype(np.float32)
print(y.dtype, x.dtype, y is x, np.shares_memory(x, y))
```
```output
astype: [1, -1, 0, 2, 3]
rint:   [2, -2, 0, 2, 4]
целое в узкий тип: [44, 255, 255]
float32 float64 False False
```

Обратите внимание: `rint` округляет половинки к чётному (`0.5` даёт `0`, `2.5` даёт `2`, `3.5` даёт `4`), а `astype` просто отбрасывает дробную часть. Приведение `astype` всегда создаёт копию.

**Пример 4. Точность float.**

```python run
import numpy as np

print(0.1 + 0.2 == 0.3, np.isclose(0.1 + 0.2, 0.3, rtol=1e-9, atol=0.0))
print("eps64 = %.3e, eps32 = %.3e" % (np.finfo(np.float64).eps, np.finfo(np.float32).eps))
big = np.float32(16777216.0)
print("float32: 2**24 + 1 == 2**24:", big + np.float32(1.0) == big)
print("float64: 2**24 + 1 == 2**24:", np.float64(16777216.0) + 1.0 == 16777216.0)
print("float32: 0.1 хранится как", np.float32(0.1).item())
```
```output
False True
eps64 = 2.220e-16, eps32 = 1.192e-07
float32: 2**24 + 1 == 2**24: True
float64: 2**24 + 1 == 2**24: False
float32: 0.1 хранится как 0.10000000149011612
```

## Типичные ошибки

* **Складывать `uint8`-изображения «как есть».** `200 + 100` даёт 44. Сначала расширьте тип (`astype(np.int64)` или `np.float32`), потом считайте, потом ограничьте обратно.
* **Ожидать ошибки при переполнении.** Для массивов её нет. Проверяйте диапазоны сами (`np.iinfo`) или считайте в более широком типе.
* **Приводить вещественные к целым через `astype` и ждать округления.** `astype` отбрасывает дробную часть; округляйте явно `np.rint`.
* **`astype(np.uint8)` для значений вне диапазона.** Для вещественных это неопределённое поведение; сначала `np.clip`.
* **Сравнивать вещественные через `==`.** Используйте `np.isclose` / `np.allclose` с осознанным допуском.
* **Считать, что `a / 2` для целого массива даёт целые.** Оператор `/` возвращает вещественные числа; для целочисленного деления есть `//`.
* **Забывать про Python-скаляры в NumPy 2.** `np.int8`-массив, умноженный на `1000`, больше не расширяется молча: будет `OverflowError`.

<!-- section: summary -->
## Итоги

* У массива один dtype; целые имеют диапазон, и арифметика идёт по модулю `2^N` без предупреждений для массивов.
* Python `int` не ограничен; `np.int64` заворачивается на границе `2^63`.
* Общий тип операции определяет `np.result_type`; `/` всегда даёт вещественный результат.
* `astype` копирует и отбрасывает дробную часть; округляйте `np.rint`, а значения вне диапазона сначала обрезайте `np.clip`.
* Вещественные числа конечной точности: сравнивайте через `np.isclose` с явными допусками.
