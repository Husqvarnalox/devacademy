## Как NumPy «растягивает» массивы разной формы

Допустим, вы хотите вычесть среднее каждого столбца из матрицы `3 × 4`. Среднее — это массив из четырёх чисел, а матрица — двенадцать. Формально размеры не совпадают, но NumPy всё равно выполнит вычитание: он «растянет» вектор средних вдоль строк, как будто повторил его три раза. На самом деле ничего не повторяется и не копируется: растянутая ось получает шаг `strides = 0`, то есть одно и то же значение читается много раз. Этот механизм называется **broadcasting** (вещание).

Broadcasting делает код короче и быстрее, но он же — главный источник тихих ошибок. Если формы «случайно» совместимы, NumPy не скажет ни слова, а ответ окажется неверным. Классический пример: матрица `3 × 3` и вектор длины 3 всегда совместимы, но вектор растягивается вдоль **строк** (по последней оси), а не вдоль столбцов. Поэтому думайте о формах явно и проверяйте их.

<!-- section: precise -->
## Правила broadcasting

Для двух массивов NumPy сравнивает формы **справа налево** (с последней оси):

1. Если у массивов разное число осей, у более короткой формы слева дописываются оси длины 1.
2. Для каждой оси длины должны быть **равны, либо одна из них равна 1**. Иначе возникает `ValueError`.
3. Длина результата вдоль оси — наибольшая из двух. Ось длины 1 растягивается до этой длины.

Примеры: `(3, 4)` и `(4,)` дают `(3, 4)`; `(3, 1)` и `(1, 4)` дают `(3, 4)`; `(8, 1, 6, 1)` и `(7, 1, 5)` дают `(8, 7, 6, 5)`; `()` (скаляр) совместим с любой формой. Несовместимы: `(3,)` и `(4,)`; `(2, 3)` и `(3, 2)`; `(4, 3)` и `(4,)`, потому что 3 и 4 при выравнивании справа не равны и не равны 1.

## Управление осями: newaxis и keepdims

Чтобы выровнять оси нужным образом, добавляют ось длины 1 через `np.newaxis` (или `None`): `x[:, None]` превращает вектор `(n,)` в столбец `(n, 1)`. Результат `x[:, None] + y[None, :]` имеет форму `(n, m)` — это внешняя сумма. Редукции с параметром `keepdims=True` сохраняют ось длины 1: `a.sum(axis=1, keepdims=True)` имеет форму `(n, 1)` и поэтому корректно делит строки. Без `keepdims` результат `(n,)` выравнивается по последней оси и делит **столбцы**.

## Память и скорость

Broadcasting не копирует данные входов, но промежуточный результат (например, разность формы `(n, m, d)` в задаче о расстояниях) создаётся целиком. На больших размерах это память `n·m·d`, и иногда применяют блочную обработку. Явные циклы по осям, как правило, хуже, но когда массив промежуточных значений не помещается в память, цикл по блокам — нормальное решение.

## Примеры

**Пример 1. Правила и ошибки.**

```python run
import numpy as np

print(np.broadcast_shapes((3, 4), (4,)))
print(np.broadcast_shapes((3, 1), (1, 4)))
print(np.broadcast_shapes((8, 1, 6, 1), (7, 1, 5)))

for s1, s2 in [((3,), (4,)), ((2, 3), (3, 2)), ((4, 3), (4,))]:
    try:
        np.broadcast_shapes(s1, s2)
    except ValueError as e:
        print("ValueError:", s1, s2)

a = np.ones((3, 4))
try:
    a + np.ones(3)
except ValueError as e:
    print(str(e).split(" with shapes")[0])
```
```output
(3, 4)
(3, 4)
(8, 7, 6, 5)
ValueError: (3,) (4,)
ValueError: (2, 3) (3, 2)
ValueError: (4, 3) (4,)
operands could not be broadcast together
```

**Пример 2. Центрирование столбцов.**

```python run
import numpy as np

a = np.array([[1.0, 10.0, 100.0],
              [3.0, 20.0, 200.0],
              [5.0, 60.0, 300.0]])
means = a.mean(axis=0)
print("means:", means, means.shape)
centered = a - means           # (3, 3) - (3,) -> (3, 3), выравнивание по последней оси
print(centered)
print("средние после равны нулю:", np.allclose(centered.mean(axis=0), 0.0, rtol=0, atol=1e-12))
```
```output
means: [  3.  30. 200.] (3,)
[[  -2.  -20. -100.]
 [   0.  -10.    0.]
 [   2.   30.  100.]]
средние после равны нулю: True
```

**Пример 3. Тихая ошибка на квадратной матрице.** Нормируем строки на их суммы двумя способами.

```python run
import numpy as np

a = np.array([[1.0, 2.0, 1.0],
              [4.0, 4.0, 0.0],
              [3.0, 3.0, 6.0]])
sums = a.sum(axis=1)                 # [4, 8, 12], форма (3,)
wrong = a / sums                     # делит СТОЛБЦЫ на 4, 8, 12 - ошибки нет!
right = a / a.sum(axis=1, keepdims=True)
print("строки, неверно:", wrong.sum(axis=1))
print("строки, верно:  ", right.sum(axis=1))

b = np.ones((3, 4))
print("(3,4)/(3,) -> ", end="")
try:
    b / b.sum(axis=1)
except ValueError:
    print("ValueError - на прямоугольной матрице ошибка заметна")
```
```output
строки, неверно: [0.58333333 1.5        1.625     ]
строки, верно:   [1. 1. 1.]
(3,4)/(3,) -> ValueError - на прямоугольной матрице ошибка заметна
```

**Пример 4. Внешняя сумма и таблица умножения.**

```python run
import numpy as np

x = np.arange(1, 4)
y = np.arange(1, 5)
print((x[:, None] * y[None, :]))
print((x[:, None] + y).shape, (x[:, None, None] + y[None, :, None]).shape)
```
```output
[[ 1  2  3  4]
 [ 2  4  6  8]
 [ 3  6  9 12]]
(3, 4) (3, 4, 1)
```

## Типичные ошибки

* **Деление строк на вектор сумм без `keepdims`.** На квадратной матрице это не даёт ошибки и тихо делит столбцы. Используйте `keepdims=True` или `[:, None]`.
* **Путать `axis=0` и `axis=1`.** `axis=0` сворачивает строки (результат — по столбцам), `axis=1` — столбцы. Проверяйте на несимметричной матрице неквадратной формы.
* **Полагаться на то, что формы «подойдут сами».** Если вы не можете сказать форму результата заранее, добавьте `assert x.shape == ...` или проверьте на маленьком примере.
* **Сравнивать `(n,)` и `(n, 1)`.** Операция между ними даёт матрицу `(n, n)`, а не вектор: типичная причина неожиданного расхода памяти и неверных значений.
* **Ожидать, что broadcasting изменит исходный массив.** Он создаёт результат; растянутое представление нельзя использовать для записи.
* **Создавать огромный промежуточный массив.** `(n, m, d)` при больших `n` и `m` не помещается в память; тогда считайте блоками.

<!-- section: summary -->
## Итоги

* Формы выравниваются справа; на каждой оси длины должны быть равны или одна из них равна 1.
* Растянутая ось не копируется (шаг 0), но результат операции создаётся целиком.
* `x[:, None]`, `x[None, :]` и `keepdims=True` управляют тем, по какой оси идёт растягивание.
* На квадратных матрицах неверная ось не даёт ошибки: проверяйте на неквадратных данных и сверяйте формы.
* Несовместимые формы вызывают `ValueError` с сообщением «operands could not be broadcast together».
