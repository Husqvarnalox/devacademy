## Матрицы вместо циклов

Почти всё машинное обучение — это линейная алгебра: данные лежат в матрице `X` (строка — объект, столбец — признак), параметры модели — в векторе или матрице `W`, а предсказания получаются умножением `X @ W`. NumPy умеет выполнять такие операции целиком, причём тяжёлые умножения делегирует оптимизированным библиотекам линейной алгебры (BLAS и LAPACK).

Два главных оператора легко перепутать. **`*` — поэлементное** произведение: элементы с одинаковыми позициями перемножаются. **`@` — матричное** произведение: строки левой матрицы скалярно умножаются на столбцы правой. На квадратных матрицах обе операции допустимы и дают разные ответы, и никакой ошибки не будет.

Второй важный навык — решать системы уравнений `A x = b`. Школьный способ «найти `A^{-1}` и умножить» в численной практике почти не используют: `np.linalg.solve(A, b)` быстрее, точнее и надёжнее. Наконец, длину вектора и расстояние между векторами измеряют **нормами**.

## Умножение и формы

Для `A` формы `(m, n)` и `B` формы `(n, k)` произведение `A @ B` имеет форму `(m, k)`: `C[i, j] = Σ_t A[i, t] · B[t, j]`. Внутренние размеры (`n`) должны совпадать, иначе `ValueError`. Для одномерных операндов NumPy применяет правила: `(n,) @ (n,)` даёт скаляр (скалярное произведение); `(n,) @ (n, k)` даёт `(k,)` (вектор трактуется как строка); `(m, n) @ (n,)` даёт `(m,)` (вектор — как столбец). Оператор `@` вызывает `np.matmul`; для 2D массивов он совпадает с `np.dot`, но для массивов большей размерности они отличаются, поэтому для матриц предпочтительнее `@`.

Поэлементное `A * B` требует совместимых по [broadcasting](lesson:python.numpy.broadcasting) форм и возвращает массив формы результата broadcasting. Аффинное преобразование слоя в ML записывают как `X @ W + b`, где `X` — `(n, d)`, `W` — `(d, k)`, `b` — `(k,)`; сложение с `b` работает за счёт broadcasting.

## Решение линейных систем

Для квадратной невырожденной `A` система `A x = b` решается через `np.linalg.solve(A, b)`: LAPACK выполняет LU-разложение с частичным выбором главного элемента и подстановки. Обращение `inv(A) @ b` делает больше работы (оно строит всю обратную матрицу, примерно втрое больше арифметических операций) и накапливает больше погрешности: остаток `A x - b` у `solve` порядка машинной точности даже на плохо обусловленных матрицах, а у `inv(A) @ b` может быть на порядки больше. Явная обратная матрица нужна редко (например, когда сама `A^{-1}` — результат задачи). Для вырожденной матрицы `solve` бросает `numpy.linalg.LinAlgError`.

Важно различать два источника ошибки. **Число обусловленности** `cond(A) = ‖A‖ · ‖A^{-1}‖` показывает, насколько решение чувствительно к возмущениям данных; ошибка решения может достигать порядка `cond(A) · eps`. Это свойство задачи, и ни один алгоритм его не отменит. Но хороший алгоритм (`solve`) не добавляет ошибок сверх неизбежной, а `inv` добавляет.

## Нормы

`np.linalg.norm(x)` для вектора — евклидова норма (`ord=2`) `√Σ x_i²`; `ord=1` — сумма модулей; `ord=np.inf` — максимум модулей. Для матрицы без `axis` по умолчанию возвращается норма Фробениуса. Параметры `axis=1` и `keepdims=True` считают нормы строк и позволяют сразу нормировать строки: `x / np.linalg.norm(x, axis=1, keepdims=True)` (нулевую строку нужно обработать отдельно). Скалярное произведение нормированных векторов — косинусное сходство.

## Примеры

**Пример 1. `*` против `@`.**

```python run
import numpy as np

A = np.array([[1, 2], [3, 4]])
B = np.array([[0, 1], [1, 0]])
print("A * B:\n", A * B)
print("A @ B:\n", A @ B)
x = np.array([1, 2, 3])
print("скалярное произведение:", x @ x, "np.dot:", np.dot(x, x))
X = np.arange(6).reshape(2, 3)
W = np.ones((3, 4))
print((X @ W).shape, (X @ W + np.arange(4)).shape)
try:
    X @ X
except ValueError as e:
    print("ValueError: внутренние размеры 3 и 2 не совпадают")
```
```output
A * B:
 [[0 2]
 [3 0]]
A @ B:
 [[2 1]
 [4 3]]
скалярное произведение: 14 np.dot: 14
(2, 4) (2, 4)
ValueError: внутренние размеры 3 и 2 не совпадают
```

**Пример 2. solve.**

```python run
import numpy as np

A = np.array([[3.0, 1.0], [1.0, 2.0]])
b = np.array([9.0, 8.0])
x = np.linalg.solve(A, b)
print("x =", x, "проверка A @ x:", A @ x)
print("совпадает с inv(A) @ b:", np.allclose(x, np.linalg.inv(A) @ b, rtol=1e-12, atol=1e-12))

try:
    np.linalg.solve(np.array([[1.0, 2.0], [2.0, 4.0]]), b)
except np.linalg.LinAlgError:
    print("вырожденная матрица -> LinAlgError")
```
```output
x = [2. 3.] проверка A @ x: [9. 8.]
совпадает с inv(A) @ b: True
вырожденная матрица -> LinAlgError
```

**Пример 3. solve против inv на плохо обусловленной матрице.** Матрица Гильберта размера 10 имеет `cond ≈ 10^13`.

```python run
import numpy as np

n = 10
H = 1.0 / (np.arange(1, n + 1)[:, None] + np.arange(n)[None, :])
x_true = np.ones(n)
b = H @ x_true
print("порядок cond:", int(np.log10(np.linalg.cond(H))))

x_solve = np.linalg.solve(H, b)
x_inv = np.linalg.inv(H) @ b
res_solve = np.linalg.norm(H @ x_solve - b)
res_inv = np.linalg.norm(H @ x_inv - b)
print("остаток solve < 1e-12:", res_solve < 1e-12)
print("остаток inv больше остатка solve более чем в 100 раз:", res_inv > 100 * res_solve)
print("решение неточно в обоих случаях (cond большое):", np.linalg.norm(x_solve - x_true) > 1e-6)
```
```output
порядок cond: 13
остаток solve < 1e-12: True
остаток inv больше остатка solve более чем в 100 раз: True
решение неточно в обоих случаях (cond большое): True
```

Остаток `solve` — порядка машинной точности, хотя сам ответ далёк от точного: это свойство задачи (число обусловленности), а не алгоритма. Конкретные значения погрешности зависят от версии BLAS/LAPACK, поэтому печатаем только сравнения.

**Пример 4. Нормы и нормировка строк.**

```python run
import numpy as np

a = np.array([[3.0, 4.0], [1.0, -1.0], [0.0, 0.0]])
print("L2:", np.linalg.norm(a, axis=1))
print("L1:", np.linalg.norm(a, ord=1, axis=1), "Linf:", np.linalg.norm(a, ord=np.inf, axis=1))
norms = np.linalg.norm(a, axis=1, keepdims=True)
unit = np.divide(a, norms, out=np.zeros_like(a), where=norms != 0)
print(np.round(unit, 4))
print("Фробениус = sqrt(сумма квадратов):", np.isclose(np.linalg.norm(a), np.sqrt((a ** 2).sum()), rtol=1e-12, atol=0.0))
cos = unit[0] @ unit[1]
print("косинусное сходство первых двух строк: %.4f" % cos)
```
```output
L2: [5.         1.41421356 0.        ]
L1: [7. 2. 0.] Linf: [4. 1. 0.]
[[ 0.6     0.8   ]
 [ 0.7071 -0.7071]
 [ 0.      0.    ]]
Фробениус = sqrt(сумма квадратов): True
косинусное сходство первых двух строк: -0.1414
```

## Типичные ошибки

* **`*` вместо `@`.** На квадратных матрицах нет ошибки, но ответ неверный. Тестируйте на квадратных несимметричных данных, где разница видна.
* **Решать систему через `inv(A) @ b`.** Это медленнее и менее точно; используйте `np.linalg.solve`.
* **Путать вектор `(n,)`, строку `(1, n)` и столбец `(n, 1)`.** Формы определяют результат `@` и broadcasting; приводите их явно через `reshape` или `[:, None]`.
* **Сравнивать решения через `==`.** Проверяйте остаток `A @ x - b` или `np.allclose` с явными допусками.
* **Не обрабатывать нулевые строки при нормировке.** Деление на нулевую норму даёт `nan`.
* **Путать норму Фробениуса и спектральную норму.** Для матрицы `norm(A)` без `ord` — Фробениус; `ord=2` — наибольшее сингулярное число.
* **Игнорировать число обусловленности.** Большой `cond` означает, что решение чувствительно к шуму в данных, и ни `solve`, ни другие алгоритмы этого не исправят.

<!-- section: summary -->
## Итоги

* `*` — поэлементное, `@` — матричное произведение; результат `(m, n) @ (n, k)` имеет форму `(m, k)`.
* Аффинное преобразование: `X @ W + b`; сложение с `b` работает через broadcasting.
* Для `A x = b` используйте `np.linalg.solve`: она быстрее и точнее, чем `inv(A) @ b`; вырожденная матрица даёт `LinAlgError`.
* Число обусловленности — свойство задачи; остаток `solve` мал, даже если решение неточно.
* `np.linalg.norm` с `axis` и `keepdims` считает нормы строк и нормирует их.
