## Что скрипт расскажет о себе - и что не должен

Когда скрипт работает ночью без вас, у вас есть два канала связи с ним: **журнал** (что произошло) и **конфигурация** (как он должен работать). Оба легко сделать плохо:

* журнал из `print("ok")` бесполезен, а журнал с паролем - уязвимость;
* конфигурация, зашитая в код, требует правки программы при смене сервера, а пароль в коде попадает в репозиторий навсегда.

Правила урока:

* **Структурные журналы.** Каждая запись - одна строка JSON с полями (`level`, `message`, `job_id`, ...): по ним можно искать и считать. Человеку остаётся читаемый вывод в консоль для разработки.
* **Уровни по окружениям.** В разработке `DEBUG`, в продакшене `INFO` или `WARNING`; уровень задаётся конфигурацией, а не правкой кода.
* **Конфигурация из нескольких источников с понятным приоритетом:** значения по умолчанию < файл < переменные окружения. И строгая проверка при старте: неверный порт - ошибка сразу, а не через час.
* **Секреты не живут в коде, не печатаются и не попадают в журнал.** Они приходят из окружения или хранилища секретов, оборачиваются в тип, который скрывает значение, а на журнале стоит фильтр-страховка.

Это продолжение темы [subprocess и logging](lesson:python.stdlib.subprocess-and-logging), где вы познакомились с самим модулем. Задачи из урока про [расписание](lesson:python.automation.scheduling-and-long-running-jobs) без журнала невозможно эксплуатировать.

## Устройство и правила

**Уровни и обработчики.** Числовые уровни: `DEBUG` 10, `INFO` 20, `WARNING` 30, `ERROR` 40, `CRITICAL` 50. Запись должна пройти порог логгера, затем порог каждого обработчика. Типичная схема: логгер `DEBUG`, консольный обработчик по уровню из конфигурации, файловый (с ротацией, `logging.handlers.RotatingFileHandler`) - `INFO`. Настройку делают один раз при старте программы в точке входа, а не в библиотечном коде. Сообщения пишите с ленивой подстановкой: `log.info("загружено %d строк", n)`, а не f-строкой: форматирование происходит только если запись принята, а значения остаются отдельными аргументами (их видит фильтр).

**Структурные записи.** Подкласс `logging.Formatter` переопределяет `format(record)` и возвращает `json.dumps({...})`. Поля из `extra={"job_id": 7}` становятся атрибутами `LogRecord`; чтобы отличить их от стандартных, сравнивают с атрибутами пустой записи. Ключи `extra` не должны совпадать с атрибутами записи (иначе `KeyError`). Исключение (`log.exception(...)` или `exc_info=True`) форматируют в одно поле `exc`, чтобы запись осталась одной строкой. JSON-строка удобна для систем сбора журналов (одна строка - одно событие), `sort_keys=True` делает вывод стабильным, `default=str` не даёт упасть на нестандартном типе.

**Источники конфигурации.** Порядок: значения по умолчанию (в коде) < файл (`tomllib` читает TOML: типизированные числа, булевы, таблицы) < переменные окружения (всегда строки, поэтому нужно приведение и разбор) < аргументы командной строки. Правила хорошей загрузки:

* *Валидация при старте* и *сбор всех ошибок*: пользователь исправляет конфигурацию за один проход, а не по одной ошибке за запуск.
* *Строгость к опечаткам*: неизвестный ключ в файле или `APP_PORTT` в окружении - ошибка, а не молчаливое игнорирование.
* *Типы*: `bool("false")` истинно; булевы значения разбирают по списку слов. `True` в Python - это `int`, поэтому порт `true` в файле нужно отвергнуть явно.
* *Неизменяемый результат*: `@dataclass(frozen=True)`.
* *Тестируемость*: загрузчик принимает `env` как параметр (словарь), а не читает `os.environ` внутри; в боевом коде ему передают `os.environ`.

**Секреты.** Не хранят: в коде, в репозитории (включая `.env` с реальными значениями; добавьте `.env` в `.gitignore`, а в репозитории держите `.env.example` с вымышленными), в образах контейнеров, в аргументах командной строки (их видно в списке процессов). Хранят: в переменных окружения процесса, в хранилище секретов (облачный секрет-менеджер, Vault, секреты оркестратора), в файле вне репозитория с правами только для владельца. Файл `.env` - удобство локальной разработки: формат `KEY=VALUE`, комментарии `#`, кавычки; его читает сторонний пакет `python-dotenv` (в курсе не запускается) или собственный небольшой разбор, как в упражнении. Секрет, попавший в репозиторий или журнал, считается скомпрометированным: его *отзывают и заменяют*, удалением коммита дело не решается.

**Не допустить утечки в журнал.** Три уровня защиты:

1. *Не передавать секрет в журнал вообще*: не логировать заголовки запросов целиком, не печатать конфигурацию «для отладки» без маскирования.
2. *Тип-обёртка*: `Secret` с `__repr__`/`__str__`, возвращающими `***`; значение отдаёт только явный `reveal()`. Тогда `print(config)` и `log.info("%s", config)` безопасны.
3. *Фильтр `logging.Filter`* на обработчике: заменяет в тексте сообщения известные значения секретов, маскирует поля с «чувствительными» именами (`password`, `token`, `authorization`, `api_key`...) и очищает traceback (исключение может содержать URL с ключом). Фильтр - страховка: он не знает о секретах, которых нет в его списке, и о форматах, которые вы не предусмотрели. Те же сообщения об ошибках конфигурации не должны включать значения параметров.

**Прочее.** Не логируйте персональные данные без необходимости (минимизация); в записи каждого запуска полезны идентификатор запуска и версия программы; уровни ошибок согласуйте с мониторингом (`ERROR` - требует внимания). Для кода возврата и аварий см. урок о [расписании](lesson:python.automation.scheduling-and-long-running-jobs).

## Примеры

**Пример 1. Структурный JSON-лог с extra и исключением.**

```python run
import io
import json
import logging


class JsonFormatter(logging.Formatter):
    STANDARD = set(logging.LogRecord("n", 0, "p", 0, "m", (), None).__dict__) | {"message", "asctime", "taskName"}

    def format(self, record):
        payload = {"level": record.levelname, "logger": record.name, "message": record.getMessage()}
        payload.update({k: v for k, v in record.__dict__.items() if k not in self.STANDARD})
        if record.exc_info:
            payload["exc"] = self.formatException(record.exc_info).splitlines()[-1]
        return json.dumps(payload, ensure_ascii=False, sort_keys=True, default=str)


stream = io.StringIO()
handler = logging.StreamHandler(stream)
handler.setFormatter(JsonFormatter())
log = logging.getLogger("nightly")
log.addHandler(handler)
log.setLevel(logging.INFO)
log.propagate = False

log.info("обработано %d строк", 120, extra={"job_id": 7})
log.debug("это не попадёт: уровень ниже порога")
try:
    1 / 0
except ZeroDivisionError:
    log.exception("сбой шага", extra={"step": "divide"})
print(stream.getvalue(), end="")
```
```output
{"job_id": 7, "level": "INFO", "logger": "nightly", "message": "обработано 120 строк"}
{"exc": "ZeroDivisionError: division by zero", "level": "ERROR", "logger": "nightly", "message": "сбой шага", "step": "divide"}
```

**Пример 2. Приоритет источников: default < файл (tomllib) < окружение.**

```python run
import tomllib

DEFAULTS = {"port": 8080, "debug": False, "log_level": "INFO"}
file_text = """
port = 9000
log_level = "DEBUG"
"""
env = {"APP_PORT": "443", "APP_DEBUG": "yes", "HOME": "/ignored"}


def to_bool(text):
    words = {"1": True, "true": True, "yes": True, "on": True, "0": False, "false": False, "no": False, "off": False}
    return words[text.lower()]


config = dict(DEFAULTS)
config.update(tomllib.loads(file_text))
if "APP_PORT" in env:
    config["port"] = int(env["APP_PORT"])
if "APP_DEBUG" in env:
    config["debug"] = to_bool(env["APP_DEBUG"])
print(config)
print("bool('false') =", bool("false"), "- поэтому слова разбирают явно")
```
```output
{'port': 443, 'debug': True, 'log_level': 'DEBUG'}
bool('false') = True - поэтому слова разбирают явно
```

**Пример 3. Secret и фильтр маскирования.**

```python run
import io
import logging


class Secret:
    def __init__(self, value):
        self._value = value

    def reveal(self):
        return self._value

    def __repr__(self):
        return "Secret(***)"

    __str__ = __repr__


class Redact(logging.Filter):
    def __init__(self, secrets):
        super().__init__()
        self.secrets = [s for s in secrets if s]

    def filter(self, record):
        text = record.getMessage()
        for secret in self.secrets:
            text = text.replace(secret, "***")
        record.msg, record.args = text, ()
        return True


token = Secret("abc123")
stream = io.StringIO()
handler = logging.StreamHandler(stream)
handler.addFilter(Redact([token.reveal()]))
log = logging.getLogger("secrets-demo")
log.addHandler(handler)
log.setLevel(logging.INFO)
log.propagate = False

log.info("токен в объекте: %s", token)
log.info("а это утечка в строке: %s", token.reveal())
log.info("url=https://api.example/?key=abc123&x=1")
print(stream.getvalue(), end="")
print(repr({"api_token": token}))
```
```output
токен в объекте: Secret(***)
а это утечка в строке: ***
url=https://api.example/?key=***&x=1
{'api_token': Secret(***)}
```

## Типичные ошибки

* **Пароль или токен в коде и в репозитории.** Он остаётся в истории Git навсегда. Секрет отзывают и заменяют; конфигурацию берут из окружения.
* **`print` вместо `logging`.** Нет уровней, времени, обработчиков; вывод нельзя отфильтровать или перенаправить.
* **f-строки в сообщениях журнала.** Форматирование выполняется даже для отброшенных записей, а фильтры не видят аргументы. Используйте `%s` и аргументы.
* **Логирование конфигурации и заголовков «для отладки».** В журнал попадают токены. Печатайте через `Secret` и маскируйте.
* **Секрет в аргументах командной строки.** Он виден в списке процессов и в истории оболочки; передавайте через окружение или файл.
* **Чтение `os.environ` по всему коду.** Невозможно тестировать и проверять конфигурацию. Загружайте и проверяйте один раз при старте, передавайте объект конфигурации.
* **`bool(os.environ["DEBUG"])`.** Строка `"false"` истинна. Разбирайте слова явно.
* **Проглатывание неизвестных ключей.** Опечатка `APP_PORTT` молча игнорируется, и скрипт работает с портом по умолчанию.
* **Остановка на первой ошибке конфигурации.** Пользователь исправляет по одной ошибке за запуск. Соберите все.
* **Уверенность в фильтре как единственной защите.** Он не знает неизвестных секретов и изменённых форматов (base64, части токена). Первая линия обороны - не логировать секреты.
* **`.env` с реальными значениями в репозитории.** Добавьте в `.gitignore` и храните `.env.example`.

<!-- section: summary -->
## Итог

* Журнал - структурные JSON-записи с `extra`, уровни из конфигурации; сообщения с `%s` и аргументами.
* Конфигурация: default < файл (`tomllib`) < окружение, с приведением типов, строгими ключами, сбором всех ошибок и неизменяемым результатом; `env` передаётся параметром.
* Секреты не хранятся в коде и репозитории, приходят из окружения или хранилища, оборачиваются в `Secret`, а `logging.Filter` маскирует остатки (включая traceback). Скомпрометированный секрет заменяют.
* `.env` и `python-dotenv` - удобство разработки, не хранилище для продакшена.
* Дальше: [этичное извлечение данных](lesson:python.automation.web-data-extraction-ethics) - автоматизация, которая уважает правила чужих сервисов.
