## Файл больше памяти, а строк с ошибками много

Типичная задача автоматизации: каждую ночь приходит выгрузка из учётной системы - миллионы строк CSV. Нужно проверить данные, посчитать итоги и выдать отчёт. Три способа сломать такой скрипт:

* прочитать всё в память (`f.read()`, `list(reader)`) - на большом файле процесс упадёт;
* упасть на первой же плохой строке и ничего не выдать;
* молча пропустить плохие строки и выдать красивые, но неправильные итоги.

Правильный скрипт читает файл **потоком**, держит в памяти только текущую запись и итоги, **проверяет каждую строку**, а плохие складывает в отдельный отчёт с номером строки, полем и причиной. Итоги и ошибки записываются в файлы, которые можно открыть, сравнить и положить в архив.

Основы формата вы уже видели в уроке [«json, csv, struct»](lesson:python.stdlib.json-csv-struct); здесь они применяются к потоку данных. Запись результатов делается так же осторожно, как перемещение файлов в [предыдущем уроке](lesson:python.automation.file-automation).

## Устройство надёжного конвейера

**Потоковое чтение.** `csv.reader(источник)` и `csv.DictReader(источник)` принимают любой итерируемый объект строк и берут по записи за раз. Источник - файл, открытый как `open(path, encoding="utf-8-sig", newline="")`, либо генератор. Память растёт только от того, что вы сами накапливаете. Ломают потоковость: `f.read()`, `f.readlines()`, `list(reader)`, `sorted(reader)`, а также неограниченное накопление списка ошибок. Группировки (словарь «месяц -> сумма») растут с числом различных ключей, а не строк. Проверка уникальности по всему файлу требует множества всех виденных значений - это сознательный компромисс по памяти (или внешнее хранилище вроде `sqlite3`).

**Кодировки и BOM.** Файл из Excel нередко начинается с метки порядка байт. Кодировка `utf-8-sig` при чтении её удаляет; `utf-8` оставит символ `﻿` в имени первого столбца, и `row["id"]` внезапно даст `KeyError`. Кодировку нужно задавать явно, а не полагаться на локаль системы. Если файл приходит в неизвестной кодировке, лучше потребовать у источника фиксированную; угадывание ненадёжно.

**Валидация.** Для каждой строки: тип и диапазон (`id` - целое > 0), обязательность (непустое имя), формат (`date.fromisoformat` принимает несколько форм записи, поэтому дополнительно проверяют длину строки 10), точность денег. Деньги разбираются в `Decimal`: `Decimal("abc")` поднимает `InvalidOperation`, а `"NaN"` и `"Infinity"` разбираются успешно, поэтому нужна проверка `is_finite()`. Число знаков проверяют сравнением `amount == amount.quantize(Decimal("0.01"))`.

**Ошибки как данные.** Валидатор поднимает исключение уровня строки (`RowError` с полем и причиной), а внешний цикл его ловит, увеличивает счётчик `rows_bad` и добавляет запись `{line, field, error}`. Номер строки берётся из `reader.line_num` (заголовок - 1; если запись занимает несколько физических строк, это последняя). Проверка «правильно ли число полей» делается через `restkey` (лишние поля) и `restval` (недостающие) у `DictReader`. Список ошибок усекают (`max_errors`), но счётчики хранят полные. Решение «пропустить или остановить пакет» принимается заранее: например, если плохих строк больше порога (скажем, 5%), весь вход считается испорченным и отчёт помечается как неудачный. Порог и поведение должны быть явными.

**Агрегаты и отчёты.** Агрегация идёт в том же цикле: счётчики, `Decimal`-суммы, `defaultdict(Decimal)` по ключу. Отчёт детерминирован: отсортированные ключи, фиксированный формат чисел (`f"{x:.2f}"`), `json.dumps(..., sort_keys=True, indent=2, ensure_ascii=False)`. Файлы пишутся в UTF-8 через временное имя и `os.replace`, чтобы читатель никогда не увидел полузаписанный отчёт. CSV-отчёт открывают с `newline=""`. Выход может быть и в форматах, которые стандартная библиотека не пишет (xlsx, docx): для этого существуют сторонние пакеты (например, `openpyxl`, `python-docx`) - они **не входят в этот курс** и не устанавливаются в его песочнице; принцип построения конвейера остаётся тем же.

**Повторяемость.** Конвейер должен быть идемпотентным: тот же вход даёт тот же отчёт байт в байт. Не вставляйте в отчёт текущее время без необходимости; если оно нужно (например, «сформирован в»), подавайте его параметром.

## Примеры

**Пример 1. Поток из генератора: память не растёт с числом строк.**

```python run
import csv
import tracemalloc
from decimal import Decimal


def source(n):
    yield "id,amount"
    for i in range(1, n + 1):
        yield f"{i},{i % 10}.50"


def total(lines):
    reader = csv.DictReader(lines)
    return sum((Decimal(row["amount"]) for row in reader), Decimal(0))


for n in (1_000, 50_000):
    tracemalloc.start()
    result = total(source(n))
    _, peak = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    print(n, result, "пик < 300 КБ:", peak < 300_000)
```
```output
1000 5000.00 пик < 300 КБ: True
50000 250000.00 пик < 300 КБ: True
```

**Пример 2. Плохие строки не роняют обработку; BOM; номера строк.**

```python run
import csv
from decimal import Decimal, InvalidOperation

lines = [
    "﻿id,amount",
    "1,10.5",
    "2,abc",
    "3,NaN",
    "4",
    "5,1,лишнее",
    "6,2.25",
]
reader = csv.DictReader((lines[0].lstrip("﻿"),) + tuple(lines[1:]), restkey="__extra", restval=None)
ok, errors, total = 0, [], Decimal(0)
for row in reader:
    line = reader.line_num
    if "__extra" in row or None in row.values():
        errors.append((line, "row", "неверное число полей"))
        continue
    try:
        amount = Decimal(row["amount"])
        if not amount.is_finite():
            raise InvalidOperation
    except InvalidOperation:
        errors.append((line, "amount", repr(row["amount"])))
        continue
    ok += 1
    total += amount
print("ok:", ok, "итого:", total)
for e in errors:
    print(e)
```
```output
ok: 2 итого: 12.75
(3, 'amount', "'abc'")
(4, 'amount', "'NaN'")
(5, 'row', 'неверное число полей')
(6, 'row', 'неверное число полей')
```

**Пример 3. Отчёты: детерминированный JSON и CSV, запись через временный файл.**

```python run
import csv
import json
import os
import tempfile
from pathlib import Path

summary = {"rows_ok": 2, "rows_bad": 1, "total": "12.75", "by_month": {"2024-02": "2.25", "2024-01": "10.50"}}
errors = [{"line": 3, "field": "amount", "error": "плохая сумма, 'abc'"}]

with tempfile.TemporaryDirectory(dir=".") as tmp:
    out = Path(tmp)
    path = out / "summary.json"
    tmp_path = path.with_name(path.name + ".tmp")
    tmp_path.write_text(json.dumps(summary, ensure_ascii=False, indent=2, sort_keys=True) + "\n", encoding="utf-8")
    os.replace(tmp_path, path)
    with open(out / "errors.csv", "w", encoding="utf-8", newline="") as fh:
        writer = csv.DictWriter(fh, fieldnames=["line", "field", "error"], lineterminator="\n")
        writer.writeheader()
        writer.writerows(errors)
    print(sorted(os.listdir(out)))
    print((out / "summary.json").read_text(encoding="utf-8"), end="")
    print((out / "errors.csv").read_text(encoding="utf-8"), end="")
```
```output
['errors.csv', 'summary.json']
{
  "by_month": {
    "2024-01": "10.50",
    "2024-02": "2.25"
  },
  "rows_bad": 1,
  "rows_ok": 2,
  "total": "12.75"
}
line,field,error
3,amount,"плохая сумма, 'abc'"
```

## Типичные ошибки

* **`list(reader)` или `readlines()` «чтобы было удобно».** Работает на тестовом файле и падает на боевом. Итерируйте читатель напрямую.
* **Исключение на первой плохой строке.** Один неправильный символ обнуляет работу ночи. Ловите ошибку строки и пишите её в отчёт.
* **Тихий пропуск.** Строка исчезла без следа, итоги занижены. Каждая пропущенная строка - запись в отчёте и счётчик.
* **`float` для денег.** Суммы дрейфуют в копейках. Используйте `Decimal` и фиксированный формат вывода.
* **`Decimal(x)` без `is_finite()`.** `NaN` и `Infinity` проходят как числа и портят итоги.
* **Кодировка «по умолчанию».** Результат зависит от локали машины; для файла с BOM первое имя столбца получает невидимый символ. Задавайте `encoding` и `newline=""`.
* **Неограниченный список ошибок.** На сломанном файле из миллиона строк список ошибок съедает память. Усекайте, но считайте все.
* **Запись отчёта прямо в итоговый файл.** При сбое остаётся обрезанный отчёт. Пишите во временный файл и `os.replace`.
* **Отчёт зависит от порядка словаря и времени запуска.** Результаты не сравнить между запусками. Сортируйте ключи, не вставляйте текущее время.
* **Номер строки по `enumerate`.** Запись с переводом строки в кавычках занимает несколько физических строк; используйте `reader.line_num`.

## Итог

* Читайте CSV потоком (`open(..., encoding="utf-8-sig", newline="")` и `csv.DictReader`), держите в памяти только текущую запись и итоги.
* Каждая строка валидируется отдельно; ошибка строки - данные отчёта (`line`, `field`, `error`), а не причина аварии; список ошибок усекается, счётчики полные.
* Деньги - `Decimal` с проверкой `is_finite()` и числом знаков; отчёты детерминированы и пишутся атомарно (временный файл + `os.replace`).
