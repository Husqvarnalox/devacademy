## Владение: у каждого значения один хозяин

Rust управляет памятью без сборщика мусора и без ручного `free`. Вместо этого компилятор проверяет три правила **владения** (ownership):

1. у каждого значения есть **владелец** - переменная;
2. владелец в каждый момент **один**;
3. когда владелец выходит из области видимости, значение **уничтожается** (вызывается `drop`).

Из этих правил следует **перемещение** (move). `let s2 = s1;` для `String` не копирует текст, а передаёт владение: `s1` после этого использовать нельзя.

```rust
fn main() {
    let s1 = String::from("hi");
    let s2 = s1;                // владение перешло к s2
    println!("{}", s1);         // ошибка компиляции
}
```

```
error[E0382]: borrow of moved value: `s1`
```

Если функции нужно только посмотреть или изменить значение, ей **одалживают** его - передают ссылку:

* `&T` - общая ссылка: читать можно, менять нельзя, таких ссылок может быть сколько угодно;
* `&mut T` - изменяемая ссылка: читать и менять можно, но она **единственная**, и в это время нет других ссылок.

<!-- section: precise -->
## Перемещение, заимствование и проверка заимствований

**Почему перемещение, а не копирование.** Если бы `s2 = s1` копировало только указатель, то при выходе из области видимости обе переменные освободили бы один и тот же буфер (двойное освобождение). Rust решает это правилом одного владельца: после перемещения `s1` недоступна, освобождает буфер только `s2`.

**Copy и Clone.** Простые типы (`i32`, `f64`, `bool`, `char`, кортежи из таких типов) реализуют трейт `Copy`: присваивание их копирует, и оригинал остаётся доступен. `String` и `Vec<T>` не `Copy`; чтобы получить глубокую копию, явно вызывают `.clone()`.

**Передача в функцию.** Передача по значению `f(s)` перемещает `s` внутрь функции, если тип не `Copy`. Вернуть владение можно, возвращая значение. Обычно удобнее заимствовать: `f(&s)` для чтения и `f(&mut s)` для изменения. Для параметров, которые только читаются, берут `&str` вместо `&String` и `&[T]` вместо `&Vec<T>`: так функция принимает больше видов аргументов.

**Правила заимствования.** В любой момент существует либо любое число `&T`, либо ровно одна `&mut T`. Ссылка не может пережить значение, на которое указывает. Эти правила проверяет **borrow checker** во время компиляции. Они исключают гонки данных и висячие указатели, а также ситуацию «изменяем коллекцию, пока читаем из неё».

**Пример отказа.** Код `let first = &v[0]; v.push(4); println!("{}", first);` не компилируется: `push` может перераспределить память вектора, и `first` указывала бы в освобождённую область. Компилятор сообщает `E0502: cannot borrow v as mutable because it is also borrowed as immutable`. Две `&mut` на один объект дают `E0499`.

**Время жизни ссылки (NLL).** Ссылка «живёт» до последнего места использования, а не до конца блока. Поэтому `let r = &s; println!("{}", r); s.push('x');` компилируется: после `println!` `r` больше не используется.

**Висячие ссылки.** Функция `fn dangle() -> &String { let s = String::new(); &s }` не компилируется: `s` уничтожится при выходе, а ссылка осталась бы. Компилятор сообщает об отсутствующем параметре времени жизни (`E0106`) и предлагает вернуть владение (`String`).

**Срезы.** `&s[0..2]` - ссылка на часть `String`, а `&v[1..]` - на часть вектора; пока срез жив, изменять источник нельзя.

**Изменение на месте.** `fn shout(words: &mut Vec<String>)` меняет элементы вызывающего кода. Внутри `for w in words.iter_mut() { *w = w.to_uppercase(); }`: звёздочка разыменовывает ссылку.

**Что даёт эта строгость.** Нет ни `use after free`, ни двойного освобождения, ни гонок данных в безопасном Rust, при этом нет накладных расходов сборщика мусора.

## Примеры

В блоках без `run` результат показан в комментариях.

**Пример 1. Перемещение и clone.**

```rust
fn main() {
    let a = String::from("rust");
    let b = a.clone();     // глубокая копия
    let c = a;             // перемещение
    println!("{} {}", b, c); // rust rust
    let x = 5;
    let y = x;             // Copy
    println!("{} {}", x, y); // 5 5
}
```

**Пример 2. Заимствование для чтения.**

```rust
fn total_len(words: &[String]) -> usize {
    words.iter().map(|w| w.len()).sum()
}

fn main() {
    let words = vec![String::from("ab"), String::from("cde")];
    println!("{}", total_len(&words)); // 5
    println!("{}", words.len());       // 2: words всё ещё доступен
}
```

**Пример 3. Изменяемая ссылка.**

```rust
fn add_exclaim(s: &mut String) {
    s.push('!');
}

fn main() {
    let mut s = String::from("hi");
    add_exclaim(&mut s);
    println!("{}", s); // hi!
}
```

**Пример 4. Функция берёт владение.**

```rust
fn consume(s: String) -> usize {
    s.len()
}   // s уничтожается здесь

fn main() {
    let s = String::from("hello");
    println!("{}", consume(s)); // 5
    // println!("{}", s);       // ошибка: s перемещена
}
```

**Пример 5. NLL: ссылка живёт до последнего использования.**

```rust
fn main() {
    let mut s = String::from("a");
    let r = &s;
    println!("{}", r);  // a
    s.push('b');        // можно: r уже не используется
    println!("{}", s);  // ab
}
```

**Пример 6. Что отвергает компилятор.**

```rust
fn main() {
    let mut s = String::from("a");
    let r1 = &mut s;
    let r2 = &mut s;    // E0499: вторая &mut одновременно
    r1.push('x');
    r2.push('y');
}
```

## Типичные ошибки

* **Использовать значение после перемещения.** Передали `String` в функцию по значению, а потом пытаетесь использовать её снова. Передавайте `&` либо `.clone()`.
* **Клонировать везде «чтобы скомпилировалось».** `clone()` копирует данные и скрывает проблему дизайна; сначала подумайте, достаточно ли ссылки.
* **`&Vec<T>` и `&String` в параметрах.** Принимайте `&[T]` и `&str`.
* **Две `&mut` или `&` вместе с `&mut`.** Сократите область использования первой ссылки.
* **Изменять вектор, пока держите ссылку на его элемент.** `push` может перераспределить память.
* **Возвращать ссылку на локальную переменную.** Возвращайте владение (`String`).
* **Забыть `mut` у переменной при `&mut`.** Нужны и `let mut s`, и `&mut s`.
* **Забыть `*` при изменении через `&mut`.** `*w = ...` меняет значение за ссылкой.

<!-- section: summary -->
## Итоги

* Один владелец на значение; при выходе владельца значение уничтожается.
* Присваивание и передача `String`/`Vec` перемещают владение; простые `Copy`-типы копируются.
* `&T` - много читателей, `&mut T` - один писатель без читателей; borrow checker проверяет это во время компиляции.
* Ссылка не может пережить значение; ссылка живёт до последнего использования.
