## Rust: компиляция заранее, без сборщика мусора

Урок продолжает курс «Rust с нуля»: `let`, `mut`, типы, ввод и `Vec` вам знакомы ([ввод](lesson:rust.from-zero.reading-input), [типы](lesson:rust.from-zero.basic-types), [векторы](lesson:rust.from-zero.vectors)). Здесь внимание на том, что стоит за ними: что делает `rustc`, чем Rust отличается от языков с виртуальной машиной и где у целых чисел границы.

Rust - **компилируемый заранее** язык. Компилятор `rustc` переводит программу в машинный код и записывает исполняемый файл. Виртуальной машины и сборщика мусора нет: память освобождается в моменты, которые компилятор определяет по правилам владения (следующий урок).

Приложение выполняет примерно:

```
rustc --edition 2021 -O main.rs -o prog
./prog
```

* `--edition 2021` - редакция языка (набор совместимых изменений синтаксиса);
* `-O` - включить оптимизации.

Минимальная программа:

```rust
fn main() {
    println!("привет");
}
```

`fn main()` - точка входа. `println!` - **макрос** (восклицательный знак), который форматирует строку и печатает её в stdout. Ввод - через `std::io`:

```rust
use std::io::Read;

fn main() {
    let mut input = String::new();
    std::io::stdin().read_to_string(&mut input).unwrap();
    println!("{}", input.len());
}
```

## Подробнее

**Cargo и rustc.** В реальных проектах программы собирают через `cargo`, который вызывает `rustc` и управляет зависимостями. Здесь используется `rustc` напрямую, поскольку программа состоит из одного файла.

**Переменные.** Вы уже знаете `let`, `let mut`, аннотацию типа и затенение. Новое здесь только одно: тип влияет на границы чисел (ниже), поэтому для суммы множества значений его выбирают осознанно: `let mut sum: i64 = 0;`.

**Целые типы.** Размеры в имени: `i32`, `i64`, `u8`, `usize` (размер указателя). Преобразования между ними явные: `x as i64` или `i64::from(x)`. Литерал: `2_000_000_000i64`. Деление целых усекает к нулю.

**Переполнение.** В отладочной сборке (без `-O`) арифметическое переполнение приводит к панике (`attempt to add with overflow`). В релизной сборке с `-O` по умолчанию проверки отключены, и значение заворачивается. Поэтому поведение зависит от режима сборки; для явного выбора есть `checked_add` (возвращает `Option`), `wrapping_add` и `saturating_add`.

**Ошибки.** В Rust нет исключений для обычных ошибок. Функции возвращают `Result<T, E>` или `Option<T>`. `unwrap()` достаёт значение и паникует при ошибке, `?` пробрасывает ошибку вызывающему коду. Для разбора чисел: `"42".parse::<i64>()` возвращает `Result`.

**Ввод.** В «Rust с нуля» использовалась запись `std::io::read_to_string(std::io::stdin())`, которая возвращает `Result<String, _>`. Есть и второй способ, привычный по старому коду: `use std::io::Read;` и `stdin().read_to_string(&mut input)`, где `input` - заранее созданная изменяемая `String`; результат оба раза нужно развернуть через `unwrap`. `read_to_string` читает весь stdin в `String`; `split_whitespace()` разбивает по пробельным символам, включая переводы строк и пропуская пустые части. Построчное чтение: `stdin().lines()`.

**Форматирование.** `{}` - вывод для пользователя, `{:?}` - отладочный, `{:.2}` - два знака после точки у `f64`, `{:>5}` - выравнивание. Форматирование чисел не зависит от региональных настроек.

**Выражения.** Почти всё в Rust - выражение: блок `{ ... }` возвращает значение последнего выражения без точки с запятой; `if`, `match` тоже выражения.

## Примеры

Блоки без `run`: вывод показан в комментариях, сборка и запуск происходят в упражнении.

**Пример 1. Типы и деление.**

```rust
fn main() {
    let a: i32 = 7;
    let b: i32 = 2;
    println!("{}", a / b);                 // 3
    println!("{}", a as f64 / b as f64);   // 3.5
    println!("{:.2}", 5.0_f64 / 3.0);      // 1.67
}
```

**Пример 2. Явное поведение при переполнении.**

```rust
fn main() {
    let x: i32 = i32::MAX;
    println!("{:?}", x.checked_add(1));  // None
    println!("{}", x.wrapping_add(1));   // -2147483648
    println!("{}", x.saturating_add(1)); // 2147483647
}
```

**Пример 3. Разбор числа: `Result`.**

```rust
fn main() {
    println!("{:?}", "42".parse::<i64>());           // Ok(42)
    println!("{}", "abc".parse::<i64>().is_err());   // true
    let n: i64 = "7".parse().unwrap_or(0);
    println!("{}", n);                               // 7
}
```

**Пример 4. Чтение всех чисел.**

```rust
use std::io::Read;

fn main() {
    let mut input = String::new();
    std::io::stdin().read_to_string(&mut input).unwrap();
    let mut it = input.split_whitespace();
    let n: usize = it.next().unwrap().parse().unwrap();
    let nums: Vec<i64> = it.take(n).map(|t| t.parse().unwrap()).collect();
    println!("{}", nums.iter().sum::<i64>());
}
```

Строка с `take(n).map(|t| t.parse().unwrap()).collect()` - краткая запись цикла `for` с `push`: `|t| t.parse().unwrap()` - безымянная функция (замыкание), `map` применяет её к каждому слову, `collect` собирает результаты в `Vec`. Те же числа можно собрать явным циклом `for _ in 0..n` и `nums.push(...)`, как вы делали в «Rust с нуля». Замыкания и итераторы подробно разбираются в `rust-fundamentals`.

**Пример 5. Блок как выражение.**

```rust
fn main() {
    let x = 5;
    let y = {
        let z = x * 2;
        z + 1
    };
    let kind = if y > 10 { "big" } else { "small" };
    println!("{} {}", y, kind); // 11 big
}
```

## Типичные ошибки

* **Сумма в `i32`.** Два числа по 2 000 000 000 переполнят `i32`: паника в отладочной сборке, тихое заворачивание с `-O`. Используйте `i64`.
* **Присвоить неизменяемой переменной.** `let x = 1; x = 2;` не компилируется; нужен `let mut`.
* **Смешивать типы.** `i32 + i64` не компилируется; приведите явно через `as` или `from`.
* **Деление `i64 / i64` с ожиданием дроби.** Результат целый; приведите к `f64`.
* **Ставить `;` после последнего выражения блока.** Значение блока станет `()`, а не числом.
* **Забыть `!` у макроса.** `println("..")` - ошибка, нужен `println!`.
* **`unwrap()` на пользовательском вводе.** Некорректный ввод приведёт к панике; в реальных программах обрабатывайте `Result` через `match` или `?` (см. [ошибки](lesson:rust.from-zero.errors)).
* **Не импортировать трейт.** `read_to_string` требует `use std::io::Read;`.

## Итоги

* `rustc` создаёт машинный код заранее; рантайма со сборщиком мусора нет.
* Переменные неизменяемы по умолчанию (`let mut` для изменения); типы целых явные, преобразования - через `as` или `from`.
* Переполнение зависит от режима сборки; для явного выбора есть `checked_`, `wrapping_`, `saturating_`.
* Ошибки - значения (`Result`, `Option`); `{:.2}` не зависит от локали.
