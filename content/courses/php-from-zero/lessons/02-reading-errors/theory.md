## Зачем читать сообщения об ошибках

Ошибаются все, и новички, и опытные программисты. Разница в том, что опытный человек не гадает, а читает сообщение: в нём сказано, что случилось и в какой строке. Этот урок учит прочитать сообщение PHP за полминуты и понять, что исправлять.

## Одна новая идея: сообщение об ошибке - это адрес и причина

Каждое сообщение PHP устроено одинаково:

```text
Parse error: syntax error, unexpected token "echo", expecting "," or ";" in main.php on line 3
```

* **Вид ошибки** - первое слово (`Parse error`, `Fatal error`, `Warning`).
* **Причина** - текст после двоеточия.
* **Файл и строка** - слова `in main.php on line 3`: где PHP заметил проблему.

Виды ошибок отличаются тем, что происходит с программой:

* **Parse error** (ошибка разбора) - в тексте нарушены правила языка: пропущена `;`, не закрыты кавычки. PHP разбирает весь файл до выполнения, поэтому **ни одна команда не выполняется**.
* **Fatal error** (фатальная ошибка) - текст верен, но в момент выполнения команда невозможна (например, функции с таким именем нет). Программа **останавливается** на этой строке. То, что напечатано раньше, остаётся.
* **Warning** (предупреждение) - что-то подозрительно, но PHP продолжает работать. Предупреждения нельзя игнорировать: чаще всего за ними стоит ошибка в программе, и результат получится не тот, который вы ожидали.

В приложении сообщения об ошибках показываются отдельно от обычного вывода программы.

## Пример 1. Верная программа для сравнения

```php run
<?php
echo "Касса открыта\n";
echo "Товар: хлеб\n";
echo "Итого: 45 руб.\n";
```
```output
Касса открыта
Товар: хлеб
Итого: 45 руб.
```

Три команды, три строки вывода. Дальше мы будем ломать эту программу по одному месту и смотреть, как реагирует PHP.

## Пример 2. Пропущена точка с запятой

```php
<?php
echo "Касса открыта\n"
echo "Товар: хлеб\n";
```

```text
Parse error: syntax error, unexpected token "echo", expecting "," or ";" in main.php on line 3
```

Построчно: PHP читает `echo "Касса открыта\n"` и ждёт либо `;`, либо запятую (после запятой может идти ещё одно значение, об этом - в следующих уроках). Вместо них на следующей строке стоит слово `echo`. Только здесь PHP понимает, что что-то не так, и называет строку 3. Пропуск же находится в конце строки 2. Правило: **если сообщение указывает на строку N, смотрите в конец строки N-1**.

Это Parse error, поэтому ни `Касса открыта`, ни `Товар: хлеб` на экран не попадут.

## Пример 3. Опечатка в названии функции

```php
<?php
echo "Старт\n";
prnt("Привет\n");
```

```text
Fatal error: Uncaught Error: Call to undefined function prnt() in main.php:3
```

Эта программа записана верно с точки зрения правил, поэтому `Старт` напечатается. Но на третьей строке PHP не находит функцию `prnt` и останавливается. В переводе: «вызов неопределённой функции `prnt()`». Ниже в сообщении PHP добавляет строки `Stack trace` и `thrown in ... on line 3` - это подробности, главное уже в первой строке: причина и номер строки.

## Пример 4. Предупреждение: программа продолжает работу

```php
<?php
echo "Цена:\n";
echo $price;
echo "после\n";
```

```text
Warning: Undefined variable $price in main.php on line 3
```

Здесь использовано имя `$price`, которое нигде не задано (переменные - тема [урока 4](lesson:php.from-zero.variables)). PHP предупреждает: «переменная `$price` не определена». Программа при этом идёт дальше: в обычный вывод попадают `Цена:` и `после`, а на месте `$price` не печатается ничего. Предупреждение - сигнал, что результат строки с ошибкой неверен.

**Попробуйте.** Сломайте пример 1 по-разному: уберите точку с запятой, удалите одну кавычку, превратите `echo` в `ecco`. Прочитайте сообщение и скажите до запуска, будет ли напечатано хоть что-то.

## Точные правила

* Сообщение содержит вид ошибки, причину, имя файла и номер строки: `in main.php on line N`.
* Parse error обнаруживается до выполнения: программа не начинает работу. Fatal error и Warning возникают во время выполнения, поэтому часть вывода может уже быть напечатана.
* PHP сообщает **первую** найденную проблему. Исправив её, вы можете увидеть следующую: это не значит, что вы сломали программу, просто файл читается по порядку.
* Номер строки - то место, где PHP заметил проблему. Причина может быть выше: чаще всего в конце предыдущей строки.
* Незакрытая кавычка обычно даёт сообщение про конец файла: `unexpected end of file`, потому что текст в кавычках «поглотил» всё до конца.
* Лишний ввод, который PHP не может связать с командой, называют **unexpected** («неожиданное»); он указывает, что PHP ждал другое. Слова `expecting ...` перечисляют, что подошло бы.
* Fatal error `Call to undefined function name()` почти всегда означает опечатку в имени функции.
* Читайте сообщение целиком, а не только последнюю строку: ответ почти всегда в первой.

## Типичные ошибки

**1. Искать ошибку в указанной строке и не найти.** Для Parse error с `unexpected token` проверьте конец предыдущей строки: возможно, там нет `;`.

**2. Чинить все ошибки сразу, не запуская программу.** PHP показывает только первую. Исправьте её, запустите ещё раз и прочитайте новое сообщение. Так надёжнее, чем менять много мест вслепую.

**3. Не закрыть кавычку.**

```php
<?php
echo "Привет\n;
```

```text
Parse error: syntax error, unexpected end of file, expecting variable or "${" or "{$" in main.php on line 3
```

PHP указывает на строку 3, которой в файле нет: он дочитал до конца и не нашёл закрывающую кавычку. Проверьте все кавычки в файле: у каждой открывающей должна быть закрывающая.

**4. Забыли кавычки у слова.**

```php
<?php
echo Привет;
```

```text
Fatal error: Uncaught Error: Undefined constant "Привет" in main.php:2
```

Без кавычек `Привет` - не текст, а имя неизвестной константы. Верно: `echo "Привет\n";`.

**5. Игнорировать Warning.** Программа «как будто работает», но результат неверный. Предупреждение показывает, где именно.

## Итоги

* Сообщение об ошибке состоит из вида, причины и места: `in main.php on line N`.
* Parse error - нарушены правила языка, ни одна команда не выполняется. Fatal error - программа останавливается в строке с ошибкой. Warning - работа продолжается, но что-то неверно.
* Если указана строка N с `unexpected token`, проверьте конец строки N-1.
* Исправляйте ошибки по одной: запускайте программу после каждого исправления и читайте новое сообщение.

Дальше вы научитесь печатать текст осмысленнее: несколько значений, табуляция, кавычки внутри текста. Об этом - [следующий урок](lesson:php.from-zero.output).

## Для тех, кто уже программирует

* PHP разделяет синтаксические ошибки (`ParseError`, до выполнения) и ошибки времени выполнения. В PHP 7+ большинство фатальных ситуаций - исключения `Error` (`TypeError`, `ValueError`, `DivisionByZeroError`), которые можно перехватить.
* Notice, Warning и Deprecated - не исключения: PHP продолжает работу. В PHP 8 многие прежние Notice стали Warning (`Undefined variable`, `Undefined array key`), а некоторые Warning стали исключениями.
* Здесь приложение запускает `php` с `display_errors=stderr`: сообщения идут в stderr, а stdout остаётся «чистым» выводом программы. В другой конфигурации (php.ini по умолчанию в дистрибутивах) сообщения могут печататься в stdout или вообще скрываться - не полагайтесь на это в своих проектах.
* Номер строки при `Parse error` указывает на токен, на котором разбор остановился, а не обязательно на место пропуска.
* `error_reporting(E_ALL)` включено на уровне приложения (значение 32767).
