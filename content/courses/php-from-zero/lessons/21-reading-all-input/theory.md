## Зачем это нужно

До сих пор программа знала, сколько строк ей дадут: одну, две или число `n` из первой строки. Настоящие данные так не приходят: это может быть выгрузка покупок, журнал событий или список оценок, где никто заранее не считал строки. Программа должна читать, пока ввод не закончится, и уметь пережить строки, которые написаны неправильно.

## Одна новая идея: читать в цикле, пока fgets не вернёт false

Вы знаете, что `fgets(STDIN)` возвращает `false`, когда читать больше нечего. Значит, цикл можно построить так:

```php
while (($line = fgets(STDIN)) !== false) {
    // обработать $line
}
```

В условии выполняются три действия: `fgets` читает строку, результат кладётся в `$line`, а затем `$line` сравнивается с `false`. Скобки вокруг присваивания обязательны: без них сравнение выполнилось бы раньше присваивания. Сравнение `!== false` строгое, потому что пустая строка и строка `"0"` - это нормальные данные, а не конец ввода.

Внутри цикла каждая строка проходит проверку. Для целых чисел её делает функция **`filter_var($text, FILTER_VALIDATE_INT)`**: она возвращает число, если текст - целое число, и `false`, если нет. Проверка с `!== false` снова строгая, потому что число `0` - допустимый результат.

<!-- section: examples -->
## Пример 1. Цикл на пустом вводе

```php run
<?php
declare(strict_types=1);

$count = 0;
while (($line = fgets(STDIN)) !== false) {
    $count++;
}
echo "Строк: ", $count, "\n";
```
```output
Строк: 0
```

Разбор: в окне примеров стандартный ввод пуст, `fgets` сразу вернула `false`, и тело цикла не выполнилось ни разу. Если подать три строки, программа напечатает `Строк: 3`.

## Пример 2. Проверка целого числа

```php run
<?php
declare(strict_types=1);

foreach (["42", "-7", "0", " 5 ", "5.0", "abc", "", "12px"] as $text) {
    $n = filter_var($text, FILTER_VALIDATE_INT);
    if ($n === false) {
        echo json_encode($text), " - не число\n";
    } else {
        echo json_encode($text), " - ", $n, "\n";
    }
}
```
```output
"42" - 42
"-7" - -7
"0" - 0
" 5 " - 5
"5.0" - не число
"abc" - не число
"" - не число
"12px" - не число
```

Разбор: `filter_var` принимает знак минус, нулевое значение и пробелы по краям. Дробь `"5.0"`, слово, пустая строка и `"12px"` отвергаются. Сравнение `$n === false` отличает «не число» от настоящего нуля. (`json_encode` здесь нужна лишь для того, чтобы показать строку в кавычках.)

## Пример 3. Сумма чисел из ввода с пропуском плохих строк

```php
<?php
declare(strict_types=1);

$accepted = 0;
$skipped = 0;
$sum = 0;

while (($line = fgets(STDIN)) !== false) {
    $line = trim($line);
    if ($line === "") {
        continue;
    }
    $number = filter_var($line, FILTER_VALIDATE_INT);
    if ($number === false) {
        $skipped++;
        continue;
    }
    $accepted++;
    $sum += $number;
}

echo "Принято: ", $accepted, "\n";
echo "Пропущено: ", $skipped, "\n";
echo "Сумма: ", $sum, "\n";
```

Для ввода

```
10
abc

-3
2.5
7
```

программа напечатает

```
Принято: 3
Пропущено: 2
Сумма: 14
```

Разбор: пустая строка пропущена молча, это не ошибка, а просто пустое место. `abc` и `2.5` не прошли проверку, их посчитали в `$skipped`. Из принятых 10, -3 и 7 получилась сумма 14. Каждый `continue` сразу переходит к следующей строке.

Проверку разумно устроить как «охранные условия»: сначала отсеять плохое с помощью `continue`, а в конце тела оставить основную работу.

**Попробуйте.** Добавьте счётчик пустых строк и напечатайте его четвёртой строкой.

## Точные правила

* `fgets(STDIN)` возвращает следующую строку вместе с `\n` или `false` в конце ввода. Если последняя строка не заканчивается переводом строки, она всё равно вернётся.
* `while (($line = fgets(STDIN)) !== false)` - привычная форма. Присваивание в условии заключается в скобки.
* Пустая строка во вводе приходит как `"\n"` (после `trim` - `""`). Это не конец ввода.
* `filter_var($s, FILTER_VALIDATE_INT)` возвращает `int` или `false`. Допускает ведущий `+` или `-` и пробелы по краям, не допускает дробную часть, ведущие нули (`"007"`), экспоненту (`"1e3"`) и текст вокруг числа. Слишком большие числа тоже отвергаются.
* Результат нужно сравнивать с `false` строго: `0` приведётся к `false` при нестрогом сравнении или в `if ($n)`.
* Для бесконечных или очень больших вводов читать построчно экономнее, чем загружать всё сразу.

## Типичные ошибки

**1. Условие без `!== false`.**

```php
<?php
$count = 0;
while ($line = fgets(STDIN)) {
    $count++;
}
echo $count, "\n";
```

При вводе `a` и `0` (без перевода строки после нуля) программа напечатает `1`, а не `2`: строка `"0"` в условии считается ложной, и цикл останавливается раньше конца ввода. Сравнивайте с `false` строго.

**2. Нет скобок вокруг присваивания.** Запись `while ($line = fgets(STDIN) !== false)` сначала сравнивает, а потом присваивает: в `$line` окажется `true` или `false`, а не строка.

**3. `trim` на конце ввода.**

```php
<?php
declare(strict_types=1);
$last = trim(fgets(STDIN));
```

```text
Fatal error: Uncaught TypeError: trim(): Argument #1 ($string) must be of type string, false given in main.php:3
```

Если ввод закончился, `fgets` вернула `false`, а `trim` строкой его не принимает. Внутри цикла с проверкой `!== false` такой ошибки нет.

**4. Проверка результата `filter_var` через `if ($n)`.** Число `0` - правильный ответ, но условие его отбросит. Пишите `if ($n === false)`.

**5. Использование результата без проверки.** `filter_var("abc", FILTER_VALIDATE_INT) + 1` не вызывает ошибки и даёт `1`, потому что `false` в арифметике превращается в `0`. Сначала проверьте, потом считайте.

**6. `(int)` вместо проверки.** `(int) "abc"` даёт `0`, и плохая строка тихо превращается в данные. Для входа, которому нельзя доверять, нужна проверка, а не преобразование.

**7. Забыли `continue` для плохой строки.** Строку посчитали пропущенной, но код ниже всё равно выполнился: она попала и в `$skipped`, и в `$sum`.

## Итоги

* Читать ввод неизвестной длины нужно циклом `while (($line = fgets(STDIN)) !== false)`.
* Сравнение с `false` строгое; пустая строка и `"0"` - обычные данные.
* Целое число проверяют через `filter_var($s, FILTER_VALIDATE_INT)`, а ответ сравнивают с `false` строго.
* Плохие строки пропускают через `continue` и считают, а пустые строки игнорируют.

## Для тех, кто уже программирует

* Идиома `while (($line = fgets(STDIN)) !== false)` - аналог `for line in sys.stdin` или `scanner.Scan()`. Строгое сравнение нужно потому, что строка `"0"` ложна в булевом контексте.
* Строки приходят с `\n` (и `\r` в файлах из Windows); `trim` убирает оба. Для сохранения пробелов в начале используйте `rtrim($line, "\r\n")`.
* `filter_var` с `FILTER_VALIDATE_INT` - самая короткая встроенная проверка целого. Параметр `options` позволяет задать диапазон: `["options" => ["min_range" => 1, "max_range" => 100]]`, а флаг `FILTER_NULL_ON_FAILURE` - получить `null` вместо `false`.
* `is_numeric` шире: пропускает дроби, экспоненту и пробелы. `ctype_digit` не принимает знак.
* Другие способы чтения: `file('php://stdin', FILE_IGNORE_NEW_LINES)`, `stream_get_contents(STDIN)`, `fgetcsv(STDIN)`. Построчный цикл не держит весь ввод в памяти.
* Нет исключений на ошибки чтения: `fgets` просто возвращает `false`, поэтому различить конец и сбой по значению нельзя.
