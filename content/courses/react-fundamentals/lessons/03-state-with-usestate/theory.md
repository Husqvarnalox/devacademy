## Состояние - память компонента

Props приходят от родителя и не меняются. Но интерфейс должен реагировать на действия пользователя: счётчик растёт, меню открывается, текст набирается. Для таких данных у компонента есть **состояние** - память, которую React хранит между рендерами.

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button type="button" onClick={() => setCount(count + 1)}>
      Нажато: {count}
    </button>
  );
}
```

`useState(0)` возвращает пару: **текущее значение** и **функцию-установщик**. Аргумент `0` - начальное значение, оно используется только на первом рендере. Вызов `setCount(...)` не меняет переменную `count` на месте: он просит React **перерисовать компонент** с новым значением.

Обычная переменная для этого не годится: функция компонента вызывается заново при каждом рендере, и локальная переменная каждый раз создаётся заново. Изменение переменной к тому же не говорит React, что нужно перерисовать.

Хуки (функции с именем на `use`) вызываются только на верхнем уровне компонента, вне условий и циклов. Вне рендера хук вызвать нельзя, поэтому запускаемые примеры показывают лишь первый рендер через `renderToStaticMarkup`:

```javascript run
const React = require("react");
const { renderToStaticMarkup } = require("react-dom/server");
const h = React.createElement;

function Counter({ initial }) {
  const [count] = React.useState(initial);
  return h("p", null, "Значение: ", count);
}

console.log(renderToStaticMarkup(h(Counter, { initial: 3 })));
console.log(renderToStaticMarkup(h(Counter, { initial: 10 })));
```
```output
<p>Значение: 3</p>
<p>Значение: 10</p>
```

Начальное значение берётся из аргумента `useState`. Все обновления состояния происходят дальше, в обработчиках событий и в браузере.

## Точные правила

### Состояние - снимок

Каждый рендер компонента получает **собственный снимок** состояния: значение `count` внутри одного рендера не меняется, даже если вы вызвали `setCount`. Обработчик, созданный в этом рендере, «помнит» значение этого рендера.

```jsx
function Bad() {
  const [count, setCount] = useState(0);
  function addThree() {
    setCount(count + 1); // просит поставить 0 + 1
    setCount(count + 1); // просит поставить 0 + 1
    setCount(count + 1); // просит поставить 0 + 1
  }
  // после клика count станет 1, а не 3
}
```

Три вызова ставят в очередь одно и то же значение `1`. Чтобы каждое обновление опиралось на результат предыдущего, передают **обновляющую функцию**: `setCount(c => c + 1)`. React вызывает её с последним значением из очереди.

Модель очереди (не код React, а иллюстрация правила: значение или функция, применяемые по порядку):

```javascript run
function applyQueue(initial, updates) {
  let state = initial;
  for (const update of updates) {
    state = typeof update === "function" ? update(state) : update;
  }
  return state;
}

console.log(applyQueue(0, [1, 1, 1]));
console.log(applyQueue(0, [(n) => n + 1, (n) => n + 1, (n) => n + 1]));
console.log(applyQueue(5, [10, (n) => n * 2]));
```
```output
1
3
20
```

Три одинаковых значения дают `1`, три обновляющие функции - `3`, а значение, за которым идёт функция, даёт `20`.

### Пакетная обработка

Все вызовы setter'ов внутри одного обработчика собираются в пакет: компонент перерисовывается **один раз** после завершения обработчика, а не после каждого вызова. С React 18 так происходит везде (в таймерах, промисах, любых обработчиках). Из этого следует, что после `setCount(...)` код дальше по обработчику всё ещё видит старый `count`.

### Сравнение и иммутабельность

React сравнивает прежнее и новое значение через `Object.is`. Если значения равны, перерисовка пропускается. Поэтому объекты и массивы в состоянии **нельзя менять на месте**: ссылка осталась бы той же, и React не увидел бы изменения (а ещё мутация портит данные, которыми пользуются другие компоненты). Создавайте новое значение:

* добавить: `[...items, x]`;
* удалить: `items.filter((i) => i.id !== id)`;
* заменить: `items.map((i) => (i.id === id ? { ...i, done: true } : i))`;
* объект: `{ ...user, name: "Аня" }`, для вложенного - копия на каждом уровне: `{ ...user, address: { ...user.address, city } }`.

```javascript run
const todos = [{ id: 1, done: false }, { id: 2, done: false }];
const next = todos.map((t) => (t.id === 2 ? { ...t, done: true } : t));
console.log(next[0] === todos[0], next[1] === todos[1], todos[1].done, next[1].done);

const user = { name: "Аня", address: { city: "Омск", zip: "1" } };
const moved = { ...user, address: { ...user.address, city: "Тверь" } };
console.log(user.address.city, moved.address.city, moved.address.zip, user === moved);
```
```output
true false false true
Омск Тверь 1 false
```

Нетронутые элементы остаются теми же объектами (`true`), изменённый - новый (`false`), исходные данные не пострадали. Это называется структурным разделением.

### Ленивая инициализация

Начальное значение используется только на первом рендере, но выражение в аргументе вычисляется на каждом. Если оно дорогое, передайте **функцию**: `useState(() => readFromStorage())`. React вызовет её один раз при создании состояния.

```javascript run
const React = require("react");
const { renderToStaticMarkup } = require("react-dom/server");
const h = React.createElement;

let calls = 0;
function expensive() {
  calls += 1;
  return 42;
}

function Lazy() {
  const [value] = React.useState(expensive); // функция, а не её результат
  return h("p", null, value);
}

console.log(renderToStaticMarkup(h(Lazy)), "вызовов:", calls);
```
```output
<p>42</p> вызовов: 1
```

### Что делать состоянием

Состоянием делают то, что меняется со временем и не может быть вычислено из других данных. Всё, что выводится из props и состояния, считайте прямо во время рендера: список после фильтрации, число элементов, полное имя. Дублирование данных в нескольких состояниях приводит к рассинхронизации.

## Примеры

**Пример 1. Переключатель.**

```jsx
function Disclosure({ title, children }) {
  const [open, setOpen] = useState(false);
  return (
    <section>
      <button type="button" aria-expanded={open} onClick={() => setOpen((o) => !o)}>
        {title}
      </button>
      {open && <div>{children}</div>}
    </section>
  );
}
```

Для булева значения, зависящего от предыдущего, удобна обновляющая функция `o => !o`.

**Пример 2. Объект в состоянии.**

```jsx
const [form, setForm] = useState({ name: "", city: "" });
setForm({ ...form, city: "Тверь" });             // допустимо
setForm((f) => ({ ...f, city: "Тверь" }));       // надёжнее, если обновлений несколько
```

Обратите внимание: `setForm` **заменяет** значение целиком, а не сливает поля, как делал `setState` у классов. Поэтому остальные поля копируют через `...form`.

**Пример 3. Список: добавить и удалить.**

```jsx
const [items, setItems] = useState([]);
const add = (item) => setItems((list) => [...list, item]);
const remove = (id) => setItems((list) => list.filter((i) => i.id !== id));
```

**Пример 4. Состояние привязано к позиции.** Два `<Counter />` рядом хранят независимые значения. Если поменять `key` у компонента, React создаст его заново и состояние начнётся с начального значения - так в уроке про ключи один и тот же `key` сохранял поле ввода.

**Пример 5. Производное значение без состояния.**

```jsx
const [todos, setTodos] = useState(initial);
const left = todos.filter((t) => !t.done).length; // не useState!
```

## Типичные ошибки

* **Мутация состояния.** `items.push(x); setItems(items)` не вызывает перерисовку (ссылка прежняя) и портит данные. Всегда создавайте новое значение.
* **Ожидание немедленного изменения.** `setCount(5); console.log(count)` выведет прежнее значение: это снимок текущего рендера.
* **`setCount(count + 1)` несколько раз подряд.** Прибавится один раз. Используйте `setCount(c => c + 1)`.
* **Хуки в условиях и циклах.** React сопоставляет состояния по порядку вызовов хуков. Если порядок меняется, состояния перепутаются. Условие кладут внутрь хука или выше по иерархии компонентов.
* **Копия props в состоянии.** `useState(props.value)` запоминает значение первого рендера; при изменении props состояние не обновится. Нужно либо использовать props напрямую, либо сознательно сделать «начальное значение» (`initialValue`) и сбрасывать компонент через `key`.
* **Лишнее состояние.** Хранить `filteredItems` рядом с `items` и `query` значит поддерживать три значения согласованными вручную. Вычислите фильтр в рендере.
* **Мутация вложенного объекта в копии.** `{ ...user }` копирует только верхний уровень: `copy.address.city = "x"` изменяет и исходный объект.
* **Дорогое выражение вместо ленивого.** `useState(parse(bigJson))` разбирает JSON при каждом рендере; нужна форма `useState(() => parse(bigJson))`.

<!-- section: summary -->
## Итоги

* Состояние - память компонента между рендерами; `useState(init)` возвращает значение и setter.
* В рамках одного рендера состояние - неизменный снимок; setter просит о новом рендере.
* Если новое значение зависит от предыдущего, передают обновляющую функцию: `setN(n => n + 1)`.
* Обновления собираются в пакет; перерисовка происходит один раз после обработчика.
* Объекты и массивы в состоянии не меняют на месте: создают копии (`...`, `map`, `filter`).
* Лишнее и вычисляемое не хранят в состоянии; тяжёлое начальное значение передают функцией.
