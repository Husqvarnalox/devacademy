## Что такое React и зачем он нужен

Интерфейс - это то, что пользователь видит в зависимости от данных: список товаров, число в корзине, сообщение об ошибке. Без библиотеки вы сами следите за тем, какие узлы DOM нужно создать, изменить или удалить, когда данные поменялись. Чем больше состояний, тем легче забыть одно из них.

React предлагает другой способ: вы **описываете, как интерфейс должен выглядеть при данных сейчас**, а библиотека сама приводит страницу в это состояние. Такой стиль называют **декларативным**. Описание пишется функциями: **компонент** - это функция, которая принимает данные (props) и возвращает описание интерфейса.

```jsx
function Greeting({ name }) {
  return <p>Привет, {name}!</p>;
}
```

Запись с угловыми скобками называется **JSX**. Это не HTML и не строка: компилятор превращает её в обычные вызовы JavaScript. Браузер и Node.js JSX сами не понимают, его переводят сборщик или тестовый инструмент (в этом курсе - Vitest).

В этом курсе React - **библиотека для интерфейса, а не фреймворк**. В неё не входят маршрутизация, загрузка данных, сборка и серверный рендеринг как готовая система: это подбирают отдельно или берут у метафреймворков вроде Next.js.

Посмотрите, во что превращается JSX. Запускаемые примеры теории - обычные скрипты Node.js, поэтому в них нет JSX: вместо него явный вызов `createElement`, в который JSX и переводится.

```javascript run
const React = require("react");

// <h1 className="title">Привет</h1> превращается в вызов createElement
const element = React.createElement("h1", { className: "title" }, "Привет");

console.log(element.type);
console.log(element.props.className);
console.log(element.props.children);
```
```output
h1
title
Привет
```

Результат - **обычный объект-описание** (его называют React-элементом), а не узел DOM. Элемент говорит: «здесь должен быть `h1` с такими свойствами и таким содержимым».

## Точные правила

### Компонент - функция, JSX - синтаксис вызова

* Имя компонента начинается с **заглавной буквы**. `<Greeting />` - вызов вашего компонента, `<greeting />` - обычный HTML-тег с таким именем. Это правило компилятора, а не соглашение для красоты.
* Компонент возвращает одно описание: элемент, строку, число, массив, `null` (ничего не рисовать). Несколько соседних элементов оборачивают в один родитель или во фрагмент `<>...</>`.
* JSX - выражение. Внутри фигурных скобок `{...}` пишется любое **выражение** JavaScript, но не инструкция: `if` и `for` внутри скобок нельзя, вместо них `? :`, `&&` и `map`.
* Атрибуты называются по DOM-свойствам: `className`, `htmlFor`, `onClick`. Значения вне строк передаются в скобках: `disabled={!inStock}`.

### Два вызова вместо угловых скобок

Современный преобразователь JSX использует автоматический «jsx runtime»: `<h1 className="t">Привет</h1>` превращается в вызов функции `jsx` из пакета `react/jsx-runtime`, а не в `React.createElement`. Результат для вашего кода одинаков: объект-элемент.

```javascript run
const React = require("react");
const { jsx } = require("react/jsx-runtime");

const a = React.createElement("h1", { className: "title" }, "Привет");
const b = jsx("h1", { className: "title", children: "Привет" });

console.log(a.type === b.type);
console.log(a.props.children === b.props.children);
console.log(React.isValidElement(b), React.isValidElement({ type: "h1" }));
```
```output
true
true
true false
```

`isValidElement` отличает настоящий элемент от похожего объекта: React узнаёт свои элементы по скрытой метке в объекте, поэтому подделать их литералом нельзя.

### Рендер и коммит

Обновление интерфейса состоит из двух разных фаз ([react.dev: Render and Commit](https://react.dev/learn/render-and-commit)).

1. **Рендер** - React вызывает ваши функции-компоненты и получает описание. На этом шаге DOM не меняется. Поэтому функция компонента должна быть **чистой**: при одинаковых props и состоянии возвращать одно и то же и не менять ничего снаружи.
2. **Коммит** - React сравнивает новое описание с предыдущим и вносит в DOM только различия.

Один и тот же вызов с теми же данными даёт то же описание:

```javascript run
const React = require("react");
const { renderToString } = require("react-dom/server");

function Greeting({ name }) {
  return React.createElement("p", null, "Привет, ", name, "!");
}

const first = Greeting({ name: "мир" });
const second = Greeting({ name: "мир" });
console.log(first === second, JSON.stringify(first.props.children) === JSON.stringify(second.props.children));
console.log(renderToString(React.createElement(Greeting, { name: "мир" })));
```
```output
false true
<p>Привет, <!-- -->мир<!-- -->!</p>
```

Два вызова дают два разных объекта (`false`), но с одинаковым содержимым (`true`). Функция `renderToString` из `react-dom/server` строит HTML-строку без браузера; пустые комментарии `<!-- -->` разделяют соседние текстовые узлы, чтобы страницу можно было «оживить» на клиенте.

### Про «виртуальный DOM»

Часто говорят: «React быстр, потому что у него виртуальный DOM». Это неточно. Объекты-описания - дерево обычных объектов JavaScript, которое React сравнивает с предыдущим. Само по себе сравнение не быстрее ручной точечной правки DOM: ручной код, который меняет ровно нужный узел, работает не медленнее. Ценность подхода в другом: вам не нужно вручную писать правки для каждого перехода между состояниями, и код остаётся понятным. Сам термин «виртуальный DOM» в современной документации React почти не используется - там говорят про рендер и коммит.

### Как React рисует в браузере

В приложении корень создаётся один раз через `createRoot` из `react-dom/client`: `createRoot(container).render(<App />)`. Старые функции `ReactDOM.render` и `ReactDOM.hydrate` удалены в React 19: в установленном `react-dom` таких экспортов нет.

## Примеры

**Пример 1. Условный вывод и список без циклов.** JSX - выражение, поэтому ветвление и повторение записывают выражениями.

```jsx
function Inbox({ messages }) {
  return (
    <section>
      <h2>Входящие</h2>
      {messages.length === 0 ? <p>Писем нет</p> : (
        <ul>
          {messages.map((m) => <li key={m.id}>{m.subject}</li>)}
        </ul>
      )}
    </section>
  );
}
```

Для пустого массива вернётся абзац, иначе - список. Атрибут `key` объясняет следующий урок.

**Пример 2. Тип элемента: тег или компонент.**

```javascript run
const React = require("react");

function Badge() { return React.createElement("b", null, "NEW"); }

const tag = React.createElement("b", null, "NEW");
const component = React.createElement(Badge, null);

console.log(typeof tag.type, typeof component.type);
console.log(component.type === Badge);
```
```output
string function
true
```

У тега `type` - строка, у компонента - сама функция. Выполнять функцию будет React на фазе рендера, а не `createElement`.

**Пример 3. Разметка из данных.** Сервер-рендер показывает, какой HTML получится:

```javascript run
const React = require("react");
const { renderToStaticMarkup } = require("react-dom/server");

const h = React.createElement;
function Price({ cents }) {
  return h("span", null, (cents / 100).toFixed(2), " ₽");
}
function Item({ name, cents }) {
  return h("li", null, name, ": ", h(Price, { cents }));
}

console.log(renderToStaticMarkup(h("ul", null, h(Item, { name: "Чай", cents: 1250 }), h(Item, { name: "Кофе", cents: 900 }))));
```
```output
<ul><li>Чай: <span>12.50 ₽</span></li><li>Кофе: <span>9.00 ₽</span></li></ul>
```

Компоненты вызывают друг друга, как обычные функции: итоговая страница собирается из вложенных описаний.

## Типичные ошибки

* **Имя компонента с маленькой буквы.** `<productCard />` ищет HTML-тег `productcard`, а не вашу функцию. Имена компонентов начинают с заглавной.
* **Изменение props.** Props - данные родителя, менять их внутри компонента нельзя: `props.items.push(x)` портит данные вне компонента и ломает чистоту рендера.
* **Побочные действия в теле компонента.** Запрос к серверу, запись в `localStorage` или изменение внешней переменной во время рендера выполнятся непредсказуемое число раз: React вправе вызвать компонент повторно, а в режиме StrictMode вызывает дважды нарочно. Побочным действиям отведены обработчики событий и эффекты.
* **`if` внутри фигурных скобок.** `{if (ok) ...}` не работает: скобки принимают только выражения. Используйте `ok ? a : b` или `ok && a`.
* **Предположение, что JSX - это HTML.** Вместо `class` пишут `className`, вместо `for` - `htmlFor`, а тег без содержимого должен быть закрыт: `<br />`.
* **Считать «виртуальный DOM» причиной скорости.** Это упрощение: React экономит ваш труд на описании переходов, а не обгоняет точечные правки DOM.

## Итоги

* React описывает интерфейс как функцию данных: компонент принимает props и возвращает описание.
* JSX - синтаксис для вызовов `jsx` / `createElement`; результат - обычные объекты-элементы, а не узлы DOM.
* Обновление - это рендер (вызов компонентов, чистая фаза) и коммит (внесение различий в DOM).
* Функция компонента должна быть чистой: те же props и состояние - то же описание, без побочных действий.
* «Виртуальный DOM» - это сравнение деревьев описаний, а не источник скорости сам по себе.
* React - библиотека интерфейса; маршрутизация, загрузка данных и сборка подбираются отдельно.
