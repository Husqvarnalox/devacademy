## Неопределённое поведение: договор с компилятором

**Неопределённое поведение (UB, undefined behaviour)** - ситуация, для которой стандарт C++ не накладывает **никаких** требований на программу. Это не «непредсказуемый результат» и не «исключение»: компилятор вправе предполагать, что UB в программе **никогда не происходит**, и оптимизировать, исходя из этого. Поэтому программа с UB может:

* работать «правильно» на вашей машине и ломаться на другой или после обновления компилятора;
* работать с `-O0` и ломаться с `-O2`;
* печатать неожиданное значение, зависать, падать или молча портить данные.

Четыре самых частых источника UB:

1. **Переполнение знакового целого** (`INT_MAX + 1`).
2. **Выход за границы** массива или `vector` (`v[v.size()]`).
3. **Висячая ссылка, указатель или итератор** на уничтоженный объект (после `push_back`, `delete`, выхода из области видимости).
4. **Гонка данных**: два потока обращаются к одной ячейке памяти без синхронизации, и хотя бы одно обращение - запись.

Встречаются и другие: разыменование нулевого указателя, чтение неинициализированной переменной, деление на ноль, сдвиг на число битов, не меньшее ширины типа, нарушение строгих правил алиасинга.

Хорошая новость: для обнаружения UB есть **санитайзеры** - инструменты, которые компилятор встраивает в программу. Они проверяют операции во время работы и сообщают точное место ошибки. Но санитайзер находит только то, что произошло в запуске: он не заменяет тесты и не доказывает отсутствие UB.

## Точные правила

**Знаковое и беззнаковое.**

* Переполнение **знаковых** целых (`int`, `long`, ...) - UB. Компилятор вправе считать, что `x + 1 > x` всегда истинно для `int x`, и убрать проверку.
* Беззнаковые типы **оборачиваются по модулю** `2^N`: это определено. `unsigned(0) - 1 == UINT_MAX`. Но смешивание знаковых и беззнаковых в сравнениях даёт сюрпризы: в `-1 < 1u` значение `-1` преобразуется в большое беззнаковое, и результат ложен (`-Wsign-compare` предупреждает). Для безопасного сравнения целых разных знаков есть `std::cmp_less`, `std::in_range` (C++20).
* Деление на ноль и `INT_MIN / -1` - UB. Левый сдвиг отрицательного значения `E1 << E2` до C++20 был UB; начиная с C++20 (P1236R1) результат определён как `E1 * 2^E2` по модулю `2^N`, где `N` - ширина типа (cppreference, «Arithmetic operators», раздел «Bitwise shift operators»). Сдвиг на **отрицательное количество** разрядов или на количество, не меньшее ширины типа, по-прежнему UB.
* Как проверять без UB: заранее (`if (a > INT_MAX - b)`), в более широком типе (`long long`) или встроенными функциями вроде `__builtin_add_overflow` (расширение GCC и Clang, не стандарт).

**Доступ к элементам.** `operator[]` не проверяет границы (UB при выходе), `at()` проверяет и бросает `std::out_of_range`. Указатели, ссылки и итераторы на элементы `vector` недействительны после операций, которые перевыделяют память (см. [урок про контейнеры](lesson:cpp.fundamentals.stl-containers-algorithms)). Индекс остаётся действительным после роста, поэтому в долгоживущих структурах хранят индексы, а не указатели.

**Время жизни.** Возврат ссылки на локальную переменную, `string_view` на временную строку, использование после `delete`, обращение к объекту после `move` вне допустимых операций, чтение из `unique_ptr` после `release` - всё это висячие обращения (см. [урок про RAII](lesson:cpp.fundamentals.raii-smart-pointers)). Современный подход: владеть через `unique_ptr`/значения, а ссылаться только на гарантированно живое.

**Гонки данных.** Гонка - это UB даже для «безобидного» `++counter`. Лечится синхронизацией: `std::mutex` с `std::lock_guard`, либо `std::atomic<T>`. Результат `std::atomic` не зависит от планировщика, а вот порядок выполнения потоков остаётся произвольным.

**Приведение типов.** Чтение `float` как `uint32_t` через `reinterpret_cast` нарушает правила алиасинга - UB. Правильно: `std::memcpy` или `std::bit_cast` (C++20).

**Санитайзеры (Clang и GCC).** Включаются флагами компиляции; замедляют программу в несколько раз, поэтому используются при разработке и в CI:

| Флаг | Что ловит |
|---|---|
| `-fsanitize=undefined` (UBSan) | переполнение знаковых, некорректные сдвиги, деление на ноль, неверные приведения |
| `-fsanitize=address` (ASan) | выход за границы кучи и стека, use-after-free, double free |
| `-fsanitize=thread` (TSan) | гонки данных (не сочетается с ASan в одном запуске) |
| `-fsanitize=memory` (MSan, только Clang на Linux) | чтение неинициализированной памяти |

Нужны отладочные символы (`-g`) для читаемых строк в отчёте и, обычно, `-O1` или `-O0`. Используйте также `-Wall -Wextra`: часть UB компилятор замечает сам. Среда выполнения курса запускает программы без санитайзеров, поэтому примеры с UB ниже показаны без запуска, а запускаемые примеры написаны так, чтобы UB не содержать.

## Примеры

**Пример 1. Беззнаковое оборачивание и проверка до операции.**

```cpp run
#include <climits>
#include <iostream>
#include <optional>
#include <string>
#include <utility>

std::optional<int> checkedAdd(int a, int b) {
    if (b > 0 && a > INT_MAX - b) return std::nullopt;
    if (b < 0 && a < INT_MIN - b) return std::nullopt;
    return a + b;  // сюда попадаем, только если переполнения нет
}

int main() {
    unsigned u = UINT_MAX;
    std::cout << u + 1 << " " << 0u - 1 << "\n";  // определённое оборачивание

    for (auto [a, b] : {std::pair{2000000000, 100000000}, std::pair{2000000000, 200000000}, std::pair{-2000000000, -200000000}}) {
        auto r = checkedAdd(a, b);
        std::cout << (r ? std::to_string(*r) : std::string("overflow")) << "\n";
    }

    long long wide = static_cast<long long>(INT_MAX) + 1;  // в широком типе переполнения нет
    std::cout << wide << " " << (wide > INT_MAX) << "\n";
}
```
```output
0 4294967295
2100000000
overflow
overflow
2147483648 1
```

**Пример 2. `at()` вместо `operator[]`.**

```cpp run
#include <iostream>
#include <stdexcept>
#include <vector>

int main() {
    std::vector<int> v{10, 20, 30};
    for (std::size_t i = 0; i <= v.size(); ++i) {
        try {
            std::cout << v.at(i) << "\n";
        } catch (const std::out_of_range&) {
            std::cout << "index " << i << " out of range\n";
        }
    }
}
```
```output
10
20
30
index 3 out of range
```

Проверка границ стоит времени, поэтому в горячем коде используют `[]` после явной проверки или алгоритмы и диапазоны, которые не выходят за границы по построению.

**Пример 3. Индекс вместо ссылки переживает рост вектора.**

```cpp run
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v{1, 2, 3};
    std::size_t firstIndex = 0;  // индекс остаётся верным при любом перевыделении
    for (int i = 0; i < 1000; ++i) v.push_back(i);
    v[firstIndex] = 99;
    std::cout << v[0] << " " << v.size() << "\n";
}
```
```output
99 1003
```

Если вместо индекса взять `int& first = v[0];` до цикла, запись `first = 99` после роста обращается к освобождённой памяти (см. пример 5).

**Пример 4. `std::bit_cast` и безопасные сравнения (C++20).**

```cpp run
#include <bit>
#include <cstdint>
#include <iostream>
#include <utility>

int main() {
    float f = 1.0f;
    std::uint32_t bits = std::bit_cast<std::uint32_t>(f);  // определённая реинтерпретация
    std::cout << std::hex << bits << std::dec << "\n";

    int negative = -1;
    unsigned big = 1;
    std::cout << std::cmp_less(negative, big) << " " << std::in_range<unsigned char>(300) << " "
              << std::in_range<unsigned char>(200) << "\n";
}
```
```output
3f800000
1 0 1
```

Результат `std::cmp_less(-1, 1u)` истинен, в отличие от наивного `-1 < 1u`.

**Пример 5. Каталог UB (не запускать).**

```cpp
int overflow(int x) { return x + 1; }          // 1) INT_MAX + 1: UB; компилятор вправе упростить x + 1 > x до true

int outOfBounds() {
    std::vector<int> v{1, 2, 3};
    return v[3];                                // 2) чтение за концом буфера
}

int dangling() {
    std::vector<int> v{1, 2, 3};
    int& first = v[0];
    v.push_back(4); v.push_back(5);             // возможное перевыделение
    return first;                               // 3) ссылка на освобождённую память
}

const std::string& danglingRef() {
    std::string s = "local";
    return s;                                   // 3) ссылка на уничтоженный локальный объект
}

int counter = 0;
void race() {
    std::thread a([] { for (int i = 0; i < 100000; ++i) ++counter; });
    std::thread b([] { for (int i = 0; i < 100000; ++i) ++counter; });
    a.join(); b.join();                         // 4) гонка данных на counter: UB, итог не обязан быть 200000
}
```

**Пример 6. Что сообщают санитайзеры (реальные запуски на Apple clang 21, строки сокращены).**

```bash
clang++ -std=c++20 -g -fsanitize=undefined overflow.cpp && ./a.out
# overflow.cpp:5:15: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'

clang++ -std=c++20 -g -fsanitize=address oob.cpp && ./a.out
# ERROR: AddressSanitizer: heap-buffer-overflow on address 0x6020000000dc ...
# READ of size 4 at 0x6020000000dc thread T0
#     #0 ... in main oob.cpp:5

clang++ -std=c++20 -g -fsanitize=address dangling.cpp && ./a.out
# ERROR: AddressSanitizer: heap-use-after-free on address 0x6020000000d0 ...
# READ of size 4 at ... thread T0
#     #0 ... in main dangling.cpp:8

clang++ -std=c++20 -g -fsanitize=thread race.cpp && ./a.out
# WARNING: ThreadSanitizer: data race
#   Write of size 4 at 0x... by thread T2:
```

Формулировки и адреса зависят от компилятора и запуска; смысл один: вид ошибки, тип доступа и строка исходника. Без санитайзера первая программа напечатала бы `-2147483648`, остальные могли бы «работать».

**Пример 7. Исправление гонки: `std::atomic` и `std::mutex` (запускается, `-pthread` включён).**

```cpp run
#include <atomic>
#include <iostream>
#include <mutex>
#include <thread>

int main() {
    std::atomic<int> atomicCounter{0};
    int lockedCounter = 0;
    std::mutex m;
    auto work = [&] {
        for (int i = 0; i < 100000; ++i) {
            atomicCounter.fetch_add(1, std::memory_order_relaxed);
            std::lock_guard<std::mutex> lock(m);
            ++lockedCounter;
        }
    };
    std::thread a(work), b(work);
    a.join();
    b.join();
    std::cout << atomicCounter << "\n" << lockedCounter << "\n";   // всегда 200000: порядок потоков не важен, итог один
}
```
```output
200000
200000
```

Порядок, в котором потоки выполняют итерации, произволен и меняется от запуска к запуску, но итог определён: оба счётчика защищены (первый - атомарной операцией, второй - мьютексом), поэтому гонки данных нет. Поэтому пример печатает только итог после `join()`, а не строки из самих потоков. Небезопасный вариант из примера 5 запускать не нужно: его результат не обязан быть `200000`, а само поведение не определено. Версия с `-fsanitize=thread` проверена: отчётов нет.

## Типичные ошибки

* **«Это работает у меня, значит, нет UB».** UB проявляется на другой оптимизации, версии или платформе.
* **Проверять переполнение после операции:** `if (a + b < a)` для знакового `int` - сама сумма уже UB, и компилятор вправе удалить проверку. Проверяйте заранее или в широком типе.
* **Использовать `[]` для данных извне без проверки индекса.** Проверьте индекс или применяйте `at()`.
* **Хранить `T&`, `T*` или итератор на элемент `vector` через операции вставки.**
* **Возвращать ссылку на локальный объект или `string_view` на временную строку.**
* **Считать `++counter` потокобезопасным** или защищать лишь запись, но не чтение.
* **Полагаться на беззнаковый тип «для надёжности».** Выражение `i >= 0` для `size_t` всегда истинно, а `v.size() - 1` для пустого вектора - огромное число.
* **Принимать молчание санитайзера за доказательство.** Он видит только исполненные пути; нужны и тесты, в том числе на граничные входы.
* **Подавлять предупреждения компилятора** (`-Wno-...`) вместо исправления причины.

## Итоги

* UB - не ошибка времени выполнения, а отсутствие гарантий: компилятор считает, что оно не происходит.
* Главные источники: знаковое переполнение, выход за границы, висячие обращения, гонки данных.
* Беззнаковое оборачивание определено; знаковое переполнение проверяйте заранее или в широком типе.
* ASan, UBSan и TSan находят UB на исполняемых путях; включайте их в разработке и CI, но не заменяйте ими тесты. `std::bit_cast`, `std::cmp_less`, `std::in_range` - возможности C++20.
