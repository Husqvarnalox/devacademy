## Адрес сайта задают папки

В приложении на одном React вы сами решаете, какой компонент показать для какого адреса: подключаете библиотеку маршрутизации и пишете таблицу «путь - компонент». В Next.js таблицы нет: адрес определяется **структурой папок** внутри каталога `app/`. Такой подход называется **файловой маршрутизацией**.

Две опорные идеи:

* **Папка - это сегмент маршрута.** Сегмент - часть адреса между слэшами. Папка `app/blog/` задаёт сегмент `blog`, а вложенная `app/blog/authors/` - адрес `/blog/authors`.
* **Публичным сегмент делает файл `page` или `route`.** Пока в папке нет такого файла, по её адресу ничего не открывается. `page` возвращает интерфейс (компонент React), `route` - HTTP-ответ (им займёмся в [уроке про обработчики маршрутов](lesson:nextjs.fundamentals.route-handlers)).

```text
app/
  layout.tsx            оболочка всех страниц
  page.tsx              адрес /
  blog/
    page.tsx            адрес /blog
    [slug]/
      page.tsx          адрес /blog/любая-строка
  _components/
    Button.tsx          не маршрут: приватная папка
```

Второе правило полезно само по себе: рядом со страницей можно держать компоненты, стили и тесты, и они не станут адресами. Наружу попадает только то, что возвращают `page` и `route`.

Страница - это компонент, который экспортируется из `page.tsx` по умолчанию. Если в `app/page.tsx` написать `export default function Page() { return <h1>Привет</h1>; }`, сайт покажет заголовок по адресу `/`. Компоненты в `app/` по умолчанию серверные; что это значит, разберёт [следующий урок](lesson:nextjs.fundamentals.server-components).

Правило «путь к файлу -> адрес» можно записать как небольшую функцию. Это упрощённая модель: она знает только файл `page.tsx` и группы `(name)`, о которых речь пойдёт ниже.

```typescript run
function urlOf(file: string): string | null {
  const parts = file.split("/");
  const name = parts.pop() ?? "";
  if (name !== "page.tsx") return null;
  const visible = parts.filter((folder) => !folder.startsWith("("));
  return "/" + visible.join("/");
}

const files = [
  "page.tsx",
  "blog/page.tsx",
  "blog/[slug]/page.tsx",
  "(shop)/cart/page.tsx",
  "blog/layout.tsx",
];
for (const file of files) {
  console.log(`${file} -> ${urlOf(file) ?? "не маршрут"}`);
}
```
```output
page.tsx -> /
blog/page.tsx -> /blog
blog/[slug]/page.tsx -> /blog/[slug]
(shop)/cart/page.tsx -> /cart
blog/layout.tsx -> не маршрут
```

Результат - **URL-шаблон**: запись адреса, в которой `[slug]` обозначает место, где подставляется любое значение.

## Примеры

**Пример 1. Макеты вкладываются друг в друга.** **Макет** (layout) - общая оболочка для страниц: шапка, меню, подвал. Он получает `children` - страницу или вложенный макет - и сам решает, где их показать.

```tsx
// app/layout.tsx - корневой макет
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ru">
      <body>{children}</body>
    </html>
  );
}

// app/blog/layout.tsx
export default function BlogLayout({ children }: { children: React.ReactNode }) {
  return <section><h2>Блог</h2>{children}</section>;
}
```

Для адреса `/blog/hello` Next.js строит дерево: `RootLayout` содержит `BlogLayout`, а тот содержит страницу. Переходя между страницами блога, макеты не пересоздаются: их состояние и позиция прокрутки сохраняются.

**Пример 2. Динамический сегмент.** Папка в квадратных скобках - место для любого значения.

```tsx
// app/blog/[slug]/page.tsx
export default async function Post({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  return <h1>Статья: {slug}</h1>;
}
```

Для `/blog/hello` значение `slug` равно `"hello"`. Почему `params` - промис и зачем `await`, объясняет следующий урок; пока достаточно записи `await params`.

**Пример 3. Группы маршрутов.** Папка в круглых скобках `(shop)` - **группа маршрутов**: она нужна для организации файлов и в адрес не попадает.

```text
app/
  (marketing)/
    layout.tsx          оболочка для лендинга
    page.tsx            адрес /
    about/page.tsx      адрес /about
  (shop)/
    layout.tsx          оболочка для магазина
    cart/page.tsx       адрес /cart
```

У разделов разные макеты, а адреса при этом не содержат слов `marketing` и `shop`. Если в `app/` нет собственного `layout.tsx`, макеты групп становятся несколькими корневыми макетами, и каждый из них обязан содержать `<html>` и `<body>`.

**Пример 4. Перехват остатка адреса.**

| Файл | Адрес | `params` |
| --- | --- | --- |
| `app/shop/[...slug]/page.tsx` | `/shop/a` | `{ slug: ["a"] }` |
| `app/shop/[...slug]/page.tsx` | `/shop/a/b` | `{ slug: ["a", "b"] }` |
| `app/shop/[...slug]/page.tsx` | `/shop` | не подходит |
| `app/docs/[[...slug]]/page.tsx` | `/docs` | `{}` (ключа `slug` нет) |
| `app/docs/[[...slug]]/page.tsx` | `/docs/a/b` | `{ slug: ["a", "b"] }` |

Запись `[...slug]` называется **catch-all** (поймать всё): значение - массив из одного и более сегментов. Двойные скобки `[[...slug]]` делают её необязательной: адрес без хвоста тоже подходит.

**Пример 5. Кириллица в адресе.** Браузер отправляет адрес в процентном кодировании, а в параметры нужно положить исходный текст:

```typescript run
const url = new URL("https://example.com/блог/привет-мир/?ref=1");
console.log(url.pathname);

const parts = url.pathname.split("/").filter((part) => part !== "");
console.log(parts.length);
console.log(parts.map((part) => decodeURIComponent(part)).join(" | "));
```
```output
/%D0%B1%D0%BB%D0%BE%D0%B3/%D0%BF%D1%80%D0%B8%D0%B2%D0%B5%D1%82-%D0%BC%D0%B8%D1%80/
2
блог | привет-мир
```

Пустые части пути, которые появляются от завершающего слэша, отбрасывают; остальные декодируют через `decodeURIComponent`. Это же вам понадобится в упражнении. **Попробуйте:** уберите `.filter(...)` и посмотрите, сколько частей получится.

## Точные правила

### Специальные файлы

Внутри сегмента имена файлов имеют особый смысл. Расширения: `.js`, `.jsx`, `.tsx` (для `route` - `.js` и `.ts`).

| Файл | Назначение |
| --- | --- |
| `page` | интерфейс сегмента; делает его публичным |
| `route` | обработчик HTTP-запросов (API) вместо интерфейса; делает сегмент публичным |
| `layout` | общая оболочка сегмента и всех вложенных; не перерисовывается при переходах между его страницами |
| `template` | как `layout`, но получает новый ключ при каждом переходе: состояние клиентских компонентов внутри сбрасывается |
| `loading` | заглушка, пока содержимое сегмента загружается (на основе Suspense) |
| `not-found` | интерфейс «ничего не найдено» для сегмента |
| `error` | граница ошибок: показывается, если внутри сегмента что-то упало |

Файлы `layout`, `template`, `loading`, `not-found`, `error` оформляют сегмент, но сами адреса не создают.

### Преобразование пути в адрес

1. Из пути берутся папки (имя файла отбрасывается).
2. Папки `(name)` - группы: в адрес не входят.
3. Папки `_name` - приватные: сама папка и всё внутри исключаются из маршрутизации. Если нужен сегмент адреса, начинающийся с подчёркивания, используйте `%5Fname`.
4. Остальные папки становятся сегментами; в `[x]`, `[...x]`, `[[...x]]` они образуют динамические сегменты.
5. Публичным сегмент становится, если в нём есть `page` или `route`.

Значения `params` имеют тип `string` для `[x]`, `string[]` для `[...x]` и `string[] | undefined` для `[[...x]]`: адрес вводит пользователь, поэтому заранее неизвестно, что в нём окажется.

### Какой маршрут выбирается

Адрес может подойти нескольким шаблонам. Например, `/blog/new` подходит и `/blog/new`, и `/blog/[slug]`. Документация Next.js не оформляет этого в отдельное правило; на практике внутренний упорядочиватель маршрутов ведёт себя так, и это же правило реализовано в упражнении:

1. Сегменты шаблонов сравниваются слева направо.
2. На первом сегменте с разными видами побеждает более конкретный: **статический**, затем `[x]`, затем `[...x]`, затем `[[...x]]`.

```typescript run
type Kind = "static" | "dynamic" | "catch-all" | "optional catch-all";

function kindOf(segment: string): Kind {
  if (/^\[\[\.\.\..+\]\]$/.test(segment)) return "optional catch-all";
  if (/^\[\.\.\..+\]$/.test(segment)) return "catch-all";
  if (/^\[.+\]$/.test(segment)) return "dynamic";
  return "static";
}

const rank: Record<Kind, number> = {
  static: 0,
  dynamic: 1,
  "catch-all": 2,
  "optional catch-all": 3,
};

const lastSegment = (pattern: string): string => pattern.split("/").pop() ?? "";

const patterns = ["/blog/[...rest]", "/blog/[slug]", "/blog/new"];
const ordered = [...patterns].sort(
  (a, b) => rank[kindOf(lastSegment(a))] - rank[kindOf(lastSegment(b))],
);
for (const pattern of ordered) {
  console.log(`${pattern} (${kindOf(lastSegment(pattern))})`);
}
```
```output
/blog/new (static)
/blog/[slug] (dynamic)
/blog/[...rest] (catch-all)
```

Так страница `/blog/new` остаётся достижимой, даже когда рядом есть `[slug]`.

### Конфликты

* В одном сегменте не может быть `page` и `route` одновременно: оба претендуют на один адрес и все HTTP-методы. `app/api/route.ts` рядом с `app/page.tsx` допустим, потому что адреса разные.
* Два файла в разных группах не должны давать один адрес: `(marketing)/about/page.tsx` и `(shop)/about/page.tsx` оба превращаются в `/about`, Next.js сообщит об ошибке.
* Если нет общего `app/layout.tsx` и используются несколько корневых макетов, главная страница `/` должна лежать внутри одной из групп.

### Корневой макет

В `app/` должен быть корневой макет, и он обязан содержать теги `<html>` и `<body>`: Next.js не добавляет оболочку документа сам. Корневых макетов может быть несколько (макет без вышестоящего `layout` считается корневым), но переход между разными корневыми макетами делается полной загрузкой страницы, а не клиентской навигацией. Теги `<title>` и `<meta>` вручную в корневой макет не пишут: для них есть API метаданных (следующий урок).

### Что в курс не входит

В App Router есть **параллельные маршруты** (папки `@slot`, несколько областей на одной странице) и **перехватывающие маршруты** (папки `(.)name`, `(..)name`, например окно предпросмотра поверх списка). Они существуют, но в этот курс не входят.

## Типичные ошибки

* **Создали папку без `page` и ждут адрес.** `/pricing` вернёт 404, если в `app/pricing/` лежит только `Table.tsx`. Добавьте `page.tsx` и экспортируйте из него компонент по умолчанию.
* **`export default` не из `page.tsx`.** Страницей считается только файл с точным именем `page`; `Page.tsx` или `index.tsx` маршрутом не станут. Регистр имени файла важен.
* **Положили `page.tsx` и `route.ts` рядом.** Next.js сообщит о конфликте. Разнесите их по разным сегментам, например `app/api/status/route.ts` и `app/status/page.tsx`.
* **Одинаковые адреса в разных группах.** `(a)/about/page.tsx` и `(b)/about/page.tsx` оба дают `/about`. Переименуйте один сегмент либо уберите дубль.
* **Корневой макет без `<html>` и `<body>`.** Это требование Next.js: именно корневой макет создаёт документ. Остальные макеты эти теги не добавляют, иначе документ окажется вложенным в документ.
* **Ожидают, что группа попадёт в адрес.** `(shop)/cart` - это `/cart`, а не `/shop/cart`. Если нужен сегмент `shop`, папка называется `shop` без скобок.
* **Путают `[...slug]` и `[[...slug]]`.** Первый не открывает адрес без хвоста (`/docs`), второй - открывает, но тогда `params.slug` может отсутствовать, и код должен это учитывать.
* **Ждут страницу внутри приватной папки.** `app/_admin/page.tsx` не маршрут: папка с подчёркиванием исключена целиком. Назовите её без `_` или используйте `%5F`.

## Итоги

* Папки в `app/` задают сегменты адреса, а публичным сегмент делает файл `page` или `route`; остальные файлы можно хранить рядом.
* Особые файлы: `layout`, `template`, `loading`, `not-found`, `error` оформляют сегмент, `page` и `route` создают адрес.
* Группы `(name)` не входят в адрес, приватные папки `_name` исключены из маршрутизации целиком.
* Динамические сегменты: `[x]` - одна строка, `[...x]` - массив из одного и более, `[[...x]]` - массив или отсутствие ключа.
* При выборе из нескольких шаблонов побеждает более конкретный: статический, затем динамический, затем catch-all; сравнение идёт слева направо.
* Макеты вкладываются от корня вглубь и сохраняются при навигации; корневой макет содержит `<html>` и `<body>`.
* Конфликты: `page` и `route` в одном сегменте, одинаковый адрес в разных группах.

## Для тех, кто знает другие фреймворки

* В Express, Django или Spring таблица маршрутов пишется в коде; в Next.js она выводится из дерева файлов, как в Nuxt и SvelteKit, но имя файла (`page`, `route`) важнее его расположения: другие файлы рядом не маршруты.
* В Pages Router (каталог `pages/`) любой файл становился страницей, а `pages/api/` содержал API. В App Router эти роли разделены на `page` и `route`, а служебные компоненты можно хранить рядом.
* `[slug]`, `[...slug]` и `[[...slug]]` соответствуют `:slug`, `*` и необязательному `*` в других маршрутизаторах, но `params` приходит промисом: его нужно ждать через `await`.
* Вложенные макеты (`layout`) сохраняют состояние при навигации; в React Router похожего эффекта добиваются вложенными `<Outlet />`.
* `middleware` в Next.js 16 называется `proxy`: это код, который выполняется до завершения запроса (перенаправления, заголовки); ему посвящён [отдельный урок](lesson:nextjs.fundamentals.proxy).

## Как вложены специальные файлы

Для одного сегмента Next.js собирает компоненты в фиксированном порядке (снаружи внутрь): `layout`, `template`, `error` (граница ошибок), `loading` (граница Suspense), `not-found` (граница «не найдено») и, наконец, `page` или вложенный `layout` дочернего сегмента. Из этого порядка следуют полезные факты:

* `error` в сегменте не ловит ошибки собственного `layout` этого же сегмента: макет находится снаружи границы. Для ошибок корневого макета есть отдельный `global-error`.
* `loading` оборачивает `page` и дочерние сегменты, но не `layout` своего сегмента: оболочка показывается сразу, а заглушка занимает место страницы.
* Компоненты дочернего сегмента вложены внутрь компонентов родительского, поэтому макет родителя остаётся на экране при переходе между дочерними страницами.
