## Где нужен браузер

Серверный компонент удобен тем, что выполняется до отправки страницы и не добавляет в браузер ни строчки своего кода. Но у него есть предел: он отработал один раз и исчез. Он не может хранить состояние между кликами, реагировать на ввод, читать `window` или `localStorage`. Всё, что должно «жить» в браузере, делают **клиентские компоненты** (Client Components).

Компонент нужно сделать клиентским, если он использует:

* состояние и эффекты (`useState`, `useEffect`, `useReducer`);
* обработчики событий (`onClick`, `onChange`, `onSubmit`);
* браузерные API (`window`, `localStorage`, `navigator`);
* хуки, которые зависят от браузера: в Next.js это `useRouter`, `usePathname` и `useSearchParams` из `next/navigation`.

Для этого первой строкой файла пишется директива `"use client"`:

```tsx
// app/ui/like-button.tsx
"use client";

import { useState } from "react";

export default function LikeButton({ initial }: { initial: number }) {
  const [likes, setLikes] = useState(initial);
  return <button onClick={() => setLikes(likes + 1)}>Нравится: {likes}</button>;
}
```

Директива не означает «этот компонент выполняется только в браузере». Клиентские компоненты тоже отрисовываются на сервере: из них собирается начальный HTML, а затем браузер **гидратирует** страницу, то есть подключает к готовой разметке обработчики событий. Поэтому первая версия кнопки появляется сразу, а по клику она начинает работать после загрузки JavaScript.

Директива задаёт **границу** между двумя мирами. Всё, что файл с `"use client"` импортирует, и компоненты, которые он отрисовывает прямо у себя, попадают в код для браузера. Эту границу можно записать как небольшую модель: по графу импортов найти модули, которые уйдут клиенту.

```typescript run
const imports: Record<string, string[]> = {
  "app/page.tsx": ["app/Header.tsx", "app/Counter.tsx", "app/Modal.tsx"],
  "app/Header.tsx": ["lib/format.ts"],
  "app/Counter.tsx": ["app/Button.tsx", "lib/clamp.ts"],
  "app/Modal.tsx": [],
  "app/Button.tsx": [],
  "lib/format.ts": [],
  "lib/clamp.ts": [],
};
const clientEntries = ["app/Counter.tsx", "app/Modal.tsx"]; // файлы с "use client"

function clientBundle(entries: string[]): string[] {
  const seen = new Set<string>();
  const visit = (file: string) => {
    if (seen.has(file)) return;
    seen.add(file);
    for (const next of imports[file] ?? []) visit(next);
  };
  entries.forEach(visit);
  return [...seen].sort();
}

console.log(clientBundle(clientEntries).join("\n"));
```
```output
app/Button.tsx
app/Counter.tsx
app/Modal.tsx
lib/clamp.ts
```

Страница `app/page.tsx` и компонент `Header` в список не вошли: они остаются на сервере. А `Button.tsx` и `clamp.ts` стали клиентскими без собственной директивы, потому что их импортирует `Counter.tsx`.

## Примеры

**Маленькие листья вместо большого клиентского дерева.** Страница остаётся серверной и подключает клиентские компоненты только там, где нужна интерактивность.

```tsx
// app/catalog/page.tsx - серверный компонент
import FavoriteButton from "../../components/FavoriteButton";

export default async function CatalogPage() {
  const items = await getCatalog(); // данные грузятся на сервере
  return (
    <ul>
      {items.map((item) => (
        <li key={item.id}>
          <span>{item.title}</span> <FavoriteButton title={item.title} />
        </li>
      ))}
    </ul>
  );
}
```

В браузер уходит код только `FavoriteButton`; функция `getCatalog`, обращения к базе и секреты остаются на сервере. Если бы директиву поставили на всю страницу, в клиентский код попало бы всё, что она импортирует.

**Хуки навигации.** Эти хуки читают состояние браузерной навигации и работают только в клиентских компонентах.

```tsx
"use client";

import Link from "next/link";
import { usePathname, useRouter, useSearchParams } from "next/navigation";

export function NavLink({ href, children }: { href: string; children: React.ReactNode }) {
  const pathname = usePathname(); // текущий путь, например "/catalog"
  return (
    <Link href={href} aria-current={pathname === href ? "page" : undefined}>
      {children}
    </Link>
  );
}

// useSearchParams().get("q") читает параметр запроса, router.push("/search?q=чай") выполняет переход.
```

**Серверное содержимое внутри клиентского компонента.** Клиентский компонент принимает `children`, а серверная страница кладёт туда свои элементы. Эти элементы отрисованы на сервере, а клиентский компонент только решает, показывать ли их.

```tsx
// components/Collapsible.tsx
"use client";

export default function Collapsible({ title, children }: { title: string; children: React.ReactNode }) {
  const [open, setOpen] = useState(false);
  return (
    <section>
      <button aria-expanded={open} onClick={() => setOpen(!open)}>{title}</button>
      {open && <div>{children}</div>}
    </section>
  );
}

// app/catalog/page.tsx (сервер)
<Collapsible title="О каталоге">
  <p>Позиций в каталоге: {items.length}</p>
</Collapsible>
```

Серверные компоненты, переданные как `children` или в другие props, не импортируются в модуль клиентского компонента, поэтому границу они не пересекают: их код остаётся на сервере.

## Как это работает точно

**Директива.** `"use client"` пишется в самом начале файла, до импортов, и действует на весь модуль; внутри функции или компонента её поставить нельзя. Достаточно пометить файлы, компоненты из которых вы подключаете прямо в серверных компонентах: остальные модули, которые они импортируют, станут клиентскими автоматически.

**Что происходит при первой загрузке.** Сервер отрисовывает серверные компоненты в RSC Payload, а из него и клиентских компонентов собирает HTML. Браузер показывает этот HTML, затем с помощью RSC Payload согласует деревья и гидратирует клиентские компоненты. При следующих переходах браузер получает RSC Payload новой страницы (он предзагружается и кэшируется), а клиентские компоненты отрисовываются уже в браузере.

**Props из сервера в клиент должны быть сериализуемыми.** Между сервером и браузером данные пересылаются как описание, поэтому в props допустимы строки, числа, булевы значения, `null`, массивы и обычные объекты из них (список поддерживаемых типов в React шире, например, есть `Date`), но не обычные функции. Исключение составляют серверные действия (Server Actions): их можно передавать как функции, это тема [урока про серверные действия](lesson:nextjs.fundamentals.server-actions). Идею проверки можно записать так:

```typescript run
function findNonSerializable(value: unknown, path = "props"): string[] {
  if (value === null) return [];
  const kind = typeof value;
  if (kind === "string" || kind === "number" || kind === "boolean") return [];
  if (kind === "function") return [path];
  if (Array.isArray(value)) {
    return value.flatMap((item, index) => findNonSerializable(item, `${path}[${index}]`));
  }
  if (kind === "object") {
    return Object.entries(value as Record<string, unknown>).flatMap(([key, item]) =>
      findNonSerializable(item, `${path}.${key}`),
    );
  }
  return [path];
}

const good = { title: "Чайник", price: 1490, tags: ["кухня", "сталь"] };
const bad = { title: "Чайник", onClick: () => {}, nested: { format: (n: number) => String(n) } };

console.log(findNonSerializable(good).join(", ") || "все значения допустимы");
console.log(findNonSerializable(bad).join(", "));
```
```output
все значения допустимы
props.onClick, props.nested.format
```

Обратите внимание: это упрощённая модель, а не настоящая проверка React. Она показывает, какие значения не пройдут через границу: функции в `props` придётся заменить данными (например, идентификатором) и обработать событие внутри клиентского компонента.

**Серверные компоненты внутри клиентских.** Нельзя импортировать серверный компонент в файл с `"use client"`: он станет клиентским. Зато его можно передать снаружи как `children` или в другой prop: тогда он отрисован на сервере.

**Хуки из `next/navigation`.**

* `useRouter()` возвращает объект с методами навигации; `router.push(url)` переходит по адресу. Для обычных переходов документация рекомендует компонент `Link`; `useRouter` нужен, когда переход выполняется кодом (например, после отправки формы).
* `usePathname()` возвращает текущий путь без параметров запроса.
* `useSearchParams()` возвращает параметры запроса только для чтения; `.get("q")` отдаёт строку или `null`.

Если маршрут готовится заранее (prerender), вызов `useSearchParams` приводит к тому, что дерево клиентских компонентов до ближайшей границы `Suspense` отрисовывается уже в браузере. Поэтому компонент с этим хуком рекомендуется оборачивать в `<Suspense>`.

**Защита от случайного импорта.** Модуль с секретами можно пометить импортом `import "server-only"`: если его подключить из клиентского компонента, сборка завершится ошибкой. Парный пакет `client-only` помечает код, который работает только в браузере. Установка пакетов необязательна: Next.js обрабатывает эти импорты сам. Без такой метки случайно импортированный серверный код всё равно не получит переменные окружения без префикса `NEXT_PUBLIC_` (они заменяются пустой строкой), но ошибка проявится не на сборке, а при работе.

**Контекст.** React-контекст в серверных компонентах не поддерживается. Провайдер оформляют клиентским компонентом, который принимает `children`, и подключают как можно глубже в дереве.

## Типичные ошибки

* **`"use client"` на каждом файле.** Директива нужна на границе, а не на каждом компоненте: всё, что импортирует такой файл, и так станет клиентским. Лишние директивы не нужны и скрывают реальную границу.
* **Директива на странице целиком.** Тогда `getCatalog()`, доступ к базе и обработка данных переезжают в клиентский код. Выносите в отдельный файл только интерактивную часть.
* **Директива не первой строкой.** Она должна стоять в самом начале файла, до импортов, и не может находиться внутри функции.
* **Функция в props.** `<FavoriteButton onToggle={() => ...} />` из серверной страницы не заработает: функцию нельзя сериализовать. Передайте данные и обрабатывайте событие внутри клиентского компонента.
* **`useSearchParams` вне `Suspense` на предварительно готовящейся странице.** Без границы вся клиентская часть до ближайшего `Suspense` отрисовывается в браузере, а не попадает в готовый HTML. Оберните компонент в `<Suspense>`: компоненты выше него останутся в начальном HTML.
* **Импорт серверного компонента в клиентский.** После такого импорта серверный компонент становится клиентским и теряет доступ к серверным данным. Передавайте его как `children`.
* **Определение текущей ссылки по началу пути.** Условие вида `pathname.startsWith(href)` для `/` отметит все ссылки как текущие. В упражнении сравнивается точное совпадение.

<!-- section: summary -->
## Итоги

* Состояние, эффекты, события и браузерные API требуют клиентского компонента: файла, первой строкой которого записано `"use client"`.
* Директива задаёт границу модуля: всё, что импортирует такой файл, попадает в код для браузера. Серверные элементы, переданные как `children`, границу не пересекают.
* Клиентские компоненты тоже отрисовываются на сервере и затем гидратируются.
* Props из серверного компонента в клиентский должны быть сериализуемыми: данные можно, обычные функции нельзя.
* `useRouter`, `usePathname` и `useSearchParams` работают только на клиенте; `useSearchParams` на готовящейся заранее странице оборачивают в `Suspense`.
* Делайте клиентскую часть маленькой: листья дерева вместо целых страниц.

<!-- section: programmer -->
## Если вы приходите из другого фреймворка

* В классическом SPA на React все компоненты клиентские. В App Router наоборот: по умолчанию серверные, а клиентскими их делает директива.
* Привычный SSR гидратирует всё дерево. Здесь гидратируются только клиентские компоненты, а серверные части не требуют JavaScript в браузере.
* `useRouter` из `next/navigation` - не `next/router`. Пакет `next/router` относится к Pages Router и в App Router не используется.

## Подробнее

**Почему тесты заменяют `next/navigation`.** Хуки навигации работают только внутри приложения Next.js, где есть маршрутизатор. В тестах Vitest их заменяют макетами: `useRouter` возвращает функцию-шпион `push`, `usePathname` - заданную строку, `useSearchParams` - объект `URLSearchParams`. Так можно проверить, что компонент переходит по нужному адресу, не запуская сервер.

**Как проверить, что страница осталась серверной.** Расставленная директива - часть исходного текста файла, поэтому тест читает файлы и проверяет, что в компонентах директива стоит первым оператором, а в `page.tsx` её нет.
