## Программа на JavaScript - это текст, который исполняет движок

Сам по себе файл `main.js` ничего не делает. Его читает **движок JavaScript** - программа, которая понимает язык.
Здесь и в браузере Chrome это движок **V8**; в этом курсе файл запускает Node.js (среда выполнения на базе V8),
то есть команда выглядит как `node main.js`. Операционная система создаёт процесс, движок читает файл и выполняет его сверху вниз.

Вывод в консоль - это `console.log`. Он не часть языка, а функция, которую предоставляет среда запуска:
Node.js направляет её текст в **стандартный вывод** (stdout) процесса. Те же слова можно перенаправить в файл, не меняя код.
Так же устроена автоматическая проверка упражнений: она запускает программу и читает её stdout.

Ввод приходит по другому каналу - **стандартному вводу** (stdin). В Node.js его можно прочитать целиком одной строкой:

```javascript
const text = require("node:fs").readFileSync(0, "utf8");
```

`0` - номер файлового дескриптора stdin. Дальше `text` - обычная строка, и программа превращает её в числа сама.

## Как V8 превращает текст в выполнение

JavaScript не «просто интерпретируется». Движок V8 работает в несколько этапов:

1. **Разбор.** Текст превращается в дерево программы (AST). Синтаксическая ошибка находится здесь, до выполнения любой строки.
2. **Байткод.** Из дерева строится компактный байткод, и его выполняет интерпретатор **Ignition**.
3. **Оптимизация во время работы (JIT).** Движок следит, какие функции вызываются часто, и компилирует их в машинный код
   оптимизирующим компилятором **TurboFan**. Оптимизация опирается на предположения о типах (например, «здесь всегда числа»);
   если предположение нарушается, машинный код отбрасывается и выполнение возвращается к байткоду.

Следствие: скорость JavaScript зависит от того, насколько предсказуемы типы значений в горячем коде.
Но результат программы от этого не меняется - оптимизации не должны влиять на семантику языка.

**Язык и среда - разные вещи.** Стандарт ECMAScript (ECMA-262) описывает синтаксис, типы, объекты и встроенные функции вроде `Math` и `JSON`.
Он не определяет ни `console.log`, ни чтение файлов, ни `stdin`: это предоставляет *хост* - браузер или Node.js.
Поэтому `document` существует только в браузере, а `require("node:fs")` и `process` - только в Node.js.

**Числа.** В JavaScript обычное число (`number`) - всегда 64-битное число с плавающей точкой IEEE 754 (двойной точности).
Отдельного «целого» типа нет, есть только `bigint` для произвольно больших целых. Точно представимы целые до `Number.MAX_SAFE_INTEGER`
(9007199254740991, то есть 2^53 - 1). Поэтому `Number("12")` даёт `12`, а `0.1 + 0.2` даёт не `0.3`, а `0.30000000000000004`.

**Преобразование строки в число.** `Number("  42 ")` - `42` (пробелы по краям отбрасываются), `Number("")` - `0`, `Number("abc")` - `NaN`
(«не число», значение типа `number`). `parseInt("42px", 10)` - `42`, то есть читает цифры с начала строки и останавливается на первом лишнем символе.

**Разбор текста на слова.** `text.split(/\s+/)` режет строку по любым пробельным символам, включая переводы строк.
Если строка начинается с пробела, первым элементом будет пустая строка; `text.trim().split(/\s+/)` этого избегает.
Для пустой строки `"".split(/\s+/)` возвращает `[""]` - массив из одной пустой строки, а не пустой массив.

**Форматирование.** `x.toFixed(2)` возвращает *строку* с двумя знаками после точки. `console.log(a, b)` печатает аргументы через пробел.

## Примеры

**Пример 1. Разбор происходит до выполнения.** Конструктор `Function` разбирает строку как код. Ошибка синтаксиса выбрасывается сразу, ещё до вызова.

```javascript run
try {
  new Function("return 1 +");
} catch (e) {
  console.log(e.name);
}
console.log(new Function("return 1 + 2")());
```
```output
SyntaxError
3
```

**Пример 2. Строки и числа.** `+` с одной строкой склеивает, а `Number` преобразует явно.

```javascript run
console.log(Number("12") + 1);
console.log("12" + 1);
console.log(0.1 + 0.2);
console.log(Number("abc"), Number(""));
console.log((2.5).toFixed(2), typeof (2.5).toFixed(2));
```
```output
13
121
0.30000000000000004
NaN 0
2.50 string
```

В последней строке `console.log` принял два аргумента и поставил между ними пробел. `toFixed` вернул строку, поэтому `typeof` - `string`.

**Пример 3. Отладочный вывод не попадает в stdout.** `console.error` пишет в stderr.

```javascript run
console.log("результат");
console.error("диагностика");
```
```output
результат
```

Проверка упражнения сравнивает только stdout, поэтому диагностику можно печатать через `console.error`, не ломая ответ.

**Пример 4. Весь ввод одной строкой.** Типичная форма программы: прочитать, разобрать, вычислить, вывести.

```javascript
const text = require("node:fs").readFileSync(0, "utf8");
const tokens = text.trim().split(/\s+/);
const n = Number(tokens[0]);
const nums = tokens.slice(1, 1 + n).map(Number);
console.log(nums.length);
```

## Типичные ошибки

* **Сложение строк вместо чисел.** После `split` все токены - строки: `"3" + "4"` равно `"34"`. Преобразуйте их в числа (`Number`, `.map(Number)`) до вычислений.
* **Пустая строка в начале или конце.** `text.split(/\s+/)` для текста с завершающим переводом строки даёт последний элемент `""`, а `Number("")` равно `0`.
  Лишний ноль незаметно портит `min`, `max` и среднее. Используйте `trim()` или читайте ровно `n` чисел.
* **`.map(parseInt)`.** `map` передаёт функции три аргумента: элемент, индекс, массив. `parseInt` воспринимает индекс как основание системы счисления, и `["1","2","3"].map(parseInt)` даёт `[1, NaN, NaN]`.
  Пишите `.map(Number)` или `.map(s => parseInt(s, 10))`.
* **Ожидание целочисленного деления.** `7 / 2` равно `3.5`, а не `3`. Для целой части используйте `Math.trunc(7 / 2)`.
* **`toFixed` вместо числа.** Результат `toFixed` - строка; складывать его с числом нельзя, форматируйте только в самом конце.
* **`Math.max(...arr)` на огромных массивах.** Спред превращает элементы в аргументы вызова, а у движка есть предел на их число. Для очень больших данных используйте `reduce` или цикл.
* **Ожидание, что `console.log` часть языка.** В браузере и в Node.js он есть, но стандарт ECMAScript его не требует.

<!-- section: summary -->
## Итоги

* Файл `.js` исполняет движок: V8 разбирает текст, выполняет байткод в Ignition и компилирует горячий код в TurboFan.
* `console.log`, `process`, `require` предоставляет среда запуска, а не язык; ECMAScript описывает только сам язык.
* Любое обычное число - 64-битное число с плавающей точкой; `bigint` нужен для точных больших целых.
* Ввод читается из stdin целиком строкой, затем `trim()`, `split(/\s+/)` и явное преобразование в числа.
