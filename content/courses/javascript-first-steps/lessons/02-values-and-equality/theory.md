## Что значит «равно» в JavaScript

В JavaScript у сравнения три разных смысла, и путаница между ними - источник половины странных багов.

* `a === b` - **строгое равенство**: значения одного типа и одинаковы. Приведения типов нет.
* `a == b` - **нестрогое равенство**: если типы разные, значения сначала по определённым правилам приводятся друг к другу.
* Для **объектов** (массивы, `{}`, функции) обе операции сравнивают не содержимое, а **ссылки**: «это один и тот же объект?».

```javascript
console.log(1 === "1");     // false: разные типы
console.log(1 == "1");      // true: строку привели к числу
console.log([1] === [1]);   // false: два разных объекта
```

Правило практики: по умолчанию пишите `===`. `==` оправдан в редких случаях, когда вы точно знаете правила приведения.

## Примитивы и объекты, строгое и нестрогое равенство

**Типы.** Примитивные значения: `undefined`, `null`, `boolean`, `number`, `bigint`, `string`, `symbol`. Всё остальное - объекты,
включая массивы и функции. Примитивы неизменяемы и сравниваются по значению; объекты живут «где-то в памяти», а в переменной лежит **ссылка** на них.

**Присваивание копирует ссылку, а не объект.**

```javascript
const a = [1, 2];
const b = a;        // b ссылается на тот же массив
b.push(3);
console.log(a);     // [1, 2, 3]
```

`const` запрещает *переприсваивание имени*, но не изменение объекта, на который оно ссылается. При вызове функции аргумент тоже передаётся «по значению ссылки»:
функция может изменить переданный объект, но не может заставить внешнюю переменную указывать на другой.

**`typeof`** возвращает строку с типом. Историческая особенность: `typeof null` равно `"object"`, хотя `null` - примитив. Это ошибка ранней реализации, сохранённая ради совместимости.
Поэтому проверка «это объект» требует явного исключения `null`: `typeof x === "object" && x !== null`. Массив отличается от объекта через `Array.isArray(x)`.

**Строгое равенство (`===`).** Если типы разные - `false`. Для чисел: `NaN === NaN` равно `false`, а `0 === -0` равно `true`.
Для объектов - `true` только если это одна и та же ссылка.

**`Object.is`** отличается от `===` двумя случаями: `Object.is(NaN, NaN)` равно `true`, а `Object.is(0, -0)` равно `false`.

**Нестрогое равенство (`==`)** при разных типах приводит операнды:

* `null == undefined` равно `true`, и больше ни с чем (включая `0` и `false`) `null` и `undefined` через `==` не равны.
* `число == строка`: строка преобразуется в число. `1 == "1"` - `true`, `0 == ""` - `true`, `0 == "0"` - `true`, а `"0" == ""` - `false`, потому что обе строки: приведения нет, строки сравниваются как строки.
* `boolean == что-угодно`: булево значение сначала становится числом (`true` - `1`, `false` - `0`). Поэтому `"1" == true` истинно, а `"true" == true` - ложно (`"true"` даёт `NaN`).
* `объект == примитив`: объект превращается в примитив (`ToPrimitive`; у массива это `toString`, то есть элементы через запятую). `[1] == 1` - `true`, `[] == ""` - `true`, `[1, 2] == "1,2"` - `true`.
* `объект == объект`: сравниваются ссылки.

**Глубокое сравнение** содержимого в языке не встроено; его пишут самостоятельно: обходят свойства рекурсивно. Для JSON-подобных данных нужно учесть
`null` (он имеет `typeof` `"object"`), различие массива и объекта и порядок ключей (он не важен для равенства объектов).

## Примеры

**Пример 1. Что даёт `==`.**

```javascript run
console.log(1 == "1", 0 == "", "0" == "");
console.log(null == undefined, null == 0, null == false);
console.log(true == "1", true == "true");
console.log([] == "", [1, 2] == "1,2");
```
```output
true true false
true false false
true false
true true
```

Каждая пара следует правилам выше. Особенно важно `null == 0` - `false`: `null` равен нестрого только `undefined`.

**Пример 2. Объекты сравниваются по ссылке.**

```javascript run
const a = { x: 1 };
const b = { x: 1 };
const c = a;
console.log(a === b, a === c);
c.x = 99;
console.log(a.x, b.x);
console.log(JSON.stringify(a) === JSON.stringify(b));
```
```output
false true
99 1
false
```

`a` и `c` - одна и та же ссылка, поэтому изменение через `c` видно в `a`. Объект `b` лишь выглядел так же; после изменения содержимое разошлось.

**Пример 3. `NaN`, `-0` и `Object.is`.**

```javascript run
console.log(NaN === NaN, Object.is(NaN, NaN));
console.log(0 === -0, Object.is(0, -0));
console.log(typeof null, typeof [], Array.isArray([]));
```
```output
false true
true false
object object true
```

Проверку на `NaN` пишут через `Number.isNaN(x)` или `Object.is`, но не через `x === NaN`.

**Пример 4. Передача объекта в функцию.**

```javascript run
function reset(list) {
  list.length = 0;   // меняем тот же объект
  list = [42];       // меняем только локальное имя
}
const items = [1, 2, 3];
reset(items);
console.log(items);
```
```output
[]
```

## Типичные ошибки

* **`[] == false` считают «странностью» и пишут `if (arr == false)`.** Правила приведения делают это истинным, но проверять пустоту нужно через `arr.length === 0`.
* **Сравнение объектов оператором `===` в расчёте на содержимое.** `[1, 2] === [1, 2]` всегда `false`. Для сравнения нужен рекурсивный обход, а не `JSON.stringify`: он зависит от порядка ключей и теряет `undefined` и `NaN`.
* **`typeof x === "object"` без исключения `null`.** Для `null` оно тоже истинно, и обращение к свойству упадёт с `TypeError`.
* **`x === NaN`.** Всегда `false`; используйте `Number.isNaN(x)`.
* **Копирование через присваивание.** `const copy = original` не создаёт копию. Поверхностную копию массива даёт `[...original]`, объекта - `{...original}`; вложенные объекты при этом всё равно общие.
* **Считают `const` «неизменяемым».** `const` защищает имя, а не объект.
* **Привычка писать `==` «для краткости».** Чтобы сказать «`null` или `undefined`», допустимо `x == null`, но это осознанное исключение, а не общее правило.

<!-- section: summary -->
## Итоги

* Примитивы сравниваются по значению, объекты - по ссылке; присваивание копирует ссылку.
* `===` не приводит типы; `==` приводит по фиксированным правилам (`null == undefined`, строка в число, булево в число, объект в примитив).
* `NaN !== NaN`, `0 === -0`; `Object.is` различает эти случаи иначе.
* `typeof null` равно `"object"`; массив отличают через `Array.isArray`.
* Глубокого сравнения в языке нет - его пишут сами, учитывая `null`, массивы и порядок ключей.
