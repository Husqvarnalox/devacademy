## Что проверяет эта проверка

`throw new Error`, `try / catch / finally`, собственные классы ошибок и `instanceof`, чтение ввода как текста, деление на строки и поля, строгий разбор чисел вместо `Number("")`, сбор ошибок данных в список.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Ошибки и исключения](lesson:javascript.from-zero.errors-and-exceptions), [Чтение ввода](lesson:javascript.from-zero.reading-input).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```javascript run
class ParseError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ParseError";
    this.field = field;
  }
}
function parseQty(text) {
  if (!/^[1-9]\d*$/.test(text.trim())) throw new ParseError("bad qty", "qty");
  return Number(text);
}
for (const t of ["3", " 12 ", "", "0", "2x"]) {
  try {
    console.log(parseQty(t));
  } catch (e) {
    console.log(e instanceof ParseError ? `${e.field}: ${e.message}` : "другая ошибка");
  }
}
console.log("a,b\n\nc".split("\n"), Number(""), Number("2x"));
```
```output
3
12
qty: bad qty
qty: bad qty
qty: bad qty
[ 'a,b', '', 'c' ] 0 NaN
```

Ошибка данных описана своим классом и перехватывается по `instanceof`. Пустая строка и строка с буквой не проходят регулярное выражение, а `Number("")` без проверки дал бы `0`.

<!-- section: precise -->
## Что нужно уметь

* бросать `new Error(...)` и свои подклассы и ловить их в `try / catch`;
* отличать ожидаемую ошибку данных от ошибки программиста и не глотать вторую;
* делить текст на строки (`\n` и `\r\n`) и поля и пропускать пустые строки;
* строго проверять числа до приведения: `Number("")` равно `0`, `parseInt("12x")` равно `12`;
* собирать несколько ошибок в список вместо остановки на первой;
* объяснять порядок `try`, `catch` и `finally`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Пустой `catch`, который прячет любые ошибки, в том числе баги в самой функции.
* `Number("")` и `Number(" ")` дают `0`, и пустое поле становится числом.
* Подкласс `Error` без `this.name`: имя остаётся `Error`.
* Лишний пустой элемент после `split("\n")`, когда ввод заканчивается переводом строки.
* Бросок строки `throw "bad"` вместо `new Error("bad")`: нет `message` и трассировки.
