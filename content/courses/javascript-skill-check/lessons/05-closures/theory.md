## Что проверяет эта проверка

Лексические области видимости и замыкания, разница `var` и `let` в циклах, временная мёртвая зона, правила определения `this` (вызов метода, отдельная функция, `call`/`apply`/`bind`, стрелочные функции), состояние, спрятанное в замыкании.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Области видимости и замыкания](lesson:javascript.fundamentals.scope-and-closures), [this и функции](lesson:javascript.fundamentals.this-and-functions).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```javascript run
function makeCounter() {
  let n = 0;
  return { inc: () => ++n };
}
const a = makeCounter();
const b = makeCounter();
const { inc } = a;
inc(); inc(); b.inc();
console.log(a.inc(), b.inc());

const user = { name: "Ада", hi() { return this?.name; } };
const detached = user.hi;
console.log(user.hi(), detached(), detached.call({ name: "Лин" }));
```
```output
3 2
Ада undefined Лин
```

Переменная `n` принадлежит конкретному вызову `makeCounter` и живёт, пока на неё ссылается хотя бы одна функция. А `this` зависит от того, как функцию вызвали: через точку, отдельно или через `call`.

<!-- section: precise -->
## Что нужно уметь

* объяснять, что замыкание хранит ссылку на переменную, а не копию значения;
* предсказывать вывод цикла с `var` и с `let` при отложенных вызовах;
* знать, что `let` и `const` недоступны до объявления (временная мёртвая зона), а `var` поднимается со значением `undefined`;
* определять `this` по месту вызова: `obj.f()`, `f()`, `f.call(x)`, `new F()`;
* знать, что `bind` фиксирует `this` навсегда, а стрелочная функция берёт `this` из окружающего кода;
* писать фабрики и обёртки (`once`, привязка метода), не теряя `this` и аргументы.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Замыкания в цикле с `var` видят последнее значение переменной.
* Метод, переданный как колбэк (`setTimeout(obj.m)`, `arr.map(obj.m)`), теряет получателя.
* Обёртка из стрелочной функции не может передать собственный `this`; для этого нужна `function` и `apply(this, args)`.
* Метод ищут и сохраняют заранее, а потом удивляются, что замена `obj.method` не заметна.
* Состояние в `this` или в переменной модуля вместо локальной переменной фабрики делает счётчики общими.
