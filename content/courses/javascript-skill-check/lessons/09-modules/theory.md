## Что проверяет эта проверка

ES-модули: именованные и `default`-экспорты, живые привязки, порядок выполнения зависимостей, пространство имён `import * as`, отличие от CommonJS; чистые функции, удобные для тестов; `node:assert` в строгом режиме.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитывается урок: [ES-модули и тесты на node:test](lesson:javascript.fundamentals.modules-and-testing).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```javascript run
const assert = require("node:assert/strict");
const source = `
  export function total(items) { return items.reduce((s, x) => s + x, 0); }
  export const unit = "шт.";
`;
import("data:text/javascript," + encodeURIComponent(source)).then((ns) => {
  console.log(Object.keys(ns).join(), "default" in ns);
  assert.equal(ns.total([1, 2, 3]), 6);
  assert.deepEqual(ns.total([]), 0);
  console.log("проверки прошли");
});
```
```output
total,unit false
проверки прошли
```

Пространство имён модуля содержит ровно то, что экспортировано. Чистую функцию вроде `total` легко проверить `assert`: результат зависит только от аргументов.

<!-- section: precise -->
## Что нужно уметь

* отличать именованный экспорт (`export function f`) от `export default` и знать, как их импортировать;
* объяснять, что `import` - живая привязка только для чтения, а не копия значения;
* предсказывать порядок выполнения модулей: зависимости раньше, импорты поднимаются наверх;
* понимать, что модуль выполняется один раз, а код верхнего уровня не должен печатать и менять глобальное состояние;
* писать чистые функции, не изменяющие аргументы, и покрывать их проверками `assert`;
* знать, что `node:assert/strict` сравнивает без приведения типов.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Экспорт лишних внутренних помощников делает их частью публичного интерфейса модуля.
* `console.log` на верхнем уровне срабатывает при каждом импорте модуля.
* `sort` без копии меняет массив вызывающего кода и падает на замороженном массиве.
* Попытка присвоить импортированную привязку заканчивается `TypeError`.
* В ES-модуле нет `require`, `module` и `__dirname`: они существуют только в CommonJS.
