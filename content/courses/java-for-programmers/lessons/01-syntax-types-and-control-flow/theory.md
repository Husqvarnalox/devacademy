## Зачем этот урок

Если вы пишете на Python, JavaScript, Go или C#, то переменные, условия и циклы Java узнаете сразу. Отличия прячутся в мелочах: `int` занимает ровно 32 бита и молча переполняется, `7 / 2` равно `3`, а `'a' + 1` - число, а не буква; `Scanner` ведёт себя неожиданно после `nextInt`, а `printf` на русской локали печатает запятую вместо точки. Урок собирает такие места в одном месте. Успешное прохождение (упражнение и квиз) засчитывает уроки 01-16 курса «Java с нуля».

## Главная мысль

Java статически типизирована, а её числовые типы имеют фиксированный размер. Компилятор строго следит за типами, но **внутри** типа арифметика не проверяет границ. Поэтому три привычки решают большинство проблем: выбирать `long`, когда сумма может выйти за два миллиарда; помнить, что деление целых отбрасывает дробную часть; и переводить `char` в строку или обратно явно.

## Пример 1. Целые числа: переполнение, деление, остаток

```java run
public class Main {
    public static void main(String[] args) {
        int big = Integer.MAX_VALUE;
        System.out.println(big + 1);
        System.out.println(Math.abs(Integer.MIN_VALUE));
        System.out.println(7 / 2 + " " + -7 / 2 + " " + -7 % 3 + " " + Math.floorMod(-7, 3));
        System.out.println(big * 2);
        System.out.println((long) big * 2);
        System.out.println(3_000_000_000L);
        System.out.println(Math.multiplyExact(100_000L, 100_000L));
        try {
            Math.addExact(big, 1);
        } catch (ArithmeticException e) {
            System.out.println(e.getMessage());
        }
    }
}
```
```output
-2147483648
-2147483648
3 -3 -1 2
-2
4294967294
3000000000
10000000000
integer overflow
```

Разбор:

* Переполнение `int` не бросает исключения: значение «заворачивается» от максимума к минимуму. `Math.abs(Integer.MIN_VALUE)` остаётся отрицательным, потому что `+2147483648` в `int` не помещается.
* Деление двух целых - целое с отбрасыванием дробной части **к нулю**: `7 / 2` равно `3`, а `-7 / 2` равно `-3`. Остаток `%` берёт знак делимого: `-7 % 3` равно `-1`. Неотрицательный остаток даёт `Math.floorMod`.
* `big * 2` вычисляется в `int` и переполняется, поэтому приведение нужно делать **до** умножения: `(long) big * 2`. Приведение результата `(long) (big * 2)` уже ничего не исправит.
* Литерал больше `int` пишут с суффиксом `L`. Подчёркивания в числах (`3_000_000_000L`) - только для читаемости.
* `Math.addExact`, `subtractExact` и `multiplyExact` бросают `ArithmeticException` при переполнении - удобно там, где молчаливая ошибка опаснее исключения.

## Пример 2. char, приведения и дробные числа

```java run
public class Main {
    public static void main(String[] args) {
        char c = 'a';
        System.out.println(c + 1);
        System.out.println((char) (c + 1));
        c += 1;
        System.out.println(c);
        System.out.println("" + c + 1);
        double d = 2.9;
        System.out.println((int) d + " " + (int) -2.9 + " " + Math.round(2.5) + " " + Math.round(-2.5));
        int i = 10;
        i += 2.7;
        System.out.println(i);
        System.out.println((byte) 200);
        System.out.println(0.1 + 0.2);
        System.out.println(1.0 / 0 + " " + 0.0 / 0);
        System.out.println(10 / 4 * 2.0 + " " + 10 / 4.0 * 2);
    }
}
```
```output
98
b
b
b1
2 -2 3 -2
12
-56
0.30000000000000004
Infinity NaN
4.0 5.0
```

Разбор:

* `char` - числовой тип (16 бит). `c + 1` вычисляется как `int`, поэтому печатается код `98`. Чтобы снова получить символ, нужно приведение `(char)`. Составное присваивание `c += 1` вставляет такое приведение само.
* `i += 2.7` значит `i = (int) (i + 2.7)`: дробная часть теряется молча. А вот `int x = 2.7;` не скомпилируется: **сужение** без явного приведения запрещено, а **расширение** (`int` в `long`, `int` в `double`) разрешено.
* `(int)` отбрасывает дробную часть к нулю (`(int) -2.9` равно `-2`); `Math.round` округляет к ближайшему целому, половину - вверх (`Math.round(-2.5)` равно `-2`) и возвращает `long`.
* `(byte) 200` сохраняет только младшие 8 бит и даёт `-56`. Приведения чисел к меньшим типам не проверяют границ.
* Деление дробных чисел на ноль исключения не бросает: `Infinity` и `NaN`. Целое деление на ноль бросает `ArithmeticException`. Дроби неточны так же, как в любом языке с `double`.
* Порядок вычислений важен: `10 / 4 * 2.0` сначала делит целые (получается `2`), `10 / 4.0 * 2` сразу работает с дробными.

## Пример 3. switch: две формы

```java run
public class Main {
    static String kind(String day) {
        return switch (day) {
            case "sat", "sun" -> "выходной";
            case "mon", "tue", "wed", "thu", "fri" -> "будний";
            default -> "неизвестно";
        };
    }

    public static void main(String[] args) {
        System.out.println(kind("sat") + " " + kind("tue") + " " + kind("xyz"));
        int n = 2;
        switch (n) {
            case 1:
                System.out.println("one");
            case 2:
                System.out.println("two");
            case 3:
                System.out.println("three");
                break;
            default:
                System.out.println("other");
        }
    }
}
```
```output
выходной будний неизвестно
two
three
```

Разбор:

* Стрелочный `switch` (Java 14+) - выражение: у него есть значение, несколько меток через запятую и **нет проваливания**. Если случай не покрыт и нет `default`, выражение `switch` не скомпилируется (для строк и чисел `default` обязателен).
* Классическая форма с двоеточием выполняет все блоки подряд, пока не встретит `break`. Здесь после `case 2` напечатаны `two` и `three`.
* `switch` работает с `int`, `char`, `String` и перечислениями. Строки сравниваются через `equals`.

## Пример 4. Ввод и вывод: nextLine и локаль

```java run
import java.util.Locale;
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner("5\nИван Петров\n2,50\n");
        int n = in.nextInt();
        String rest = in.nextLine();
        String name = in.nextLine();
        System.out.println("n=" + n + " rest=[" + rest + "] name=[" + name + "]");
        String price = in.next();
        double value = Double.parseDouble(price.replace(',', '.'));
        System.out.printf(Locale.ROOT, "%.2f %5d|%-5d|%05d%n", value, 42, 42, 42);
        System.out.println(String.format(Locale.ROOT, "%,d", 1234567));
    }
}
```
```output
n=5 rest=[] name=[Иван Петров]
2.50    42|42   |00042
1,234,567
```

Разбор:

* `Scanner` можно создать не только над `System.in`, но и над строкой - так удобно проверять разбор. `nextInt()` читает число и оставляет перевод строки; следующий `nextLine()` возвращает пустой остаток (`rest=[]`), и только второй вызов читает саму строку. Либо читайте всё через `next()`, либо после числа один раз вызовите `nextLine()` вхолостую.
* `nextDouble()` и `String.format` без локали используют **локаль системы**: на русской или белорусской локали дробная часть отделяется запятой (`2,50`), на английской - точкой. Программа, которую проверяют автоматически, должна быть от этого независима: читайте `Double.parseDouble(in.next())` (точка) и всегда передавайте `Locale.ROOT` в `printf` и `String.format`.
* Спецификаторы: `%d` - целое, `%s` - строка, `%.2f` - дробное с двумя знаками, `%n` - перевод строки платформы, `%5d` и `%-5d` - ширина с выравниванием справа и слева, `%05d` - дополнение нулями, `%,d` - с разделителями разрядов.

**Попробуйте.** Измените значение в `Math.round(2.5)` на `-2.5` и `Math.round(2.4)`, замените в `switch` значение `n` на `1`, `3` и `7` и предскажите вывод до запуска.

<!-- section: precise -->
* Целые типы: `byte` (8 бит), `short` (16), `int` (32), `long` (64) - все со знаком. `char` - беззнаковый 16-битный код UTF-16. Дробные: `float` (32) и `double` (64). `boolean` не является числом и не приводится к нему.
* Литералы: `10` - `int`, `10L` - `long`, `1.5` - `double`, `1.5f` - `float`, `'x'` - `char`, `"x"` - `String`.
* Расширяющее преобразование (меньший тип в больший) неявное; сужающее требует приведения `(int) x`. Смешанная арифметика поднимает операнды: `byte`, `short`, `char` становятся `int`; если есть `long` - `long`; если `float`/`double` - дробный тип.
* Арифметика `int` и `long` переполняется молча по модулю `2^32` и `2^64`. Проверяющие версии: `Math.addExact`, `subtractExact`, `multiplyExact`, `toIntExact`.
* `/` для двух целых - деление с отбрасыванием к нулю, `%` - остаток со знаком делимого; деление целого на ноль - `ArithmeticException`. `Math.floorDiv` и `Math.floorMod` округляют к минус бесконечности.
* `==` для чисел и символов сравнивает значения. Для строк и объектов он сравнивает ссылки, поэтому строки сравнивают через `equals` (подробно - в следующем уроке).
* Составное присваивание `x op= y` эквивалентно `x = (T) (x op y)`, где `T` - тип переменной.
* Область видимости переменной - блок `{}`; переменную с таким же именем во вложенном блоке объявить нельзя. Локальная переменная не получает значения по умолчанию и должна быть присвоена до чтения. `var` выводит тип по правой части (`var n = 5;` - `int`), но только для локальных переменных.
* `for (init; условие; шаг)` и `while` как в C; метки `outer:` позволяют `break outer` и `continue outer` для вложенных циклов. Тернарный оператор `a ? b : c` - выражение.
* `Scanner(System.in)`: `next()` читает слово, `nextInt()` - число, `nextLine()` - остаток строки; `hasNext()`, `hasNextInt()` и `hasNextLine()` проверяют наличие данных. `Integer.parseInt` и `Double.parseDouble` бросают `NumberFormatException` и не принимают пробелы вокруг числа.

<!-- section: mistakes -->
**1. Дробное значение в int.** `int x = 3.5;` не компилируется:

```text
Main.java:3: error: incompatible types: possible lossy conversion from double to int
```

Компилятор защищает от потери данных. Если потеря задумана, напишите `(int) 3.5` или `Math.round(3.5)`.

**2. Присваивание вместо сравнения.** В отличие от C, `if (z = 5)` не скомпилируется, потому что условие должно быть `boolean`:

```text
Main.java:7: error: incompatible types: int cannot be converted to boolean
```

**3. Сравнение строк оператором `>`.** Для строк нет операторов порядка:

```text
Main.java:8: error: bad operand types for binary operator '>'
```

Используйте `a.compareTo(b)` (число меньше, равно или больше нуля).

**4. Сужение в явном виде не указано.** Литерал `200` не помещается в `byte`, а `long` не присваивается `int` без приведения:

```text
Main.java:9: error: incompatible types: possible lossy conversion from int to byte
Main.java:11: error: incompatible types: possible lossy conversion from long to int
```

**5. Необъявленное или неприсвоенное значение.** Локальная переменная не имеет значения по умолчанию: `int y; System.out.println(y);` даёт `variable y might not have been initialized`.

**6. Тип метки не совпадает с типом switch.** `case 1` при `switch (s)` для строки `s`:

```text
Main.java:13: error: incompatible types: int cannot be converted to String
```

**7. Молчаливые ошибки, которые компилятор не видит.** Переполнение `int` (`count * price` для больших значений), потеря дробной части в `i += 2.7`, деление целых там, где ждали дробное (`sum / n` при целых `sum` и `n`), запятая в `printf` на русской локали, `nextLine()` после `nextInt()`. Здесь помогают тесты на границах и привычки из этого урока.

## Главное для тех, кто уже программирует

* Статическая типизация с фиксированными размерами: `int` 32 бита, `long` 64. Переполнение молчит (в Python целые не ограничены, в C# есть `checked`); проверяющие версии - `Math.addExact` и друзья.
* `/` для целых отбрасывает дробную часть к нулю (как в C, Go, C#; в Python `//` округляет вниз, в JavaScript все числа дробные). `%` берёт знак делимого; неотрицательный остаток - `Math.floorMod`.
* `char` - число, `'a' + 1` равно `98`. Строки неизменяемы, символ строки - `charAt(i)` (UTF-16, как в JavaScript и C#).
* Сужение требует приведения; `+=` вставляет его сам. `boolean` не приводится к числу, условие обязано быть `boolean`.
* Деление на ноль: целые - исключение, дробные - `Infinity`/`NaN`. `Math.round` возвращает `long`.
* `switch`: стрелки без проваливания и со значением (Java 14+); двоеточия проваливаются как в C.
* Ввод: `Scanner`; `nextLine()` после `nextInt()` возвращает остаток строки. Форматирование и `nextDouble` зависят от локали; для предсказуемого вывода - `Locale.ROOT`.
* Метки для вложенных циклов есть; `for-each` по массивам и коллекциям - следующий урок.
* Программа - класс `Main` с `static void main(String[] args)`; с Java 25 допускаются «компактные» файлы без обёртки, в Java 22 это включается флагом предварительных возможностей.

## Почему переполнение молчит

`int` в байткоде - 32-битное число в дополнительном коде: сложение выполняет та же машинная инструкция, что и для обычных чисел, а лишний бит отбрасывается. Проверка границ на каждой операции замедлила бы все программы, поэтому Java оставила её явной (`Math.addExact`) - и такая же практика принята в C, Go и Rust в режиме release. JIT-компилятор умеет использовать сложение с проверкой переноса, поэтому `addExact` дешёвый.
