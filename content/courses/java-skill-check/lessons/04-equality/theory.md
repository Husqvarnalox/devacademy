## Что проверяет эта проверка

Различие примитивов и ссылок, оператор `==` для ссылок, `equals` для содержимого, автоупаковка и кэш `Integer`, сравнение с `null`, `Objects.equals`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Примитивы и объекты: == против equals, упаковка](lesson:java.first-steps.primitives-objects-and-equality).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

## Пример того, что понадобится

```java run
import java.util.Objects;

public class Main {
    public static void main(String[] args) {
        Integer a = 127;
        Integer b = 127;
        Integer c = 1000;
        Integer d = 1000;
        System.out.println((a == b) + " " + (c == d) + " " + c.equals(d));
        String s = new String("hi");
        System.out.println((s == "hi") + " " + s.equals("hi"));
        String missing = null;
        System.out.println(Objects.equals(missing, null) + " " + Objects.equals("hi", missing));
    }
}
```
```output
true false true
false true
true false
```
Значения от -128 до 127 при упаковке берутся из общего кэша, поэтому `a == b` истинно, а для `1000` создаются два объекта и `==` ложно. `new String(...)` всегда создаёт отдельный объект. `Objects.equals(x, y)` корректно работает и тогда, когда один из аргументов `null`, а вызов `missing.equals(...)` бросил бы `NullPointerException`.

<!-- section: precise -->
## Что нужно уметь

* объяснять, что `==` для объектов сравнивает ссылки, а `equals` - содержимое;
* сравнивать `String` и `Integer` через `equals`, а не `==`;
* предсказывать результат `==` для упакованных чисел внутри и вне кэша от -128 до 127;
* безопасно сравнивать значения, которые могут быть `null`, через `Objects.equals`;
* помнить, что `Long.equals(Integer)` даёт `false` из-за разных типов;
* знать, что распаковка `null` бросает `NullPointerException`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* `==` для строк: работает на литералах и ломается на данных из ввода.
* `==` для `Integer`: правильно только для значений в кэше, поэтому ошибка проявляется на больших числах.
* `a.equals(b)` при `a == null` бросает `NullPointerException`.
* `Long` и `Integer` с одним числом не равны по `equals`.
* Присваивание `int m = n;` при `Integer n = null` бросает исключение при распаковке.
