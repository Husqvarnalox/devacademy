## Что проверяет эта проверка

Классы с полями и методами, `record` (компоненты, автоматические `equals`, `hashCode` и `toString`), компактный конструктор для проверки данных, `enum` с методами и статическими фабриками, равенство объектов и работа с `HashSet`.

## Что даёт прохождение

Проверка состоит из короткого упражнения с запуском тестов и квиза на чтение кода (порог квиза - 75%). Если пройдены обе части, засчитываются уроки: [Классы, записи, перечисления и равенство](lesson:java.fundamentals.classes-records-enums).

Если не пройдены, ничего не отнимается: прогресс сохраняется, а система покажет первый незавершённый урок из этого списка как место для повторения. Проверку можно пройти снова в любой момент, и открыть её можно без каких-либо условий.

<!-- section: examples -->
## Пример того, что понадобится

```java run
import java.util.*;

public class Main {
    enum Size {
        SMALL, LARGE;
        static Size of(int cm) {
            return cm < 50 ? SMALL : LARGE;
        }
    }

    record Box(String label, int cm) {
        Box {
            if (cm <= 0) {
                throw new IllegalArgumentException("размер должен быть положительным: " + cm);
            }
        }

        Size size() {
            return Size.of(cm);
        }
    }

    public static void main(String[] args) {
        Box a = new Box("книги", 40);
        Box b = new Box("книги", 40);
        System.out.println(a + " " + a.equals(b) + " " + (a == b) + " " + a.size());
        Set<Box> seen = new HashSet<>(List.of(a));
        System.out.println(seen.contains(b) + " " + Size.valueOf("LARGE").ordinal());
        try {
            new Box("пусто", 0);
        } catch (IllegalArgumentException e) {
            System.out.println(e.getMessage());
        }
    }
}
```
```output
Box[label=книги, cm=40] true false SMALL
true 1
размер должен быть положительным: 0
```
У `record` `equals`, `hashCode` и `toString` строятся по компонентам, поэтому две записи с одинаковыми данными равны и находятся в `HashSet`. Компактный конструктор выполняется до присваивания полей и может отвергнуть данные исключением. Перечисление `Size` хранит варианты и может иметь методы; `ordinal()` - номер варианта с нуля.

## Что нужно уметь

* объявлять `record` с компонентами и получать доступ через методы `id()` и `amount()`, а не через поля;
* проверять данные в компактном конструкторе и бросать `IllegalArgumentException` с понятным сообщением;
* описывать `enum` с методами и статической фабрикой `of`, перебирать варианты через `values()`;
* объяснять, почему записи равны по компонентам, а обычные классы без `equals` - по ссылке;
* помнить, что компоненты записи неизменяемы (`final`);
* использовать запись как элемент `HashSet` и ключ `HashMap`.

<!-- section: mistakes -->
## На чём чаще всего ошибаются

* Класс без `equals` и `hashCode` в `HashSet`: два объекта с одинаковыми данными считаются разными.
* Обращение `p.x()` заменяют на `p.getX()` по привычке: у записи методы называются так же, как компоненты.
* Попытка изменить компонент записи (`p.x = 5`) не компилируется: `cannot assign a value to final variable x`.
* Проверка в обычном методе вместо компактного конструктора: некорректный объект уже создан.
* `Level.valueOf("low")` с неверным регистром бросает `IllegalArgumentException`.
* Сравнение значений `enum` через `==` корректно, а через `equals` тоже, но `==` безопаснее с `null`.
