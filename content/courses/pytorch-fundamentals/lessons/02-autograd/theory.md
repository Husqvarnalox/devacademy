## Откуда берётся градиент без формул

В курсе [«Основы машинного обучения»](lesson:ml.foundations.linear-regression) мы выводили градиент потерь вручную, а в курсе по [NumPy](lesson:ml.numpy.linear-regression) записывали его матрицами. Для линейной модели это просто. Для сети из десятков слоёв выводить формулы руками невозможно, и здесь работает **автоматическое дифференцирование** (autograd): PyTorch запоминает, какие операции вы выполнили над тензорами, и потом применяет правило цепочки в обратном порядке.

Схема работы:

1. Создаёте тензор-параметр с `requires_grad=True`: «следи за ним».
2. Выполняете обычные вычисления до скалярной потери `loss`. Каждая операция записывается в граф.
3. Вызываете `loss.backward()`. Градиент потери по каждому параметру появляется в его поле `.grad`.

Всё остальное в обучении — это то, что вы делаете с `.grad`: сдвигаете параметры против градиента (спуск), обнуляете градиенты перед следующим шагом и не забываете выключать запись графа там, где градиенты не нужны.

Полезная привычка: **проверять autograd независимой формулой**. Если аналитический градиент или центральная разность совпали с `.grad`, вы поняли и модель, и код.

<!-- section: precise -->
## Граф, листья и backward

Каждый тензор, полученный из тензора с `requires_grad=True`, хранит ссылку на функцию, которая его создала (`grad_fn`). Тензоры, созданные вами напрямую (параметры), называются **листовыми**. Вызов `loss.backward()` проходит граф от `loss` к листьям и **прибавляет** к `.grad` каждого листа вклад этого прохода. Три следствия:

* **Накопление.** Два вызова `backward()` без обнуления дают сумму градиентов. Это не ошибка дизайна: так можно накапливать градиент по нескольким мини-батчам. Но в обычном цикле перед каждым шагом градиент нужно обнулять (`optimizer.zero_grad()` или `x.grad = None`).
* **Граф одноразовый.** После `backward()` буферы графа освобождаются. На каждом шаге обучения прямой проход строит граф заново (поэтому граф называют динамическим).
* **Только листья.** Для нелистовых тензоров `.grad` не сохраняется, если не вызвать `retain_grad()`.

`loss` для `backward()` должен быть скаляром (иначе нужно передать вектор весов `gradient=...`).

## Вне графа: `no_grad` и `detach`

* `with torch.no_grad():` — внутри блока операции не записываются; результат имеет `requires_grad=False`. Используется при оценке модели, предсказаниях и ручном обновлении параметров: `w -= lr * w.grad` без `no_grad` пытался бы записать само обновление в граф (для листа с градиентом PyTorch это вообще запрещено).
* `x.detach()` — тензор с теми же данными (и **общей памятью**), но вне графа. Для независимой копии: `x.detach().clone()`.

## Проверка градиента

Для функции `f` и точки `x` аналитическая проверка — сравнение с формулой (для MSE линейной модели: `∇ = (2/n) Xᵀ (Xw - y)`). Универсальная проверка — **центральная разность** `(f(x + h eᵢ) - f(x - h eᵢ)) / (2h)`: ошибка метода порядка `h²`. Для `float64` и `h = 1e-6` ожидайте расхождение около `1e-8`; для `float32` такая проверка слишком грубая из-за округления, поэтому градиенты проверяют в `float64`.

## Примеры

**Пример 1. Градиент многочлена и сравнение с производной.**

```python run
import torch

x = torch.tensor(2.0, requires_grad=True)
f = 3 * x ** 3 - 2 * x + 1
print("f(2) =", f.item())
print("leaf:", x.is_leaf, "| grad_fn у f:", f.grad_fn is not None)
f.backward()
print("autograd:", x.grad.item())
print("аналитически 9x^2 - 2 =", 9 * 2.0 ** 2 - 2)
```
```output
f(2) = 21.0
leaf: True | grad_fn у f: True
autograd: 34.0
аналитически 9x^2 - 2 = 34.0
```

**Пример 2. Градиент MSE по весам и накопление.**

```python run
import torch

g = torch.Generator().manual_seed(0)
X = torch.randn(6, 2, generator=g, dtype=torch.float64)
y = torch.randn(6, generator=g, dtype=torch.float64)
w = torch.zeros(2, dtype=torch.float64, requires_grad=True)

loss = ((X @ w - y) ** 2).mean()
loss.backward()
analytic = 2.0 / 6 * X.T @ (X.detach() @ w.detach() - y)
print("совпадает с (2/n) X^T (Xw - y):", bool(torch.allclose(w.grad, analytic)))

first = w.grad.clone()
loss2 = ((X @ w - y) ** 2).mean()
loss2.backward()                                     # без обнуления
print("градиент удвоился:", bool(torch.allclose(w.grad, 2 * first)))

w.grad = None
loss3 = ((X @ w - y) ** 2).mean()
loss3.backward()
print("после обнуления снова исходный:", bool(torch.allclose(w.grad, first)))
```
```output
совпадает с (2/n) X^T (Xw - y): True
градиент удвоился: True
после обнуления снова исходный: True
```

**Пример 3. no_grad и detach.**

```python run
import torch

w = torch.tensor([1.0, 2.0], requires_grad=True)
x = torch.tensor([3.0, 4.0])

y = (w * x).sum()
print("с графом: requires_grad =", y.requires_grad)

with torch.no_grad():
    z = (w * x).sum()
    print("в no_grad: requires_grad =", z.requires_grad)
    w -= 0.1 * x                                       # обновление параметра вне графа
print("w после обновления:", [round(v, 2) for v in w.tolist()], "| w всё ещё параметр:", w.requires_grad)

d = w.detach()
d[0] = 100.0                                           # detach делит память!
print("w после записи в detach:", [round(v, 2) for v in w.tolist()])
```
```output
с графом: requires_grad = True
в no_grad: requires_grad = False
w после обновления: [0.7, 1.6] | w всё ещё параметр: True
w после записи в detach: [100.0, 1.6]
```

## Типичные ошибки

* **Не обнулять градиенты.** Градиенты накапливаются, шаги получаются завышенными и «прыгают». Обнуляйте перед каждым `backward()` или используйте `optimizer.zero_grad()`.
* **Вызывать `backward()` на не-скаляре.** Потеря должна быть скаляром: усредните (`.mean()`) или просуммируйте.
* **Обновлять параметры вне `no_grad`.** `w -= lr * w.grad` вне блока приводит к ошибке про листовой тензор, которому нужен градиент.
* **Считать `loss.item()` внутри графа и накапливать сам `loss`.** `history.append(loss)` хранит граф и память; кладите `loss.item()`.
* **Думать, что `detach()` копирует.** Он делит память с исходным тензором.
* **Проверять градиенты в `float32` слишком малым шагом.** Для центральных разностей используйте `float64` и `h` порядка `1e-6`.
* **Вызывать `backward()` дважды по одному графу.** Граф освобождён; постройте прямой проход заново.

<!-- section: summary -->
## Итоги

* `requires_grad=True` включает запись графа; `loss.backward()` прибавляет градиенты в `.grad` листьев.
* Градиенты накапливаются: обнуляйте их перед каждым новым `backward()`.
* Вне обучения вычисляйте под `torch.no_grad()`; `detach()` отделяет тензор от графа, но делит память.
* Проверяйте autograd аналитической формулой или центральной разностью в `float64`.
* Для линейной модели с MSE градиент по весам равен `(2/n) Xᵀ (Xw - y)` — ровно то, что мы писали руками.

## Сравнение с GoMLX и NumPy

В [GoMLX](lesson:go.ml.gomlx.automatic-differentiation) градиент запрашивается как отдельная операция над графом, который сначала описывается целиком. В PyTorch граф рождается сам при выполнении кода и живёт один шаг, поэтому в нём работают обычные `if` и циклы Python. Платой за это становятся обязанности пользователя: следить за накоплением в `.grad` и за тем, какие вычисления попадают в граф. NumPy автоматического дифференцирования не умеет вовсе, поэтому в курсе [«Классическое ML на NumPy»](lesson:ml.numpy.logistic-regression) градиенты выводились вручную.
