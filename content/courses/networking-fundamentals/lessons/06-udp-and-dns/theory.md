## Письма без конвертов подтверждения

TCP из прошлого урока - как телефонный звонок: сначала соединение, потом разговор с подтверждением каждой фразы. **UDP** - открытка: вы отправляете **датаграмму** и не знаете, дошла ли она, в каком порядке и один ли раз. Зато нет ни рукопожатия, ни ожидания: открытка уходит сразу.

Это не недостаток, а выбор. UDP подходит, когда:

* ответ умещается в один пакет, а ожидание рукопожатия дороже самого обмена (**DNS**);
* потерянные данные бессмысленно повторять, потому что они устаревают (голос, видео, игры);
* нужен собственный протокол надёжности поверх (QUIC, на котором работает HTTP/3, строит надёжный поток поверх UDP).

Главный пример - **DNS**, «телефонная книга» интернета: он превращает имя `example.com` в адрес. Запрос и ответ обычно помещаются в одну датаграмму. Сообщение DNS - компактная двоичная структура: заголовок, затем вопросы и ответы. Чтобы не повторять `example.com` в каждой записи, имена **сжимаются**: вместо повтора ставится «ссылка» на место, где имя уже встречалось. Разобраться в такой структуре значит научиться читать любой двоичный протокол: идти по байтам, помнить позицию и аккуратно проверять границы ([struct и работа с двоичными данными](lesson:python.stdlib.json-csv-struct), [буферы и кодировки](lesson:nodejs.fundamentals.buffers-encodings)).

UDP-датаграмма, как и TCP-сегмент, вкладывается в IP-пакет ([заголовок IP и контрольная сумма](lesson:networking.fundamentals.ipv4-header-and-checksum)); сравните его простоту с автоматом состояний TCP ([урок про TCP](lesson:networking.fundamentals.tcp-connections-and-congestion)).

## Заголовок UDP, контрольная сумма и формат DNS

**Заголовок UDP** (8 байт, сетевой порядок):

| смещение | размер | поле |
|---|---|---|
| 0 | 2 | порт отправителя |
| 2 | 2 | порт получателя |
| 4 | 2 | длина (заголовок + данные) |
| 6 | 2 | контрольная сумма |

Порт отправителя и получателя вместе с адресами определяют «разговор». Сервер DNS слушает порт 53.

**Контрольная сумма UDP** считается теми же правилами RFC 1071, что и сумма IP (дополнение до единицы суммы 16-битных слов), но не над одним заголовком, а над **псевдозаголовком**, заголовком UDP и данными. Псевдозаголовок IPv4: адрес отправителя (4 байта), адрес получателя (4), нулевой байт, номер протокола `17`, длина UDP (2). Он нужен, чтобы датаграмма не могла быть принята не тем адресатом, если IP-заголовок будет повреждён. Если данных нечётное число, дополняют нулевым байтом. Результат `0` отправляется как `0xFFFF`; в IPv4 нулевое поле значит «сумма не вычислялась».

**Сообщение DNS.**

* **Заголовок, 12 байт:** `id` (2), флаги (2), `qdcount`, `ancount`, `nscount`, `arcount` (по 2).
* **Флаги** (16 бит): QR (1 бит, 0 запрос, 1 ответ), OPCODE (4), AA (авторитетный), TC (усечён), RD (желательна рекурсия), RA (рекурсия доступна), три нулевых бита, RCODE (4).
* **Секции:** вопросы, ответы, авторитетные серверы, дополнительные.

**Вопрос:** имя, QTYPE (2), QCLASS (2). **Запись ресурса:** имя, TYPE (2), CLASS (2), TTL (4), RDLENGTH (2), RDATA. Типы: A = 1 (4 байта IPv4), NS = 2, CNAME = 5, AAAA = 28 (16 байт IPv6). Класс обычно IN = 1.

**Имя** состоит из меток: байт длины `n` (0-63) и `n` байтов. Нулевая длина завершает имя. `example.com` кодируется как `07 example 03 com 00`.

**Сжатие.** Если два старших бита байта длины равны `11`, то этот байт и следующий образуют **указатель**: 14 младших бит - смещение от начала сообщения, где имя продолжается. Имя может состоять из меток, за которыми идёт указатель, либо только из указателя. Типичный ответ начинается с `c0 0c`: имя ответа - то, что в вопросе по смещению 12. Правила разбора:

1. Позиция после имени в основном потоке - сразу за первым встреченным указателем (либо за нулевым байтом, если указателей не было).
2. Указатель должен вести **строго назад**, иначе возможна петля. Разумная защита от зацикливания: требовать цель меньше текущей позиции.
3. Значения `01` и `10` в старших битах зарезервированы.
4. Имя в rdata (CNAME, NS) тоже может использовать указатели и читается относительно всего сообщения, а не от начала rdata.

**RCODE.** 0 NOERROR, 1 FORMERR, 2 SERVFAIL, 3 NXDOMAIN, 4 NOTIMP, 5 REFUSED. NOERROR без записей значит, что имя есть, но данных этого типа нет.

**Размер.** Классический лимит UDP-сообщения DNS - 512 байт. Если ответ не помещается, сервер ставит бит TC, и клиент повторяет запрос по TCP; расширение EDNS(0) позволяет договориться о большем размере.

## Примеры

**Датаграмма UDP: упаковка и контрольная сумма с псевдозаголовком.** Алгоритм суммы тот же, что для заголовка IP:

```python run
import struct

def checksum(data):
    if len(data) % 2:
        data += b"\x00"
    total = sum(struct.unpack("!%dH" % (len(data) // 2), data))
    while total >> 16:
        total = (total & 0xFFFF) + (total >> 16)
    return ~total & 0xFFFF

payload = b"hello"
length = 8 + len(payload)
src, dst = bytes([192, 0, 2, 1]), bytes([192, 0, 2, 53])
pseudo = src + dst + struct.pack("!BBH", 0, 17, length)
header = struct.pack("!HHHH", 40000, 53, length, 0)
csum = checksum(pseudo + header + payload)
datagram = struct.pack("!HHHH", 40000, 53, length, csum) + payload
print(len(datagram), datagram.hex(" "))
print("checksum = 0x%04x" % csum)
print("проверка (должен быть 0):", checksum(pseudo + datagram))
```
```output
13 9c 40 00 35 00 0d 9b 55 68 65 6c 6c 6f
checksum = 0x9b55
проверка (должен быть 0): 0
```

**Запрос DNS: сборка байтов.** Закодируем имя метками и соберём запрос типа A:

```python run
import struct

def encode_name(name):
    out = b""
    for label in name.split("."):
        out += bytes([len(label)]) + label.encode("ascii")
    return out + b"\x00"

header = struct.pack("!HHHHHH", 0x1A2B, 0x0100, 1, 0, 0, 0)  # RD=1, один вопрос
query = header + encode_name("example.com") + struct.pack("!HH", 1, 1)
print(len(query), "байт")
print(query.hex(" "))
print(encode_name("example.com"))
```
```output
29 байт
1a 2b 01 00 00 01 00 00 00 00 00 00 07 65 78 61 6d 70 6c 65 03 63 6f 6d 00 00 01 00 01
b'\x07example\x03com\x00'
```

**Разворачивание сжатого имени.** В ответе имя заменено указателем `c0 0c` на смещение 12:

```python run
msg = bytes.fromhex(
    "1a2b81800001000100000000"          # заголовок
    "076578616d706c6503636f6d0000010001"  # вопрос: example.com A IN
    "c00c000100010000012c00045db8d822"    # ответ: имя=указатель, A, TTL 300, 93.184.216.34
)

def read_name(data, pos):
    labels, end = [], None
    while True:
        n = data[pos]
        if n & 0xC0 == 0xC0:
            target = ((n & 0x3F) << 8) | data[pos + 1]
            if end is None:
                end = pos + 2
            pos = target
        elif n == 0:
            return ".".join(labels), (end if end is not None else pos + 1)
        else:
            labels.append(data[pos + 1:pos + 1 + n].decode())
            pos += 1 + n

question_end = 12 + len(bytes.fromhex("076578616d706c6503636f6d0000010001"))
name, after = read_name(msg, question_end)
print("имя ответа:", name, "| позиция после имени:", after, "| следующий байт ответа:", msg[after:after + 2].hex())
print("TTL:", int.from_bytes(msg[after + 4:after + 8], "big"), "| адрес:", ".".join(str(b) for b in msg[-4:]))
```
```output
имя ответа: example.com | позиция после имени: 31 | следующий байт ответа: 0001
TTL: 300 | адрес: 93.184.216.34
```

Позиция после имени в потоке сдвинулась только на 2 байта (на сам указатель), хотя читалось 11 символов.

## Типичные ошибки

* **Читать rdata CNAME с начала rdata.** Указатели внутри имён отсчитываются от начала всего сообщения, поэтому в `read_name` нужно передавать всё сообщение.
* **Двигать позицию по длине прочитанного имени.** После указателя позиция в исходном потоке продолжается сразу за указателем, а не за целевым именем. Переход записи к следующей полю делайте через RDLENGTH.
* **Разрешать указатели вперёд или на себя.** Это даёт бесконечные циклы и уязвимости. Требуйте строго меньшее смещение.
* **Принимать любой байт длины.** Значения от 64 до 191 (биты `01` и `10`) недопустимы; метка не длиннее 63 байт.
* **Путать NXDOMAIN и пустой NOERROR.** Первое - имени нет совсем, второе - имя есть, но записей нужного типа нет.
* **Считать UDP ненадёжным значит «плохим».** Это инструмент: когда задержка важнее надёжности или надёжность реализуется выше (QUIC).
* **Забыть про TC.** Усечённый ответ нужно повторить по TCP, а не использовать как есть.
* **Игнорировать порядок байтов.** Все числа в DNS и UDP сетевые (big-endian): `struct.unpack("!H", ...)`.

## Итоги

* UDP - датаграммы без соединения, подтверждений и порядка; заголовок 8 байт; сумма считается с псевдозаголовком.
* DNS-сообщение: 12-байтный заголовок, затем вопросы и записи; числа сетевые.
* Имя - метки с длиной и завершающий ноль; указатель `11xxxxxx xxxxxxxx` - смещение от начала сообщения, только назад.
* После указателя позиция в потоке продолжается сразу за ним; rdata двигают по RDLENGTH.
* NXDOMAIN (RCODE 3) отличается от пустого NOERROR; усечённый (TC) ответ повторяют по TCP.
