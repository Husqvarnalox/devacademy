## Конверт, который открывает только адресат

HTTP по умолчанию передаёт всё открытым текстом: любой маршрутизатор по пути может прочитать или подменить пароль и страницу. **TLS** (Transport Layer Security) оборачивает соединение в защитный слой и даёт три свойства:

* **Конфиденциальность** - данные шифруются, посторонний видит лишь поток шифротекста;
* **Целостность** - подмену или порчу данных заметят;
* **Аутентификация сервера** - клиент убеждается, что говорит именно с `example.com`, а не с подставным узлом, с помощью **сертификата**.

HTTP, обёрнутый в TLS, называется HTTPS ([HTTP и его версии](lesson:networking.fundamentals.http-evolution)).

Перед защищённым обменом стороны проводят **рукопожатие**: клиент присылает **ClientHello** («я умею такие версии и шифры, мне нужен сайт example.com, я говорю на h2»), сервер отвечает выбором и сертификатом, стороны договариваются о ключах. Обычно это один круговой обход.

Когда сеть работает не так, как ожидается, помогают диагностические утилиты. `ping` отвечает «жив ли узел», `traceroute` показывает маршрутизаторы на пути, `dig` спрашивает DNS ([DNS](lesson:networking.fundamentals.udp-and-dns)), `curl -v` показывает всё: TCP-соединение, TLS и HTTP. Каждая работает на своём уровне модели ([уровни и инкапсуляция](lesson:networking.fundamentals.layers-and-encapsulation)), и умение определить, на каком уровне ломается, и есть главное диагностическое умение. Как надёжно обрабатывать сетевые ошибки в коде, см. [надёжные HTTP-клиенты](lesson:python.automation.robust-http-clients). Разбор двоичных структур по длинам полей повторяет приёмы из урока про [struct](lesson:python.stdlib.json-csv-struct).

## Записи, рукопожатие, сертификаты и инструменты

**Запись TLS.** Всё передаётся записями: заголовок 5 байт - тип содержимого (`22` рукопожатие, `23` данные приложения, `21` предупреждение, `20` change cipher spec), версия записи (2), длина (2, не более 2^14 для открытого текста), затем содержимое. Для совместимости версия записи ClientHello чаще `0x0301`.

**Рукопожатие (сообщение).** Тип (1 байт) и длина (3 байта). `1` - ClientHello, `2` - ServerHello.

**ClientHello:** версия (`0x0303` для TLS 1.2 и для совместимости 1.3), 32 случайных байта, session id (до 32 байт, в 1.3 для совместимости), список **шифронаборов** (по 2 байта; в TLS 1.3 их пять, например `0x1301` TLS_AES_128_GCM_SHA256), методы сжатия (в 1.3 только нулевой) и **расширения** (тип 2, длина 2, данные).

Основные расширения:

| тип | имя | назначение |
|---|---|---|
| 0 | server_name (SNI) | имя желаемого сервера |
| 10 | supported_groups | эллиптические кривые для обмена ключами |
| 13 | signature_algorithms | допустимые алгоритмы подписи |
| 16 | ALPN | прикладной протокол (`h2`, `http/1.1`) |
| 43 | supported_versions | реальные версии TLS клиента |
| 45 | psk_key_exchange_modes | режимы возобновления |
| 51 | key_share | публичная часть обмена ключами |

**GREASE.** Клиенты подмешивают значения вида `0x?A?A` в списки, чтобы реализации серверов не привыкали к фиксированному набору и не ломались на новых значениях.

**TLS 1.3, ход рукопожатия (1-RTT).** 1) Клиент: ClientHello с `key_share` (предположение о группе). 2) Сервер: ServerHello со своим `key_share`; дальше всё шифруется: EncryptedExtensions, Certificate, CertificateVerify, Finished. 3) Клиент проверяет сертификат и подпись, отправляет Finished и начинает передавать данные. Ключи выводятся из обмена Диффи - Хеллмана на эллиптических кривых, поэтому даже компрометация долгоживущего ключа сервера не раскрывает прошлые сессии (прямая секретность). Возобновление по PSK и 0-RTT сокращают рукопожатие, но 0-RTT уязвим к повторам.

**Сертификат и цепочка доверия.** Сервер предъявляет сертификат X.509 со своим открытым ключом и именами в **Subject Alternative Name (SAN)**. Он подписан промежуточным удостоверяющим центром, тот - корневым; корневые сертификаты хранятся в системе клиента. Проверка включает: подпись каждого звена, срок действия, отзыв, и совпадение имени хоста с SAN (в том числе шаблоны вида `*.example.com`). Частые ошибки: истёк срок, не хватает промежуточного сертификата, имя не совпадает, самоподписанный сертификат, неверные часы на клиенте.

**SNI виден.** Расширение SNI передаётся в открытом виде, поэтому наблюдатель видит имя, к которому вы обращаетесь, хотя содержимое скрыто (Encrypted ClientHello решает это, но в уроке не разбирается).

**Диагностика по уровням.**

| утилита | что делает | уровень |
|---|---|---|
| `ping` | ICMP Echo Request/Reply, показывает потери и RTT | сетевой |
| `traceroute` | пакеты с TTL 1, 2, 3...; каждый маршрутизатор отвечает ICMP Time Exceeded | сетевой |
| `dig` | DNS-запрос и ответ, TTL, rcode | прикладной (DNS) |
| `curl -v` | DNS, TCP, TLS, HTTP: все этапы | прикладной |

В песочнице нет сети, поэтому блоки ниже с утилитами **не запускаются**: это иллюстративный вывод, который показывает, как читать такие результаты.

## Примеры

**Сборка ClientHello с SNI и разбор записи.** Соберём упрощённый ClientHello и вынем из него запись и рукопожатие:

```python run
import struct

def build_client_hello(host):
    name = host.encode()
    sni = struct.pack("!HBH", len(name) + 3, 0, len(name)) + name
    exts = struct.pack("!HH", 0, len(sni)) + sni
    body = (struct.pack("!H", 0x0303) + bytes(range(32)) + b"\x00"
            + struct.pack("!HHH", 4, 0xC02F, 0xC030) + b"\x01\x00"
            + struct.pack("!H", len(exts)) + exts)
    handshake = b"\x01" + len(body).to_bytes(3, "big") + body
    return struct.pack("!BHH", 22, 0x0301, len(handshake)) + handshake

record = build_client_hello("example.com")
ctype, version, length = struct.unpack("!BHH", record[:5])
print("тип записи", ctype, "версия 0x%04x" % version, "длина", length, "всего байт", len(record))
print("тип рукопожатия", record[5], "длина", int.from_bytes(record[6:9], "big"))
print(record[:16].hex(" "))
```
```output
тип записи 22 версия 0x0301 длина 69 всего байт 74
тип рукопожатия 1 длина 65
16 03 01 00 45 01 00 00 41 03 03 00 01 02 03 04
```

**Поиск SNI и ALPN в расширениях.** Расширения идут списком «тип, длина, данные»; нужный тип находят, перепрыгивая по длинам:

```python run
sni_ext = bytes.fromhex("0000" "0010" "000e" "00" "000b") + b"example.com"
alpn_ext = bytes.fromhex("0010" "000e" "000c") + bytes([2]) + b"h2" + bytes([8]) + b"http/1.1"
blob = sni_ext + alpn_ext

pos, found = 0, {}
while pos < len(blob):
    ext_type = int.from_bytes(blob[pos:pos + 2], "big")
    ext_len = int.from_bytes(blob[pos + 2:pos + 4], "big")
    found[ext_type] = blob[pos + 4:pos + 4 + ext_len]
    pos += 4 + ext_len
print("типы расширений:", sorted(found))
sni = found[0]
print("SNI:", sni[5:].decode(), "| длина имени:", int.from_bytes(sni[3:5], "big"))
alpn, p = [], 2
while p < len(found[16]):
    n = found[16][p]
    alpn.append(found[16][p + 1:p + 1 + n].decode())
    p += 1 + n
print("ALPN:", alpn)
```
```output
типы расширений: [0, 16]
SNI: example.com | длина имени: 11
ALPN: ['h2', 'http/1.1']
```

**GREASE.** Правило проверяется двумя битовыми операциями:

```python run
def is_grease(value):
    return value & 0x0F0F == 0x0A0A and (value >> 8) == (value & 0xFF)

values = [0x0A0A, 0x1A1A, 0xFAFA, 0x1301, 0x0A1A, 0xC02B]
print([("0x%04x" % v, is_grease(v)) for v in values])
```
```output
[('0x0a0a', True), ('0x1a1a', True), ('0xfafa', True), ('0x1301', False), ('0x0a1a', False), ('0xc02b', False)]
```

**Диагностика (иллюстративный вывод, не запускается).** Значения адресов и времён условны.

```text
$ ping -c 3 example.com        # пример вывода, не результат реального запуска
64 bytes from 93.184.216.34: icmp_seq=1 ttl=56 time=11.2 ms
64 bytes from 93.184.216.34: icmp_seq=2 ttl=56 time=10.9 ms
64 bytes from 93.184.216.34: icmp_seq=3 ttl=56 time=11.0 ms
3 packets transmitted, 3 received, 0% packet loss
```

Строка с `ttl=56` показывает остаточное значение TTL ответа; потери в 0% означают, что маршрут и целевой узел достижимы.

```text
$ traceroute example.com       # пример вывода, не результат реального запуска
 1  192.168.1.1     1.1 ms   1.0 ms   0.9 ms     # домашний маршрутизатор
 2  10.20.0.1       8.4 ms   8.1 ms   8.3 ms     # провайдер
 3  * * *                                           # узел не отвечает на ICMP, это не обязательно поломка
 4  93.184.216.34   11.3 ms  11.0 ms  11.1 ms
```

```text
$ dig example.com A +noall +answer +stats   # пример вывода, не результат реального запуска
example.com.   300   IN   A   93.184.216.34
;; Query time: 14 msec
```

```text
$ curl -v https://example.com/   # пример вывода (сокращён), не результат реального запуска
* Host example.com:443 was resolved.            # DNS
* Connected to example.com (93.184.216.34) port 443    # TCP
* TLSv1.3 (OUT), TLS handshake, Client hello (1):      # ClientHello
* ALPN: server accepted h2                      # согласован HTTP/2
* SSL certificate verify ok.                    # цепочка и имя проверены
> GET / HTTP/2
< HTTP/2 200
```

Чтение сверху вниз показывает, где ломается: нет строки «resolved» - проблема DNS; нет «Connected» - TCP или маршрут; ошибка после «Client hello» - TLS или сертификат; а код 5xx - уже сервер приложения.

## Типичные ошибки

* **Путать версию записи и реальную версию протокола.** В ClientHello TLS 1.3 версия 0x0303, а настоящие версии перечислены в supported_versions.
* **Выходить за границы вложенных структур.** Каждый список в TLS имеет свою длину; читайте вложенные части через отдельные ридеры, а не по глобальному смещению.
* **Считать шифронаборы 1.3 и 1.2 одним форматом.** В 1.3 набор задаёт лишь шифр и хеш; обмен ключами и подпись согласуются отдельными расширениями.
* **Принимать GREASE за настоящее значение.** `0x0A0A` не шифронабор; печатайте и обрабатывайте его особо.
* **Думать, что SNI зашифрован.** В обычном ClientHello имя видно наблюдателю.
* **Отключать проверку сертификата «чтобы заработало».** Это превращает TLS в шифрование без аутентификации; исправляйте причину (цепочка, имя, часы).
* **Считать `* * *` в traceroute поломкой.** Многие маршрутизаторы не отвечают на ICMP; смотрите, доходит ли дальше.
* **Читать успешный ping как гарантию работы сервиса.** ICMP может проходить, а порт сервиса быть закрыт.

## Итоги

* TLS даёт конфиденциальность, целостность и аутентификацию сервера по сертификату.
* Запись TLS: тип, версия, длина; ClientHello - версия, random, session id, шифронаборы, методы сжатия, расширения.
* SNI называет имя сервера, ALPN - прикладной протокол, supported_versions - реальные версии; GREASE - заведомо неизвестные значения для устойчивости.
* TLS 1.3 завершает рукопожатие за один RTT; сертификат проверяют по цепочке, сроку и имени (SAN).
* ping, traceroute, dig и curl -v диагностируют разные уровни: определите, на каком этапе цепочки DNS, TCP, TLS, HTTP возникает сбой.
