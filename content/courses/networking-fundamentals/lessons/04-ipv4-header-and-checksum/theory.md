## Паспорт IP-пакета

Перед данными в каждом IP-пакете идёт **заголовок**, паспорт пакета. В нём записано, откуда и куда пакет идёт (два IP-адреса), какой протокол лежит внутри (TCP, UDP, ICMP), сколько пакет живёт (**TTL**), не разрезан ли он на части (идентификатор, флаги, смещение) и **контрольная сумма**, которой проверяют, не испортился ли сам заголовок по дороге.

Заголовок - просто набор байтов в строго заданном порядке. Первый байт содержит сразу два числа: версию протокола (4) и длину заголовка. Дальше идут поля по 1, 2 и 4 байта. Чтобы прочитать их, не нужно никаких библиотек: срезы массива байтов, сдвиги и маски.

**TTL** (time to live) - счётчик хопов. Каждый маршрутизатор уменьшает его на единицу, и если получилось 0, пакет выбрасывается. Это защита от петель: пакет, ходящий по кругу, не засорит сеть навсегда. Заодно так работает `traceroute`: он посылает пакеты с TTL 1, 2, 3, ..., и каждый маршрутизатор в пути по очереди сообщает о себе.

**Контрольная сумма** - короткое число, посчитанное по всем 16-битным словам заголовка. Получатель пересчитывает её: не совпало - пакет испорчен и выбрасывается. Маршрутизатор уменьшил TTL, значит, и сумму нужно обновить; поэтому она меняется на каждом хопе.

В этом уроке вы разберёте заголовок по hex-дампу, как это делает Wireshark. Для чтения байтов полезны [struct](lesson:python.stdlib.json-csv-struct) и аналогичные средства в [Node.js](lesson:nodejs.fundamentals.buffers-encodings); обработку «битых» данных без падений вы встретите и в [обработке ошибок в Rust](lesson:rust.fundamentals.error-handling).

## Поля заголовка и алгоритм RFC 1071

**Раскладка (байты, смещение от начала).**

| смещение | размер | поле | пояснение |
|---|---|---|---|
| 0 | 4 бита + 4 бита | version, IHL | версия 4; IHL - длина заголовка в 32-битных словах (5-15) |
| 1 | 1 | DSCP (6) + ECN (2) | класс обслуживания и сигнал перегрузки |
| 2 | 2 | total length | заголовок + данные, не больше 65535 |
| 4 | 2 | identification | общий для всех фрагментов датаграммы |
| 6 | 3 бита + 13 бит | flags, fragment offset | `0x4` reserved, `0x2` DF, `0x1` MF; смещение в блоках по 8 байт |
| 8 | 1 | TTL | уменьшается на каждом хопе |
| 9 | 1 | protocol | 1 ICMP, 6 TCP, 17 UDP, 41 IPv6-in-IPv4, 47 GRE, 50 ESP, 89 OSPF |
| 10 | 2 | header checksum | см. ниже |
| 12 | 4 | source address | |
| 16 | 4 | destination address | |
| 20 | до 40 | options | редко используются |

Все многобайтовые числа хранятся в **сетевом порядке байтов** (big-endian): старший байт первым.

**Контрольная сумма Интернета.**

1. Обнулите поле контрольной суммы.
2. Разбейте заголовок на 16-битные слова (big-endian) и сложите их в обычное целое.
3. Пока выше 16 бит что-то есть, добавьте старшую часть к младшей: `s = (s & 0xFFFF) + (s >> 16)` (перенос по кругу, «арифметика дополнения до единицы»).
4. Инвертируйте: `~s & 0xFFFF`. Это и есть значение поля.

Проверка получателя: сложите все слова **вместе** с записанной суммой и сверните перенос; должно получиться `0xFFFF` (инверсия даёт 0). Так же считаются суммы TCP, UDP и ICMP (у TCP и UDP к данным добавляется псевдозаголовок с адресами). Алгоритм слабый: он не замечает перестановки слов и некоторые парные ошибки, но очень дёшев в вычислении.

**Инкрементальное обновление.** Если изменилось одно слово заголовка (например, TTL и protocol лежат в одном слове: смещения 8 и 9), новую сумму получают по формуле RFC 1624: `HC' = ~(~HC + ~m + m')`, где `m` и `m'` - старое и новое значение слова. Так маршрутизаторы обрабатывают пакеты быстро.

**Фрагмент и флаги.** Если DF=1, пакет фрагментировать нельзя. Если MF=1 или смещение не ноль, это фрагмент: у последнего фрагмента MF=0, но смещение больше нуля. Первый фрагмент имеет смещение 0, но MF=1.

**Опции** (IHL > 5) используются редко: запись маршрута, метки времени, source routing. Современные маршрутизаторы часто отбрасывают или замедляют такие пакеты, поэтому в обычном трафике IHL равен 5.

## Примеры

**Контрольная сумма из RFC 1071.** В разделе 3 RFC приведён пример: байты `00 01 f2 03 f4 f5 f6 f7` дают сумму слов `ddf2` (до инверсии). Проверим функцией:

```python run
def ones_complement_sum(data):
    if len(data) % 2:
        data += b"\x00"
    total = 0
    for i in range(0, len(data), 2):
        total += (data[i] << 8) | data[i + 1]
    while total >> 16:
        total = (total & 0xFFFF) + (total >> 16)
    return total

data = bytes.fromhex("0001f203f4f5f6f7")
s = ones_complement_sum(data)
print(f"sum      = {s:04x}")
print(f"checksum = {~s & 0xFFFF:04x}")
print("check    =", f"{ones_complement_sum(data + (~s & 0xFFFF).to_bytes(2, 'big')):04x}")
```
```output
sum      = ddf2
checksum = 220d
check    = ffff
```

Последняя строка - проверка получателя: данные вместе с суммой дают `ffff`.

**Разбор заголовка.** Заголовок UDP-пакета из ходового примера (источник 192.168.0.1, адресат 192.168.0.199):

```python run
import struct

raw = bytes.fromhex("45000073000040004011b861c0a80001c0a800c7")
ver_ihl, tos, total, ident, flags_frag, ttl, proto, checksum, src, dst = struct.unpack("!BBHHHBBH4s4s", raw)
print("version", ver_ihl >> 4, "ihl", ver_ihl & 15, "header bytes", (ver_ihl & 15) * 4)
print("dscp", tos >> 2, "ecn", tos & 3)
print("total", total, "id", hex(ident))
print("DF" if flags_frag & 0x4000 else "-", "MF" if flags_frag & 0x2000 else "-", "offset", flags_frag & 0x1FFF)
print("ttl", ttl, "proto", proto, "checksum", hex(checksum))
print("src", ".".join(map(str, src)), "dst", ".".join(map(str, dst)))

zeroed = raw[:10] + b"\x00\x00" + raw[12:20]
total_sum = 0
for i in range(0, 20, 2):
    total_sum += int.from_bytes(zeroed[i:i + 2], "big")
while total_sum >> 16:
    total_sum = (total_sum & 0xFFFF) + (total_sum >> 16)
print("computed", hex(~total_sum & 0xFFFF), "matches", (~total_sum & 0xFFFF) == checksum)
```
```output
version 4 ihl 5 header bytes 20
dscp 0 ecn 0
total 115 id 0x0
DF - offset 0
ttl 64 proto 17 checksum 0xb861
src 192.168.0.1 dst 192.168.0.199
computed 0xb861 matches True
```

Формат `!BBHHHBBH4s4s` - это раскладка таблицы выше: 20 байт без опций.

**Что делает маршрутизатор с TTL.** Уменьшаем TTL и обновляем сумму инкрементально, а затем сверяем с полным пересчётом:

```python run
def checksum(header):
    total = sum(int.from_bytes(header[i:i + 2], "big") for i in range(0, len(header), 2))
    while total >> 16:
        total = (total & 0xFFFF) + (total >> 16)
    return ~total & 0xFFFF

header = bytearray.fromhex("45000073000040004011b861c0a80001c0a800c7")
old_word = int.from_bytes(header[8:10], "big")      # TTL и protocol в одном слове
old_sum = int.from_bytes(header[10:12], "big")

header[8] -= 1                                       # TTL: 64 -> 63
new_word = int.from_bytes(header[8:10], "big")
# RFC 1624: HC' = ~(~HC + ~m + m')
t = (~old_sum & 0xFFFF) + (~old_word & 0xFFFF) + new_word
t = (t & 0xFFFF) + (t >> 16)
t = (t & 0xFFFF) + (t >> 16)
incremental = ~t & 0xFFFF

header[10:12] = b"\x00\x00"
full = checksum(header)
print(f"ttl 64 -> {header[8]}, incremental {incremental:04x}, full {full:04x}, equal {incremental == full}")
```
```output
ttl 64 -> 63, incremental b961, full b961, equal True
```

Так маршрутизатор экономит время: пересчёт одного слова вместо десяти.

## Типичные ошибки

* **Считать сумму с непустым полем.** Поле checksum должно быть обнулено при вычислении; иначе получите значение, не совпадающее с ожидаемым.
* **Забыть перенос.** Сумма слов может перевалить за 16 бит, и перенос нужно прибавить к младшей части, иногда дважды.
* **Брать длину заголовка 20 всегда.** Длина - `ihl * 4`; с опциями до 60 байт. Сумма считается по всему заголовку, включая опции.
* **Считать сумму по всему пакету.** Контрольная сумма IPv4 покрывает только заголовок; данные защищают TCP, UDP и канальный FCS.
* **Путать порядок байтов.** Сетевой порядок - старший байт первым; `int.from_bytes(..., 'big')` или `!` в `struct`.
* **Читать смещение фрагмента в байтах.** Записанное число нужно умножить на 8, чтобы получить байты.
* **Путать флаги и смещение.** Они делят одно 16-битное слово: флаги - три старших бита, смещение - 13 младших.
* **Принимать любой дамп.** Проверяйте версию, IHL и длину данных до чтения полей; иначе чужой (или сломанный) дамп приведёт к исключению вместо понятной ошибки.

## Итоги

* Заголовок IPv4 - от 20 до 60 байт в сетевом порядке; длина задаётся IHL в словах.
* Поля читаются срезами, сдвигами и масками: `version = b[0] >> 4`, `ihl = b[0] & 15`, флаги - три старших бита слова, смещение - 13 младших.
* Контрольная сумма: сумма 16-битных слов с переносом по кругу, инверсия; проверка даёт `0xFFFF` по всему заголовку.
* TTL уменьшается на каждом хопе, поэтому сумма пересчитывается (в том числе инкрементально, RFC 1624); TTL 0 приводит к ICMP Time Exceeded.
* Все ошибки дампа нужно обрабатывать явно: не IPv4, неверный IHL, обрезанные данные.
