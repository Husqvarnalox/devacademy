# {{name}}

Минимальное приложение NestJS 12 без Nest CLI. Нужен Node 22.15 или новее.

## Что внутри

- `src/main.ts` — запуск приложения на порту `PORT` (по умолчанию 3000).
- `src/app.module.ts` — корневой модуль.
- `src/todos.controller.ts` — маршруты `GET /todos` и `POST /todos` (валидация тела вручную, `400` при пустом `title`).
- `src/todos.service.ts` — провайдер с хранилищем в памяти; внедряется в контроллер через DI по типу параметра конструктора.
- `src/app.test.ts` — e2e-тест: `@nestjs/testing` поднимает модуль, запросы делает `fetch`, раннер — `node:test`.
- `scripts/dev.mjs` — режим разработки: `tsc --watch` пересобирает `dist/`, `node --watch` перезапускает сервер.

## Скрипты

| Команда | Что делает |
| --- | --- |
| `npm install` | ставит зависимости (нужна сеть) |
| `npm run dev` | пересборка и перезапуск при изменениях, http://localhost:3000 |
| `npm run build` | компиляция `tsc` в `dist/` |
| `npm start` | запуск собранного `dist/main.js` |
| `npm test` | сборка и тесты `node:test` из `dist/` |

## Заметки об архитектуре

- Nest 12 поставляется как ESM, поэтому проект `"type": "module"`, модуль `NodeNext`, а в относительных импортах пишется `.js`.
- Внедрение зависимостей опирается на метаданные декораторов: нужны `experimentalDecorators` и `emitDecoratorMetadata`,
  а значит код должен компилироваться `tsc`. Загрузчики, вырезающие типы (Node strip-types, esbuild), метаданные не создают.
- Для валидации DTO позже добавьте `class-validator` и `ValidationPipe`; для этого шаблона они намеренно не подключены.
